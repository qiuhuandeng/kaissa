# 凯撒销售移动端 · 项目规则

这是 caesar-system/caesar-sales-mobile/ 内独立组织的HTML移动业务原型，不是生产系统。用户于2026-09-27明确放入 caesar-system 项目内；保留独立入口、移动样式与本地预览服务。

- 主要角色为销售顾问。主链路为客户本次需求→现成产品或定制方案→客户确认→核对开单→订单办理。
- 保留 commerce-agents 的旅游卡片交互；根据用户后续要求，视觉采用绿灰色员工移动工作台，产品、订单用紧凑列表，不照搬后台蓝色或消费者旅行展示页。源项目保持只读。通用样式放 assets/style.css，AI会话专用样式放 assets/assistant.css，交互放 src/app.js，业务样例与规则放 src/model.js。
- 标题栏补充要求：五个一级页参照领队端采用60px原型标题栏、居中16px标题及宿主胶囊区域（2026-09-28最新参考，替代原44px示意栏），标题栏不放业务按钮；新增客户放搜索区；订单页不放开单按钮，预订仍从工作台或产品进入，账号和消息放工作台正文，切换需求放AI客户卡片。胶囊仅为原型的宿主外观示意，不实现宿主行为。
- 当前导航：一级页显示底栏和统一页头；详情及表单只用独立返回栏，关键预订／开单操作置底。保持分组紧凑列表和已验收的组合筛选、搜索清空、自适应AI输入区。
- 五个入口：工作台、客户、AI助手、产品、订单。当前方案属于一次需求，不是跨客户购物车。
- 销售不能确认计调资源、财务实收、客户签署或退款。资料提交与下游确认分别展示。
- 无真实模型、支付、微信、短信、合同或ERP接口；新增能力必须明确区分原型演示与正式接入。
- 本地存储只服务本项目草稿及演示会话，不建设跨系统同步。
- 不因本端调整顺带修改 caesar-system 其他端或外部 commerce-agents 的业务页面；业务规则来源记录在 docs，变更后保留已有验收及并行工作线。
- 完成必要金额与状态测试、手机尺寸浏览器验收后更新 docs/实施与验收.md。UI使用业务叫法，不将内部实现说明塞入主流程。

- 2026-09-28 UI基准：参考主项目 `leader/index.html` 的排团／消息／我的三页。390px最大预览宽度、浅灰底、白色信息区、10—12px卡片圆角、8px按钮和输入框、细边框；绿色仅用于主操作、选中与少量提示。首页不恢复大块深绿概览；AI卡片继续保留。详见设计方案第九节。

- 2026-09-28 AI页专用规范：用户明确要求文字和卡片继续参考commerce-agents移动智能助手。AI对话正文15.5px，行程与产品标题采用本地衬线字、行程22px圆角、产品图文卡14px圆角并横滑；灰绿底与深绿操作。该页正文及输入区独立覆盖，不将领队端10—12px圆角强套在生成卡片上；其他四页及统一标题栏继续沿用领队规范。保留客户需求、方案版本、报价及客户确认边界。

- 2026-09-28 用户截图修正规范（覆盖上一条AI视觉尺寸）：AI结果参考截图中的预订卡结构，浅米色背景、接近满宽的18px圆角卡、17—18px标题、13px常规正文、描边状态、内嵌浅色明细和箭头入口；不使用大天数或大幅图片卡。对话气泡右对齐，工具收为紧凑一行；行程说明可逐日展开。其余四页、一级标题栏、底栏和业务职责保持。

- 2026-09-28 AI整体视觉统一（最新）：保留用户认可的紧凑文字和结果卡结构；配色直接引用本端共享ground／paper／well／ink／soft／line／primary，移除米色与渐变、投影、倾斜印章。状态与控件回到全端4px／8px规范，用户气泡及发送／箭头采用统一主绿；结果卡18px圆角与17—18px标题、13px正文保持。

- 2026-09-28 行程折叠统一：产品详情、方案详情、客户版预览及AI卡片均使用11px细线箭头，收起向下、展开向上，不使用加减号；复用arrow图标和辅助文字色。

- 2026-09-28 产品分享：参考sales产品详情分享流程，产品详情底部提供分享；区分产品介绍和具体报价，客户咨询经销售核对后接入出行意向。使用本端share-model.js和share-ui.js，不耦合sales端数据。链接、指定客户验证及咨询接待仅为同浏览器原型，不冒充微信发送、真实鉴权或资源预留。

- 2026-09-28 订单详情：按用户明确要求取消详情Tab，用订单摘要、本单办理、订单信息及记录组织；收款与认款、合同、游客资料、出行资料、售后均进独立返回页，售后不可删除。认款补充回原申请，提交及签署发起不替代财务或客户结果。本端order-ui.js承载页面，sales参考端保持只读。
