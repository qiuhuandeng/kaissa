# 二级页面通用 UI 规范

## 1. 适用范围

本规范适用于后台从列表页进入的二级详情、新建、编辑、审批详情和配置页面。

典型页面：

- 产品编辑页
- 产品详情页
- 团期新建页
- 团期详情页
- 订单详情页
- 供应商详情页
- 财务结算详情页

## 2. 顶部标题区

二级页标题区固定为：

`返回 + 当前页面标题 + 右侧操作区`

规则：

- 返回文案只显示 `返回`。
- 页面标题使用 `18px / 26px / 600`。
- 不在内容区重复面包屑。
- 右侧只放页面级主操作。
- 页面级主操作只出现一次，摘要卡、详情卡和表单卡内不重复放同一组主操作。

## 3. 宽度规则

二级页面分两层宽度：

- 页面画布、标题区、摘要卡、步骤 Tab 或详情 Tab：`100%`。
- Tab 下真实内容轨道：最大 `1216px`，左对齐。

例外：

- 宽表格需要横向承载完整业务列时，可在表格容器内滚动。
- 看板、财务报表、复杂分析页可按看板规范处理。
- 2026-10-18用户明确：航服新增／编辑BSP散票、团队票、包机票四个页签的表单与底部步骤区，以及机票订单详情六个页签的内容区，均使用可用宽度100%，与页头、摘要及Tab左右对齐，不保留右侧1216px限制产生的空白；宽名单只在表格容器内滚动。该例外适用于`air-order-edit.html`和`air-order-detail.html`，其他模块继续按原规则。

- 2026-10-18用户追加：包机项目详情 `air-charter-detail.html` 的所有页签内容区使用可用宽度100%，与页头、摘要及Tab左右对齐，移除1216px上限造成的右侧空白；宽表格仍只在各自容器内滚动。

  验收：筹备与执行两个项目、四页签、1920／1024两种视口共16项通过，内容宽度1654／758px，卡片与页签左右对齐，页面无横向溢出，脚本错误0。证据见 `evidence/air-charter-detail-width-20261018/`。

## 4. 编辑页与详情页差异

编辑页：

- 使用输入框、选择器、上传控件和可编辑明细卡。
- 一个 Tab 内尽量是一个整体表单卡。
- 底部步骤按钮跟随当前 Tab。

详情页：

- 使用只读字段、业务列表、附件预览、状态和跳转入口。
- 不把详情页做成表单输入感。
- 不展示说明性建模语言、字段口径、对象链路或系统内部来源。

## 5. Tab 规则

步骤 Tab 和详情 Tab：

- 宽度铺满页面内容区。
- 选中态可以使用浅蓝底和主色文字。
- 不使用粗下划线。
- active 不导致高度、字号、布局跳动。
- Tab 下内容默认进入 `1216px` 左对齐内容轨道；第3节明确的全宽页面例外按可用宽度100%展示。

## 6. 线条与颜色

默认视觉必须克制：

- 卡片边框使用中性灰。
- 分割线使用中性浅灰。
- 输入框普通态边框使用中性灰。
- 不使用明显蓝色边框作为默认边线。
- 蓝色只用于主按钮、链接、当前步骤、选中态、焦点态和必要的业务状态。

## 7. 摘要卡边界

摘要卡用于确认当前对象，不承担业务解释职责。

本规范暂不强制所有二级页摘要卡结构完全一致。产品编辑页和产品详情页可以保留各自编辑态、展示态差异，但信息层级必须克制，不放重复主操作和大段说明。

## 8. 验收清单

- 返回入口是否只显示 `返回`。
- 页面标题字号是否为 `18px / 26px / 600`。
- 页面级主操作是否只出现一次。
- Tab 是否 100% 铺满。
- Tab 下真实内容是否符合第3节宽度规则（默认1216px左对齐，明确例外页面全宽）。
- 默认边线是否为中性灰。
- 蓝色是否只用于交互状态。
- 详情页是否避免表单输入感。
- 页面是否没有说明性建模语言。

## 2026-10-18 导入交互补充

用户明确：导入文件选择、核对、逐行处理、批次结果使用右侧抽屉，来源列表保持；不采用整批导入二级页面。票务资料选择抽屉880px、批次核对1280px、单行核对1040px，均限制在当前窗口内，表格横向滚动且操作列固定。移除手动载入模拟／示例数据入口，列表预置记录保留；模板不带模拟业务行。

补充（同日用户后续明确）：原型各步骤默认有模拟数据，无须上传文件或填完表单才能点击下一步；票务导入采用打开即预置资料、直接核对及结果的方式。无手动载入按钮，文件替换可选，保留重复和待匹配等业务场景展示。该条覆盖此前“未上传无模拟内容”的执行理解。
