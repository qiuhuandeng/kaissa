# Admin成员任职与审批人员统一实施

2026-09-24。承接用户“执行”和《Admin部门组织对审批设置的支持核对》，本次推进第一步：集团组织内成员任职、直属上级维护，以及员工账号、组织成员、审批候选资料统一。组织新增／停用、组织调整申请受理与生效不混入本步。

## 角色及操作路径

账号管理员在“部门组织—员工账号”开通、编辑、停用账号，设置可任职公司及角色资料。集团组织管理员进入“组织架构”，选中公司或部门，在“成员任职”中新增或调整主／兼任、直属上级、任期和生效日期。审批管理员继续在审批中心配置模板及公司职责，通过试跑核对实际审批人。业务端仍提交调整申请，不以提交申请直接改动当前关系。

本步是业务原型：没有真实账号服务、短信、后台权限执行或生产组织同步。资料只用于当前原型会话。账号和任职维护可操作、保存可复开，审批试跑读取相同的有效人员及关系。

## 页面及实现位置

- `admin/org.html`：统一成员任职Tab与主入口，按组织公司识别范围。
- `admin/employees.html`：共同员工账号列表及账号维护；角色资料可保存，完整角色权限执行留后续。
- `shared/admin-org-members.js`、`shared/admin-employee-accounts.js`、`shared/org-admin-ui.js`、`shared/org-admin-members.css`：列表、标准抽屉、只读详情、未保存保护及表格固定操作列。
- `shared/approval-org-data.js`：账号维护、任职维护、按期取关系、校验及变更记录。
- `shared/approval-config-model.js`、`shared/approval-config.js`：有效账号／任职／审批资格核对、刷新候选资料；角色名不自动决定审批人。
- `shared/approval-staff-bridge.js`、`shared/approval-org-maintenance.js`、`merchant/system/staff-management.html`、`merchant/system/my-org.html`：业务端共用成员展示与现有申请入口。
- `shared/style.css`仅增加本步样式导入；不改全局导航。

## 2026-09-24 员工账号抽屉直接维护任职（用户追加）

用户明确新增／编辑员工账号也应能填写任职部门、直属上级，并与组织架构新增任职核心内容一致。本条覆盖此前“复杂任职只在组织架构维护”的入口约定：员工账号按员工维护任职，组织架构按部门维护成员，两处复用同一表单、同一任职记录和校验，不再要求开通账号后跳页补任职。

| 要求 | 原缺口 | 本轮修改 | 验收 |
| --- | --- | --- | --- |
| 账号新增同时安排任职 | 只保存账号，提示到组织架构维护 | 同抽屉增加公司、必填部门、主兼任、生效／结束日期、直属上级、汇报预览及原因 | 缺部门不落账号，账号及任职一起校验保存 |
| 编辑已有员工任职 | 账号只能看任职，不能改 | 带入现任；多项任职选择本次编辑项，允许新增兼任；切换未保存修改需确认 | 部门和上级带入、本人排除、跨公司候选隔离及兼任保存 |
| 两入口规则一致 | 分开表单容易产生差异 | 新增共享 `org-appointment-form.js`，账号与组织成员共同使用；沿用有效期、循环及主任职校验 | 组织列表和审批试跑读取同一记录，校验失败不部分保存 |
| 账号编辑不造任职变更 | 混合保存可能产生空调整 | 未修改任职时只保存账号；任职新增／实际变更才要求原因和写记录 | 仅改手机号无新增任职记录，改上级缺原因时账号也不写入 |
