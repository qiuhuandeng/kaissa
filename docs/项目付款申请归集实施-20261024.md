# 项目付款申请归集实施

## 四种汇总列表样式修正（2026-10-24，已实施验收）

付款经办人需在按科目／供应商／团期／项目列表核对金额，再进入原请款抽屉。此前仅按项目设置紧凑列宽，其余模式继续铺开全部付款节点、关联团号及供应商，长内容撑高行并挤出金额。本轮保留各模式原汇总、筛选、金额和请款入口，只统一固定列宽、长内容摘要及按汇总对象命名表头；完整名称保留搜索与悬停查看。回归四种模式切换、按原团名／团号搜索、请款和窄屏内部滚动。

本轮只改列表呈现：四模式共用固定列宽，多付款节点／关联团／供应商／费用显示数量；多日期显示最早日期及日期数量。公共费用不计作一个团，完整内容仍可悬停查看和搜索。表头按供应商、团期、项目、科目对应显示，原金额汇总和动作状态不改。将该页已有局部样式移回共享样式文件，项目请款抽屉外观与顺序保留。

9组页面观察通过：1600px下四种模式表格均1309px、最大行高89px，页面无横向溢出；按科目用EU-ABC-202607-SX和日本关西奖励旅游均找到团费；研学成本请款保留3,200元；项目请款保留摘要前置、同条件合并和532,700元；1024px下1216px表格仅在内部滚动，操作列在992px以内。语法、差异格式和财务执行清单检查通过，浏览器错误／警告为空。未提交新付款申请。

## 当前操作路径

履约中心 → 付款申请 → 汇总方式选择“按项目” → 项目行“请款” → 勾选子团对应费用、填写本次申请金额 → 保存草稿或提交付款申请。

同一子团可以有多笔采购，逐费用选择；同一笔跨团采购可以分别填写各团金额，整笔采购合计控制。公共费用单列，未分配的跨团采购余额也单列。项目和币种分别汇总，批量选择多个币种仍分别显示合计，不自动折算。提交按原采购分别保留申请和子团金额，交原财务复核；已付款金额只来自原财务结果。

采购详情移除“申请付款”，申请记录详情在采购来源中只读；撤回在统一付款申请页办理。原供应商、团期、科目模式和通用抽屉保留。付款条件依据可展开核对，未明确时显示待核对并禁止选择该行。草稿可继续编辑，不作为有效未付申请占用余额，不进入财务办理列表。
