## 二、业务方真正要完成的工作

### 1. 外采业务

供应商维护原始产品、具体日期的公开售价和结算报价 → 外采人员审核并选择代理 → 包装我方销售内容、确定供给确认方式 → 销售下单 → 供应商确认有位、保留、补差或无法承接 → 我方处理客户侧下一步 → 计调核实际服务和费用 → 双方对账 → 财务核应付、预付抵扣、付款及票据。

集团内部产品共享另走内部公司之间的合作与结算。产品提供公司、客户签约销售公司、外部采购公司、最终收款供应商应分清，不能因为销售方把它称为“外采”，就全部放到外部供应商端。

### 2. 自营业务

产品经理维护长期产品及多出发地线路方案 → 产品定价人员形成批准规则 → 计调开团并分配名额、销售范围和采购资源 → 销售按当期价格及渠道名额下单 → 计调管理名单、签证、资源、领队及出团资料 → 回团后核实际成本与收退依据 → 提交业务结算和必要的后补调整 → 财务复核及付款。

资源可先买后开团，也可先建团后采购；付款可按批准节点先发生，不必等全团最终结算。采购数量、团期分配、渠道配额、订单占位必须能分别核对。

## 五、建议收敛的页面改进包

下面是供用户审阅的顺序，不是已取得的实施授权，也不启动历史未完任务。

| 优先顺序 | 应处理的问题与业务影响 | 修改主位置 | 边界 |
|---|---|---|---|
| 1 | 团期结算的订单及收退依据失真，财务无法逐单核对 | 履约中心 → 团期结算 | 只替换错误金额与明细依据；复用既有供应商对账、二次结算和财务承接 |
| 2 | 交通采购减量、零量、多规格及已分配不足，可能错报名额和申请金额 | 履约中心 → 交通采购 | 原采购变更及付款节点内修正；不自动改已售订单或已付款 |
| 3 | 外采产品报价和声明不完整也可提交，审核入口缺必要约束 | 供应商端产品编辑／团期报价；产品市场审核 | 草稿可存、正式提交核双价与主动确认；不用真实识别、后台上传作为完成前提 |
| 4 | 二次确认在销售侧缺本次结果和责任接手，静默订单易无承接 | 销售预订／订单详情；工作台；复用现有供应商采购回复 | 先做待确认、补差、无位、保留到期的操作表达；不建设跨端自动回写或短信服务 |
| 5 | 规则有配置但预订价格缺采用依据；外采扣点缺完整适用规则 | 原定价／佣金配置、预订明细、公司协议及采购费用 | 门店佣金和供应商扣点分别处理；不恢复已删除价格试算或价格权限演示 |
| 6 | 团期是否可报名与是否对外展示未明确分开 | 团期新建／详情，引用产品渠道范围 | 默认对客展示关闭；不重做渠道平台同步 |
| 7 | 行程识别校对、每日多段交通及服务类型仍需补齐 | 自营／供应商共用产品编辑能力 | 保留已有酒店、须知、购物表及混合签证，按真实资料整理，不堆重复字段 |
| 8 | 素材有页面但业务上传到销售使用尚未完整 | 营销中心 → 素材中心 | 当前页面完成选择、预览、结果和下载；不建设新媒体平台 |

单独保留的差距：**销售后团期核心信息编辑限制**。已有整团转移不等于此项已解决，但9月19日用户曾明确排除此项，本轮仍只登记，不把它悄悄加入默认实施包。价格试算、产品预订演示价权、已删除出团资料缺口区同样不自动恢复。

产品近月分析、领队资料、付款币种、纯预付、批量付款、佣金配置、二次结算已有基础，不建议以“附件提到”为由重建。

## 六、明确需求与待确认规则分开

| 待确认事项 | 由谁确认 | 原型可先推进的内容 |
