# 业务角色阅读导航与确认范围

业务确认辅助稿 v1.0  
编写日期：2026年8月2日  
适用对象：所有参与业务流程确认的部门负责人、岗位代表、项目组成员

本文用于解决“文档很长，业务岗位不知道先看哪里”的问题。正式业务规则仍以各《流程01》确认稿为准；本文只告诉每类岗位应该主看哪些文档、重点确认哪些内容、哪些内容只需要协同了解。

全局性的决策表和状态字典只在本文、总目录和评审会中统一提示，不进入各岗位流程稿的“本文件怎么读”。各岗位流程稿正文应先讲完整业务流程，再在“需要业务确认事项”前用跨部门协作场景说明本岗位操作之后会交给谁、对方怎么处理、什么情况会退回、最终形成什么结果。

## 一、确认范围原则

| 确认类型 | 含义 | 适用情况 |
| --- | --- | --- |
| 主责确认 | 该部门是流程主责任方，需要确认本岗位从开始到结束怎么操作、数据是否正确、规则是否能执行 | 销售确认销售流程，财务收款确认财务流程01，航服确认航服流程 |
| 协同确认 | 该部门不是主流程拥有者，但流程会影响本部门承接，需要确认交接边界和数据口径 | 销售协同确认财务收款，产品计调协同确认销售售后 |
| 只读 | 该部门需要了解上下游，不直接确认规则 | 门店只读航服 BSP 账单，销售只读 NC 细节 |
| 拍板 | 涉及跨部门利益或风控，必须由业务负责人、财务负责人、法务或公司管理层明确选项 | 合同放行、退款扣损、应付预付判断、门店分润 |

## 三、按角色推荐先读顺序

### 销售和门店

1. 先读销售流程01或加盟门市流程01的“本文件怎么读”和正文主流程。
2. 读到“常见端到端场景”章节时，只复核会影响收款、合同、履约、退款、转款和结算的跨部门事项。
3. 涉及收款、退款、转款时读财务流程01。
4. 涉及邮轮、外采、航服时，只读对应专项文档的销售承接和变更章节。

### 产品、计调和履约

1. 先读产品计调流程01的“本文件怎么读”和正文主流程。
2. 读到“产品计调端常见端到端场景”章节时，复核订单进入团期后，名单、资源、成本、付款和结算由谁继续处理。
3. 涉及外采、邮轮、航服时读对应专项确认稿。
4. 涉及成本、预付、付款、回团结算时读财务流程02和财务流程03。

### 外采和供应商运营

1. 凯撒外采产品部先读外采产品部流程01的正文主流程。
2. 第三方供应商运营先读体系外供应商端流程01的正文主流程。
3. 读到各自“常见端到端场景”章节时，复核内外部来源、订单确认、供应商账单、应付付款和结算影响。
4. 涉及供应商账单、应付、付款、NC 时读财务流程02和财务流程03。

### 邮轮和航服

1. 邮轮先读邮轮业务流程01正文主流程。
2. 航服先读航服机票业务流程01正文主流程。
3. 读到各自“常见端到端场景”章节时，复核专项操作对订单、资源、收付、成本、应付、付款、结算和 NC 的影响。
4. 涉及客户侧退转读财务流程01，涉及供应商侧预付/付款读财务流程02。

### 财务

1. 收款岗先读财务流程01正文主流程。
2. 应付/付款岗先读财务流程02正文主流程。
3. 结算/NC 岗先读财务流程03正文主流程。
4. 读到对应“常见端到端场景”章节时，复核每笔业务事件如何影响应收、应付、预付、付款、结算、发票和 NC。

## 四、评审会建议用法

评审会不建议从长文第一页读到最后一页。建议按以下顺序推进：

1. 先用本文确认每个岗位要看的文档和确认范围。
2. 各岗位先读自己的流程正文，再用“常见端到端场景”复核跨部门协作是否跑得通，不再单独跳转场景索引。
3. 用《待确认问题决策表》逐项拍板 P0 问题。
4. 用《统一状态字典与流转口径》确认状态命名。
5. 最后各部门回到对应流程确认稿确认。
