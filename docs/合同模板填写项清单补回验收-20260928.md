# 合同模板填写项清单补回验收

日期：2026-09-28。依据：用户指出只看正文不能判断合同需要哪些字段，确认补回按模板显示的填写项清单。本次仅模板编辑页和直接相关共享展示，不改变合同办理状态、订单金额或门店／团期撤回边界。

## 交付与业务位置

合同管理员选择合同文本后，在基本信息下方直接核对“合同填写项”，再阅读或编辑正文。清单集中展示合同需要的资料、必填或条件要求、从哪里取得或在哪里确认；具体游客、金额和客户选择在来源业务或合同准备中处理。

| 修改位置 | 内容 |
|---|---|
| `merchant/sales/contract-template-edit.html` 对应共享 UI | 基本信息 → 合同填写项 → 合同正文，保持单页分区，不恢复四个混杂 Tab |
| 合同填写项 | 三列：合同填写项、填写要求、资料来源／填写位置；按签约旅行社、人员、服务、费用、约定等业务内容分组，默认展开，无重复输入框 |
| 文本切换 | 从所选模板的填写要求生成清单，企业、境内／出境、邮轮、研学、省级、一日游、代办分别展示；不让管理员重复手工搭建字段 |
| 必需附件 | 清单列出当前勾选的附件，勾选调整后立即更新；避免再重复展示一行笼统“行程、费用和通用附件” |

页面会明确区分订单资料带入、公司资料带入、产品资料带入后核对、团期已确认安排，以及合同准备填写／向客户确认。产品中已撤回的成团说明、专项约定等不再声称有新增维护区域，由合同准备核对本次约定。法务固定条款不列成要求业务人员重复填写的字段，仍在正文维护。

## 开发承接：字段清单与平台对应关系

1. 填写项清单依据所采用模板维护，不代表任意正文占位文字都已具有自动取值或平台字段对应。正式新增／修订模板时，正文、字段清单、条件必填和对应关系必须按同一版一起校验；当前页不实现自定义字段设计器。
2. 一个业务填写项可能拆成多个平台参数，例如游客名单对应多名游客各自的姓名、证件及签署关系；不能把页面一行业务名称直接当成一个平台字段。
3. 平台字段名尚未取得，不编造参数。技术对接文档至少记录：合同文本及版本、业务填写项、ERP实际取值、平台参数路径、数据格式／枚举／单位、重复明细、条件必填、附件方式及缺项处理。映射需要配置，但不由合同管理员在本页逐项手填。
4. 自动带入不等于允许修改。订单金额、游客、出行日期等事实仍回来源确认；客户选择仍由合同经办人在合同准备中确认；缺项定位来源页面或本次填写处，不以空串／默认同意绕过必填。
5. 原型清单用于表达业务要求和填写位置，不表示已与12301自动同步。真实正文、接口参数及正式政策仍按既有待核实清单处理。

技术对应示例（平台字段留待接口资料确认）：

| 业务填写项 | ERP取值／处理 | 平台对应待核实内容 |
|---|---|---|
| 合同总额 | 本份合同确认金额；分签不得重复带订单总额 | 金额参数、币种、单位和精度 |
| 游客及签署人 | 本份覆盖游客、必要签署方、代表关系 | 游客数组、签署任务及授权资料的关联方法 |
| 委托投保资料 | 客户选择委托购买后填写保险产品、保费与人员 | 保险选项枚举、条件参数及人员对应 |
| 行程／服务明细 | 已确认业务资料及本次附件 | 结构化字段或文件上传方式、文件限制 |
