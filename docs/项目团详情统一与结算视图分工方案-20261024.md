## 一 当前差异的原因

两张图实际对应两套项目团执行详情。图2虽然从团期结算进入，但打开的是旧版团期详情的项目团模式；它不是“提交结算”时打开的结算核对抽屉。

| 比较项 | 图1 当前会奖项目团详情 | 图2 旧版项目团详情 |
| --- | --- | --- |
| 业务样例 | 三亚四日奖励旅游，60人 | 北京某科技有限公司欧洲奖励旅游，80人 |
| 项目团编号 | PRJ20261000001 | PRJ-MICE-20260915-001 |
| 内容组织 | 执行安排、成本摘要、客户款项、完成与结算记录、资料记录 | 总览、行程安排、项目名单、签证进度、资源确认、名单结构、项目订单、项目资料、项目成本、操作日志 |
| 设计出发点 | 一个项目下的具体会议、旅游或混合服务交付 | 在普通团期详情中套用项目团名称和客户专属信息 |
| 当前资料来源 | 当前会奖项目及项目团记录 | 结算页旧项目团样例与通用详情中的固定模板 |

团期结算中同时有这两类记录。当前会奖记录的“查看项目团”已经进入图1；旧样例仍进入图2。两张图的编号、客户、服务日期和人数不同，不能把它们强行认作同一团，更不能把旧80人团直接指向三亚60人团。

旧版还存在模板补值：缺少日期、人数、金额等传入资料时使用固定示例，预算及部分成本按比例生成。例如旧结算列表服务结束显示09-24，详情模板显示2025-09-23。这类资料不能作为结算事实，应在统一时核对来源并消除默认补造。

前两步已处理结算入口和成本维护位置，本轮发现的“两套执行详情并存”尚未解决。原成本边界验收不能作为详情统一已完成的依据。

## 二 三个办理位置怎样分工

上游由单团项目确定客户、约定和项目团安排，订单承接成交及客户款项；计调按项目团组织交付，服务完成后交业务结算核对收入、成本和税额，实际收付及开票继续交原财务功能办理。

| 办理位置 | 主要使用人和高频任务 | 处理对象与完成结果 |
| --- | --- | --- |
| 项目团详情 | 计调维护日程、名单、资源、服务资料并确认完成；负责人及销售查看交付 | 改变本项目团的执行资料和履约状态，留下实际服务期间、人数及交付依据 |
| 团期结算的维护成本抽屉 | 计调、采购经办维护费用、预计、分配、票据和供应商核对依据 | 改变原费用及本团承担金额；进行中即可维护，不以服务已完成为前提 |
| 团期结算的结算核对抽屉 | 经办人核本次范围及收支税额，审核人按节点确认 | 形成或续办本次结算记录；服务完成、客户认可、业务结算和资金结清分别表达 |

原型仍使用超级管理员，不按岗位隐藏功能；岗位只说明实际职责，操作继续受单据状态和业务顺序约束。

执行页保留只读成本摘要及结算结果反查，不恢复成本新增、费用确认或结算提交。客户款项保留原报价、订单及款票申请承接，财务实际认款、付款、开票不迁入团控。

## 三 统一后的项目团详情

继续沿用图1的五个页签。项目团编号、名称、所属项目、客户、服务类型、计划日期、人数口径、主责计调和地点使用同一份资料；实际日期和人数在确认完成记录中单列。所有入口打开同一团时，资料和可操作内容一致，仅返回来源不同。

| 原图2内容 | 统一详情中的位置 | 保留及补充方式 |
| --- | --- | --- |
| 总览 | 原顶部项目团信息、执行安排中的准备情况 | 保留识别本团及判断准备程度的信息；明确计划人数、已登记名单和实际服务人数，不能混作一个人数 |
| 行程安排 | 执行安排中的日程与行程 | 保留会议议程、旅游行程和混合服务，不把会议强行套成几天几晚旅游线路 |
| 项目名单、名单结构 | 执行安排中的参会或游客名单 | 共用一份人员资料；分组、到离批次、分房、分车在该区域核对和办理，不再维护两套名单 |
| 签证进度 | 执行安排中的名单准备区域 | 有签证需求时展示本团应办、资料、送签、出签结果，并承接现有签证办理；国内游和纯会议不固定展示申根样例或强制签证要求 |
| 资源确认 | 执行安排中的资源安排 | 保留会场、设备、餐饮等会奖资源；补齐适用的交通、酒店、车辆和领队安排。已有可用表单及确认方式优先复用，不能只用一条通用备注替代 |
| 项目订单 | 客户款项 | 保留订单、报价及覆盖范围；整包订单显示覆盖哪些项目团，不能在本团把整包总额当作本团独立收入 |
| 项目成本 | 成本摘要 | 展示本团直接费用、跨团分配、管理分摊和相关原费用；只读，维护入口统一指向团期结算 |
| 项目资料、出团资料 | 资料记录 | 依据服务类型组织客户资料、会议执行资料、旅游出团资料和交付附件，保留有效生成、查看及维护方式 |
| 操作日志 | 资料记录中的办理记录 | 保留变更依据、经办人与时间，区分本团记录和所属项目的公共记录 |
| 完成及结算结果 | 完成与结算记录 | 原实际完成、客户认可及结算记录继续保留；查看某次结算回到对应原记录，不在此再提交一次 |

现有会奖名单已经支持分组、批次、房间和车辆字段，但不等于已具备旧版全部专门办理能力。实施时要逐项核验签证、交通、分房分车、领队及资料操作，把确实可用的部分接入上述区域；固定统计卡和无来源样例不作为必须保留的功能。

“执行安排”按日程、人员准备、资源三个原有业务区域组织，必要时用区域定位、折叠及原抽屉缩短查找距离，不把旧版十个页签全部塞进一个无层次长页面，也不重做一套独立执行流程。

## 四 团期结算保留自己的核对内容

团期结算仍是一个列表，项目团与普通团期共用成本维护及结算流程。点击项目团名称或“查看项目团”，进入第三节统一的执行详情；“维护成本”打开原成本抽屉；“结算”或“查看结算”打开原结算核对抽屉。三类入口用名称说明处理对象，不用一个含糊的“详情”混指三件事。

结算抽屉保留原十页签，项目团差异放入已有相应区域：

| 原页签 | 项目团应核对的内容 |
| --- | --- |
| 单据总览 | 所属项目、客户、当前项目团及本次结算范围；服务完成和客户认可；含税、预计扣税后、核定扣税后的收入、成本、毛利及毛利率 |
| 收入明细、优惠减免、订单明细 | 原订单及客户确认依据、单团或整包覆盖范围、实际优惠和销售税额；整包未分团金额明确提示，不按团数或人数自行拆分 |
| 成本明细 | 本团直接费用、跨团分配、管理分摊、本次承担及原采购；成本和可扣税依据；项目承担、未分配金额单列且不混入本团承担 |
| 收款预收、预付付款 | 对应订单及费用的收付结果、在途与未结金额，保留原财务单据反查，不把未收未付直接当作收入或成本缺失 |
| 变更记录、附件依据 | 影响本次结算的有效变更、客户认可、交付及供应商核对依据和缺项；执行资料引用原团，不在这里重做日程、名单和资源维护 |
| 结算记录 | 本次草稿、提交、退回、确认及历史版本，保留原查看、导出和打印能力；历史金额对应当次范围 |

三种金额口径沿用已实现规则，“扣税后”指当前系统对收入税额和成本可扣税的核对结果，不改称企业所得税后净利润。未核定税额仍显示待确认，不能按零处理，也不在本轮制定新税率或抵扣政策。

结算范围可能覆盖多个项目团及项目公共费用。即便从一个项目团进入，也要明确“当前查看哪一团”和“本次结算包含哪些团及公共费用”，不能默认一团只对应一张结算单。此前已记录的旧样例22万元成本差额继续待核实，不为统一界面修改原金额。

返回来源是使用体验要求：从团期结算进入项目团详情，返回团期结算并保留筛选；从团控进入则回团控。它不应决定另一套项目团数据或页面内容。

## 六 旧样例和入口的处理顺序

1. 先列出旧项目团在结算列表、项目、订单、成本和历史结算中的引用，区分真实对应关系与模板示例。按项目团编号核对，不按客户名称猜测关联。
2. 旧80人欧洲团作为独立样例承接到统一项目团资料，保留原编号及有效引用；三亚60人团保持自己的资料。日期、预算和成本有冲突时保留来源并标待核对，不用模板比例推导成已确认数据。不存在可用来源的旧资料不伪造补齐；是否归档另按引用核查结果处理。
3. 统一团控、单团项目、团期结算及直接关联单据中的“查看项目团”入口。已能识别的旧地址进入对应记录；无法识别时明确未找到或待核对，不回落到默认80人团。
4. 补入第三节列出的适用执行能力，保持结算抽屉第四节的内容和分工；同步旧使用说明，防止仍指导用户进入两套详情。
5. 按第七节逐项验收后才将“项目团详情统一”标为完成。

本方案限于原型页面及直接入口，不增加菜单、不建设生产数据迁移或跨模块自动回写。关联资料统一用于避免用户看错团、看错金额，不扩展真实财务接口。

## 七 实施后的验收标准

以下为本次实施的验收标准，逐项结果和证据见[实施验收第四节](项目团详情统一实施验收-20261024.md#四-验收证据)：

- 同一项目团分别从团控、单团项目、团期结算进入，编号、客户、服务日期、人数、负责人、页签及业务资料一致，返回原入口并保留筛选。
- 旧80人欧洲团、当前60人三亚团各自独立；不存在的编号不显示默认团，旧订单和成本引用不串团。
- 纯会议按人数交付、国内旅游实名、出境旅游签证、会议加旅游分别显示适用内容；无签证需求不出现固定申根统计。
- 分组、批次、分房分车、交通酒店确认、领队安排、执行资料逐项核验有效操作；不因统一入口丢失原可用能力。
- 团控可以维护执行和确认服务完成，不能新增或确认成本、提交结算；进行中可在团期结算维护成本，最终结算继续按既有状态及依据办理。
- 单团订单、整包多团订单、跨团采购、项目公共费用和多团结算分别核对范围与金额，不重复计收入或费用。
- 原结算十页签、三种税额口径、退回续办、审批中只读及历史记录保持；未知税额不当零，旧差额仍可识别。
- 普通跟团、邮轮、专列原执行详情与成本结算回归通过；报价流程不变，超级管理员仍按业务节点连续操作。

方案阶段证据为[只读入口与内容核查](evidence/mice-prototype/detail-unification-plan-20261024/audit.json)，含两套详情及结算抽屉的实际内容和链接，脚本错误为0；它证明当前差异，不是上述新方案已通过功能验收。页面证据见[旧版详情](evidence/mice-prototype/detail-unification-plan-20261024/legacy-detail.png)与[当前详情](evidence/mice-prototype/detail-unification-plan-20261024/current-detail.png)。
