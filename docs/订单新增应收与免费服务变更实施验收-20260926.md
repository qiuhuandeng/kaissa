# 订单新增应收与免费服务变更实施验收

日期：2026-09-26。用户在代码对比后明确“执行”。本次沿用[五项对照](订单新增应收与零金额服务变更代码对照-20260926.md)，交付当前页面和直接入口范围内的业务原型。

## 一、业务责任与范围

销售在原订单申请新增收费、减免或服务安排；计调在团期确认可供、不可供或需补差；财务继续在应收、业务结算与结算调整办理。销售提交申请不改变已生效应收，不代替计调确认，也不代表已完成财务审核。

修改销售下单、订单列表、订单详情和团期详情，以及它们直接使用的共享脚本。未恢复产品预订页已撤回的身份及结算价展示；保留并行供应商对账和整团转移修改。独立团期订单入口未扩大改造。

## 四、原型与正式开发边界

1. 新增申请保留在当前页面会话，关闭抽屉再开仍可查看；刷新后重新使用示例。不新建跨页面本地数据同步。订单列表与详情、销售与计调使用各自会话，计调页演示独立的免费／房差／升舱申请，不声称刚提交的销售申请已实时发送到计调。
2. 强提醒是团期页面可见、未确认持续保留的业务提醒，不是真实消息推送、短信或企微通知。订单申请中的负责计调及状态为正式通知承接提供明确对象。
3. 非零差额的审批及财务入口只传原订单和申请单号，不模拟审批通过、应收生效、财务结算、实际核销或NC推送；0元不生成虚假的应收单据。正式系统的0元财务单据政策仍待确认。
4. 参团下单的1800元／人·全程为本页演示报价，团期价格维护仍有各自样例；未实现自动采用上游有效报价，不能将示例金额和单位当作统一业务政策。正式开发应采用对应团期有效的价格与计量单位。
5. 未重新批准完整款项清单、审批岗位／阈值、正式通知对象或价格政策。原财务报表8批／36项／6场景保持，不把本任务另计报表批次。
