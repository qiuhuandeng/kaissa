# 审批配置列表与抽屉 UI 对齐

日期：2026-09-24。依据用户指定的 `merchant/channel/commission_rules.html` 及共享 UI 规则实施。

## 用户截图复核与修正

用户反馈两个 Tab 的主按钮独占上行，筛选项落在下一行。复现发现首次加载的公共脚本会生成 `list-surface-filter-layout`，但审批页在切换 Tab、搜索、重置和翻页时重建了未经整理的筛选结构；前轮仅检查 class 存在，未覆盖重建后的布局层级，不能据此前检查认定样式已正确。

本次改为每次渲染直接生成公共布局完整结构：左侧字段及搜索重置、右侧主按钮，使用公共窄屏换行规则；标记为已整理，避免再次嵌套。只改审批交互脚本，不增加 CSS 覆盖或修改共享导航。26 组既有交互回归、9 次首次加载／重复切换／分页／空结果／重置的结构核对通过，JavaScript 语法、差异和财务执行清单检查通过。浏览器视觉仍未验，下一步根据真实页面复核截图所示错行和多余空白已消除。

## 范围与角色

管理员在审批配置维护模板、公司审批职责和人员，来源为现有业务表单、组织及员工任职；保存或发布后形成供业务申请选择的配置。本轮只调整审批配置两个列表及直接打开的配置抽屉，不改变业务规则、来源单据、日常审批处理和财务承接。

## 对照结果

| 位置 | 原问题 | 调整 |
| --- | --- | --- |
| 模板、人员列表 | 自建 Tab、工具栏、表格和分页，未使用统一列表结构 | 采用佣金政策页同款功能 Tab、筛选区、右侧主按钮、连体表格及分页；搜索重置紧随条件 |
| 表格列宽 | 自建列宽和操作样式，公共样式不能完整承接 | 固定操作列 164px，col／th／td 一致；模板名称或审批人员吸收剩余空间，最小表宽 1140px，仅表格内横向滚动 |
| 单元格及操作 | 自定义颜色、间距与操作链接 | 采用公共辅助行、主次操作和菜单项样式，内容垂直居中，长文本省略，关键状态及操作保留完整 |
| 抽屉框架 | 固定 600px，自定义标题和关闭结构被全局规则隐藏 | 使用 modal-title、modal-close、公共正文和底栏；常规 md、代办／字段选择／条件 lg，版本记录用查看抽屉 |
| 人员和代办 | 表单单列堆积、记录嵌套卡片 | 公司职责、审批人员、代办人员、生效范围分区；关联字段两列，原因整行，代办记录改轻量行 |
| 节点、条件和字段选择 | 内容分组不清楚、表单控件样式独立 | 使用公共分区标题及 form-control；条件信息与判断条件分开，审批来源、人员和办理方式分开 |
| 退出保护 | 使用标准关闭按钮后可能被公共监听直接关闭 | 在关闭事件到达公共监听前执行未保存检查，取消保留原抽屉和修改，确认放弃才退出 |

实现集中在 `shared/approval-config.js` 和 `shared/approval-config.css`；移除旧列表和抽屉框架的覆盖规则，不修改导航及其他模块样式。

## 本轮核验

- JavaScript 语法检查通过。
- 既有 DOM 检查 26＋25＋18，共 69 组通过，覆盖列表、人员代办、草稿发布、字段分组、分支和审批规则及模拟办理。
- 一次性结构核对通过：两个列表的公共结构、固定操作列与单一弹性列、抽屉标题／底栏／分区／尺寸；等待公共动态绑定完成后，关闭按钮的未保存确认、取消和放弃均正常。
- 专用 CSS 解析通过；差异格式和财务执行清单检查通过，原 8 批／36 项／6 场景保持。

这些检查不替代浏览器视觉验收。此前本地文件预览受到工具安全策略限制，本轮未更换通道绕过；实际桌面及窄屏的列宽、横向滚动、抽屉底栏和焦点体验仍待浏览器复核。
