### P01 供应商详情：保留已完成的公司协议来源

页面：[供应商详情](../merchant/resource/supplier-detail.html)。对应核01，**已完成，不再实施一遍**。

使用角色是供应商经办；上游为现有准入和协议审批，下游由产品、计调及财务引用。经办在这里维护合作，产品和财务查看正确依据，不在本页确认付款。

| 页面位置 | 当前成果与后续必须保留的行为 |
|---|---|
| “公司合作与协议” | 一家供应商分别列北京、上海等合作公司及其协议；不同公司的账期、范围和生效状态独立 |

### P04 团期详情：在两处处理名额归还和核心信息变更

页面：[团期详情](../merchant/tour/schedules-detail.html)。对应核03、04。

计调／团控从团期管控进入详情，处理本团名额及执行条件；上游为采购分配和订单占用，下游交售后、资源及合同处理。现有价格名额、编辑及售后入口继续使用。

**P04-A执行状态：已完成。** 原“释放”入口已改为逐笔核对原订单占用并归还原渠道，数量校验、停售渠道、取消／重复处理、邮轮不占舱和专列不占铺规则均已通过实际浏览器验收；见[P04-A实施与验收](P04-A订单名额归还原渠道实施与验收-20260918.md)。P04-B核心信息变更仍待实施。

| 具体位置 | 控件和操作怎么改 | 提交后的结果 |
|---|---|---|
| “价格名额”→“释放”→现有确认区 | 带入原订单、原渠道、原占用数量；经办只填本次释放量与原因。原渠道不可改成别的渠道；一次涉及多笔占用时逐笔核对 | 原渠道可用量增加，其他渠道不动；本次释放记录对应原占用 |
| 释放数量核对 | 数量必须大于0且不超过本笔剩余占用；已经释放的部分不能再次释放 | 不符合时留在当前处理区，说明哪笔可释放多少，不能只弹“成功” |
| 原渠道停售 | 归还仍记到原渠道，保持停售；如需调给其他渠道，使用既有渠道名额调整 | 不因渠道停售就自动分给直营或全渠道 |
| 顶部“编辑”→现有团期编辑抽屉 | 筹备且无关联订单／费用按原流程改；已有订单或成本时，日期、方案等核心项不能普通保存覆盖，新增“办理变更”入口 | 未受影响的普通资料可继续维护；核心变更进入影响核对 |
| 新增“办理变更”处理区 | 展示原值、拟变值及受影响订单／交通／合同／费用范围，提供“选择目标团期”；没有目标时提供新建团期去向 | 原团期保留；目标团期准备后进入已有售后转团，不自动把全团搬走 |

交通只有时刻变化且无费用影响是否可直接调整，仍待财务确认；原型中作为待确认例外，不做默认放行。订单占位释放与采购资源还位不是一个动作，释放2个订单名额不等于退掉2个采购座位。

验收：代理10位已占6，取消2位后代理可用6，直营不变；重复释放被提示。一个有订单和机票成本的团期不能直接另存出发日，但能找到目标团期及转团处理路径。

### P05 交通采购：将数量变更改成可核对的变更申请

页面：[交通采购共用页](../merchant/tour/resource-procurement-inventory.html)，三菜单分别为机票切位、邮轮包舱、专列包铺。对应核05。

资源采购／计调在已有合同详情“付款变更／发起变更”办理，影响团期分配及后续付款计划。保留已有合同、分期付款和资源分配，不增加采购一级菜单。

| 抽屉内顺序 | 具体修改 |
|---|---|
| 1. 原合同与本次变更 | 原数量、规格、单价、已分配和已售只读；填写变更后数量与依据。多舱型／铺型显示逐规格编辑行，不能只给一个总数量 |
| 2. 分配影响 | 显示变更后有效数量、已分配数量、剩余可分配量及受影响团期；核对已分配内的已售占用，不把两者重复相加 |
| 3. 冲突处理 | 变更量低于有效分配或已售时，列缺口和涉及团期；允许保存为待处理申请，不允许直接显示生效。经办从现有分配／团期入口解决后再提交确认 |
| 4. 付款影响 | 按规格和节点分别显示原计划、本次变化及变更后计划；未付金额可以为0，已付款仍保留原记录。补付、待抵扣、待退回分别说明，不把减量自动当可退款 |
| 5. 提交变更 | 无冲突按现有批准流程承接；有冲突保留待处理及原因。变更前后和批准依据留在原变更记录中 |

验收示例：100座已分配60且其中已售40，改80后未分配20；改50缺10个已分配座位，不能直接生效。原来10位每位1000元、尚未占用和付款，批准全退且无损耗的示例减为0，未付节点为0，不能回退为原10000元。

多规格再验：A舱10间×2000、B舱5间×3000，改A舱8间、B舱4间，示例资源金额28000；不能按A舱单价算全部。实际押金、免费退回及损耗条款按合同，超分配损失谁承担待确认。

### P07 团期结算：同一页分四个已有处理区修改

计调在此维护本团成本、核对供应商费用、发起付款及结算；财务接收已确认依据。最高频任务仍是成本维护和提交，不能把四项需求变成四张新的说明卡或四套表单。

| 已有区／拟补位置 | 具体页面修改 | 完成后的承接 |
|---|---|---|

| 原付款申请抽屉“公司协议与付款责任依据” | 保留核01已完成内容；本次申请额、原成本及协议清楚对应，历史协议到期不抹掉已发生应付 | 审批后交财务付款，不在此显示银行已经付款 |

### P08 预订填写：确认价格、占用渠道和供给条件

### P09 订单详情：分别修改四个处理区，原订单保持完整

页面：[订单详情](../merchant/sales/orders-detail.html)。对应核02、06、07、10、13。

销售负责游客选择、客户确认、改价及售后发起；计调核价／核资源，财务确认资金。订单详情聚合当前订单的处理依据，下游执行仍归原岗位。

| 页面处理区 | 字段和动作的具体修改 | 异常与下一步 |
|---|---|---|
| 游客资料→现有游客编辑 | 增加该游客“签证办理方式”，候选只来自产品允许方式；同订单每人分别选。已有代办任务时查看任务阶段再变更，保存变更原因 | 已送签或已发生费用不得直接删任务；交签证／计调处理，若改价走应收调整，不因自办自动减钱 |

| 售后→转款申请 | 目标订单由自由填写改为可核对的订单选择；新增原收款选择。显示原／目标订单收款公司、客户、门店、待收额及可转额，经办填写本次金额和理由 | 不同公司或客户不直接按普通同主体转款完成；交现有审批／财务核对，待批准路径明确。目标已取消、原款不足等就地说明，不能提交成功 |
| 关联记录 | 原订单、原价格、应收调整、供应回复、转款申请及结果各有原记录；查看下游单据沿既有详情关联区域 | 关闭申请、退回补充不删除原金额；下游办理页不是订单页再做一次财务操作 |

### P15 供应商账单：先挂接来源，再核对差异

页面：[供应商账单](../merchant/finance/finance-supplier-bills.html)。对应核09，建议首个实施位置。

| 原操作／区域 | 必须替换或补齐的内容 |
|---|---|
| 挂接处理抽屉 | 原账单公司、供应商、币种、期间和金额只读；选择相应公司／供应商的成本明细，展示所选成本合计及差额。同名供应商的其他公司成本不能当普通匹配项 |
| “确认挂接” | 只保存本账单与所选成本的关联；**删除把账单金额写入系统成本、把差额设0的处理**。挂接后仍展示双方金额和差额 |

| 退回业务核实 | 填写差异涉及的成本项、原因和经办人；返回原成本处理，不在财务挂接抽屉直接改采购事实 |
| 引用批准调整 | 选择已有批准依据，展示原成本、本次调整、调整后成本；不能让“已批准”成为无金额依据的普通勾选项 |
| 确认核对后的详情 | 显示采用的账单版本、成本与调整依据及未处理差额；未获处理的差额继续存在，不能显示全部一致 |

验收：原成本80000、账单82000，挂接后差2000；批准增加1000后当前成本81000、仍差1000，原80000及调整1000均保留。没有批准依据不能通过改账单合计把差额抹平。此项可独立修改，不等对账发起方向确定。

### P18 认款复核：确认本次分配，剩余资金按已有去向处理

### P19 转款处理：申请金额、实际转款和冲正各留一份依据

页面：[转款处理](../merchant/finance/finance-transfer-records.html)。对应核13。

财务核对P09来源申请，确认原款能否用于目标订单；转款改变款项分配，不改变银行实际收到的钱。原审批流程保留，自动审批范围待确认。

| 处理区／动作 | 具体修改 |
|---|---|
| 转款详情 | 左右或上下列原订单／目标订单，两边分别显示收款公司、客户和门店；原银行流水及已分配记录单独列出，不能只显示一个笼统公司 |

| “确认核销” | 本次转款金额不得超过可转额；公司／客户异常须已有适用批准或改走允许路径。普通转款不直接解决跨公司资金责任 |

## 八、财务：付款、退款和供应商退回

<a id="p20"></a>
### P20 退款执行：执行退款不能代替应收调整审批

页面：[退款执行](../merchant/finance/finance-refund-execute.html)。对应核10。

出纳依据已批准退款及原收款执行，收款会计核对资金，业务应收调整仍来自原批准单。保留现有退款、回单及失败处理入口。

| 位置／动作 | 具体修改 |
|---|---|
| 原款及退款依据 | 查看本次批准退款范围、所对应的原收款及其实际可退余额；多次退款要扣除已退与有效占用，不能按合同原价无限重退 |
| 关联应收区域 | 显示原应收调整单及其实际批准状态；**删除用退款主状态推断“已冲销”的处理**。没有调整依据就不标已完成 |

| 结果未知 | 在原执行详情提供“核查结果”的处理，不将超时直接当失败再付；核实明确未退后才按批准流程重试 |
| 客户退回结果 | 明确累计已退及剩余待退；供应商是否追回在关联售后／追款记录查看，不由退款按钮抹平供应商余额 |

验收：应收减价5000已批准，但退款申请被退回补充，仍可看到减价依据及尚未实际退款；反之没有应收调整依据不能冒称已冲销。退款5000首次失败、第二次成功，保留两次，累计实际退款只计5000。

### P21 付款执行：付款结果和回单处理分开

页面：[付款执行](../merchant/finance/finance-payment.html)。对应核10。

出纳接收已批准付款申请，完成实际支付并交回单核销。申请批准不是钱已付，银行受理也不是最终支付成功。

| 现有动作／区域 | 具体修改 |
|---|---|
| 执行抽屉的依据 | 保留申请、采购公司／付款责任、付款金额、账户和成本或预付依据；不在付款时重新选另一供应商协议 |
| “提交银行” | 演示为已提交／待结果，不增加实际已付；本轮不要求连接银行 |
| “登记已付款” | 输入实际支付日期、金额、原交易依据及确认人；按财务批准的有效证据确认。与后续回单状态分别表达，不能仅凭按钮名称确定最终制度 |
| “上传回单” | 关联到已经发生的那次执行，补材料并转待核销；不再新增一次支付，不将上传日期替换实际支付日期 |
| 明确失败→重新付款 | 留原执行记录，新一次付款另有结果；审批申请金额和原失败依据不能被新记录覆盖 |
| 结果未知 | 保留待核查的这次执行，核查后显示成功或明确失败；不能以重复点击解决未知状态 |

验收：申请60000，第一次明确失败、第二次成功，则实付60000而非120000。后补回单不改变实付60000及原支付日。支付成功采用何种证据、是否需复核仍待财务确认，原型用明确给定的“已核实付款成功”样例演示，不代定制度。

<a id="p22"></a>
### P22 回单核销：复用原处理，只核对对应的实际支付

页面：[回单核销](../merchant/finance/finance-remittance.html)。对应核10。

财务核销人员核对P21的支付与回单，不再次执行付款。此页主要是承接约束与回归，现有表达已经满足的部分不用改。

| 现有处理区 | 必须达到的结果 |
|---|---|
| 原付款／执行依据 | 明确核销哪一次支付、对应申请及金额；重试后的回单不能误挂首次失败记录 |
| 回单核对 | 本次回单金额和实际支付比较；不一致保留差异及核对去向，不能为匹配而覆盖原支付金额 |
| 确认核销 | 只改变回单核对结果；原实际已付不重复增加，实际支付日不改为核销日 |
| 退回或补资料 | 原支付和回单记录仍在；“材料待补”不等于付款没发生，也不反向改业务成本 |

验收：实际付款60000，核销后仍已付60000；回单59000时显示1000差异待核，不直接把付款改59000。若当前区块已能正确演示，仅补配套样例并回归，不增加新表单。

### P23 预付管理：申请退回与实际到账不能用同一个结果

| 现有区／拟补内容 | 具体修改 |

| 已结清判断 | 原预付的实际抵扣、实际退回及其他获批处理合计核对后才说明结清；客户退款不单独决定本账户结清 |

### P24 付款退回：保留尚未到账的供应商退款及部分处理

| 当前错误示例 | 原借297800、贷441600，改为校验不通过并显示差143800；保留原业务来源，不为凑平新增无依据科目 |
| 行“推送”与批量推送 | 使用相同校验结果；不平或关键依据缺失不能点击后显示成功。批量含失败项时显示哪些未通过，不一键全成功 |
| 补正处理 | 原凭证返回财务补充核算依据；获得完整、经确认凭证后重新核对。原错误及补正记录可查，不直接在推送页改采购事实 |
| 正常样例 | 采用既有完整、平衡且来源明确的凭证，演示校验后进入推送结果；注明实际接口不属于本次建设 |

验收：上述差143800的例子不能推送；一笔已确认应付付款60000的完整平衡示例按批准分录可通过。平衡只是必要条件，不代表财务科目、公司或期间已自动正确，也不在本方案自定会计分录制度。

<a id="p26"></a>
### P26 期间关账：检查的是未解释差异，不要求所有资金余额为零

页面：[期间关账](../merchant/finance/finance-period-close.html)。对应核14。

总账人员在本公司本期间核对资金、往来、业务结算及会计记录。现有关账、检查、反关入口保留，只纠正检查分类及最终放行条件。

| 页面位置 | 具体修改 |
|---|---|
| 检查明细 | 原待收款、预付未冲抵、待开／收票等不再仅凭“有数量／有金额”一律标阻断；逐条查看是否有依据、余额是否解释清楚、是否需批准跨期 |
| 分类结果 | 使用“正常余额、待核实、待批准跨期、阻断异常”等处理含义；正常余额继续保留来源及后续日期。分类需有理由或批准依据，不让经办任意改成正常 |
| “刷新检查／确认检查” | 判断未解除的阻断及必要批准，而不是所有提示条数都必须为0。仅有正常余额或已批准跨期事项时可进入下一步 |
| 关账确认 | 在最终按钮再次核对本次检查结果；有未解释金额差异、未通过凭证等阻断时不能只选一个确认下拉就显示检查通过 |
| 关账后查看及调整 | 原期间结果保留；后补费用沿已有调整／补结算或获批反关，不直接编辑已关账原记录。反关条件仍由财务确认 |

验收：一个未到期且依据完整的月结应收不要求先收齐；一笔正常待履约预付与同额无法解释差额得到不同检查结果。前者按已批准分类保留余额，后者未解决不能完成关账。待开／收票是否可跨期及重大性标准由财务确认，本方案不宣布全部放开。
