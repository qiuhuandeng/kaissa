# 对账到业务付款申请本单承接实施验收

日期：2026-09-26。接续[角色走查](同行结算角色操作路径与走查-20260926.md)的走查01，只补原业务付款申请工作区的本单承接。主要使用人是采购公司的计调，上游是双方已确认的对账及费用，下游是该公司付款复核岗。

## 一、入口及办理

入口：履约中心 → 团期结算 → 供应商对账 → 已确认单详情 → 付款申请。仍使用原付款工作区“待申请付款／申请记录”两个页签，无新增菜单。

1. 进入后仅显示本次对账、确认版本、采购公司、供应商及币种，不再展示另一套固定费用。费用详情带订单、团期、应结金额、预付冲抵、实际已付、原申请占用与可申请金额。
2. 计调选择本次费用、填写金额、期望付款日期及依据，可保存草稿、复开修改，再提交财务复核。多笔费用可只选其中一笔，不能把未选费用的金额平摊进申请。
3. 保存草稿不占用可申请金额；提交后显示“待财务复核”，下一办理人为本公司付款复核岗，去向为财务 → 成本应付 → 付款申请。此时只增加申请占用，不增加实际已付款、不表示审批完成。
4. 同页返回原对账再进入，已保存的草稿／提交记录仍保留。提交后该申请只读，重复提交被拦截；未保存退出可继续填写或放弃。

本例：应结101,000元 − 已冲抵预付30,000元 − 尾款实际已付50,000元 − 原占用10,000元 = **可申请11,000元**。未付21,000元中已有10,000元占用，不能再次全额申请。申请5,000元后尚可申请6,000元，实际已付仍为50,000元；申请11,000元后尚可申请为0。

同页刚核对完成的新账单也使用当前确认结果：DZ20260925001确认第2版后，62,000元和20,000元两项均可带入；只申请第二项5,000元，总剩余可申请77,000元。此处不依赖旧示例或地址中传入的金额。

## 二、校验与范围

| 情况 | 当前处理 |
|---|---|
| 未双方确认、错误或缺失版本、不存在的对账 | 拒绝申请，并显示原因，不回退到其他示例费用 |
| 跨公司／供应商／币种／协议、费用不属于本单或重复 | 拒绝保存或提交 |
| 实际服务或款项依据缺失、明细与汇总款项不一致 | 先核对依据，不默认为可付款 |
| 超额、零金额、无效日期、提交缺少依据 | 保留表单并提示，金额和记录不变 |
| 打开后来源金额／版本变化、重复提交旧记录 | 拒绝使用旧依据 |
| 未保存退出、窄屏操作 | 有退出确认；表格内横向滚动、操作列固定，抽屉可填写并提交 |

各页仍为独立原型会话。业务申请没有自动写入财务页、审批中心或银行；财务页已有的11,000元样例不是对任意新申请的真实自动接收，部分申请也不会自动替换该样例。刷新重新载入示例，不引入跨页存储串联。

当前新承接以“待财务复核”表达下一岗位；集团各公司应先业务审批还是先财务复核、票款顺序和例外仍待业务及财务确认。普通付款入口原流程保留，不把本例顺序宣布为全集团政策。走查02、03未在本步实施。

## 三、实现位置与验收

开发位置：

- `merchant/tour/fulfillment-cost.html`：原付款两个页签提供进入和返回方式，加载本单申请脚本。
- `shared/supplier-reconciliation.js`：确认单入口带当前版本；同页传递当前对账来源，支持刚确认的新账单；付款地址不误开对账抽屉。
- `shared/supplier-payment-request-model.js`：本单来源核对、可申请金额、草稿及提交记录。
- `shared/supplier-payment-request.js`、`shared/supplier-payment-request.css`：原工作区内的限定列表、申请抽屉和退出保护；专用样式由公共样式入口引入。
- 付款弹窗仅在进入本单工作区时挂入，返回对账时移除，避免隐藏弹窗影响原对账办理。
