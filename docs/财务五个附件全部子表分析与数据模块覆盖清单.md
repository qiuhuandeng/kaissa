# 财务五个附件全部子表分析与数据模块覆盖清单

## 一、结论先行

本次已直接读取 4 个工作簿的全部 93 个子表，包括隐藏表和空表；同时读取 Word 的 86 个正文段落、1 个产品类型表和 3 张嵌入图片。空表没有业务数据，但保留其表名和表头所表达的目标需求。

现有数据模块采用“5 类结果页 + 常用分析视图 + 来源核对 + 分类例外”的结构，不把 93 个 Excel 子表机械复制成 93 个网页：

1. 财务业绩明细：承接共同底表、来源字段和逐笔下钻。
2. 订单业绩：承接自然周、双周、月度同进度、年度累计、同比、环比和任务完成。
3. 回团业绩：承接实际回团、财务回团月份、跨年回团、待确认、回团后调整和任务完成。
4. 产品渠道人员：承接产品、旅游范围、业务类型、目的地、渠道、区域、人员及交叉构成。
5. 毛利预算异常：承接团队毛利、不含税毛利、单团利润、结算进度、返点、任务和异常。

页面结构已经能够容纳附件中的分析结果，但“能够自动算出并对账一致”仍取决于上游字段、发生时归属、有效订单、回团确认、收入成本、退款、返点、任务版本等规则落地。因此当前可判断为“分析页面覆盖完成，正式自动化尚未完成”，不能直接说已经完全满足生产使用。

## 七、财务分析习惯如何从 Excel 转成网页

| Excel 习惯 | 网页保留方式 | 不照搬的内容 |
|---|---|---|
| 多个周报、双周报和月报子表 | 顶部“常用分析视图”保存时间窗口与筛选组合 | 不为每个日期复制新页面 |
| 订单口径与回团口径分别做透视表 | 两个独立结果页，列结构尽量一致，并可共同下钻明细 | 不混成一个金额指标 |
| 当周、上周、当月、上月、上年同期、年度累计并排 | 指标卡、经营单位表和同进度说明中并排显示精确期间 | 不用模糊的“较上期”代替具体区间 |
| 透视表反复按渠道、门店、目的地、产品、人员切换 | 产品渠道人员页用维度切换和交叉构成 | 不复制十几张同结构表 |
| 透视表合计、检验和验算行 | 来源核对记录原始、排除、进入明细数量和金额差额；交叉构成显示平衡状态 | 不隐藏在辅助 Sheet 中 |
| 人工改目的地和自营外采标签 | 分类例外显示系统判断、人工调整、原因和版本 | 不允许静默覆盖历史 |
| 单独维护任务拆分表 | 预算任务区分订单任务与回团任务，并保留年度、月度、责任层级和版本 | 不把任务数字写死在报表里 |
| 指定活动或特殊来源另建底稿 | 作为来源、活动和特殊业务筛选条件 | 不长期复制临时表 |
| 每日刷新后邮件发送 | 订阅发送表达时间、视图、收件人、附件和生成记录 | 原型不真实发邮件 |

## 八、当前仍不能宣称“完全自动化”的原因

1. 有效订单状态、取消和退款在何期间冲减尚未由财务最终确认。
2. 实际回团日期、财务回团月份与结算确认的责任人及变更规则尚未完全落地。
3. 产品负责人、销售人员、销售组、渠道、门店和预算区域必须保留订单发生时归属，现有原型尚无正式记录。
4. 自营、甄选、外采和多目的地计金额规则仍有待确认例外。
5. 原表“收入”在不同来源里可能指供应商结算、业务收入或其他金额，必须拆开。
6. 实收、应退、已退、净收、供应商结算价、实际成本和财务确认收入仍需统一来源。
7. 不含税收入、成本、税额、返点和跨期调整规则尚未完整确认。
8. “未提交准单”在新系统中对应哪个正式业务结果尚未明确。
9. 订单与回团任务的下达层级、生效版本和调整留痕尚未形成正式功能。
10. 当前 HTML 是业务原型，只表达页面、动作、状态和下钻方向，不代表真实数据已经汇总生成。

## 九、验收口径

只有同时满足以下条件，才能对外说“财务五个附件的自动化报表需求已满足”：

1. 上述 93 个子表的用途均能在 5 类结果页或常用分析视图中找到，不丢失空表表达的目标需求。
2. 任一汇总可下钻到共同业绩明细，再回到订单、团期、回团确认、收退款、成本、结算和调整依据。
3. 自然周、双周、月度同进度、三年分月、同比、环比、任务完成率与原表选定样本一致。
4. 三套来源原始数量、排除数量、进入明细数量和金额能够平衡。
5. 分类例外、人工调整和规则版本可以查看，不会因当前主数据变化改写历史。
6. 订单任务与回团任务分别核对，年度任务与月度分解一致。
7. 毛利、不含税毛利、结算进度、返点、负毛利和待确认事项均有明确来源和状态。
8. 页面与正式导出在同一数据截止、口径版本和筛选条件下合计一致。
