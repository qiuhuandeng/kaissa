航服系统开发流程功能清单
第一部分：航服业务流程梳理
一、整体业务架构
航服（北京凯撒航空服务有限公司）作为集团内部的客票代理公司，具备 IATA 资质。整体业务由资源端（上游采购）和销售端（下游分销）两侧组成，中间通过 ERP 承接库存管理、订单管理、收付款、结算对账、发票管理等核心环节，最终数据推送至 NC 财务系统。

第二部分：ERP 系统功能需求清单
模块 A：库存管理
A1 支持系列位、单团位、包机位三种库存类型录入，允许 Excel 批量导入。
A2 库存录入时同时登记：航班号、出发/回程日期、往返航段、总位数、一压政策、二压政策、尾款时间点、单价政策（如经济舱加 50 元）。
A3 库存与团号解耦：先录库存，再按需从库存中拆分生成团号，避免"一次拿 20 套系列位要手工建 20 个团号"的问题。
A4 库存前置分配：录入时即可指定归属（部门/产品/计调），支持多级分配。
A5 库存状态可追溯：已分配、已出票、已退位、剩余可售、空置风险。
A6 一押/二押时间点自动提醒（航司政策到期前预警）。
A7 包机切位库存独立管理，支持余位二次分销。
模块 B：订单管理
B1 支持 BSP 散票、团队票、包机票三类订单的统一管理，统一入口。
B2 一次建单、字段齐全：建单时强制录入必要字段（航段、政策、预估成本、销售价），避免后期补录。
B3 BSP 订单支持多种建单方式（优先级从高到低）：
B3.1 白屏系统 API 接口直连（优先推进，待确认接口可行性）
B3.2 BSP 日报 Excel 日导入自动建单（一期必做兜底）
B3.3 IATA PDF 账单导入（后期对账用）
B3.4 截图识别 / OCR 建单（备选）
B3.5 PNR 转换建单（备选）
B3.6 手工录入（兜底）
B4 团队票订单与"团号"双向强绑定：集团内团号创建后航服团号自动生成，产品端的客人信息、金额、团期变动自动同步至航服订单。
B5 订单必备字段：航司订单号、PNR、票号、乘客（护照首页信息）、航段、舱位、票价、税费、政策扣点、销售价、毛利。
B6 一个团支持生成多条行程记录（联运、升舱场景可达 7-8 条）。
B7 自动识别国内/国际：按航段自动归类，无需人工选择。
模块 C：名单管理
C1 源头录入：销售端录入时即支持护照扫描 OCR 自动识别 + 手工录入。
C2 一处录入、多处调用：销售、计调、票务共用同一套名单数据，禁止重复录入和二次人工加工。
C3 名单支持联运标记、升舱标记、特殊餐食等扩展字段。
C4 按航司（国航、东航、南航、海航、法航、土航、卡航、阿联酋航空等）模板自动导出符合 B2B 系统格式的名单文件。
C5 按出发地自动拆分名单（如 7 个联运城市自动拆成 7 份 Excel）。
C6 计调通过"团号"认领名单，形成审计链条。
模块 D：收款
D1 支持公账转账 + 手工认款（线下兜底）。
D2 订单直收：生成订单时同步生成支付二维码/支付链接，发送客户随票付款，收款与订单自动绑定。
D3 支持多笔订单合并生成一个收款码/链接，客户一次支付，系统自动拆分认款至各订单。
D4 银企直连：银行流水自动匹配订单，实现自动收银确认、自动出纳审核。
D5 账期客户管理：维护信用额度、账期规则、逾期提醒。
D6 团队票支持一押、二押、尾款多次收款，每次收款与团号绑定。
D7 预付款池管理（如航司 B2B 平台的余额沉淀）。
D8 兼容"预收款后认"模式：客户先打款、订单后建的场景可先入预收款池，后期关联订单认款。
模块 E：付款
E1 收付款统一到航服资金模块下，不再分散在多个入口。
E2 预付款 vs 付款自动判断：系统根据供应商类型（航司 B2B 预充值账户 / BSP 账期 / 票代随结）自动决定走预付款池还是即时付款。
E3 IATA 账期自动归集：扣款日前 N 天，系统自动汇总待付 BSP 清单并推送审批。
E4 B2B 航司平台充值、扣款、退款全流程记录。
E5 第三方票代付款与成本票（进项专票）核销绑定。
E6 包机付款与航司直签协议匹配。
E7 付款发起 → 审批 → 执行全线上化，禁止线下口头确认。
模块 F：结算
F1 一团一结：不完全依赖航司账期，支持业务侧提前结算。
F2 "准单"概念：每个团号下总览应收/实收、应付/实付、费用调整、单团毛利。
F3 结算单自动生成：BSP 日报导入或白屏接口对接后，结算单自动生成，操作员只需审核确认，无需逐单补录。
F4 票号自动灌入：对接白屏接口或 BSP 日报后，票号自动回填。
F5 利润自动计算：成本和销售价字段齐全后，利润由系统自动计算并校验，杜绝人工录利润的错误。
F6 自动匹配团号：BSP 票通过 PNR / 票号 / 乘客信息自动匹配至对应团号，匹配不上的进入"待匹配池"由人工处理。
F7 一次提交、财务直审：改为一步提交并自动流转至财务审核队列，去掉冗余的二次确认动作。
F8 BSP 日报 + IATA PDF 账单双向校验，自动提炼差异数据。
F9 B2B 平台按航司订单号与系统订单对账，提炼"已出未提结算"数据。
F10 内部结算强推：航服收入 = 产品端成本，金额强一致，禁止产品端手工维护大交通成本。
模块 F+：变更单 / 退票（结算模块的子功能）
F11 退票与退款合一：订单上一键发起退票，系统自动联动：
向航司/BSP 发起退票（成本侧）
向客户生成退款单（收入侧）
两侧状态在同一界面可见
F12 变更单不限次数，统一管理退票、改签、升舱、联运差价、ADM 调整。
F13 退票产生的 ADM / 定损费用自动挂到原订单下，不新建"费用订单"，便于利润还原。
F14 结算完成后财务数据锁定；如需二次变更，走财务解锁流程。
模块 G：发票管理
G1 独立发票工作台：从订单发起开票申请，审批流独立于收款流程。
G2 销项发票：按订单维度申请，支持单笔或多笔合并开票。
G3 发票申请走审批流，开票后票号回填系统。
G4 进项发票：登记供应商（航司、票代）成本票收回状态。
G5 发票报表：已开/未开、已收/未收，按客户和供应商双维度监控。
G6 全额计税场景：机票打包至产品公司按旅游产品整体开票的逻辑支持。
G7 预收款自动标记"待开票"状态，推送至财务侧跟进。
模块 H：对账与校验
H1 BSP 对账：日报与 IATA PDF 账单自动比对，差异标记（主要是退票差异、ADM）。
H2 B2B 对账：以航司订单号为唯一键，比对系统订单 vs 航司平台订单。
H3 银行对账：银企直连流水与系统收付款记录自动匹配。
H4 内部对账：航服订单 vs 产品端团号成本，金额不一致自动告警。
模块 I：外部系统对接
I1 白屏系统（中航信）：优先推进 API 接口对接，由航服方（李雪）联系供应商确认可行性与费用。
I2 航司 B2B 官网：国航、东航、南航、海航、法航、土航、卡航、阿联酋航空——至少做到按航司模板导出名单文件，长期目标是接口直连。
I3 IATA PDF 账单：PDF 解析/OCR 导入。
I4 银企直连：实现收付款自动确认。
I5 NC 财务系统：业务凭证按科目规则自动推送。
I6 凯撒内部系统：与销售端、计调端、产品端打通，共享客户/名单/团号数据。
模块 J：客户与供应商管理
J1 客户分类：内部（呼叫中心、门店、产品公司、计调）vs 外部（同行旅行社、企业客户、散客）。
J2 外部客户区分月结、预付、现结三种结算模式。
J3 供应商管理：航司、第三方票代、IATA 分别维护账期、信用、政策。
J4 客户/供应商维度的应收应付汇总表、逾期报表。
模块 K：权限与审计
K1 操作留痕：所有减员、加员、升舱确认、价格调整均在系统内完成，形成"纸面证据"，取代微信口头沟通。
K2 三级角色分离：票务录单员（建单+结算录入）、票务主管（审核）、财务（终审+凭证）。
K3 关键字段锁定：计调确认后票价锁定，变更需走审批。
K4 所有变更（金额修改、退票、改签）强制留痕，操作人、时间、修改前后值可追溯。
模块 L：报表
L1 BSP 日报、BSP 对账报表。
L2 团组毛利分析表。
L3 应收/应付汇总表（按客户、按供应商、按团号）。
L4 未提结算明细表。
L5 逾期账款表。
L6 发票开具/收回状态表。
L7 库存使用率 / 包机空置率报表。
