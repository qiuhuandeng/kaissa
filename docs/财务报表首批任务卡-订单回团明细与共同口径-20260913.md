## 二、业务链路与当前证据

订单明细主要由财务分析和授权销售负责人使用，高频任务是解释本期成交由哪些销售内容构成、归哪个公司和部门、哪些调整影响本期。上游为订单确认、发生时归属及生效变化；下游供经营总览、产品和渠道分析核数。报表查询不改变订单状态，错误事实由来源业务负责人更正。

回团明细主要由财务分析、结算会计和授权履约负责人使用，高频任务是查清实际完成、未结算、财务资料缺失与未来安排。上游为实际回团、离船、服务完成或项目验收及其金额分配；下游供回团业绩、团期盈利和核算对照。确认履约在履约模块，确认收入成本在财务模块，均不迁入报表。

以下冲突按本卡处理并回填主对照表：

1. 旧字段字典有“主表默认已确认”“点击下钻”“同一订单展开”等历史表达。本批依当前进度与新页面方案，实际完成包含待结算，明细直接列示，无下钻；不因此全面重写旧字典。
2. 下单样例仍包含固定公司、按门店名称推分公司等演示逻辑。只能证明字段位置存在，不能当正式组织对应依据；报表不得复制这些推断规则。
3. 当前订单查询对“全部”状态可能混用确认日期与创建日期，但标题只写确认日期。第一小批必须明确日期依据，不继续用创建日期兜底确认日期。
4. 当前财务确认视图实际按完成日期查询完成业务，并非按会计期间查已确认收入。第二小批仍定位“财务确认资料”，不把它改名包装成正式收入报表。
5. 当前完成样例根据计划日期与演示截止生成实际日期。第二小批改为显式给出完成事实；保持原验收金额，增加计划到期但未确认的独立测试，不把演示生成方式移植成业务规则。

## 三、两份明细共同要求

### 1. 记录、金额和期间

| 项目 | 本批约束 | 待确认/后续依赖 |
|---|---|---|
| 订单行 | 一行是一项可独立确定数量、成交和归属的销售内容；变化视图一行是一笔生效变化 | 正式接入需销售内容对应关系，不能只按产品名称匹配 |
| 回团行 | 一行是一项销售内容的一次完成分配；部分完成不复制整单金额 | 不同业务的完成条件与分配依据由业务、结算负责人确认 |
| 对客成交 | 同一客户订单的销售内容只计算一次；销售公司和产品公司是两种观察方式，不相加 | 集团范围、内部贡献和法定合并政策另待财务确认；内部结算不追加对客成交 |
| 金额名称 | 原成交、生效增项、生效减项、净成交额、实际完成分配成交额分别列；实收、已退款只作独立核对 | 主考核金额和减项期间待确认；不得将这些列统称收入 |
| 收款分配 | 只有已明确分到当前销售内容的金额才进入该行；只有整单金额时标“未分配到销售内容” | 不按成交比例自行分摊，不重复整单收款；历史余额另由财务收付报表承接 |
| 订单日期 | 默认按确认日期；可选按创建日期查源记录。选未确认状态时明确改为创建日期；选全部状态也必须使用一种明确日期依据 | 变化视图只用变化生效日期；未确认金额不计净成交，未知确认日不作日期推断 |
| 履约日期 | 实际完成用实际日期，未来安排用计划日期；缺实际确认不能因计划到期自动纳入 | 完成事实和财务收入成立不是同一动作 |
| 管理月/会计期 | 回团管理月是管理统计归属月；会计期间是财务记账归属月，二者不同 | 26日至25日继续只作已标明的演示规则；未定周界/双周起点不新增伪正式标签 |
| 数量 | 订单单数去重、销售内容/完成记录条数分别展示；人数、张、间夜等分单位合计 | 当前“服务项”样例不是游客人数；分次完成条数不能当独立游客数 |
| 币种 | 本批仍只提供人民币元/万元；真实原币与折算依据有来源再显示 | 不提供无依据汇率或跨币种合计；单位切换不改变原始金额 |

### 2. 归属字段与来源责任

所有“发生时”字段在本批演示中采用订单确认时归属，正式历史考核仍待确认；归属变更不得通过当前员工名册悄悄覆盖旧值。产品版本是当时采用的产品资料，归属版本是当时采用的组织/渠道规则，二者分开。

|---|---|---|---|
| 销售公司、销售分公司、销售事业部、销售部门 | 组织与员工任职资料，订单确认时销售核对 | 销售公司保留常用；其余可选列，事业部/部门进更多筛选，按选定销售公司限制选项 | 未设事业部可不适用；未查到关系为待补充，不由部门名称猜公司 |

| 销售部门领导、产品部门领导 | 组织负责人任命及生效期；组织维护人员确认，订单保存发生时结果 | 分别可选列及更多筛选，不设含义不明的统一“部门领导”；姓名旁可按需配所属部门 | 不是销售顾问、产品负责人、审批人或店长的替代字段；无正式记录待补充 |

### 3. 财务标识只读，不替财务作结论

若未来同一销售内容包含不同收入方式或税务处理，订单页摘要应为“多种处理”，不能取第一条确认结果冒充全部；具体组成在财务确认明细按记录列示，原成交金额不随确认条数复制。该多条确认结果计算留后续财务批次。

### 4. 缺数、权限及导出

“待补充”表示应有业务资料但缺来源；“待确认”表示规则或财务结果尚未确认；“未分配”表示有上层金额但没有当前行分配；“不适用”表示业务明确不使用该字段；数值0仅代表已知为零。导出保留同样区别，不把空值一律转0。

两页增加“资料情况”更多筛选：全部、经营归属待补充、分类待确认；回团财务资料另可筛收入/成本确认记录未提供。缺数条件是字段缺口，不是人工催办。筛“全部”时未知归属不能消失；筛具体组织时只纳入已明确属于该组织的记录。

金额合计应同时说明已知金额合计、金额待确认条数、未分配条数；全部未知时显示待确认，而不是0。未确认订单的预留额与净成交合计分开；财务资料缺失不影响已实际完成的成交分配额保留。

字段选择不是权限设置。集团财务看授权集团范围，公司/部门/门店负责人看获授权范围；是否允许跨销售/产品公司查看及人员领导字段权限，交由财务与组织负责人批准。当前静态原型不使用真实敏感数据，不宣称已实施访问控制；正式服务必须同时约束页面、筛选选项、明细、导出和订阅，不能仅隐藏列。

导出继续生成当前已查询结果的全量文件，不只导出当前页；列与已选字段一致，业务主识别字段不可全部取消。文件包含报表名称、日期依据/起止、已查询筛选、币种单位、业务截止、演示或发布版本、口径待确认标识。未查询的新条件、未适用的日期条件不得进入导出摘要；显示名用业务中文，不导出程序字段名称。下载不代表正式发布。

## 四、第一小批：订单明细怎么改

### 页面布局与操作
