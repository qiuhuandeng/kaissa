# 报表管理基础版原型验收记录

日期：2026-09-14。范围：整体计划阶段2、小批顺序第3项，P8基础版。结论：本小批原型通过；不代表正式财务规则、自动取数、审批、权限或发布已经完成。

## 一、角色和业务边界

入口：数据中心 > 报表管理 > 口径与数据核对，页面为 `merchant/data/report-management.html`。

主要使用者是财务报表管理员、数据维护人员，日常任务是核对缺失资料、找到来源及负责角色、维护报表分类与组织对应的生效期间。上游是业务分类、组织与人员任职、订单发生时归属、实际完成及财务确认记录；下游是经确认后供经营报表使用的对应规则。业务事实由来源角色维护，收入与成本确认仍由财务处理，管理员不能直接改报表金额。

本轮依次完整阅读四份控制文档，盘点数据页面、导航、共享脚本，与P8设计及整体计划成对核对；复核业务组织、员工任职页的组织调整、生效日期、历史任职及原订单归属表达。不重建组织树，不读取或改写这些源页面的演示记录。

## 二、页面检查清单

| 检查位置 | 本批完成内容 | 验收重点 |
|---|---|---|
| 数据核对 | 订单明细与实际回团明细分别查询；日期、销售公司、核对字段、金额单位筛选 | 订单按确认日期，回团按实际完成日期；不把计划到期视为完成 |
| 字段核对 | 销售部门领导、产品负责人、主目的地、管理分区、经营分类、预算区域；实际回团另核对财务确认收入和成本 | 列出缺口条数、涉及成交额、负责角色及核对资料；不推填未知资料 |
| 缺口明细 | 订单号、销售内容编号或完成记录号、销售内容、业务日期、缺口字段、资料情况、成交额和来源责任 | 一条业务可有多个缺口，成交额按业务去重，不将各字段金额相加 |
| 分类规则 | 地理分区、管理分区、渠道分类、预算区域、经营分类 | 引用已有演示来源候选，不要求财务逐单打标签；未确认分类不能成为正式规则 |
| 组织对应 | 销售组织、产品组织、核算部门分开；显示适用公司、对应结果和来源 | 核算主体是独立记账单位，核算部门资料未提供，不以销售公司或业务部门替代 |
| 生效期间 | 开始日、结束日、版本、依据、维护原因；按适用日期查版 | 校验真实日期、前后顺序及同一来源期间交叠；原版本只读，新建变更不覆盖历史 |
| 主状态与操作 | 草稿：编辑、提交、作废；待确认：查看、撤回；演示参照：查看、新建变更；已作废：查看 | 提交需对应结果和依据，无批准按钮；同状态动作稳定，不由缺口类型生成按钮 |
| 编辑与记录 | 当前页二级编辑区，保存草稿、返回、未保存离开确认；保留本次维护记录 | 不跳转下游业务页，不生成正式审批、订单、应收应付或财务确认记录 |
| 查询与导出 | 排序、分页、重置、空态、日期校验、全查询结果导出 | 未查询条件不进入排序、分页或导出；文件包含已查询范围、单位、截止日和演示标识 |
| 页面布局 | 三页签、直接表格，无统计卡；主状态前移、右侧操作固定176像素 | 多余宽度给来源名称，表格内横向滚动；极窄容器解除固定避免完全遮挡业务信息 |

演示维护记录只保留本页本次会话，重新进入恢复；不改其他报表结果。既有资料统一称“演示参照”，没有把未提供批准记录的资料标为“已生效”。“重新检查”只复核已查询演示样例，不伪造正式来源刷新成功。

## 三、设计取舍与未完成范围

P8原设计包含来源更新、统计日历及发布记录，是完整目标，本次按整体计划阶段2收缩为分类、生效期间、组织对应和缺数核对。生效期间不是正式周报日历；未伪造更新成功时间、正式原始/排除数量、日历批准或发布记录。正式来源的重复排除、更新失败保留上次结果、日历断档与跨年双周、发布更正、订阅及权限留后续阶段。

实际只改新页、新页脚本、必要导航、报表局部样式、共享演示资料读取入口、测试和文档。现有四张报表的计算与业务金额不变；团期订单、产品、销售、履约、组织及财务源页面均未修改。
