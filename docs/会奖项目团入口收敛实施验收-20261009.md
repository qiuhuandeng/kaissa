# 会奖项目团入口收敛实施验收

日期：2026-10-09。状态：本次入口调整已完成并验收。执行依据为用户对“项目团内又有项目团／负责项目”的反馈及后续“执行”。本次只修正履约入口层级，原第4步任职、汇率及完整结果输出继续待执行。

## 一、业务位置与产品判断

上游由销售或项目负责人在产品中心的单团项目建立客户大项目、维护框架与人员分工。计调的高频任务是找到具体活动、建团并办理执行；将上层项目与活动并列成两个页签，会迫使计调先猜在哪一层操作。履约中心因此只保留项目团列表，所属项目作为筛选条件和建团必选项。建团后仍是同一场活动，进入项目团详情办理原执行、采购、客户款项和结算核对。

单团项目继续承担客户框架、项目分工与整体查看；项目团承接各场执行。没有增加新菜单、HTML页面或中间选择页面，没有改成“大团嵌小团”。原7大痛点整体交付不因本次入口修正而自动标为完成。

## 二、实际操作

| 任务 | 页面操作 | 结果与边界 |
|---|---|---|
| 日常找活动 | 履约中心 → 项目团；按所属项目、计调、执行状态及日期查询 | 直接列具体活动；取消项目团／负责项目两个内部页签；计调仅看到本人活动 |
| 已授权但还没有活动 | 在所属项目筛选中选择该项目，或直接点击新增项目团 | 零活动项目仍可选择，不必先让销售造一个空活动 |
| 新增一场 | 新增项目团 → 在同一抽屉选择所属项目 → 填活动资料 → 保存草稿或提交核对 | 未指定项目时不默认第一条；当前筛选项目具备建团权限时可预选；选择后带入客户、公司及本人分工 |
| 操作人员自主建场 | 选择本人有有效建团分工的项目 | 主责计调自动带本人且不可改；负责事项带入，唯一城市及服务类型自动带入；日期、城市、服务范围沿用校验 |
| 批量建立 | 批量建团 → 同一抽屉选所属项目 → 导入CSV／粘贴表格 → 预检 → 明确选择仅保存有效草稿 | 项目内逐行校验并保存独立活动；计调留空带本人，不能为其他人越权建场 |
| 更换所属项目 | 新建或批量抽屉更改所属项目 | 有未保存内容时确认清空；取消则保留原项目和内容；确认后清空输入、导入和预检结果，重新带分工；不套第二层抽屉 |
| 批量维护和报价 | 列表筛选一个所属项目 → 勾选本页或当前筛选全部 → 批量维护／批量报价 | 保留跨分页选择、逐行预检、报价草稿与确认金额区别；改变查询条件时清空原选择，防止隐含跨项目处理 |
| 进入具体活动 | 点击项目团名称或详情 | 原五页签保持；返回保留所属项目等筛选，不再出现负责项目页签 |
| 分工已结束或无权访问 | 可继续查看本人已有活动；新增下拉仅列当前可建团项目 | 打开和保存重验；没有任何可建团项目时新增／批量入口禁用；跨公司或未委派项目直达为空态并能返回 |
| 原地址访问 | 打开旧负责项目地址 | 正常列表移除旧视图参数并显示唯一项目团列表；不保留旧上层项目页面 |

当前项目采购台账入口保留。详细采购在原项目团详情费用采购中办理；此次不新增采购工作区或改写税费逻辑。

## 三、页面规范

列表没有额外页标题及内部层级页签，采用既有搜索区和操作区。表头明确“项目团／编号”“所属项目／客户”；操作列固定168px，项目名称保留足够宽度，横向滚动限制在表格内。选定项目后才出现批量选择工具。

新建采用餐厅库同一套640px普通抽屉，批量采用既有920px宽抽屉。所属项目放在首个分区，选择后原位展开表单；蓝色分区标题、双列字段、底部固定按钮、无卡片套框保持。
