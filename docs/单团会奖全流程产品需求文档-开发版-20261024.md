## 1. 先理解业务怎样走通

### 1.1 四个对象，分别解决四件事

| 对象   | 业务含义                         | 关键关系与金额                                    |
| ---- | ---------------------------- | ------------------------------------------ |
| 项目   | 客户的一次整体委托，例如“华远保险年度奖励旅游”     | 保存客户、销售、执行公司、总合同、费用预算；可包含多个项目团             |
| 项目团  | 一次实际交付，例如“厦门60人奖励游”“11月北京会议” | 独立维护日期、人数、计调、执行、承担费用和结算；不是一张订单             |
| 客户订单 | 客户已经同意购买的服务及成交价款             | 可以一团一单，也可以一单覆盖多团；当前首次成交范围内，一个团不能重复关联两张有效订单 |
| 采购费用 | 向供应商购买服务形成的一笔成本              | 可以由一个团、多个团或项目整体承担；成本分配、申请付款及结算均引用这笔原费用     |

年框合同500万元，不代表已经成交500万元；团费用预算8万元，不代表售价8万元；支付采购款，也不代表新增了一笔成本。

“新增单团”是便捷入口：在一次操作中创建项目资料和首个项目团。业务人员不用先跑两张表，系统仍保留项目与团的关系，后续可以继续追加团。

### 1.2 完整业务流程与页面对应

本表先把立项、预算、建团、成交、执行采购、收付款、结算及结项串起来。开发据此找到办理页面，再阅读对应页面章节的具体功能规则。

| 业务环节    | 使用人及办理页面                    | 核心操作与规则                                    | 办完交给哪里                         |
| ------- | --------------------------- | ------------------------------------------ | ------------------------------ |
| 客户立项    | 销售；单团项目列表                   | 新建项目，关联合同、登记成员；一次性业务通过“新增单团”同时填写客户、项目及首团资料 | 项目详情准备具体场次，规则见第2节              |
| 预算分工    | 项目负责人；项目列表→分工额度             | 设置项目费用预算、公共预算、人员额度；后续成团、确认费用、移交和结算共同使用     | 各团在额度内办理，预算占用与释放见第2.3节         |
| 创建项目团   | 销售／操作；项目详情→项目团              | 单个或批量建团，确定日期、人数、计调及团预算；草稿与正式成团分开           | 团控开始执行准备，规则见第3、5节              |
| 报价、登记成交 | 销售；项目详情→报价／创建订单             | 报价可选，不自动产生订单；客户谈妥后统一建单，支持分别成交或整包成交         | 原订单核价、收款计划、款票办理，规则见第3、4节       |
| 执行交付    | 计调；项目团控及执行详情                | 安排行程／议程、名单、签证、资源和执行准备，最后确认实际服务完成           | 客户认可及团期结算，执行规则见第5节             |
| 采购费用    | 操作；项目采购／统一新增费用抽屉            | 登记线下采购结果，确认含税成本，明确单团、跨团或项目承担               | 付款申请及成本结算，费用规则见第6节             |
| 客户收款、开票 | 销售发起、财务办理；原订单→认领／开票申请       | 申请与实际结果分开；财务确认后才增加已认款，开票成功后才增加已开票          | 原订单、团控及结算引用结果，规则见第7节           |
| 供应商付款   | 操作请款、财务复核及付款；履约付款申请→原财务页面   | 按项目集中选择采购及各团金额；实际付款不重复增加成本或占用预算            | 原费用保存已付、未付及申请结果，规则见第8节         |
| 业务结算    | 销售登记客户认可、操作提交结算；客户结算确认→团期结算 | 核客户认可、订单收入、费用承担、税额及遗留款项；分清团费用与整包订单范围       | 财务核项目汇总、继续处理未结款票，规则见第9、10节     |
| 项目结项    | 项目负责人；项目列表→结项检查             | 核全部团、订单和公共费用；按批准范围登记遗留事项                   | 项目归档，批准保留的尾款、票据继续从原单办理，规则见第11节 |

**报价、执行、采购可以交叉进行；收付款不必等全部结算完成。** 成团表示进入执行管理，创建订单表示登记客户成交，结算表示核对本次业务金额及依据，三者不互相替代。订金可在执行前收付，尾款可在结算后收付。供应商询价和客户议价在线下进行，系统登记结果及依据。

### 1.3 状态分别由什么决定

| 对象   | 状态如何变化                                               | 不应发生的联动                        |
| ---- | ---------------------------------------------------- | ------------------------------ |
| 项目   | 新建项目：草稿→待确认→进行中；新增单团可直接建立进行中项目；结项申请后待结项→已结项，退回则恢复进行中 | 不取所有子团中“最大”的状态；一个团完成不等于项目结束    |
| 项目团  | 草稿→确认成团→进行中→确认完成→已完成；取消生效为已取消                        | 进行中包含出发前准备；建订单不等于已完成；收齐钱不等于已结算 |
| 客户订单 | 未建单→有效订单；按实际数量成交先待最终定价，核价后确认金额                       | 报价不自动建单；待最终定价也是已有订单，不能再首次建单    |
| 业务结算 | 未结算→草稿→审批中→已确认；退回后修改原申请重提                            | 团已完成不等于结算已确认；款未付清不自动阻断全部业务结算   |
| 款票单据 | 申请、审批、实际成功分别记录                                       | 提交认领不等于已认款；批款不等于已付款；申请开票不等于已开票 |

同一项目下有草稿、进行中、已完成团时，项目仍为进行中。全部团完成后也不自动结项，要继续核整包订单、公共费用及遗留款票。

**调整要求：** 父项目草稿／待确认时可以准备子团草稿，正式成团前须完成原项目启用；不得出现父项目仍未启用、子团却已经正式履约的矛盾。新增单团默认一次启用项目和首团；勾选草稿时两者暂存。

## 2. 单团会奖｜单团项目列表

页面：[product-custom-list.html](../merchant/tour/product-custom-list.html)。销售或项目负责人在此管理整个客户委托。针对整个项目的操作放列表“更多”；详情以项目团操作为核心，不再重复放一套项目级按钮。

### 2.1 新增单团、新建项目、维护项目【沿用】

**新增单团：** 在同一抽屉填写客户及项目资料，再填写首团日期、地点、人数、计调、建团模式、费用预算等资料。保存默认生成一个进行中项目和一个进行中团；勾选“保存为草稿”则两者为草稿。取消不留下半个项目，重复提交不重复创建。成功进入原项目详情，项目列表和团控引用同一份记录。此时不自动生成报价、订单或款项。

**新建项目：** 适用于年框或先立项后分批执行。只建立父项目，经原提交核对、确认启用流程进入进行中；随后在详情新增团。客户类型、项目分类使用维护的选项；真实客户、项目名称、销售、负责人及总合同归本项目。

**编辑／期限／附件：** 在原抽屉维护本项目，保存变更依据。业务执行公司新建时来自登录人员所属公司，子团继承；更换经办人不能改变历史公司归属。合同签约、开票、付款公司分别按原单约定，不一起替换。

**复制项目：** 复制可复用资料形成新草稿，不复制已成交订单、实际费用、收付款或结算结果。复制团遵守同样原则。

### 2.2 合同资料、项目成员【沿用】

**合同资料：** 关联客户合同及版本、签约公司、有效期和盖章文件。致远OA已审批盖章的合同回传后直接关联，ERP不重复发起相同合同审批；回传未完成时允许登记来源编号及附件，不能显示已自动接通。建单引用适用合同，合同上限不生成收入。

**项目成员：** 新增／编辑员工、岗位、参与期间及负责团范围；同一员工的参与关系保留职责，不重复建立冲突成员。没有“负责事项”输入。结束参与保留历史；有未交接主责团的，先移交。

成员回答“谁参与”，主责计调回答“谁负责这一个团”，分工额度回答“此人能使用多少费用预算”。登记成员不自动给额度；调整成员不自动移交团；分配额度时选新人员，可同时加入成员。参与记录可导出，奖金计算不在本功能内。

### 2.3 项目分工与费用额度【沿用，分状态规则明确】

**入口：更多→分工额度。** 设置项目费用总预算、公共费用预算、预算参考／启用预算管控；新增人员分工，填写人员、负责起止日期、费用额度和币种。负责期间与操作人员同排常显，不折叠，不填写负责事项。“负责业务金额”只作成交规模参考，不是费用额度。

新项目默认启用预算管控；历史参考模式保持。参考模式展示预算差异；管控模式在正式成团、批量成团、拟采购确认、调整团预算、人员移交时校验。草稿资料可以保存，不能把预算问题处理成不允许记录真实业务。

**先确定本团占用，再核人员及项目剩余额度：**

| 本团情况              | 应占用的额度                | 预算8万元时的示例             |
| ----------------- | --------------------- | --------------------- |
| 草稿，无已确认或已实际发生费用   | 0，不预占团预算              | 0                     |
| 草稿，已有确认／实际费用      | 仅已确认／实际承担费用，不取整个团预算   | 实际1万元，占1万元            |
| 正式成团，尚未满足费用完整结算条件 | 团预算与已确认／实际承担费用取较大值    | 费用7.2万元占8万元；费用9万元占9万元 |
| 已取消，无实际费用、无待核损失   | 释放团预算                 | 0                     |
| 已取消，有费用或损失待核      | 保留原应占用；核清且结算批准后转为实际费用 | 损失未明不能先释放到0           |
| 费用完整声明成立且结算批准     | 仅保留本团实际承担，释放未用预算      | 费用7.2万元，占7.2万元        |

“实际承担”包含本团直接费用和跨团已分给本团的费用；保存采购草稿不等于确认费用。标明已实际发生的支出必须进入占用，不能通过保持待确认绕开预算。

**项目总额与人员额度不能重复相加。** 例如项目50万元，公共预算10万元，李梅额度30万元，则项目还可分配10万元。李梅有一个8万元团后，其个人可用22万元，项目可分配仍为10万元，不再扣一次8万元。没有人员额度的团使用项目未分配预算。某人员实际占用超过已分额度时，超出部分也占项目总额，不能只显示人员超支而漏项目超支。

**调整额度／团预算：** 不得把额度调到已占用以下来消除差异。拟采购超额先调整预算；实际已发生超支按真实金额登记原因并提示差额。公共费用占公共预算，未分配采购保留项目占用；管理分摊不重复扣各团额度。不同币种分别核对，折算须有预算汇率依据；缺汇率不能按0处理或直接汇总。

**结束分工：** 先交接草稿、进行中团及待办费用，再收回未用额度。8万元团最终费用7.2万元，结算批准释放的0.8万元先恢复人员可用额；调整／结束分工才收回项目。供应商付款、客户收款均不再次占用或释放费用预算。

### 2.4 其他项目级操作的归属

“新增费用”在更多中打开第6节统一费用抽屉，默认项目整体承担；“客户结算确认”见第9.1节；“结项检查”见第11节。单团项目列表不保留收款认领和采购付款入口。

## 3. 单团会奖｜单团项目详情

页面：[product-custom-detail.html](../merchant/tour/product-custom-detail.html)。进入一个项目后，主要任务是安排场次、建团和登记各团成交。保留“项目团、客户订单、费用与结算、项目资料”分工；后三者用于查看和进入原单，不重复维护项目预算、款项和结算。

### 3.1 新增项目团、批量建团【沿用；父项目启用校验补齐】

新增团继承项目客户、业务执行公司及适用模式，填写本次服务的日期地点、人数、主责计调、名单要求、费用预算。旅游单团按旅游服务安排，会议专票团使用会务及税额核对资料；模式不直接决定税率或抵扣资格。

默认成团进入进行中；勾选保存草稿则暂存。正式成团核执行资料及预算；不满足时保留草稿并指向原缺项，不要求重建一张团。项目尚未启用时，从原项目启用功能处理后返回本次建团。

批量建团使用同一抽屉的逐行填写、日期规则或导入方式。共用资料可带入，各团日期、地点、人数、计调、预算仍独立。整批校验预算总占用；不能每行单独通过、合计却超额度。导入在抽屉核对和修正，逐行结果明确，不静默漏建或重复建团。原型提供默认资料，不要求上传文件才能演示。

**可选收款计划：** 建团时折叠、非必填，沿用订单计划样式。可只填一个约定日期，也可填订金、尾款、比例、日期及触发条件。尚未确定的日期标“预计”；它不是实际到账日，也不能据此判逾期。计划随报价／建单带入，成交后以原订单计划为准，团表不另维护第二份应收计划。

### 3.2 报价【沿用；查看与导出日期补齐】

**入口：团行更多→报价，或选团后批量操作→报价。** 用于保存、修改、导出线下议价资料。填写服务范围、计价方式、总价或单价、币种、收款安排及依据；已报价则维护原记录及版本，不重复新建同一份报价。

保存报价只产生报价记录，不建订单、不增加应收、不自动成团。客户谈妥后可“按此建单”引用该版本；也可不准备报价，直接创建订单填写成交价。没有强制的独立“销售确认报价”步骤，按钮统一称“报价”。

已经有有效订单时，成交变化从原订单改价，不再修改前期报价去覆盖订单。已完成但未建单的团直接补录成交，不再走新报价；已取消团不继续正常报价。

**调整：** 编辑、只读查看、报价导出、建单承接均要保留“约定日期／预计日期／触发条件”，不能查看时丢失预计日期，也不能把预计日期变成确定到期日。

### 3.3 创建订单【沿用统一入口；补已完成团成交登记】

**入口：团行创建订单；多选团后批量操作→创建订单。** 所有入口打开同一抽屉，只有默认选中范围不同，不再并列“逐团创建订单”“整包建单”三个不同流程。

| 客户成交方式   | 抽屉内处理               | 保存结果              |
| -------- | ------------------- | ----------------- |
| 一场服务独立成交 | 选择本团，填写成交资料         | 一团一单              |
| 多场分别谈价   | 选择“每团分别成交”，逐团核价、核计划 | 每团一单，每单保留自己的金额及依据 |
| 多场谈一个总价  | 选择“合并成交”，填写整包价及一份计划 | 一张订单覆盖选中多个团       |

同一订单的客户、签约公司、币种必须相容。选入已有有效订单的团时，明确指出相应团和原订单，调整选择后继续；不能静默跳过、重复建单。报价不必先有，销售必须登记实际成交依据、日期和服务范围。

价格只取成交约定：固定总价直接确定金额；确定数量×单价计算金额；按实际数量核价先保存单价及规则，订单为“待最终定价”，金额未定不以0或预计数充当正式成交。

收款计划在这里确认。每团成交分别形成各自计划；合并成交重新核一份整单计划，不能把各团计划简单累加。已谈妥的新团可在原新增抽屉勾选直接建单，仍使用同一套成交规则。

**保存之后：** 显示订单编号及查看原订单入口，后续收款／开票从原订单办理。父项目已启用且草稿团资料、预算满足时一并成团；不满足时订单仍保留、团仍草稿，补缺项后成团，不重建订单或重填全部团资料。

**补充：服务已完成、尚未建单。** 原创建订单允许补录真实成交日期和依据，保存后团保持已完成，订单按正常成交方式生成。若已有本团费用结算，后续订单结算引用该记录，不再计一遍成本。此分支只补登记原服务，不允许借机扩展已完成团的交付范围。

| 所选团情况          | 报价     | 首次创建订单  | 后续动作                            |
| -------------- | ------ | ------- | ------------------------------- |
| 草稿／进行中，无有效订单   | 可用     | 可用      | 报价可选，成交后建单                      |
| 已有报价、无订单       | 编辑原报价  | 可引用报价建单 | 保留引用版本                          |
| 已有有效订单，包括待最终定价 | 查看历史报价 | 不可重复    | 查看原订单，核价／变更／款票                  |
| 已完成、无订单【补充】    | 不再新报价  | 可补录真实成交 | 保持已完成，进入原订单及结算                  |
| 已取消            | 查看历史   | 不走正常建单  | 按第5.3节核取消费用及客户退补                |
| 所属项目待结项／已结项    | 查看     | 不新增成交   | 待结项先撤回／退回申请；已结项按批准遗留办理，新业务需重新开项 |

### 3.4 修改团资料、分配计调、移交、调整预算【沿用】

草稿编辑资料，批量修改仅处理适用草稿；进行中日期、服务范围变化进入原团变更申请。分配计调确定主责，移交核接手人期间、额度及未完成事项，保存前后负责人和交接依据；不能仅改项目成员就当作团已移交。

调整团预算只改本团，项目总预算和人员额度回项目列表。批量建单在确认前展示本次生成几张订单及每张覆盖范围；保存失败保留已成功编号和失败行，重试只处理未成功行。批量操作先检查选中范围，混入不适用状态时指出具体对象，不能只给灰色按钮让用户猜原因；菜单不堆长说明，具体原因在操作核对中呈现。

## 4. 销售中心｜客户订单详情及关联单据

页面：[orders-detail.html](../merchant/sales/orders-detail.html?mice=1)。销售围绕一笔已经成交的服务办理核价、合同、款票及变更。点击项目团中的订单号必须打开这张原单。

### 4.1 确认最终价款、修改已成交金额【沿用】

**确认最终价款：** 仅用于按实际数量核价订单。原600元／人、预计40人，客户最后认可38人，确认后原订单金额为22,800元。登记实际数量、单价规则、认可依据和日期；不重新建单，也不把原预计24,000元当正式收入再减1,200元。

**申请改价：** 已明确金额后来增减时，从原订单进入[订单售后／金额变更](../merchant/sales/orders-after-sales.html?mice=1)，登记原因、差额及依据，审批生效后保留原价和调整历史。已收、已开票结果不抹除；减价产生多收、超开票时，分别进入原退款、红冲处理，不能以改价直接当退款成功。

整包范围变化需同时核覆盖团，不能按团数平均减掉包价。订单有有效变更审批中时，相关最终结算等待变更结果，避免核旧价。

### 4.2 收款计划及日期承接【沿用；条件触发日期核对补充】

订单建立后，以此处计划为准。每阶段记录金额或比例、约定／预计日期、触发条件；固定价订单阶段合计等于订单金额。最终核价时比例阶段重算，固定金额阶段重新核对；已认款保留，阶段变动不得让已认款金额消失。

“开票后30天”在未开票时可记预计日；实际开票后，引用对应发票及触发日期，核定该阶段到期日，并保留原计划及变更依据。多张发票必须明确对应阶段和触发发票，不能任取最后一张。15个工作日需营业日规则；规则未配置时由经办人确认日期，不静默当15个自然日。

报价只读、订单计划、团控摘要、导出使用相同日期含义。建团时只记日期、尚无金额的计划，成交时补金额；不能生成一条0元应收冒充已完成计划。

### 4.3 合同、收款、开票与经营摘要【沿用】

订单关联原客户合同及适用版本，合同查看／办理回[客户合同](../merchant/sales/contracts.html?mice=1)；已有OA合同沿用来源，不重复审批。收款认领及开票申请分别见第7节。按实际数量金额未定时先走原预收管理，最终确认后再分配给订单，不虚建固定价订单收款。

报价、建单和订单详情提供只读经营摘要：有可靠预计费用时看预计成本和毛利；执行后看已确认费用；结算后看对应确认结果。费用未完整、未分配或收入范围未知时标待核对，不显示虚高毛利。预算不当实际成本，已收款不当成交收入，整包价不平均分给各团。

## 5. 单团会奖｜项目团控与执行详情

列表：[schedules.html](../merchant/tour/schedules.html?mice=1)。详情：[schedules-detail.html](../merchant/tour/schedules-detail.html?mice=1)。计调跨项目查找待执行团并组织交付；执行详情与结算详情是两个页面，不能共用一套内容。

### 5.1 列表操作与完成交付【沿用】

草稿可确认成团、编辑和更多→新增费用；进行中可执行、变更、确认完成；已完成查看交付记录，金额变化按原结算／调整处理。新增费用始终在更多中，草稿允许录入费用。列表优先展示可处理的草稿、进行中示例，保留已完成、已取消分支，不能首屏全部完成。

确认完成时核实际服务日期、人数、交付依据。服务未做完先完成或有效调整范围；资料遗留明确责任及后续安排。结果只将团变为已完成，生成完成记录及适用结算期限；未建订单不阻止真实完成，但提示成交待补，按第3.3节补录。订单、成本和收付款不会自动变成已结清。

### 5.2 执行详情的操作边界【页签沿用；人员安排规则补齐】

| 页签          | 在此可以做什么                      | 规则及完成后去向                                                                                             |
| ----------- | ---------------------------- | ---------------------------------------------------------------------------------------------------- |
| 总览          | 查执行缺项、完成记录、只读收款摘要            | 收款摘要引用原订单及认款结果，展开认领明细；整包注明整单范围，不把整单已收算成本团已收                                                          |
| 执行安排        | 新增／编辑行程或会议议程，调整服务要求          | 时间、地点、负责人、服务范围供实际交付核对；金额变化仍走原单                                                                       |
| 报名名单        | 新增人员、编辑个人资料与服务需求；导入、导出       | 人员资料只保留一份；导入识别重复并逐行处理，不重复加人；无需实名的会议允许按人数交付                                                           |

| 关联订单        | 查看报价版本、订单、合同、服务覆盖范围          | 金额、认款和开票回原单，执行页不直接改价                                                                                 |
| 执行准备        | 上传交付资料，生成／下载通知单、手册，保留版本      | 缺资料供完成核对；不另复制一份名单及资源数据                                                                               |

### 5.3 改期与取消【进行中沿用；草稿及取消结清补齐】

原“项目团变更”办理改期或取消，填写原因、依据及客户／供应商影响。审批通过前原日期与状态保留；通过后改期标记需重新核资源日期、确认号及行程，不能自动沿用旧确认号。

取消后团为已取消，保留原名单、资源、订单和费用。逐项核未履行服务、取消损失、已付款应退及客户退补；“待定损”与“已确认0损失”必须区分。未付款部分减少应付，已付款涉及供应商退款或预付处理；客户退款另外核原已认款及已退，不按取消动作直接返款。

补齐草稿取消：无订单、无费用的草稿可以确认取消；已有费用／订单则进入同一影响核对，不能直接删除。取消团可做取消费用结算，确认零损失且无客户款项时允许0元收尾，不要求虚造订单或正常交付证明。取消赔付若形成客户应收，必须有原成交／赔付依据，经原订单变更或原客户应收处理，不用普通建单重卖已取消服务。

## 6. 单团会奖｜项目采购及统一新增费用

页面：[fulfillment-cost.html?mice=1](../merchant/tour/fulfillment-cost.html?mice=1)。操作把线下采购结果登记为成本，并明确由谁承担；不在这里与供应商线上询价或实际付款。

### 6.1 新增、保存、确认费用【沿用】

| 进入位置           | 默认带入         | 不同入口共同使用的功能      |
| -------------- | ------------ | ---------------- |
| 项目列表→更多→新增费用   | 当前项目、项目整体承担  | 同一个新增费用抽屉        |
| 项目团控→更多→新增费用   | 当前项目、本团、服务日期 | 同一个新增费用抽屉，草稿团也可用 |
| 项目采购→新增费用      | 选择项目与服务范围    | 可录单团、跨团、公共费用     |
| 团期结算→成本明细→维护成本 | 本次核对范围及原采购   | 补录／修正成本，不能另建重复费用 |

选择归属后填写采购服务、供应商、付款公司、含税金额、币种、日期、采购依据及付款条件。付款公司按原业务约定，不与执行公司字段合并。

**保存明细**形成待确认费用；**确认费用**核金额、归属及依据，通过适用预算检查后成为确认成本及可请款来源。拟采购超额先调整预算；已实际发生的超支登记真实金额及原因。确认费用不表示已经付款。

确认后修改需留历史；有付款申请的金额、公司、币种、供应商或分配变化须先核原申请；审批中及已结算范围不可普通编辑覆盖，走第9.5节调整。取消团只补取消相关费用，不继续一般新增服务采购。

### 6.2 费用分配【沿用；已结算部分保护补验】

直接费用归一个团。跨团费用指定覆盖团及各团承担额；项目公共费用留项目。比如采购10,000元：A团3,000、B团4,000、项目2,000、未分配1,000，合计仍为10,000。项目汇总计原采购一次，团只计各自承担。

保存时允许留未分配金额，完整结算前须核清；未分配不能按0忽略，也不能自动平均分摊。公共费用管理分摊可用于分析，但不能生成第二笔费用。已结算承担额锁定；剩余未结算部分可以继续分配，跨过已确认范围的变化须走调整记录。

### 6.3 付款条件、发票及税额【沿用】

付款条件记录约定及当前累计可申请金额。采购10万元、订金条件30%时，当前上限3万元；满足后续条件再核定上限。确认采购全额不代表可立即全付。

费用按含税口径录入。上传发票、识别后由经办人复核票面金额、税率和税额；冲突以核对后的真实票据为准，保留修正记录。识别失败、多税率、票额与采购额不一致时手工核对，不直接把票额覆盖采购总额。预计可扣税与财务核定可扣税分开保存，未核定不算0，也不默认全额可扣。

**采购详情**只对应新增费用资料、分配和依据，不再展示付款记录或供应商对账办理入口。付款申请统一走下一节指定页面；结算中仍可反查原采购及实际收付结果。

## 7. 客户收款、认款及开票

这些页面承接原订单，不另造会奖收款系统。收款、开票无统一先后：可以先开后收，也可先收后开，按合同条件办理。

### 7.1 收款认领与财务认款【沿用】

销售从订单进入[收款认领](../merchant/sales/payment-claim.html?mice=1)，选择实际到账流水、订单及阶段，填写本次分配金额和依据后提交。集中入口支持一笔到账分配多单，但须核客户、收款公司和币种；从单订单进入默认只处理本单。

申请金额不能超过到账可用额、订单及阶段可认款余额；待复核申请占用可分配余额，但不增加已认款。已退回在原申请修正重提，不能生成第二笔占用。

财务在[认款复核](../merchant/finance/finance-matching.html?mice=1)确认到账及归属，确认后原订单／阶段增加已认款；退回则保留原因，不计已认款。同一申请重复操作不重复计收。多团整包的已认款计原订单一次；团控查看的是同一结果。

没有订单或最终价款未定的先款，进入[预收管理](../merchant/finance/finance-advance-receipts.html)，后续按原预收分配／核销到订单。客户退款从原订单关联[退款申请](../merchant/sales/orders-refund.html)进入[退款执行](../merchant/finance/finance-refund-execute.html)，退款余额要扣已经成功的退款与有效在途申请，不因业务入口不同多退。申请／审批不计已退，实际成功才计已退；失败或结果未知保留原申请继续处理。会奖取消、减价及结项遗留的原单承接须补验，不能仅凭通用退款页存在判定已贯通。

### 7.2 开票申请与财务开票【沿用；计划日期关联补充】

销售从原订单开票申请，选择抬头、税号、票种、开票项目、本次金额和收票资料。可开项目及税务口径引用财务维护；建团模式只能提供业务默认项，不能替代税务判断。有效在途申请和已开票都参与防重复额度核对。

[发票管理](../merchant/finance/finance-invoice.html?mice=1)接收申请，审核后办理；资料有误退回原申请。开票中或结果未知先查询，明确失败才重试，避免重复发票。成功后保存号码、日期、PDF并关联订单；申请不算已开票，开票不增加已认款。订单可以查看、下载票据。

红冲／作废沿用原发票关联处理，不删除已开票历史。按实际开票触发的收款阶段按第4.2节核定日期；开票平台与OA一样，原型演示结果不表示已完成真实接口联调。

## 8. 履约付款申请、财务复核及实际付款

### 8.1 履约付款申请【沿用】

主页面：[fulfillment-cost.html?view=payment](../merchant/tour/fulfillment-cost.html?view=payment)。菜单[fulfillment-payment-apply.html](../merchant/tour/fulfillment-payment-apply.html)转入同一页面，不是第二套付款功能。

操作选择“按项目”，项目行点击请款，在原抽屉选择采购及具体子团，填写各行本次申请金额、计划付款日期、备注和依据。项目公共费用及未分配部分单列。按供应商、团期、科目仍保留原流程；列表关联团显示数量，详细范围在抽屉核对，不能把大量团名撑开列表。

按项目只是集中选单，不把不同供应商、付款公司、币种混成一笔付款。提交前呈现按原采购及付款对象拆出的申请结果，各行保留本次分团金额。

**保存草稿**不送财务、不占有效申请额度；**提交申请**为待财务复核，占用未付申请额，已付款不增加。退回后原申请修改重提。撤回释放未付占用，实际已付保留；部分付款后撤回剩余，不自动退款。

可申请余额＝采购有效可付总额与当前付款条件上限取较小值－实际已付－已核销预付－有效申请尚未支付部分，最低为0。核销预付是用以前付的钱冲抵本次应付，不是再付一次。

同时核“每团本次金额不超本团承担可申请额”和“同一采购各行合计不超原采购余额”。例：采购10万元，允许累计5万元，已付2万元、核销预付0.5万元、在途申请1万元，本次最多1.5万元；可A团0.8万元、B团0.7万元，不能各1.5万元。历史付款没有分团明细时扣原采购总余额，不伪造历史分团付款。

### 8.2 财务付款复核及审批【沿用】

[付款复核](../merchant/finance/finance-payment-apply.html?mice=1)核采购依据、付款条件、金额及已审核供应商账户。通过后进入原审批；退回说明原因，经办人回原申请修正。业务登记了银行账号不等于财务已经核准账户。

[审批中心](../merchant/approval/approvals.html?mice=1)处理本次版本，通过为已批待付，交付款管理；退回不计已付。来源金额或范围变化须重核，不能批准旧版本而支付新金额。审批人及金额阈值引用原配置，不在本PRD新增一套会奖审批政策。

### 8.3 实际付款、回单与预付【沿用】

[付款管理](../merchant/finance/finance-payment-management.html?mice=1)对已批待付／部分付款申请办理，记录实际金额、日期、银行交易号及依据。成功才增加原申请和原采购已付，部分成功则保留剩余；结果未知继续查询，明确失败后处理，不先计付。

同一成功交易不能重复计付；超剩余申请额须重新核原申请。付款结果回原单可查；[回单管理](../merchant/finance/finance-remittance.html)和[预付核销](../merchant/finance/finance-prepayment-offset.html)沿用，不复制到采购详情。付款不重复增加费用、不再次扣预算，也不自动把团结算完成。

## 9. 客户认可与团期结算

### 9.1 客户结算确认【沿用；整包阶段认可口径明确】

入口：项目列表→更多→客户结算确认。销售按订单、团及服务期间登记客户确认人、认可内容／金额、争议和附件。**这是交付后的客户认可，不是前期报价确认，也不新增一笔收入。**

客户对金额有异议时回原订单改价；按实际数量成交先确认最终价款。整包仅一部分服务完成时可记录该部分交付认可，不能仅凭完成团数推算对应收入。存在争议的范围保留待核，不用其他团认可替代。

### 9.2 团期结算的入口和页签【沿用】

页面：[fulfillment-cost.html?type=project](../merchant/tour/fulfillment-cost.html?type=project)。项目团和其他类型均有详情，项目团使用自己的结算资料，不能跳回执行详情。

执行期间可以进入成本明细维护费用；提交交付结算须服务已完成或取消收尾。未提交时保存草稿／继续结算；审批中、已确认行只显示“详情”，不再并列“查看结算”或重复首次结算按钮。需要核交付依据时从结算详情反查执行详情。

| 页签   | 功能边界                             |
| ---- | -------------------------------- |
| 单据总览 | 选本次范围、核完成与认可、判断哪些金额本次确认，哪些只是原单参考 |
| 收入明细 | 引用原订单及有效调整，核成交和对应税额；不在此改价或新造收入   |
| 优惠减免 | 核已生效折让及依据，已包含在成交价中的不再扣一次         |
| 成本明细 | 通过统一费用功能补录、确认、分配；核直接、跨团、项目承担及未分配 |
| 订单明细 | 查看来源订单、覆盖团、金额和状态                 |
| 收款预收 | 核认款、退款、预收分配、未收余额；办理回原单           |
| 预付付款 | 核原采购付款、预付及核销；区分原采购已付与本团承担        |
| 变更记录 | 查看影响服务范围、价格、费用和结算期间的有效变更         |
| 附件依据 | 补结算依据、无费用说明、遗留事项、费用完整声明          |
| 结算记录 | 保存／提交／退回／确认版本，查看原审批、调整及导出打印      |

### 9.3 三种结算范围怎样处理【单团沿用；整包分批及公共费用独立入口补齐】

**A. 一团一单，或已完整履行的订单。** 选本次团，核客户认可、原订单最终金额及本团费用；收入与成本范围均明确后提交完整业务结算。无订单的已完成团可以先核交付费用，但客户成交及收入仍待补，不能显示收入0、完整结算完成。补录订单后，若本团费用已经确认，从结算详情的“结算记录→订单结算”继续核客户成交，只引用原费用确认，不再结一次费用。

**B. 一张整包订单、分批完成多个团。** 保留子团独立收尾能力，不强制所有团等最后一场：

1. A团先结束：提交本团交付与费用核对，登记客户对A团交付认可。系统将本次标明为“团费用结算”；整包订单金额仅作参考，本次不确认整单收入、不计算虚构的A团毛利。费用完整且审批通过后，A团可按实际费用释放预算。
2. B团以后结束：同样办理B团；不能因A已确认，就禁止B或整包后续核对。各团已确认费用锁定并可引用。
3. 订单全部服务结束、客户认可整包最终金额后：在任一关联团的**结算详情→结算记录→订单结算**继续，仍用原结算抽屉，范围自动为该订单全部团。已确认的团费用只引用，未确认的费用本次核对；本次仅首次确认整包业务收入，汇总成本不再生成一笔费用。完成后关联团可查同一整包结算记录。
4. 订单已经完整结算时不再有首次订单结算动作；价格或费用后变动走调整。整包内部分服务取消，先核原订单变更及各团取消结果，再核最终范围。

例如订单A＋B共20万元，A成本6万元、B成本8万元。A先确认只产生6万元费用确认；最终整包收入20万元、成本合计14万元、含税毛利6万元，不能成本记成20万元，也不能A单独显示收入10万元。这里的业务收入核对不等于财务会计收入确认。

**C. 项目承担费用。** 原抽屉保留“同时核对项目承担费用”，用于本次一并核项目公共费用；只能纳入本次明确选择的未结算费用，不能一个勾选自动锁死整个项目未来公共费用。

补充团期结算项目视图的**项目费用结算**入口，选择项目后直接打开同一结算抽屉，以项目费用为范围，可不选任何团。适用于所有团都已结算、最后才核年度统筹费的情况；不虚建一个公共费用团。项目详情的费用汇总只提供去原结算页查看的链接。

公共费用可以分批确认，每笔原费用及承担部分只确认一次，后增费用不覆盖旧结果。未分配采购先明确归团或项目，不能借公共结算吞掉分配缺项。项目结项须核所有应确认公共费用，但项目结项本身不另产生一笔结算金额。

**防重复规则：按本次确认的收入范围和费用承担明细判断。** 同一部分不能重复确认；已有团费用确认可以被整包总核对引用，不等于再次确认。现有“只要团号重复就一律禁止”需调整，现有“包含项目费用便锁住以后所有公共费用”也需调整。

### 9.4 保存、提交、退回、确认与税额【沿用，分范围检查补充】

保存草稿不锁最终金额。提交时逐项核本次完成／取消依据、适用客户认可、费用确认及分配、有效变更、附件；无费用填写明确说明。完整订单结算还须最终价款明确、订单覆盖范围全部可核；团费用结算不借未完成的整包收入强行算利润。

提交后审批中，保留本次来源、金额和依据版本。审批退回修改原申请重提；来源已变化需重核新版本。批准后已确认，历史结果不随着后来修改重新计算。保存或提交重复点击不能产生两笔有效结算。

含税、预计扣税后、核定扣税后三套口径分别展示：扣税后收入＝含税收入－相应销项税；扣税后成本＝含税成本－相应可扣税；毛利＝同口径收入－成本；毛利率＝同口径毛利÷收入，收入0或未知不计算比率。核定税额未完成时保留待确认，不显示成已核定0税额。税务方式及可扣资格按财务确认规则，不固定一个演示税率。

税额算例只用于验证公式：含税收入106,000、销项税6,000，含税成本53,000、预计可扣税3,000，则预计扣税后收入100,000、成本50,000、毛利50,000、毛利率50%；若核定可扣仅2,000，核定成本51,000、毛利49,000、毛利率49%。不得把预计3,000继续用于核定口径。

未收尾款、未付供应商尾款不自动清零，可以保留为未结事项；税额未核定可形成带待核税项的业务确认，不能宣称最终核定税后利润。费用未完整可以保存核对，但不能勾费用完整释放节余预算。公共费用的未用预算同样在对应范围核清后释放，不影响已发生费用。

### 9.5 结算后追加／减少费用、订单改价【原调整沿用；后续结算承接补齐】

从原结算详情的变更／结算记录关联[结算调整](../merchant/finance/finance-settlement-adjustment.html?mice=1)。指定原费用或原订单、调整差额、服务日期、原因及依据；审批生效后生成关联原单的增减记录，保留原结算，不直接覆盖。

调整生效后，仍在团期结算的结算记录中核本次差额，生成与原确认记录关联的调整结算。历史确认额＋有效调整＝最新业务结果；原成本及原收入只计一次。追加费用须明确由哪个团／项目承担，跨团不能沿用空分配；减费不能形成超出原费用的负成本。

未付款的减费减少可付余额；已付形成应退／预付处理，不能简单把已付扣掉；新增费用按本次预算差异核对。调整导致结项依据变化时按第11节处理，不回退真实执行完成状态。

## 10. 财务业务结算、汇总和导出

### 10.1 财务业务结算【已有来源查看；项目完整汇总补充】

页面：[finance-settlement.html](../merchant/finance/finance-settlement.html?mice=1)。财务接收已确认业务结算，按项目查看原订单、各团确认、整包确认、公共费用及后续调整，必要时返回原业务依据核查。

现有会奖页面主要列业务结算来源，需补项目汇总核对：有效订单金额计一次；团承担＋项目承担＋未分配与原采购总额可对上；已确认与待核部分分开；收付、预收预付、款票余额独立呈现。不同币种分开，无依据不折算。整包引用过的团费用不在汇总中再次累加。

此页不重建订单、采购或付款，不因为汇总完毕自动做会计凭证。会计收入确认、会计期间、正式税务及NC推送仍走原财务规则，不在会奖原型里自创。

### 10.2 工作台提醒及数据中心【沿用；新结算范围承接回归】

[工作台](../merchant/dashboard.html)按明确到期日提示未回款、超期未结算及责任人；预计收款日、尚未触发条件不能当逾期。团费用已确认但整包还待核时，应提示对应订单范围，不继续误报本团费用未结算。经办人与项目设置的部门经理沿用原提醒配置，不把催办按钮塞回业务列表。

[订单口径明细](../merchant/data/order-report-details.html)、[回团口径明细](../merchant/data/return-report-details.html)、[结算报表](../merchant/data/settlement-reports.html)按现有会奖区查询、导出。订单金额、已认款按原订单一次；回团行标明来源订单及覆盖范围，整包金额不复制到各团累计。约定日期、预计日期和收款条件分别导出；项目成员参与记录保持可追溯。报表只读，不成为另一套改金额入口。

## 11. 项目结项及结项后遗留事项

### 11.1 结项检查与提交【沿用；整包及公共费用完整性补充】

入口：项目列表→更多→结项检查。用于判断整个委托是否可以关闭，和某一个团结算是两件事。

硬缺项须先处理：尚有草稿／进行中团，交付或取消事项不明，有未确定成交价、未结争议或有效变更审批，团费用未核、订单完整结算未核、公共费用／分配未核。每项列出具体团／订单／费用和原处理入口，不只写“检查不通过”。无费用、无客户应收的取消业务允许有依据的0元结清。

未收尾款、未付尾款、票据／税额待核属于可登记的遗留事项；是否允许带遗留结项按原批准规则。允许时每项记录原单、剩余金额／内容、责任人、计划及批准依据；不能只有“同意例外”总开关。提交进入待结项，锁本次范围；批准前可撤回本次结项申请，或审批退回，均恢复进行中并保留记录；批准后已结项。待结项期间不新增团、成交和普通采购，已批准或明确登记的原款票继续办理，结果变化须在批准结项前重新核对。

项目已结项不再新增团、正常成交或普通采购。全部团完成不自动结项；没有后续场次也需要核项目公共费用。项目提前结束时先取消未执行团、核已执行部分及款项，再按同样检查收尾；不提供一键清空团、费用和订单的项目终止。

### 11.2 已结项项目怎样继续办尾款【调整】

当前原款票申请会统一拦截已结项项目，须改为按批准遗留范围判断，不要求用户到财务重新建无来源单据。

| 已批准遗留事项       | 后续入口及允许动作              | 控制边界                       |
| ------------- | ---------------------- | -------------------------- |
| 客户尾款未收        | 原订单→收款认领→财务认款；已有预收按原分配 | 只认原单剩余金额，不能追加成交范围          |
| 客户发票未开或税项待核   | 原订单→开票申请、原发票记录／税额核对    | 限原单未开或待核范围，保留与结项依据的关联      |
| 原采购尾款未付       | 履约付款申请选择原费用→财务复核／付款    | 限批准剩余及实际满足的付款条件，不新增采购      |
| 已批准客户退款或供应商退回 | 原退款／预付及付款关联记录          | 仍核原款余额，记录实际成功结果，不直接改历史已收已付 |

未列入遗留清单或金额／范围发生新变化时，不准普通补单绕过。由项目列表结项记录中“申请重新开项”，提交原因及影响，按原结项审批责任核准后恢复项目办理；保留已结项历史，原团仍保持真实完成／取消状态。该入口及相应状态校验需补充。原型已有“已终止”历史记录不能因此全面放开业务操作，须先核原批准来源及可处理范围。
