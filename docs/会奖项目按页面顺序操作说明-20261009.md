整体业务是：销售建立客户项目，负责人分工，计调建立和执行项目团；销售确认报价并形成订单，采购确认实际费用；财务分别办理收款、付款和发票；业务核客户认可和本次结算，负责人最后检查结项。实际签约、订金、采购和开票可以按业务安排穿插进行，本文的章节顺序用于对照页面，不是强制的业务先后条件。

**四份主要记录：**“单团项目”承载客户整体委托；“项目团”承载一次会议、一次出行或一次完整服务；“订单”承载客户确认的一份成交；“原采购”承载一笔真实支出。多团可以共用一份整包订单或一笔采购，不能按团数重复计收入、成本。

“应收”是客户应付给我方的钱，“应付”是我方应付给供应商的钱；“认款”是财务确认到账属于哪个订单。“业务结算”确认已交付范围及承担费用，“结项”结束整个项目；二者均不等于收付和发票已经办完。

当前为业务原型。以下区分已有操作、只读核对和待调整建议；未接通的银行、电子签约、开票和财务核算接口，不写成已经完成的实际结果。公司金额、税额、汇率及结项政策仍须有确认依据。

## 一、单团项目列表

**入口：产品中心 → 自营产品 → 单团项目。谁使用：销售、项目负责人。**上游是客户需求或框架合作，本页先把客户的整体委托建成一个项目，交负责人组织具体项目团。

### 1.1 顶部“新建项目”

销售先查询是否已有同一委托；没有时点“新建项目”。在“项目资料”中确定客户、我方公司、整体服务范围和期间、销售及项目负责人。有来源时，再核下方“需求来源”带入的原需求。

| 操作 | 谁、如何办理 | 解决的问题及结果流向 |
|---|---|---|
| 保存草稿 | 销售把已知需求录入，资料未齐时点“保存草稿” | 留下可继续补充的项目；此时没有实际成交或财务应收 |
| 提交核对 | 销售补齐项目资料后点“提交核对” | 项目进入待确认，由负责核对人员核客户、公司、范围与人员 |
| 确认启用 | 待确认项目从列表“核对”进入，确认无误后点“确认启用” | 项目进入进行中，负责人可组织分工建团；新建和启用项目均不自动建立首个项目团 |

组织方式选择“单个项目团”或“多个项目团”，都只是确定整体安排。具体哪一天、多少人、谁执行，之后在项目团中确定。线路详情、销售报价、意向询单和企业客户中的“新建单团项目”属于来源入口，带入需求后仍办理同一个项目。

### 1.2 筛选区

销售或负责人按项目／客户／编号搜索，再按业务分类、组织方式、销售、负责人、状态和期间查询；“重置”清除条件。用于找到原委托继续办，年度客户下个月增加会议时，应先查原年度项目。

### 1.3 项目列表及行操作

先认项目和客户，再看服务期间、责任人、项目团完成情况与客户已确认金额，判断要找谁处理。待定价金额保留待确认，不计成零收入。

| 行操作 | 谁、如何办理 | 结果流向 |
|---|---|---|
| 详情／项目名称／项目团数量 | 销售、负责人进入单团项目详情 | 在原项目中处理分工、报价及整体资料 |
| 编辑 | 销售继续补草稿，再保存或提交核对 | 完善项目建档，不代替客户报价确认 |
| 核对 | 核对人员检查待确认项目，可保存草稿或确认启用 | 把可组织执行的项目交负责人 |
| 复制 | 销售复用相似项目，选择服务安排、预算参考或人员安排，重新核客户、日期及责任人后保存 | 只保存新草稿，所属团也为草稿、日期重新填写；不带入原结项、建团、完成、取消或客户认可结果。未选项目分工时不带入原分工及团计调；报价、合同、收付重新核办 |

列表底部分页只改变查看范围。完成项目团数量、已成交金额和项目结项状态分别判断，不能用其中一个代替另外两个。

## 二、单团项目详情

**谁使用：负责人统筹，销售办理对客成交，计调查看本人工作范围，财务按来源核对。**页面固定顺序为：顶部操作及项目摘要，然后“项目团 → 报价与合同 → 费用总览 → 项目资料”。

### 2.1 顶部操作及项目摘要

先核项目、客户、我方公司、服务期间、销售和负责人，确认自己正在办理哪项委托。顶部操作如下，结项虽然是业务最后一步，按钮在这里，故在此完整说明。

| 操作 | 谁、如何办理 | 解决的问题及结果流向 |
|---|---|---|
| 项目资料 | 草稿／待确认项目由销售或负责人打开建档核对；其他状态进入“项目资料”页签查看 | 继续当前项目资料，不另建项目；已启用后的共同资料并非全部可直接修改 |
| 结项检查 | 进行中的项目由负责人打开后，先看“未结事项”，按各项“查看”回原来源处理；确认不再新增服务，填写结项说明后“申请结项” | 把服务完成、客户认可、费用及业务结算是否齐备交审批人判断 |
| 带未清款票申请结项 | 符合已确认制度时，负责人在同一检查中登记例外批准依据、遗留款票、责任人和处理安排 | 业务结束后仍明确谁继续收款、付款或开票。服务未完成、争议未解决、费用未确认等业务缺项不能靠款票例外绕过 |
| 查看结项审批／查看结项 | 待结项时查看审批进度；已结项时查看“项目资料”内结项情况 | 负责人核批准结果，遗留责任人按原单继续收尾 |

结项批准时再次核当前团、客户认可、费用、结算、争议及未完变更；出现新增草稿团或未结业务，应退回处理。新出现款票未清须有有效例外及处理安排。已终止项目的旧审批不能批准或退回恢复为进行中。审批“查看来源单据”回项目资料中的结项情况。

当月会议办完但年度项目还要继续时，只结已完成范围，不申请结束年度项目。**现有边界：**结项后新认领／开票受到限制，提示转财务调整流程；获批遗留如何新发起办理仍需验收，不能把例外说明当成后续功能已完整。

### 2.2 第一个页签“项目团”

#### 第一块：项目分工

**使用场景：负责人先把一部分业务交给计调，让计调能在自己的范围内自主建团、准备报价或登记客户确认。此时具体项目团可以还没建。**

例如，医药客户委托全年会议，负责人先让李梅负责10月上海会议。李梅据此建立自己的34个项目团。若只允许她准备报价，最终客户确认仍由销售办理。

| 操作 | 谁、如何办理 | 对后续操作和金额的作用 |
|---|---|---|
| 新增分工 | 负责人点“新增分工”，先确定人员及负责事项、期间、城市和服务类型；再确定可否自主建团及报价范围，最后核业务计划金额、费用预算和适用限额依据 | 给员工本项目的办理范围。建团、报价及客户确认会核这个范围；本次分工本身不生成项目团、订单或费用 |
| 维护 | 负责人在有效分工上点“维护”，调整以后要负责的范围或允许办理事项并保存 | 后续操作按有效范围检查；原项目团主责、既有报价和历史金额不会因为改分工而自动搬给别人 |
| 结束 | 负责人说明结束原因和未完项目团安排，再保存 | 结束本项分工。已有团和历史经办仍保留，未完团需要接手时还要办理下面的“移交” |
| 查看 | 员工看本人负责范围；负责人看已结束的分工及原因 | 确认自己能办到哪一步，避免遇到无权操作就重复建项目 |

列表中的计划、预算和限额用于不同判断：业务计划看预计负责多少成交，费用预算看准备花多少钱，硬性限额须有批准依据。新增项目分工也不能授予员工原本没有的公司岗位权限、财务付款权或审批权。

#### 第二块：“项目团”标题及右侧按钮

| 操作 | 谁、如何办理 | 解决的问题及结果流向 |
|---|---|---|
| 新增项目团 | 负责人或获授权计调在已确定的项目下，录本团服务、日期地点、人数和主责，保存后为草稿；客户确认后另办确认建团 | 把整体委托拆成一次可执行服务，交本团计调补日程、名单及资源；报价另行办理 |
| 批量建团 | 按客户清单选择直接填写、按日期生成或导入表格，填共同资料后逐团核差异，点“核对项目团”，全部通过后“保存N团草稿” | 一次形成多团草稿，各团仍要核执行和成交，不因批量创建自动产生订单或应付 |
| 分配计调 | 勾选要分配的未完项目团，选择接手计调、生效日期及分工说明 | 确定这些已经建好的团由谁主责，与前面“允许在哪个范围建团”是两件事 |
| 移交 | 勾选未完团，核原计调和未完事项，登记新计调、生效日期及原因 | 只处理草稿／进行中团；提交时再次核当前状态。接手人在原团继续办理，保留交接历史；已完成／已取消或项目已结束时不改历史负责人 |

批量建团抽屉内按“共同资料 → 创建方式 → 项目团清单 → 核对保存”顺序处理。按日期生成时核周期或手动选期、排除日期及服务起止；导入时使用模板的逗号／制表符文本，当前不直接读取Excel工作簿。生成清单后可调整、复制、删除或补一团，再逐页核错误；生成不等于保存。

#### 第三块：筛选、选择及批量操作

先按执行月份、城市、计调和状态查询，再逐团勾选或“选择当前筛选的全部”。核“已选”数量后办理，跨页选择不能只凭当前屏幕行数判断。

| 操作 | 谁、如何办理 | 结果流向 |
|---|---|---|
| 批量维护 | 负责人或获授权计调对草稿团统一补资料，应用到所选团后逐团核差异，核对后仅保存有效团 | 未通过的团仍待修正；已经执行的改期应走变更，不能在此覆盖 |
| 批量报价 | 有报价范围的经办选择项目团，补每团金额和依据，选择“保存报价草稿”或“登记客户已确认报价”，核对后仅办理有效报价 | 每团独立成交才逐团报价；一份整包总价应办一份覆盖多团的报价。确认还须满足客户依据、岗位权限和适用审批 |

批量建团要求整批通过后保存；批量维护和批量报价允许仅办理有效行。办理后核成功数与未办数，交接时不能把已选数量说成全部完成。

#### 第四块：项目团列表、行操作及分页

列表用于核团名、日期、人数、计调、项目团状态和资料缺口。**项目团状态决定当前能做什么；资料缺口说明为什么还不能继续。**

| 行操作 | 谁、如何办理 | 结果流向 |
|---|---|---|
| 详情／项目团名称 | 计调打开本团五个页签，负责人查看执行及金额依据 | 从整体项目进入具体服务，继续同一项目团 |
| 确认建团／编辑 | 草稿可编辑并保存；确认建团时引用覆盖本团的客户已确认报价或有效订单、核客户委托凭据和本团服务资料 | 编辑或保存草稿不改变状态；确认建团才进入进行中，不重复生成订单 |
| 复制 | 显示“复制”的原团可按需复用服务安排、预算或计调；重新填写日期和客户委托编号，核日程后保存草稿 | 建立新草稿；只复用勾选的服务计划／预算／计调，清除原日程日期、确认建团、完成、取消、客户认可和移交记录；名单、资源及新成交重新办理 |

底部可翻页继续查看或勾选。复制、分配和移交解决不同问题：复制建新团，分配确定已有团的主责，移交把原团交另一人继续办。

### 2.3 第二个页签“报价与合同”

本页由销售或有报价权限的计调使用，按“框架合同 → 客户报价 → 客户对账”三块从上到下处理。前两块确定成交及签约依据，最后一块在交付后核客户认可。

#### 第一块：框架合同

| 功能 | 谁、如何办理 | 在业财流程中的作用 |
|---|---|---|
| 登记框架合同 | 销售点“登记框架合同”，核签约双方，再登记服务范围、有效期、金额性质、签署依据及附件 | 给后续报价一个长期合作依据。框架上限、预估或客户承诺金额不能直接算成订单成交 |
| 查看 | 销售从原框架核资料、签署情况和已引用业务，必要时维护现有记录 | 保持报价引用同一框架，不重复建同一合同 |
| 合同办理 | 销售进入该框架的合同办理，核双方及范围，完成签署或线下归档 | 留下有效框架文件；框架可独立签，不需要虚构收费订单 |

例如年框500万元若明确是上限，本页用来核后续已确认和审批中的占用；实际收入仍按客户确认的具体订单判断。

#### 第二块：客户报价

先在报价列表看当前版本和状态，再操作。仅覆盖草稿团的“草稿／已报价”点“办理”，“待审批／已确认”等记录看“详情”；已有订单可“查看订单”。

点“新增报价”或“办理”后，按抽屉自身顺序完成：

| 抽屉区块／操作 | 谁、如何办理 | 解决的问题及结果流向 |
|---|---|---|
| 客户与报价版本 | 销售或获授权计调先核客户、公司和本版报价 | 防止拿另一版金额或另一公司文件继续成交 |
| 服务及计价、税费测算 | 写本次服务包含什么，选择固定总价、数量单价或按实际数量结算；有依据时维护预计税费 | 明确卖什么及如何计价，给计调执行和财务核应收提供依据；税费测算不是财务最终核定 |
| 关联项目团 | 勾本报价覆盖的具体项目团 | 决定一单覆盖一团还是多团。整包未分团价格时不平均拆出各团收入 |
| 收款计划 | 安排订金、进度款、尾款，按需“增加收款阶段”，核金额／比例及到期日或收款条件 | 后续按订单和收款阶段认款、查未收；总额已明确时阶段合计应等于确认金额 |
| 客户确认与内部审批 | 登记客户确认人、日期和凭据，引用有效框架及适用审核依据；已有相同成交订单时选择“关联已有订单” | 有效客户确认和审核共同支撑成交；同客户、公司、币种、金额与覆盖范围一致时沿用原订单，避免重复成交 |
| 金额范围核对、客户附件 | 核人员和框架的已确认、审批中及可用金额，补本版客户材料 | 超出硬性限制按已批准制度处理；计划参考不冒充批准限额 |
| 保存报价草稿／登记已报价 | 经办保存准备内容，或记录已向客户提出当前报价 | 尚未形成有效客户成交，不能据此计已确认收入 |
| 登记客户确认 | 有确认权限的经办核完整依据后提交；需要内部审批时交审批中心 | 有效确认后承接一个原订单，计调接服务范围，财务接订单应收。审批退回后回原报价草稿补正，使用新版本重提 |

有本版线下审批结果时，可在原表单选择“已取得外部审批结果”，核批准编号、版本和依据；旧版批准不能替代新金额审批。

“详情”中依次核报价及版本、关联项目团、收款计划，再“查看订单”“下载报价单”或“查看审批”。报价历史用于确认客户曾收到哪版；当前报价下载为网页文件，不等于已经签署合同。

#### 第三块：客户对账

**销售办理，负责人和计调查看。**计调登记已完成后，销售在这里核客户认可了哪些服务、多少金额。可以按一团核，也可以按月集中核原订单。

1. 点“客户对账”，先选期间、币种及“结算金额与服务确认”或“整包交付进度确认”。候选按项目团计划结束日期筛入，还须核实际完成范围。
2. 在“待对账订单”选择原订单，核认可金额、争议金额和原因；按实际数量结算时补客户认可数量和单价。认可加争议应与原金额或本次数量单价依据相符。
3. 补客户确认资料。未拿到结果先“保存草稿”或“登记待客户确认”；后续从原行“办理”继续，取得依据后“登记客户确认”。登记本身不代表系统向客户发送了消息。
4. 已确认或部分认可的原记录点“详情”，核原订单、认可、争议和原因。有减价争议，从“办理订单金额变更”进入原订单售后申请改价，不能直接覆盖原成交。

确认结果交计调业务结算，交销售和收款财务核应收。月度100单对账仍引用原100单，不再生成一张同额月结订单。整包仅完成部分团时先核交付进度，不能据此分摊收入。

**现有边界：**按实际数量对账不会直接确定原订单总额。金额未定时仍需核最终订单金额和收款阶段，现有结项检查会指向通用“申请改价”；这条最终定价路径需要专项验收。部分让价、补服务后重新认可也不能假定均可自动解除原争议。

### 2.4 第三个页签“费用总览”

**负责人、销售及经营管理人员查看整体经营情况。**本页顺序是费用总览、费用明细、业务毛利测算。

| 页面区块 | 谁、如何使用 | 解决的问题及结果流向 |
|---|---|---|
| 费用总览 | 负责人核原预算、最新预计和已确认费用，再按币种看各团直接费用、项目公共费用和跨团采购的组成 | 判断整体预算是否够、哪部分还没确认；需要办理采购点“履约采购”，交计调／采购经办处理原记录 |
| 费用明细 | 负责人打开费用“详情”，核供应商、原采购总额、本团承担、付款和票据；需要修改从“查看采购”回履约办理 | 管理者能找到支出依据，本页不再重复录一笔采购 |
| 业务毛利测算 | 销售、负责人分别看含税金额、扣除预计税额及扣除财务核定税额的结果，核差异提示 | 预计税额供报价判断，核定税额供进一步财务核对；缺金额、缺分配或缺税额时保留待核，不能称为公司净利润 |

一笔采购在项目总额中只算一次；各团承担加项目承担及未分配应能解释原采购总额。发现异常交回原采购或原订单，不在总览里补造一笔金额。

### 2.5 第四个页签“项目资料”

本页实际顺序为：**基本资料 → 项目成员 → 变更与办理记录 → 结算期限 → 项目附件 → 结项情况**。下面按这个顺序说明。

#### 第一块：基本资料

负责人、销售及接手人员查看业务分类、组织方式、整体服务范围和需求依据，确认这项委托原来要做什么。它是共同档案；新增一团或修改一团日期，不应直接改成另一项整体需求。

#### 第二块：项目成员

**使用场景：记录实际参加项目的人和参与期间，尤其是不会在系统内独立建团、报价的协作人员。**例如王芳仅在10月12日至13日协助某场会议签到和会场支持，负责人在这里登记“现场支持”和对应项目团；王芳不因此取得建团、报价、付款或审批权限。

| 要区分的事 | “项目团”页签中的项目分工 | 本页的项目成员 |
|---|---|---|
| 业务目的 | 事前交办某个范围，并决定员工可在系统办理什么 | 留下谁实际参与了哪些项目团、何时参与、做什么职责 |
| 典型人员和场景 | 李梅负责10月上海会议，可自主建团，报价交销售确认 | 王芳协助其中两天现场签到；另有签证或资源协作人员 |
| 对操作有什么影响 | 建团、报价、客户确认会核分工及既有岗位权限 | 只是参与记录，不扩大岗位权限，也不自动改变项目团主责 |
| 对业财有什么使用 | 明确业务责任和允许办理的金额范围，为订单、采购及交接追责提供依据 | 给人员投入和参与记录导出提供依据；当前不自动分毛利或计算奖金 |
| 是否要两边重复录一遍 | 分工后按实际建团或分配主责；分工记录并非实际参与记录 | 已有项目团主责计调会进入参与记录导出，不应为了导出再次重复新增同一份计调记录 |

本区的两个操作：

- **新增成员：**负责人选实际员工、参与职责和期间，勾具体项目团或记录项目总体参与，说明实际工作后保存。需要这个人操作建团／报价时，仍由负责人在“项目分工”授权；需要他接手已有团，办理“分配计调／移交”。
- **导出参与记录：**负责人导出项目团主责计调、移交记录和另行登记的参与成员，核人员及期间后交管理人员参考。同一人确实承担另一职责时可以另记，但不能把重复行直接当多份工作量。

**产品判断：**保留“操作分工”和“参与记录”的业务区别；本区更适合叫“参与人员／补充参与人员”，让人知道只需补充实际协作，不必与项目分工重复建人。当前仍叫“项目成员／新增成员”，本轮仅说明，未改名。成员目前没有逐条编辑／删除入口，记录错误的修订方式仍需完善。

#### 第三块：变更与办理记录

负责人和接手人员按记录查谁在何时做过分工、资料或业务变更，回对应原单核依据。这里用于追溯已经发生的操作，不是另设一套审批或重新录入业务。

#### 第四块：结算期限——当前存在，建议从本页移除

现有“维护结算期限”由负责人登记“实际完成后几天应办业务结算”和依据；保存后为已完成的项目团计算截止日期，以后确认完成的团也按该设置计算。工作台据此提示结算是否到期。

**建议去掉本页这项日常维护。**它只影响到期提醒，不决定能否提交业务结算，也不是客户付款期限、供应商付款条件或财务记账月份。让每个项目负责人重复维护天数，容易让人误以为是结算必做步骤。

以后若有明确的公司统一结算时限，可统一管理；确有项目特殊期限时，再在具体办理场景表达。公司天数仍待确认，不在文档里预设。若实施删除，应同时核原有截止日期和工作台提醒如何保留或调整，不能把没有设置期限说成业务已经结算。本轮原型按钮仍保留，故在当前页面位置注明用途与建议。

#### 第五块：项目附件

负责人点“维护项目附件”，保存整项委托共用的需求、整体方案或公共交接材料，核文件后保存。销售、计调和审批人由此找到共同依据；本团完成证明和具体执行材料放在本团资料，避免每团复制公共材料造成不同版本。

#### 第六块：结项情况

业务结算抽屉保存或提交时再次核项目、团及原结算状态；已确认原单和已结束项目不能被旧窗口覆盖。

负责人查看项目收尾安排或已提交结项的说明、状态、遗留款票及责任人。正式申请从本页顶部“结项检查”办理；这里承接结果，供审批后继续核未清事项。

## 三、项目团控

**入口：履约中心 → 项目团 → 项目团控。谁使用：计调、负责人。**这里跨项目列具体项目团，适合计调每天找自己要办的团；不另建一套与项目详情不同的记录。

### 3.1 顶部“新增项目团／批量建团”

| 操作 | 谁、如何办理 | 解决的问题及结果流向 |
|---|---|---|
| 新增项目团 | 获授权计调点按钮，在抽屉顶部搜索项目／客户／编号并选项目，再填本团服务、日期、地点、人数及主责；先保存草稿留待报价及客户确认，再从本团办理确认建团 | 已分工但尚无团的项目也可开始建团；草稿交本团计调补执行，客户报价另办 |
| 批量建团 | 选所属项目及共同资料，采用直接填写、按日期生成或导入表格；逐行核对清单，全部通过后“保存N团草稿” | 把百场排期变成各自可追踪项目团，仍留在一个年度项目下 |

按日期生成时可选择周期规则或手动日期，核排除日后“生成项目团”；生成后可逐行调整、复制、删除、补团，按分页定位错误。导入使用模板文本或粘贴表格，先读取纠错再保存，当前不直接读取Excel工作簿。更换项目会清除尚未保存的准备资料，保存前应核准客户和所属项目。

找不到可建团项目时，由负责人核“项目分工”中的人员、期间、城市、服务和建团权限；不是去“项目成员”加个人就能解决。

### 3.2 筛选及批量操作区

计调按项目团／客户／编号、所属项目、计调、项目团状态及日期查询。限定一个项目后，可选择当前筛选的全部或跨页勾选，出现“批量维护／批量报价”。

- **批量维护：**对草稿团应用共同资料，再逐团核差异，核对后保存有效团。未通过的继续修正，已执行团的改期走变更。
- **批量报价：**选本人允许办理的项目团，逐团核金额、客户凭据及审批依据，保存草稿或登记客户已确认报价，仅办理有效行。此处适用于每团独立成交；整包总价按一份多团报价办理。

### 3.3 项目团列表及分页

每行先认项目团、所属项目和客户，再看日期地点、人数、计调、状态和资料缺口。2026-10-21按用户澄清撤回模块二级办理区，恢复原详情；现保留以下业务表单或导出；成本和结算已按10月24日要求移至团期结算。计调／项目负责人从当前团办理，申请仍交原审批及财务流程。

| 快捷操作 | 直接办理内容 |
|---|---|
| 导出名单 | 导出当前项目团名单CSV |
| 收款认领、开票申请 | 当前团只有一张已确认订单时直接开申请；多张先选本次订单，整包金额仍按整单办理 |
| 订单改价 | 打开本团独立订单的原金额变更抽屉；整包订单须从订单详情申请整单变更 |
| 新增报价 | 打开原报价抽屉，预选当前项目团 |
| 结算办理 | 已移至“履约中心 → 团期结算”，项目团控列表不再提供结算动作 |
| 发起项目团变更 | 打开原项目团改期／取消申请抽屉 |
| 维护附件 | 打开当前团资料附件抽屉 |

2026-10-21按用户最新确认，项目团只保留4种状态：草稿、进行中、已完成、已取消。确认建团直接进入进行中，包含服务准备和实际交付，不再另点“开始执行”。旧待确认并入草稿，旧准备中／执行中并入进行中，保留资料、原状态记录和实际服务事实；项目、报价、订单及结算单各自状态保持。

列表常驻“详情＋阶段推进动作＋更多”：草稿确认建团，进行中确认完成，均直接打开原表单；业务快捷操作按下表进入更多。完成与取消后查看历史资料，成本和结算收尾进入团期结算。保存或关闭回原列表，保留筛选及页码；当前团离开所选状态后从筛选结果中消失，切换状态即可找到。

| 项目团主状态 | 常驻办理动作 | 更多中的范围 |
|---|---|---|
| 草稿 | 确认建团 | 仅编辑、新增报价；附件随建团资料维护 |
| 进行中 | 确认完成 | 导出名单、收款认领、开票申请、订单改价、发起项目团变更、维护附件 |
| 已完成 | 详情 | 导出名单、收款认领、开票申请、订单改价、维护附件；审批中或已确认结算不得直接新增原费用，差异走原调整流程 |
| 已取消 | 详情 | 导出名单；有关订单或费用时到团期结算办理收尾 |
| 所属项目已结项／终止 | 详情 | 导出名单、查看已有结算（若有） |


确认建团复用已有客户确认资料；按实际结算的报价可以引用已确认的计价规则，不要求先填最终结算金额。引用框架合同时须已签署且覆盖服务日期。草稿不办理费用、款票或结算，进行中不提前核对结算。

款票及改价依关联订单状态限制：无已确认订单时置灰并说明原因；整包订单的本团改价入口置灰。按钮不随名单、资源等资料缺口改变。原型统一超级管理员，岗位只解释职责。详情按八个执行页签组织；金额、成本和款票核对进入团期结算，列表不再复制详情模块。

底部翻页后仍核实际选择数。批量维护和逐团报价仅允许草稿，核对及提交均重验阶段；已建团价款变化回原订单改价。项目内团列表、团详情、费用、变更审批、提醒和查询已按同一规则同步。

## 四、项目团详情（执行交付）

**入口：项目团控 → 详情。主要使用人：计调、项目执行负责人。**上游引用客户委托、原报价和订单，现场按本团资料交付；完成后交结算经办核单据。团期结算操作列“详情”打开独立的十页签结算抽屉，只有“查看执行详情”才反查本页。

### 4.1 顶部操作与总览

草稿团沿用“确认建团／编辑”，进行中沿用“确认完成”。完成时登记实际日期、实际人数、完成依据、交付情况和附件；真实未交付服务先补交付或办理有效范围调整。我方完成不等于客户认可，也不等于资金结清。

“总览”核客户、服务日期、负责人，分别显示计划人数、确认人数、名单人数和实际服务人数；未知确认人数不取计划人数冒充。执行缺口定位到日程、名单、签证或资源。本团完成记录及结算状态可以查看，完整成本、收付款和毛利集中在结算详情。已完成／已取消团保留查看，原执行资料受状态保护。

### 4.2 执行安排

“调整服务”维护会议、旅游或混合服务及名单要求；已有实名资源不能靠改成人数交付绕过资料要求。“新增日程／编辑”维护日期、时间、行程或议程、地点、负责人和引用资源；旅游服务可补餐饮、住宿、交通等安排。原服务类型留下的历史日程在操作日志查看。资源本身在“资源安排”维护。

### 4.3 报名名单（紧接执行安排）

| 入口 | 如何办理 | 边界 |
| --- | --- | --- |
| 新增人员／编辑 | 登记姓名、电话、证件、需求和备注；需要签证时核个人办理方式与依据 | 不改计划人数、原订单金额或已有接待安排 |
| 导入名单 | 抽屉打开有默认资料，可选CSV替换；逐行核对后导入，待修正行留在批次结果 | 重复保留原人员；模板只含表头 |
| 分组分房分车 | 勾选人员；未勾选使用当前筛选。进入“人员安排”逐行填写，需要多人同值时展开“统一填写一项”，最后保存安排 | 只修改当前范围内的分组、到离批次、房间和车辆；个人资料与签证结果不覆盖 |
| 导出 | 分别导出人员资料或分组安排，沿用已选／当前筛选范围 | 不受全团统计影响 |

名单只显示签证摘要和个人状态，团级要求统一在下一页签维护。按人数交付的会议不强制实名；完成团仍可查看和导出。

### 4.4 签证进度

设置本团是否需要签证、目的地、类型和依据；列表核个人代办、自办、已有签证或免签方式及已有材料、送签、出签记录。“查看人员”回报名名单定位该人员，个人资料只维护一份。“打开签证办理”进入原签证工作台，不另造签证订单或自动回写结果。目的地或证件变化保留原结果并标待复核；已有签证声明不当成已核验出签。

### 4.5 资源安排

集中维护交通、酒店、车辆、会场设备、餐饮、地接及其他服务，会议也可安排交通和酒店。按类别筛选后新增／编辑原资源，核供应商、服务日期、数量、单位和安排；“确认资料”核班次、订位记录、确认号、规格、地点及联系人，交通可登记本团人员票号。清空已确认资源的确认依据后恢复待确认。取消保留原记录与原因，不自动消除费用。

领队／会务执行人员引用原档案，按安排、确认和实际出行登记，重复有效派团不重复新增。资源数量是交付安排，不是公开可售名额；确认资源不生成或确认成本。

### 4.6 关联订单

查看本团客户委托、原报价、订单、合同、成交金额和覆盖范围，进入原单据继续办理。多团整包金额明确属于原整单，不复制成本团成交收入。报价仍在原“报价与合同”流程办理；改价、认款、开票与退款继续在原订单和原财务单据处理。

### 4.7 执行准备

核日程、名单、签证和资源的准备情况，回相应页签补资料；根据本团数据生成出团通知／会议执行资料，预览或下载。维护客户与执行附件，查看完成交付附件。这里不维护结算依据或票据金额。

### 4.8 操作日志

查看本团执行资料、人员、资源和服务状态变动，保留历史日程和“改期与取消”原申请。审批后重核相关日期及资源；金额变化回原订单／费用，不在日志直接改金额。

### 4.9 独立的项目团结算详情

**入口：团期结算 → 项目团操作列“详情”。**默认只读单据总览，沿用以下十页签；“结算／查看结算”按原状态办理或查看，“维护成本”在执行期间即可使用。

| 页签 | 核对内容 |
| --- | --- |
| 单据总览 | 本次范围、完成与认可、含税／预计扣税后／核定扣税后的收入、成本、税额、毛利；按币种分别显示 |
| 收入明细 | 本次收入与销项税、原订单、客户认可单及依据；整包进度认可不生成分团收入 |
| 优惠减免 | 原单已登记优惠及已批准订单增减；未单列标待核，不默认为零，不重复扣减 |
| 成本明细 | 直接费用、跨团分配、管理分摊、本次承担、项目承担、未分配、可扣税及原差额 |
| 订单明细 | 本次相关原订单、覆盖团、成交金额与状态 |
| 收款预收 | 原订单已认款、认款申请及预收分配记录；待认款不计实收，整包款不均分 |
| 预付付款 | 原采购总额、已付、核销、付款申请和执行记录，对照本次承担 |
| 变更记录 | 与本次项目团、订单或费用关联的变更、状态、增减金额及依据 |
| 附件依据 | 结算缺项、本次依据、未结事项，及原完成、客户认可、采购和供应商对账材料 |
| 结算记录 | 草稿、提交、退回、确认、版本、导出与打印预览 |

结算办理时先选范围，在原费用补分配和税额依据，再保存草稿／提交。审批中及已确认金额继续引用原提交／确认记录，后续来源金额变化不覆盖历史结果；退回按原记录修正重提。当前原单收付资料与当时结算金额分别核对。

总览“查看执行详情”反查交付资料；返回恢复原团、记录、列表筛选和原结算页签。整包未分团收入、未知税额、未登记优惠／核销及旧22万元成本差额均保留待核，不补造零值。实际收付、预收退款及原单余额继续在原单核对，本次不新增真实财务接口。

## 五、项目采购与团期结算中的成本维护

**入口：履约中心 → 项目团 → 项目采购；本团成本也可从团期结算办理。谁使用：计调、采购经办，负责人查看。**项目采购独立列表集中管理公共、跨团及未排团采购。本团在团期结算列表点击“维护成本”，同页“项目费用”仍引用原采购；两处使用同一费用表单和记录。进行中可以维护费用，服务完成后再办理最终结算。

本团维护抽屉可引用执行资源新增费用，带入服务名称、供应商、日期、数量和确认依据，金额及税费仍在费用表单核对。资源安排继续归团控。

#### 本团成本维护：摘要、范围及顶部操作

先核本团预算、最新预计和已承担费用。范围选“本团费用”时看本团直接费用及已分配承担；选“项目采购”时看该项目整体或跨团采购。

| 操作 | 谁、如何办理 | 解决的问题及结果流向 |
|---|---|---|
| 新增费用 | 经办先选费用归属，确定单个项目团、指定多个项目团或项目整体；按服务、供应商及真实采购依据录金额和日期，再补付款条件、适用汇率、票据及附件。“保存明细”留待确认，依据齐后“确认费用” | 建立同一笔支出来源，交财务核应付及付款；确认费用不等于财务入账或已经付款 |
| 调整本团预计／调整项目预计 | 经办填写最新预计、变化原因和依据后保存，保留原预算 | 负责人能提前判断超支。费用增加不会自动增加客户订单金额，要加价由销售取得客户同意 |

共同采购有“采购服务交付”时，核实际交付并登记依据；不能因其中一团结束就把整个跨团采购认定为全部交付。票据识别只提供样例结果，经办仍须对原票核验，最终可扣税额由财务核定。

#### 本团成本维护：费用列表及“详情”

打开原费用后，按“采购费用 → 金额及付款 → 适用汇率／费用分配 → 付款申请记录 → 票据资料 → 关联办理”核对。看清原采购总额和本团承担的区别，再操作：

| 详情中的操作 | 谁、如何办理 | 结果流向 |
|---|---|---|
| 编辑费用 | 经办补采购依据、交付情况、付款条件或票据，保存明细或确认费用 | 应付和付款仍核同一原采购。已付／已结部分受限制，不能直接覆盖 |
| 分配费用 | 原采购经办按实际使用或已有分配依据填各团承担，同时核项目承担和未分配余额 | 本团结算和差额使用明确承担金额；各团分配不再加一遍项目成本，已结部分保留 |
| 申请付款 | 核当前条件允许申请额、已付及有效申请占用，填本次金额、日期、用途和材料，提交 | 进入待财务复核，交财务核账户和条件，再交审批、出纳。提交只占用可申请额，不增加已付款 |
| 付款申请记录 → 查看 | 经办查本次状态、退回原因和财务复核入口；符合条件时“撤回申请” | 未付款部分按规则撤回，已付款记录保留。业务侧退回后改原申请金额／依据的统一入口仍待完善 |
| 费用调整 | 有权限的经办登记增减、原服务日期、调整日期、原因和依据，提交适用审批 | 已结算后保留原费用和原结算，以关联调整反映追加或减费；退款到账另由财务处理 |
| 供应商对账 | 从本采购进入双方对账，核同供应商、公司、币种及服务期间的采购 | 交供应商核当前版本，双方认可后交应付财务；不再形成第二笔成本 |

分配时应能核平：各团承担＋项目承担＋未分配＝原采购总额。未分配不等于零成本，也不等于已批准全部由项目承担。



### 5.1 项目采购顶部“新增采购”

点“新增采购”进入原“新增费用”抽屉，先确定所属项目及单团／多团／项目整体范围，再按“采购明细 → 付款条件 → 适用外币折算 → 票据 → 采购服务交付 → 附件”填写。未齐点“保存明细”，有真实采购确认依据后“确认费用”。结果交应付财务及付款申请使用，不直接完成付款。

同供应商一笔费用服务多个团时建一笔采购，再明确分配；不要为了每团都有记录而重复建相同采购。

### 5.2 筛选和采购列表

按费用／供应商／编号、项目、服务范围及确认状态“查询”，或“重置”。从本团来源进入时会带相应范围，可“清除项目团筛选”看更完整采购。

列表用于找原采购和确认状态，点“详情”核供应商、总额、已付与可申请金额。缺供应商确认或付款条件时，先补原依据，不通过重复新增避开旧记录。

### 5.3 原采购“详情”及全部处理

详情依次核采购资料、金额及付款、汇率或分配、付款申请记录、票据、关联办理；经办在这个原记录内完成下列操作：

| 操作 | 谁、如何办理 | 结果流向 |
|---|---|---|
| 编辑费用 | 原采购经办补金额、确认依据、交付、付款条件或票据，保存明细或确认费用 | 更新应付和请款的业务依据；已付、已结部分需核限制 |
| 分配费用 | 经办登记每团实际承担和分配依据，区分项目承担与未分配，核总额后保存 | 本团费用、业务结算和经营结果引用各自承担；已结分配不能覆盖 |
| 申请付款 | 核当前条件、已付及其他申请占用，提交本次金额、用途、日期和依据 | 待财务复核，再审批、出纳付款；批准也不等于实付 |
| 付款申请记录 | 查看状态、原因和财务办理；允许时撤回未付部分 | 跟踪同一申请，已付款留痕，退回修订入口不足的分支继续核查 |
| 费用调整 | 填原服务和本次调整日期、增减额与依据后审批 | 保留原采购和原结算，形成关联调整，后续由财务处理补付或退回 |
| 供应商对账 | 进入原采购对应的供应商对账，核双方版本和材料 | 认可金额供应付核验，不另增一笔采购 |

成本维护负责确认采购和分配依据；提交业务结算从团期结算列表“结算”进入原十页签抽屉，选择已完成或取消收尾范围，必要时包含项目承担费用。项目团控不办理费用或业务结算。

## 六、供应商对账

**入口：原采购详情“供应商对账”，或履约中心供应商对账中的“项目采购对账”。**我方计调／采购经办发起，供应商确认金额，财务使用双方确认依据。

### 6.1 顶部、页签和查询

我方视角可“新建对账”，下方按“我方对账／供应商确认”查看对应处理，输入对账单／供应商／项目团找原单。两视角用于表达不同办理方职责，不是我方业务人员替供应商随意批准金额。

新建时先限定公司、供应商、币种、服务期间和采购确认依据，再选符合交付和确认条件的原采购，核金额后“保存草稿”或“提交对账”。此动作把我方核对清单交供应商，不形成新成本或付款。

### 6.2 列表与详情

草稿由我方“编辑”，其他状态点“详情”。详情顺序为当前版本摘要、采购明细、办理记录、当前办理。

| 当前办理 | 谁、如何操作 | 结果流向 |
|---|---|---|
| 确认当前版本 | 供应商核逐笔原采购及本次金额，填认可金额或差异原因，上传本版盖章材料，核一致后“提交确认” | 留供应商认可或差异。旧版盖章件不能证明新金额已获认可 |
| 处理差异 | 我方经办核服务、数量、价格和损失，登记本次认可金额与原因，“重新提交” | 新版本再交供应商确认，保留旧记录 |
| 查看财务核验 | 双方确认后，财务进入应付管理核对原采购、对账差额、票据和付款 | 对账结果成为财务依据，实际付款仍按原申请办理 |

## 七、项目订单列表及订单详情

**入口：销售中心订单管理中的“项目订单”，或报价／本团客户订单“查看订单”。谁使用：销售主办，负责人、计调及财务按权限核对。**本页围绕一份成交，不按项目团数量强行拆单。

### 7.1 项目订单列表

销售按订单／项目／客户“查询”，核客户确认金额、覆盖团数和状态后点“详情”。同一报价有效确认承接同一订单；年度月结不能再加一份同额收入。

### 7.2 订单详情顶部及摘要

先核订单号、项目、客户、覆盖团数、客户确认金额和财务已认款。顶部“合同”进入本单合同办理，“收款认领”进入本单认领；两项结果仍分别回合同记录和财务认款结果。

下面七个页签按页面从左到右说明。

### 7.3 “订单概览”

销售先在“订单资料”核客户、公司、原报价版本和服务范围，再在“关联项目团”核本单覆盖及每团的草稿／进行中／已完成／已取消状态。订单仍保留自己的成交状态，不因团完成就改成订单已结清。需要看履约时点具体项目团名称进入原团。这个页签把对客成交和计调执行范围对应起来，整包未分价时不显示虚构的单团收入。

### 7.4 “游客信息”

“服务名单”按覆盖项目团看名单要求、已登记与计划人数。销售发现缺项时点“查看项目团”，由计调在原名单补正；订单这里不再维护第二份名单。按人数交付与实名服务分别判断，不能只看登记人数就认定服务资料齐全。

### 7.5 “合同资料”

销售在“本笔合同”核客户、公司、金额、合同编号和状态，点“合同办理”继续本单签署或归档。签署文件交计调作为服务依据、交财务核对；合同完成不代替到账认款。

### 7.6 “应收收款”

页面依次为收款计划、认领记录、开票记录。

| 区块／操作 | 谁、如何办理 | 结果流向 |
|---|---|---|
| 收款计划 | 销售核各阶段确认金额、财务已认款、未认款及到期条件 | 判断订金或尾款是否已实际认款，不以日期到期或客户口头付款当实收 |
| 收款认领 | 从本单选适用流水，按订单和阶段分配金额、登记归属依据并提交 | 收款财务接原认领复核，成功后反映本单实收 |
| 开票申请 | 核本单及可开范围，补完整客户开票资料、备注和收票方式后提交 | 开票财务审核办理，成功结果回原订单 |
| 认领记录 | 查原认领编号、流水、本单金额及状态，通过“财务复核”查看来源办理 | 出错先由财务退回，业务在原申请修正，不重复占用同一流水 |
| 开票记录 | 查原申请、备注和状态，“查看办理”核原结果 | 未知、失败、成功分别处理，已开具查发票文件 |

### 7.7 “售后变更”

本页“订单改价”由销售点“申请改价”，登记本次增减、原因、客户确认依据及适用审批，再保存草稿或提交变更。批准后在原订单体现新金额并留原记录，财务重核应收、税额及需要的补收或退款。

已有草稿／退回记录从“修正”继续，审批中／已批准看“详情”。减价恰好等于原对账整笔争议时已有解除该笔争议的处理；部分让价或补服务后的重新认可另须验证。最终金额原本未定的订单也被引向此处，但按实际数量形成最终金额和收款计划的完整操作仍待专项验收。

若从来源入口打开独立“订单售后”页面，先核当前订单，再在“订单改价”区申请、修正或查看同一批变更记录，处理方式与本页一致；它不是另建一份售后金额。

### 7.8 “收付与发票”

销售和财务核订单应收、已认款、已开票和报价来源依据，再按实际任务进入“合同办理”“收款认领”“开票申请”或“财务结算”。这些入口把本单交给对应办理岗位；本页不负责付款、核销或记账。

### 7.9 “操作日志”

销售、负责人核本次报价、改价及办理历史，追溯经办责任。当前日志包含同项目记录，要按订单和来源辨别，不能把另一订单动作当成本单已完成。

## 八、合同管理及合同办理

**谁使用：销售、合同经办及合同审核岗位。**优先从原框架或原订单“合同办理”进入，以免选错签约来源；无具体成交订单的框架也能办理。

### 8.1 合同列表：状态、查询、行操作

先按合同状态页签找草稿、待审核、待签署、签署中或归档记录，再按合同／订单／客户等条件查询。需要新建时“生成合同”选择正确来源；已有来源合同继续原记录。

| 行操作 | 谁、如何办理 | 解决的问题及结果流向 |
|---|---|---|
| 归档／编辑 | 销售核草稿或审核退回合同。线下签署准备归档资料；在线渠道按可用模板及规则准备正文、签署人和附件，再提交审核 | 把完整合同资料交审核岗位，不以保存草稿代替双方签署 |
| 归档确认 | 有权限的归档经办核已审版本、双方盖章、授权及文件，预览后“确认归档” | 留可追溯签署文件供执行和财务核对 |
| 发起签署／平台办理／签署核对 | 经办按当前合同显示的渠道动作办理，核双方、已审稿及签署安排 | 内部审核只允许继续签，实际签署结果另行核实 |
| 签署进度 | 经办查询必要签署方及我方签章结果，失败或超时从原合同处理 | 全部必要结果成立后核签署文件，不因单方已签就认定合同完成 |
| 详情 | 销售、负责人、审核人查看下列区域 | 核哪份文件、哪一版服务已生效 |

### 8.2 线下合同归档办理

核原项目／订单及本版金额，准备双方盖章文件和企业代表授权；必要时补签署人资料。资料未齐保存草稿，齐备后提交归档审核。已有外部批准时，核同一合同版本及批准依据后引用，不能跳过文件核对直接宣称归档成功。待归档再从原行完成“归档确认”。

客户要求改内容时修订原待办或建立适用变更版本，不覆盖已归档文件。框架上限不变成具体订单收入，具体服务金额与本单成交保持对应。

### 8.3 合同详情：从上到下核对

| 区域 | 谁、如何使用 | 对后续业务的作用 |
|---|---|---|
| 合同摘要、变更或解除情况 | 经办核当前有效版本及正在处理的变化 | 确认计调和财务应使用哪版文件 |
| 框架服务范围／本单合同覆盖 | 销售核框架范围，或具体订单必要签署及覆盖情况 | 框架与收费订单分别对应，避免未覆盖服务被当成已签 |
| 内部审核 | 核本次审核、退回原因；需要时“进入审批中心”，待审核按权限可撤回 | 退回后补原合同再重提；演示审核结果不是销售审批授权 |
| 监管相关区域 | 合同经办按已确认的适用要求核报送或不适用依据，结果未知查原申请 | 签署、归档和监管结果分别留记录；不由销售自行批准监管规则 |
| 正文与附件 | 预览稿件，查看归档／签署文件，缺文件时按当前状态获取，核附件和授权材料 | 计调按有效内容执行，财务核签约依据 |
| 同订单合同及历史版本 | 核原主合同、补充协议、新版本及历史文件 | 保持变更前后对应，不把每份文件都算一次成交 |
| 办理记录 | 查提交、审核、签署、归档及文件访问历史 | 出现争议时能找到本次使用版本及经办依据 |

详情底部按状态可“修改重提”“撤销草稿”“变更处理”或“撤销／解除申请”。已签变更从有效原合同发起，选择原业务变化依据并建相应版本；解除需核批准及双方／渠道办理结果。涉及金额及退款先核原订单和财务，不以合同解除替代实际退款。

## 九、收款认领

**入口：销售中心 → 收款认领，或原订单“收款认领”。谁使用：销售或有办理范围的经办。**这里解决客户一笔汇款到底属于哪些订单和阶段；财务随后确认。

### 9.1 顶部“认领款项”及认领抽屉

1. 在“客户款项”先核客户、收款公司、币种，选择匹配到账流水，核可认领余额。
2. 在“订单分配”按客户付款清单逐单填写金额和收款阶段；跨阶段时可选“按剩余应收分配”。只在本团来源办理时核本单，集中办理可核允许的相容订单。
3. 登记客户付款与归属依据、附件，核合计不超过可认领款及订单已明确未收金额后“提交认领”。超出部分留原流水，不另造收入。

结果为待财务认款，交收款财务核实。当前会奖认领使用演示到账记录，普通到账流水与此视图的来源接续仍需验收；没有匹配流水时交财务核实，不能凭空认领。

### 9.2 认领列表及原申请恢复

业务从“查看复核”追踪原申请；已退回点“修正”，核错误的流水、订单或阶段后重新提交。合并多单的申请应在这里核全单，保留原编号和意见，避免重复申请占用同一流水。财务确认成功后，订单的已认款和对应收款阶段才增加。

## 十、财务办理页面

这一章逐个页面讲完。菜单说明职责归属；核当前会奖原型时优先从原订单、认领、付款申请或对账来源进入对应视图，并核项目及单据。普通菜单能否直接找到同一会奖申请仍是交接检查项。

### 10.1 到账流水

**收款财务使用。**在“财务 → 收款应收 → 到账流水”核银行到账、付款方、收款公司、币种和金额，给销售提供可认领依据。客户口头说已付、合同已签或发票已开，均不能代替实际到账。当前普通流水与会奖演示流水分开，不把新增普通流水后继续会奖认领写成已验证操作链。

### 10.2 认款复核

页面先列认领编号、流水、金额与状态；待财务认款点“复核”，其他记录“查看”。

收款财务在抽屉先核流水及付款方，再逐单核金额和收款阶段，最后登记复核意见：正确“确认认款”，错误“退回认领”。成功才反映原订单实收；退回交业务在原认领修正，财务不以改订单总额掩盖认错款。

### 10.3 应收管理

应收财务在订单列表核确认金额、已认款及未收／多收，先识别客户还欠多少。点“查看订单”回本单收款计划及认可依据；点“税额核对”核定收入相关税额和依据后保存，供财务金额及业务毛利核对。

订单改价后应重新核应收和税额。原金额仍待确认时，不能把客户对账或已开票当成订单已最终定价；出现多收，核原批准变化再办理适用退款。

### 10.4 应付管理

应付财务先核来源项目；从供应商对账进入时还会看到对账版本、确认情况及与原采购的差额。费用列表逐笔核确认费用、实付和未付，点“核对”进入原费用与应付核对。

抽屉先核原采购及付款结果，再核财务可扣税额、适用折算汇率和依据；需要时核分团税额。点“查看业务费用”回原采购核材料，“保存财务核对”留下核定结果。票面税额、预计可扣税额和财务认可的可扣税额各按依据处理，不由票据识别自动定案。

### 10.5 付款复核

应付／付款财务在列表定位原申请，点“复核”。依次核付款公司、供应商、申请及已付金额、原采购条件和申请依据，再核供应商已审核账户及本次意见。

- 不符合：退回原申请，申请人核原因及原采购依据。当前业务侧统一修订原申请金额／依据的入口仍需完善。
- 符合：点“送业务审批”，交审批人核本次付款事项。复核通过不增加实际已付。
- 从具体申请进入时，可通过“查看付款管理”和“查看审批”继续查本单结果。

### 10.6 付款管理

出纳先从申请列表核状态和本笔已付，点“查看付款”。在“付款管理”抽屉核批准申请和核准账户，再登记本次实际金额、交易号、日期及银行结果，查看原付款记录。

成功才增加本笔及原采购已付；部分付款保留剩余。失败不增加已付；结果待查先核原交易，不能再付一次。审批通过、付款申请金额、实际付款分别是不同事实。需要反查从原申请“查看复核记录／查看审批”核依据。

### 10.7 发票管理：业务申请视图

销售或授权经办从原订单进入“开票申请”视图。顶部“开票申请”先核购买方和销售公司，再填税号、开票项目、金额、完整备注、收票方式，核允许订单的逐单分配后提交。

申请列表中，已退回或开具失败从“修正重提”补资料，其他状态进入“办理／查看”核原结果。申请占用与已开金额分开，成功才计已开票；不能因需要百单月结就默认系统已有百单一键开票。

### 10.8 发票管理：财务办理视图

开票财务按本页顺序办理：

| 位置／操作 | 谁、如何办理 | 结果流向 |
|---|---|---|
| 顶部“开票配置” | 有权财务核本公司常用税率、可用开票项目及维护依据后保存 | 给业务适用选项；配置本身不是税务政策批准 |
| 申请列表“办理／查看” | 核申请编号、购买方、金额、备注及状态，打开原申请 | 找到本次开票来源，不重新建重复申请 |
| 申请资料、订单分配 | 核完整客户资料、原订单可开范围、占用和税额依据 | 正确才“审核并开票”，错误“退回补充”交业务原单修正 |
| 办理结果、办理记录 | 开票中或结果待查“查询开票结果”；明确失败修正后“重试开票”；已有实际结果按可用入口“补录已有开票结果” | 未知保留原占用，查清后再决定下一步；成功记录不能重复开具 |
| 发票文件 | 成功后核发票号、日期和文件，可下载已有PDF或明确标识的PDF样例 | 业务回原订单／本团核开票结果，样例不作为真实发票 |

先票后款是否允许，按公司已确认政策；开票完成、到账认款和服务完成仍分开判断。

### 10.9 业务结算及业务结算详情

财务进入本项目结算视图，先在列表核业务结算状态、确认版本与款票情况，点“查看业务依据”回本次原结算，核服务范围、客户认可、实际承担费用及审批。

列表之后的“后续核算”提示由财务继续核收入确认和**会计期间**（记账月份或期间）；按项目来源可“应收核对／应付核对”。**NC**为财务核算系统，当前原型未连接，不会因业务结算批准自动生成凭证。

退款、预付款处理、回单核销和核算推送等，由相应财务岗位按原单据及批准依据承接。是否能从会奖原单正确进入后续页面须验收，不能因为财务菜单存在就认定这一条业务已经办完。

### 10.10 结算调整

负责人、业务经办和财务在集中列表看项目团变更、订单改价及费用调整的来源、金额和状态。草稿／退回点“修正”，其余“详情”；费用调整的修正回原采购，订单改价回原订单，项目团改期取消仍对应原团。

详情核原结算、变化前后、原因与依据，再“查看本次审批”；订单调整还可“查看原订单”。这个页面把变化集中展示，不能在此把成本变更直接当作客户同意加价，也不能覆盖原已确认结算。

## 十一、审批中心及手机审批

**入口：审批 → 待我审批 → 项目事项，或原事项“查看审批”。谁使用：该事项的审批人。**不因自己是项目负责人就默认能批准本人申请。

### 11.1 列表及手机入口

列表按事项、来源、项目、申请人、当前版本和状态核原待办。待审批点“审批”，已处理点“查看”；“手机审批”呈现同一事项的手机卡片，作出的决定仍针对同一版本，不新增一份批准。

### 11.2 “项目事项审批”抽屉

按页面从上到下：先核事项、来源、公司、版本、金额及申请依据；再看“办理内容”，业务结算还须看“本次费用”；用“查看来源单据”核原资料；按要求签名，核申请附件，填意见，最后“批准本版本”或“退回补充”。

| 事项 | 审批人重点核什么 | 决定交给谁继续 |
|---|---|---|
| 报价单 | 客户确认、本版价格、覆盖项目团、收款阶段、人员及框架范围 | 销售查订单和合同，计调按确认服务执行，财务核应收 |
| 付款申请 | 原采购、当前付款条件、可申请金额及已核准账户 | 出纳按批准范围办理实际付款 |
| 业务结算 | 本次完成范围、客户认可、原采购及本次承担 | 财务核后续收付、发票和核算，业务继续未结事项 |
| 项目团／订单／费用变化 | 原依据、本次变化及客户、供应商、款票影响 | 计调处理服务，销售处理成交，财务处理收退付 |
| 项目结项 | 业务缺项是否解决、未清款票是否有有效例外和责任安排 | 负责人核结项结果，遗留责任人继续原单 |

来源版本变化应退回重新核对，不用旧批准覆盖新金额。外部批准仍要在原报价／变更表单登记同版依据；演示审批和正式公司审批配置的适用范围按实际实施记录核对。

## 十二、工作台

**入口：工作 → 工作台 → 项目到期事项。谁使用：销售、计调、负责人。**只说明其中与会奖直接相关的区块。

先核“核对日期”，再按事项、到期日、未结金额、当前情况和责任人看列表。该日期用于原型演示；点“查看”按事项回到对应处理：

| 事项 | 谁接手、在哪里办 | 形成什么结果 |
|---|---|---|
| 到期收款未认完 | 销售回原订单“应收收款”，核客户付款及认领；收款财务复核 | 财务认款结果反映订单和收款阶段，结清后不再按未结款提醒 |
| 服务应完成但未登记 | 主责计调回本团，核真实交付后“确认完成” | 留实际完成依据；未交付不能为了消提醒强行确认 |
| 已完成但业务结算未确认 | 主责计调到团期结算核缺项并提交 | 审批确认本次结算，已结范围退出未结提醒 |

首页最多显示30条，没显示不代表整个项目已清。结算到期提醒依赖明确截止日期；本次建议移除项目资料中的手工期限配置后，提醒的期限来源要一起核清，业务结算本身仍可继续办理。

## 十三、数据中心

**谁使用：经营管理人员、负责人及财务。**以下按每个页面讲完，不在报表里修改原订单或原采购。

### 13.1 产品分析 → 项目结果

先选择项目、项目团月份、计调和币种，结果随条件变化；再看客户确认金额、费用组成、项目承担及未分配、业务差额和提示；需要交接时“导出当前结果”。

负责人用它判断项目贡献和费用是否完整。发现未确认金额或分配问题，按原项目、订单及采购回业务核对；框架上限、未确认报价和月度对账不再计一次成交。

### 13.2 业务毛利 → 项目结果

本页同样先限定项目、月份、计调、币种，再核收入和费用是否在同一范围，最后导出。管理者重点看是否有未定价、未确认采购、整包未分团或费用未分配，未核全时不据此评定单团利润。

当前这一“项目结果”使用业务确认金额和成本差额，不能因主菜单叫“业务毛利”就认定它等于正式会计利润。整包订单只覆盖部分筛选团时，不平均拆收入计算分团毛利。

### 13.3 订单明细 → 项目订单

按同样条件筛选，逐单核订单、项目、客户、覆盖团数、确认金额、已认款和订单状态，然后“导出当前结果”。销售及财务据此查成交和未收，原整包订单只算一次。发现金额不同，回原订单核报价和批准改价，不在报表补一张月结收入。

### 13.4 回团明细 → 项目团

先筛项目、项目团月份、计调和币种，再逐团核编号、项目、主责、项目团状态、实际完成及客户金额，最后导出。会议也依据项目团服务完成事实查询，不必是旅游回团。

本报表没有完整采购成本明细，承担费用回团期结算或项目结果核。四页的“项目团月份”按计划开始月份筛选，不是财务记账期间；报表只读，当前不提供点击单元格下钻。完整项目／项目团资料输出仍属原第4步待完善范围。

## 十四、按页面核完后，再检查岗位之间能否交接

本表为产品走查标准，不是本轮重新做过业务操作的通过清单。

| 检查点 | 对照页面及应看到的结果 |
|---|---|
| 一个客户委托只建一个共同项目 | 单团项目下有各具体项目团，两个建团入口查看同一记录 |
| 先交办，再自主建团 | 项目分工说明建团／报价范围，计调能在范围内建团；不是靠新增成员获得操作权 |
| 主责与协作人员分清 | 具体项目团有主责及移交；项目资料只补实际参与人员，导出不把重复录入当多份投入 |
| 客户成交只计一次 | 报价确认对应原订单；框架、月度对账、合同文件均不再重复生成收入 |
| 按实际数量结算能继续收款 | 客户认可数量、单价与最终订单金额及收款阶段相符；此分支仍需专项验收 |
| 计调有明确执行版本 | 原订单／合同覆盖与本团日程、名单、资源对应，完成事实有依据 |
| 采购及分团承担不重复 | 项目原采购只计一次，各团、项目承担和未分配能解释总额，已结部分不被覆盖 |
| 业务申请能交给财务 | 财务从实际工作入口找到对应认领／付款／开票申请及原依据，不能只凭菜单同名判断 |
| 审批与资金结果分开 | 财务认款后才增加实收，付款成功才增加实付，开具成功才增加已开票 |
| 客户认可与内部完成分开 | 本团完成记录、客户对账各有责任人与依据；争议处理留原订单变化及历史 |
| 可先结一部分，继续其他团 | 本次结算范围及承担明确，项目承担费用也能收尾；年度项目未完不结项 |
| 退回和变化能回原记录 | 报价、变更、结算修正重提；付款退回修订、部分争议处理等未完分支继续查 |
| 结项后遗留有实际承接 | 业务问题先解决，获准款票遗留有责任和入口；结项后新认领／开票仍须验收 |
| 管理结果能解释 | 币种、日期、范围、税额及费用状态一致，缺项不按零；正式任职、汇率和完整输出继续原第4步 |

可用两条故事贯穿核对：奖励旅游五团各自成交时保留五单，整包总价时保留一单；医药年度会议项目在当月百场结算后继续第101场，按月对账不重复建成交。两种故事都要检查共同采购、提前收付、取消、追加减费和未清款票由谁继续处理。
