# P0-5 团期订单跨主体履约承接实施验收

2026-09-27。依据用户本轮指定及《福建销售北京产品-原型改动详细方案》第四节P0-5，修改团期订单列表、详情及仅这两页使用的直接共享文件。

## 业务位置与改造边界

销售下单后，团期订单由实际履约公司的计调承接资源、名单、供货补差依据和执行结果。销售公司查看履约结果，客户合同、对客成交金额及客户款继续由销售公司办理；结算确认、应收应付和付款仍归财务。

现有团期订单保留独立入口，这是用户此前明确的页面安排。本次用户又明确授权修改这两页，因此历史报表工作线中“团期订单不改”的阶段边界不阻止本次实施。两者不冲突，也不据此重新改报表。

现有团期订单详情沿用较多销售办理内容，原列表也有应收调整和批量业务动作。按本次“普通自营保持、特殊场景按需出现”约束，原自营页面保持；仅跨主体订单采用履约内容和公司办理限制，避免供货方在履约页修改另一主体的客户价格。

## 代表场景

1. `KSIC260901`：福建销售北京“西藏深度探索7日”，团期 `BJ-XZ-20261015`。福建查看履约，北京处理履约；客户订单已确认、实时资源已确认，不因跨公司再制造一轮强制确认。
2. `KSIC260902`：北京销售福建“福建闽南文化5日”，团期 `FJ-MN-20261022`。福建处理履约，北京查看结果；初始资源待确认。福建反馈确认或无位均不直接改变北京客户订单状态或对客价格。
3. 默认福建节点即可分别看到“销售方只读”和“履约方办理”两种场景。进入详情后，履约操作位于游客名单、资源安排、补差依据、执行结果各自页签；列表不重复堆操作。
4. 关联销售订单与团期订单引用同一个订单号，不另建第二笔客户成交。销售公司可从关联订单进入自己的销售详情；履约公司只显示另一公司的订单号，不提供越主体修改客户单据的跳转。

## 原型与后续边界

- 本步实现当前页面内的操作与公司归属限制，没有新增用户角色切换器。共享导航仍是现有福建公司部门树；北京及无关公司用同一上下文切换事件验收。正式多公司范围、员工岗位和字段授权按P1-2实施；不能把公司符合直接当作任何员工已获得生产操作权限。
- 两个样例沿用前序订单事实，采用本页独立的名单和履约记录。保存可在本页查看，刷新恢复样例；不自动写回销售订单、不自动生成财务单据、不修改真实团期库存，也不伪称已发送通知。
- 对客成交金额在本页只读，供货补差待销售方确认；内部价格授权、补差审批、双方结算与会计政策仍需业务／财务确认。实际对账办理仍是后续P1-1。
- 旧普通自营流程、其他团期管控页及财务页面未扩大改造。原状态页签数量与分页仍为原示意数据，不把新增两例作为正式统计结果。
