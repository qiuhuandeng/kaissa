# 供应商主动账单与计调核对实施验收

日期：2026-09-26。状态：本次原型已实施并验收。

## 一、用户确认的方向与本次边界

用户澄清“供应商不用等我方先发起，也能选采购订单提交账单”，随后要求“执行下一步”及“继续完成上一步未完的”。本次优先补齐这一明确范围；此前建议先补采购订单确认的顺序由本指令接续。两方均可先提交，不再将我方先发起作为供应商上传的前置条件。

采购订单来自我方向供应商采购的业务，不由对账单创造。供应商仅选择本供应商的采购费用；按采购公司、协议、币种及期间分开。已有对账匹配原单，没有对账才建立新单；同一费用不能重复对账。

## 二、人员与工作流

| 当前动作 | 操作岗位与入口 | 数据与下一位办理人 |
|---|---|---|
| 我方先发起 | 采购公司计调；履约中心→团期结算→供应商对账→新建对账 | 选采购费用，提交给供应商对账人员；状态待供应商确认 |
| 供应商先提交 | 供应商对账人员；supplier→对账结算→提交账单 | 选择采购订单费用，填写账单号、日期、逐项金额、总额、增减依据及附件；给对应采购公司计调；状态待我方核对，供应商看到待采购公司核对 |
| 计调核业务 | 同一供应商对账工作区，筛选待我方核对，点击核对 | 对照采购金额、数量、实际服务、增减依据与供应商账单，逐项填写认可金额与依据；可先保存，不自动通过 |
| 原账单全额认可 | 采购公司计调提交核对结果 | 供应商已提交原账单，计调逐项认可同一金额，双方已确认；下一位是财务应付岗 |
| 计调调整金额 | 采购公司计调提交核对结果 | 形成新版本，待供应商确认；供应商认可后完成业务对账，有异议仍按原差异处理流程继续 |
| 材料不足 | 计调填写补充要求、退回补充 | 给供应商对账人员；供应商在原单“补充”入口补金额、依据和附件，再提交回采购公司计调 |
| 后续付款 | 财务应付岗核款、审批人审批、出纳／资金岗执行付款 | 沿用既有财务入口；本次不自动生成应付、不进行审批或实际付款 |

抽屉摘要显示“当前办理：采购公司·计调／供应商·对账人员／采购公司·财务应付岗”。实际员工分工及具体审批制度仍按公司安排，样例岗位不能当作已接入正式员工权限。

## 三、金额、匹配及异常规则

- 无原单可直接提交，例如采购25,200＋17,700，账单合计42,900；提交后等待采购公司计调核对，不自动成为双方确认。
- 选到已有待确认对账的费用时匹配原单；要完整覆盖该原单费用。同一文件跨多张对账或包含原单之外的新费用，提示分开提交；不将同一费用再建一次。
- 同一供应商在同一采购公司重复账单号、同一费用重复提交、已确认费用重复对账均拦截。退回补充是原单的下一次提交，保留旧次记录。
- 供应商账单总额必须等于本次明细合计；金额非负、最多两位小数。账单金额与采购金额不同必须填写增减依据；附件为1至5份PDF、表格或图片，每份大于0且不超过10MB。
- 供应商可以先报尚待实际服务确认的采购费用，进入待我方核对；计调未补齐实际服务依据不能完成该单。本轮未改上游实际服务维护页。
- 原采购80,000、供应商账单82,000：计调认可81,000时只能交供应商确认新版，原82,000账单和费用依据保留；计调认可82,000并填写差额依据时双方已确认，不要求供应商对自己未变更的原账单再点一次。
- 退回示例原账单13,000，补充修正12,800：同一对账单保留两次金额及附件名称，再回计调核对。不得覆盖原记录。
- 历史采购使用原订单协议对应关系，不因协议今天到期而禁止对历史业务报账；不开放跨公司、跨供应商引用。

## 五、原型边界与唯一下一步

两端仍各自是页面内演示会话，刷新恢复样例；本轮不做真实跨端发送、自动回写或后台权限。上传控件登记文件名和大小，不实际上传或保存文件内容。计调端提供两张供应商来单样例，可独立演示接收、核对与退回；不能将供应商端刚提交后的页面状态说成已经同步到计调端。

本次“供应商主动提交→计调核对／退回→原金额确认或新金额交供应商”原型完成。唯一下一步为按后续续做指令补采购订单确认及实际服务依据维护，再处理本次对账在既有应付、预付、款票及退回页面中的承接；不自动扩大为生产闭环。
