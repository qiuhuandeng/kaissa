# 电子合同多平台集团配置第一步实施验收

日期：2026-09-28。依据：用户要求同时支持12301与法大大，并在流程方案后明确“执行”。本次只完成[多平台方案](电子合同多平台协同与定制模板完善方案-20260928.md)第1步集团配置，销售准备与发起、签后结果分别保留在第2、3步。

## 一、角色、入口和本步结果

集团技术管理员维护平台连接和公司授权；集团合同管理员维护文书、适用范围与发布版本；公司管理员维护签约付款条件，审批职责继续在原审批配置。产品人员只沿用公司规则或指定一份可用模板，销售后续按本份模板准备并办理。

| 入口 | 本步已完成 |
|---|---|
| 系统配置 → 接口配置 → 电子合同 | 同页选择12301／法大大，分别维护连接、公司授权、对接记录；接入环境、应用、结果通知地址及逐项能力可保存和核对 |
| 电子合同 → 公司授权 | 按公司、平台维护企业、经办人、用章及所属公司、授权期限和依据；另一平台或另一公司的授权不能代用 |
| 合同管理 → 合同模板 | 列表显示和筛选平台；编辑确定标准／企业自有文本、签署平台和文书生成方式，保留现有正文、普通项、明细表及预览 |
| 模板编辑 → 签署设置 | 配置顺序、共同签署文件、每份文件必要签署方及文末位置／指定标记；正文必须包括必要客户与我方公司，企业授权材料不默认共同签署 |
| 模板编辑 → 平台对应 | 填写平台模板时沿用普通资料与表格对应；系统生成文件时只核对文件接收配置；到平台办理时显示办理路径，不造创建参数 |
| 合同管理 → 合同规则 | 按适用公司、产品类型、旅游范围、客户及附加条件选择默认模板；列表带出平台；新增、编辑、启停及冲突校验均可操作 |
| 系统配置 → 基础参数 → 销售签约条件 | 独立维护公司通用／指定业务的付款条件和依据，引用原合同审批配置；邮轮原“待确认”保持，不能由通用先签后收覆盖 |
| 合同规则 → 监管要求 | 单独登记公司、业务和旅游范围的要求及依据；选择法大大不自动得出需报或免报结论，重新打开可回显本页保存结果 |
| 产品编辑 → 合同模板 | 保留沿用／指定两种选择，候选标明平台；企业自有邮轮模板不套用上海示范文本的适用地限制，经营资格仍需满足 |

本轮没有新增HTML页面或业务一级菜单。接口及合同规则页面已实际加载原工作区的新配置脚本；基础参数增加一个销售签约条件页签，后台角色中补相应配置权限项。组织档案只展示各平台授权摘要和配置入口。

## 二、关键业务规则

1. 一份模板版本确定一种签署平台和生成方式。平台或生成方式改变后，旧平台对应失效，签署设置及合同预览需要重新核对。
2. 名单、行程、费用及正文继续使用已有资料配置。文件方式不要求重复填写正文每一列的平台参数；原12301结构化对应继续保留。
3. 签署顺序及文件位置核对后再修改，必须重新检查。模板正文或附件变化也会使签署检查失效。这里验的是原型配置与样例，不代表实际文件已完成签章定位。
4. 模板修订先建新版本，预览后送审；退回可改，待审只读，通过后才能启用。原启用版及历史采用的版本保留。
5. 默认规则只负责选模板。条件更具体且包含关系明确时优先；同范围重复或互相交叉而不能确定优先时阻断，不取第一条。多公司规则的模板必须适用全部所选公司。
6. 产品指定模板不依赖默认选模规则，但仍检查实际公司授权、经营资格、模板范围和期限，以及公司的付款与审批条件；指定失效不自动回退其他平台。
7. 公司通用政策与邮轮专用政策分别保留。少数既有具名演示订单使用其明确标注的已确认样例；改变订单身份或公司后不能继续借用此样例。
8. 默认规则编号与产品条件、签约政策分别保存；公司通用政策不会覆盖原默认规则的编号或业务范围。
9. 对接记录按平台、公司及原办理号核对。两平台同号不混用；未知记录不新建合同，订单关联不一致或不唯一不自动合并。
10. 连接保存和本地参数检查不显示真实接通。原型认证凭据不保存；所有配置当前页保存、刷新恢复，不做跨页面持久化或真实回写。
