# 供应商对账前预付款查看实施验收

日期：2026-09-26。接续[角色走查](同行结算角色操作路径与走查-20260926.md)的走查02，本步只补供应商原采购详情的只读查看。

## 一、位置、岗位和金额

入口：supplier → 订单确认 → 本采购单“详情”（待回复单从“回复”进入）→ 预付款。采购回复仍是原主操作，不新增一级菜单或付款按钮。

供应商订单／结算人员在本单核对采购公司的预付款安排和实际付款记录。上游为该采购单已有的付款节点及采购公司登记的付款结果；缺少材料由供应商补充并交该公司计调，付款失败或付款中由采购公司资金岗处理。申请、复核、审批和执行仍由我方原业务／财务入口办理。当前查看、展开及关闭不改变采购、对账、应付或付款状态。

预付款是最终结算前按采购安排提前支付的款项。本区只展示本采购单已发布的预付款安排，不以最终对账或实际服务确认作为查看前置条件。金额分开列示：

- 安排预付：本采购单各预付节点的安排金额合计，不等于整单采购金额。
- 实际已付：仅累计本采购节点的成功付款记录。
- 未付预款：安排预付减实际已付，**包含付款中金额**，不是最终结算尾款或可重复申请金额。
- 其中付款中：已进入付款但未有成功结果的金额，不算实际已付。失败记录保留，但不计入已付或付款中。

| 本单示例 | 当前依据 | 展示结果 |
|---|---|---|
| CG-C07，福建凯撒，人民币 | 未建立最终对账；安排12,000，成功6,000，付款中3,000，另3,000缺收款账户证明 | 实际已付6,000，未付6,000，其中付款中3,000；三个付款节点及材料缺口分别显示 |
| CG-C06，北京凯撒，人民币 | 采购已确认，实际服务待确认；安排10,000，曾尝试付款4,000但失败 | 实际已付0，未付10,000；付款失败原因、原记录及资金岗处理责任可查看 |
| CG-C09，北京凯撒，日元 | 安排12,000，付款成功12,000 | 按JPY原币显示已付清，不折成人民币、不与其他采购合并 |
| CG-C15等无已发布安排单 | 当前供应商查看资料中没有本单付款安排 | 显示“暂无已发布的预付款安排及记录”，不伪造零金额，不借用其他采购数据 |

节点展示名称、约定付款日、安排金额、已付、尚未支付、条件及材料缺口。付款记录默认折叠，可展开查看付款单号、日期、金额、节点、成功／付款中／失败结果、回单编号或缺失情况；不模拟银行回单文件下载。

## 二、范围与保护

1. 先按当前供应商可见采购单取值，再核对采购号、公司、供应商、协议、币种、订单和团期；不能查看其他供应商的采购，也不能按订单号混入另一条费用。
2. 节点及付款记录不得重复；未知结果、记录不属于节点、无效金额或已付与付款中超过节点安排时提示核对，不展示错误合计。
3. 无已发布资料不等于实际付款为零；已有预付冲抵也不直接推算成新的付款历史。采购回复确认不会自动产生预付款安排。
4. 本区只读，没有申请、审批、付款、账户编辑或修改金额按钮；展开付款记录不触发未保存确认，换采购单不残留前单内容。
5. 只在supplier端加载，商户计调“采购依据”办理保持。各页独立原型会话，未增加财务自动回写、银行对接或真实权限服务；本例付款日期、条件和材料不代表全集团统一政策。
