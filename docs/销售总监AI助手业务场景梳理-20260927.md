# 销售总监AI助手业务场景梳理

日期：2026-09-27。状态：本轮业务分析建议，未实施页面。范围为现有AI助手的销售总监角色，不改其他角色、销售办理页面或已确认报表范围。

## 一、定位与岗位边界

销售总监每天需要判断：目标还差多少、机会在哪里、成交卡在哪里、哪些门店和顾问需要支持、哪些订单存在风险，以及下一轮如何改善。

业务顺序为：目标与主推安排 → 获客与分配 → 需求与产品匹配 → 预订及成交 → 合同与回款 → 出行与售后 → 复购与经营复盘。

上游是授权范围内的经营任务、客户意向、产品及可售日期、订单、合同、财务已确认收款、履约和售后记录。AI助手整理事实、比较差异、提出有依据的建议和生成可复核草稿；下游仍由销售顾问、门店店长、产品、计调、审批人和财务在各自业务入口办理。

销售总监侧重团队经营和跨岗位协调；店长侧重本店分工；顾问侧重具体客户的需求、推荐、资料和订单。总监可进一步查看重点客户，但不应把顾问日常话术工具作为主工作区。

## 二、当前原型的直接证据

- [AI助手](../merchant/ai/ai-assistant.html)销售总监只有渠道业绩4条、审批与折扣3条、渠道分析3条，共10条快捷指令；内容集中在业绩查询、排名和审批记录。
- 同页发送处理只有产品审批、旅游通知书、收款三个专门回复分支，其余进入通用回复；尚无销售总监专属分析结果。
- 切换角色只更新名称和快捷指令，默认对话仍是产品审批、出团通知和待收款；未围绕总监的经营任务更新。
- 选择工具只有团期、线路、客户；总监所需统计期间、公司／区域、门店和团队的明确分析范围尚未形成。
- 同页通用执行确认只返回任务已生成文案，不能作为真实业务办理或已发送结果的证据。
- [电销意向](../merchant/sales/call-center/intents.html)已有来源、预算、目的地、顾问、分配和跟进记录；“转产品预订”仍直接映射为已转订单。AI不能直接把该状态当作真实成交依据。此项沿用销售方案S03，不新增重复整改任务。
- [销售流程](销售流程01-订单合同收款售后流程-业务确认稿.md)明确销售全过程、财务实收复核、计调资源确认，以及单团项目确认后录入的边界；[直营与加盟销售需求方案](直营与加盟销售需求对照及原型增改方案-20260926.md)记录现有意向、优惠、认款和售后承接缺口。

以上为源码与业务文档核对；本轮没有运行浏览器，不将固定回复视为模型已接入或正式数据已接通。

## 三、沿销售流程设计场景

| 编号／业务环节 | 总监典型提问 | AI应交付的结果 | 后续岗位与办理 |
|---|---|---|---|
| 销AI01 目标与差距 | 本月还差多少？主要差在哪些门店、团队和产品？ | 同口径目标、已完成、差额；差距组成；可争取机会与缺少依据。预测与已成交分开 | 总监决定经营重点；任务调整按原批准流程 |
| 销AI02 获客质量 | 本周哪个来源带来的有效咨询和成交更好？ | 按同批线索和相同观察窗口比较需求完整度、有效咨询、确认订单、取消；获客费用齐备才比较投入产出 | 总监与营销负责人调整获客安排；平台流量未接入时不编造 |
| 销AI03 线索分配 | 哪些高意向客户尚未分配？哪些顾问承接过多？ | 未分配及重复线索、已有归属、顾问在手量；结合业务专长提出分配草稿 | 主管在原意向入口确认分配，不因AI建议改变客户归属 |
| 销AI04 重点商机 | 今天最值得优先推动的客户有哪些？ | 需求明确程度、出行时间、意向产品、当前阶段、保留截止和缺少条件；逐客列推荐理由 | 店长／顾问处理具体商机；未验证前不显示精确成交概率 |
| 销AI05 转化卡点 | 为什么咨询不少，最终成交却少？ | 咨询→意向→预订→确认订单各阶段数量、停留时间和流失记录；区分价格、日期、资源待确认、资料缺失与原因未知 | 顾问补需求，产品处理供给，计调确认资源；原因推测须标明 |
| 销AI06 主推产品与团期 | 下周每个区域主推什么？哪些团期需要优先补客？ | 客户需求与当前可售团期匹配，列出发地、日期、售价、余位、报名／材料截止、确认方式；按区域建议主推和替代方案 | 总监形成主推安排；产品定价、计调名额确认各归原岗位 |
| 销AI07 团队与门店诊断 | A店落后是线索少、转化低，还是取消多？ | 拆解线索来源、产品结构、客单价、阶段转化、取消及回款；比较同来源同类型，列需支持的环节 | 店长调整分工、主管安排辅导；不单凭排名判断员工能力 |
| 销AI08 优惠与成交质量 | 哪些让利需要重点看？申请减价会影响什么？ | 已生效价格、既有优惠、本次额外让利、承担方、申请依据与权限；成本齐备且有权限才看预计贡献 | 具备审批职责者进入原审批办理；AI不自动批准或修改应收 |
| 销AI09 订单签约与回款 | 未来7天出发的订单，哪些还不具备交接条件？ | 逐订单汇总资源未确认、合同未完成、资料缺项、到期未收、已付待认及责任岗位；按有效期限排优先级 | 顾问处理客户及认款申请，合同经办处理签署，计调处理资源，财务确认实收 |
| 销AI10 售后与流失 | 本月取消集中在哪些产品和环节？还有哪些订单能提供替代方案？ | 取消及投诉原因、责任和已有处理结果；按客户原需求列改期／换产品候选及需确认条件 | 销售发起售后，计调确认损失和资源，业务审批及财务办理；退款不由AI执行 |
| 销AI11 老客复购与企业客户 | 哪些老客适合下一季产品？重点企业项目有哪些收款或交付风险？ | 基于已记录偏好、历史订单和服务结果生成候选客户及推荐理由；企业项目只看确认方案、阶段收款和变更资料 | 顾问复核触达对象和文案；企业项目沿既有确认后录入流程，不恢复完整在线询价 |
| 销AI12 经营复盘与销售赋能 | 帮我准备周会，重点讨论哪些问题？ | 本周结果、差距、可核查原因、未证实判断、重点机会、责任岗位和行动建议；附产品差异说明与案例辅导草稿 | 总监审核周会材料并安排工作；与上期比较需要已保留的计划和结果 |

## 四、结果如何帮助决策

每次分析按“结论 → 依据 → 受影响门店／客户／订单 → 建议与责任岗位 → 下一步入口”展开。复杂问题先给少量重点结论，明细留在当前回答中展开，避免一口气堆全部报表。

例如“本月差额怎么补”，先展示选定公司的销售目标和同口径完成情况，再区分已确认订单、尚未成交意向、资源待确认订单和本期取消影响。意向预算只是机会参考，不能直接加到已完成业绩，也不能把收款待认当作客户没付款。

可继续追问“只看直营门店”“排除资源未确认”“逐个说明推荐理由”“按顾问整理”。追问应沿用或明确修改原期间、公司、业务口径；不能追问一次就换一套范围。

资料不足时明确缺什么：没有批准目标不算目标完成率；没有线索进入及成交记录不报转化率；没有流失记录不把未成交归因为价格；没有成本及费用不称渠道净利润。事实、比较结果、推测、建议和预测分别表达。

## 五、页面组织及第一轮建议

保留当前“左侧快捷场景＋右侧对话”的结构，销售总监左侧按六组组织：

1. 目标达成：业绩差距、期间比较、机会与预测。
2. 商机转化：重点客户、线索分配、转化卡点。
3. 产品主推：区域选品、团期补客、替代推荐。
4. 团队渠道：门店诊断、顾问支持、获客质量。
5. 成交风险：优惠申请、资源确认、签约回款、售后。
6. 客户经营：复购客户、企业客户、经营周报。

首轮只把六个场景做完整：销AI01业绩差距、销AI04重点商机、销AI05转化卡点、销AI06主推团期、销AI07团队诊断、销AI09成交风险。其余场景作为后续候选，不默认一次全部实施。

销售总监默认开场围绕“今天哪些事情需要我介入”；提供当前公司／授权销售组织和期间选择，沿用共享组织入口，必要时选区域、门店、团队、产品或团期。分析结果的具体操作用“查看订单、查看意向、进入审批、生成周报草稿”等业务名称，不使用无确定结果的“继续执行”。

原型使用明确且内部一致的独立样例完成分析、筛选、追问、正常及缺资料结果。角色选择只表达演示身份，不作为正式授权；不以真实模型、后台接口、自动通知和跨页回写作为本轮原型门槛。

## 六、口径、权限与后续验收

- 公司、门店、顾问只看授权范围；销售公司与产品公司分开，跨公司共享产品不重复计集团对客成交。示例金额不能冒充实时实账。
- 订单成交、实际收款、实际完成业务分别统计；取消退款及考核归属采用已确认规则，未定部分标待确认。“销售额”必须说明采用哪个金额和日期。
- 转化按相同进入批次、明确阶段和观察窗口计算，不能用本周成交直接除以本周新线索；进入预订不等于确认成交。
- 产品推荐尊重可售状态、实际团期／航次／班期、出发地、材料截止及二次确认。邮轮按舱型、专列按铺位、自由行按出行日期及套餐，不能把所有余量当人数。
- 客户偏好基于已记录事实，不根据姓名、年龄等凭空推断购买意愿；资料缺失和无权限时返回可用范围与缺项。
- 第一轮至少验证：同范围目标与实际一致、意向不当成交、来源缺失不填零、资源未确认不承诺可售、客户已付待认与未付款区分、跨公司／门店不过界、追问保持期间与范围、只读分析不改变业务状态。

待确认事项：销售总监的具体管理范围、销售考核金额和日期、线索阶段及有效咨询定义、客户归属调整权限、优惠审批职责。场景建议不代表这些政策已经批准。

本轮仅完成场景分析与现状对照，没有修改HTML或新增业务测试。下一步是把上述六个优先场景细化为销售总监专属快捷指令、结果示例和连续追问；收到本工作线页面实施指令后，仅在现有AI助手及直接依赖范围制作原型。
