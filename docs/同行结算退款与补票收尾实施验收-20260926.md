# 同行结算退款与补票收尾实施验收

日期：2026-09-26。范围：接续本工作线已授权的异常收尾，沿用付款退回、发票管理和供应商对账详情。当前页面内操作，不接银行、税控、集团核算系统，不做跨端自动回写。

## 一、岗位和实际入口

| 使用岗位 | 进入位置 | 本次办理 | 交给谁 |
|---|---|---|---|
| 供应商财务人员 | supplier → 对账结算 → 原对账详情 → 预付退回 | 查看应退金额与原预付，提交退款交易号、日期及凭据 | 采购公司资金岗核对实际到账 |
| 我方资金岗 | 财务 → 成本应付 → 付款退回 → 核对 | 按原付款、预付或应付，逐笔选择实际到账流水核对；可分次到账 | 应付岗核对余额，核算岗另行处理凭证 |
| 供应商票据人员 | supplier → 对账结算 → 原对账详情 → 补正发票材料 | 查看退回原因，补清晰票面、购销方、金额及说明，在原收票任务重提 | 采购公司发票岗 |
| 我方发票岗 | 财务 → 资金票据 → 发票管理 → 核验 | 查看第2版补正材料及第1版退回历史，核验或再次退回 | 原任务保存结果，付款金额不随核票改变 |
| 我方计调 | 履约中心 → 团期结算 → 供应商对账 → 详情 | 查看双方确认依据，通过关联记录进入原付款退回页 | 不替资金岗认到账，不替供应商补票 |

上游是已确认的退回依据、实际原付款和原收票任务。供应商上传退款凭据只表示对方提供了材料，我方银行到账仍由资金岗独立核对。应付是已确认欠供应商的款项；预付是提前支付、尚需核对用途的款项；已冲抵部分已经用于抵减欠款，不能再作为未使用余额退回。

## 二、实际样例与余额方向

均关联福建凯撒、北京国旅地接部、人民币及对账单DZ20260926003第1版。原应结101,000，已冲抵30,000，尾款原已付50,000，待付21,000，已有付款占用10,000，可申请11,000。

| 退回单 | 原单及依据 | 核对动作 | 本页结果 |
|---|---|---|---|
| RET-DZ-003，供应商退预付 | 原预付PP-DZ-003为35,000，原付款PAY-PP-003，已冲抵30,000；双方同意退未用5,000，确认单TH-0926-03 | 先核对2,000到账，再核对3,000到账 | 待到账→部分到账→已到账；预付可用余额5,000→3,000→0，原应付、冲抵和尾款已付不变 |
| RET-DZ-004，银行退回 | 原尾款付款FK03为50,000，银行通知BR-0926-04退回其中10,000，原应付仍需支付 | 核对银行退回10,000到账 | 原付款50,000的记录保留，退回另列；尾款净付40,000，待付31,000，可申请21,000；预付余额不变 |

退款流水须与本单的到账公司、对方名称、币种、收支方向相符，本次核对金额等于该流水金额。原付款金额、应退金额及未冲抵预付余额控制上限，重复流水、旧办理版本、超额或缺依据均不保存。本例按整笔到账流水核对，多笔到账逐笔办理；一笔到账拆给多张退回单不在本步演示范围。

原《财务流程02》第十三部分曾将多类退回统一写成“冲减应付或恢复预付余额”，本轮核对发现该说法不足以指导以上两种余额方向，已在原文修订区分。供应商因服务减免退款还需双方确认的费用调整依据；客户退款不能直接推定供应商应退，也不据本次到账重写原成本。正式会计处理、审批和期间仍待财务政策确认。

## 三、原票补正与历史

供应商原单示例现在处于“待补正”：收票任务INV-DZ-003，第1版发票FJ20260925003、101,000元，退回原因是购方名称缺字，要求补清晰完整票面。供应商补正必须提供本次材料和说明，核对票面购销方与币种；原收票任务及对账版本保持，材料升至第2版并变为“待财务核验”。

第1版材料、金额、退回原因和发票岗记录保留；第2版补正材料、说明和提交记录追加。重复提交、旧票据版本、超应结金额、缺材料及购销方不符均拦截。尚无材料的其他已确认对账仍可首次提交。

财务页用独立的“第2版材料已收到，待核验”样例承接同一任务，并展示原退票与补正历史；核验通过或再次退回也追加历史。两端示例代表不同办理时点，不表示浏览器上传后已向另一端发送。补票不修改双方结算金额、应付或实际付款。

## 四、页面审计与改动

| 原有功能与缺口 | 本轮修改 | 验收证据 |
|---|---|---|
| 付款退回原页已有独立原付款、到账和处理抽屉，但本次对账无对应记录 | 原列表增加两张本单退回；关联对账、原款、应付／预付；当前退回摘要及到账表单集中核对 | 部分到账、超额、重复、错公司、未知单号和旧版链接检查 |
| supplier原来只支持一次发票提交 | 原单补正、材料版本、历史和下一岗位；增加原预付退款凭据提交 | 缺件、不符、重提、无财务按钮及上传不改到账检查 |
| 财务核票有退回，但缺补正材料历史 | 原发票任务展示补正第2版和处理历史 | 核验及退回仍不改款项 |
| 原付款退回页有页面内样式 | 迁入既有同行财务共享样式；保持只引用统一样式文件 | 样式解析，桌面和390像素抽屉、固定操作列检查 |

技术落点：`merchant/finance/finance-payment-return.html`；`shared/supplier-finance-model.js`、`shared/supplier-finance-ui.js`、`shared/supplier-finance.css`；`shared/supplier-reconciliation-model.js`、`shared/supplier-reconciliation.js`。发票、供应商对账和团期结算沿用已有共享入口，没有增加菜单或新的财务模块。原退回案例及详情保留，本轮不宣称已重构全部历史逆向场景。

## 五、验收结果

- 新增 `node scripts/check-supplier-closeout.cjs`：17组规则通过。
- 新增 `node scripts/check-supplier-closeout-browser.cjs`：29组Chrome检查通过，页面异常0。包含原退回详情、状态筛选、实际关联入口、两个退回类型、补票、退款凭据、未保存退出、财务补正核验及390像素操作。
- 原规则回归：款票17组、双方对账22组、主动账单18组、采购15组，共72组通过。对账原发票测试随示例从“首次提交”调整为“补正重提”，新增规则另验首次提交，未删除功能覆盖。
- 原浏览器回归：款票33组、财务导航19组、对账37组、对账导航3组，共92组通过。最终抽屉信息层级与发票历史调整后，新29组再次通过。
- 修改脚本与退回HTML内联脚本解析、统一样式引用、共享CSS解析、文档引用、差异格式和财务执行清单检查通过。原8批／36项／6场景保持。
- 已人工查看桌面退款核对、银行退回及supplier结果、窄屏退回抽屉／表格／补票截图。退款抽屉已将应退、已到、未到放到摘要，办理字段前置。

## 六、遗留与唯一下一步

本次授权的退款核对和原票补正收尾已完成原型验收。正式银行到账、税控验真、文件服务、人员权限和跨端传递没有接通，集团代付、票款强控、会计和税务政策仍待确认。

唯一下一步：按原七项缺口做一次从供应商、计调到财务的角色操作走查，交付简明使用路径与仍需确认的业务规则；逐项核实后再判断整条同行结算原型覆盖程度，不新增模块、不自动转入生产联调。
