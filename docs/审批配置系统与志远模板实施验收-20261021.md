# 审批配置系统与志远模板实施验收

日期：2026-10-21。依据用户指定的审批配置页面及三张参考截图实施，界面名称沿用用户所称“志远”。

## 本次步骤与业务位置

本次完成审批配置的两种模板入口、志远模板抽屉，以及用户随后要求的列表筛选、发布与启停。审批管理员在集团后台维护模板名称、业务场景、适用公司和部门，以及志远表单与本系统业务资料的对应关系。上游为业务申请中的单据、申请人、部门和申请内容；下游的审批办理平台由模板类型区分：系统模板继续配置本系统审批节点，志远模板维护第三方表单参数。

本次不改变付款、退款、合同等来源页面，也不接通第三方接口或模拟外部审批成功。既有审批扩展第2步、会奖及财务报表工作线保持原断点。

## 状态与操作

| 当前情况 | 列表主状态 | 主按钮及更多操作 |
|---|---|---|
| 新建或复制后保存 | 草稿 | 主按钮编辑；更多中发布。发布后按“发布后启用模板”设置进入已发布或已停用 |
| 已发布模板编辑后保存 | 待发布 | 主按钮编辑；更多中发布，以及原版本的停用／启用；弱文字标明原版本生效中或已停用 |
| 已发布且在使用，无未发布修改 | 已发布 | 主按钮查看；更多中编辑、停用；停用后供新申请选择的资格关闭 |
| 已发布且停用，无未发布修改 | 已停用 | 主按钮查看；更多中编辑、启用；启用原已发布版本，不重新发布、不增加版本 |

“待发布”表示已有版本的修订草稿，原版本是否生效仍保持；新建保存不自动发布。发布新版本后，在途申请保留原版本的业务表达。志远未完善资料允许保存，发布确认中提示待补内容但不阻断原型演示，保留原始内容且不伪造字段解析或第三方结果。系统模板继续沿用原编辑与发布规则。

## 保存与后续边界

配置继续沿用当前浏览器会话保存。志远配置单独保存，不能被内部审批模型误当作无需审批的空流程；在同一模板列表统一维护。模板编号、默认内容及系统标签为本次原型资料，实际第三方字段与接口约定仍需正式接入时核对。保存配置或勾选启用不代表已请求志远或取得外部审批结果。

本次原型范围无待实施项。唯一下一步：刷新“审批配置”，核对每行“编辑／查看＋更多”，在更多中试用发布、停用和启用；按具体反馈调整当前页面，不自动推进来源单据或第三方接口联调。

## 开发文件

- `admin/approval-config.html`：两类模板列表入口及志远配置脚本加载。
- `shared/approval-config.js`：入口分流、共用列表和志远抽屉；系统编辑直接链接误带志远记录时回到志远配置。
- `shared/approval-zhiyuan.js`：默认资料、模板内容解析、关联修改、独立草稿保存与发布。志远记录保存在原会话配置的 `zhiyuanTemplates`，原 `templates` 继续仅供内部审批使用。
- `shared/approval-config.css`：局部列表和抽屉样式；`shared/approval-editor-page.css` 通过既有构建脚本生成。
- `admin/approval-template-edit.html`：更新共享脚本、生成样式版本，原系统配置流程保持。
- `scripts/check-approval-zhiyuan.cjs`、`scripts/check-approval-zhiyuan-browser.cjs`：规则和实际浏览器验收；原交互脚本同步列表列名、共享浮层选择器及模拟环境兼容。
