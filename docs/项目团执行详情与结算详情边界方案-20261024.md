## 一、当前结论与现状

项目团详情处理本团怎样交付，项目团结算详情处理本次收入、成本、税额、收付款及依据怎样核对。两处共用同一项目团和原始单据资料，分别组织页面、主状态及操作。

此前把各入口都指向同一执行详情，解决了两套样例和资料不一致的问题，但团期结算的详情入口仍打开执行内容；执行详情又保留成本摘要、客户款项及完整税额测算，造成职责重叠。本方案更新此前“所有查看入口均进入同一详情”的规则，保留已整理的同团资料、旧编号对应、独立样例、人员安排和原结算能力。

## 二、业务链路与两页责任

客户委托及原报价／订单确定服务范围，计调在项目团组织日程、人员和资源；费用经办可在执行期间进入团期结算维护成本。服务交付后，计调登记实际服务日期、人数与完成依据；结算经办据此核对结算范围和金额，提交原审批，财务继续承接原应收应付、收付款、开票及核算。

| 项目 | 项目团详情 | 项目团结算详情 |
| --- | --- | --- |
| 主要使用人 | 计调、项目执行负责人；销售查交付 | 费用／结算经办、项目负责人、财务核对人 |
| 最高频任务 | 排日程、补名单、分组分房分车、核资源和签证、准备交付资料 | 维护及核对费用、核本次收入和成本承担、税额、收付及依据 |
| 主对象 | 一个具体项目团 | 当前团对应的本次结算范围／某次结算记录 |
| 主状态 | 草稿、进行中、已完成、已取消 | 当前结算进度；已有单按草稿、审批中、退回、已确认等原状态 |
| 完成后改变什么 | 本团执行资料、实际交付结果及履约状态 | 原费用及分配，或本次结算依据、版本及审批状态 |
| 异常处理 | 名单、证件、票号、确认号、服务变更及交付缺口回执行区域处理 | 金额、成本分配、税额、款票及结算依据差异回相应原单处理 |

岗位用于说明职责，原型仍按超级管理员展示；实际动作继续受业务状态和审批顺序约束。

### “价格名额”怎样处理

当前项目团按客户委托提供会议、奖励旅游或组合服务，不应默认出现散拼团的公开售价、余位、停售和可售库存。人数放总览／名单，交通座位、酒店间夜、车辆和会场容量等实际供给数量放资源安排；成交价及计价方式引用报价／订单。没有资料的能力标待完善，不推算可售余位。未来确有对外售位业务时另按实际销售对象承接，不在本次创造新售卖模式。

本次“资源安排”承接用户举例的交通资源，同时保留会奖所需会场和设备等能力。表格和确认表单按类别表达差异，不能把班次、票号、房型等全部压成备注。
