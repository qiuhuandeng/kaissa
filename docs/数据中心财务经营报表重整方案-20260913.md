## 一、建议结论

建议最终形成 **6个报表页面 + 2个配套管理页面，共8个功能页面**。普通使用者主要看前6个，预算和报表管理员按权限使用后2个。

| 编号 | 页面 | 主要回答的问题 | 主要使用者 |
|---|---|---|---|
| P1 | 经营总览 | 集团及各公司经营规模、履约进度、利润和任务完成怎样？ | 集团经营管理、公司负责人、财务分析 |
| P2 | 产品经营分析 | 哪些事业部、产品经营组、目的地、产品和供应方式贡献业绩？ | 产品负责人、事业部负责人、财务分析 |
| P3 | 渠道经营分析 | 各区域、渠道、门店、呼叫中心销售组和顾问完成怎样？卖了什么？ | 销售、渠道、门店、呼叫中心负责人及财务 |
| P4 | 团期毛利与结算分析 | 已完成的团期赚多少？哪些尚未确认成本或结算？ | 产品、计调负责人、结算会计、财务分析 |
| P5 | 订单明细 | 本期有效订单业绩具体来自哪些订单、哪些销售内容？ | 财务核对及权限范围内的业务负责人 |
| P6 | 回团明细 | 本期实际完成与财务确认分别有哪些，金额为何不同？ | 财务核对、产品及履约负责人 |
| P7 | 预算任务管理 | 谁承担哪种指标、哪个期间的任务？调整前后是多少？ | 财务预算、经营管理、获授权的任务负责人 |
| P8 | 报表管理 | 数据更新到哪里？什么口径？哪里缺数？本期发布哪一版？ | 财务报表管理员、数据维护人员 |

这里的8页是功能信息架构，不代表新建8个文件。订单、回团已有的明细能力应整理复用；门店、呼叫中心是P3中的专属视图，不再各建一套独立计算的财务周报。P7、P8属于配套管理，不混入日常分析菜单。

**不把“周报”“月报”“年报”“双周报”拆成不同页面，不把Excel隐藏表做成菜单，不保留多个并行的经营分析方案供财务猜该看哪个。**

此前“四个顶层页签、无下钻”属于方案三专项。用户本次要求重新梳理页面数量，因此提出上述替代架构，仍须确认后实施。本方案的汇总与明细直接以表格呈现，不依赖点击图表、弹窗或逐层下钻才能取数；来源单号保留供核对，是否增加业务跳转另行确认。团期订单业务列表和详情继续独立，完全不在本次改造范围内。

## 三、先把集团的业务关系摆清楚

### 1. 报表在业务链上的位置

资源、供应商资料 → 产品及供应安排 → 团期、航次、班期或服务日期 → 销售订单、合同与售后 → 实际出行或服务完成 → 成本和业务结算 → 财务收入、收付款及核算 → 数据中心分析。

产品和运营负责“卖什么、谁经营”；销售负责“卖给谁、谁成交”；计调和团控负责“什么时候实际完成、成本依据是什么”；财务负责“哪些收入、成本及收付款已确认”；数据中心负责“按统一规则汇总和解释差异”，不代替这些模块制单或确认。

集团财务核算系统（项目中称NC）仍承接核算和凭证。周报不能因为尚未推送该系统就遗漏已发生业务，也不能把推送成功当作唯一业绩依据。

### 2. 同一笔业务需要三种观察角度

| 角度 | 需要保留的关系 | 用途与限制 |
|---|---|---|
| 销售责任 | 销售公司、分公司、部门、门店或呼叫中心销售组、销售人员 | 订单任务、回团任务、渠道贡献；不代表这些单位都独立核算 |
| 产品经营责任 | 产品经营公司、事业部、经营组、产品负责人、业务线 | 产品规模、结构、经营毛利；不能用销售公司代替产品经营公司 |
| 财务责任 | 合同销售公司、收入确认公司、成本承担公司、收款公司及内部交易双方 | 公司确认收入和成本、内部交易核对；收款公司不自动取得销售业绩 |

法人主体是承担对外合同和法律责任的公司；核算主体是财务单独记账、出账的范围。事业部、部门、分公司、门店是否独立核算，必须按正式组织资料确认，不能仅凭名称判断。

组织隶属、产品经营管理线和预算责任线可能不完全重合，不强塞进一棵组织树。页面筛选分别选择“销售组织”“产品经营组织”“收入确认公司”；集团管理范围单独明确。

### 3. 渠道、门店和呼叫中心

- 来源系统说明记录来自哪里；获客来源说明客户从哪里来；成交渠道说明通过谁完成销售；门店或销售组说明谁负责业绩。这四者不能合成一个“渠道”。
- 呼叫中心既是销售组织场景，也可对应成交渠道；线上获客由呼叫中心成交时，两种信息同时保留，但主渠道业绩只计一次。
- 门店应分别记录所属销售公司、门店、直营或加盟等经营性质、合同及结算关系。加盟店不自动纳入集团法人合并范围。
- 财务“一区至六区”是预算管理分区，不直接用行政区划或旅游目的地替代；保留分区版本及有效日期。
- 顾问调组、门店改名、离职不能让已发布历史业绩随当前资料无声变动；跨组贡献如需拆分，须有明确分配依据，不能两组各算全额。
- 集团和公司看授权全貌，店长和组长看自己的范围；个人不默认查看其他顾问业绩、供应商底价或公司间结算价。页面汇总、明细、导出遵守相同权限。

### 4. 自营、内部共享、外采与甄选

必须保留“对当前销售公司的供应关系”和“集团产品经营分类”两个视角。A公司卖B公司自营产品，对A是内部采购，对集团不因此变成体系外外采。A卖B包装的外部C供应商产品，存在A与B内部结算、B与C外部结算，两套金额不能合并当成一笔外部成本。

示例仅说明管理去重，不作为收入确认政策：A对客成交10,000元，A与B结算8,000元，B向外部采购7,000元。集团对客成交规模是10,000元，不是18,000元；在业务范围、期间及成本口径一致且没有其他费用时，相关直接业务毛利合计为3,000元，不把8,000元内部结算重复扣除。各公司自己的收入、成本怎样确认，以及集团财务抵销怎样处理，由财务规则决定。

“凯撒甄选”需要保留品牌或经营分类，但与自营、外采是否互斥须确认。供应方式不直接决定收入按全额还是净额确认；不能规定“外采统一只认差价”。自营产品也会向酒店、航司、地接采购资源，不能把自营成本误当成没有外部采购成本。

## 四、逐页方案

### P1 经营总览

- 首屏：本期净订单成交额、本期实际回团成交额、已确认业务毛利、订单与回团任务完成；不同口径分区显示，不相加成“总收入”。缺少正式毛利时明确未确认。
- 主表：公司或事业部的本期、上期、上年同期、增长额、增长率、年累计、任务、完成率、任务缺口。切换销售责任和产品经营责任时，标题及合计含义同步变化。
- 趋势：订单与回团按周或月对比；毛利按已选确认期间单独看。附可读取的数值表，不依赖图形取数。
- 补充：截至统计日已售、计划本年或次年完成的业务；已回团待结算团数及相关金额；来源未齐或未归类的影响范围。
- 特别限制：集团对外管理规模与各公司内部交易口径分开，不宣称本页替代法定合并财务报表。实收属于对应订单的收款结果，不并入成交或收入。

### P2 产品经营分析

- 页内视图：经营组业绩、产品结构、跨年收客。经营组视图对应附件“欧洲一组、欧洲二组、定制单团组”等；结构视图对应产品类型、旅游范围、目的地、自营外采甄选。
- 经营组主表：经营公司、事业部或经营组、负责人、本周、上周、环比、本月、同期、同比、年累计、年度任务及完成。订单与回团分别选择口径。
- 产品结构主表：产品类型或目的地 × 供应方式，显示成交额、人数或商品数量、金额占比；同时支持“渠道 × 产品类型”和“渠道 × 目的地”，与P3使用同一结果。
- 跨年收客主表：下单年份 × 计划回团年份／实际完成年份，分开当年收当年回、往年收本年回、本年收次年回；每组都按相同统计截止对比。
- 毛利补充：仅显示能由同一批收入成本核对的确认毛利和完整性状态。跨公司经营组毛利采用哪套内部贡献规则待确认，不默认从集团利润分摊。
- 多目的地产品默认保留一个“报表主归属目的地”的建议；如财务要求分配，必须明确比例且合计100%。旅游目的地多选用于筛选，不允许每个目的地各计一次全额。

### P3 渠道经营分析

- 页内视图：渠道与区域、门店、呼叫中心、渠道产品结构。可直接切换并阅读完整表格，不经过多层详情。
- 渠道与区域：预算区域、渠道大类、具体渠道、经营性质；列示周、月、年实际、同期、增长、任务、缺口和完成率。
- 门店：区域、门店、所属销售公司、直营或加盟；订单与回团任务分别统计。新开、关闭或改名门店保留历史；同店同比是否剔除新店作为可选已确认规则，不能默认改总量同比。
- 呼叫中心：销售组、顾问、任职有效期、任务适用级别；列示个人与组别周月年订单及回团业绩、目标和差额。个人合计、组别合计、中心合计必须可核对，未分配业绩单列。
- 产品结构：在指定渠道、门店或销售组内看产品类型、目的地、供应方式的金额及占比。占比明确是“占本渠道”还是“占该目的地全部渠道”。
- 呼叫中心线索量、转化率、通话效率仍留销售模块；这页只负责成交、回团及经营任务，不做另一套顾问操作工作台。
- 暂不承诺渠道级正式毛利：只有团期总成本时，不按订单金额比例随意分给顾问或门店。取得明确费用归属或财务批准的分配后才开放该指标。

### P4 团期毛利与结算分析

- 页内视图：团期利润、经营组月度结算毛利、待确认与异常。跟团、邮轮、专列、研学、定制及项目团统一按实际业务名称显示团期、航次、班期或项目。
- 主表：团号、名称、产品经营组织、负责人、实际完成日、结算确认日及月份、业务结算收入、已确认成本、业务毛利和毛利率、结算主状态。
- 另设金额视图：财务确认的不含税收入、不含税成本及毛利，不能用含税成交额减不含税成本。表格不用一屏横铺全部指标。
- 异常视图：已完成待成本确认、成本资料不全、待结算、确认负毛利、结算后调整；显示明确缺口数量及影响金额，不展示“待联系、待催促”等员工沟通事项。
- “未提交准单”保留来源名称和业务编号作为核对证据。它对应新系统哪个审批或结算对象，须财务和业务确认；暂不创建“准单管理”菜单。
- 供应商返点作为利润补充表：供应商、关联团期、计提依据、预计返点、已确认返点及计入期间分别列示。渠道附件“Sheet2”的预计比例不能直接当作已确认收益；财务确认其冲减成本还是其他处理后，只计入利润一次。应付、预付和付款明细仍在财务模块，不扩成第三套资金台账。
- 已完成未结算与已确认结果都能看到，但不能把不完整成本算出的毛利当作正式毛利。供应商账单、阶段结算可以发生在出团前，不一律视为错期。
- 本页只分析，实际成本确认、结算提交、付款和财务调整仍在各自业务模块处理。

### P5 订单明细

- 统计目的：说明本期有效成交从哪里来；与销售模块“今天处理哪些订单”的列表不同。
- 一行建议对应“订单中的一项销售内容”，如一个团期产品、单项服务或项目报价项。简单订单只有一行；同单多个内容分别保留金额，单数按订单去重。
- 默认列：订单号、来源订单号、销售内容／产品、订单确认日、状态、关联团期或服务日期、销售公司与门店／销售组、产品经营组织、渠道、数量及单位、净成交额。
- 可选字段组：全部产品分类、地理目的地、供应商与供给公司、销售／客服、预算区域、创建及确认时间、归属版本、原成交及增减项、财务分配实收、来源及调整记录。
- 当期增减变化明细可单独切换查看，与按原订单形成期间查看的当前净值明确区分。转单、更换来源编号不制造新的业绩。
- 不将订单应收、供应商报价、订单预计利润作为财务确认收入、实际成本或正式毛利。

### P6 回团明细

- 统计目的：说明哪些销售内容完成服务、对应金额是多少，哪些还待财务确认。
- 一行建议对应“订单销售内容的一次实际完成及金额分配”。一个订单涉及多次服务时分别呈现，不能用订单表与多团表直接相连后把整单金额重复展示为可加总值。
- 默认列：订单号、销售内容、团号或服务单号、计划完成日、实际完成日、财务回团管理月份、销售及产品经营归属、数量及单位、分配回团成交额、确认状态。
- 财务确认视图增加：业务结算单号、结算确认日、财务确认期间、业务结算收入、财务确认收入、可归属成本、调整额及原记录。费用尚未分配到订单行时不展示虚构订单毛利，团期毛利在P4查看。
- 计划回团尚未完成的业务放独立“未来回团安排”视图，按计划日期统计；不能进入“实际回团”结果。
- 单项服务按服务完成依据归入，不强制编造团号；部分完成、延期、取消未出行和跨年调整保留独立处理规则。

### P7 预算任务管理

- 分开维护订单业绩任务、回团业绩任务、毛利任务；每项写明金额定义、含税或不含税、考核期间及责任范围。附件“单团利润”的毛利预算不能被订单任务替代。
- 支持公司、事业部／产品经营组、区域／渠道、门店、销售组和顾问的年度任务与月度拆分，按实际已批准层级录入，不强制所有层级都有任务。
- 年度、月度、责任人、组织版本、生效日期、批准记录、调整前后金额均保留；有录入、导入及差额校验，但不让财务每周重新填实际完成。
- “上级任务”和“下级拆分任务”是同一目标的不同管理层次，不跨层相加；未分配任务单列。一个顾问的任务分拆到组或门店时也不得重复累加。
- 月度实际除月度任务称月度完成率，年累计实际除年度任务称年度完成率，年累计实际除同期累计任务称累计进度完成率，三者不能混叫完成率。
- 目标本身需由管理者制定；自动化消除的是每周人工归类、汇总、对比和计算，不是让系统凭空生成预算。

### P8 报表管理

- 页内管理项：报表规则、统计日历、数据核对、发布记录。尽量引用现有组织、渠道、产品配置，不在这里再维护一套公司、人员和产品档案。
- 规则：有效订单范围、来源对应、组织渠道历史归属、管理分组、金额映射、自营外采分类、数据排除及调整规则；每次变更保留生效时间、理由和确认人。
- 日历：周、双周、自然月、财务回团管理月及同比对比日期；页面始终列明起止日，而不是只显示“本周”或“5月”。
- 核对：来源刷新时间、原始记录数、重复与排除数、纳入条数、金额差额、未归类、未匹配订单或团期、成本或任务缺失。原始记录数与去重业务单数分别显示，不将拆分后行数强行与原始行数相等。
- 发布：工作中最新结果和已发布周报版本分开，保留数据截止、规则版本、任务版本、发布人和更正原因；历史周报能重现。规则尚未定或关键来源失败时不能显示“全部完整”。
- 报表数字只读；数据错误回来源修正，规则错误经确认后改规则。必要的财务调整带原业务、依据及审批记录，不能直接改汇总格。

## 五、两套明细怎样支持这些报表

订单明细和回团明细是两种观察业务的底表，不是两套分别手工维护的账。它们能提供规模、结构和期间分析的基础，**但仅有这些表头，不能自动得到任务、结算毛利和财务确认收入**。

| 数据类别 | 已有明细对应字段 | 还必须明确或补齐的业务记录 | 维护／确认环节 |
|---|---|---|---|
| 订单识别与防重复 | 凯撒订单号、通通游订单号、数据来源、订单状态 | 来源系统与原订单对应、销售内容、订单生效时间、有效范围、替换关系 | 订单及历史数据接入 |
| 履约识别 | 凯撒团号、出团日期、回团日期 | 团期／服务对象、计划与实际日期、完成依据、确认人、更正记录、部分完成分配 | 团期与服务执行 |
| 产品经营归属 | 产品代理、产品归属、产品分公司、代理人、业务线 | 产品经营公司、事业部、经营组、负责人及当时版本；旧三列不能按同义词直接合并 | 产品及经营归属确认 |
| 产品分类 | 产品类别、类型细分、出入境类型、自营／外采 | 产品形态、旅游范围、供应关系、甄选分类分别定义 | 产品配置及财务报表规则 |
| 供应来源 | 供应商、趣享供应商结算价 | 内部供给公司、外部供应商、采购公司、结算对象、对应订单／团期和金额口径 | 采购、履约及财务结算 |
| 地理信息 | 目的地分区、国家／省份、城市、出发城市 | 管理分组与地理分区分开，多目的地归属或分配 | 产品与报表配置 |
| 销售归属 | 销售分公司、销售ID、销售名字、客服 | 销售部门、门店、呼叫中心销售组、历史任职及归属变更 | 组织人员、订单确认 |
| 渠道归属 | 渠道、分销商、亿步渠道分类、25年渠道 | 渠道大类、具体渠道、获客来源、门店性质、平台店铺、有效版本 | 渠道及订单；旧年度字段转历史映射 |
| 集团多主体 | 现有“产品／销售分公司”仅覆盖部分关系 | 合同销售、收入确认、成本承担、收款公司，内部交易对应及集团范围 | 合同、采购、财务主体确认 |
| 任务责任 | 明细没有正式任务 | 预算区域、责任组织／人员、指标、月年任务、含税口径、批准版本 | 预算任务管理 |
| 数量 | 订单人数或商品数 | 出游人次、订单数、团期数、商品数量和单位分开；退款或调整数量 | 订单与履约 |
| 成交金额 | 订单流水、收入 | 原成交、已生效增项与减项、币种、明确单位；旧“收入”逐来源解释 | 订单及售后 |
| 收付款 | 实收 | 已确认分配到订单的收款、退款、转款及日期；预存余额不能全挂订单 | 收款认款及退款 |
| 结算及毛利 | 收入、供应商结算价、毛利额、毛利率 | 业务结算收入、确认成本、结算日期、完整性、可分配范围 | 成本与业务结算 |
| 供应商返点 | 渠道附件Sheet2的预计返点比例和预计返点 | 协议条件、计提范围、预计与确认金额、团期归属及计入期间 | 采购依据与财务确认 |
| 财务金额 | 原明细尚不足 | 财务确认收入、不含税成本、税额、确认期间、总额或净额政策 | 财务确认，不由订单页面计算 |
| 调整及核对 | 差异 | 比较双方的名称、原值、新值、差额、原因、原订单／原团及生效期间 | 原业务调整及报表核对 |
| 报表期间 | 年、月、周、双周、本年／年度、本周／周度、上周、月日 | 按统计日历动态计算；不在下单或团期表单增加这些人工字段 | 报表计算 |

“差异”不保留成没有含义的一列：来源差异、预算缺口、同比变动额、结算调整额分别命名。空白列删除，重复产品分公司先核实语义；历史字段原值作为迁移核对依据保留，不直接丢弃。

## 六、统一指标与日期规则

以下是建议计算规范，涉及纳入范围、归属时点及财务政策的部分均需确认后启用。

| 指标 | 计算与边界 |
|---|---|
| 净订单成交额 | 选定有效订单范围内，原成交额＋已生效增项－已生效减项。现金退款和合同减项若是同一事项只影响成交一次；退款支付本身不重复减成交 |
| 当期成交变动 | 本期新生效成交＋本期已生效增减变化；与“本期形成订单的截至当前净值”分开，待财务选择周报主口径 |
| 实际回团成交额 | 已实际完成的销售内容所分配的净成交额；不直接等于财务确认收入 |
| 未来回团安排 | 截至数据截止已生效且未取消、计划在选定期间完成的未履约销售内容金额；不是已完成业绩，也不是概率预测收入 |
| 业务结算收入 | 经业务结算确认、口径明确的该项收入，不用订单应收或已收款替代 |
| 财务确认收入 | 财务按公司及期间确认的收入；与订单规模、回团规模分别展示，不能互相代替 |
| 业务毛利及毛利率 | 同一批业务结算收入－对应业务成本；合计毛利÷合计收入。不能简单平均各行毛利率，成本不全时不出正式毛利率 |
| 不含税毛利 | 财务确认的不含税收入－对应不含税成本；不得把含税业务毛利换个名字显示 |
| 同比／环比 | 对比基数大于0时为（本期－对比期）÷对比期；基数为0显示新增／无可比基数，缺数据与真零分开，负基数优先显示变动额并提示不可直接比较 |
| 完成率／任务缺口 | 同期间、组织、金额及版本的实际÷任务；建议任务缺口为任务－实际，正值尚差、负值超额。无任务不显示0% |
| 结构占比 | 分类金额÷明确范围合计；金额与人数占比分开；渠道内占比与产品内渠道占比分开，筛选后保留分母含义 |
| 单数／团数／人次 | 按业务订单、团期去重；同一旅客多次出行属多人次，不是去重人数。人数与签证份数、酒店间夜等不同单位不相加 |
| 实收 | 按订单关联的财务收退款分配记录计算，并声明是期间流入还是截至日净收款；不把未分配到账、门店预存余额或公司间调拨当订单收款 |

日期至少区分订单创建、确认生效、计划完成、实际完成、业务结算确认和财务确认期间；财务回团管理月不是天然等于会计期间，收款日期也不替代上述日期。

周起止日、跨年周、双周起点、闰年同期、自然月和26日至25日的适用范围建立统一日历。默认同比建议同长度、同截止进度；全年对全年与截至日对截至日不得混用。跨年回团还要同时限定订单形成期和完成期。

内部金额保留明确币种和原始单位，汇总后再按元／万元展示；先换算统一报告币种，再求和，不能猜汇率或对已是万元的数字再除10,000。源数更新与报表所属期间分开，所有报表同时标明统计区间、数据截止、金额口径、组织范围及已发布版本。

## 八、怎样做到财务不用再算

1. 日常业务在原模块正常下单、归属确认、实际完成、成本整理和财务确认；历史来源接入后按订单及业务关系防重复。
2. 已确认的报表规则自动计算日期、分类、增减变化及集团管理去重；不能每周要求财务再用姓名匹配经营组、手工粘贴历史数据。
3. 系统使用批准的预算和同一统计日历自动形成实际、同期、增长、缺口和占比；预算维护不等于每周人工编报。
4. 更新成功后，P1至P6读取同一批结果。更新失败保留上次成功版本并显示过期状态，不以零值冒充没有业务。
5. 财务主要核对P8异常，源数据正确且检查通过时查看或发布本期结果；是否允许自动发布及固定更新时间待确认。
6. 历史更正保留原发布版和更正版，能解释“这周重新看上周，为什么金额变了”。按权限导出同口径明细作为辅助，不要求导出Excel再计算才能使用。

当前系统是静态业务原型。后续页面原型能验证这些任务和交互，但正式做到上述自动化还需要业务数据服务、共同资料、历史数据、预算及财务确认来源。不能把浏览器内的演示保存或固定图表视为自动报表已经上线。

## 九、实施顺序与验收

只在用户确认本方案后进入页面设计，不在本轮扩大改动范围。

1. 确认8页架构和下节口径，形成正式页面字段及样例验收表；不回到旧四页签里继续堆字段。
2. 原型先做P1至P3及P5、P6的主要分析与核对路径，同时表达P7、P8必需配置；在毛利来源未完备处明确待确认。自动周报上线必须有对应任务与报表规则能力，不能永久省略配套页。
3. 明确成本和结算来源后完成P4及确认毛利视图。正式实现时先验收共同数据、去重和来源核对，再验收报表汇总，不要求静态原型做生产级联调。
4. 核对原导航及历史链接后替换正式数据中心入口；团期订单、销售操作、财务制单入口不变。

| 验收场景 | 必须得到的结果 |
|---|---|
| 普通有效订单→实际完成 | P5与订单分析一致，P6与回团分析一致；两套金额不相加 |
| 同一订单在两个来源出现 | 对应业务只计一次，排除原因可查 |
| 一单多项、多团、部分完成 | 订单单数不翻倍，完成金额不超过该内容可归属金额，未完成部分保留 |
