# 航服新结算核算准备实施验收

日期：2026-10-17。执行范围：附件差异复核第四组补05，对应I5。依据进度第三、四节和用户“执行”；验收重点按用户要求放在页面内容、功能和上下游跳转。补05的原型范围已完成，剩余完善01航司模板差异配置与导出。

## 一 业务位置与实际入口

上游是主管和财务已批准的机票结算、包机项目结算及补充调整。核算财务选择本次资料范围和会计期间，即准备交给财务记账的月份，生成核算准备记录。票务、包机负责人和主管可以查看来源；实际确认与生成由核算财务办理。

- 财务管理→NC推送→航服核算，打开“结算来源／准备记录”。沿用原财务页面，没有新增菜单或HTML页面。
- 机票结算详情→核单明细→财务核算→核算准备，带本结算和演示岗位。
- 包机项目结算→财务核算→核算准备；每笔已批准补充调整有本调整的核算准备入口。
- 准备详情“查看来源结算”回到相同结算或项目。包机负责人查看机票原单时按主管只读身份承接，避免未识别岗位回退成票务编辑身份。
- 原三个凭证样例保留在“凭证演示”，明确为独立样例，不占用新结算的准备范围；其他业务返回原NC页面。

## 四 交付边界和唯一下一步

本步交付核算资料准备，正式科目、税务政策、收入确认、实际内部公司关系、辅助核算对应仍待财务确认。准备记录停在待配置是当前批准范围，不表示正式凭证已生成或NC已推送。包机补充调整未登记业务期间时明确显示待核，不冒用原结算期；财务单独选择开放会计期并记录依据。

用户已授权继续跳过两项文件环境验收：真实文件上传、file://跨页仍待人工补验。航待01—12及真实航司／银行／税务／NC接入边界保持。集团财务原8批／36项／6场景不变。

唯一下一步：完善01航司模板差异配置与导出。至少两种明确不同的演示格式，覆盖列名、顺序、姓名、日期和允许值，并从名单导出入口验收实际内容；正式航司格式须以实际样板确认，不凭空宣称可被航司受理。补05不重复实施。
