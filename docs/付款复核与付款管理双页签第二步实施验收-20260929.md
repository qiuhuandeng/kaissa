## 一、角色和菜单

| 页面 | 谁使用、处理什么 | 上游与下一步 |
|---|---|---|
| 履约中心／付款申请 | 计调按已保存的有效成本提交预付或付款；最终确认后多付的成本可申请退回 | 成本、采购依据进入财务付款复核；业务应退交资金人员核对到账 |
| 财务／付款复核 | 核对业务原申请的公司、供应商、金额、付款依据和账户；通过后送审批，资料不足退回原申请人 | 既有成本付款与最终账单申请并存，不统一要求先结算或先对账 |
| 财务／付款管理／付款执行 | 资金人员办理已审批付款、检查结果、查看原款和回单；从成功付款发起重复实付退回或银行退汇 | 付款结果不明时保留付款中，不开放重复付款或资金退回 |
| 财务／付款管理／付款退回 | 核对实际入账、分次到账、原款匹配及材料 | 到账结果交应付岗核对余额；凭证由核算岗另办 |
| 财务／预付管理／预付退回 | 按预付单查询全部申请、历史和原付款分配 | 未用预付继续按第1步逐实际付款申请，资金页核对到账 |
| 财务／回单核销 | 保留原付款回单及其他收付范围 | 本步不把该菜单整体并入供应商付款 |

付款复核的“退回补充”退的是申请资料，不是资金。付款管理两个页签办理同一岗位的付款与资金退入，切换保留本页筛选及办理结果；旧付款、退回地址及单号仍可打开，菜单统一选中付款管理。

## 二、退回入口和处理结果

1. **重复实付**：原成功付款详情的“付款退回→申请退回”。填写本次金额、另一笔重复实付的付款号及原因。金额不能超过原款尚可退回额。
2. **银行退汇**：原成功付款详情的“登记银行退回”。银行通知号为必要依据；此动作形成待到账记录，实际入账仍须单独核对。付款失败、银行拒付与已成功付出后退汇分开表达。
3. **业务减费**：履约付款申请中的“供应商应退”成本使用“申请退回”，带入最终确认额、净已付和应退差额，并选择具体原成功付款。本步样例已付120,000元、最终确认90,000元，两笔原付款70,000及50,000元，最多申请30,000元。分次申请合计不能超额。
4. **未使用预付**：保留预付管理逐原付款入口，不能把普通资金退回当成绕过已冲抵余额限制的入口。
5. **银行已到账、原款未清楚**：资金页“登记到账”，先选择真实收入流水并记录依据，状态为“已到账待匹配”；匹配时校验付款公司、付款对象、币种和原付款结果。
6. **银行已到账、供应商材料未齐**：允许按已核实流水登记到账，材料保持待补。预付申请后补凭据时保留既有到账和余额，不重复扣减。

资金主状态统一为待到账、部分到账、已到账、已到账待匹配。列表只保留退回单、付款对象、原付款、应退金额、已到账／未到账、资金状态和操作；核算、业务关联及材料进详情。退回流水不能重复使用，超额、错公司／币种／方向、缺核对依据均不保存。

## 三、资金和核算边界

旧退回页“确认冲销”及随操作生成凭证的路径已撤下。新申请、供应商凭据和资金到账是不同事实；核对到账不自动生成凭证，不直接减少确认成本，也不把业务减费与银行退汇统一恢复应付。

现有专用银行退汇样例仍演示原债务有效时恢复同额待付；未用预付样例只减少预付余额、不改应付。通用退回保留原款和到账记录，原应付的调整对应与确认口径留第3步核对。已开票后的票据处理、外币差额和正式审批／入账政策仍待财务确认。外币到账不足应退金额保留未到账差额，不擅自写成手续费或损失。
