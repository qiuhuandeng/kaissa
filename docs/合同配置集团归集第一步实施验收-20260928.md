# 合同配置集团归集：第一步实施验收

日期：2026-09-28。依据：[全流程职责重审方案](合同配置全流程职责与页面归属重审方案-20260928.md)及用户“执行”。本步只完成入口与职责归位；下一步在集团模板页实现字段取值及受控平台对应。

## 一、页面在全流程中的位置

公司资料由集团组织档案提供；技术管理员维护该公司的平台关系；集团合同管理员／法务维护复用模板，公司规则决定具体场景的默认模板、审批和付款条件。产品人员继续采用系统设置或指定一份适用模板。销售在合同准备中处理具体订单、游客与签署人，签约和签后处理继续在商户合同管理完成。

模板发布与具体合同审批仍是两类事项，沿用现有审批中心。编辑模板不修改在途合同和已签文件；接口授权核对不代表模板已发布，模板发布也不表示真实接口已经开通。公司政策和平台能力的样例不作为正式业务确认。

| 门店中心 → 门店列表及详情中的销售／合同配置 | 共享表单只保留签约公司和是否允许本店发起签署；不再单独绑定一份模板、一条规则。详情摘要和变更记录改为沿用公司规则，规则行不再提供门店调整按钮 | 门店管理员确定签约主体及本店办理开关；具体模板在订单业务场景确定 |

## 三、页面看不到的处理约束

1. 公司规则先确定实际签约公司，再筛选适用模板；空选项不默认取其他公司的第一份模板。新规则须有公司、名称才能存草稿；缺模板／政策可存草稿，不能启用。
2. 已启用规则保存时重新核对模板、有效期、审批、付款条件和同公司冲突；缺付款节点、无适用模板或同场景重叠均阻断。不同公司不会因为规则名称相似而互相覆盖。
3. 门店开关只决定能否发起办理；公司授权不足仍阻断。移除门店单模板限制不表示所有订单均可签，实际选用仍须满足公司、产品和具体合同条件。
4. 平台授权能力是核实结果，合同规则不能通过勾选扩大接口能力。印章公司与实际签约公司不一致仍阻断保存；授权未知或过期仍提示缺项。
5. 商户只读页面不注册模板保存／发布操作；切换公司重新过滤模板并关闭原详情。原型的端口区分不等于正式服务端鉴权，正式开发须校验岗位、公司范围和审批任务权限。
6. 本步各页仍为会话演示，刷新恢复；不新增跨页自动同步。审批来源使用明确的审核样例，未声称已保存真实发布申请或连接生产审批。
