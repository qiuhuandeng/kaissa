## 2026-10-09最新反馈：统一为餐厅库新增餐厅抽屉规范

用户明确指定“资源 → 餐厅库 → 新增餐厅”为参照。读取`merchant/resource/resource-masterdata.html?type=restaurant`及共享样式，并在浏览器实际打开该抽屉采集计算样式；会奖共用抽屉复用相同标准类与布局，不修改已恢复的单次／多场使用逻辑。

## 具体调整

- 一级列表取消大标题；条件区使用32px控件、12px间距、明确的起止日期和查询／重置分组。新增项目等主操作放在右侧；合同生成放在页签栏右侧。
- 单团项目详情、项目团详情保留固定页面名称，对象名称与编号、主状态放摘要卡；摘要按宽度自动改为三列或两列。
- 详情页签、内容卡和表格使用一致宽度。切换后保留相同样式，避免共享导航再次将详情页签当列表页签改写。
- 日程日期列定宽，议程／行程承担剩余宽度；操作列固定在右侧。金额、人数和按钮完整显示，长文本可换行或在详情查看。
- 分区标题与当前分区的按钮同行；统一费用、客户约定、资源、结算及资料区的间距、边框和层级。
- 表单统一标签、必填、输入框、文件选择、错误提示、抽屉头部和底部。批量导入、名单、资源及费用抽屉保留字段联动和未保存确认。
- 移除全局“演示身份”和审批办理身份下拉。按页面岗位保留权限判断；协作、跨公司、销操兼岗和计调范围继续用独立测试资料验收。旧身份缓存不再影响日常展示。
- 供应商参与通过“我方对账／供应商确认”流程视图表达，保留双方确认与当前版本盖章件校验。
- 财务项目列表补齐当前列表查询、空态和重置；合同沿用原过滤与详情办理逻辑。报表继续只读，不增加下钻或重复计收。
