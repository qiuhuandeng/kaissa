## 2026-10-08 现行实施基线

本轮延续“单团项目”，扩展单次、多场和年度框架业务。没有另设会奖主菜单。项目用于客户统筹、总体约定和费用总览；项目内活动用于具体日期、人员、执行与业务结算；订单记录客户确认的具体价款，同一笔固定包价可以覆盖五场活动。

1. 项目建档、客户价款确认和活动确认执行是三个独立动作。启用项目不代表自动成交、签约、应收确认或付款。
2. 项目详情四页签为活动安排、客户约定、费用总览、项目资料。活动详情五页签为执行安排、费用采购、客户款项、结算核对、资料记录。
3. 年度框架可以先登记和办理合同；额度／预估不能成为500万元成交。具体服务委托进入原订单。月度核对引用原订单，不增加同额销售。
4. 客户价款有固定总价、确定数量单价、按实际确认三种。预计数量只产生预计金额，最终价款通过有依据的客户确认及原订单变更处理。
5. 每场直接费用归活动；共同费用留项目；跨场采购按有依据的金额分配。未分配部分明确保留，采购总额只计一次。实际维护、分配及请款在履约项目团详情原位办理，也可从项目采购集中台账办理同一原单。单团项目费用总览只读；本场分配不能作为另一笔采购请款。
6. 费用均按含税金额录入。预算、最新预计、已确认费用、实付分开；票面税额与财务核定可扣税额分开；参考、预算、固定约定、财务折算汇率分开。
7. 开始执行、实际完成、客户认可、业务结算、资金结清和项目结项分别记录。取消一场不删除原采购成本，不按场数平分退款。
8. 正式收款认款、付款结果、发票结果、税额核定归财务原页。业务提交只改变申请状态。业务结算后费用增减关联原费用和原结算，保留原已确认数。
9. 原付款菜单继续进入团期结算的付款工作区；供应商对账仍我方发起、供应商确认当前版盖章件。本轮没有恢复已撤回的独立付款类型改造。
10. 本轮用户明确要求贯通原型，页面以同一浏览器会话保存演示办理结果；实际接口、银行、税务查验、致远、短信及NC未接通。

角色：销售维护客户约定和订单合同、认领及开票申请；负责人统筹分工和结项；计调维护本人活动、采购和业务结算；财务确认款票与核定税额；审批人办理当前事项版本。成员登记不增加岗位授权。

## 1. 业务目标

单团自组要解决的是客户专属团队在销售和客户已确认方案、金额和服务标准后，从项目录入、审核、合同订单、专属团期、执行成本到团期结算的业务承接。系统不承接完整询价报价流程。

单团不是一个新的标准线路类型，也不是资源模块的动态库存入口。它是产品中心下的项目型成团入口，主入口保留在：

```text
产品中心 -> 单团项目
```

菜单和页面主标题统一使用“单团项目”；“单团自组”只作为业务场景口径保留在说明中。

## 2. 两条业务路径

### 2.1 引用标准线路独立成团

适用于客户选择已有成熟线路，只要求独立成团、专属日期、专属人数、客户确认金额或局部服务调整。

```text
旅游线路/方案 -> 创建专属团期 -> 团体订单 -> 出团执行 -> 团期成本 -> 回团结算
```

关键边界：

- 不新增“单团线路类型”。
- 独立成团是团期的成团方式，不是线路类型。
- 专属团期必须关联客户或单团项目。
- 专属团期不进入公开渠道售卖。
- 团期仍承接名单、资料、执行、成本和回团结算。

### 2.2 新建定制单团项目

适用于客户的行程、资源、服务标准、会议活动、金额和付款节点已经在线上或线下确认好，需要在系统录入单团项目并进入审核、团控和结算。

```text
客户已确认方案 -> 单团项目录入 -> 审核确认 -> 项目团期 -> 合同订单 -> 执行成本 -> 团期结算
```

关键边界：

- 系统录入前，客户方案、金额和服务标准已由业务线下确认。
- 录入后先审核，审核通过后是正式项目。
- 执行时承接到专属团期或项目团期。
- 收款时承接到订单和应收计划。
- 结算时承接到团期结算/团结算。
- 后续可支持“沉淀为标准线路/方案”，但不是第一轮主流程。

## 3. 对象边界

| 对象 | 维护位置 | 说明 |
|---|---|---|
| 单团项目 | 单团自组列表/详情 | 客户、联系人、人数、日期、目的地、客户确认金额、服务要求、会议活动要求 |
| 客户确认材料 | 单团详情 | 客户确认的方案、报价单、邮件、合同附件或内部审批附件 |
| 项目审核记录 | 单团详情 | 审核客户、金额、服务范围、收款节点、合同主体和履约责任 |
| 专属团期/项目团期 | 履约中心 > 团期管控 | 用于名单、资源确认、执行、成本和回团结算 |
| 团体订单 | 销售中心 | 用于合同、收款计划、游客名单、售后和退款 |
| 项目成本 | 团期成本/单团详情承接入口 | 业务侧确认成本，财务侧承接应付和付款 |
| 团期/项目结算单 | 财务 > 业务结算 | 财务确认收入、退款、成本、应付、毛利和 NC |

## 4. 页面责任边界

单团主页面负责让业务人员理解和推进流程，不负责深度财务执行。

单团详情页可以展示：

- 客户确认材料、确认金额和项目审核结果。
- 合同、订单、专属团期、收款计划、成本和结算的承接状态。
- 进入订单、团期、财务页面的入口。
- 关键数据缺口，如确认材料缺失、审核未通过、合同未生成、名单缺失、资源未确认、成本未确认。

单团详情页不做：

- 财务认款。
- 付款执行。
- 发票认证。
- NC 推送。
- 跨页面真实自动回写。
- 自动生成完整下游单据闭环。

## 5. 页面实施卡模板

每次改造页面前，必须先按以下模板确认：

| 项 | 必答 |
|---|---|
| 页面位置 | 当前页面位于单团链路哪一段 |
| 使用角色 | 销售、产品/计调、团控、财务、审批人谁为主 |
| 上游来源 | 从需求、线路、报价、团期、订单哪个对象来 |
| 当前对象 | 当前页面维护的唯一主对象是什么 |
| 高频任务 | 用户进入页面最常做什么 |
| 下游承接 | 完成后流向订单、团期、成本、财务还是审批 |
| 不做事项 | 当前页面不处理哪些下游动作 |

## 6. 第一轮实施范围

第一轮只处理单团主入口，不做全系统闭环。

必改页面：

- `merchant/tour/product-custom-list.html`
- `merchant/tour/product-custom-detail.html`

第一轮目标：

- 列表统一为“单团项目”入口。
- 支持“新建定制需求”和“引用线路创建独立成团”两个入口。
- 列表操作列稳定，不用当前待办生成不同按钮。
- 详情页按需求、报价、锁定、合同订单、执行资源、成本、收款结算、变更记录组织。
- 财务和团期只做承接入口，不做深闭环。

## 7. 后续实施顺序

1. 单团列表和详情。
2. 标准线路/方案发起独立成团。
3. 新建团期支持独立成团和客户/项目关联。
4. 团期列表和详情识别专属团期。
5. 订单、合同、意向订单承接单团来源。
6. 执行、成本、结算页面识别单团项目来源。
7. 财务、审批、客户详情补充反查和来源筛选。

## 8. 防跑偏规则

后续任何页面改造，如果发现页面在尝试把单团做成标准线路类型、资源日常操作入口、财务深闭环页面或 NC 推送入口，必须先收敛为业务承接入口，再判断是否需要修改下游页面。

一句话基线：

```text
单团主入口管需求、报价、锁定和项目推进；团期管执行；订单管合同收款；财务管应收应付结算和 NC。
```
