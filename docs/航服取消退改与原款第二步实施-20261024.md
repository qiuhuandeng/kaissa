## 已完成的业务结果

1. 原订单取消抽屉区分“待定损”和“已确认”。待定损金额为空；确认0元也保存依据。原团号、报价、名单、出票及原收付款保留。部分出票先处理已出票范围，全部退完后才能确认整单取消。已确认取消结果不可重复覆盖。
2. 原结算核对取消最终费用和供应商损失，不再要求未出票取消单补票号；待定损不能用暂估绕过。草稿核单读取当前实际收付，已审批版本仍保留。取消后已确认的待收费用可沿原收款申请和认款办理，未结算查询保留取消待定损记录，不显示为0元。
3. 原退改款项抽屉展示原订单、原票、原团、原收款和原付款。客户退款复用原退款申请、审批与执行；普通退款、退改退款、已退及在途共用可退余额。历史已登记但缺逐笔原款的金额保留待核并扣减余额，不虚构原流水；历史未知结果必须先查询。
4. 供应商调减分为未付冲减、银行退回、平台退回余额及BSP账期抵扣。现金退回保留原付款或原扣款；非现金冲减不冒充银行到账。客户补收、供应商补付沿原收付款申请，保留原退改依据。
5. 原执行抽屉支持分次金额、实际日期、我方付款账户和回执。失败可重试，结果未知先查询原请求，成功金额不可重做；供应商收款账户与我方付款账户分别展示。
6. 机位释放留原团来源；从部门额度继续释放时可以引用原团释放记录。退位确认、待定损和确认损失在原详情办理，后续再分配不改变原损失归属。公共库存保留“责任归属待确认”。原付款安排接原资金申请，返回可查看实际付款；来源保留采购、航班、航期和付款节点。
7. 平台每次充值独立申请，已有在途充值先核原申请；完成50000后可继续申请10000。原交易详情可查看原付款、订单收付及已有结算，余额核对保留日期、依据和差额；充值不计为客票成本。

## 试用顺序

- 机票订单：在未出票订单“更多→取消订单”先保存待定损，再点“取消结果”确认0元或有损；从航服结算新建原订单的结算草稿。
- 退改处理：在业务结果生效后进入“款项结果”；也可从航服资金现有客户退款列表打开预置退改 `HFTGSTEP2-RETURN`。原型案例原收6000、原付5000，客户需退2000、供应商需退1200；可分次办理并查看每笔原款。
- 机位管理：详情“付款安排”进入申请；“机位分配”释放额度后，从原列表“更多→申请退位”选择原团释放来源，再在“变更记录”核对退位和损失。
- 航服资金：平台预付“明细→申请充值”，按原审批与执行继续；再次申请时使用新的充值金额。
