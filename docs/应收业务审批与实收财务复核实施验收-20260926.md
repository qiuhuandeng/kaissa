# 应收业务审批与实收财务复核实施验收

日期：2026-09-26。依据：用户在[职责修订方案](应收业务审批与实收财务复核职责修订方案-20260926.md)后明确“执行”。本步交付订单申请、审批与财务应收职责修正的可操作原型，不建设跨页自动回写或正式账务系统。

## 一、角色和流向

销售确认订单后，系统自动形成应收；后续销售从原订单新增项目、修改原项目或申请减免。涉及服务安排的先由计调确认供给，金额变更进入业务审批。批准前原应收不变，批准后按差额生效。财务复核到账和认款、查看已生效应收，并承接后续收款、退转及结算。

审批岗位、金额分流和适用条件尚未确认。新申请显示“待配置业务审批”，不能自动批准，也不默认指定财务。审批中心的应收变更案例明确标为演示，仅在当前页面演示通过、驳回或退回及金额结果。正式岗位未定不阻塞其余已明确原型功能。

| 编号／业务要求 | 修改前问题 | 本次修改页面及行为 | 验收与边界 |
|---|---|---|---|
| 职责01 订单确认自动生成应收 | 预留订单也显示初始应收已生效，下单结果写待审核 | 新建订单、订单管理、订单详情区分预计应收与已生效应收；未确认不能提交正式应收变更；订单确认后显示系统生成，保留确认前真实预收入口 | 浏览器验证预留不显示已生效、确认后系统生成、未确认增项被拦截；沿用订单确认主状态校验，不新增财务确认环节 |
| 职责02 全部应收变更进入业务审批 | 泛化待审批及提交财务审核混用 | 订单单笔／批量统一业务审批；未配置岗位保留待配置，资源确认与业务审批分列；审批中心演示业务批准后自动生效 | 新增、减免、数量、单价及批量检查；未批准原金额不动；批准仅生效一次；应收版本变化须退回重核；退回／驳回要求原因。销售新申请不自动写入审批中心示例 |
| 职责03 修改原项目有前后对比 | 只有新增或负向差额，没有原行数量单价 | 订单列表及详情增加“修改原项目”，读取订单费用明细，保留原数量／单价／金额，计算新旧差额。列表不再按2%临时拆造保险金额 | 原单房差1800改单价1500，差额-300；修改数量正确；原项目未被覆写，未选择原项目及零差额误申请被拦截 |
| 职责04 财务不审批业务应收金额 | 普通应收及补差有确认／复核／退回 | 应收管理普通记录只查看；补差业务批准后直接待收款；复核处理函数也限制为优惠承担。新增减价多收款示例 | 浏览器普通行无确认及退回操作；应收7000、实收8000、多收1000单独显示；未自动改实收、退款。优惠承担、坏账及认款等独立职责保留 |
| 职责05 两类审批分别配置 | 认款与应收变更合为财务事项 | 审批配置增加销售“订单应收变更”和财务“认款调整／复核”；应收必显原值、拟值、差额、依据及实收影响。新配置草稿不含默认审批岗位；已保存旧模板及历史版本不改名、不覆盖，仅补独立草稿 | 配置规则及浏览器筛选验证；历史保留与重复补入检查。审批中心仍保留旧事项筛选，便于已有记录查阅 |
| 职责06 计调确认不代替业务价格审批 | 服务确认后应收去向不明确 | 团期详情确认摘要明确收费变化仍须业务审批；需补差转销售确认后再送业务审批，免费只留服务记录 | 原免费联运、强提醒、可供／不可供／补差、重复确认阻断全部浏览器回归；不制造零元应收审批 |

## 五、交付边界和唯一下一步

本页会话申请记录不自动发送到其他页面。审批中心演示金额变化，财务页示例表达已生效结果，不能据此宣称跨页实账更新、自动生成生产单据、审批结果自动回写或退款执行已接通。退回／驳回原因及原应收保持已验；生产中的历史版本重提、正式审批人路由和后台并发控制不属于本次原型交付。

本步已明确的页面职责修正完成。唯一下一步：业务明确“订单应收变更”的审批岗位、适用公司和金额分流条件后，配置该事项的正式审批流程；在此之前保留待配置状态。并行供应商工作线及已撤回的产品预订结算价展示不受本步影响。
