# 参团游真实ERP验收准备01：公司与交易责任

日期：2026-11-07。状态：第一组责任与测试算例已整理，正式组织和财务政策待确认；本稿没有记录真实ERP执行结果。

上游：[范围与规则梳理](测试目录.md)、实际旅游及采购合同、集团组织与岗位制度。下游：订单与名额规则、各场景测试数据、财务独立计算底稿及AI执行说明。本期验收到ERP财务确认、凭证生成和相应报表；NC接收及记账分期。

本组由产品、销售、计调、外采、渠道及财务共同核对：一笔参团业务究竟属于哪个公司，形成哪几段结算关系，每笔收付款归谁，变更后由谁承担。没有实际合同及配置支持的责任不得只根据产品来源、门店名称或收款账户猜测。

## 一、已确认范围与本稿测试设定

用户已确认：国内与出境参团游、自营与外采均覆盖；集团内部采购转售、代销两种模式都存在且分别验收；已有独立测试环境、多岗位账号及接口／只读数据查询条件；正式规则尚未统一，需要先整理。

以下公司、游客、金额、日期顺序和分配方式均为专用测试设定，不是凯撒实账、现行费率或制度批准。四个主案例分别创建数据，不把四笔10万元重复计入同一笔业务；每个变化分支使用独立副本或独立测试批次，不累计到另一个分支。

应收表示他人已确认欠本公司的款，应付表示本公司已确认欠他人的款；预付表示已先行支付、尚待与相应欠款抵扣的款。核销指用已确认款项抵扣相应欠款；预付分配给某个团不等于已经冲抵应付。

本稿的“交易差额”仅为本案例对客约定金额、采购约定金额及佣金之间的业务差额。金额均未作价税拆分，未加入其他经营费用；不把该差额命名为会计收入、不含税毛利或净利润。收入、税费、凭证及期间须另绑批准规则。

### 4.4 责03：A采购B的产品再向游客销售

故事：B从S引入“日本关西6日游”，外部采购70,000，向A供货80,000；A与游客成交100,000。源产品和源团期由B承接，A引用，不复制第二份物理资源库存。

| 步骤               | 经办动作及交接                                                                                          | 本次应核对的事实                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1 源产品与授权     | B核S协议、供给和70,000采购约定；建立可售产品团期，向A开放销售范围及80,000内部价格                       | B对S负责，A对B采购；A未因共享而直接向S欠款                                                                 |
| 2 A成交与B承接     | A建立O01/O02并与游客签约；B收到关联供货和10人名单                                                       | 游客成交只计100,000；A采购合计80,000、B对外采购70,000分别关联；10人不重复占20位                            |
| 3 首款及提前采购款 | 游客付A30,000；A按约先付B20,000；B按约先付S10,000                                                       | A现金净增加10,000，B净增加10,000；欠款尚未正式确认时先保留各自预付，不提前形成最终收入成本                 |
| 4 履约及双方核对   | B组织服务，A核客户侧变化；B/S确认70,000，A/B确认80,000适用业务依据                                      | A只能确认本方责任和金额，不能替B修改成本；双方确认版本、币种和范围相同                                     |
| 5 尾款与部分结算   | A收游客尾款70,000，此时A现金净增加80,000；已付B20,000抵清后仍需付60,000；B已付S10,000抵清后仍需付60,000 | A欠B60,000与B应收A60,000对应；B欠S60,000独立。对账完成不自动清零这两笔余额                                 |
| 6 资金结清         | A向B再付60,000，B向S再付60,000                                                                          | A本例净现金20,000，B10,000；内部累计收付80,000，集团外部实收100,000、实付70,000                            |
| 7 结算与财务交接   | A核对客及内部采购，B核供货及外部采购；各自形成适用财务确认和凭证                                        | A交易差额20,000、B10,000；集团外部交易差额30,000。不能把A客户100,000与B内部供货80,000相加为对客销售180,000 |

同组必须追加“B自营组团”的来源分支：B从S1—S5采购28,000＋16,000＋18,000＋5,000＋3,000，合计仍70,000。A/B80,000关系不变；B外部采购分为五项，不能在保留70,000整包采购的同时又新增五项70,000。本组算术核70,000相等；实际五供应商办理及权限留真实执行。

| 3 收款及预付     | 游客向B付30,000；B向S预付10,000，随后收尾款70,000         | B本例净现金90,000；A现金仍0，不能因A录单显示A收到游客款                                 |
| 4 履约和应结确认 | B确认S采购70,000；A/B按约确认佣金20,000                   | B欠S在预付抵清后为60,000；B对A佣金20,000与A应收B20,000对应                              |
| 5 付款           | B付S余款60,000，另付A佣金20,000                           | B净现金10,000，A20,000；采购付款和佣金付款有不同依据和对手                              |
| 6 结算与财务交接 | B核对客、资源采购及佣金；A核佣金及销售归属                | A交易差额20,000，B为100,000－70,000－20,000＝10,000；集团内部佣金不重复增加集团外部费用 |

佣金生效时点、计价基础、税费及退款后怎样调整均需正式协议和政策。本例只在已满足这些条件的假设下设置20,000，不能在新建订单时自动视为已付佣金。

## 五、代销的两种代收转付分支

两分支都要求有效代收授权，并分别从责04新建独立测试数据。游客付给A100,000，经适用规则确认后，游客对B的付款义务履行情况与B银行尚未收到该款必须分开显示。

### 5.1 全额转付后另付佣金

| 节点                                                       | A本例现金净额 | B本例现金净额 | 尚需结算的责任                                                 |
| ---------------------------------------------------------- | -------------:| -------------:| -------------------------------------------------------------- |
| A代收游客100,000，已确认代收事实；佣金20,000已满足确认条件 | 100,000       | 0             | A应向B转付100,000；B另应付A佣金20,000；不冒充B银行到账         |
| A将100,000全额转给B                                        | 0             | 100,000       | 代收转付余额0；佣金20,000仍待付                                |
| B付A佣金20,000、付S采购70,000                              | 20,000        | 10,000        | 本例相关余额0；游客付款100,000及内部转账不能重复计集团外部收款 |

### 5.2 有批准依据的净额转付

| 节点                                         | A本例现金净额 | B本例现金净额 | 尚需结算的责任                                                         |
| -------------------------------------------- | -------------:| -------------:| ---------------------------------------------------------------------- |
| A代收100,000，佣金20,000已确认               | 100,000       | 0             | 代收转付100,000和佣金20,000分别存在                                    |
| 依双方约定及审批，将佣金20,000抵扣代收应缴款 | 100,000       | 0             | 代收应缴余额80,000、佣金待付余额0；抵扣没有新增银行收付                |
| A转付B80,000，B付S70,000                     | 20,000        | 10,000        | 本例相关余额0；保留游客支付100,000、抵扣20,000、实际转付80,000三项依据 |

两种方式最终资金相同，实际银行流水不同。没有抵扣批准时，不能自行把100,000和20,000净成80,000并标双方结清；佣金尚未成立时也不能提前扣除预计佣金。这里不授权跨公司任意抵销，不把净额转付误认成产品采购80,000。
