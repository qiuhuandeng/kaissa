# 邮轮中心舱位采购实施

日期：2026-10-24。依据：用户明确新增一级邮轮中心（简称邮轮，航服上方）及采购合同、采购订单、采购入库。此授权只将邮轮采购组织到新中心，通用产品、销售、订单、履约和财务继续沿用。

## 本次步骤与逐页边界

本次作为一个采购原型步骤交付三项业务及直接承接入口。采购人员从船公司／船只资料和合作条件建立合同；具体航次通过采购订单落实；舱位核对人员办理入库与差异，审批人沿审批中心处理。统一超级管理员可连续操作各环节，但已完成单据不可重复办理。

## 状态与金额约定

- 合同：草稿→待审批→待签订→已签订；退回可修改重提。框架只约定范围，不能在签订时把整季估量一次入库。
- 采购订单：草稿→待审批→待执行→部分入库／已入库；可在入库前按原号留变更记录并重新审核。入库后不直接改原采购数量，后续沿库存退舱／调整处理。
- 入库：待入库→待审核→已入库；数量或舱型不符进入异常处理，保留原确认与处理依据。审核通过才增加库存，重复操作不再次入库。
- 采购金额按每条航次舱型的间数乘每间成本计算，船票成本、港口税、燃油和其他费用分列。此为演示合同的每间成本口径，不替代销售端按人票价。付款计划不自动记实付；保底条款只记录约定，不自动确认最终补差或损失。
- 本次限定原型会话中的合同→采购订单→入库→审批承接。实际接口、后台自动任务及财务记账不作为本轮内容，未定真实条款使用明确示例。

### 边界与遗留

本轮可操作原型无未验收项。新增采购记录在同一浏览器页签会话中用于页面和审批往返；关闭会话恢复示例，不作为生产台账。入库生成的是采购航次与舱位供给，不代替产品创建、销售团期或真实船方接口；原库存分配与财务仍沿用各自原型交互，没有声称已打通真实库存服务、付款或记账。文件选择登记合同附件，超过1MB的文件仅保留文件信息，不冒充已上传后台。

旧资源资料待补、价格／名单／分房补核、正式船方协议、财务政策与其他已登记遗留不由本轮自动解决；原财务8批／36项／6场景和并行会奖工作线保持。
