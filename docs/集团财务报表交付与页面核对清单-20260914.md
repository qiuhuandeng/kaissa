2026-09-15入口更新：本清单保留原8批功能交付证据；原10页及6类财务查询现已统一归数据中心四组16项，最新页面入口及内容调整请按[菜单归集交付清单](数据中心菜单归集交付与验收-20260915.md)核对。下文两处查询入口不再代表当前菜单；旧财务报表链接仍承接对应页面。

## 一、两块模块的关系

数据中心回答“经营得怎么样”：从订单成交、实际完成、财务确认到公司部门损益，分析产品、渠道、资源风险与预算差异。

财务报表回答“钱和账对不对”：核对收退转付、待收待付、四类预款、实际账户、票款以及结算与核算记录。收款认款、应收应付、付款、结算、开票等办理仍在原财务功能中，报表不办理这些动作。

核算公司是承担收入、成本或往来账务的公司；经营责任是承担销售或产品经营任务的公司、部门、门店等。两者分别查询，不用实际收款公司替代，也不因集团内部供货再增加一次对客成交。

## 四、优先核对顺序

1. 先看订单明细与回团与履约明细，确认两种日期和金额口径仍分开。
2. 再看月度经营损益，资料范围选“独立经营算例”，2026年9月：A公司经营结果3,400元，B公司5,400元；缺费用算例不输出虚假利润。
3. 产品/渠道切到“经营贡献”，与同公司损益来源核对；部门公共费用不能重复扣到每个产品或渠道。
4. 财务报表切换六个主题，资料范围选择各主题的独立算例，再看日期、截止、公司和原币条件。金额与明细依据一起核对。
5. 最后进入“口径与数据核对”的“业务场景核对”，依次看六种场景。每个都是独立、明确条件的验证范围，不与共同业绩混加。

六场景条件与数值、命令、结果及异常回归见[第8批及整体验收记录](集团财务报表第8批及整体验收记录-20260914.md)。不要拿不同页不同月份的独立样例强行勾稽。

## 开发定位附录

新增只读主题使用`shared/finance-readonly-report.js`，分组入口使用`shared/report-section-tabs.js`。普通有序脚本保留本地加载能力，不改回本地文件不能加载的动态模块。10页入口和6主题路径详见执行清单附录；全量回归入口为`tests/report-regression-browser.cjs`，最终清单检查为`node scripts/check-finance-report-execution.cjs --final`。
