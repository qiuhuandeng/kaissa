# 回团明细补充原型验收记录

日期：2026-09-13。范围：总体计划阶段2第二小批，依据《财务报表首批任务卡-订单回团明细与共同口径-20260913》第五节。结论：本小批原型通过，不代表正式数据取数、财务口径、收入成本确认或生产权限已经完成。

## 一、角色、入口与范围

入口：数据中心 > 经营报表 > 回团明细，页面为 `merchant/data/return-report-details.html`，由报表共享脚本绘制，本次没有修改HTML入口和导航。

主要使用角色为财务分析、结算会计及授权履约负责人；核对实际完成事实、未结算业务、财务确认资料缺口和未完成安排。上游为回团、服务完成、项目验收及金额分配；下游供经营分析和财务核算核对。实际完成确认仍在履约模块，结算及收入成本确认仍在财务模块，报表只读。

本次复核目录、导航、两份明细入口、报表共享脚本及样式，并与任务卡、总体计划和团期详情的完成确认/更正字段成对核对。既有按计划日期派生实际日期的样例逻辑已替换为独立给出的完成事实；未读取业务页面本地记录，没有建设跨页面回写。

## 二、页面检查清单

| 检查位置 | 本批完成内容 |
|---|---|
| 实际完成 | 保留12个默认列，默认包含待结算业务；可选完成记录号、完成类型、依据、确认人/时间、计调、计划/实际开始日、更正前日期及原因、金额分配依据 |
| 财务确认资料 | 明确为已完成业务的财务资料，按实际完成日期筛选；默认分别展示结算、收入确认、成本确认状态，不用一个状态替代全部结果 |
| 财务可选字段 | 核算主体、收入/成本各自的确认日期、会计期间与记录号、收入确认方式、税务处理、原结算及调整关联；未提供记录如实标明 |
| 未来安排 | 仅按计划完成日期查询；支持计划依据、共同归属和计划开始日等字段，不显示实际日期、回团管理月或收入税务状态 |
| 完成后调整 | 保留原订单/完成记录、原完成日、调整生效日、成交和成本调整；增加原结算、调整确认状态、原/本次会计期间。未提供样例记录，不声称调整为零 |
| 共同归属 | 引用上一批订单发生时的演示资料；销售与产品责任独立，销售/产品部门领导不被当前任职覆盖；共同组织、目的地两分区、渠道来源及版本可选 |
| 更多筛选 | 销售/产品组织及负责人、两分区、经营分类、预算区域、资料情况；财务资料视图另有收入/成本确认记录缺失筛选；切视图清除结算和财务资料条件 |
| 显示字段 | 五组复选框，订单和销售内容固定可识别；调整视图另固定调整记录号。完成记录号为可选字段，不扩大原12默认列 |
| 合计与缺数 | 分配成交额、业务结算收入、财务确认收入及成本分别合计；已知金额、待确认与未分配条数分别表达，全未知不合成0；数量按单位汇总 |
| 日期与导出 | 管理月只按实际日期派生；财务资料不误称会计期间查询；导出全查询已选字段，未查询条件不污染文件；未来/管理月/调整不导出未适用的日期条件 |
| 页面边界 | 只读表格，无业务下钻、弹窗、制单或确认按钮；编号金额不可跳业务页；窄屏滚动限表格容器，极窄容器取消冻结避免遮挡全部信息 |

缺少的计调、开始日期、真实组织及确认资料仍显示待补充/未提供；未依据确认人猜计调，未依据计划日猜实际日，未依据外采或零税额猜净额/免税。
