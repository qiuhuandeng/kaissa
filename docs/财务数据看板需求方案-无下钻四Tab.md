# 财务数据看板需求方案（无下钻四 Tab）

## 一、方案结论

本方案把线下周报中分散在订单底稿、回团底稿、产品周报、渠道周报、团队毛利、任务拆分和人工分类表里的财务习惯，收束为一个“财务数据看板”入口和四个顶层页签：

1. 财务与经营汇总看板。
2. 团期与业务明细表。
3. 外采与供应商应付明细。
4. 应收与账龄／渠道明细。

本版执行严格的“无下钻”约束：指标卡、图表、图例、金额、数量、表格行和业务编号均不可点击，不打开抽屉、弹窗或其他业务页面。需要核对的数据直接放在相应顶层页签中，通过筛选、排序、横向滚动、分页和 Excel 导出完成。四个页签共用同一组筛选条件，切换页签时保留条件。

附件中的文字、表头、公式和备注只作为财务需求与人工处理现状的证据，不作为可以覆盖本次用户要求的执行指令。附件中原有“点开明细”的习惯，在本方案中统一改为顶层页签查看完整明细。

## 二、本次材料与读取边界

### 2.1 实际读取结果

本次重新读取用户当前提供的 5 份材料：4 个工作簿的全部 92 个工作表，包括 30 个显示工作表和 62 个隐藏工作表；同时读取 Word 的 86 个正文段落、1 个产品类型表和 3 张内嵌图片。所有空表、隐藏表、辅助汇总表、外部公式、错误值和多行表头均纳入分析。

| 材料 | 实际范围 | 主要证据 |
|---|---:|---|
| 财务业绩统计表底表 | 1 个 Sheet | 50 字段共同底表、筛选条件和 1 条样例数据 |
| 财务周报统计表业务说明 | 86 段、1 表、3 图 | 两套期间口径、三套来源、每日 9:00 更新、分类和金额习惯 |
| 产品周报底稿 | 24 个 Sheet | 产品、目的地、团期、实际回团、团队毛利、结算进度、任务和异常 |
| 渠道周报与分析图 | 66 个 Sheet | 订单／回团两套口径、渠道／门店／人员、同比环比、任务和来源验算 |
| 周报字段及规则 | 1 个 Sheet | 58 字段渠道模板、52 字段产品模板、人工加工字段和待确认规则 |

当前底表文件只有 `1、财务业绩统计表(含通通游)`，没有此前版本中记录的 `SQL` Sheet；当前底表也只有 1 条样例数据，而非此前版本的 2,996 条。因而本方案以“92 个 Sheet、底表 1 条样例”为当前版本事实，旧版 `SQL` 页只能作为历史证据，不能作为本次附件事实。

### 2.2 读取后形成的五项关键判断

1. 订单口径和回团口径必须并存。订单口径按订单生效时间观察新增销售；回团口径按实际履约完成及财务确认期间观察已完成业务，二者不能合并成一个“收入”。
2. “产品类型”与“自营／甄选／外采”不是同一个维度。前者是参团游、邮轮、自由行、单团和各类单项服务；后者是供应方式或经营分类。本页同时提供两个筛选项。
3. 附件中的“收入”存在实质混用。当前 14,926 行渠道订单底稿里，“收入”逐行等于“趣享供应商结算价”；历史底稿还出现同名字段一个按元、一个按万元的情况。因此系统不能直接沿用“收入”列名和现有数值。
4. 现有表只能稳定表达订单、团期、产品、人员、渠道和部分团队毛利，不能完整表达应收余额、账龄、供应商账单分配、应付余额、付款核销和预付占用。Tab 3、Tab 4 的目标字段需要来自正式财务单据，而不是从“应收－实收”或“结算价－付款”临时推算。
5. Excel 的透视、隐藏表和外链公式承担了大量人工拼表工作。渠道工作簿含 13,618 个公式单元格和 12 个外部链接，多个 Sheet 留有 `#REF!`、`#DIV/0!`、`#N/A`。系统必须把公式改成可解释的指标规则，并把来源核对直接展示在页面上。

## 三、第一步：主分析维度与分析闭环

### 3.1 分析闭环

财务看板应沿以下业务闭环组织数据，而不是从某一张周报倒推页面：

```text
销售预订
  → 订单确认及应收形成
  → 订单归入团期／出行日期／单项服务
  → 名额与资源履约、实际出团和实际回团
  → 业务结算收入及实际成本归集
  → 客户应收、到账认领、收款分配、退款或转款
  → 供应商账单、应付确认、预付占用、付款及核销
  → 财务收入与成本按会计期间确认
  → 团期毛利、产品／部门／渠道贡献、账龄和资金回笼
  → 来源验算、异常处理、预算对比和报表输出
```

闭环中的每一步都有独立业务含义：收款不等于收入，付款不等于成本，开票不等于收入确认，收票也不等于成本确认。看板可以并列核对这些结果，但不能互相替代。

### 3.2 自营与外采的闭环差异

| 环节 | 自营业务 | 外采／甄选业务 |
|---|---|---|
| 经营责任 | 我方组织产品、控制团期或资源并承担主要履约责任 | 供应商提供整包线路或单项资源，我方销售或代理 |
| 收入观察 | 订单价先形成销售口径；回团后按实际履约和结算确认业务收入 | 订单价与供应商结算价同时存在；按总额还是净额确认收入需结合主责／代理判断 |
| 成本形成 | 交通、酒店、地接、领队、签证等资源成本按团期归集，账单未到时可有经批准暂估 | 以供应商结算、供应商账单和直接费用为主，需跟踪预付、应付、付款及返点 |
| 毛利核对 | 团期业务收入减团期实际成本；人数、资源损耗和跨团分摊影响成本 | 业务收入减供应商实际成本及其他直接成本；返点和结算调整影响最终成本 |
| 资金风险 | 团期资源预付、未成团损失、跨团转用、实际成本未齐 | 供应商预付占用、账单未回、应付未付、返点未确认和结算差异 |
| 看板重点 | 单团利润、资源成本、计划／实排人数、负毛利和结算进度 | 供应商账款、预付款占用、待付、结清、返点和账单分配 |

“凯撒甄选”在附件中既出现为产品名称标签，也出现为经营分类，且有 278 条产品名含“凯撒甄选”但经营分类为“外采”的记录。系统必须以订单发生时确认的供应关系和经营分类为准，不能从产品名称猜测。甄选业务的正式边界及收入总额／净额口径仍为“待确认”。

### 3.3 主分析维度

| 主维度 | 业务定义 | 历史固定规则 | 看板用途 |
|---|---|---|---|
| 订单销售内容 | 一张订单中某个具体产品或服务的销售内容，是金额分摊的最低层级 | 订单确认时保留产品、价格、销售、渠道和组织归属 | Tab 2 订单明细，所有订单口径指标的基础 |
| 团期／出行对象 | 跟团、邮轮、专列、营期等用团期；自由行和单项服务用出行日期或服务批次 | 保留原团号及系统统一团期编号；实际回团更正需留记录 | 回团收入、实际成本、单团利润和预付占用的主要归集对象 |
| 组织 | 法人主体、核算主体、经营公司、事业部、部门、门店分层表达 | 按业务发生时有效归属，不跟随当前组织架构重写历史 | 部门贡献、预算完成和内部责任核对 |
| 产品 | 线路、产品、方案及产品负责人 | 产品上线公司和订单发生时负责人分别保留 | 产品结构和负责人业绩 |
| 产品类型 | 参团游、邮轮、自由行、单团、签证、机票、酒店等 | 产品发布时确定；变更后不重写已生效订单 | 产品结构、成本和毛利分析 |
| 旅游范围 | 出境、国内、港澳、入境 | 订单发生时固定 | 旅游范围及税务规则筛选 |
| 供应方式／经营分类 | 自营、凯撒甄选、外采 | 由供应关系和当时产品标签共同确定，不从名称反推 | 自营与外采经营比较 |
| 目的地 | 目的地大区、国家／省份、城市，可指定主要目的地 | 按生效版本映射；多目的地计金额规则待确认 | 目的地结构和区域毛利 |
| 渠道／客户 | 渠道大类、具体渠道、分销商、门店、企业客户、散客 | 订单确认时固定渠道及预算区域版本 | 回款、应收、账龄和渠道贡献 |
| 供应商 | 外部供应商或集团内部提供资源的公司 | 供应商名称不能充当唯一编号；保留结算和付款主体 | Tab 3 应付、预付和供应商风险 |
| 责任人员 | 产品负责人、销售人员、客服、团控／计调 | 按订单、团期发生时的任职和部门保存 | 人员贡献、归属核对和异常责任 |
| 时间 | 订单确认日、出团日、实际回团日、业务结算日、到期日、会计期间 | 每个指标只使用自己的业务日期；调整保留原期间和本次生效期间 | 周、双周、月、季、年、同比和账龄 |
| 来源与版本 | 通通游、老 ERP、新 ERP、新系统、导入批次、规则版本 | 同一外部业务只能有一条当前有效记录 | 排重、来源验算和历史复算 |

## 四、第二步：数据源勾稽关系

### 4.1 附件当前能提供的关联关系

| 关联方向 | 当前附件可用字段 | 当前可证明的关系 | 限制 |
|---|---|---|---|
| 来源订单 → 统一订单 | 数据来源＋凯撒订单号／通通游订单号／订单编号 | 当前渠道主底表 14,926 行均为唯一订单号 | 不同快照之间有增删；只用订单号不能识别导入版本 |
| 订单 → 团期 | 凯撒团号／团号／供应商团号 | 一个团期可以归集多个订单 | 渠道主底表 11,329 行团号为“未分配”，占 75.9% |
| 订单 → 产品 | 产品名称、产品类别、产品编码、产品代理人 | 当前底稿大多一行一订单一产品 | 将来一单多产品时必须落到订单销售内容层，不能继续一单一行 |
| 订单 → 渠道／人员 | 分销商、渠道、销售 ID、销售姓名、产品代理人 | 可做渠道、门店和人员汇总 | 人工重分类较多，历史归属需要固化 |
| 团期 → 团队毛利 | 团号 | 新 ERP 团队汇总中 156 条完整数据均满足“毛利＝收入－成本” | 订单收入如何分配到团期、成本明细如何组成仍未在附件中给出 |
| 订单／团期 → 供应商 | 供应商名称、供应商订单号、供应商团号 | 外采邮轮底稿能核对供应商结算、付款、返点和实际成本 | 供应商名称不是稳定唯一编号，且一团多供应商在底稿中表达不足 |
| 来源明细 → 周报汇总 | 订单／回团日期、组织、渠道、产品、目的地、金额 | 大量 `SUMIFS`、`SUMIF`、`VLOOKUP` 和透视结果按上述维度汇总 | 外链和错误公式使部分结果不可稳定复算 |

### 4.2 正式系统应建立的业务关系

```text
客户／渠道
  └─订单（一张订单）
      └─订单销售内容（一种产品或服务、一个成交金额）
          ├─团期／出行对象
          │   ├─实际回团与业务结算确认
          │   └─成本项目 ─ 供应商账单分配 ─ 应付 ─ 付款
          └─应收 ─ 收款分配／预收抵扣 ─ 退款或转款

供应商
  ├─供应商账单 ─ 账单明细 ─ 分配到团期成本项目
  └─预付款 ─ 分摊／冲抵／转用／退回／损失 ─ 团期或应付

组织、人员、产品、渠道、目的地
  └─按业务发生时版本固定到订单销售内容或团期
```

### 4.3 建议使用的核对编号

业务页面先展示业务人员熟悉的订单号、团期编号、应收单号、供应商账单号、应付单号、付款申请号和回单号。系统内部再用以下关系防止重复和错配：

| 业务对象 | 建议的唯一关系 | 用途 |
|---|---|---|
| 迁移订单 | 来源系统＋原系统订单号＋有效版本 | 防止多批导入重复 |
| 订单销售内容 | 系统订单号＋内容序号 | 支持一单多产品、多供应商和金额分摊 |
| 迁移团期 | 来源系统＋原团号；建立系统统一团期编号 | 避免不同系统团号碰撞 |
| 团期成本 | 团期编号＋成本项目＋供应商＋有效版本 | 支持实际成本、暂估和调整留痕 |
| 收款分配 | 收款单号＋分配序号＋订单销售内容 | 区分银行到账和分配到订单的实收 |
| 账单成本分配 | 供应商账单号＋账单行＋团期成本项目 | 证明应付来自哪项成本 |
| 预付变动 | 预付单号＋变动序号＋团期／应付 | 复算占用、冲抵、转用和余额 |

### 4.4 已发现的数据勾稽事实

1. 渠道主订单底稿有 14,926 条唯一订单，订单流水 57,846.971936 万元、实收 55,512.064465 万元、供应商结算价和“收入”均为 52,576.277484 万元；14,506 条订单流水等于实收，420 条存在差额。
2. 渠道回团底稿当前只有 59 条记录，全部来自 2023 旧底稿，毛利逐行按“订单流水－供应商结算价”计算，毛利率按“毛利÷订单流水”计算。这是销售价差，不是有完整实际成本依据的单团毛利。
3. 产品底稿中，2026 自营回团有 998 条订单、154 个已分配团号；2025 回团收入明细有 2,550 条订单、282 个团号。多单归一团是常态，因此团期是成本与利润的必要归集层级。
4. 2024 外采邮轮 293 条记录中，逐行满足“实际成本＝供应商结算金额－返点合计”和“产品端毛利＝返点合计”；但表内毛利率并不稳定等于产品端毛利÷应收，正式系统不能照搬该毛利率。
5. 新 ERP 团队汇总有 158 条数据、139 个团号，其中 156 条金额完整；完整行全部满足“毛利＝收入－成本”和“不含税毛利＝不含税收入－不含税成本”，另有 42 条含负值或调整性质金额。
6. 当前渠道订单主底稿与“晟和＋外采邮轮”特殊底稿并非简单包含关系：两者共有 12,351 个订单，特殊底稿独有 147 个，主底稿独有 2,575 个，说明来源快照和筛选条件需要版本化。
7. 历史通通游底稿的“趣享供应商结算价”为元，而“收入”为万元；当前底稿两个字段都按万元。系统入库必须统一保存原币金额和本位币金额，页面单位只在展示层转换。

## 五、核心指标字典与计算规则

### 5.1 口径总原则

1. 金额底层按原币最小货币单位和本位币金额保存，页面可切换“元／万元”；同一公式不得混用单位。
2. 汇总毛利率、收款率、预算完成率均使用“汇总后的分子÷汇总后的分母”，禁止平均各行百分比。
3. 分母为零时显示“—”，不得显示 `#DIV/0!` 或强制显示 0%。
4. 订单、团期、应收、应付、预付和会计期间各用自己的业务日期。调整不得覆盖已发布历史结果，应形成调整记录并保留原期间。
5. “订单流水”“业务结算收入”“财务确认收入”三个指标必须分列，页面不得只写“营收”。
6. 收款、付款、发票只用于核对资金和票据，不能直接生成收入或成本。

### 5.2 指标定义

| 指标 | 业务定义与公式 | 时间口径 | 状态 |
|---|---|---|---|
| 有效订单数 | 在统计日处于财务认可有效状态的订单去重数 | 订单确认日 | 有效状态范围待确认 |
| 订单人数／商品数 | 有效订单销售内容的成人、儿童或服务数量净额 | 订单确认日 | 退订数量冲减时点待确认 |
| 订单流水 | 有效订单原成交金额＋生效增项－生效减项；取消和退款按经确认的冲减期间处理 | 订单确认日及调整生效日 | 冲减期间待确认 |
| 已分配实收 | 已被财务确认并分配到订单销售内容的收款－已解除分配金额 | 收款确认日 | 不取原始银行到账总额 |
| 订单收款率 | 汇总已分配实收÷汇总有效订单应收 | 截止日 | 分母为零显示“—” |
| 已实际回团金额 | 已有实际回团日期、但尚未完成财务结算确认的业务金额 | 实际回团日 | 金额取值待财务确认 |
| 已确认回团业务收入 | 已实际完成履约并经业务结算确认的收入＋已生效业务调整 | 实际回团日／业务确认日 | 与财务确认收入分开 |
| 财务确认收入 | 按履约义务和会计期间确认的不含税或含税收入 | 会计期间 | 各产品确认时点、总额／净额待确认 |
| 外采实际成本 | 分配到外采订单或团期的有效供应商成本＋其他直接成本＋经批准暂估／调整－已确认并分配的供应商返点 | 实际回团或成本确认期间 | 返点税务和跨期规则待确认 |
| 自营实际成本 | 自营团期实际消耗的交通、酒店、地接、领队等资源成本＋外部直接采购＋经批准暂估／调整－已确认返点 | 实际回团或成本确认期间 | 分摊规则待确认 |
| 总实际成本 | 每项有效成本只计一次；按供应方式汇总外采或自营实际成本，内部结算不得双方重复计入集团合计 | 成本确认期间 | 内部往来抵销规则待确认 |
| 业务毛利 | 已确认回团业务收入－总实际成本 | 回团／业务结算期间 | 已确定计算关系，收入成本范围待确认 |
| 业务毛利率 | 汇总业务毛利÷汇总已确认回团业务收入 | 同业务毛利 | 不允许平均行毛利率 |
| 财务毛利 | 财务确认收入－财务确认成本 | 会计期间 | 与业务毛利并列，不互相覆盖 |
| 应收余额 | 截止日全部有效应收－收款分配－预收抵扣－有效减免／核销；已撤销的分配或核销应反向恢复 | 截止日 | 退款不得与订单冲减重复扣减 |
| 逾期应收 | 应收余额中到期日早于截止日的金额 | 截止日 | 到期日规则待确认 |
| 回款率 | 截止日已分配净收款÷截止日到期应收；订单收款率可另列 | 截止日 | 是否包含未到期应收待确认 |
| 应付余额／应付未付 | 截止日有效应付－已核销付款－预付款冲抵－有效减免／核销；撤销付款或冲抵应反向恢复 | 截止日 | 付款申请不等于已付 |
| 供应商已付 | 已完成付款且回单有效、并核销到应付的金额 | 付款日 | 不取“已申请金额” |
| 团期预付款占用 | 截止日已支付且仍分配在该团期／项目、尚未冲抵应付或退回／转出的预付款余额 | 截止日 | 跨团、跨主体和跨币种规则待确认 |
| 账龄天数 | 截止日－应收或应付到期日；未到期显示 0 并单列“未到期” | 截止日 | 分段边界待确认 |
| 预算完成率 | 同期间、同组织、同口径的实际金额÷有效预算版本金额 | 预算期间 | 订单任务和回团任务分别计算 |
| 负毛利团期数 | 业务毛利小于 0 的有效团期去重数 | 回团／结算期间 | 调整单需并回原团期观察 |

建议账龄分段为“未到期、1—30 天、31—60 天、61—90 天、91—180 天、181 天以上”；这是页面方案，不是已获财务确认的规则。

## 六、第三步：页面总体架构

### 6.1 页面定位与角色

页面主入口建议放在“数据中心—经营分析—财务数据看板”。主要角色是集团管理者、总部财务、事业部财务和经营分析人员；团控、销售和采购只按权限查看其负责范围。页面只做分析和对账，不在此处发起收款、付款、成本确认、结算、开票或 NC 推送。

### 6.2 页面骨架

### 12.2 每批必须执行的质量检查

| 检查 | 规则 |

## 十三、验收场景

1. 一张自营参团游订单进入团期，实际回团后归集多项资源成本；Tab 1 部门毛利、Tab 2 团期利润和订单明细金额一致。
2. 一张外采邮轮订单使用预付款、收到供应商账单、确认返点并付款；Tab 3 可逐行复算实际成本、预付占用和应付未付，Tab 2 团期毛利引用同一结果。
3. 一个团期包含多张订单、一张订单包含两个服务内容；订单流水不重复，团期收入等于分配到该团期的订单销售内容与调整合计。
4. 一笔银行到账分配到多张订单；Tab 4 各订单已分配实收合计等于收款分配金额，不能把整笔到账重复记入每张订单。
5. 一个渠道客户跨多个账期欠款；账龄分段之和等于应收余额，截止日变化时账龄自动迁移。
6. 上年下单、本年回团、次年补成本；订单口径、回团口径和财务会计期间分别落入正确时间，历史已发布结果保留原值和调整版本。
7. 同一订单同时出现在两个来源批次；系统识别重复，只保留一条当前有效数据，并在来源核对表显示排除数量。
8. 团号、产品负责人或渠道缺失时，数据进入“待归集／待归类”而不是静默丢弃，Tab 1 来源质量与 Tab 2 明细数量一致。
9. 任意 KPI、图表、金额、订单号、团期号或表格行被点击时，不产生页面跳转、抽屉或弹窗；用户只能切换四个顶层 Tab。
10. 在同一筛选、截止时间和口径版本下，Excel 导出合计与页面一致，且文件记录完整口径信息。
