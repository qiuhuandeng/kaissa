## 本批完成范围

按清单先完成门店列表、详情、成员，以及直接关联的集团组织、任职、角色和门店审批内容。门店运营在本页维护档案、销售授权、收款与结算配置；集团组织管理员处理已有员工的归属；审批人员核对变更前后内容及生效日期。历史订单、合同、售后和资金处理继续进入原业务模块。

| 页面或流程 | 已完成内容 | 可直接查看的样例 |
|---|---|---|
| 门店管理 | 删除价格口径、库存口径及授信配置；列表保留详情、销售、财务、暂停或恢复。财务配置未生效时明确显示，不能作为当前结算安排 | 软件园门店为正常、文灶门店为待开通、观音山门店为暂停 |
| 档案、销售、财务变更 | 分开审核；展示当前资料、申请内容、原因、审核岗位、申请日期和实际生效日期。支持草稿、提交、撤回、退回重提。同类待批申请不能重复建立 | 软件园门店的销售申请审批中、财务申请已退回、负责人变更待生效；泉州丰泽门店演示晚于期望日期批准后生效 |
| 新增门店 | 先提交档案准入；可保存草稿并继续填写。档案提交不自动通过销售和财务审核，不带入其他店的账户资料和余额 | 新店列表状态为待开通，结算安排显示待财务配置生效 |
| 暂停与恢复 | 仅保留暂停、恢复。暂停时填写原因和历史业务负责人，说明新增订单和名额占用限制；恢复先检查资质及分项审核，再提交审批。账户冻结独立处理 | 泉州东海门店资质到期，不能直接申请恢复；观音山门店可以申请恢复，但仍保留账户冻结说明 |
| 门店详情 | 档案、销售与合同、收款与结算、成员、历史业务和变更记录分区。历史订单、补签、售后、账户、对账及交接入口集中展示 | 软件园门店当前负责人仍为孙丽，待生效的郑华变更仅在申请记录中显示 |
| 门店成员 | 人员身份及组织只读，入口指向集团已有员工的组织调整。本店权限申请不提前覆盖现有角色；停用本店权限需填写原因及接手人，保留历史销售归属 | 郑华可申请从店员调整为客服；申请中仍是店员；停用只撤销本店权限 |
| 集团统一组织架构 | 门店、部门入口改为调整组织归属；选择集团已有员工，核对当前和目标组织、生效日期及原因；提交、撤回不立即改变当前归属。门店员工信息改为从共同演示人员资料展示 | 从成员详情进入郑华组织调整，默认展示原组织；目标相同不能提交 |
| 任职、角色、审批 | 任职申请选择已有员工，姓名不再自由创建，手机号及工号只读。清理门店角色中的旧配置说明；审批分开档案、销售、财务、恢复及组织调整，批准结果说明何时生效 | 恢复审批明确资金冻结单独处理；未来生效申请批准后保留当前资料 |

## 验收结果

- 规则测试：7项通过。覆盖提交/撤回不覆盖当前资料、待生效及延迟批准、退回重提、防重复、恢复与冻结分离、准入与其他审核分离。
- 浏览器：18组检查通过，无页面脚本错误。Chrome，本地直接打开与随机本地端口网页服务各9组；覆盖筛选导出、申请与重提、暂停恢复、新店草稿、成员权限、组织调整、审批承接、菜单连续切换和窄屏表格。
- 桌面视图核对列表、详情、成员和组织申请；操作列固定宽度，表格内部横向滚动。390像素窄屏需使用现有按钮收起侧栏，再查看或滚动表格。
- 检查范围是本批页面及直接入口，没有将这些检查写成全站验收。

复验脚本：[规则测试](../tests/store-governance.test.cjs)、[浏览器测试](../tests/store-governance-browser.cjs)。本机截图及浏览器结果存于 `/private/tmp/caesar-store-qa/`，临时目录不作为长期项目资料。

## 原型表达边界及待确认规则

申请、撤回及停权操作用于当前页面的原型演示，刷新重新载入演示数据。审批中心使用独立样例，未建设真实审批任务同步、跨页数据回写、定时生效或员工权限服务。历史业务入口明确处理去向，本批未增加自动按门店筛选、下游凭证生成或资金执行。

占位时长与订单/合同付款条件未擅自设定，仍需业务提供规则；管理费按协议确认，付款节点由财务确认。正式准入材料、资质处理、结算安排及具体授权政策沿用16项答复中的待确认范围。价格口径、库存口径、授信、终止和新建员工均已从本期范围删除，不再交业务确认。

本批完成清单第2、3、5组基础管理原型；第1组仍有工作台旧说明待第15组一起处理；第6组完成直接入口和基础权限表达，正式审批与历史任职服务不属于静态原型任务。第4、7—15组业务页面仍按清单推进，不因本批完成而关闭。

唯一下一步：修改销售下单、订单详情和合同管理中的门店授权、占位期限、确认及发合同条件，明确暂停门店的新业务限制和历史补签入口；未确定的具体时长、付款条件继续保留待确认。
