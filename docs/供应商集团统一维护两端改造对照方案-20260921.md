## 一、业务职责与范围

集团供应商管理岗位在admin统一维护档案、资质、公司合作、协议、账期、平台费、联系人、合同生成及归档、提醒和账户资料；账户是否可付款仍由财务审核，正式准入、资料变更、协议及临时合作审批由致远承接，不进入merchant审批中心。完整维护不等于系统管理员获得审批权。

分公司采购在merchant提交新增合作、续签／变更、临时合作申请并补充材料；计调在产品、履约、请款中查看本公司可用供应商和已批准的条款。申请提交只改变申请状态，不直接创建正式供应商、协议、账户或扩大公司可见范围。

集团需查重后复用已有供应商；未获授权公司不能浏览集团供应商库。申请时录入供应商名称、登记资料，集团负责判断新建还是复用，反馈本次处理结果而不披露其他公司合同。

## 四、merchant页面具体变化

### 合作供应商列表

原“新增供应商”“临时供应商”从档案列表移除；普通查看入口仍为“详情”，合作申请页提供“新建申请”。详情内的续签／变更申请进入同一申请流程，不再直接新建协议。可给高频新申请提供明确的合作申请页入口，不复制另一套申请表单。

原列表主状态“准入状态”只反映集团档案，不能直接替代本公司合作状态。业务端用“合作状态”表达待开通、正常合作、已暂停等本公司结果；具体标签在实施时与申请及协议样例逐一核对，不用全局准入通过推导所有公司可用。地区、分类、当前有效协议及本公司负责人保留按业务取舍，不增加聚合工作待办列。

### 供应商详情

| 现有内容 | 业务端处理 |
|---|---|
| 基本资料 | 保留用于识别和核对的公开资料；原始资质文件按权限，不默认全量返回 |
| 公司合作与协议 | 改为本公司合作；只读显示有效期、适用业务、批准账期和联系人；合同原件默认不显示 |
| 联系人和服务范围 | 本公司对接信息优先，不能误用他公司联系人；修改诉求走申请 |
| 提供产品 | 保留授权产品及实际产品入口 |
| 财务资料 | 移除维护页签；请款场景继续查看经财务审核的必要账户资料 |
| 审批与变更 | 集团审批记录不在业务档案里全量展示；本公司合作申请在独立列表查看 |

### 合作申请表单

- 共用：申请公司及部门（取当前组织，不能任意选别家公司）、申请人、我方联系人、申请类型、拟合作内容、国家城市、期望合作日期、原因和附件。
- 新增合作：供应商名称、登记资料、供应商联系人及已取得资质；集团查重决定新建或复用。
- 续签／变更：选择本公司可见供应商及原协议，填写续签或变更诉求；拟议账期只作为申请意见，不直接覆盖批准条款。
- 临时合作：本次团期／业务、合作原因、使用期限、最少联系资料；不强制合同。提交生成申请单号，正式临时供应商编号由集团建立档案时生成。
- 账户／联系人资料变更：复用变更申请承载材料，不在业务端修改正式资料；账户继续转财务审核。

申请状态与协议审批状态分开。“处理中”不表示合同已批准，“已办结”需显示具体结果；不获准合作应展示原因，不能当作可用。“撤回”仅适用于未受理申请，已经送审或进入办理的变更应按处理规则提出，不擅自撤销正式审批。

## 五、开发实施说明

1. 保留现有集团维护能力，拆为集团控制脚本；merchant使用独立的只读控制脚本。公共字段展示、地区查找、账期计算可复用，管理动作不再依赖role网址参数开关。
2. 在共享样例中明确供应商档案、协议、公司合作开放记录、合作申请、审批记录。新申请保存只处理申请；集团办理再调用既有档案／协议草稿方法。保留原申请与办理结果的关联，未审批不自动开放新业务。
3. 公司信息由共享导航提供最小的当前公司上下文；本模块使用同一来源。测试参数只能作为明确的原型样例，不当登录鉴权。正式服务端授权仍为后续依赖。
4. `supplier-template-admin.js` 改为真实admin挂载入口，去掉merchant销售模板中的供应商用途编辑分支和系统通知中的供应商行注入；旧地址显示迁移提示／无维护权限，不把普通业务用户自动引到集团管理页。
5. 保留 `supplier-company-agreements.js` 与 `product-supplier-contacts.js` 的只读合同／联系能力，核对公司与供应商身份一致；不为了迁移菜单制作跨页面localStorage业务数据库。
6. `nav-admin.js` 增供应商管理分组及详情归属；`nav-merchant.js` 更新合作供应商名称、新申请入口和页签归属。复用共享样式，保持抽屉无外层卡片边框和固定操作列。
7. 原型以一致的样例编号和明确入口说明承接关系，当前页面的办理过程可演示；不宣称已完成真实跨端收件、致远回传、企微通知及账户审批接口。

## 六、实施顺序与验收

一次边界明确的两端职责改造按以下依赖完成，不拆成互相失去入口的半成品：集团维护入口与导航 → 独立合作申请及集团处理 → merchant固定公司只读 → 模板／提醒归属及角色／审批来源 → 上下游链接回归。

必验：集团新增与公司申请分离；现有供应商复用；他公司不可见；业务修改网址不能恢复编辑；申请退回补充不改主档；临时申请不提前生成重复供应商；集团归档不自动批准生效；产品联系抽屉和付款历史账期不退化；游客合同模板与其他通知不受影响；抽屉无外卡片、窄窗固定操作列。

本轮只完成代码核对及方案记录，无页面改动，未声称新方案通过浏览器验收。财务执行清单保持原8批／36项／6场景。
