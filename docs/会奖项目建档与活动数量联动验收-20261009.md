# 会奖项目建档与活动数量联动验收

日期：2026-10-09。依据用户对“单次活动／多场活动”用途的讨论及后续“执行”指令实施。本轮范围为单团项目建档、项目活动安排、关联表单和原流程回归；是可操作HTML原型，不增加后台接口。

## 一 本轮业务规则

项目由销售、项目负责人统筹客户、我方公司、整体服务期间和需求；活动由计调承接具体服务、日期、地点、人数和执行。客户确认价款继续由客户约定及原订单承接，费用和结算沿用原有办理流程。

“单次／多场”不再作为必须选择的固定项目类型。连续多日会议加旅游可以是一场，独立安排和执行的场次可以有多场；活动场数不决定订单数量，也不自动决定合同、收费或结算方式。

| 页面／步骤 | 实际改动 | 业务结果 |
|---|---|---|
| 单团项目列表 | 移除组织方式筛选和显示，保留服务期间、实际活动数及项目状态；旧筛选链接自动移除失效条件 | 不再出现“单次”标签下实际有多场的矛盾 |
| 新建项目 | 默认勾选“同时建立首场活动”，可取消 | 勾选保存项目和一场活动草稿；取消只建项目；年度也可同时建首场 |
| 编辑／核对项目 | 仅维护项目资料，取消首场执行资料的重复编辑 | 保存、提交、启用均不覆写已有活动；已有活动的修改由活动维护或变更处理 |
| 零场项目 | 建场空态，保留新增、批量录入 | 可以先建档，再补场次；无需预填年度总人数或虚构成交 |
| 一场项目 | 展示当前活动状态、日期地点、人数、计调及资料缺口，直接进入执行；收起筛选、勾选和分页 | 保留新增、复制、批量录入；未完成活动可直接分配或移交当前计调，不要求先勾选 |
| 两场及以上 | 自动增加月份、地点、计调、状态筛选，选择范围、批量分配／移交和分页 | 新增、复制或导入第二场后即可统筹，无类型转换 |
| 复制项目 | 按原复制范围复制原有各场草稿，不显示“同时建立首场活动” | 不额外多建一场，不复制原订单、名单、资源确认或客户确认结果 |

菜单保持“产品中心 → 自营产品 → 单团项目”和“履约中心 → 项目团”，本轮新增菜单0个、新增HTML页面0个。详情继续使用满宽卡片、统一页签、固定操作列与原抽屉规范；没有恢复演示身份下拉。

## 二 新建表单的联动

- 项目名称、客户单位满足草稿识别要求；提交、启用继续核对公司、部门、业务分类、服务期间、销售、项目负责人、整体范围及需求依据。
- “同时建立首场活动”仅在新建时出现。取消勾选后隐藏并停用首场字段，隐藏的人数等内容不参与保存和校验；重新勾选可继续填写。
- 首场资料为活动名称、服务类型、城市、活动开始／结束日期、计划人数、主责计调。活动名称初次沿用项目名称；未填写名称时保存沿用项目名称。日期初次沿用项目期间，每个活动字段经手动修改后不再随项目字段变化。
- 例如项目期间为2026全年，首场可以填写10月20日至21日；不会把年度期间强制写成该场执行日期。新建首场检查日期顺序及已填写的项目期间，人数可留空，填写时必须为正整数。
- 首场无论随项目保存还是提交，均是活动草稿；启用项目不自动确认执行或生成客户订单。名单要求、客户约定、确认依据和后续执行继续在活动内维护。
- 项目编辑不再读取、写入首场名称、城市、人数、日期、计调和服务类型。已有客户订单的签约客户／我方公司保护继续保留。
- 一场时的分配／移交直接使用当前活动；多场使用已勾选范围。完成／取消的历史负责人继续保留，移交只更新负责人及分工记录，不改变执行状态。

旧记录中保存过的组织方式不再被界面、筛选或校验读取；不清空用户已有项目、活动或关联单据。客户约定的覆盖场次和计价、服务类型的执行分区、名单要求、费用所属范围继续各自决定后续表单。
