## 一、业务人员先看这一页

采购公司是实际向该同行采购、承担本笔结算责任的集团公司；集团其他公司不因同属集团就自动承担付款。同行的订单人员、结算人员、票据人员可以由同一人兼任，但系统中处理的业务动作不同。

| 顺序／分支 | 谁操作、从哪里进 | 做什么 | 下一步交给谁、带什么 |
|---|---|---|---|
| 1 采购确认 | 供应商订单人员：订单确认 → 本采购单 → 回复 | 确认数量、价格和确认号；有补差、取消损失则单列申报 | 原条件确认交我方计调；变更报价交计调认可，未认可不能当最终成本 |
| 2 服务依据 | 我方计调：履约中心 → 团期结算 → 供应商对账 → 采购依据 | 核实际服务数量、增加／减免及依据；认可或退回供应商补差 | 形成可核对费用，供双方对账使用 |
| 3A 供应商先报 | 供应商结算人员：对账结算 → 提交账单 | 直接选已确认采购费用，填账单金额和材料；已有对账则匹配原单 | 交采购公司计调，状态“待采购公司核对”；不必等我方先建对账 |
| 3B 我方先发 | 我方计调：供应商对账 → 新建对账 | 选择公司、供应商及费用，核对后提交 | 交供应商结算人员，状态“待供应商确认” |
| 4 核金额／处理差异 | 计调核供应商来单；供应商核我方发单，均在原对账单办理 | 相同金额确认；不同金额逐项写原因、处理并重新提交 | 原金额全获认可，形成双方确认；改过金额必须交另一方确认新版；材料不足退原提交人补充 |
| 5 对账完成 | 双方同一版、同一明细和金额均已认可 | 状态为“双方已确认”，保留旧账单、异议及处理依据 | 交采购公司财务应付岗；这是“账对完”，还不等于付款或发票完成 |
| 6 财务与请款 | 财务 → 成本应付 → 供应商账单／应付管理／预付管理；业务付款申请走原工作区 | 核原应付、预付冲抵、实际已付和可申请，复核付款条件 | 按获批流程交审批人。业务申请的本单带入和复核顺序限制见下文，不能演示成一键连续完成 |
| 7 付款 | 获授权审批人审批；资金岗：财务 → 成本应付 → 付款执行 | 核账户，执行已获批付款，登记成功／失败；失败可重试 | 实际付款结果供财务及供应商核对，成功才计已付；审批通过不是已付款 |
| 8 发票 | 供应商：原对账详情提交／补正材料；我方：财务 → 资金票据 → 发票管理 | 发票岗核验或退回；供应商在原任务补正重提，保留历史 | 补正重提交采购公司发票岗；上传材料不是核验通过。票与款的先后由公司政策决定 |
| 9 退款异常 | 供应商：原对账详情提交退款凭据；我方资金岗：付款退回 → 核对 | 按原付款及预付／应付核实际到账，支持部分到账 | 到账后交应付岗核余额、核算岗处理凭证；供应商承诺或上传凭据不是我方到账 |

两条发起路径最终汇入同一对账单：**供应商先报 → 计调核对**，或 **计调先发 → 供应商核对**。采购订单先于对账存在；同一费用不能因两边都提交就产生两笔成本。

金额核对示例：双方应结101,000，减已冲抵预付30,000、尾款实付50,000，未付21,000；其中已有付款占用10,000，尚可申请11,000。票据核验、付款申请占用、实际付款分别记录。

## 四、业务与财务待确认规则

| 待确认事项 | 建议由谁确定 | 对当前原型的影响 |
|---|---|---|
| 计调提交付款后，先业务审批还是先财务复核再送审；退回由谁重提 | 业务负责人、财务负责人及审批管理员 | 旧业务申请目前直接显示审批中，新款票样例为财务复核后提交审批，顺序应统一；不能默认二者是同一连续记录 |
| 各公司／供应商先票后款、先款后票及紧急例外 | 公司财务、采购负责人 | 本例先款后票只是演示，不能成为全集团默认政策 |
| 行前预付、账期、分期节点与最终结算尾款条件 | 公司财务、采购／计调负责人 | 两方均可先报账已明确；采购未确认或服务未完成时，哪些款项可申请仍依付款节点 |
| 跨公司代付、冲抵及到账公司范围 | 集团与公司财务 | 当前不同公司不能直接混冲；集团关系不等于已获代付批准 |
| 结算后增减、客户退款涉及供应商责任的确认人及期间 | 业务负责人、公司财务 | 客户退多少不代表供应商必须退多少；原账保护继续有效 |
| 公司岗位兼任与正式数据可见范围 | 业务负责人及权限管理员 | 当前角色动作在原型中区分，尚未接真实员工及权限 |

原型不要求真实银行、税控、后台文件、集团核算系统或跨端自动回写。上述生产依赖不是本轮三项原型缺口，也不是继续做单页承接的阻塞理由。
