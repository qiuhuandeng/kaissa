# 标准跟团自营链路复盘与开发验收

日期：2026-09-16。状态：样板现状审计已完成；规则评审及开发验收尚未完成。

本文件是本轮样板的交付附件，问题状态仍统一维护在《财务要求—现有功能—缺口—修改对照表》，财务政策仍统一维护在《待确认问题决策表》，续做位置仍以《业财报表自动化改造进度》第三、四节为准。

## 一、本轮结论与边界

同一公司自营标准跟团的主要页面入口已经具备。当前交付风险主要在跨岗位交接、金额依据和状态解释，不能用“有页面、有按钮”判断开发就绪。本轮确认七组需要修正的原型表达问题，以及一组尚需确认的订单与签约条件，详见TG-01至TG-08。

已经补过的能力应保留：下单记录真实创建/确认时间及销售归属；实际回团记录日期、依据、确认人和更正历史；团期结算已经有二次结算相关处理。旧审计中“实际回团没有记录”等结论不再作为当前缺口直接交给开发。

本轮只检查：同一公司签约、销售、履约、收付款的自营标准跟团，人民币结算，正常业务、部分退款、供应商费用变更、付款失败与重试、回团结算后补成本。自营团向外部供应商购买地接、酒店等资源，仍属于本样板；整包外采产品、多公司互供及代收、同公司部门分成另做样板。

未修改页面、导航或生产代码，未删除或移动文档，未启动财务管理页面整体方案。团期订单独立入口、并行门店工作线及一期排除范围保持原约定。

核对方法：读取必读控制资料；盘点目录、导航和相关共享脚本；按下面路径核对页面源码与流程文档相关章节；复核文档引用；运行已有订单规则检查及独立金额演算。没有把相关文档全部章节定级，也没有验证生产仓库。

浏览器验收未执行：本地HTML地址被浏览器安全策略拒绝访问。本轮未通过其他地址或自动化方式绕过。下文“源码确认”不等于已点击验证。

## 二、正常业务的岗位交接与页面路径

应收表示客户按约定尚应承担的付款义务，应付表示公司对供应商已经确认的付款义务；预付表示先付给供应商、尚待抵扣相应应付的款项。业务成本与财务确认计入某个会计期间的成本分别记录；会计期间是财务记账所属的月份等期间。集团财务核算系统在现有页面中简称NC。

下面是本样板的核对路径，不要求原型各页共享实时数据。页面路径能定位不等于所有按钮和目标数据已验收。

| 环节、主要角色 | 上游与当次任务 | 当前入口 | 必须交给下一岗位的结果 | 本轮判断 |
|---|---|---|---|---|
| 产品，产品经理 | 供应商资源、线路方案进入可售产品 | `merchant/product/products.html`、`product-self-edit.html`、`products-detail.html` | 线路/方案、经营公司、供应方式；具体日期价格与名额交团期 | 已有产品到团期入口，未全量验产品字段 |
| 团期，计调/团控 | 按产品创建出发与返回安排、售价、名额和资源确认条件 | `merchant/product/product-schedules.html` → `merchant/tour/schedules-detail.html`；履约主入口 `schedules.html` | 可售团期、剩余名额、确认方式、报名及材料截止；交销售下单 | 入口已核对，库存并发不是静态页验收范围 |
| 下单，销售 | 选择团期，核对游客、联系人、价格、销售归属与资源条件 | `merchant/sales/booking.html` → `orders.html`、`orders-detail.html` | 订单号、公司、团期号、人数、约定金额、当前状态、收款计划、归属记录 | 创建/确认时间及归属有记录；付款与保留时限未获统一批准，见TG-08 |
| 合同，销售/合同审核人 | 根据本单适用条件生成、审核及签署合同 | `merchant/sales/contracts.html` | 合同版本、签约公司、签署人、签署结果；失败/撤回记录 | 合同页使用条件检查脚本；不能把“先签还是先收”写成所有订单统一规则 |
| 收款，销售→收款会计 | 销售提供到账依据并申请认款，财务确认款项属于哪笔订单 | `merchant/sales/payment-claim.html` → `merchant/finance/receipts.html`、`finance-matching.html`、`finance-receivable.html` | 原到账流水、认款分配、确认人/日期、本次金额、累计已收及未收 | 销售提交进入待复核；未证明所有收款页已共用正式记录 |
| 履约，计调 | 按团期核对名单、资源、执行结果与实际回团 | `merchant/tour/schedules-detail.html`；独立 `schedule-orders.html`；`fulfillment-roster.html` | 实际完成日期、依据、确认人、游客及资源差异；成本与结算后续承接 | 回团事实及更正历史已存在，不重做；不能用计划返回日替代实际完成 |
| 成本与账单，计调→应付会计 | 业务确认供应商费用，财务核对供应商账单 | `merchant/tour/fulfillment-cost.html` → `merchant/finance/finance-supplier-bills.html`、`finance-payable.html` | 同一费用的业务依据、供应商账单、确认金额、差异及已形成的应付 | 账单挂接会覆盖成本比较值，见TG-02；不能因收到又一份凭据再记一次成本 |
| 预付与付款，业务申请→审批→出纳 | 按合同支付预付款；应付确认后抵扣预付款并支付余款 | `merchant/tour/fulfillment-payment-apply.html`；财务 `finance-payment-apply.html`、`finance-payment.html`、`finance-prepayment-offset.html`、`finance-remittance.html` | 审批结果、每次执行、实际支付结果、预付抵扣、未付余额及回单 | 预付可发生在最终账单/结算前；付款完成条件与失败历史见TG-04/05 |
| 业务结算，计调→结算会计 | 汇集实际完成、订单变化、收入依据与成本，确认本团经营结果 | `merchant/tour/fulfillment-cost.html` → `merchant/finance/finance-settlement.html`、`finance-settlement-adjustment.html` | 原结算及后续调整、原因、责任人；未决项交回原岗位 | 收款明细仍由团期总数按比例拆出，见TG-01；已有二次结算不能当完全缺失 |
| 核算与报表，核算会计→经营财务 | 按批准制度确认收入成本、凭证及期间，并按同一范围核对报表 | 财务 `finance-invoice.html`、`finance-nc.html`、`finance-period-close.html`；数据中心菜单及 `shared/report-pages.js` | 每项金额对应业务依据、财务确认和期间；资金、经营结果、会计结果分开解释 | 不能以业务结算、开票或付款替代核算确认；核算独立页面方案未实施；见TG-06/07 |

合同、收款和资源确认的先后应遵循本单已批准条件，不能机械地照上表行号串行执行。付款也不必等回团结算才发生。正常业务说明必须同时表达这些并行和前置关系。
