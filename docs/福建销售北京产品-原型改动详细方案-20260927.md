# 集团内跨主体销售：原型改动收敛方案

日期：2026-09-27。实施状态：用户已授权第四节P0到P1依次实施。P0-1产品市场完成，见[验收记录](产品市场跨主体条件按需显示实施验收-20260927.md)；P0-2预订页完成，见[预订页跨主体关系与确认分流实施验收](预订页跨主体关系与确认分流实施验收-20260927.md)；P0-3订单列表完成，见[订单列表跨主体筛选与弱提示实施验收](订单列表跨主体筛选与弱提示实施验收-20260927.md)；P0-4订单详情关系及只读对账关联入口完成，见[订单详情跨主体关系与对账关联实施验收](订单详情跨主体关系与对账关联实施验收-20260927.md)，实际对账办理页按P1-1实施；P0-5团期订单履约承接完成，见[团期订单跨主体履约承接实施验收](团期订单跨主体履约承接实施验收-20260927.md)；P1-1公司间对账完成，P0-4只读关联入口已升级为实际财务页入口，见[公司间对账特殊场景实施验收](公司间对账特殊场景实施验收-20260927.md)；下一步P1-2节点和权限。下文为范围依据，原方案中的未实施说明仅指当时状态。

## 一、先确定范围

主流场景仍是“本公司销售本公司自营产品”。跨主体销售只是需要支持的特殊场景，不能让所有订单都变成多主体订单。

本方案分三种订单：

| 类型 | 示例 | 列表处理 |
|---|---|---|
| 本公司自营 | 福建销售福建自营产品 | 沿用现有订单列表和字段，不显示跨主体字段 |
| 本公司外采 | 福建销售体系外供应商产品 | 沿用现有外采／采购状态和供应商信息，不生成集团内部往来 |
| 集团内跨主体 | 福建销售北京产品，或北京销售福建产品 | 只对这类订单增加跨主体标识、详情关系和公司间结算入口 |

福建销售北京产品只是第三类的一个演示样例，不能据此把福建固定成销售方、北京固定成产品方。

## 二、订单列表应该怎么改

### 1. 默认列表保持现状

自营订单仍按销售人员每天使用的字段展示：

- 订单号；
- 客户；
- 产品／线路；
- 出行日期；
- 销售渠道、门店或销售组；
- 订单主状态；
- 收款状态；
- 操作。

不把“销售方、产品方、履约方、签约方、我方角色、交易对手”等字段全部加入一级列表。多数订单没有这些跨主体关系，强行展示只会增加理解和操作成本。

### 2. 跨主体订单只增加一个轻量提示

订单列表增加一个可选筛选：“来源类型（自营／集团内跨主体／体系外外采）”；需要时再按“跨主体订单”筛选。对于确实跨主体的订单，在已有产品或来源信息旁显示弱提示，例如：

“跨主体：产品由北京公司提供”

或：

“跨主体：北京销售／福建履约”

不建议把所有关系拆成六个固定列。用户点击订单详情后，再查看完整关系。

列表可以增加一个“业务关系”筛选项，但不默认增加“我方角色”列。需要集团财务或特殊岗位分析时，再通过筛选或详情查看销售方、产品方和履约方。

### 3. 右上角节点只负责范围

右上角切换公司／部门后：

- 自营订单：按当前公司、门店、人员权限显示原有订单；
- 本公司外采订单：显示本公司销售和外部供应商信息；
- 跨主体订单：当前公司只有参与该订单且有权限时才显示，进入详情后按本公司在本单中的实际角色显示字段和动作。

福建和北京不建立两套订单列表，也不在列表里固定写“福建销售视角”“北京供货视角”。

## 三、确认规则仍按产品和团期决定

是否需要人工确认，不由公司名称决定：

| 产品／团期条件 | 结果 |
|---|---|
| 余位实时可售、授权和价格有效 | 正常提交，直接进入履约 |
| 标记下单后二次确认或资源不实时 | 进入待资源确认，由实际履约方处理 |
| 超授权、补差、人数超额或退改例外 | 进入异常／审批 |

这条规则同时适用于“福建销售北京产品”和“北京销售福建产品”。不新增“提交北京确认”或“提交福建确认”这类公司专属按钮。

## 四、页面改动方案

### P0-1 产品市场：跨主体条件按需显示

页面：merchant/product/product-market.html。

产品卡仍以产品名称、销售状态、确认方式和销售规则为主。只有产品属于集团内跨主体共享时，采用抽屉才显示：

- 产品提供公司；
- 可销售公司；
- 实际履约方；
- 内部结算方式和结算价；
- 退改责任；
- 有效期。

本公司自营产品不显示这些字段。体系外供应商产品继续使用现有供应商／外采表达，不和集团内公司混成一个来源。

### P0-2 预订页：只有特殊订单显示关系区

页面：merchant/sales/booking.html。

正常自营订单保持现有预订流程。只有选择了跨主体产品时，才显示“跨主体业务关系”摘要：

- 当前销售公司；
- 产品提供公司；
- 履约方；
- 签约／收款主体；
- 内部结算价（仅授权岗位）；
- 资源确认方式。

提交按钮仍是保存草稿、提交订单。产品实时可售就正常提交，需要二次确认才进入待确认。

### P0-3 订单列表：主列表不重构

页面：merchant/sales/orders.html。

只做三项小改：

1. 增加“来源类型”筛选，并提供“仅看集团内跨主体”条件；
2. 跨主体订单在产品或来源单元格增加一行弱提示；
3. 操作列继续以订单主状态为准，不增加公司间对账、供货确认等复杂动作。

自营订单的显示、排序、操作和字段不因本次特殊场景改变。

### P0-4 订单详情：条件展示完整关系

页面：merchant/sales/orders-detail.html。

普通自营订单继续显示现有销售、收款、履约内容。只有跨主体订单增加“跨主体业务关系”区，内容包括：

- 销售方；
- 产品方；
- 履约方；
- 签约／收款方；
- 当前节点在本单中的角色；
- 交易对手；
- 内部结算状态；
- 公司间对账入口。

如果订单没有跨主体关系，整个区域不出现，避免给普通订单增加空字段。

### P0-5 团期和履约页面：仅承接有关系的订单

页面：merchant/tour/schedule-orders.html、merchant/tour/schedule-orders-detail.html。

团期页面继续以实际履约工作为主。跨主体订单进入时，显示来源销售公司和关联订单；本公司自营订单不增加“来源销售方、产品方、交易对手”等额外字段。

实际履约方处理资源、名单、补差和执行结果；销售方不能修改履约方资源或另一主体的对客成交价。

### P1-1 公司间对账页：特殊场景入口

新增：merchant/finance/finance-intercompany-reconciliation.html。

它只承接真实发生集团内采购、供货、代收或佣金关系的订单。入口从跨主体订单详情和财务结算模块进入，不要求普通自营订单经过此页面。

对账明细显示我方主体、交易对方、关联订单、结算金额、增减项、已收／已付、未收／未付、差异和双方确认状态。自营订单不生成内部对账记录。

### P1-2 节点和权限

右上角节点切换继续作为公司／部门工作范围。权限判断顺序是：

1. 当前用户是否有该公司／部门范围；
2. 当前订单是否与该节点有关；
3. 当前岗位是否有对应字段和动作权限。

节点切换不把普通销售变成集团财务，也不让无关公司看到客户资料。

## 五、优先级收敛

**必须改：**

- 保持自营订单列表不变；
- 跨主体订单有明确来源提示；
- 跨主体订单详情能看到销售方、产品方、履约方和结算关系；
- 需要二次确认时由实际履约方处理；
- 跨主体订单能进入公司间对账。

**可选增强：**

- 跨主体订单筛选；
- 集团财务按销售方／产品方分析；
- 北京销售福建产品的反向演示；
- 多公司复杂代销和自动抵销。

**暂不改：**

- 全量订单增加多主体字段；
- 把所有订单改成动态角色列表；
- 自动库存同步、银行接口、NC接口。

## 六、验收场景

| 场景 | 结果 |
|---|---|
| 福建自营产品 | 列表和详情保持现有流程，不出现跨主体字段 |
| 福建外采外部供应商产品 | 显示现有供应商／采购信息，不生成集团内部往来 |
| 福建销售北京产品 | 列表只有跨主体提示，详情显示完整关系并可进入对账 |
| 北京销售福建产品 | 同样使用跨主体提示，详情中的销售方和产品方按实际关系显示 |
| 同公司销售和产品 | 不生成内部采购应付 |
| 实时可售 | 不进入公司专属人工确认 |
| 需要二次确认 | 由实际履约方处理 |

## 七、结论

你指出的问题成立：之前把特殊场景的关系字段放到了所有订单列表，改动过度。现在收敛为：

**主流自营流程保持原型稳定；跨主体销售只在相关订单上出现提示、详情关系和公司间对账入口。**

本轮仍未修改 HTML、共享脚本或正式权限。


## 八、从下单到对账的完整页面承接

上一节说明了跨主体特殊场景。本节把主流自营、体系外外采和集团内跨主体三条路径放在同一条链路里，明确每一步应该改哪个原型页面。

### 1. 产品和团期可售

页面：merchant/product/product-market.html、merchant/product/product-schedules.html、merchant/product/product-outsource-list.html、merchant/product/product-outsource-detail.html。

所有产品都要能看见产品名称、销售状态、适用渠道、出行日期／团期、余位、价格和资源确认方式。

只有集团内跨主体产品才出现产品提供公司、可销售公司、实际履约方、内部结算方式、内部结算价和退改责任。体系外外采继续显示供应商和采购信息；本公司自营产品不出现公司间字段。

确认方式分为实时可售、下单后二次确认、例外需审批。确认方式决定后续路径，不由福建或北京公司名称决定。

### 2. 下单和意向承接

页面：merchant/sales/booking.html、merchant/sales/orders-intent.html。

普通自营产品沿用现有流程：选择客户、产品、团期、人数和成交价，保存草稿或提交订单。

只有选择集团内跨主体产品时，预订页才显示“跨主体业务关系”摘要：

- 当前销售公司；
- 产品提供公司；
- 履约方；
- 签约／收款主体；
- 内部结算价；
- 资源确认方式。

不增加“提交北京确认”或“提交福建确认”按钮。实时可售产品正常提交；需要二次确认的产品进入资源待确认；例外进入审批或异常处理。

### 3. 订单列表和订单详情

页面：merchant/sales/orders.html、merchant/sales/orders-detail.html。

订单列表保持现有自营字段：订单号、客户、产品、日期、渠道／门店、订单主状态、收款状态和操作。

新增最小能力：

- 来源类型筛选：本公司自营、集团内跨主体、体系外外采；
- 仅看集团内跨主体的筛选条件；
- 特殊订单在产品或来源信息处显示一行弱提示。

不把销售方、产品方、履约方、交易对手等关系字段全部加入一级列表。操作列不增加供货确认、公司间对账和付款等复杂动作。

订单详情全部订单都显示客户、产品、日期、订单状态、对客金额、收款状态、合同和履约入口。只有跨主体订单增加“跨主体业务关系”区域，显示销售方、产品方、履约方、签约／收款方、当前节点角色、交易对手、内部结算状态和对账入口。自营订单和体系外外采订单不显示空的跨主体区域。

### 4. 合同、客户收款和认款

页面：merchant/sales/contracts.html、merchant/sales/payment-claim.html、merchant/finance/finance-receivable.html、merchant/finance/receipts.html、merchant/finance/finance-advance-receipts.html。

需要区分：

- 对客签约主体；
- 客户应收；
- 已收；
- 待认款；
- 退款和转款；
- 收款渠道及到账依据。

客户已付不等于销售公司已付产品方，也不等于供应商已收。实收、认款、内部付款和供应商付款分别显示。

必须校验实收大于应收、凭证不等于到账、待认款被误算已收、退款超可退金额以及预收预付重复抵扣。

### 5. 资源确认、名单和履约

页面：merchant/tour/schedules.html、merchant/tour/schedules-detail.html、merchant/tour/schedule-orders.html、merchant/tour/schedule-orders-detail.html、merchant/tour/fulfillment-roster.html、merchant/tour/resource-procurement-inventory.html。

团期和履约页面继续以实际履约工作为主：

- 实时可售订单直接进入履约；
- 二次确认订单显示确认数量、确认号、保留截止、补差或无位原因；
- 维护名单、交通、酒店、服务确认和执行结果；
- 跨主体订单显示关联销售订单；
- 自营订单不增加多主体字段。

资源状态与订单状态分开表达：待确认、已确认、无位、补差待确认、已取消。提交订单不能直接等于资源已确认。

### 6. 售后、退款和转款

页面：merchant/sales/orders-after-sales.html、merchant/sales/orders-refund.html、merchant/sales/orders-transfer.html、merchant/finance/finance-refund-execute.html、merchant/finance/finance-refund-transfer.html、merchant/finance/finance-settlement-adjustment.html。

售后详情增加：

- 客户应退；
- 实际退款；
- 产品方／供应商可退；
- 资源损失或补差；
- 是否影响本公司结算；
- 是否影响公司间或供应商对账；
- 已生成的调整记录。

客户退款不能直接复制为产品方应退；销售优惠也不能自动减少另一主体的结算价。发生变化时生成调整记录，回到对应结算或对账页面。

### 7. 业务结算和成本确认

页面：merchant/finance/finance-settlement.html、merchant/finance/finance-settlement-detail.html、merchant/tour/fulfillment-cost.html。

业务结算确认：

- 实际出行人数；
- 已完成服务；
- 客户收入；
- 产品成本；
- 供应商成本；
- 增减项；
- 毛利依据；
- 结算资料缺口。

业务结算不代替公司间对账，也不代替供应商对账。自营订单只处理本公司业务结算；体系外外采订单继续进入供应商账单；集团内跨主体订单才增加公司间结算关系。

### 8. 集团内公司间对账

建议新增页面：merchant/finance/finance-intercompany-reconciliation.html。

只有订单真实发生集团内采购、供货、代收或佣金关系时才进入。入口来自跨主体订单详情和财务结算模块，普通自营订单不经过这里。

列表显示：

- 对账单号；
- 我方公司；
- 对方公司；
- 关联订单／团期数；
- 应结金额；
- 已收／已付；
- 未收／未付；
- 差异；
- 主状态；
- 操作。

明细显示业务关联号、双方主体和关系、协议价、数量、增减项、双方记录金额、已确认预付冲抵、实际付款／收款、未结余额、差异原因、双方确认人和版本。

状态为草稿、待对方确认、差异中、待财务复核、已确认、已作废。申请中的付款不算实际付款，预付冲抵不能重复扣减。确认对账不直接生成客户收款、供应商付款或收入。

### 9. 体系外供应商对账

页面：merchant/finance/finance-supplier-bills.html、merchant/tour/fulfillment-supplier-fees.html、merchant/finance/finance-payable.html，以及现有 supplier 页面。

供应商对账处理本公司与外部酒店、地接、车队或同行供应商的账单、实际服务、预付、应付、付款和发票。北京公司与外部供应商的账不转给福建门店处理；福建直接采购时才由福建承担该段对账。

### 10. 付款、收款核销和发票

页面：merchant/finance/finance-payment-apply.html、merchant/finance/finance-payment-management.html、merchant/finance/finance-payment.html、merchant/finance/finance-receivable.html、merchant/finance/finance-remittance.html、merchant/finance/finance-invoice.html、merchant/finance/finance-matching.html。

规则：

- 对账确认后才能进入相应付款申请；
- 实际付款才增加已付；
- 收款认领与应收核销分开；
- 发票与付款、收款分别展示；
- 列表不重复办理付款和核销；
- 客户收款、公司间付款、供应商付款分别核算。

## 九、状态和入口约束

每个业务列表只保留一个主状态。订单主状态不被资源、收款、结算或对账状态替代。

- 订单：草稿、待确认、已确认、履约中、已完成、已取消；
- 资源：待确认、已确认、无位、补差；
- 收款：未收、部分收款、已收、待认款；
- 结算：待结算、结算中、已结算；
- 对账：未生成、待确认、差异中、已确认；
- 付款：未申请、审批中、已付款、已核销。

客户订单在订单详情处理，资源在团期详情处理，公司间对账在公司间对账页处理，供应商账单在供应商对账页处理，付款在付款页处理。一个动作只保留一个主办理入口。

## 十、改动优先级

### P0 必须改

- 产品和团期确认方式明确；
- 普通自营订单列表保持稳定；
- 跨主体订单才显示关系提示和详情关系；
- 订单详情能承接合同、收款、履约和售后；
- 资源确认、收款、结算、对账和付款状态分开；
- 跨主体订单有公司间对账入口；
- 外采订单有供应商对账入口；
- 直营、加盟、呼叫中心按真实合作关系分流。

### P1 建议改

- 售后影响公司间或供应商结算的提示；
- 业务结算与对账单反查；
- 集团财务按销售方、产品方、履约方查询；
- 同一业务关联号贯穿订单、团期、结算和对账；
- 预付、实付、冲抵和未付分开显示。

### P2 可后补

- 自动库存同步；
- 自动催办；
- 自动集团抵销；
- 银行直连；
- NC接口；
- 复杂代销自动判断；
- 多公司批量分摊。

## 十一、端到端验收场景

| 场景 | 预期结果 |
|---|---|
| 本公司销售本公司自营产品 | 订单流程保持现有结构，不出现跨主体字段和公司间对账 |
| 本公司销售体系外外采产品 | 进入供应商确认、供应商账单和供应商付款 |
| 福建销售北京产品 | 列表出现特殊提示，详情显示关系，履约和公司间对账可承接 |
| 北京销售福建产品 | 同一规则反向成立，销售方和产品方按实际关系显示 |
| 同公司销售和产品 | 不生成内部采购应付 |
| 实时可售 | 提交后直接进入履约 |
| 需要二次确认 | 实际履约方处理确认、无位或补差 |
| 客户已收但内部未付款 | 客户实收与内部未付同时显示 |
| 对账金额不一致 | 显示差异，不能直接结清 |
| 客户退款与供应商扣损不同 | 三段金额分别记录，不复制退款金额 |
| 直营门店 | 核销售、收款和业绩，不产生门店向本公司的法人采购 |
| 加盟门店 | 按代收、佣金、预存或独立采购模式处理 |
