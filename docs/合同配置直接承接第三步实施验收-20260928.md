# 合同配置直接承接：第三步实施验收

日期：2026-09-28。依据：用户“执行”及[全流程职责重审方案](合同配置全流程职责与页面归属重审方案-20260928.md)第3步。本步验证集团配置如何进入产品选模、合同准备、审批及签署，交付范围仍是可操作原型。

## 一、角色和流程

集团合同管理员维护正文和公司规则，实施人员维护ERP取值，技术管理员维护模板对外对应及公司平台授权。产品人员默认沿用公司规则，必要时指定一份适用模板；销售从具体订单进入合同准备，核对资料、客户选择和签署关系。审批人核对本次提交的全文；通过后由销售发起签署或按获准渠道办理。

流程为：实际签约公司与订单场景 → 唯一有效公司规则／产品指定模板 → 本份合同资料与客户选择 → 完整预览 → 内部审核或规则免审 → 待签署 → 各必要方及我方完成 → 监管及文件归档。合同签完不等于款项已收、退款已付或财务处理完成。

## 三、页面之外的规则

1. **先确定资格和规则，再准备具体内容。** 继承模式必须匹配一条当前公司、业务、客户类型及旅游范围的有效规则；省级场景进一步检查省份与天数。无规则或多规则不能任取一条。指定模板仍受公司授权、规则政策、模板启用及适用条件约束。
2. **只检查本次签约公司的办理条件。** 福建公司不能借北京的模板或印章，北京也不能借福建的授权。模板同时适用多家公司时，其他公司的缺授权不应阻断已获准的本次公司；但集团发布模板时仍核对全部拟适用公司。
3. **准备页采用模板实际配置。** 金额、公司、名单从限定来源取值；固定条款不可在本单覆盖；客户选择由经办人在本次填写。新增自定义项按模板要求出现输入框，必填只填空格也不通过。字段来源错误交集团实施人员，订单资料不足回订单核对，客户选择留在合同准备补齐。
4. **版本按办理阶段保护。** 草稿保存采用的模板正文、字段要求、规则及资料版本。发现当前有效配置变更时，由经办人明确更新后重新核对，不能静默替换。送审、待签与已签内容使用提交时全文；新模板或产品资料不覆盖它。实际公司授权仍在发起前复核。退回修改重新走配置检查和预览。
5. **内部审核与签署分开。** 需要审核的合同通过后才待签；明确免审的规则直接进入待签。两者都需另行发起签署，不能用内部审批通过代替客户签名、我方章或监管结果。
6. **分签不重复计费。** 必须使用订单已确认的逐人分配，缺分配不得临时平均拆价。每份的正文金额、费用附件、覆盖人和必要签署范围一致，不能把订单总额复制到每份。共用监护材料可以引用，但本份代表范围只列本份人员。
7. **后续处理仍有明确责任。** 授权、印章或渠道缺配置由技术／平台授权管理员处理；无规则、冲突或模板不适用由集团合同管理员处理；客户选择、授权材料或服务资料缺失由相应业务人员补齐。受理超时先查询原申请，明确未受理才重提；监管失败不抹去已签事实。
8. **企业场景保持资格门槛。** 原企业电子合同样例不再以“模板已支持”绕过集团草稿模板和规则缺失。补齐代表资料不能使未启用模板可送审、可签署；仍可演示企业代表与授权资料维护，原企业线下归档路径保持。

## 四、原型与正式开发的边界

- 出境正常样例使用当前启用公司规则；其他具名旅游场景订单带有明确的“此演示订单已确认签约条件样例”，用于独立验收邮轮、研学、省级等表单。该样例不自动启用集团草稿规则，不作为陌生订单的兜底政策。没有真实公司政策的正式订单必须等待配置确认。
- 原型读取同一套字段定义和当前页配置，并沿用当前合同办理组的临时会话交接。产品、集团设置与合同页面之间没有新增全局保存、自动回写或后台同步。
- 正式开发需持久保存每份采用的模板版本、规则、确认资料、客户确认依据和签署文件，并由后台核对公司与岗位权限。真实平台参数、身份验证、获准文本、文件限制及公司政策依据仍须正式资料，不能把原型样例当作接口协议或已获客户同意。
- 新增 `shared/contract-template-bridge.js` 为原型取值及匹配共用逻辑；技术说明中的 `templateSnapshot`、`sourceSnapshot` 分别表示“生成本份时保留的模板内容”和“当时采用的确认资料”。它们服务版本保护，不表示新增财务处理或生产数据库设计。

## 六、收尾与下一步

第3步完成，职责重审方案三个步骤的原型均完成。下一步由业务按现有场景试用并反馈，按具体问题修订，不另开“真实接口联调”作为原型未完步骤。

正式获准正文、公司政策、平台协议及生产权限仍在正式实施时核实。它们不等于本轮原型遗漏，也不能据本轮样例宣称已接通12301。
