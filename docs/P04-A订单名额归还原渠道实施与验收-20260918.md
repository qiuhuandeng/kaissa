# P04-A 订单名额归还原渠道实施与验收

日期：2026-09-18  
菜单：履约中心 → 团期管控 → 详情 → 价格名额  
页面：[团期详情](../merchant/tour/schedules-detail.html)  
范围：主方案P04中的名额释放、核心项核03中的团控处理部分。

## 一、业务位置与边界

团控在团期详情中根据原订单占用和售后依据释放名额。释放结果只回到原渠道；渠道间重新分配暂不在本页处理。订单名额释放不等于退还采购资源，本次不会修改采购座位、舱房、铺位、已付款或销售售后单。

2026-09-18后续调整：经页面核对，“渠道价格与名额”的原“调整”按钮实际只改变同步提示，不能维护价格、名额或售卖状态。按用户要求暂时隐藏整个操作列，保留价格、名额、已售／余量、停售时间和同步状态用于查看；正式调整能力后续另行实现。

## 二、原能力、修改与结果

| 业务要求 | 原能力与问题 | 本次修改 | 当前结果 |
|---|---|---|---|
| 按原占用逐笔释放 | 原确认框从列表整行提取人数，无法区分订单、渠道和多笔占用 | 原“释放”按钮直接打开当前页处理抽屉，列出原订单、占用记录、原渠道、单位、原占用、已释放和剩余占用 | 可选择一笔或多笔，逐笔填写本次量和原因 |
| 数量必须真实且不能重复 | 原逻辑直接执行团期可用量加整行数量 | 正整数、剩余上限和原因在提交时统一校验；成功后按记录累计，团期已售／余量和渠道占用／余量均由明细重新计算 | 部分释放可继续处理；全部释放后只保留查看；重复点击不会再次增加 |
| 必须归还原渠道 | 原页面只更新团期总余量，未更新渠道结果 | 每条明细固定原渠道且不可改；代理10、占用6、可用4作为独立样例 | 释放2后代理占用4、可用6；直营不变 |
| 停售渠道不自动转库存 | 原页面无法表达释放渠道状态 | 代理样例保持“停售”，释放结果仍累计到代理可用量 | 停售状态保持，未转成直营或全渠道 |
| 不占用游客不能多释放资源单位 | 邮轮和专列页面已有不占位表达，但原整行释放会误按人数处理 | 邮轮增加“不占舱／同舱第三人”零占用只读记录，专列增加“不占铺儿童”零占用只读记录 | 零占用记录不可选择；实际释放只按间或铺计算 |
| 采购与付款保持原记录 | 名额释放文案容易让人误解为采购还位 | 抽屉明确提示采购数量和已付款不变；提交只更新订单占用及渠道名额 | 交通采购分配和已付款显示在释放前后保持一致 |

## 三、交互结果

- 释放入口直接进入原占用明细，没有新增动作选择层。
- 未选择任何明细时提示“请至少选择一笔仍有占用的原记录”。
- 超过剩余占用时提示本笔最大可释放量；零、负数和小数不能提交。
- 释放原因必填。任何一笔校验失败时，本次所有明细均不更新。
- 取消抽屉不会修改已释放、剩余占用或渠道可用量；再次打开仍显示提交前结果。
- 成功结果生成当前页面内的释放处理编号，说明数量和归还渠道；不生成采购退位、退款或付款记录。

## 四、实际验收

使用无头Chrome打开真实页面并点击入口、复选框、数量、原因、取消和提交按钮，结果如下：

| 场景 | 结果 |
|---|---|
| 代理配额10、占用6、可用4，逐笔释放2 | 通过：占用4、可用6；直营数量不变 |
| 同一成功结果再次点击提交 | 通过：渠道和团期数量未重复增加 |
| 剩余2时再次释放5 | 通过：提示“本笔最多可释放2人”，数据不变 |
| 输入0或-1 | 通过：提示必须为正整数，数据不变 |
| 填写后取消，再次打开 | 通过：两笔剩余仍为2、2 |
| 部分释放后继续处理 | 通过：列表显示“部分释放”，仍可打开处理 |
| 全部释放 | 通过：列表显示“已释放”，操作变为“查看”，抽屉隐藏提交按钮 |
| 原代理渠道停售 | 通过：释放前后均为停售，名额仍归代理 |

| 390×844窄屏 | 通过：抽屉宽度、提交按钮完整可见，页面无横向溢出 |
