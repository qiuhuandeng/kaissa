# 集团财务视角：数据模块整体优化方案

日期：2026-09-14。状态：供用户确认的方案，不是页面施工或财务政策批准。

## 一、结论和本次边界

现有数据中心能够表达订单、实际完成、产品、渠道、团期结算及采购返点的基础分析，但还不足以承担集团完整的经营财务分析。主要缺口不是缺更多订单字段，而是尚未完整回答：谁贡献利润、内部交易是否重复、未来业务占用多少资金、资源承诺会产生什么损失、业务结果与财务账为什么不同。

保留现有业务链路、角色分工和已经完成的报表基础；团期订单继续独立，不改下单、收付、成本确认、结算、门店和呼叫中心日常流程。不照搬其他企业管理软件的全套模块，不在本系统重建总账、薪酬、固定资产、税务申报或法定合并报表系统。

本轮复核四份项目控制文档，盘点当前目录、导航、9个数据中心页面的主要共享逻辑及财务报表新旧入口，并抽查组织、动态资源、成本、核算和关账页面，与多主体基线、结算流程及现有计划成对核对。财务工作簿沿用既有需求证据，未重新读取原附件；未逐按钮重验全部业务页面，未运行浏览器或计算回归。本次结论是代码与业务规则层面的方案评审，不是正式账务审计。

## 二、以现有凯撒业务事实为基础

### 1. 不把所有组织都当作独立公司

组织页已有集团、板块、主体公司、分公司、中心、部门、门市部和门店。示例中厦门、泉州等分公司挂在福建主体下，产品中心及长线中心承担产品职能。以上是系统支持的组织形态，不是已经核准的集团实际法人清单。

报表至少区分三种责任：

| 责任 | 要回答的问题 | 使用的已有资料 |
|---|---|---|
| 核算责任 | 哪家公司记收入、成本和费用 | 法人主体，即承担法律责任的公司；核算主体，即独立形成会计结果的单位；与集团财务核算系统（以下简称NC）的账簿对应 |
| 经营责任 | 哪个产品部门、销售分公司、门店或呼叫中心贡献业绩 | 产品与销售发生时归属、事业部、部门、渠道和人员 |
| 资金责任 | 钱实际在谁的账户、替谁收付、尚未清算多少 | 实际收付款公司、账户、代收代付关系和原单 |

同一业务允许同时从产品与销售角度观察，但不能把两种业绩相加当集团规模；同法人部门协作与跨法人交易也不能混成一种内部往来。

### 2. 两套明细只是基础，不是万能财务总表

订单明细回答“卖了什么”；回团明细回答“完成了什么”，其中已有项目、服务及分次完成的表达。收付款明细回答“钱如何收付”；收入成本确认记录回答“财务在哪个月确认多少”；费用记录回答“哪个部门承担费用”。这些事实相互关联，但不能互相代替。

跟团、邮轮、专列、研学、项目、自由行及单项服务保留各自真实完成依据。不把所有业务改成团期，不把计划回团视为实际完成，不把同一订单不同服务的金额重复累计。

### 3. 自营、内部供应和外采分别看

已有供应关系与经营分类分开设计，应保留。集团内部采购不等于集团新增对客成交；外采不当然按净额确认收入；同一笔优惠或返点不能在成交、成本和贡献中反复扣减或增加。具体收入、税额和分配政策继续待财务确认。

## 四、应补齐的六个大维度

### 1. 公司部门的责任利润：最需要补

新增原计划已有的“月度经营损益”页面，建议设置公司损益、经营责任、费用构成、预算差异四种查询。上游为财务确认收入成本、NC部门费用及已批准管理对应，主要使用者为集团财务分析、公司财务和获授权的经营负责人，下游是经营复盘，不产生付款或会计凭证。

展示财务确认收入、结转成本、毛利、直接销售费用、管理费用、经批准分摊费用、未分配费用，以及有依据的经营结果。费用已计入成本的不得再次扣减；没有完整费用不能把结果叫净利润。月度财务确认与业务完成范围的差额须另表解释。

法律公司与经营部门用不同查询视角：部门贡献相加还要说明未分配费用、内部管理结转等调整，才能核对公司结果。只汇总经营收入成本的页面不能冒称完整法定损益表。

### 2. 集团内部业务和代收代付：必须补清楚

在“结算与核算核对”增加内部双方核对，在月度经营损益展示集团汇总调整。区分内部产品互采、同法人内部服务、跨法人服务、代收代付和账户转账。

关键结果为双方公司、原订单/采购/结算单、内部应收与应付、确认期间、差额、差异原因、已确认抵销金额和待确认金额。内部交易伙伴是集团内交易的另一家公司，不是所有关联供应商。

必须区分三件事：集团对客成交不重复统计；内部双方记录是否一致；是否完成正式会计抵销。第一件能做不代表后两件已完成。没有财务确认的合并范围与抵销结果，只能显示未抵销汇总，不造合并利润。

### 3. 已售未完成业务与未来资金安排：补连接，不重建

经营总览与回团明细已经有“已售未完成”，产品页已有跨年收客。保留这些内容，补按计划出发/完成月份、产品公司、业务类型看未来安排，区分尚未开始、履约中未完成、计划到期未确认，不把已经到期的缺确认业务都称作未来新增收入。

资金报表从已确定的客户付款计划、退款安排和供应商付款节点看未来30/60/90天或逐周收付；期间仅为建议显示方式，最终由资金财务确认。已形成应付的节点不能再按采购计划重复加一次，逾期款不默认明天必收。

展示计划收款、计划付款、预付可冲抵、已安排退款、期初可用资金及计划期末资金；未有依据的计划单列缺口。预收、预存是款项责任，不是天然受限银行存款，不能从现金余额中机械再扣一次。该表不是法定现金流量表，也不承诺概率预测。

### 4. 包销资源和供应商资金占用：旅游行业重点

上游机票切位、邮轮及专列资源页面已有数量、还位截止、付款节点、预付分摊、票损/舱损/铺损；成本页已有预估与确认区别。问题是经营报表尚未完整汇总这些风险，而不是系统没有这些业务流程。

在产品经营与业务毛利中补资源风险查询：已承诺数量、已售/已用、可退未退、不可退未售、已确认损耗、待确认损耗；按资源批次归集，跨多个团期分配不重复计成本。人、机位、舱、铺分单位，不做一个混合“上座率”。

供应商页补采购集中度与预付款占用观察，金额引用预付款报表的同口径结果，不另造余额；关注未履约预付、应退未退及长期未冲抵，不把“付款多”直接当采购多。

本期只建议汇总已有数量、期限及确认金额。保本人数、价格情景、动态预测损失属于可选增强，必须先有固定/变动成本及取消条款资料，不自动加入本次剩余承诺。

### 5. 产品、渠道和客户的贡献：不要停在成交排名

产品页看哪些产品组合、目的地、业务类型和供给方式贡献毛利；渠道页看直营、加盟、合作门店、呼叫中心、平台、企业客户等既有渠道的贡献差异。门店不重建结算，呼叫中心不重建顾问管理。

在确认依据齐备时，列业务毛利、渠道佣金/平台服务费、公司承担且尚未扣除的优惠、直接费用和扣除后的贡献。工资、租金、获客等部门费用在月度损益反映；渠道页引用结果，不按成交额默认均摊。渠道还原毛利校验不等于渠道经营利润，也不等于门店分润或员工奖金。

企业客户及项目业务在渠道页补客户类型/企业客户查询，结合项目毛利及账龄观察“大客户成交高但回款慢”的情况，不新建客户主档、不以游客姓名当付款客户。不默认做个人消费画像或客户终身价值模型。

### 6. 预算差异和报表可信度：把“可看”变成“可用”

现有预算任务管理只支持订单、回团和毛利任务，建议明确为“经营任务与预算”。保留任务下达，不把它包装成完整财务预算编制系统；费用预算先引用财务批准的预算资料，在月度损益比较实际、预算、差额和可解释原因。

产品和渠道结构、价格、数量、资源损耗、费用等原因仅在资料齐备时拆解，不编造归因。旺淡季不能简单按天均摊全年任务，负利润预算不得被订单任务的非负金额限制误伤；负数/零预算的完成率展示另由财务确认。

报表管理补统计期间、截止时点、工作版/已发布版、更正版本、数据覆盖情况及权限。经营负责人先看到结果和异常，财务查看核对明细，管理员维护规则；大段实现说明退出业务主界面，必要口径和待确认状态保留。

## 五、最终页面安排：不继续膨胀

建议保持原计划上限：数据中心10个页面，其中9个已有、仅月度经营损益尚未建设。6类财务核对主题仍归财务报表，数据中心可以提供一个目录入口，但不复制一套计算和办理功能。主题不等于必须新建独立文件。

| 当前页面 | 建议处理 | 页面主任务及优化边界 |
|---|---|---|
| 经营总览 | 保留优化 | 集团规模、已确认利润、未来安排和重点风险摘要；不承载全部明细，不混加不同日期口径 |
| 产品经营 | 保留优化 | 产品结构、贡献、跨年安排及资源风险；取现有产品与履约事实 |
| 渠道经营 | 保留优化 | 渠道/门店/呼叫中心/企业客户贡献；保留渠道产品交叉，不新建门店或中心报表 |
| 团期毛利 | 建议名称调整为“业务毛利与结算分析” | 继续覆盖团期、项目、服务；补成本组成和已确认损耗，预估独立显示；不动团期订单 |
| 供应商采购与返点 | 保留优化 | 采购、返点、集中度及预付占用，采购/账单/付款不混算 |
| 订单明细 | 保留 | 订单确认与变更的事实底稿，不塞入全套往来、票据和部门费用 |
| 回团明细 | 保留，建议标题“回团与履约明细” | 实际完成、分次完成、已售未完成、完成业务财务核对；沿用财务回团叫法 |
| 月度经营损益 | 按原计划新增1页 | 公司部门责任损益、费用、内部调整及预算差异 |
| 预算任务管理 | 建议改为“经营任务与预算” | 保留成交/回团/毛利任务；不重建完整财务预算审批体系 |
| 口径与数据核对 | 保留并完成报表管理职责 | 分类、组织对应、规则版本、数据核对及发布更正；不与期间关账重复办理 |

主任务分工：财务办理页负责确认、更正及执行；财务报表负责钱、账、票、内部往来的查询核对；数据中心负责经营分析。报表不新增认款、付款、开票、推送按钮。沿用当前无金额/编号点击下钻约束，核对采用直接筛选、完整依据表和导出；目录导航与业务办理入口仍各归原模块。

回团页“完成业务核对”保留；按会计期间查“确认发生明细”的主职责建议归结算与核算核对。到第6项实施时复用同一确认记录与规则，原回团视图可保留为受限范围查询，不同时维护两套计算，不提前删除已有功能。

## 六、应去掉或降级的内容

| 内容 | 当前证据及判断 | 建议处理 |
|---|---|---|
| 历史方案、方案二/三、产品分析旧版 | 仍在数据中心常规导航，与新经营页并列，使用者难判断哪份有效 | 第8项核对引用后从日常菜单撤下，文件保留归档；旧链接不能悄悄显示另一套正式结果 |
| 旧财务经营损益计算 | 旧查询入口仍可执行，其代码把应收加入收入；不属于新收退转付原型 | 禁止成为新报表数据来源；第7项由月度损益替代，旧入口在替代验收后停用 |
| 未批准渠道还原毛利规则被当通用渠道利润 | 当前代码已正确标待确认，但其位置容易让人误认为经营利润全覆盖 | 保留专门校验视图和适用范围，不扩用为全部渠道利润，不删财务原需求 |
| 团期/服务“利润”与会计利润混称 | 当前团期分析已有服务单和项目，主结果实为业务毛利 | 调整标题和指标名；无费用及核算结果时不称净利润 |
| 不分视角的“全部公司合计” | 采购与回团财务当前已标未抵销，不能因此认定合并已做 | 保留内外分列与未抵销提示，补核对结果后再展示批准集团口径 |
| 主界面长篇演示或实现说明 | 多页已有大段说明和数据缺口文字 | 正式页面保留必要统计口径、数据状态与简明异常；详细规则进入报表管理，原型仍明确算例身份 |
| Excel人工加工列变成业务必填项 | 原表含本月/本周/上周、双周和空列/差异列 | 日期归属由批准日历计算，不逐单人工录入；通用“差异”改成有比较对象的差异，不照搬空列 |

另有旧来源示例不能直接承接：NC页项目结算示例存在借贷金额不同却标校验通过的情况，关账页把多类未结事项并列为缺口。新核算报表只能用已确认事项及真实返回结果；正常未收、未付或待票不能一律判错或一律阻断关账。这里只登记取数与判断风险，不在本轮重写NC或关账业务。

## 七、放进剩余7项，不另开新的建设长队

以下为调整建议，用户确认后才纳入实施范围。第1项收退转付已完成，保持完成状态。

| 原约定项 | 本方案建议一起补的分析内容 | 边界 |
|---|---|---|
| 2. 订单收付与往来账龄 | 主体/客户/渠道/供应商余额、逾期、内部代收代付待清算；企业客户查询 | 截止日余额与发生额分开，不改认款核销 |
| 3. 四类预款与保证金 | 未履约资金占用、供应商长期未冲抵及应退未退 | 四类性质分开，不改充值、扣款、退款 |
| 4. 资金收支 | 实际收付、账户受限/可用、内部转账、已确定付款节点与计划资金缺口 | 不建概率预测、银行接入或资金调度新流程 |
| 5. 发票收付核对 | 收票/开票时差、红冲、分配差异及正常未到期事项 | 不另做税务申报和收入确认 |
