# 业财报表产品与团期代码—文档核对

更新时间：2026-09-06

> 本文是阶段2第一个模块的审计结果。范围仅限产品、外采、目的地、团期和团期成本；本轮不修改业务页面，也不把静态原型中的演示数据误判为已经形成正式数据链路。

## 一、本轮要回答的问题

财务最终需要从每笔订单和每个已履约团队中，稳定取得产品类型、旅游范围、业务类型、目的地、产品负责人、产品经营公司、供应商、团号、计划出回团日期、实际回团日期、收入、成本和毛利。

本轮核对的是：产品和团期环节现在能不能产生这些信息，文档与实际页面是否一致，以及后续应该先修上游业务流程还是直接做报表。

这一环节位于完整业财链路的中段：

`供应商和资源 → 产品/线路 → 方案 → 团期/航次/班期/营期 → 订单 → 履约与成本 → 结算 → 财务分析`

主要使用角色是产品经理、外采产品经理、计调、团控和成本结算人员。产品环节负责确定“卖的是什么、归谁经营、来源于谁”；团期环节负责确定“哪次出行、何时实际完成、由谁执行”；财务环节承接已经确认的收入、成本和结算结果。

## 三、总体结论

现有文档已经给出了基本正确的业务主线，页面也能较完整地演示多种产品和团期对象，但目前还不能据此自动形成财务要求的产品、回团和毛利分析。

原因不是页面数量不够，而是同一个业务事实被分别写在产品页、团期页和成本页的演示数据中，没有形成一条可以持续传递和追溯的业务记录：

1. 产品类型与旅游范围在部分代码中已经分开，但文档中仍有混用。
2. 产品经营公司、产品负责人、供应来源和业务类型在不同产品页面上不完整，也没有统一传给团期和订单。
3. 目的地配置页、产品编辑页和团期页使用各自的固定数据，没有共同的目的地分类及历史规则。
4. 团期有计划回团日期和“已回团”状态，却没有实际回团日期、确认人、确认时间和财务确认月份。
5. 团期成本页能展示收入、成本、毛利、预付和付款，但它使用另一套固定数据，不能回到同一产品、团期和订单。
6. 页面中的“结算价”同时存在渠道售价和供应商成本两种含义，直接汇总会造成收入或毛利口径错误。
7. 外采文档对内部共享和外部采购的责任划分较清楚，页面却没有完整记录产品归属公司、销售公司、履约公司和结算对象。

因此，正确的改造顺序是先统一上游业务事实，再做订单归属和财务报表；现在直接开发固定周报，只会把现有不一致继续固化。

## 四、代码与文档五类核对结果

| 分类 | 已确认事项 | 对财务报表的意义 |
|---|---|---|
| 代码与文档一致 | 线路/方案与团期分层；邮轮用航次和舱房、专列用班期和铺位、研学用营期和名额；自由行按出行日期维护价格和库存；团期销售、执行、结算状态应分开 | 这些对象层级可以继续保留，是后续按产品类型下钻的基础 |
| 文档已有、页面未完整承接 | 文档要求区分产品归属、销售、履约、供应和结算责任；要求实际回团后进入成本确认和结算；要求内部共享和外部采购分别处理 | 财务所需的责任公司、业务类型和回团口径仍无法从页面记录稳定取得 |
| 代码新于文档 | 产品下的团期页已经能复用履约中心的团期新建抽屉；旧审计仍写产品侧不应出现新建入口 | 旧文档需要标明历史时点。是否保留产品上下文快捷入口，应以是否复用同一套规则为判断标准 |
| 代码与文档冲突 | 文档把国内、出境与邮轮、专列、研学混在“产品类型”；页面已部分拆成产品类型和旅游范围。页面把渠道结算价与供应商结算价都简称“结算价” | 分类会重复或错位；金额会被错误当作收入或成本，需要统一业务名称与取值来源 |
| 代码和文档均缺失 | 多目的地如何计入财务分析；产品和人员归属变更后历史订单归谁；实际回团与财务确认月份的关系；回团后成本、退款、变更如何进入原期间或调整期间 | 这些是报表可复算的必要规则，必须由业务和财务确认后才能实施 |

## 六、需要形成的业务记录

后续不是简单给现有页面多加几列，而是需要让以下业务事实各自有唯一、可核对的来源。

### 6.1 产品归属记录

由产品经理维护并在发布前校验：

- 产品类型和旅游范围。
- 产品经营公司、产品负责人和归属部门。
- 业务类型及其判断依据。
- 自营、内部共享或外部采购的供应来源。
- 主要供应商或内部提供方。
- 主要目的地及辅助目的地。

产品归属发生变化时，不能直接覆盖历史订单采用的归属，需要记录生效时间。订单模块应在下单时保留当时适用的产品归属，避免产品负责人转岗或产品经营公司变化后重算历史业绩。

### 6.2 团期履约记录

由计调或团控负责：

- 团号以及对应的产品、方案。
- 计划出团和计划回团日期。
- 实际出团和实际回团日期。
- 团控负责人、履约公司和主要供应方。
- 销售、执行和结算三个阶段的主状态。
- 回团确认人、确认时间和异常原因。

“已回团”必须是一次可追溯的业务确认，不能只是把页面标签改色。

### 6.3 财务回团确认记录

由财务按已确认规则承接：

- 实际回团日期。
- 本次进入的财务月份。
- 已回团但成本未齐、结算未完成等异常状态。
- 回团后退款、成本调整和变更单的处理期间。
- 调整前金额、调整后金额和依据。

实际回团日期是履约事实，财务月份是统计和确认口径，两者不能混成一个字段。

### 6.4 目的地分析归属

目的地配置应成为产品选择和报表分析共同使用的资料，至少包含国家或省份、目的地区域、标准名称、历史生效时间。多目的地产品还必须确定主目的地和财务统计规则，不能用名称拼接后再由报表猜测。

### 6.5 成本和结算关系

团期成本必须能够回到对应团号、产品、供应商账单或成本确认依据。应明确区分：

- 客户成交金额和实收金额。
- 渠道或同业结算价。
- 供应商报价或采购价。
- 回团后的供应商实际结算金额。
- 财务确认的收入、成本和调整金额。

页面可以展示预计毛利，但正式毛利必须使用同一团队的财务确认收入和完整确认成本。

## 七、建议的修改顺序

### P0：先统一业务口径和来源

1. 确认产品类型、旅游范围、业务类型三组分类，修正文档中的混用。
2. 确认产品经营公司、销售公司、履约公司和结算对象分别代表什么，不能继续共用模糊的“主体公司”。
3. 统一产品编辑与发布校验，补齐产品负责人、经营公司、供应来源、供应商和目的地。

### P0：补齐实际回团和跨年依据

1. 将“确认回团”改为需要填写或确认实际回团日期的业务动作。
2. 保存确认人、确认时间和调整记录。
3. 财务确认实际回团与财务月份的关系，以及跨年和回团后调整规则。

### P0：打通团期与成本结算

1. 团期成本只能从已存在的团号进入，不能另造一套同名演示团队。
2. 每项成本保留供应商、金额性质、确认状态和结算依据。
3. 去除按固定比例估算供应商结算价并进入正式毛利的做法。

### P1：统一目的地与价格名称

1. 目的地配置、产品选择和报表分类使用同一套标准资料及生效时间。
2. 确认多目的地的财务归属规则。
3. 将目前含义为同业售价的“结算价”改为“渠道结算价”或“同业结算价”；供应商结算金额只在成本或结算环节使用。

### P1：收敛重复入口和保存方式

1. 履约中心继续作为团期日常操作主入口。
2. 产品页可以保留带入当前产品的快捷新建入口，但必须复用履约中心同一套表单、校验和保存规则。
3. 合并团期三页式新建和独立新建页的重复规则，避免同一团期因入口不同而缺字段。

## 八、需要财务和业务确认的事项

1. “凯撒自营、凯撒甄选、外采”分别依据产品归属、供应商性质、合同关系还是结算方式判定；内部共享产品进入哪一类。
2. 财务报表里的“产品归属”以订单发生时、出团时还是回团时的产品负责人和部门为准。
3. 产品经营公司、合同销售公司、履约公司和最终收入核算主体不一致时，各报表分别采用哪一个。
4. 多目的地产品按一个主目的地统计、按金额或人数分摊，还是允许在分析中多标签展示但汇总不重复。
5. 回团业绩默认按实际回团日期还是财务确认月份；延期、提前、跨年和回团后调整分别进入哪个期间。
6. 财务材料中的“结算价”在不同表里分别指渠道结算价、供应商结算价还是财务确认收入。
7. 团期收入按订单成交、实收、履约分摊还是财务确认金额计算；退款和变更在何时冲减。

## 九、本轮边界与下一步

本轮已经确认“产品与团期”存在P0数据链路缺口，但尚未改业务页面。订单发生时究竟保留哪些产品、组织和人员归属，需要结合订单与销售代码继续判断。

唯一下一步是核对“订单与销售归属”模块，重点检查订单日期、有效订单、产品和团期关联、销售人员、销售组、门店、渠道、成交金额、退款变更以及历史归属保留方式。
