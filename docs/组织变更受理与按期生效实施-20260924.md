# 组织变更受理与按期生效实施

2026-09-24。用户在第一步交付后要求“执行／继续”，本轮承接[Admin部门组织能力核对](Admin部门组织对审批设置的支持核对-20260924.md)的第二步：公司内组织新增、调整、停用，以及组织、负责人和成员任职申请的受理与生效原型。

## 角色和范围

集团组织管理员在 `admin/org.html` 直接维护公司内组织、成员和负责人安排；公司组织管理员在组织架构和员工任职提交申请；审批人在现有审批中心处理。上游是账号与有效任职资料，下游是新业务申请按公司、日期、个人汇报关系或部门负责人找人。组织迁移不会替员工更换个人直属上级，已有业务归属和历史审批不自动重写。

本步仍是会话内的业务原型。组织申请使用一个“组织变更核准”节点演示受理结果，尚未绑定已发布模板、实际登录审批人、多级逐节点办理及签名规则；这项限制不能与已经完成的审批配置／试跑混淆。两个现有法人公司的合同和财务配置保持原入口，本步新增组织指公司内分公司、中心、部门及门市部，不含新设法人公司的完整准入。门店经营档案及业务停业仍在门店管理，组织停用只控制组织可用性。

## 财务要求—现有功能—缺口—修改—验收

本轮财务要求限于付款等审批找人所依赖的公司、组织与任职资料，不修改金额、核算或结算政策。

| 要求 | 原功能与缺口 | 本轮页面／流程 | 验收 |
| --- | --- | --- | --- |
| 新增组织可被审批配置使用 | 旧新增抽屉保存只提示成功 | admin实际保存公司内组织，树与下级列表读取共同资料；新增组织进入模板范围候选 | 新建、重新读取、组织树／模板候选DOM检查 |
| 迁移及停用不破坏组织找人 | 静态树，缺真实上级调整及影响核对 | 同公司上级、组织名称／类型／范围、启停用、日期和原因；显示成员、下级、负责人及申请数量 | 同名、循环、跨公司、门店下挂组织拦截；个人链不随部门迁移更换 |
| 停用前处理依赖 | 原按钮无处理结果 | 当前与未来任职、下级组织、负责人、未完成申请检查；有占用不能停用，空组织可停用／恢复 | 未来入职、计划停用、待建子部门、负责人任期及空组织正反例 |
| 负责人可核对每人任期 | 原多人姓名塞进一行 | 负责人Tab逐人列开始／结束日期、任期中／待生效／已结束；调整保留旧任期，可结束全部现任 | 多人保存、旧任期保留、未来接替、生效前后取人 |
| 提交申请不等于变更生效 | 非负责人类型也提示成功，任职申请无收件后续 | 新建、迁移、停用、负责人及任职形成共同申请；现有待我审批／我发起的／总览展示 | 来源提交、待我审批、退回、修改重提、通过、来源页复开 |
| 通过后按期采用新关系 | 没有处理／生效动作 | 通过写入带日期的安排；到期读取新关系；超过期望日期才批准则从批准日生效 | 今天旧关系、未来新关系、重复通过阻止、拒绝／退回／撤回不生效 |
| 不能覆盖申请后的新安排 | 申请没有变更前资料 | 提交保留原资料，审批前重新核对有效人员、组织和原资料；资料已变化要求退回 | 停用候选人、管理员已改资料、重复申请、缺意见及旧申请缺依据拦截 |
| 历史处理可核对 | 固定示例记录及仅一行待审批 | 每次提交、修改重提和处理留记录；保留每轮申请内容及当时名称；组织记录反查审批 | 原轮次不被新理由覆盖，撤回后可查，按日期部门链一致 |

## 页面组织与实现

- `admin/org.html`：原提示式新增抽屉替换为统一组织维护抽屉；保留集团／板块分组和两家公司；成员任职继续使用第一步入口。下级列表、负责人及变更记录改为实际会话资料。
- `merchant/system/my-org.html`：共同组织树、按申请类型显隐字段、固定组织记录选择、真实调整记录。保留既有门店档案映射及门店管理方向。
- `merchant/system/staff-management.html`：原任职申请接入共同收件，人员详情显示申请结果并可查看审批；个人与部门选择按固定记录识别。
- `merchant/approval/approvals.html`：组织申请合入原三类视图，按状态提供审批、修改重提、撤回、详情；旧独立组织调整示例退出列表，其他业务审批继续保留。
- `shared/approval-org-data.js`：组织按日期读取，任职期间检查计划停用；原人员及个人汇报关系接口保持。
- `shared/approval-org-workflow.js`：公司内组织维护、负责人任期、申请状态、批准前校验、按期安排与记录。
- `shared/approval-org-workflow-ui.js`、`shared/admin-org-structure.js`：统一抽屉、组织树和处理内容。
- `shared/approval-org-maintenance.js`：来源申请提交、记录和未提交退出保护；移除旧直接负责人保存入口。
- `shared/org-admin-members.css`：局部表格、固定操作列、组织操作区样式，沿用公共抽屉规范。

旧会话内只有待审批但缺变更前资料的申请，不直接批准：可以退回，在修改重提时补齐依据。本轮不伪造它们过去的申请内容。

## 验证结果

新增20组组织规则检查、15组来源—审批—组织DOM检查；连同既有188组配置、规则、层级、人员及DOM回归，共223组通过。旧层级DOM用例随新的“生效日期不早于今天、变更原因必填、负责人统一抽屉”调整，原业务断言保留。

检查覆盖新增部门、新开员工、负责人接替、同公司兼任、账号停用、福建／北京分别维护六类业务场景，以及未来日期、并行调整、重复处理和撤回等异常。JavaScript语法、CSS解析、差异格式和财务执行清单检查通过，原8批／36项／6场景不变。

前序本地文件浏览器访问限制继续保留，本步没有绕过限制，未取得浏览器截图或真实排版验收。上述DOM结果不等于浏览器视觉通过。
