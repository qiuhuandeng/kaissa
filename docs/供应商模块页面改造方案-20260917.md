# 供应商模块页面改造方案

整理日期：2026年9月17日  
需求依据：[业务会议需求完整梳理](业务会议需求完整梳理-供应商产品与销售-20260917.md)的供01—供16  
现状依据：[业务需求与现有功能分模块核对及增改清单](业务需求与现有功能分模块核对及增改清单-20260917.md)、当前页面代码及供应商/产品/财务流程稿  
文档性质：页面和流程改造设计，不代表已经修改页面、完成接口或批准财务政策。

## 一、结论

供01—供16都是供应商相关需求，但不能全部堆进现有 `resource/suppliers.html`。正确的页面分工是：

- **资源模块**维护供应商是谁、与哪些公司合作、协议和资料是否有效。
- **审批中心**承接供应商准入、新增合作公司、协议和账户变更审批；审批页不替代供应商档案。
- **产品中心**查看供应商提供的产品；产品页只表达可选来源，不承接具体日期的供应确认和成本。
- **履约中心**在具体团期内选择实际服务供应商、维护承接段落和成本，并发起付款申请。
- **财务模块**按协议账期核对账单、发起供应商对账、审核付款；不在供应商档案中直接完成付款。
- **供应商端**确认我方发出的对账单、提出差异、补充发票；供应商不再作为默认对账发起方。

本轮建议新增2个二级页面、调整9个现有业务页面，并补导航承接。不新增“供应商合同”“供应商产品库”等重复一级菜单。

| 类型 | 页面 | 主要职责 | 承接需求 |
|---|---|---|---|

## 二、资源模块

### 1. 供应商列表 `merchant/resource/suppliers.html`：修改

当前页面同时承载列表、新建准入、合同管理和供应商设置，且各行按钮打开同一组固定示例。新需求涉及多公司、多协议、多类资料和审批记录后，继续在列表上叠加抽屉会让对象混乱。因此列表只负责查找、判断状态和进入详情；准入保留为列表上的新增入口，合同和复杂设置移入详情页。

#### 列表调整

| 位置 | 当前 | 修改后 |
|---|---|---|
| 搜索 | 名称/负责人/合作范围 | 支持名称、供应商编号、统一社会信用代码、联系人、国家/城市模糊搜索 |
| 筛选 | 类型、提供服务、状态、供应商端 | 保留供应商类型和主状态；新增签约公司、服务国家/城市、协议到期范围；供应商端状态移入详情或弱文本 |
| 列1 | 供应商名称 | 供应商名称＋唯一编号；简称作为辅助信息 |
| 列2 | 单一供应商类型 | 主类型＋合作内容摘要；跨业务合作不要求重复建档 |
| 列3 | 提供服务/服务范围 | 有效公司协议数＋主要国家/城市；完整范围进详情 |
| 列4 | 供应商状态 | 只保留供应商主状态：草稿、审核中、启用、停用、黑名单 |
| 列5 | 供应商端 | 改为“有效合作公司”，数字可进入详情对应公司协议 |
| 列6 | 合同截止 | 显示最近到期协议日期和签约公司，不把某份协议到期等同整个供应商停用 |
| 列7 | 负责人 | 集团维护负责人；公司业务负责人进详情 |
| 操作 | 合同、设置 | 主操作“详情”；草稿/退回显示“继续完善”，其余低频动作进入更多 |

列表操作不能再让六行供应商共用“协成”的合同和设置数据。点击详情必须带当前供应商编号；新增、停用、黑名单等动作也必须作用于当前供应商。

#### 新增供应商流程

“新增供应商”先打开查重步骤，再进入准入表单：

1. **查重**：输入供应商名称、统一社会信用代码或境外注册号。完全匹配时显示已有档案，主按钮改为“新增合作公司”；名称近似或银行账户重复时提示人工核对。
2. **基础资料**：维护供应商身份、主类型、注册地址、品牌/英文名称、法定代表人及主联系人。删除“集团内部公司”外部供应商类型，集团内部主体从组织架构引用。
3. **合作申请**：选择本次拟合作公司、负责部门、负责人、合作内容、国家/城市、准入原因。这里表达本次申请，不在基础资料中反复录入集团各公司联系人。
4. **准入资料**：继续按供应商类型动态呈现材料；未标为必填的附件不擅自改成必填。版权和真实性声明由提交人主动勾选，不能默认代勾。
5. **财务资料**：可采集开户名、银行、账号、币种等，但显示“待财务审核”，业务准入通过不自动进入付款白名单。
6. **提交结果**：生成准入申请记录，状态变为“审核中”，可查看审批编号和当前节点；缺少必填资料时留在原页，不显示提交成功。

“新增”按钮可采用下拉选择“正式供应商准入 / 临时合作申请”。临时合作复用查重，另收集临时原因、使用公司、适用业务、有效期和最少资料；不得另建一套不查重的临时供应商名册。

#### 本页不做

- 不在列表直接维护多个协议和银行账户。
- 不在列表放“续签、生成协议、发起对账、付款”等跨对象操作。
- 不把合同到期、供应商端培训、某公司合作暂停并列成多个主状态。

### 2. 供应商详情 `merchant/resource/supplier-detail.html`：新增

这是供应商主操作页，从列表“详情”进入；仍归“资源 > 供应商”，不增加菜单。页面顶部展示供应商名称、唯一编号、主类型、主状态、集团维护负责人和最近更新。右上主操作按状态显示“完善准入”“新增合作公司”或“编辑档案”，不在每个卡片重复放同一操作。

建议设置六个详情页签：

#### 页签一：基本资料

- 供应商唯一编号、中文全称、简称、英文名/品牌名。
- 境内统一社会信用代码或境外注册号、注册国家/地区、注册地址、法定代表人。
- 主类型及可合作内容摘要；同一供应商可有地接、完整外采线路或单项服务等多种合作内容。
- 集团维护负责人、主联系人、基础资质及更新时间。
- 相似档案提示和合并记录只供集团维护人员查看。

“主类型”用于材料和主要识别，“合作内容”来自具体公司协议，两者不能混成一组随意多选。集团内部公司不在此建档。

#### 页签二：公司合作与协议

这是供03、供04、供06、供07、供10、供15的核心页签。每行是一份“供应商＋我方签约公司＋协议”，而不是一家公司共用集团合同。

列表字段：协议号/名称、我方签约公司、负责部门、公司业务联系人、合作内容、服务国家/城市、有效期、账期摘要、协议状态、操作。

操作规则：

- “新增合作公司”复用供应商基础档案，创建新的合作申请，不再新建供应商。
- “新增协议”必须先选择我方签约公司和负责部门，再填写合作范围和结算政策。
- “续签”复制原协议范围作为草稿，原有效协议继续可查；新协议未生效不覆盖旧协议。
- “停用协议”只影响该公司和协议，不直接停用整个供应商。
- “生成协议”选择批准模板和版本，带入双方主体；生成稿、人工修改稿、双方盖章版分别留存。

协议编辑内容：

- 协议名称、类型、我方签约公司、负责部门、双方联系人。
- 适用产品大类、合作内容、洲/国家/城市、适用期间。
- 结算方式、币种、对账周期、平台使用费、返佣或扣点政策。
- 账期由“起算事件＋天数”表达，例如出票后30天、回团后15天、账单确认后7天；同时显示计算出的起算日和应付日。
- 发票要求、付款节点、协议附件、模板版本、盖章件。
- 草稿、审批中、待盖章、有效、临期、已到期、已终止等协议状态；供应商主状态仍独立。

审批通过与协议生效分开显示。最终以“审批通过”还是“双方盖章归档”作为可引用条件，仍需业务和法务确认；页面先保留两个结果，不能自动当成同一状态。

#### 页签三：合作联系人和服务范围

- 按签约公司维护产品、操作、财务和紧急联系人，不再以一个全局“供应商设置”覆盖所有公司。
- 服务范围采用洲—国家—城市多选，允许直接搜索城市。
- 每条范围显示合作内容、负责人员、协议来源和有效期。
- 只能引用有效公司协议中的范围；超出范围需新增协议或补充审批。

#### 页签四：提供产品

- 展示供应商提交或我方已代理的产品数量、产品名称、类型、目的地、入库/代理状态及负责计调。
- “查看全部产品”进入 `product-market.html?supplierId=...`，不在供应商详情复制一套产品编辑功能。
- 普通业务人员只看本公司协议和本人授权范围内的产品；价格可见性继续遵守产品与岗位权限。

#### 页签五：财务资料

- 按签约公司和协议展示结算账户、币种、开户名、银行、账号/IBAN、SWIFT/BIC、联行号、发票要求和财务审核状态。
- 默认遮蔽账号中段；只有财务及获授权岗位可查看完整信息。
- 新增或变更账户生成“供应商账户变更”审批，不因业务人员保存就可用于付款。
- 显示“当前可用于付款的账户”和“待审核账户”，二者不能混在一起。

#### 页签六：审批与变更记录

- 展示供应商准入、新增合作公司、协议、续签、临时合作、账户变更和停用记录。
- 每条记录含申请编号、事项、申请公司、申请人、当前节点、结果、退回原因和时间。
- 退回后从来源事项“继续完善”，不在审批记录内重复编辑供应商资料。

## 三、审批中心

### `merchant/approval/approvals.html`：修改

现有审批事项已经包含“供应商准入”和“供应商账户变更”，应复用审批中心，不另建致远审批页面。新增或补齐以下事项示例：

| 审批事项 | 来源 | 审批详情应展示 | 通过后回到哪里 |
|---|---|---|---|
| 供应商准入 | 供应商基础档案 | 身份、类型、资料、拟合作公司、合作原因、风险项 | 供应商详情；不自动视为协议生效 |
| 新增合作公司/协议 | 公司合作与协议 | 原供应商编号、本次公司/部门、范围、联系人、政策、附件 | 对应公司协议记录 |
| 临时合作 | 临时准入 | 临时原因、有效期、使用范围、最少资料及限制 | 临时合作记录 |
| 协议续签/变更 | 公司合作与协议 | 原协议、变更前后、有效期、账期、费用政策 | 新协议版本，不覆盖原记录 |
| 供应商账户变更 | 财务资料 | 原/新账户、签约公司、影响的未付款事项、确认函 | 财务资料及付款白名单状态 |

审批结果支持通过、退回补充、拒绝和撤回。原型中表现来源单据和结果回写；致远接口、外部审批编号和异常重试留正式对接，不用一个“提交成功”提示代替审批过程。

## 四、产品和履约模块

### 1. 自营产品编辑 `merchant/product/product-self-edit.html`：修改

供14不能只用一个“主供应商”。在线路方案或每日行程中增加“可选地接及承接段落”：

- 可选择多个有效地接供应商。
- 每个供应商维护适用国家/城市、行程天数或服务内容，例如法国D1—D4、意大利D5—D8。
- 这里只表达产品设计时可选来源，不维护具体团期确认号、实际人数、最终成本或付款节点。
- 供应商选择受当前产品公司、有效协议和服务区域限制；失效协议只可查看历史，不可新增引用。

### 2. 产品市场 `merchant/product/product-market.html`：修改

- 接受 `supplierId`、签约公司和负责区域筛选，从供应商详情进入时自动定位该供应商产品。
- 产品卡显示来源供应商、授权公司、负责计调、入库/代理状态。
- 无本公司有效协议或超出本人区域权限的产品不可进入代理操作，但可否查看由权限规则决定。
- 不在此页显示供应商银行账户、真实应付成本或其他公司的敏感协议。

### 3. 团期详情 `merchant/tour/schedules-detail.html`：修改

具体日期、执行段落和实际供应商属于履约对象。在“资源/服务安排”中增加地接服务分段表：

| 字段 | 含义 |
|---|---|
| 服务段 | 日期、城市或行程天数范围 |
| 服务内容 | 酒店、用车、餐饮、景点、导游或地接打包 |
| 实际供应商 | 从本公司有效协议范围选择 |
| 协议 | 当前公司与该供应商的有效协议 |
| 联系人 | 本公司协议下的业务/操作联系人 |
| 确认结果 | 待确认、部分确认、已确认、有差异 |
| 成本承接 | 查看对应成本项，不在本表直接完成付款 |

允许同一团期由多个地接分别承接不同国家或日期；不设置一个全局主供应商覆盖所有服务段。分段供应商确认后进入团期成本，未确认时不显示为已取得资源。

### 4. 团期结算/付款申请 `merchant/tour/fulfillment-cost.html`：修改

- 成本明细继续按供应商分别维护，增加服务段、协议号、我方签约公司和账期摘要。
- 同一团期的两个供应商分别形成成本和付款依据，不能因线路主供应商合并。
- 付款申请工作区显示起算事件、起算日、账期天数、应付日、当前是否未到期/临期/逾期。
- 未到期只作提示；是否允许提前申请及例外审批按财务确认，不自行全部拦截。
- 点击协议号进入供应商详情的公司协议；点击账单进入供应商账单。
- 不在本页确认实际付款、回单或集团核算系统结果。

## 五、财务模块

### 1. 付款申请 `merchant/finance/finance-payment-apply.html`：修改

现页已有合同号、付款节点和计划日期，应补成完整的账期核对：

- 付款对象对应的供应商编号、我方签约公司、协议号和协议状态。
- 账期起算事件、起算依据编号、起算日、天数、应付日。
- 本次申请日与应付日的差异，显示“未到期、临期、已到期、逾期”，作为提示而不是新的申请主状态。
- 提前付款时显示申请理由和例外审批；规则未确认前不默认拦截或自动通过。
- 财务可查看获授权的完整收款账户，普通业务申请页只看脱敏账户。

审批详情继续在审批中心承接；付款执行、回单和核销仍留在现有财务页面，不并入供应商档案。

### 2. 供应商账单 `merchant/finance/finance-supplier-bills.html`：修改

该页负责单张或若干账单的识别、业务挂接、金额核对和应付承接，不等同期间供应商对账单。需要：

- 账单行增加供应商编号、签约公司、协议号、账期及可进入的供应商对账单编号。
- 选择正确协议后再计算应付日；同名供应商不能只按名称猜协议。
- 保留供应商账单金额、系统成本、确认金额和差异，不因“确认挂接”就把账单金额覆盖为系统成本。
- 已进入供应商对账的账单显示对账状态和入口；未解决差异不能被标成双方已确认。
- 从新对账页选择账单或成本时，以本页的已核对事实为来源，不重复造金额。

### 3. 供应商对账 `merchant/finance/finance-supplier-reconciliation.html`：新增

放在“财务 > 结算对账 > 供应商对账”，解决供16。这个页面和“供应商账单”的区别是：供应商账单核对具体账单金额，供应商对账按公司、供应商、协议和期间确认该期间全部往来与差异。

列表建议字段：对账单号、我方签约公司、供应商、协议/期间、应结金额、差异金额、供应商确认结果、当前主状态、负责人、操作。

主状态：草稿、待发送、待供应商确认、差异处理中、双方已确认、已关闭。操作由主状态决定：

- 草稿：编辑、发送供应商。
- 待发送：发送供应商、作废草稿。
- 待供应商确认：查看；必要时撤回后修改。
- 差异处理中：处理差异、重新发送。
- 双方已确认/已关闭：详情。

新建对账单流程：

1. 选择我方签约公司、供应商和有效协议。
2. 按协议对账周期带出期间和账期规则。
3. 汇集符合范围的订单、团期成本、供应商账单、扣款/补差、预付冲抵和已付款；没有依据的项目不自动补零。
4. 财务或获授权岗位复核，保存草稿。
5. 我方发送供应商，记录发送人和时间。
6. 供应商确认或提出逐行差异。
7. 我方处理差异后重新发送；双方确认后保留版本及确认记录，向应付和付款提供依据。

“双方已确认”不等于已付款、已收票、已核销或已推集团核算系统。对账单详情应分区展示账单/成本、调整、预付冲抵、付款和发票，状态彼此独立。

## 六、供应商端

### `supplier/settlements.html`：修改

当前三行列表和所有按钮共用固定结算单，确认只关闭抽屉。改造后：

- 仅展示我方已发送给当前供应商的对账单，不提供“新建对账”入口。
- 列表按所选对账单打开对应详情，显示我方签约公司、协议、期间、版本、金额和确认截止日。
- 明细至少包含业务单号、团期/订单、费用项目、数量、我方确认金额、供应商确认金额、差异和依据。
- “确认无误”前校验所有明细；提交后更新当前行并增加确认记录。
- “提出差异”要求选择差异行、填写供应商金额、差异原因并上传依据；状态进入“差异处理中”。
- 我方重新发送后显示新版本，原版本及双方意见仍可查看。
- “提交发票”只在双方确认且规则允许时出现，提交发票不把付款状态改成已付款。

供应商端订单确认 `supplier/orders.html` 属于外采订单二次确认，和本次供16对账确认是两个不同业务动作；本次供应商基础模块不把两者合并。

## 九、页面验收重点

1. 同一供应商与福建、上海两家公司合作，只存在一个供应商编号，两份协议各有联系人、范围、账户和账期。
2. 上海协议到期时只禁止上海新增引用，福建有效协议和历史团期不被误停。
3. 临时酒店先查重、走临时申请；转正式时保留原编号关系、业务和付款记录。
4. 普通销售不能看到完整银行账号和真实应付成本；财务可按授权查看审核资料。
5. 一条线路可设置两个候选地接，具体团期按法国段、意大利段分别确认实际供应商和成本。
6. 付款申请显示“出票后30天”的起算依据、日期和应付日；未到期只按批准规则提示或例外审批。
7. 我方对账单发送后，供应商端打开的是正确单据；确认、提差异和重发产生不同状态及版本记录。
8. 供应商账单82,000元与系统成本80,000元挂接后仍保留2,000元差异，不能因挂接直接归零。
9. 双方对账确认不自动变成已付款、已收票或已完成集团核算系统推送。
