# 单团会奖项目操作说明

> 2026-10-24已从新建项目实际走到结算提交，见[业务走查验收记录](单团项目实际业务流程走查验收-20261024.md)。单笔订单进入收款认领或开票申请仅办理本订单；项目入口保留本项目多单分配。会议专票团默认专票与会务服务，仍可按客户要求调整。修正原申请保留原覆盖订单，不自动带入新订单。

适用版本：2026年10月24日统一创建订单入口及报价命名版。供销售、计调、项目负责人及财务按页面办理，也供开发理解各步处理的业务对象。

本次操作的核心是：**项目团管理执行，报价管理价格准备，订单管理成交。新增默认成团进入进行中；仅暂存资料时勾选保存为草稿。客户在线下谈妥后再登记成交并创建订单，保存报价不会自动生成订单。** 创建订单后，执行交付、收款开票和成本结算分别沿原页面办理。

当前原型统一使用超级管理员，无须切换岗位。文中的岗位说明业务职责；页面中的演示姓名、金额、日期和收款比例应按本次业务核对。

## 一 先分清项目 子团和订单

| 对象 | 用来管理什么 | 不代表什么 |
| --- | --- | --- |
| 大项目 | 客户、总合同、销售、项目组、总预算、人员费用额度及各子团汇总 | 建立项目不代表客户已经成交，也不生成整份年框金额的订单 |
| 子团或项目团 | 一场会议、一条线路或一批服务的日期、地点、人数、负责人和执行交付 | 子团的预算和客户预计金额不是成交价 |
| 客户订单 | 客户已经同意购买的服务、含税价格或计价规则、收款计划及成交依据 | 创建订单不代表已收款、已开票或已结算 |

一个独立成交的子团通常对应一张订单；一次整包成交可以用一张订单覆盖多个子团。判断依据是客户如何成交，不是系统创建了几个团。同一批服务已有有效订单时，继续办理原单，不能为了补价格或收款再建一张相同订单。

例如：客户年框上限500万元，某场会议成交3万元，本次订单是3万元。该场费用预算2万元用于控制支出，不能拿来作为订单价格。

## 二 按业务情况选择入口

日常从 **产品中心 → 自营产品 → 单团项目** 开始。整个项目的分工、额度、合同等办理集中在列表“更多”；点击“详情”默认进入项目团列表，新增、批量处理和执行查看在此完成。

详情按业务对象分为四个页签，不照搬产品详情的页签数量：

| 页签 | 主要用途 | 操作边界 |
| --- | --- | --- |
| 项目团（默认） | 管理各场会议、线路或服务批次，按月份、计调、地点和状态筛选 | 新增、批量建团、团资料修改、成交建单、分配计调、移交及进入执行详情 |
| 客户订单 | 核对订单覆盖哪些团、金额、已收待收、开票和客户结算确认记录 | 反查原订单；在原订单办理最终定价、收款及开票，不再重复建一份款票表 |
| 费用与结算 | 核对各团承担、结算进度与期限、公共费用归属和三套税额毛利 | 查看原结算详情；采购和结算办理继续原履约入口 |
| 项目资料 | 查看客户需求、合同、项目成员、分工额度、附件及日志 | 低频档案集中在最后；项目级维护从列表“更多”进入 |

| 现在的业务情况 | 从哪里操作 | 保存后的结果 |
| --- | --- | --- |
| 已决定安排这场服务，价格还没谈妥 | 项目团 → 新增项目团，默认不勾选保存为草稿，暂不创建订单 | 团为进行中，可准备执行；没有订单 |
| 只想暂存团资料 | 新增项目团 → 勾选保存为草稿 | 团为草稿，不生成订单，不进入执行办理 |
| 服务及价格已经谈妥，子团还没建 | 新增项目团 → 客户已在线下确认，直接创建订单 | 一次保存子团和客户订单 |
| 子团已是草稿，现在谈妥了 | 子团所在行 → 创建订单 → 创建订单并成团 | 一次登记成交，资料齐全的团同时进入进行中 |
| 团已进行中，后来谈妥 | 子团所在行 → 创建订单 | 新增原团首笔订单，团仍为进行中 |
| 客户整包购买多个子团 | 项目团 → 勾选多个未建单的草稿或进行中团 → 批量操作 → 创建订单 → 多团合并一单 | 一张订单覆盖多团，总价只计一次 |
| 多场会议各自成交 | 项目团 → 勾选未建单的团 → 批量操作 → 创建订单 → 每团一单 | 逐团分别生成订单 |
| 已有报价资料，希望沿用内容 | 项目团所在行 → 更多 → 报价 → 按此建单 | 带入资料，核对本次成交后再建单 |
| 单价已谈妥，最终数量未知 | 创建订单时选择按实际数量最终定价 | 先保留订单及计价规则，最终金额待确认 |

通常按“立项 → 建团进入进行中 → 可选报价 → 客户线下谈妥后创建订单 → 执行交付 → 完成与客户结算确认 → 团期结算”推进。若先存草稿，可以单独确认成团，也可以成交时一次建单并成团；建单成功后不重复建团。收款、开票和采购按合同及执行进度穿插办理，不必等服务全部完成才开始。

### 状态与操作入口

“进行中”包括执行准备和正式服务，并不表示已经出发、已成交或已收款。团、报价、订单、结算各自记录自己的阶段，不用一个团状态代替整条链路。

| 业务动作 | 项目团状态 | 报价／订单结果 | 实际操作入口 |
| --- | --- | --- | --- |
| 暂存团资料 | 草稿 | 无新增订单 | 项目详情 → 项目团 → 新增／批量建团，勾选保存为草稿 |
| 正式建团 | 进行中 | 可以尚无订单 | 新增默认不勾选；已有草稿从更多 → 确认成团，只做简短确认或补缺项 |
| 报价 | 保持原团状态 | 报价草稿；登记已报价后为已报价，仍无订单 | 本团更多 → 报价 → 新增报价；多团用批量操作 → 报价 |
| 客户成交，金额已确定 | 进行中 | 订单已确认，已收初始为0 | 本团创建订单，或报价 → 按此建单，核对成交依据和收款计划 |
| 客户确认单价，最终数量未定 | 进行中 | 订单待结算确认，含义是最终价款待定 | 创建订单选按实际数量最终定价；之后进入原订单最终定价 |
| 收款／开票 | 不改变团状态 | 认款后更新已收；开票沿原申请记录更新 | 项目列表更多 → 收款认领；或原订单办理收款及开票 |
| 服务完成 | 已完成 | 不代表已收齐或已结算 | 项目团执行详情 → 确认完成 |
| 核收入、成本、税额并结算 | 团保持已完成 | 结算单按草稿、审批中、已确认推进 | 履约中心 → 团期结算 → 结算；完成后只留详情 |

成交价格来自客户确认的含税总价或单价，不从费用预算取数。固定价订单例如30000元，订金30%为9000元、尾款70%为21000元；成团和建单都不会自动把这两笔变成已收。

## 三 建立大项目并分配费用额度

1. 在单团项目列表点击 **新建项目**，选择客户单位、客户类型和业务分类，填写服务期间、销售、项目负责人及整体服务范围。
2. 年框、多场会议或多线路项目，组织方式选择 **大项目（多个子团）**；只有一次独立服务时选择“单个项目团”。选择默认建团模式，并登记项目组成员和负责事项。
3. 可以先保存草稿；提交核对后留在列表，在该行 **核对 → 确认启用**。启用后点击详情进入项目团工作区。
4. 在列表该行 **更多 → 分工额度**，在同一抽屉登记操作人员、负责事项、负责期间和费用额度，点击 **保存分工**。不再分别办理“新增分工”和“分配费用额度”。
5. 在列表 **更多 → 项目成员** 维护销售、操作、资源、签证等参与人员及负责事项，支持导出参与记录。项目成员登记参与；“分工额度”配置其中操作人员的费用预算，并自动补齐新操作人员的成员记录。
6. 在列表 **更多 → 合同资料** 中维护框架合同；已有致远OA盖章资料时使用 **关联OA合同**，选择本客户、本公司的对应版本。
7. 项目附件、结算期限和结项检查也在该行“更多”办理，详情的项目资料只查看结果。

费用额度是操作人员可承担的费用预算，与负责业务金额和合同金额分开。新项目默认预算管控；历史项目可在“分工额度”启用。正式成团占用本团预算，草稿不预占；确认新采购时累计检查费用预算，超额先调整预算，已发生超支说明原因后如实登记。原采购确认与付款不重复扣预算。项目团预算及人员额度不能调低到现有占用以下。

例如人员额度30万元、子团预算8万元，成团后可用22万元；确认采购7.2万元仍占8万元。结算“附件依据”确认无后续费用，并在原结算正式确认后，释放未使用8000元，人员可用恢复22.8万元。未勾选费用完整、未确认结算或仍有未核对费用时保留预算。

分工额度可选择已有项目成员，也可直接选择其他操作人员，保存后自动补入成员名册，不需要登记两遍。成员页只读展示费用额度；普通销售、签证、酒店等参与登记不会自动获得支出额度。结束成员参与前先移交／完成其未完子团，再收回未使用额度，保留实际费用与历史记录。

人民币项目预算与外币人员额度没有折算依据时，可用额度显示待核对，不混算。项目承担和未分配公共费用在“费用与结算”单独查看，不当作该人员的可付款余额。

OA关联使用原型中的回传资料演示。已签版本作为合同依据，不在这里再发起一遍合同审批；真实自动回传不属于本次操作交付。

## 四 新增子团并登记成交

### 默认成团，或仅保存草稿

进入 **项目团 → 新增项目团**，填写项目团名称、建团模式、服务类型、主责计调、服务日期、地点和计划人数。**保存为草稿默认不勾选**；成交情况保留“暂不创建订单”，点击“创建项目团”，团即为进行中，可维护执行资料，但没有客户订单。

如果仅暂存筹备资料，勾选“保存为草稿”，点击“保存草稿”。此时成交区停用，避免一边选择仅暂存、一边又提交成交。批量建团使用同一个复选框，作用于本次整批；日期生成、导入和逐行核对方式保留。

草稿可继续编辑和准备报价。决定开始执行时，在该团“更多 → 确认成团”；资料齐全只需简短确认，缺项只补缺项。客户已经谈妥时也可以直接“创建订单并成团”，不需要重新新增子团。

### 创建子团时已经成交

在同一抽屉把“成交情况”改为 **客户已在线下确认，直接创建订单**，填写展开的成交和收款资料，点击 **成团并创建订单**。

| 要核对的资料 | 填写含义 |
| --- | --- |
| 订单服务名称、约定服务及计价说明 | 客户本次购买哪些服务，价格覆盖哪些内容 |
| 币种、计价方式、含税总价或含税单价 | 客户已在线下认可的成交条件 |
| 合同依据 | 可引用适用的已签合同；不要引用未签、期间不符或币种不符的合同上限 |
| 客户确认人、客户确认日期 | 实际代表客户确认本次服务的人和日期，不是系统内的审批人 |
| 成交依据及附件 | 合同、确认单、邮件等能够说明本次成交的资料 |
| 收款计划 | 分几次收、每次多少、何时到期或满足什么条件后收 |

创建成功后，结果抽屉显示订单号、金额、订单状态和关联项目团执行阶段，提供 **查看订单、收款计划、收款认领、进入团控**。正常资料齐全时团已为进行中，不再出现一遍完整确认建团表单。历史草稿有缺项时保留已建订单，仅补缺失的执行资料。

## 五 选择计价方式和收款计划

### 三种计价方式

| 计价方式 | 适用情况 | 录入内容与订单结果 |
| --- | --- | --- |
| 固定总价 | 客户已确认这一场或整包服务总价 | 填客户确认含税总价，例如30000元，订单金额即30000元 |
| 确定数量 × 单价 | 计价数量已经确认，按人数、场次、间夜等收费 | 例如确定60人，每人500元，订单金额30000元 |
| 按实际数量最终定价 | 客户已认可单价和服务，但最终数量还会变化 | 填预计数量及已确认含税单价，订单金额保持待最终定价 |

“按实际数量最终定价”中的60人×500元只能作为预计30000元，不能直接当作已确定成交金额。实际完成数量明确后，使用第八节的最终定价操作。

### 收款计划如何填写

在建单抽屉的“收款计划”中逐行填写阶段名称、金额或比例、到期日和收款条件。可用 **增加收款阶段** 增加中期款，也可删除不需要的阶段。

固定总价30000元时，示例为：

| 收款阶段 | 约定比例 | 阶段应收 |
| --- | --- | --- |
| 订金 | 30% | 9000元 |
| 尾款 | 70% | 21000元 |
| 合计 | 100% | 30000元 |

30%与70%只是默认演示比例，应按客户约定修改。已明确总价的订单，所有阶段金额合计必须等于订单金额；阶段应收不等于已经收到的钱。

新建“按实际数量最终定价”的订单时，当前表单只支持合计100%的比例阶段，阶段金额待最终定价后计算。最终金额未定但已经提前到账的款项，从原 **预收管理** 承接；本次没有新增自动将预收核销到订单的操作。

“计税参考与成交附件”可展开维护。销售端录入的税额参考不能替代财务核定税额。

## 六 一个创建订单入口，按成交范围办理

单团行和批量操作菜单均使用 **创建订单**，打开同一套抽屉。只选一个团时直接填写；选择多个团时才显示“每团一单／多团合并一单”。菜单不再保留“逐团创建订单”和“整包建单”两个独立入口。

### 多个团分别成交

1. 勾选尚未建单的草稿或进行中团，点击 **批量操作 → 创建订单**。
2. 选择 **每团一单**。顶部列表逐团显示本次金额和收款阶段。
3. 点击对应团的 **编辑**，在下面同一份表单中核对计价、成交依据和收款计划；不同团可以使用不同计价方式和分期。
4. 点击 **创建N笔订单**。包含草稿时按钮同时标明成团，结果列出各自订单、已收和待收及收款入口。

例如A团20000元、订金40%／尾款60%，B团50人×500元、订金30%／尾款70%，分别形成两单；各期为8000／12000元与7500／17500元。无需为分期再换到另一套抽屉。

### 多个团作为一笔成交

同一抽屉选择 **多团合并一单**，核对覆盖的全部团，填写整包价格和一份收款计划，点击 **创建1笔订单**。

例如两个团整包80000元，只生成一个订单号、计80000元；30%订金24000元、70%尾款56000元。不把总价复制给每个团，不自动平分各团收入或毛利。

切换建单方式或编辑其他团，会保留本次尚未提交的价格、收款阶段和附件。每团独立资料与整包资料分别保存，不互相覆盖。关闭抽屉放弃修改后不保留未提交内容。

批量提交先核对全部订单；分期金额不平、已有有效订单、报价正在审批、合同合计超限等情况不先创建部分订单，修正后再提交。

## 七 报价：保存服务和价格，不自动建单

需要在系统保存方案和价格测算时，从 **项目团所在行 → 更多 → 报价 → 新增报价** 办理。

多团同时准备报价时，勾选未建单的草稿或进行中团，点击 **批量操作 → 报价**；这只保存价格资料。**修改团资料** 则批量维护草稿团日期、地点、人数和预算，不涉及成交。批量按钮仅处理所选范围；进行中无订单的团可准备报价和建单，但不可批量改草稿资料；已完成团不能重复成交。批量菜单只显示操作名称，不符合条件的操作置灰。可用“客户订单情况 → 未建单”筛选后再勾选；已有订单或报价继续从原记录办理。查询／重置会清空旧选择，建单成功后移除本次已办理团的勾选。

**分配计调／移交项目团** 针对具体未完成子团：前者指定负责人，后者登记换人及交接原因；不会另给这个人增加一笔费用额度。

- **保存报价**：保存准备中的资料。
- **登记已报价**：登记已向客户报价的事实，沟通仍在线下进行。
- **按此建单**：客户已经谈妥后，进入同一个“创建订单”抽屉，带入该报价并核对成交依据和收款计划。

也可以直接点击项目团行的 **创建订单**：已有覆盖范围一致、未用于有效订单的报价时，自动带入最近保存的报价版本、价格、计税参考、附件和收款阶段。有多份适用报价可在“引用报价”中切换，也可选“直接填写成交价”。引用报价不修改原报价；报价备注不会自动充当客户成交确认依据。

整包报价只在完整覆盖的多团合并订单中引用，不把整包金额填入某一个团。多个团有完整整包报价时，抽屉默认选择“多团合并一单”；改为分别成交时需核对各团价格。

前两个动作都不会生成订单，也不把报价金额计为已成交。报价被订单采用后，查看原报价及关联订单；后续订单价格变化从原订单办理，不修改准备资料来替代订单变更。

历史审批中的报价继续原办理，不另建一张覆盖相同服务的订单。新成交路径不要求额外增加一次“销售确认报价”审批。

## 八 按实际数量确认同一订单的最终价款

客户认可实际服务数量后，从 **客户订单 → 订单详情** 进入原单，点击 **确认最终价款**。

1. 在“确认订单最终价款”抽屉核对原订单、客户、已确认单价及原成交依据。
2. 填写客户认可的实际数量、确认日期、客户确认人和实际数量及价款确认依据。
3. 核对计算出的最终总额和各收款阶段。
4. 点击 **确认最终价款**，回到同一张订单查看结果。

例如预计60人、含税单价500元，实际客户认可64人：最终总额为32000元；原30%订金、70%尾款相应变为9600元、22400元。**订单号保持不变，不再新建订单，也不会因此增加已收款或已开票金额。** 历史订单原来约定固定阶段金额时，需要在本抽屉核对各阶段合计。

已经确定总价后又有增减项、折让或争议改价，进入原订单“售后变更”办理。关联结算已经提交或确认时，应先处理原结算；不能在已提交的结算之外直接覆盖原订单金额。

## 九 开票与收款分别办理

在项目详情 **客户订单** 核对成交金额、已认款、待收和已开票；具体收款阶段及申请记录进入原订单查看。

### 收款认领

收款认领是把已经到账的款项分配到对应订单；财务认款是核实这笔分配后正式计入订单已收。

1. 单笔订单从 **订单详情 → 应收收款** 进入原认领；多单合并到账从 **单团项目列表 → 更多 → 收款认领** 进入原收款认领页面，点击 **认领款项**。项目范围会带入。
2. 在“收款认领与分配”抽屉选择本客户、我方公司和币种一致的到账流水。
3. 核对每张订单本次认领金额，选择“订金”“尾款”等阶段，或选择 **按剩余应收分配**。
4. 填写客户付款及归属依据，点击 **提交认领**。此时状态为待财务认款，订单已收金额不增加。
5. 从认领记录 **查看复核**，在原认款复核页面点击 **复核**，填写复核意见后 **确认认款**。确认后才增加对应订单和收款阶段的已收金额；有问题则退回认领。

30000元订单先认款9000元订金，订单已收为9000元，剩余待收21000元。一个到账流水可按条件分给多张订单，不能重复认领，也不能超过订单或所选阶段剩余金额；没有分配完的款项留在原流水。

订单还未最终定价时，先核定价款再按订单认领。提前到账使用原预收管理，不能把预计金额当作确定应收来分配。

### 开票申请

在对应订单点击 **开票申请**，按原抽屉核对抬头、票种、开票项目、金额和依据，提交给原财务办理流程。结果和票据资料回到原订单查看。

申请提交不代表已经开票；开票也不代表已经收款。真实电子开票平台、PDF自动回传和客户发送不作为本次原型已接通的能力。

## 十 执行采购与两类详情的分工

| 页面 | 在这里办理什么 | 与下一步的关系 |
| --- | --- | --- |
| 履约中心 → 项目团 → 项目团控 → 详情 | 行程、会议议程、人员资料、分组分房分车、签证进度、资源安排、执行准备及服务完成 | 为客户核对及结算提供实际交付资料 |
| 履约中心 → 项目团 → 项目采购 | 通过新增采购登记线下谈妥的供应商、服务、含税金额、税额资料、费用归属及确认依据 | 集中管理项目公共采购和跨团采购；按实际归属供各团核对 |
| 履约中心 → 团期结算 | 维护本团成本、核对费用分配、收入、收付款、税额、依据并提交结算 | 形成结算记录，继续原审批及财务承接 |

供应商询价、比价和沟通在线下进行，系统不要求先创建询价单。项目采购和团期结算引用同一笔采购资料，不能在两个页面各录一笔相同费用。

项目团执行详情保留八个页签：**总览、执行安排、报名名单、签证进度、资源安排、关联订单、执行准备、操作日志**。名单的新增或编辑负责人员资料；“分组分房分车”负责逐人安排，同批相同内容可用其中的“统一填写一项”。签证进度另按本团要求及个人办理情况核对。

结算详情使用独立的十个页签：**单据总览、收入明细、优惠减免、成本明细、订单明细、收款预收、预付付款、变更记录、附件依据、结算记录**。

执行期间就可以维护成本。服务完成后在项目团详情 **确认完成**，记录实际完成及交付依据；确认完成不等于财务已结算。

## 十一 客户结算确认与成交确认的区别

**原“客户对账”现称“客户结算确认”，不是报价确认。** 两者发生时间和处理结果不同，当前页面另有“最终定价”，也要分别理解。

| 事项 | 什么时候发生 | 客户确认什么 | 当前系统处理结果 |
| --- | --- | --- | --- |
| 线下成交确认及系统成交登记 | 客户同意购买本次服务时 | 服务范围、总价或单价、收款条件 | 创建客户订单；没有独立的线上客户确认审批 |
| 最终定价 | 按实际数量计价，客户已认可最终数量时 | 实际数量和依原单价计算的最终价款 | 更新同一订单总额和收款计划 |
| 客户结算确认 | 服务完成或整包中的阶段交付完成后 | 已完成的服务、认可金额、争议，或本次交付范围 | 保存客户认可记录，供业务结算核对；不直接改原订单金额 |

### 当前原型怎样操作客户结算确认

入口为 **单团项目列表 → 更多 → 客户结算确认**；已有记录可在该抽屉展开继续办理，或在详情“客户订单”底部只读查看。

1. 核对客户、我方公司，选择核对期间和币种。期间应覆盖要核对的项目团服务结束日期，才能列出相应订单。
2. 选择核对内容：**结算金额与服务确认** 用于核对完成后的服务与金额；**整包交付进度确认** 用于多团整包中的阶段交付，仅确认本次已完成范围。
3. 选择本次订单。金额核对时填写本次认可金额和争议金额；有争议填写原因。
4. 填写客户确认人、确认日期、客户确认凭据及适用的确认资料。可以 **保存草稿** 或 **登记待客户确认**；客户在线下已确认后再点 **登记客户确认**。
5. 全部认可后，相关项目团取得客户认可记录。部分认可保留争议，后续需要改价时从对账详情进入 **办理订单金额变更**。

已确定金额的订单，本次认可加争议应等于原订单金额。例如原单30000元、认可28000元、争议2000元，系统保留原30000元及争议记录；不会因填写28000元就自动把订单改为28000元。

### 成交金额与交付认可分别登记

当前项目团提交结算会检查“客户已认可”或“进度已认可”。因此，**固定总价且没有增减项的订单，目前仍需通过客户结算确认登记交付认可**。这次记录的业务含义是完成及结算依据，不是再谈一次价格。

“确认最终价款”目前只更新原订单及收款计划，并不会自动生成客户结算确认记录。按实际数量计价的订单，当前试用顺序为：**原订单确认最终价款 → 服务完成 → 客户结算确认登记认可 → 团期结算**。客户结算确认中原有的未定价数量和单价字段，不能替代原订单最终定价操作。

本次已调整名称、入口和说明；认可的业务前置条件保持原规则。自动复用最终数量和确认附件、进一步减少重复填写仍是后续待优化事项，不能把已改名理解为已完成自动认可。

## 十二 提交团期结算并查看大项目汇总

1. 进入 **履约中心 → 团期结算**，筛选项目团并找到本团。点击 **详情** 查看单据；需要办理时按状态点击 **结算、继续结算或修改结算**。
2. 在“单据总览、收入明细”核对原订单、客户认可、收入范围，以及含税、预计扣税后和核定扣税后的金额。整包收入未明确归属时按缺项核对，不能重复计入每个子团。
3. 在“成本明细”核对直接费用、跨团分配、本次承担、项目承担和未分配费用。采购总额与本团承担额分别核对。
4. 在“收款预收、预付付款”核对原单据和分配。客户欠款、供应商未付款与业务结算状态分开查看，不能因为提交结算就视为钱已收付。
5. 在“附件依据”填写本次结算依据、未结事项及附件，点击 **保存依据**。根据页面缺项补齐服务完成、客户认可、费用确认等资料，再 **提交结算**。
6. 在“结算记录”查看本次提交、审批及历史版本。提交后进入原审批，尚不等于结算已确认。
7. 结算完成后列表只保留 **详情**。确有后续差额时，从详情的结算记录进入原二次结算办理。

核定税额缺失时，相关结果应保持待确认，不能按零税额补算毛利。票面税率、预计可扣税额和财务核定扣税额是不同资料，不可互相替代。

返回大项目的 **项目团** 看执行进度，**客户订单** 核成交和款票，**费用与结算** 核承担、税额及结算。父项目按同一订单和同一采购计一次；各子团承担明细用于解释归属，不再重复增加项目总额。大项目汇总不等于另行完成了一次财务总体结算。

## 十三 常见操作问题

| 遇到的情况 | 如何处理 |
| --- | --- |
| 子团已经创建，为什么没有订单 | 成团与成交是两件事；默认成团也不会自动生成订单，谈妥后从该团创建订单 |
| 为什么看不到创建订单 | 当前新成交入口面向尚未建单的草稿或进行中团；已有订单查看原单，已完成团不要重复建单 |
| 如何直接试批量操作 | 全部13个预置项目均有草稿、进行中和已完成案例。草稿可批量修改；未建单的草稿或进行中团可报价、逐团或整包建单；原完成案例继续用于结算。首次补入后保留用户操作，不随刷新重置 |
| 建单提示收款计划不一致 | 已知总价时核对阶段合计；最终金额待定时使用合计100%的比例阶段 |
| 一笔客户汇款支付多场会议 | 在项目列表“更多→收款认领”进入集中认领，按对应订单和阶段分配，保留未分配余额 |
| 提交了认领，已收金额没变 | 认领仍待财务认款；从查看复核继续原认款操作 |
| 已确认最终价款，结算仍提示客户未认可 | 最终定价和客户结算确认目前分开保存；按第十一节登记交付及结算认可 |
| 客户结算确认里找不到本团订单 | 核对项目、币种和核对期间；检查订单是否已纳入其他有效对账记录 |
| 价格或服务发生变化 | 从原订单售后变更办理，不能重复创建订单，也不能仅改报价或对账金额 |
| 项目总额和某个子团显示的包价一样 | 先看是否一张整包订单覆盖多团，不能把每个团显示的包价再相加 |

## 十四 用一场会议走一遍

以下是操作示例，金额不代表公司的统一定价或收款规则。

1. 在已启用的年度会议项目中新增“杭州渠道会议”，费用预算20000元，客户确认含税总价30000元。
2. 选择客户已在线下确认，登记成交依据，收款计划设订金30%、尾款70%，点击成团并创建订单。
3. 记下生成的订单号，核对订金9000元、尾款21000元；项目团已为进行中，直接进入团控。
4. 执行人员维护报名名单、会议安排和资源；在项目采购登记线下确认的供应商服务。涉及本团成本及分配，在团期结算按本团核对。
5. 客户订金到账后认领9000元到原订单的订金阶段；财务确认认款后，查看订单已收9000元、待收21000元。需要开票时另提交开票申请。
6. 服务结束，在项目团详情确认完成；从项目列表进入客户结算确认，核对原订单30000元、认可30000元、争议0元，并登记客户认可依据。
7. 在团期结算核对收入、承担成本、税额及附件依据后提交，随后查看原结算记录。
8. 返回大项目检查：该订单只计30000元；收款、开票、费用承担和结算状态各有自己的记录。

若客户实际按人数结算，第2步改选“按实际数量最终定价”，并按第八节核定实际数量后继续原订单；不要把这个例子的固定总价直接套用。
