# 数据中心全页面分析与优化方案

> 日期：2026-09-15。状态：分析与设计建议，尚未实施。依据当前页面代码、浏览器实际呈现、财务需求基线及已确认方案。覆盖四组16个菜单、71个业务Tab。本文中的“建议”“应”均为待实施的产品方案，不代表现有页面已经具备这些能力，也不批准尚未确认的财务政策。

## 一、结论：问题不只是表格太多，而是缺少分析主线

用户对收款Tab的判断成立。目前多个页面把“分析结果、查询合计、原始记录、分配核销记录、异常记录”按照实现顺序连续摆放，使用者必须自己判断哪些金额可加、哪些只是重复引用、应该先看哪张表。部分页面进一步存在重复结果、页面职责重叠和筛选范围不一致的问题，仅调间距、折叠表格不能全部解决。

**本方案的核心是：每个Tab明确一个主要问题、一种默认行含义、一条阅读路径；默认展示一个主结果，依据按需切换，跨主题内容归回已有专门Tab。** 财务需要的完整核对能力保留，但完整性不等于全部同时展开。

“一个页面不能有多个报表”不宜理解成技术上只能有一个表格。例如，短小的总分核对与其唯一明细、同一结果的图与表可以共同服务一个问题。真正应禁止的是：不同业务目的、不同日期依据、不同金额可加规则的多份报表，没有主次地连续展示。单纯把五张表塞进五个折叠区，也没有解决这个问题。

### 1.1 实页盘点结果

本次逐一打开16个菜单，切换全部71个Tab，并读取对应共享逻辑；浏览器未出现页面脚本错误。下表统计**默认展开的表格数量**，不等于首屏内能看到的数量，不包含关闭状态的依据区。

| 默认展开表格 | Tab数 | 判断 |
|---|---:|---|
| 1张 | 30 | 基本结构可保留，仍需审计业务目标、字段及口径 |
| 2张 | 8 | 判断是否为必要总分关系，不能一律判错 |
| 3张 | 9 | 优先检查依据平铺、重复明细和范围混用 |
| 4张 | 8 | 优先重组主次及页面职责 |
| 5张 | 15 | 高度影响阅读，需逐表确定保留方式 |
| 6张 | 1 | 集团调整，需把汇总、调整及依据分层 |

合计41个Tab默认多表展开，其中33个至少3张，16个至少5张。最明显的是收付明细四个Tab各5张、月度损益各5—6张、票款核对四个Tab各5张。渠道毛利校验、供应商采购汇总等已有关闭的依据区，不能把这些也算成默认平铺问题。

### 1.2 问题来源及处理原则

| 类型 | 当前证据 | 产品处理 |
|---|---|---|
| 核对依据被当作并列报表 | 通用报表组件把每个补充结果逐个追加在主表之后 | 改为一个主结果区，用“查看内容”选择当前要看的结果或依据；同一时刻呈现一种行含义 |
| 同结果重复 | 公司损益主表后又有公司核对；账户收支后又展示完整收支依据；成本分配又列同份分配记录 | 主表已经表达的信息不再生成第二份表；补充字段通过显示字段提供 |
| 页面职责串用 | 任务预算的批准预算复用预算差异，连带会计确认、费用分配、内部结转依据 | 批准预算看计划及版本；实际差异回月度损益，不能只改标题 |
| 筛选范围与依据范围不同 | 产品/渠道贡献筛到具体销售内容后，部分会计和费用依据仍按公司期间提供 | 能关联到选择范围的依据才参与该范围核对；公司完整记录需明确独立范围，不伪装成选中产品的依据 |
| 财务上下文被弱化 | 日期控件并排、通用字段名、说明统一隐藏，页面自身不总能说明发生期还是余额截止日 | 依靠控件值、准确表头和短结果名称表达必要上下文；不恢复大段说明面板 |
| 原型用例集合影响理解 | 收款默认列表存在相同可见单号、相同金额的独立场景记录；不同页默认期间不统一 | 后续准备一套可阅读的常规样例，边界场景在验收页验证；本轮未据此认定真实资金重复计算 |

历史实现为保证“不点击下钻也能查完整依据”，持续追加依据表有其背景。但“可以核对”与“默认全部列出”是两回事。本次是对内容组织再审计，不否定原功能测试通过，也不把旧验收当作阅读体验已经合格的证明。

## 二、共同财务阅读规则与交互方案

### 2.1 先定义财务在看什么

首次使用以下概念时，页面及帮助资料需保持一致：法人主体是依法承担交易责任的公司；核算主体是独立记账并出具账务结果的单位；核销是用已确认款项抵减对应应收或应付；暂估是依据业务事实先估计确认、以后再调整；内部往来是集团内公司间相互应收应付；会计期间是该笔账务计入的月份或期间；辅助核算是按部门、产品等进一步分类看账。法人、核算公司、销售公司、产品责任公司和实际收付款公司不能用一个泛称“公司”替代。

每个Tab必须回答五个基础问题：

1. **一行是什么？** 一笔到账、一笔分配、一项销售内容、一个团期、一家公司一个月，不能含混。
2. **何时的数？** 成交日期、实际完成日期、资金发生日期、会计期间、截至某日余额分别表达。
3. **谁的数？** 按本次分析所需责任公司、部门、渠道和账户明确归属。
4. **哪些数可以相加？** 原款与其分配不能相加；月末余额不能跨月求和；不同币种不能直接合计。
5. **看完得出什么判断？** 经营变化、成本缺口、未收余额、资金缺口、票款差异、预算偏差应各有明确结果。

### 2.2 共用页面结构

保持已确认的四组16入口和71个单层业务Tab，不新增一排“汇总/明细/依据”业务Tab，不恢复跨菜单快捷链接。沿用Tab置顶、无内容页标题、筛选与结果分卡、导出在重置之后、隐藏长口径说明的既有规范。

推荐结构：

```text
现有业务Tab：收款 | 退款 | 转款 | 付款

查询卡：公司、日期类型与日期、币种、交易对象、更多筛选
        查询  重置  导出当前结果 ▼

结果卡：收款单据明细      查看内容：[单据明细 ▼]    显示字段
        当前条件的简短结果名称 / 必要时按公司和币种分组的小计
        一张主表
        全部结果合计、条数及分页
```

“查看内容”只切换同一业务主题下的观察层次，例如单据明细、订单分配、原款记录、核销记录、差异记录，**替换当前结果表，不在下面继续追加**。不是增加业务Tab，也不是点击金额或单号下钻。已有“统计内容”只在确有不同指标选择时保留，不与“查看内容”表达同一功能。

处理顺序：先删除重复呈现；再把不属于当前主题的报表移回已有Tab；剩余必要依据通过查看内容切换。只有确实需要同时核对的短总分结果，才保留简短合计或固定对照区。不要把所有页面机械套成很多下拉选项：原本清楚的单表Tab不加这个控件。

### 2.3 结果、依据、异常分别承担什么

| 内容 | 展示方式 | 约束 |
|---|---|---|
| 主分析结果 | 默认的一张表，可配同一范围的少量指标或一张有用的图 | 有唯一行含义；列顺序符合“对象—结果—差异—原因” |
| 同范围合计 | 主表页脚或按公司、币种分组的小计 | 明确全部查询结果合计与当前页小计；非可加值不求和 |
| 分配与原记录 | 查看内容切换，使用对应筛选和分页 | 显示被引用的原金额，但不把它当可加发生额 |
| 异常 | 当前主题的差异查看方式，或主表状态筛选 | 区分数据缺失、真实差额、正常未到期与业务风险 |
| 另一主题分析 | 归入已有对应Tab，在本文明确归属 | 不用“补充表”继续挂在当前主表下 |

### 2.4 筛选、输出与财务习惯

- **日期随问题变化。** 发生明细用起止日期；余额用截至日；预算用年度/月度和版本；资金计划用未来区间。必须用“发生日期”“截至日期”等控件内前缀或清晰名称区分，不要求恢复外置标签。
- **只保留生效条件。** 某Tab没有部门依据，就不显示一个看起来会影响结果的部门条件。切Tab沿用现有独立查询状态，输出以已成功查询的条件为准。
- **常用条件优先。** 公司、期间、币种、核心对象直接可见；低频业务类型、来源记录和特殊核对条件进更多筛选。隐藏长说明不能隐藏期间、币种、版本等决定金额含义的信息。
- **财务列的顺序。** 识别列固定左侧，金额右对齐、千分位、统一小数位；同组金额使用同单位；负数保留负号，零、缺数、不适用分别表达。说明不挤占主要金额列。
- **比较有同一基础。** 同比、环比、预算完成率都要求同期间长度、同范围、同币种、同有效版本；预算为零或未批准时不硬算完成率。毛利率用合计毛利除以合计收入，不平均各行比率。
- **选列有边界。** 保留原有字段能力，但默认只放完成当前判断必要的字段；账户、长说明、来源编号等按场景进入可选列，不能把币种或关键日期都藏掉。
- **查询只读。** 报表不放认款、核销、退款、付款、开票、推送等办理动作；金额、单号和行不设点击下钻。管理Tab可以保留其职责范围内的维护动作。
- **输出与当前问题一致。** 默认导出当前查看内容的全部查询结果，单表单表头；完整核对资料作为单独输出选项，按内容分文件或工作表。不要把多块异构表纵向拼在一个CSV内，让财务再拆表。完整输出必须包含查询条件、币种、期间、版本与各表行含义。
- **真实金额与核对范围。** 多币种分币合计；折算币种、汇率及集团抵销政策未批准时，不自动给一个“集团总金额”。未完成财务确认不能以成交或回团金额直接填成收入。

以下各页的“建议默认字段”是设计取舍，不是本轮修改。完整核对字段继续有查询或输出位置。

## 三、经营分析：6个菜单、33个Tab

### 01 经营总览

**用户与位置：** 集团管理层、经营负责人、财务负责人；承接销售、完成、损益、资金、计划和资源结果。首要任务是判断本期经营表现及需要关注的领域，不在此核对每一笔会计分配。下游是经营决策和对应专门报表的独立查询。

**阅读顺序：** 选公司和时期 → 看核心结果与可比变化 → 看主要差异来自哪些公司/类别。总览是摘要，不是所有明细的合集。

| 编号 / Tab（展开表数） | 分析目标、行含义与时间 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC01-01 经营规模（4） | 管理层看订单、完成规模和任务差距；默认每行销售公司，期间发生与月/年累计分别标明 | 主结果后接任务、趋势、未来安排，四种问题连续展开；与计划概况重叠 | 主表保留本期、可比期、增减、月累计及任务差额，年度列按需显示；任务金额并入主结果，趋势用图表切换，未来安排归计划概况。验收同口径任务不再独立重复、未来数不混入本期规模 |
| DC01-02 损益摘要（2） | 财务负责人快速看各公司收入、成本、费用及经营利润；按会计期间 | 摘要下展开会计原记录，阅读从管理问题突然转到底账；存在与月度损益重复铺陈 | 默认公司损益摘要和一个差异排序；移除逐笔依据默认展示，完整核对归月度损益/核算核对。结果名称标明未抵销或有效集团口径。验收成交额、业务毛利不被替代成核算收入利润 |
| DC01-03 资金概况（2） | 财务负责人看截至日资金余额、期间净收支和可用资金 | 账户摘要与实际流水同级；发生区间和截止日需要区分 | 主表每行实际资金公司或账户组，列期末余额、可用余额、期间流入流出、净额；流水归资金分析。验收内部账户调拨不解释成新增经营现金 |
| DC01-04 计划概况（2） | 管理层看已售业务将在哪些月份完成；每行计划月份/公司 | 计划汇总后接逐项依据；与经营规模未来表重复 | 只保留未来月份分布、已售未完成金额/人数及未排期，按月柱图可选；逐项业务在回团明细已售未完查。验收无计划日期单列，不归入任意未来月份 |
| DC01-05 风险概况（2） | 财务和经营负责人看风险集中程度与金额 | 当前主要是资源批次明细及依据，缺少“概况”层次 | 默认按风险类别/责任公司汇总数量、涉及金额、临期金额；若当前来源只有资源风险，明确显示资源范围，不能伪装覆盖所有风险。具体批次归业务毛利资源风险。验收不同性质风险金额不简单累加成总损失 |

### 02 月度损益

**用户与位置：** 总账/管理会计、财务经理、公司和部门负责人。承接已确认收入成本、费用、责任归属和批准预算；回答“利润怎样形成、与预算差在哪”。会计期间是主日期，不用出团日或到账日替代。经营利润的费用覆盖范围按现有批准范围表达，不能直接称法定净利润。

**主要缺陷：** 五个Tab共用一组公司汇总及依据，导致公司损益重复、费用页夹公司总表、预算页夹内部结转记录。应为各Tab分别组织结果，不能只重排共享模板。

| 编号 / Tab（展开表数） | 目标及默认字段 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC02-01 公司损益（5） | 每行核算公司/币种/期间；收入、成本、毛利、费用、经营利润及完整性 | 主表与“公司核对（未抵销）”重复，下接三类依据 | 删除第二份相同公司表；主表展示利润形成过程，收入成本、费用记录按查看内容切换。验收利润等于已批准口径下的收入减成本减费用，缺失费用不能显示为完整利润 |
| DC02-02 部门损益（5） | 每行公司内部门；收入、成本、毛利、归属费用、管理结转、利润 | 通用公司依据占篇幅；默认缺少直观的毛利中间层，管理结转易被误读为新增收入费用 | 增加毛利结果层，直接费用与分配费用可分列，未归属单列；管理结转以转入/转出或净影响表达，不改公司总额。验收部门及未分配合计与公司结果衔接，结转双方相抵 |
| DC02-03 费用构成（5） | 财务看哪类费用增长；默认每行费用类别，按期间 | 当前偏费用记录列表，配套公司和会计表使“构成”不突出 | 默认类别、金额、占比、可比期差额；部门可作为分组选择。费用单据及部门分配作为另一查看内容。验收占比分母为当前有效费用范围，原费用在多个部门分配后不重复计入 |
| DC02-04 预算差异（5） | 负责人看预算与实际偏差；每行公司/部门的指标 | 差异统一实际减预算，但收入和费用的好坏方向相反；依据多且预算版本不够突出 | 默认指标、批准预算、实际、差额、差异率、方向、原因分类；收入不足和费用超支分别判断。预算版本必须可辨，明细依据按指标查看。验收零预算、未批准、范围不同均不误判达成 |
| DC02-05 集团调整（6） | 集团财务看公司汇总如何形成集团结果 | 汇总三行之外又铺公司、会计、费用、结转、抵销依据，内部管理结转与集团抵销容易混淆 | 默认三段桥接：公司合计→已确认抵销/调整→调整后结果；按收入/成本/费用/利润对照，调整明细替换主结果查看。验收只有批准范围进入调整后结果，内部部门结转不重复参与集团抵销 |

### 03 产品分析

**用户与位置：** 产品负责人、经营分析、管理会计。承接产品责任、成交/完成、渠道及已确认成本费用；回答“哪些产品形成规模、未来业务和贡献”。产品归属、销售归属与供货来源不能混为一个分类。

| 编号 / Tab（展开表数） | 目标及默认行与期间 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC03-01 经营业绩（2） | 产品负责人比较各产品责任单位或产品的成交/完成及任务，选定业务日期 | 主结果与任务比较分表，读者需来回找同对象 | 同对象的实际、任务、差额及完成率并入主表；年度低频指标选列。允许选择产品、目的地、类型等一种分组，不同时混多层总计。验收任务与实际的归属和期间一致 |
| DC03-02 产品结构（1） | 看产品类型与自营/内部/外采等来源的结构 | 单表方向合理，但金额指标和占比分母必须明确 | 保留矩阵，行产品类型、列来源类型，配合计与占比；只显示本次选定成交或完成指标。未分类独列。验收各来源合计等于行总计，不把未知来源隐藏 |
| DC03-03 渠道构成（1） | 产品负责人看产品通过哪些渠道销售 | 当前所选渠道金额、渠道内占比及渠道贡献占比并存，两个分母易混淆 | 默认产品×渠道构成矩阵，主占比明确为该产品各渠道占比；跨产品的渠道结构作为显示方式选择，不能用相同“占比”列名。验收100%的合计方向明确 |
| DC03-04 跨年收客（2） | 看本年接单有多少在本年/以后完成；成交年度与计划完成年度交叉 | 交叉表、未完成安排表连排，通用成交构成图不完全适配 | 默认接单年×计划完成年矩阵；累计已完成、未完成清晰分列。未完成月份分布作为替换视图；同比按相同观察截止日。验收已售总额分解不重计，未排期独列 |
| DC03-05 经营贡献（4） | 管理会计看产品收入扣除成本与直接相关费用后的贡献；会计期间 | 主表、逐销售内容、公司会计依据及费用依据平铺；后两者可能超出所选产品 | 主表产品/责任公司、收入、成本、毛利、佣金/平台费/优惠/其他直接费用、贡献。逐项与关联依据按需切换；无法分配费用单列公司未分配，不强摊。验收筛选产品后依据与贡献可解释且不把公司全部费用冒作该产品费用 |
| DC03-06 产品风险（1） | 产品负责人看资源承诺、已分配和未消耗占用 | 单表清楚，但资源批次与产品汇总层次需说明 | 默认按产品归集风险批次数、采购金额、已分配、未分配及临期量/额；批次记录作为查看内容。产品无法确定的资源不得强归属。验收同批跨产品分配金额不在各产品重复算全额 |

### 04 渠道分析

**用户与位置：** 销售负责人、门店/呼叫中心管理者、渠道财务。承接销售责任、订单/完成、渠道费用与结算校验。回答“谁带来业绩、卖了什么、扣除直接费用还贡献多少”。不同Tab服务不同角色，不应全部套成一个渠道排行榜。

| 编号 / Tab（展开表数） | 目标及默认行与期间 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC04-01 渠道概况（1） | 销售负责人比较渠道规模；每行渠道大类/渠道 | 默认净额、订单数及归属/金额缺口较突出，经营比较不足 | 主表净成交或实际完成、占比、可比期差额及有效任务；缺口用筛选和一个必要提示承接。统计订单数去重。验收不以销售内容行数代替订单数，缺数不填零 |
| DC04-02 门店业绩（1） | 区域/门店负责人看门店业绩及达成；每行门店 | 公司、性质、预算区域等识别信息较多，主结果的任务比较需聚焦 | 默认门店、所属公司/区域、有效金额、任务、完成率及变化；门店性质等低频项选列。只评价销售结果，不在此办理预存。验收历史门店归属按有效时期取值 |
| DC04-03 呼叫中心（1） | 中心负责人按中心/组/顾问看业绩与完成 | 基本明细具备，但层级比较及人均口径不应靠猜 | 每次只选一个组织层级；保留净成交、有效订单、任务与完成率，客单价可选；人员基数不全时不提供人均排名。验收调组记录不造成历史归属漂移、跨组重复 |
| DC04-04 产品构成（1） | 渠道负责人看本渠道卖哪些产品 | 与产品分析渠道构成接近，双占比可能重复含混 | 行渠道、列产品类型/产品组合，默认在渠道内部看产品占比；产品侧为反向矩阵。验收同范围两页金额一致，仅观察方向不同 |
| DC04-05 经营贡献（4） | 渠道财务比较渠道扣除直接费用后的贡献 | 同产品贡献，明细和公司级依据平铺、过滤范围混合 | 默认渠道贡献表；可区分渠道与具体客户，不将客户查询变成默认逐客账单。费用分配、逐销售内容、确认依据切换查看。验收优惠、佣金、平台费用的业务与会计扣减不重复 |
| DC04-06 毛利校验（1） | 结算/渠道财务核对还原前后金额及异常，按适用业务范围 | 已有折叠依据，非默认多表问题；财务模板中的不同10%比较含义不能混同 | 保留校验专用表，突出基础毛利、还原因素、还原后结果、触发原因和依据完整性；三类依据一次选一种查看。验收区分缺数与超阈值，10%仅按原待确认定义演示，不自动推广为统一利润红线 |

### 05 业务毛利

**用户与位置：** 计调负责人、成本结算财务、业务负责人。承接实际完成、成本确认、结算与资源分配；回答“这批业务赚了多少，结果是否完整，资源还压在哪里”。业务毛利不等于会计期间利润，也不等于产品/渠道扣费后贡献。

| 编号 / Tab（展开表数） | 目标及默认字段 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC05-01 毛利明细（1） | 每行团期/项目或可独立结算业务；实际完成日期、业务收入、确认成本、毛利/率、结算状态 | 单表合理；完整与未完整成本结果可能被同等阅读 | 主表先按完整性区分可评价结果与待确认结果；缺成本金额不可当作高毛利。原依据保留按需查看。验收完整业务小计和全部业务规模不同范围有明确名称 |
| DC05-02 部门毛利（1） | 每行责任部门，看业务毛利与结算覆盖 | 默认覆盖数量、缺口与金额较多，13列并列影响主次 | 默认收入、确认成本、可评价毛利、毛利率、未完成结算业务数；覆盖明细选列。验收毛利率按可评价范围加权，不用全部收入配部分成本 |
| DC05-03 结算异常（1） | 发现成本缺失、差异及负毛利；每行业务 | 真实经营亏损与资料缺失、流程未结束可能同叫异常 | 稳定列出业务、异常类别、涉及金额、缺项、结算状态；以类别筛选，不为每种异常造办理按钮。验收正常未结算与应完成未完成可区分，负毛利不被当作数据错误 |
| DC05-04 结算调整（1） | 看结算结果为何变化；每行一笔调整 | 原完成日期、调整日期、财务期间等13列并列，影响前后结果理解 | 默认业务、原结算结果、本次收入/成本变动、调整后结果、调整日期与原因；财务入账月份另列或选列，不回改原业务日期。验收累计调整只算一次，撤销有对应记录 |
| DC05-05 成本分配（3） | 财务核对资源采购成本分到哪些业务；每行分配记录 | 分配主表后再次列分配依据及采购批次，存在重复 | 默认分配明细，采购批次金额仅作引用；切换“采购批次核对”看原采购、已分配、未分配。验收每批已分配加未分配等于有效采购金额，跨多个团期不重复加原采购额 |
| DC05-06 资源风险（3） | 团控/财务看包机、舱房、铺位等未消耗承诺与临期风险；每行资源批次 | 批次风险后再列批次和分配；风险要素与金额重复 | 默认批次、资源类别、采购承诺、已分配、未分配、使用/释放期限和可核对风险；分配记录按需查看。只有来源提供释放条款才计算不可退风险。验收未分配不直接等同已发生损失 |

**用户与位置：** 采购负责人、供应商结算财务、资金管理。承接采购合同、确认采购、返点及预付款；回答“采购集中在哪里、返点是否兑现、供应商占用多少资金”。采购金额、成本、应付和付款是不同结果。

| DC06-05 预付占用（1） | 采购/资金负责人比较供应商资金占用；默认每行供应商/公司/币种 | 当前偏通用逐笔预付台账，与预款余额预付款重复 | 改供应商汇总：预付余额、未履约对应额、到期/超期额、待退额、主要风险；逐笔合同作为查看内容。验收与预付款同截止日同范围汇总一致，但不再复制整套逐笔页 |

## 四、业务明细：2个菜单、6个Tab

**用户与位置：** 销售财务、经营分析、订单核对人员。承接客户订单中的销售内容及后续变更，输出成交规模底表；不以收款事实代替成交，不产生会计收入。主要任务是查明哪一项业务构成订单口径金额。

## 五、资金核算：6个菜单、24个Tab

### 09 收付明细——优先改造样板

**用户与位置：** 出纳、收款/认款财务、付款财务、资金核对人员。上游是实际到账、退款执行、非现金转款、付款执行与分配核销记录；下游供余额、票款和资金核对使用。最高频任务是按公司、日期、交易对象查清“实际发生什么、分给哪些业务、是否有差异”，不是在报表中办理收付。

#### 9.1 收款Tab五张表的逐表处置

| 当前表 | 为什么需要 | 当前阅读问题 | 建议位置 |
|---|---|---|---|
| 单据明细 / 订单分配主表 | 查到账或分配给订单的金额 | 两种行含义需要非常清晰；收款与认款编号易混 | 默认单据明细；查看内容可选订单分配，表头随行含义变化 |
| 本次查询合计 | 对账总数及分币合计 | 独立全表与主表同级，合计范围容易误读 | 合并主表页脚；多公司/币种可分组，不造跨币总额 |
| 原款与转款依据 | 追溯原到账和连续转款 | 原款金额在不同链路反复引用，容易被看作新增收入 | 查看内容选原款记录；原款金额列明确“原款金额（参考）”，不重复求和 |
| 分配与核销依据 | 查到账如何分配、又如何抵减余额 | 分配和核销是两类行为，混表会让人误认为两次现金发生 | 分为订单分配、核销记录两种查看内容；显示行为日期和有效状态，现金发生额不复制成发生 |
| 核对缺口与重复记录 | 发现缺归属、缺原款、异常重复等 | 与正常流水混排，没有先看金额还是先修资料的引导 | 查看内容选差异记录；用类别、影响金额、关联记录及原因解释；不在此生成处理按钮 |

**这不是简单把五张表折叠：** 合计归主表，重复结果取消，分配与核销拆清对象，原款和差异变成同一主题内可切换的查询结果。低频依据仍可完整输出，每个结果均有独立分页，避免主表10行、依据几十行甚至上百行直铺。

例：到账100,000元，分给订单甲60,000元、订单乙30,000元，未分配10,000元。

- 单据明细是一行：到账100,000、已分配90,000、未分配10,000。
- 订单分配是两行：甲60,000、乙30,000；合计90,000，原款100,000只是引用。
- 筛选订单甲时，当前订单分配合计是60,000，不能把原款100,000说成甲订单收款。
- 后续核销60,000不再增加现金60,000；转款也不能再产生一次到账。
- 原款记录可完整显示100,000，但不能与两笔分配或核销相加。

这是解释设计的示例，不是对当前真实账务的计算认定。

#### 9.2 四个Tab的专门方案

| 编号 / Tab（展开表数） | 默认目标与字段 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC09-01 收款（5） | 每行实际到账记录：交易号、到账日期、收款公司/账户、付款方、币种、到账额、已分配、未分配、核对结果 | 五表平铺；到账与认款单据词义不够明确；独立场景同号影响理解 | 采用上述结构；到账与认款编号分别命名，避免“收款/认款单号”掩盖区别。验收一收多单、部分分配、代收、同号不同来源、外币和未分配，主表合计只认有效到账 |

### 10 往来账龄

**用户与位置：** 应收应付会计、信用管理、财务经理。应收是尚待收回的债权，应付是尚待支付的债务；上游为有效应收应付、调整、核销及冲回。最高频任务是截至某日判断“谁还欠谁多少、形成多久、是否到期”。下游办理仍在财务业务页。

| 编号 / Tab（展开表数） | 目标及默认字段 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC10-01 应收余额（4） | 每行应收单/业务；客户、公司、币种、确认日、到期日、调整后应收、已核销、未收余额 | 通用“应收/应付”“客户/供应商”命名不具体，后接合计及大量依据 | 默认应收余额表，合计归页脚；余额变动和核销按查看内容切换。验收截至日后的核销不影响历史余额，冲回可追溯，负余额独立说明 |
| DC10-02 应付余额（3） | 每行应付单/供应商账单，查未付和到期 | 与应收使用通用字段，未付款与未核销可能混为一谈 | 使用供应商、应付确认额、已核销额、未付余额及付款条件；在途付款独立状态，不直接扣减无有效核销余额。验收同公司币种下余额桥接成立，预付款不自动抵扣 |
| DC10-03 账龄分析（5） | 财务看余额在哪些年龄段；默认每行客户/供应商 | 当前默认偏逐单明细再接合计、原单、核销、缺口，核心分布不突出 | 默认往来对象×账龄区间矩阵，区分应收/应付；另选逾期区间或逐单明细，不能混为同一种龄。验收账龄按确认起算、逾期按约定到期后起算，缺日期独列，各区间和等于适用余额 |
| DC10-04 内部清算（4） | 每行公司对公司/清算关系，查代收代付等尚待结清金额 | 业务责任与实际资金公司混读，依据四表并列 | 默认双方公司、内部业务类型、应清算、已清算、未清算、币种与差异；明细切换查看。验收不能因集团已有现金就把业务公司应收当已结清；与核算内部对账分工明确 |

### 11 预款余额

**用户与位置：** 往来会计、资金管理、供应商财务。预收是客户先付而业务尚未按规则确认的款项；预存是账户中可按约定使用的余额；预付是先付给供应商的款项；保证金需区分收取与支付方向。四类余额不能相加成同一种资金资产。

**共同主线：** 截至日余额 → 本期怎样变化 → 哪部分不能用/未履约/应退。变动桥接应覆盖转入转出和有效调整，不能只用增加、使用、退款三项遗漏其他变化。

| 编号 / Tab（展开表数） | 默认目标与行含义 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC11-01 预收款（3） | 每行客户预收记录/业务，查余额和待结转用途 | 通用对象字段与多表削弱客户预收主线 | 默认客户、收款公司、关联业务、币种、期初、增加、使用/结转、退回、其他净变动、期末；流水切换查看。验收预收不直接记作收入，与已认款或已核销区别清楚 |
| DC11-02 预存款（4） | 每行预存账户，查账面、冻结、可用 | 原通用12列不充分突出客户/门店账户及可用关系；流水、风险连排 | 默认账户、所有人及账户类别、管理公司、币种、账面余额、冻结、其他限制、可用额、账户状态；余额变动切换。验收账户冻结与金额冻结分开，不把冻结金额再扣两次 |
| DC11-03 预付款（5） | 每行供应商预付记录/合同，查尚未抵扣及履约风险 | 余额、未完成业务、流水、缺口并列，与供应商预付占用重复 | 默认供应商、付款公司、合同/业务、币种、已付、已抵扣、已退、余额、约定履约/退回日；占用风险按查看内容。验收分摊到团期不等于已抵扣应付，未履约不直接等于损失 |
| DC11-04 保证金（3） | 每行保证金合同/事项，查持有/缴纳、到期与退回条件 | 一套增加使用字段容易掩盖资产和负债方向 | 默认先区分收取/支付，再列对方、公司、用途、币种、余额、到期日、可退/限制；变动另查。验收两方向不轧差，未满足条件不自动归可用资金 |

### 12 资金分析

**用户与位置：** 资金经理、出纳负责人、集团资金管理。承接真实账户余额/流水和有效收付款计划，回答“钱在哪里、如何变化、未来是否够用”。预算收入、应收、预收责任和银行可用余额不能互相代替。

| 编号 / Tab（展开表数） | 默认目标与行含义 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC12-01 账户余额（3） | 每行资金账户；截至日账面、受限、可用 | 余额页追加全量收支；历史区间和截止日并排分散注意 | 默认公司、账户、币种、账面、受限、可用、核对状态；截止日为主，期初变化按需查看。验收同币账户合计可核对，不把预收负债再次作为账户冻结扣除 |
| DC12-02 账户收支（3） | 每行实际资金流水；发生起止日期 | 主表与全部流水依据重复，后表不分页 | 保留一份流水，识别收入/支出、对方、用途及内部转账；期初和期末作为同范围页脚结果。验收转账双方可查、同一流水不在主表和依据当两笔发生 |
| DC12-03 收支汇总（3） | 每行期间/公司或收支类别，解释净变化 | 汇总与完整流水并排，余额跨期可加性容易误读 | 默认期初、外部流入、外部流出、内部调拨净额、期末；可按类别构成切换分组，流水另查。验收跨月只加发生额，期初取首期、期末取末期 |
| DC12-04 资金计划（4） | 看未来日期收付款和现金缺口；每行计划日/周或计划节点 | 默认逐计划记录后还附历史流水，未来日期可能藏在更多条件，主问题不突出 | 未来区间直接显示；默认按日/周汇总期初可用、预计流入流出、预计期末与缺口，计划明细切换查看。资金不足只在有效期初和计划完整时计算。验收已执行计划不再与实际重复预测，过期未执行单列，不把意向订单当确定收款 |

### 13 票款核对

**用户与位置：** 开票/进项管理、往来会计、财务经理。承接有效收付款、有效发票、分配及红冲更正；主要任务是发现票与款的对应差异及到期事项。差额不自动代表逾期、违规或收入差异，应结合业务允许的票款范围与约定节点。

**共同缺陷：** 四个Tab各五张表，通用“款、票、差额”列名与当前视角不匹配，原始记录、分配、修正和未分配记录并排。统一改成一个差异主表；查看内容可选匹配记录、红冲/更正、未分配记录。未分配若只能提供公司全范围，必须明确其范围，不能冒充当前订单明细的合计依据。

| 编号 / Tab（展开表数） | 目标及默认行 | 专门设计 | 验收 |
|---|---|---|---|
| DC13-01 已收未开（5） | 每行客户业务/订单，已收款尚未对应开票 | 列客户、收款公司、币种、已收金额、已开有效票额、待对应开票额、约定开票节点与差异原因；默认正差额，可查全部 | 原始发票红冲后采用有效净额；未开差额不等于必须当日开票，分配范围须一致 |
| DC13-02 已开未收（5） | 每行客户业务/订单，开票超过已收 | 列有效已开票额、已收款、未收对应额、约定收款日及逾期信息；不把所有已开票业务重复列入重点 | 发票不是应收确认来源的替代；与应收余额的差异能够按开票范围和业务范围解释 |
| DC13-03 已付未收票（5） | 每行供应商业务/账单，已付款未对应收到发票 | 列供应商、付款公司、已付、有效收票、待收票额、约定收票日和剩余天数/逾期；特殊允许无票范围独立 | 预付款是否纳入由批准规则决定；不能把全部已付直接认定为到期进项缺口 |
| DC13-04 已收票未付（5） | 每行供应商业务/账单，收票超过付款 | 列有效收票、已付、未付对应额、付款条件、到期日；正常未到期与应付逾期分别判断 | 发票未匹配应付不自动生成应付；红冲、分票、多次付款和未分配记录不重复计差额 |

### 14 核算核对

**用户与位置：** 核算会计、集团财务、财务接口核对人员。承接收入成本确认、业务结算、内部对应记录及集团核算系统凭证返回。任务是查“业务结果、会计确认、两边账与凭证是否相符”，不在报告中完成确认或推送。

|---|---|---|---|
| DC14-01 确认明细（3） | 每行会计确认或有效调整，按会计期间/确认日期 | 主表后接31列原记录和分配明细；一笔确认可在多分配中重复出现 | 默认公司、会计期间、确认日期、确认类型、币种、金额、已分配、未分配、有效状态；分配记录另看。验收按会计期间查发生，与按业务查累计区分；调整不覆盖原记录 |
| DC14-02 结算对照（4） | 每行结算业务，对比业务收入成本与财务已确认 | 完成业务范围、期间确认发生和分配依据不一定同一集合，四表加剧误解 | 默认同一业务的结算收入/成本、累计确认收入/成本、差额、未分配及原因；业务日期与确认截止日各有定义。期间全部确认不附作本表合计依据。验收跨期确认、未结算已确认、已结算未确认分别解释 |
| DC14-03 内部对账（1） | 每行双方对应内部交易，按公司/对方/期间/币种核对 | 单表适合；易与内部清算理解成一回事 | 保留双方应收/应付或收入/成本对应金额、差额和匹配状态，业务类型清楚；看账务配对，不看资金结清进度。验收跨币、跨期或不同交易不能强匹配，单边缺失不标通过 |

## 六、报表管理：2个菜单、8个Tab

### 15 任务预算

**用户与位置：** 经营计划、财务预算负责人及授权维护人员。承接批准目标和预算版本，供经营规模和损益差异引用。经营任务衡量销售/完成目标；财务预算是收入、成本、费用等计划，二者不能共用一种达成解释。

| 编号 / Tab（展开表数） | 目标及行含义 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC15-01 经营任务（1） | 每行年度/月份、组织、指标和有效版本，维护批准任务 | 基础任务列表与年度月度分解合理；年额、月合计和差额是必要核对，不宜误删 | 保留任务对象、指标、年度额、月分解合计、差额、版本与主状态；维护在当前任务内完成，实际业绩只读引用。验收月度合计等于年度，下级分解约束按已批准规则，不默认平均摊到每月 |
| DC15-02 批准预算（5） | 应查批准收入/成本/费用预算的期间、责任与版本 | 实际复用了月度损益预算差异，连带公司、会计、费用、内部结转表；职责不符 | 默认每行公司/部门/期间/预算科目，列批准金额、币种、版本、生效与批准信息；月份分解可切换，变更记录按需查。实际与预算比较只归月度损益预算差异。验收切入本Tab无需实际发生数据即可读懂批准计划，不能把修改中的预算当批准 |

### 16 数据管理

**用户与位置：** 数据管理、财务报表负责人、授权管理员。承接分类/组织有效对应、核对质量、发布版本、访问范围与订阅规则；保证其他15页的数据可解释、可复用。这里是管理工作页面，不能机械套用只读财务明细模板。

| 编号 / Tab（展开表数） | 目标及默认行 | 当前问题 | 优化设计与验收 |
|---|---|---|---|
| DC16-01 数据核对（2） | 每行核对问题或检查项，判断哪些结果受影响 | 检查汇总与问题明细存在总分关系，并非毫无逻辑；但当前两套表主次仍弱 | 默认问题清单，检查项数量做轻量概况/筛选；完整检查结果可切换。字段为检查项、影响报表/业务、涉及金额或数量、原因、责任归属与核对状态。验收无异常但未检查不能显示全部通过 |
| DC16-02 分类规则（1） | 每行业务分类规则，维护产品/渠道等归属 | 单表维护适合，需重视覆盖、冲突与历史生效 | 默认规则名称、适用业务、归属结果、生效期间、优先关系、状态；编辑内展示命中样例和冲突。验收一条业务同一时期不被相互矛盾规则重复归类，历史不被当前规则静默改写 |
| DC16-03 组织对应（1） | 每行来源组织与报表组织的有效对应 | 同名公司/部门可能错误关联，仅看名称不够 | 默认来源组织、报表公司/部门、生效止期、状态；多主体职责分开，不用名称猜对应。验收调组前后、同名不同公司、有效期重叠和未匹配均有结果 |

### 7.1 相似内容如何取舍

| 相似内容 | 主页面负责什么 | 其他页面保留什么 | 避免的问题 |
|---|---|---|---|
| 损益摘要 / 公司损益 | 月度损益负责利润形成和完整核对 | 总览仅关键结果和变化 | 两处各铺一套账务依据 |

| 毛利明细 / 经营贡献 / 月度损益 | 业务结算毛利 / 扣直接费用后贡献 / 会计期间损益 | 保留各自日期和费用边界 | 三个结果都叫利润并要求无条件相等 |
| 产品风险 / 资源风险 / 风险概况 | 产品侧汇总 / 具体资源批次 / 管理摘要 | 不同观察层次，共用核对范围 | 同批采购金额在多产品重复求和 |
| 供应商预付占用 / 预付款 | 供应商集中及风险 / 逐笔预付余额和变动 | 不重复默认台账 | 为同一台账新增两个名字 |
| 收付明细 / 账户收支 | 业务交易及订单分配 / 银行与支付账户实际流水 | 以有效交易对应，不强制一对一 | 一笔收款多订单被当多次账户入账 |
| 应收应付 / 票款核对 | 债权债务余额 / 票与款对应差额 | 解释范围不同 | 用未开票额代替应收、用发票直接生成应付 |
| 内部清算 / 内部对账 / 集团调整 | 公司间未结款 / 两边账匹配 / 集团口径抵销 | 各自保留必要对应信息 | 清算就等于抵销、内部转款就等于收入 |

### 7.2 必须成立的核对关系

以下为产品验收关系；具体会计政策仍依批准口径。缺资料时应给出缺口，不用虚拟金额把关系凑平。

1. 有效到账 = 已有效分配 + 未分配；订单分配不再次增加现金。
2. 同业务、同截止日：调整后应收/应付减有效核销等于余额，冲回及更正必须计入有效结果。
3. 各预款期初 + 增加 + 转入 − 使用/抵扣 − 退回 − 转出 ± 有效调整 = 期末；不同款项性质分别核对。
4. 同账户、币种：期初余额 + 有效流入 − 有效流出 = 期末余额；内部双方转账在集团同币范围内不形成外部流量。
5. 同资源批次有效采购 = 已分配 + 未分配；已分配不等于已确认成本，更不等于已付款。
6. 同确认记录：可分配金额 = 有效分配合计 + 未分配；原确认额只算一次。
7. 费用分配加未分配能解释原费用；部门之间的管理结转不改变公司整体结果。
8. 业务收入减已确认业务成本是适用范围的业务毛利；扣直接相关费用后的经营贡献另列；公司利润不能强行按产品贡献汇总推得。
9. 票款差额只在同公司、币种、业务及有效分配范围比较；未分配项单列，不任意补到某订单。
10. 批准预算的月分解、年度总额及版本可对应，实际发生与计划相互独立。

## 九、后续验收要求与本轮证据边界

### 9.1 每个Tab改造后的验收

逐项采用本文DC编号验收，不能只验菜单能打开：

1. 首次进入能说清主要使用者、问题、每行含义及期间；无需连续阅读多张依据表才能理解主结果。
2. 默认一个主结果；保留多表时须说明唯一总分关系及为何同时展示有必要，不能出现第二份相同明细。

8. 管理页另外验未保存提醒、版本有效性及失败状态；不把假发送、假权限和假发布作为成功结果。
