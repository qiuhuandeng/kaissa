# 预付管理退回页签与统一逐笔退回实施验收

日期：2026-09-29。依据用户“执行”及[成本应付菜单职责与付款退回优化方案](成本应付菜单职责与付款退回优化方案-20260929.md)，本轮只推进第1步：预付管理的退回页签、逐次申请历史、逐笔实际付款退回及旧错误路径撤下。原报表8批保持，不扩大为真实银行、凭证系统或跨页自动回写。

## 一、页面与职责

应付财务在“预付款”查看已付未用资金，核对业务依据后申请退回；“预付退回”每行是一张申请，查看各次申请和到账。资金岗在既有“付款退回”核对银行实际入账。供应商提交的退款凭据保留，凭据本身不减少预付余额。

- 预付管理新增“预付款／预付退回”两个业务页签，原预付款的筛选和办理保留。
- 退回列表展示退回单、付款对象、申请日期、预付单、付款公司、申请金额、已到账、未到账、主状态；支持单号／付款对象搜索、公司与状态筛选、重置及空结果。
- 退回记录包括外采历史、同行预付及旧备用金退回，不再只读取最新申请；同一预付可多次申请，分别编号、占用和查阅。
- 申请入口位于本页原预付款行，余额处理中直接办理，其他未关闭的有余额记录通过“处理 → 申请退回”；旧“余额退回”不再作为冲抵／转款抽屉里的整笔扣减选项。
- 抽屉逐笔显示实际付款号、银行交易号、日期、付款结果、原付金额、已冲抵、已退到账、处理中、可退及本次退回。未成功付款、全额冲抵、全额退回和无可退金额的付款不能填写。
- 新申请不预填退款金额；填写原因和业务依据，可附材料，展示当前公司的核准退款收款账户。样例账户与材料只用于原型展示。
- 详情保留申请明细、退款凭据、每次到账及其原付款分配。未提交退款凭据且无到账的申请可填原因撤销，保留记录并释放占用；已退款／部分到账不能直接撤销。

## 二、金额及旧路径修正

每笔可退金额 = 成功付款 − 已冲抵 − 已转用 − 已退到账 − 有效退回处理中金额。转用与冲抵分别记录，不把转出冒充冲抵。

申请只占用可退金额，不减少预付余额。上传供应商凭据也不扣余额。实际到账核对后按此次到账金额减少余额，原付款金额不改写，不在申请环节生成凭证或标记待推送。

旧备用金11,400元退回记录保留为申请；无实际到账时余额仍为11,400元、凭证未生成。旧 `applyBalanceResult` 中直接扣余额及生成退回凭证的分支已删除，旧下拉入口也已撤下。其他冲抵／转款动作会检查退回占用，不得重复消耗同一余额。

规则同时修正两类失败后仍可能改变记录的问题：到账按原付款重复分配被拦截；缺核对依据时不会提前把银行流水标为已使用。每张申请的到账按该申请识别，不因后来新增申请而归到最新一张。

## 五、原型边界及唯一下一步

各页面保持独立演示会话：本页可分次申请和查历史，资金页用既有样例演示分次到账；刷新恢复样例，不宣称新申请已自动写入另一页。已有资金页单号可定位原单，新产生的演示申请只提供付款退回工作区入口，避免错误打开另一张同号样例或自动代办。

已开票的快速退回限制、外币退款汇率、退回审批及正式核算口径仍待财务确认，不在本步批准。缺供应商材料但银行已入账的通用待匹配办理，以及旧资金页待冲销／凭证状态，按成付07留在第2步处理。

唯一下一步：执行方案第2步，财务“付款申请”改为“付款复核”；“付款执行／付款退回”归为付款管理两个页签，补清一般供应商退回与银行退汇入口、到账和核算边界，并保留回单核销与既有审批能力。
