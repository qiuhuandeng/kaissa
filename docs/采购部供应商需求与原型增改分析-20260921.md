> 后续进展：附件逐项复核和本轮补漏已完成，当前结论及唯一下一步以[整体验收与遗留清单](供应商附件整体验收与遗留清单-20260921.md)为准。下文保留本步骤当时的证据和历史待办，不作为当前断点。

> 后续状态：四步原型已实施，最新为[付款账期与审批](供应商付款账期与审批实施验收-20260921.md)。附件整体尚未完成验收；唯一下一步按13项及完整字段表复核、补遗漏和分类记录待确认事项。下文为分析时点证据，不能覆盖进度第三、四节的最新断点。

日期：2026-09-21。交付性质：需求与现有代码对照、页面范围和验收设计；本轮未修改页面。

## 一、本次依据与结论

需求依据为采购部提供的《副本新系统供应商管理部需求-采购部.docx》，已读取正文和完整字段表。附件“功能需求”有两个第11条，本文分别记作11①“临时编号”和11②“产品查看”，共13条，均纳入下文。字段表中两段“合同信息”合并理解，内部备注与平台使用费分别保留。

附件描述业务希望达到的结果，不构成本轮执行外部审批、发送企业微信或创建正式客商资料的授权。用户本轮明确要求先分析；因此只更新分析与进度文档，不实施页面或接口。

当前代码依据包括供应商列表、供应商详情、审批中心、产品市场及代理产品、团期结算、付款申请、合同模板、通知模板及直接共享脚本。项目导航中没有名为“产品库”的独立菜单，本文优先将其对应为产品市场和代理产品；自营产品需要展示实际采购供应商的范围仍待确认。

**结论：需要重构供应商档案与协议的处理方式，补齐审批、模板和权限，并局部修改产品、付款承接页面；不是只给供应商列表增加字段。现有供应商详情和公司协议引用可以复用，无需再新建一个供应商主页面。**

核心业务关系是：一家供应商只有一份基础档案和一个编号；同一家供应商可以有多份协议；一份协议又可能有多个我方签约主体，各主体分别约定账期、联系人和适用范围。现有“每条协议只选一个公司”的做法不能完整表达附件示例，不能要求业务重复上传同一份合同来绕过问题。

2026-09-17的供应商列表改造已经按用户要求撤回；详情页、审批事项和后续公司协议引用仍保留。本文以当前代码重新判断，不把回撤前验收当作当前列表能力，也不把已经存在的详情页再列为新增。旧《供应商模块页面改造方案》的多地接、供应商对账等范围不自动带入本次附件。

## 二、页面在业务链路中的位置

| 使用角色 | 当天主要任务与入口 | 上游依据 | 本页处理结果与下游承接 |
|---|---|---|---|
| 采购／供应商管理 | 在资源中心查找供应商、建档、维护资质、办理新协议和续签 | 供应商资料、合作意向、合同文本 | 唯一供应商档案、各签约公司合作依据；供产品和计调选用 |
| 审批人 | 从审批中心核对本次准入、协议或临时合作 | 本次提交资料及对应协议 | 审批结果返回原申请；正式致远返回另行建设 |
| 产品／计调 | 在产品或成本、付款场景查看本公司可用供应商及联系人、协议账期 | 经确认的供应商与公司协议 | 明确本次采用哪份协议；不在产品页维护合同或银行账户 |
| 财务 | 审核收款账户，复核付款依据和账期 | 账户资料、协议、付款申请及业务发生日期 | 财务审核结果与付款处理；不能把业务准入通过等同于账户可付款 |

主操作仍留在资源中心。供应商详情承担跨协议、资质、联系人和账户的完整维护；审批归审批中心；产品页只查必要信息；付款、账户审核仍按财务职责处理。不把供应商主档移到财务，也不把付款执行塞进供应商页面。

| 2．合同可对业务人员隐藏 | 详情无合同查看角色区分；现有“设置”不是合同文件权限 | 详情按权限区分合同正文、账期摘要；无权限不能通过预览、下载或直达入口查看文件 | 普通业务人员可看获准的合作摘要，但看不到受限合同；授权采购能查看 |

| 4．洲／国家／城市关联筛选及目的地直接模糊搜索 | 列表只有合作范围等条件；合同抽屉有目的地树，但没有供应商档案到列表搜索的完整对应 | 供应商档案维护业务区域和国家城市，列表直接搜目的地；复用现有目的地资料，不另造一套地点名称 | 输入国家或城市可找到对应供应商；无需先选洲；多目的地记录均可命中 |
| 5．仅指定签约主体可以看到或搜到供应商 | 现有公司协议选择能过滤公司，但列表、详情、产品名称展示不等于已隔离 | 供应商列表、详情、产品供应商摘要增加当前公司可见范围；集团管理例外单独待确认 | 未签约且无授权公司搜索无结果、直接进入详情也不展示；已授权公司正常查看 |
| 6．供应商唯一编号，已有供应商只增主体和条款 | 列表没有查重续办；多个入口靠固定名称或固定样例，不是一致的供应商记录 | 新增前查重，匹配已有记录后续办协议；列表及详情使用同一供应商编号 | 新增相同供应商引导复用，增加公司后编号不变；无权限者的重复提示不泄露其他公司合同 |
| 7．每份新协议单独送致远，批准后填业务对接人、电话、账期、平台费 | 详情“新增合作”会追加本页审批记录；“新增协议送审”只增加审批中协议，没有对应审批历史；费用等部分输入未被保存 | 每份协议独立申请、状态和记录；批准后补充／核对联系人和费用，沿用已填内容；条款实质变化是否重新审批待确认 | 连续提交两份协议出现两个独立审批记录；原有效协议不受影响；批准后补充内容可重新打开核对 |
| 8．计调付款、财务审批时显示账期 | 团期结算付款和财务付款复核已有协议依据；审批中心普通付款样例未显示对应协议账期；共用计算仅支持某事件后若干天 | 保留既有付款依据区，扩展月结等表达；审批中心付款详情补签约主体、协议、账期及日期依据 | 同供应商不同公司显示各自账期；起算资料缺失显示待确认；月结不误算成30天；旧单不替换为新协议 |
| 9．到期自动禁用，临期提醒，可选择企微提醒 | 有到期不可新引用的样例规则，但使用固定演示日期；没有完整提醒规则和发送记录；列表还有固定“临期”标签 | 按协议及适用公司判断是否可新使用；详情维护临期提醒，通知模板增加供应商协议场景 | 一公司到期不误停另一公司的有效合作；到期前后边界正确；提醒不重复；存量业务不凭猜测停付 |
| 10．临时酒店等一次性合作，无合同，最少资料，临时审批及致远客商创建 | 审批中心有临时供应商事项，但来源链接指向列表未处理的临时申请参数；列表缺少对应入口与表单 | 列表新增“临时供应商”快速办理，详情标明临时合作依据，审批中心返回同一申请；正式客商创建另列接口范围 | 无合同可按临时材料规则送审；返回申请能看同一记录；正式准入必传项不误拦临时流程 |
| 11①．临时编号“临＋年月日＋4位流水” | 审批样例已有该格式；列表无生成和续办过程 | 临时申请展示编号并贯穿审批与后续引用；生成时点、转正式编号规则待确认 | 展示如“临202609010001”；同日多条不重号；不因换页面或补资料重新生成身份 |
| 11②．产品库供应商查看权限；点击供应商弹出签约主体、联系人、电话 | 产品市场及代理产品已有供应商名称，部分已有协议选择；名称主要为普通文本，无该权限控制的联系信息弹层 | 产品市场、代理产品列表及详情复用供应商信息抽屉，仅展示本公司允许查看的合作联系人 | 授权用户点击正确供应商出现对应主体及联系人；无权限不出现查看入口；不泄露内部备注、平台费或其他公司资料 |
| 12．按已有协议模板自动生成合同 | 已有合同模板页主要服务游客和客户销售合同；供应商协议未接模板生成 | 在现有合同模板列表／编辑页增加“供应商合作协议”用途；从供应商协议表单选模板、主体并预览生成内容 | 一份多主体协议正确带入各主体名称和约定；缺必需内容定位补充；模板版本和实际签章文件分别保留 |

## 四、字段取舍和归属

字段表应落实到档案或协议，不应全部变成一级列表列。

| 字段要求 | 当前状况 | 本次目标 |
|---|---|---|
| 供应商全称、英文名、品牌名、注册地、公司地址 | 有名称、简称、注册地等；英文名、品牌、地址等未完整独立表达 | 基础档案分别维护；简称不能替代英文或品牌名。保留查重需要的注册登记信息，但不额外增加无依据必填项 |
| 法人及电话、总经理及电话、业务联系人及电话、微信／邮箱 | 有主要联系人和电话，缺少上述联系人区分 | 法人、总经理归档案；业务联系人可在档案登记，再在公司协议中指定本次对接人。普通产品查询只展示业务联系所需信息 |
| 五类供应商，允许多选 | 旧表单按地接、同业、酒店、航司等单选；还含集团内部公司 | 按附件采用境外地接、国内旅行社、出境批发商、单项供应商、综合类供应商五类多选。单项服务细分只用于明确合作内容和材料适用；集团内部产品提供公司不混作外部供应商 |
| 业务区域；国家及城市；可承接团组 | 有合作范围和合同目的地，但不等于完整供应商能力资料 | 区域按国内、港澳台、欧洲、亚洲、美洲、大洋洲、非洲多选；国家城市关联维护；单团、定制、散拼、研学、单项、会议会展等团组类型多选 |
| 合同有效期、我方签约主体、账期 | 旧新增把期限和结算方式放在供应商层；详情协议只有一个公司 | 移到协议；每份合同明确有效期、多个签约主体及各自账期。列表只概括当前公司合作，不给整个供应商强行设一个统一合同到期日 |
| 平台使用费、内部备注、普通备注 | 详情有平台费输入但提交未保存；费用权限不明 | 平台费及内部备注归相关合作协议并限制查看；普通备注另存。费用按金额还是比例、收费周期及各主体差异待业务确认，不自行推算应收 |
| 开户名称、开户行、银行地址、账号、Swift Code | 新增已有多数银行字段；多账号展示和添加未形成完整维护 | 账户独立成组，可新增、编辑多账户并保留财务审核状态；录入完成不等于获准付款 |
| 多账号；同一境外账户支持多个结算币种 | 新增单账户单币种，详情固定展示人民币／欧元卡片；列表合同的“添加账户”仅提示 | 同一账户允许选择多个币种，不能为同一账号每种币种重复建档；财务人员按账户与支持币种核对 |
| 营业执照必传 | 旧表单按旧类型给固定文件样例，缺实际选择与缺件处理 | 按正式准入要求设必需材料；境外对应证明、临时流程最少材料单独确认，不强迫境外填写国内格式 |
| 经营许可证必传 | 与附件“综合类不具备旅行社资质”冲突 | 按适用类别确认材料要求后实施；不把旅行社经营许可证强加给酒店、摄影等供应商 |
| 旅责险选填 | 旧地接／同业模型设为必传 | 按附件改选填；后续若特定合作有特殊条件，在明确依据下另行表达 |
| 报价单一般选填，综合类必传 | 现有材料跟随旧类型，规则不一致 | 综合类必传，其他类选填；多分类时适用材料合并且同一材料只上传一次 |
| 待审批合同、双方盖章件 | 当前多为文件文字与提示式预览 | 分别保留送审文件和签章后文件、上传人及日期；不能用后上传文件无记录地覆盖批准依据 |

供应商一级列表建议保留“供应商、分类／合作内容、服务地区、当前公司合作、我方负责人、操作”这类判断字段；法人、总经理、银行、全部协议、费用和文件进入详情。最终列宽随可操作样例确定，操作列固定右侧，关键数量和状态完整显示；不新增通用“关键缺口”列，不把多份协议状态并排堆成多个主状态标签。

## 六、必须先修正的现状问题

1. **列表操作与行对象脱节。** 多行“合同／设置”共用固定供应商内容，不能继续在固定抽屉上叠加多主体功能；先保证点哪家就处理哪家。
2. **有表单不等于能保存。** 新增、添加账户、保存设置主要为提示；详情协议提交遗漏已填写的平台费、币种等字段。验收应检查重新打开后的内容，不能只检查成功提示。
3. **详情入口需统一。** 列表没有详情入口，详情对未知供应商编号回落到默认样例，可能展示错误供应商。应明确“未找到／不可查看”，不以另一家供应商代替。
4. **协议送审与审批记录不一致。** 公司合作申请会追加历史，而新协议送审只改变协议显示。需同一申请可从协议与审批两处查看，但不必在原型阶段建设跨页自动回写。
5. **现有公司过滤不是完整权限。** 共享规则可以限制选择某公司协议，但详情显示全部公司资料，完整账户的显示按钮也无角色判断。不能据此宣称满足合同隐藏、产品查看和主体可见三类要求。
6. **到期判断不能只靠固定标签。** 共享样例使用2026-09-17基准日，列表还有固定期限状态。原型需说明可复核的日期并覆盖边界场景；正式定时停用和发送通知另属服务建设。

## 八、实施顺序与验收边界

**唯一下一步：在收到实施指令后，先完成“供应商档案与多主体协议”这一个边界清楚的步骤。** 范围为供应商列表、供应商详情、必要的审批事项展示及直接共享样例；交付可操作的正式／临时建档、五类多选、正确对象详情、一份协议多主体、各主体账期、独立送审与盖章资料区。未确定政策以待确认表达，不顺带启动全系统联调。

此步完成后依次补协议模板生成与提醒、产品联系信息和权限、计调付款及财务审批账期承接；每步均按第三节逐项核对，最后回到附件13条和字段表整体验收，不能只做完供应商列表就宣布全部完成。

建议至少覆盖以下业务场景：新供应商正式准入；重复供应商追加合作；一份协议两主体及另一主体独立协议；新协议退回且旧协议仍可用；批准后待盖章／已归档；临时酒店无合同申请；综合类缺报价和旅责险未上传；境外同账户多币种；国家与城市搜索；未授权查看；一家公司到期而另一家仍有效；月结及回团后3天分别显示；产品联系人及付款审批分别查看本次公司信息。每个场景同时检查正常处理、缺项或异常以及取消后不改原记录。
