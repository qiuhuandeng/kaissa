## 本批解决了什么

资金池原来主要查余额、流水和资金占用，不能维护公司账户、商户及使用范围；门店财务表单直接手填缴款账号，无法说明账户由谁核准、用于哪类收付款。本批在财务现有“资金票据”菜单增加“收付款配置”，资金池同步提供入口；门店财务配置改为选用已核准资料。

主要使用者是公司财务专员、财务负责人和门店财务联系人。上游是公司开户资料、支付机构商户协议及门店收付款关系；财务维护并提交审核，门店选择获准资料后另行申请财务配置变更。下游供新收付款选用，历史退款和对账继续保留原资料，由财务模块处理。

## 页面与流程

| 页面／位置 | 本批实现 | 开发需要理解的边界 |
|---|---|---|
| 财务 → 资金票据 → 收付款配置 → 公司账户 | 按公司、名称／账号、状态查询；新增、变更、停用申请及当前有效详情 | 公司自己的银行账户，按门店缴款至公司、客户转账收款、商户结算、对外付款区分用途 |
| 收付款配置 → 支付商户 | 维护支付机构、商户号、户名、支付渠道、结算账户及门店范围 | 结算账户必须属于同一公司、币种，已核准商户结算用途并覆盖相应门店；公司账户缩小用途或门店范围前，先办理关联商户变更 |
| 收付款配置 → 门店收付款资料 | 财务核验门店缴款来源及接收分润或退款账户，每份资料对应一家门店 | 用于证明门店收付款关系，不作为公司自有资金余额台账；不替代客户退款的原付款资料 |
| 收付款配置 → 变更申请 | 草稿、审批中、撤回重提、待生效、已生效记录；核对变更前后、原因及日期 | 申请中不覆盖有效资料。同一对象有未处理申请时先处理原申请；账号、商户号或归属变化新增资料，旧记录保留 |
| 门店列表“财务”及详情“收款与结算” | 分开选用门店缴款至公司、客户转账收款、客户扫码商户、门店缴款来源、门店接收分润或退款 | 只提供本公司、本店、用途匹配、已批准且有效的资料；停用及不合规资料不能新选用，无可用项时由公司财务维护，不自动替换 |
| 审批中心 | 新增“收付款配置变更”“收付款资料停用”事项、岗位与核对样例，表达通过、退回及生效结果 | 公司财务负责人核对归属、资料、用途、关联商户、在途收付和历史退款安排；关联范围冲突样例不能直接通过 |

操作顺序：财务填写资料 → 核对并提交 → 审批中心审核 → 到达生效日期供选用 → 门店提交默认选用变更 → 该变更批准且生效后用于新交易。

实际生效日期取申请日期与批准日期中较晚者。审批晚了不追溯启用，待生效期间继续显示旧资料。默认账户变更不修改原收款记录；原收款继续保留发生时的公司、账户和商户号。停用只停止新选用和新交易，不等于银行销户、支付平台注销或原路退款能力关闭。原路退款不可用时，由财务在退款执行核实并办理非原路退款审批，不能自动套用新商户。

## 原型边界和待提供资料

当前资料、账号、户名、商户及审核记录均为固定演示样例，不是正式主数据或财务核准结论。申请在当前页面内演示，刷新复位；审批中心提供独立样例，不将本页新申请自动复制过去，也不回写门店或资金台账。没有接通银行、支付平台、真实权限、附件服务或退款执行，没有生成余额、真实收付款及跨页资金闭环。

正式实施时，财务提供实际公司户名与开户证明、支付商户协议及结算账户、各门店获准用途和收付款关系；旧账户／商户停用时的在途收款、清算和原路退款安排由财务逐项核实。这是正式资料及具体处理安排，不重新讨论已经确定的功能分工。结算周期、付款节点、管理费等原有待确认规则保留，取消的功能不再提出确认。

下一批只推进第8组：门店及财务两端预存账户的开户、整户控制和权限表达。充值、扣款、对账及工作台后续分别推进；报表工作线和履约中心团期订单不在本批改动范围。
