# 财务部门系统使用培训稿（最新财务页面优化版）

本稿在原《财务部门系统使用培训稿》的整体结构和讲法不变基础上，结合当前财务模块最新页面、列表字段、抽屉、按钮和状态口径做补充优化。培训仍然不是“财务菜单介绍”，而是讲清 ERP 如何把旅游业务数据转成财务可核对、可结算、可入账、可推 NC、可出报表的数据链路。

## 第一部分 概述

### 1. 财务是业财的验收者

**这套 ERP 要回答的问题是：业务发生以后，系统如何自动沉淀成财务可核对、可结算、可入账、可推 NC、可出报表的数据链路。**

财务不是单纯的系统使用者，而是整个业务链路的数据质量验收部门，是系统链路的最终验收者。销售、产品、计调、履约完成各自业务后，系统最终要回答财务关心的问题：

- 这笔钱该不该收，钱有没有到账，到账后认到哪张订单、哪张应收；
- 这笔余额属于客户预收、门店预存、转款留存，还是应该退款；
- 这笔成本有没有业务依据，供应商账单和系统成本能不能对上；
- 付款申请有没有超过可申请金额，审批通过后是否真正付款并回单核销；
- 发票、回单、汇率、结算、NC 是否能对上；
- 报表里的数能不能穿透到源单。

一句话概括分工：业务部门负责把业务事实录准，系统负责把业务事实自动沉淀成财务对象，财务负责核对、确认、处理异常，完成入账、付款、开票、结算、关账和 NC。

### 2. 从“录入”转向“核对”

系统不是让财务多录一遍业务数据，而是让销售、产品、履约在源头把业务事实结构化。财务从录入型工作转向核对型、规则型、异常处理型工作，通过系统管资金、管票账、管结算、管关账。

财务不应该替业务补订单、补名单、补成本依据、补供应商账单。财务看到的是业务链路沉淀下来的财务对象，财务要做的是核对、确认、退回、异常处理和最终入账。

| 业务动作 | 系统沉淀的财务对象 | 财务要做的事 |
| --- | --- | --- |
| 销售订单确认 | 应收单、应收计划、发票前置信息 | 核来源、核主体、核金额、核账龄，不替销售补订单 |
| 客户付款或门店上传水单 | 到账流水、识别结果、后续去向 | 核流水重复、付款方、收款账户和资金用途 |
| 认款确认 | 收款凭证、应收核销、NC 收款任务 | 核一笔流水认到哪张应收，处理拆分、合并、超收、短收 |
| 售后退款或改期转团 | 退款单、转款单、应收冲减、预收余额 | 核可退/可转金额、原收款、账户、发票红冲和凭证 |
| 供应商账单进入系统 | 账单识别、成本核对、应付基础 | 核供应商、关联团期/项目/批次、账单金额和差异 |
| 应付确认和付款申请 | 应付单、付款申请单、审批任务 | 核应付依据、可申请金额、本次申请金额、预付冲抵 |
| 付款执行和回单核销 | 付款单、回单、应付已付、NC 付款任务 | 核账户、付款结果、回单金额和银行退回异常 |
| 业务结算、门店对账、渠道结算 | 结算单、差异记录、结算调整、报表口径 | 核收入、成本、收付、退款、票据、毛利和 NC |

## 第二部分 业财一体化总链路

### 1. 业财一体化主链路

财务要先从全链路看系统，而不是从财务菜单看系统。

```text
产品/线路/团期/项目/服务单
-> 销售订单/合同/售后
-> 应收/到账流水/认款/预收/预存/转款/退款
-> 履约成本/供应商账单/应付/预付
-> 付款申请/审批/付款执行/回单/付款退回
-> 业务结算/门店对账/渠道结算/结算调整
-> 发票/资金池/期间关账/NC/报表
```

业务部门录入的是业务事实，系统沉淀的是财务对象，财务最终验收的是资金、票据、结算、凭证和报表。

## 第三部分 第一条主链：收入资金链

主线：

```text
销售订单/服务单/项目阶段款 -> 应收单 -> 到账流水
-> 资金用途识别 -> 认款复核 -> 应收核销
-> 预收/预存/转款/退款分流 -> 发票 -> 收入确认 -> NC
```

### 场景一：订单确认，系统自动形成应收

**业务背景** 销售创建订单并确认提交后，系统不应等财务重新录一张应收。订单金额、客户、合同、产品、团期、渠道、收款计划已明确时，系统自动生成应收对象。

**上游业务动作** 销售创建订单，客户和联系人完整，产品/团期/套餐/服务单/项目明确，订单金额、优惠、补差、付款节点明确，合同或收款计划确认。

**系统入口** 财务 > 应收管理。

**当前页面讲法** 应收管理列表重点看“应收单/来源、客户/渠道、关联业务、财务主体、应收金额、客户已收/待收、调整/减免、应收状态”。当前页面已经把应收状态分成待确认、待收款、部分收款、已收清、已确认、已退回、已关闭，培训时要让财务明白：操作列跟主状态走，待确认处理确认/退回，待收款和部分收款看认款记录，已收清看详情和凭证承接。

**演示流程**

1. 进入应收管理，按应收单、订单号、客户、渠道、团期或项目筛选。
2. 打开“复核/确认”抽屉，先看来源依据，再看本次处理。
3. 核对应收金额、已认金额、待收金额、财务主体、调整减免和到期状态。
4. 来源完整则确认应收；金额、主体、客户信息异常则退回业务源单修正。
5. 进入详情 Tab，查看基本信息、认款记录、调整关账、处理记录。
6. 确需核销时，走“申请核销”，不直接修改原应收。

**财务要核什么** 来源订单是否真实有效；财务主体是否正确；应收金额是否等于订单财务口径；优惠/补差/退差是否已审批；客户/渠道/门店对象是否准确；币种、汇率、本币金额是否完整；到期日和账龄是否正确。

培训提醒：应收页不是销售催收页，也不是财务补订单页。财务只确认财务对象是否成立，源头错误要退回源单。

### 场景二：客户付款、水单上传与到账流水分流

**业务背景** 客户付款来源多样：银行转账、POS、银联、微信、支付宝、OTA 回款、门店上传水单。系统目标是把这些资金统一进入到账流水和资金池，再根据资金用途分流。到账不等于已收清。

**系统入口** 财务 > 到账流水；财务 > 资金池。

**当前页面讲法** 到账流水列表当前展示“流水号/来源、到账时间、收款账户、付款方、到账金额、资金用途、识别对象、未识别金额、流水状态”。流水状态包括待识别、已识别、部分识别、异常、已关闭。页面已支持登记流水、导入流水、识别、处理、详情。

| 资金用途 | 后续去向 | 讲课重点 |
| --- | --- | --- |
| 订单收款 | 认款复核 | 进入认款后才核销应收，不能把到账直接当收款完成。 |
| 门市充值 | 预存账户 | 这是门店账户余额，不是单张订单收款。 |
| 转款入账 | 转款处理 | 要核原订单、新订单、可转金额和差额去向。 |
| 退款退回 | 退款执行 | 银行退汇或退款失败要回到退款执行处理，不随意挂收入。 |
| 其他入账 | 其他收入或暂挂台账 | 必须有识别依据和处理记录，不能成为无法追溯的杂项。 |

**演示流程：登记/导入流水**

1. 进入到账流水，演示“导入流水”，选择主体公司、收款账户和流水日期。
2. 上传银行流水、POS/银联清算文件或门店水单模板。
3. 在导入预览中看流水号、到账时间、付款方、到账金额、重复校验、识别建议。
4. 确认导入后，流水进入待识别、已识别或部分识别状态。
5. 特殊线下收款使用“登记流水”，填写主体公司、到账时间、收款账户、付款方、付款方式、回单附件。

**演示流程：识别流水**

1. 待识别或部分识别流水点击“识别”；异常流水点击“处理”。
2. 抽屉先看流水核对，再选择资金用途、识别依据和识别对象。
3. 识别依据可以是付款方匹配、银行附言匹配或人工核对。
4. 若存在付款方不符、金额不符、附言缺失、疑似重复，要在识别差异中保留原因。
5. 详情中通过“流水信息、识别信息、后续去向、操作记录”说明这笔钱最终去了哪里。

**财务要核什么** 流水是否重复导入；收款账户是否属于正确主体；付款方能否匹配客户/门店/渠道；金额是否等于应收或可拆分认款；银联/POS 水单与实际到账是否有清算差异；该流水应进入认款、预存、转款、退款退回还是暂挂。

### 场景三：系统自动认款，财务处理未匹配异常

**业务背景** 应收已生成、流水已到账，系统应尽量自动匹配。财务不应逐笔翻订单和流水，而是处理系统无法确定的异常。

**系统入口** 财务 > 认款复核。

**当前页面讲法** 认款复核列表当前展示“认款单/来源、付款方、关联业务、应收单、本次认款、差额、认款场景、认款状态”。认款状态包括待复核、差异中、已确认、已退回。抽屉里有来源信息、核销明细、本次处理；详情里有来源凭证、核销明细、收款凭证、处理记录。

**自动匹配规则** 系统可按金额精确匹配、付款方与客户/门店/渠道匹配、订单号或附言匹配、收款计划到期匹配等规则，给出高低置信度结果。

**操作流程**

1. 进入认款复核，按认款单、来源流水、付款方、订单或项目筛选。
2. 待复核认款点击“复核”，差异中点击“处理”。
3. 先看来源信息：来源流水、付款方、来源金额、提交人、凭证、系统校验。
4. 再看核销明细：订单/项目、应收单、应收金额、已认金额、本次认款、认后余额、差额。
5. 无差异时选择“确认认款”；有差异时可选择“转入预存账户、保留待认、生成补收应收、退回补充”。
6. 确认后生成收款凭证，更新应收状态，产生 NC 收款任务；退回则保留原记录和退回原因。

| 认款异常 | 当前页面处理口径 | 培训话术 |
| --- | --- | --- |
| 一笔流水对应多张订单 | 核销明细拆分到多张应收 | 系统不是强行一对一，而是让财务确认分配明细。 |
| 到账金额大于应收 | 转入预存账户或保留待认 | 超收不能随意冲其他订单，必须形成余额或待认记录。 |
| 到账金额小于应收 | 部分认款，认后余额保留待收 | 部分收款后订单仍未收清，应收余额继续存在。 |
| 付款方不符或凭证不清 | 退回补充 | 财务不能猜客户，要退回销售/门店补说明。 |
| 确需补收 | 生成补收应收 | 差额不是备注，要形成新的应收对象。 |

### 场景四：预收、预存与转款核销

**业务背景** 旅游业务常见超收、企业预付款、门店预存、渠道预存、转团转款。这些余额必须在系统里管清楚，不能散落在 Excel 或备注里。

| 对象 | 当前页面 | 业务含义 | 重点动作 |
| --- | --- | --- | --- |
| 预收 | 预收管理 | 客户或订单层面的可用余额，如企业预付款、超收、退款转预收、转款剩余 | 确认、使用、解冻、退款承接、查看收款凭证 |
| 预存 | 预存账户 | 门店、渠道或客户账户余额台账 | 查看可用余额、冻结金额、待处理项、订单扣款、流水明细、财务承接 |
| 转款 | 转款处理 | 原订单收款转入新订单的核销事件 | 转款、处理差异、冲正、查看凭证/NC |

**预收管理讲法** 列表看预收单/客户、来源业务、预收金额、已用金额、可用余额、使用去向、冻结退款、预收状态。详情里有预收总览、来源业务、使用明细、转款记录、冻结退款、收款凭证、处理记录。处理抽屉分为处理依据、本次确认、本次使用、本次解冻。

**预存账户讲法** 预存账户不是资金池。预存页看账户对象、账户类型、财务主体、可用余额、冻结金额、待处理项、最近变动、账户状态；资金池看真实银行或支付账户余额。预存账户详情里要讲账户总览、待处理项、订单扣款、流水明细、冻结调整、财务承接。

**转款处理讲法** 转款处理列表看转款单/审批、转款对象、原订单、新订单、可转金额、本次转款、新单待收、差额去向、转款状态。差额去向可能是无差额、转预收、补收应收、退回客户、退回补资料。已核销后如发现认错，不删除原记录，走冲正。

培训提醒：预收、预存、转款都不是备注。每一次确认、使用、冻结、退款、转款、冲正，都要有余额流水、来源单据、处理记录和凭证状态。

### 场景五：退款和售后反冲

**业务背景** 售后由销售或客服发起，财务负责执行和入账。售后审批通过不等于钱已退，财务执行成功并核销回单后退款才完成。

**系统入口** 财务 > 退款执行；财务 > 转款处理；财务 > 发票管理。

**当前页面讲法** 退款执行列表看退款单/审批、来源订单、退款对象、退款原因、可退金额、本次退款、退款去向、退款状态。状态包括待退款、退款中、待回单、退款失败、已完成、已关闭，以及账户校验类状态。详情 Tab 包括执行总览、原收款、执行校验、退款去向、应收冲销、支付与凭证、退款记录。

**操作流程**

1. 打开退款执行列表，按退款单、来源订单、客户、状态筛选。
2. 待退款点击“退款”，先看执行依据，确认审批结果、原收款、可退金额。
3. 核对退款去向：原路退回、指定账户、预收/预存余额退回等。
4. 检查执行校验：退款账户、白名单、原收方式、已退金额、发票状态。
5. 执行退款后进入待回单或退款中。
6. 上传或同步回单，完成后生成退款凭证和 NC 任务。
7. 原订单已开票的，进入发票管理处理红冲；退款失败或银行退回则回到退款执行/到账流水处理。

**财务要核什么** 退款是否已审批；原订单是否已收款；可退金额是否准确；未收部分是否先冲应收，已收部分才退款；退款账户是否与客户或原付款方一致；已开票是否触发红冲；退款完成是否回写订单和 NC。

## 第四部分 第二条主链：成本付款链

主线：

```text
供应商账单 / 系统成本确认 -> 账单识别与业务挂接
-> 应付确认 -> 预付分摊/冲抵 -> 付款申请
-> 审批通过 -> 付款执行 -> 回单核销
-> 付款退回/异常处理 -> 应付结清 / 凭证 NC
```

### 场景一：团期/项目/服务成本进入财务

**业务背景** 计调或履约在团期、项目、自由行采购批次、服务单里确认成本。财务不能凭口头、微信、Excel 或供应商一句话付款，必须看到成本来源、供应商、费用项目、金额和附件。

**上游业务动作** 计调确认团期实际成本；项目经理提交项目成本；自由行采购批次完成供应商对账；服务单确认代垫或服务成本；供应商账单上传或导入；业务侧提交结算申请或成本确认。

**系统自动形成** 成本项按团期/项目/采购批次/服务单沉淀，带供应商、费用项目、原币金额、汇率、本币金额、附件。财务在供应商账单和应付管理里核对并确认，不回到业务页面改成本。

### 场景二：供应商账单识别与应付确认

**系统入口** 财务 > 供应商账单；财务 > 应付管理。

**供应商账单页面讲法** 列表看账单号/来源、供应商、关联团期/批次、账单类型、账单金额、系统成本、核对差异、主状态、应付结果。状态包括待识别、待挂接、待核对、差异中、已确认、已关闭。操作包括上传账单、录入账单、识别、关联、核对、处理差异、详情。

**供应商账单操作流程**

1. 账单通过上传、录入、接口或业务成本承接进入系统。
2. 待识别点击“识别”，看原始附件、识别明细、账单信息。
3. 待挂接点击“关联”，选择团期、项目、采购批次或服务单。
4. 待核对点击“核对”，比较对方账单和系统成本。
5. 金额不一致进入差异处理，保留差异依据和处理结论。
6. 账单确认后承接到应付/发票。

**应付管理页面讲法** 列表看应付单/来源、付款对象、关联团期/批次、费用项目、应付金额、已付/可申请、主状态、付款进度。状态包括待确认、差异中、已确认、付款中、已结清、已关闭。详情 Tab 包括应付总览、应付依据、付款与冲抵、发票/NC、处理记录。

**应付确认流程**

1. 进入应付管理，查看来源账单、供应商、费用项目、关联团组。
2. 核对原币应付、汇率、本币金额、已付、待付、预付冲抵、发票风险。
3. 待确认应付点击“确认应付”，差异中点击“处理差异”。
4. 确认后才允许进入付款申请；付款中查看付款进度，已结清只反查。

培训提醒：预估成本不是应付，供应商账单确认也不等于已付款。财务确认应付后，才进入付款申请和付款执行。

### 场景三：供应商预付、预付冲抵与余额管理

**业务背景** 旅游业务常有资源预付款：机票锁位、邮轮舱房、专列铺位、酒店定金、地接预付。预付不是成本，也不是应付结清，后续必须冲抵实际应付。

**系统入口** 财务 > 预付管理。

**当前页面讲法** 预付管理列表看预付单/付款对象、预付类型、关联团期/项目、预付金额、已冲抵/余额、主状态、凭证 NC。状态包括待分摊、待冲抵、待确认、余额待处理、差异待处理、已结清、已关闭。操作包括分摊、冲抵、确认、转款、退回、处理、详情。

**操作流程**

1. 预付款执行完成后形成供应商预付余额。
2. 回团或账单确认后进入预付管理。
3. 待分摊时按团期、项目或供应商账单确认分摊对象。
4. 待冲抵时选择应付单或账单，系统计算可冲抵金额。
5. 余额待处理时判断继续留存、退回、转款或关闭。
6. 冲抵后更新应付待付金额和预付余额，形成凭证 NC。

**财务要核什么** 预付来源是否有合同或付款节点；是否关联正确团期/项目/供应商；已冲抵和余额是否准确；长期未冲抵预付是否有风险；预付冲抵是否影响结算和 NC。

### 场景四：付款申请、审批与付款执行

**业务背景** 业务发起付款申请、审批中心审批、财务/出纳执行付款、回单核销。付款申请通过不等于已付款。

**系统入口** 财务 > 付款申请；财务 > 付款执行；财务 > 回单核销；财务 > 付款退回。

| 金额口径 | 说明 | 在哪个页面重点看 |
| --- | --- | --- |
| 应付金额 | 成本或账单确认后的付款义务总额 | 应付管理 |
| 可申请金额 | 扣除已申请、已付、已冲抵后，当前还能申请的余额 | 付款申请列表 |
| 本次可申请 | 进入申请/复核抽屉后，受付款节点、依据和规则限制的本次上限 | 付款申请抽屉 |
| 本次申请金额 | 用户本次提交的付款金额 | 付款申请抽屉和审批记录 |
| 本次实付 | 扣除预付冲抵后真正需要付款执行的金额 | 付款申请、付款执行 |

**付款申请页面讲法** 列表看申请单/类型、付款对象、付款依据、关联团组/项目、申请信息、可申请金额、本次申请/本币、冲抵/实付、主状态。状态包括待复核、审批中、已通过、已退回、已关闭。详情 Tab 包括申请总览、付款依据、金额核对、审批记录、付款单、附件依据。

**付款执行页面讲法** 列表看付款单/申请、付款对象、付款依据、关联团组、原币付款、汇率/本币、付款账户、收款账户、主状态、回单凭证。状态包括待付款、校验异常、付款中、付款失败、待回单、已付款、已关闭。详情 Tab 包括付款总览、申请来源、账户校验、原币汇率、执行记录、回单核销、预付/备用金、异常记录、凭证 NC。

**操作流程**

1. 进入付款申请，复核付款对象、付款依据、关联团组、可申请金额和本次申请金额。
2. 核对供应商账单、应付单、合同节点、预付冲抵和附件依据。
3. 复核通过进入审批；依据不足退回业务补充。
4. 审批通过后付款任务进入付款执行。
5. 出纳核对付款账户、收款账户、账户余额、币种、付款方式。
6. 银企直联付款或线下付款，成功后形成付款单和付款流水。
7. 待回单状态上传或同步回单，后续进入回单核销。

### 场景五：回单核销与付款退回

**回单核销入口** 财务 > 回单核销。列表看回单号/来源、回单类型、关联单据、付款对象、关联团组、原币回单、汇率/本币、核对结果、回单状态、凭证 NC。状态包括待匹配、待核销、差异待处理、已核销、已关闭。

**回单核销流程**

1. 付款执行完成后，系统等待回单。
2. 回单通过银行接口同步或人工导入。
3. 待匹配点击“匹配”，选择付款单、退款单或相关业务单据。
4. 待核销点击“核销”，核对付款对象、账户、金额、币种、付款单。
5. 核销成功后应付状态更新，生成 NC 凭证任务；金额、账户或币种不一致进入差异处理。

**付款退回入口** 财务 > 付款退回。列表看退回单/来源、退回对象、原付款单、关联团期/项目、退回类型、原币退回、汇率/本币、到账流水、退回状态、凭证 NC。状态包括待匹配、待确认、差异待处理、待冲销、已冲销、已关闭。

**付款退回流程** 银行退回或付款失败形成退回记录，财务匹配原付款单，核对退回原因，判断重新付款、冲销应付、恢复预付或关闭，最后生成处理记录和 NC 调整任务。

## 第五部分 第三条主链：结算对账链

主线：

```text
团期/项目/订单/服务单/门店/渠道/OTA
-> 发起结算或对账
-> 收入成本票据回单核对
-> 差异处理 / 结算调整
-> 财务结算确认
-> 报表 / 期间关账 / NC
```

结算的本质：财务对一个业务对象的经营结果进行确认。结算不是业务补录，也不是单纯报表，而是财务把收入、成本、收款、退款、应付、付款、发票、回单和毛利统一核对并锁定。

### 场景一：团期/项目/订单/服务单业务结算

**系统入口** 财务 > 业务结算；财务 > 业务结算详情。

**业务结算页面讲法** 列表看结算单/类型、结算对象、结算周期、收入核对、成本核对、票据回单、核算结果、结算状态、凭证 NC。状态包括待核对、差异待处理、退回补充、审批中、已结算、已归档。详情 Tab 包括结算总览、收入核对、成本核对、差异记录、票据回单、审批 NC、处理记录。

**业务结算详情页面讲法** 详情页按收入退款、成本应付、盈亏核算、审批 NC 展开。这里不是重新录结算，而是穿透应收、收款、退款、发票、付款、回单、应付等源单，让财务判断这张结算单能不能确认。

**操作流程**

1. 进入业务结算，按团期、航次、班期、项目、订单或服务单筛选。
2. 点击“核对”或“处理”，先看结算总览：收入、成本、已收、待收、已付、待付、毛利。
3. 核对收入明细：应收、已认款、退款、优惠、待收。
4. 核对成本明细：供应商、费用项目、应付、预付冲抵、已付、待付。
5. 核对票据回单：销项开票、进项收票、红冲、核验、付款回单。
6. 核对审批 NC：结算审批状态、凭证是否生成、是否失败。
7. 处理差异后确认结算；已结算后发生后补账单、退款、汇兑或发票红冲，进入结算调整。

### 场景二：门店月结对账

**业务背景** 门店对账不是单纯核订单金额，而是核订单、收款、预存、退款和差异。门店侧可自查或发起，总部财务确认承接。

**系统入口** 财务 > 门店对账；财务 > 预存账户；财务 > 资金池。

**当前页面讲法** 门店对账列表看对账单/门店、对账周期、对账类型、订单/收款、预存账户、门店承担/扣项、差异金额、主状态。状态包括待核对、差异待处理、退回补充、待确认、已对账、已关闭。详情 Tab 包括对账总览、收款退款、预存流水、门店扣项、差异记录、后续单据、处理记录。

**操作流程**

1. 进入门店对账，选择门店、周期、对账类型。
2. 系统汇总门店订单、门店收款、银联/POS 水单、预存充值、预存扣款、退款。
3. 财务点击“核对”查看核对依据；有差异点击“处理”。
4. 逐项处理缺流水、预存未确认、退款未执行、订单状态不一致、门店扣项等问题。
5. 核对完成后点击“确认”，结果进入业务结算、预存调整、应收或 NC。

培训重点：以前门店月结靠门店 Excel 加总部 Excel 对齐。系统要让订单、流水、预存、退款自动汇总，财务只看差异。

### 场景三：渠道/OTA/代理对账

**业务背景** 平台账单、订单、佣金、扣点、退款、回款经常不一致。系统目标是自动匹配订单和平台账单，把财务从逐笔 Excel 对账变成差异处理。

**系统入口** 财务 > 渠道结算。

**当前页面讲法** 渠道结算列表看对账单/渠道、账期、订单/优惠、平台扣项、应回款、已到账、差异金额、主状态。状态包括待核对、差异待处理、待确认、已结算、已关闭。详情 Tab 包括结算总览、订单明细、平台扣项、到账认款、应收回款、处理记录。

**操作流程**

1. 导入账单或新建对账，选择渠道、账期、对账范围。
2. 系统按渠道订单、系统订单、金额、日期自动匹配。
3. 核对订单/优惠、平台扣项、退款折减、应回款、已到账。
4. 匹配成功形成对账明细；未匹配或金额不一致进入差异清单。
5. 财务处理订单缺失、退款不同步、佣金规则差异、平台扣项异常。
6. 确认渠道结算，结果进入应收、认款、佣金应付、业务结算和 NC。

### 场景四：结算调整与补充结算

**业务背景** 结算完成后仍可能出现后补供应商账单、退款追溯、汇兑差异、发票红冲、成本差异。已结算对象不能直接改原单，要走结算调整。

**系统入口** 财务 > 结算调整。

**当前页面讲法** 结算调整列表看调整单/来源、原结算单、结算对象、调整类型、调整金额、调整后口径、调整依据、调整状态。状态包括待核对、差异中、待提交、审批中、已生效、已驳回、已关闭。详情 Tab 包括调整总览、原结算、调整依据、金额影响、票据税务、审批 NC、处理记录。

**操作流程** 选择原结算单，选择调整类型，填写调整金额和依据，上传附件或引用来源单据，提交审批或财务复核，生效后生成调整凭证、报表重算和 NC 任务。

培训提醒：已生效财务数据不能覆盖修改，所有调整都必须追加记录，保证审计可追溯。

## 第六部分 六个横向能力

### 1. 横向能力一：发票税务与自动开票

**财务关心的问题** 能否按订单/应收自动生成开票任务、按抬头自动带税号、合并或拆分开票、对接电子发票或税控平台、退款后自动提示红冲、进项发票与账单应付付款匹配、发票状态回写订单结算和 NC。

```text
应收/收款/结算/应付/付款/退款 -> 发票任务
-> 开票/收票/核验/认证/红冲 -> 税务台账 -> NC
```

**系统入口** 财务 > 发票管理。

**当前页面讲法** 发票管理列表看发票任务、发票类型、业务来源、发票对象、发票金额、税票信息、匹配校验、主状态、凭证/NC。状态包括待开票、待收票、待核验、异常中、待红冲、已完成。详情 Tab 包括任务总览、业务来源、金额与票据、税控/核验、凭证/NC、处理记录。

**自动开票讲法** 系统不是让税务会计重新录开票信息，而是根据应收、客户抬头、税号、可开金额、税率和发票类型自动生成开票任务。税务岗核对后，对接电子发票或税控平台开票，结果回写系统；同步失败进入异常处理。

**操作流程**

1. 进入发票管理，按待开票、待收票、待核验、异常中、待红冲筛选。
2. 打开详情，先看业务来源和金额与票据。
3. 销项任务点击“开票”；进项任务点击“收票”，登记后进入待核验。
4. 待核验点击“核验”，选择税务平台查验或境外票据人工核验。
5. 退款或冲减场景进入待红冲，确认红冲后回写税务台账。
6. 完成后生成凭证/NC 任务；同步失败或票面不符进入异常处理。

### 2. 横向能力二：多币种、汇率与汇兑差异

**业务背景** 出境、邮轮、专列、境外酒店、境外地接、国际机票业务大量涉及外币。订单币种、成本币种、付款币种和报表本位币可能不同。

**系统入口** 财务 > 财务设置。

**当前页面讲法** 财务设置页面当前围绕币种和汇率：支持币种列表看币种代码、币种名称、对 CNY 汇率、最后更新时间、更新方式；订单锁汇列表看订单号、外币金额、外币种类、锁定汇率、锁定时间、当前汇率、潜在差异金额、锁汇状态；还支持手动录入汇率、修正、历史。

**必须讲清四个概念** 原币金额、汇率、本币金额、汇率来源及锁定时间。所有涉及钱的对象都应保留这些字段，否则应收、应付、付款、结算和报表无法追溯。

### 3. 横向能力三：资金池与资金调拨

**业务背景** 财务需要知道每个银行账户、支付账户、门店 POS 清算户、预存账户的账面余额、可用余额、待处理资金、冻结占用和同步差异。

**系统入口** 财务 > 资金池；财务 > 资金调拨。

**资金池页面讲法** 资金池列表看资金对象、主体公司、账户类型、系统/来源余额、可用余额、未识别/待核对、冻结/占用、最近刷新、最近资金动作、主状态。状态包括正常、待核对、待确认、占用中、异常。详情里看账户余额、资金变动、待处理资金、关联调拨。

**资金调拨页面讲法** 资金调拨用于集团、主体公司或账户之间的资金转移。列表看调拨单/调拨主体、调出账户、调入账户、调拨金额、调拨用途、预计/实际到账、主状态、流水/NC。操作包括新增调拨申请、提交、转出、到账、再提交。调拨完成后形成流水和 NC。

### 4. 横向能力四：报表与经营分析

**培训定位** 财务报表不是月底手工做出来的，而是订单、认款、应付、付款、结算、发票、NC 这些对象在系统里自动沉淀出来的结果。

**系统入口** 财务 > 财务报表。

**当前页面讲法** 财务报表页面有经营损益、收款分析、付款分析、往来分析、预付分析、资金余额。经营损益列表看结算单、结算方式、产品/线路、团期/订单、结算收入、确认成本、毛利、毛利率、发票/NC；收款分析看收款单、来源流水、订单/应收单、客户/渠道、产品/线路、收款金额、入账结果、NC 状态。

**报表讲法** 报表只读，可穿透到应收、应付、付款、结算、NC 等源单，但不能在报表里直接改业务数据。报表数不对，先穿透源单看单据状态和生效口径。

### 5. 横向能力五：期间关账

**业务背景** 月末关账不能靠财务人工到处问。系统应先做关账预检，把收入、成本、结算、票据、回单和 NC 缺口列出来。

**系统入口** 财务 > 期间关账。

**当前页面讲法** 期间关账列表看关账单/期间、主体公司、收入/应收、成本/应付、结算/发票、NC 凭证、主状态。状态包括核算中、有缺口、待关账、已关账、已反关。详情 Tab 包括关账总览、收入/应收、成本/应付、结算调整、发票税务、NC 凭证、关账缺口、关账记录。

**操作流程** 进入期间关账，选择主体公司和期间，发起关账预检，系统生成异常清单，财务通过缺口入口回到来源页面处理。缺口清理完成后执行关账。已关账期间如需反关，必须发起反关审批，审批通过后回到关账页执行。

培训提醒：关账页只显示缺口和入口，不直接修复各模块明细。修复必须回到源单，保证单据链完整。

### 6. 横向能力六：NC 推送与异常处理

**业务背景** NC 是最终入账和凭证承接系统。ERP 里已确认的财务事件会生成 NC 凭证任务。NC 推送失败不代表业务失败，也不能回滚业务状态，财务要修复失败原因后重新推送。

**系统入口** 财务 > NC 推送。

**当前页面讲法** NC 推送列表看推送任务、业务类型、业务单据、业务对象、金额、科目摘要、校验结果、主状态。状态包括待推送、推送中、成功、失败、缺失、待同步、人工处理。操作包括批量推送、推送、详情、进度、修复、同步。详情里看来源单据、凭证数据、会计分录、校验结果、推送结果、关联入口；失败修复里看失败原因、缺失项、本次修复。

**操作流程**

1. 进入 NC 推送，查看待推送、失败、缺失、待同步任务。
2. 打开凭证任务，核来源单据、金额、科目、辅助核算、客户/供应商、币种、汇率。
3. 对待推送任务执行推送或批量推送。
4. 对失败任务查看失败原因和缺失项。
5. 根据原因修复科目、辅助核算、主体、币种、发票号、客户供应商档案、凭证字段。
6. 保存并重推，成功后保存 NC 返回号和日志。

## 第七部分 财务倒逼上游数据质量

### 1. 财务如何检查上游业务数据质量

财务不是替业务补数据，而是通过系统更早发现数据缺口，并通过退回、卡控、异常提示倒逼业务录准。

| 上游问题 | 财务会在哪里发现 | 正确处理 |
| --- | --- | --- |
| 客户信息、抬头、税号缺失 | 应收管理、发票管理 | 退回销售或客户档案补充，不在财务侧临时造抬头 |
| 订单金额、优惠、补差异常 | 应收管理、业务结算 | 退回订单、合同、优惠审批或补差源头修正 |
| 流水付款方不清、附言缺失 | 到账流水、认款复核 | 保留待识别或退回补充，不随意挂单 |
| 供应商账单无业务对象 | 供应商账单 | 挂接团期、项目、采购批次或服务单，不能直接生成应付 |
| 成本金额与供应商账单不一致 | 供应商账单、应付管理、业务结算 | 进入差异处理，必要时回业务补成本依据 |
| 付款账户、供应商账户异常 | 付款申请、付款执行 | 退回补账户或进入账户校验异常，不执行付款 |
| 回单金额或账户不一致 | 回单核销、付款退回 | 进入差异处理或付款退回，保留银行证据 |
| 发票金额、票号、税号不一致 | 发票管理 | 进入异常、退回补票、红冲或核验处理 |
| 汇率未维护或外币金额不完整 | 应收、应付、付款、结算、财务设置 | 维护币种汇率或锁定汇率，保留汇率来源 |
| NC 科目或辅助核算缺失 | NC 推送 | 修复科目、辅助核算、对象映射后重推，不回滚业务单据 |

讲法：财务不再靠微信群、Excel 和电话追业务资料，而是在系统里看到哪个对象缺什么、影响哪个财务动作，然后按对象退回或卡控，倒逼业务源头录准。

### 2. 财务日常工作顺序（按岗位）

**应收会计每日** 到账流水待识别/部分识别/异常；认款复核待复核/差异中/超收待处理；应收管理待确认/部分收款/逾期；预收管理可用余额/冻结/退款中；预存账户待处理项；转款处理待核销/差异中；开票任务是否因收款触发。

**出纳每日** 资金池余额差异/待处理资金/付款占用；付款执行待付款/校验异常/付款失败/待回单；退款执行待退款/退款中/退款失败；回单核销待匹配/待核销/差异；付款退回待匹配/待确认。

**应付会计每日** 供应商账单待识别/待挂接/待核对/差异中；应付管理待确认/差异中/付款中；付款申请待复核/审批中/已通过；预付管理待分摊/待冲抵/余额待处理；进项发票待收票/待核验/票据差异。

**税务会计每日** 发票管理待开票/待收票/待核验/待红冲/异常中；自动开票任务抬头、税号、金额、税率是否正确；税控/电子发票同步失败；退款触发红冲；发票 NC 状态。

**结算/总账每日** 业务结算待核对/差异待处理/审批中；门店对账和渠道结算状态；结算调整；NC 待推送/失败/缺失/待同步；期间关账预检和报表。

## 第九部分 NC 推送的核心原则

旅行社业务系统推送 NC 的本质是：将业务动作自动转换为会计凭证，财务人员不需要手工重复录入，只做审核、修复和重推。推送的不是报表，而是原始单据和凭证生成所需的结构化数据。

### 1. 基础档案类：一次性同步，变更时更新

| 基础档案 | 为什么影响 NC | 失败时修复位置 |
| --- | --- | --- |
| 主体公司、部门、门店 | 决定凭证公司、责任中心和辅助核算 | 组织/门店档案或 NC 映射配置 |
| 客户、渠道、OTA、企业客户 | 决定应收、收款、开票辅助核算 | 客户档案、渠道档案、NC 客商映射 |
| 供应商 | 决定应付、付款、进项发票辅助核算 | 供应商档案、银行账户、NC 客商映射 |
| 产品、团期、项目、服务单 | 决定收入成本归集维度和结算穿透 | 业务源单或辅助核算映射 |
| 币种、汇率、税率、科目 | 决定原币、本币、税额、科目和汇兑差异 | 财务设置或 NC 科目映射 |

### 2. 收入类推送：应收、收款、退款方向

| 业务事件 | ERP 财务对象 | NC 凭证方向 | 前置条件 |
| --- | --- | --- | --- |
| 订单确认或项目阶段款确认 | 应收单 | 生成应收或待收款凭证任务 | 客户、主体、金额、币种、收款计划完整 |
| 认款确认 | 收款凭证 | 生成收款凭证 | 到账流水已识别，应收核销明细明确 |
| 超收转预收/预存 | 预收单或预存账户流水 | 生成预收或账户余额凭证 | 余额对象、来源流水、使用规则明确 |
| 退款执行完成 | 退款凭证、应收冲减 | 生成退款或红字冲销凭证 | 退款审批、原收款、退款账户、回单完整 |
| 转款核销 | 转款凭证、原新订单核销 | 生成转款或冲销凭证 | 原订单、新订单、可转金额、差额去向明确 |

### 3. 成本类推送：应付、付款、预付方向

| 业务事件 | ERP 财务对象 | NC 凭证方向 | 前置条件 |
| --- | --- | --- | --- |
| 供应商账单确认 | 应付单或应付基础 | 生成应付凭证任务或待付款承接 | 账单已挂接业务对象，成本金额一致或差异已确认 |
| 应付确认 | 应付单 | 进入应付/成本凭证承接 | 供应商、费用项目、原币、本币、发票风险明确 |
| 预付款执行完成 | 预付余额 | 生成预付付款凭证 | 合同节点、付款对象、回单完整 |
| 预付冲抵 | 预付冲抵记录 | 生成冲抵或结转凭证 | 关联应付单、冲抵金额、余额流水明确 |
| 付款执行并回单核销 | 付款单、回单核销 | 生成付款凭证 | 审批通过、账户校验通过、回单核销完成 |
| 付款退回或银行退汇 | 付款退回单、冲销记录 | 生成红字或冲销凭证 | 匹配原付款单，明确应付/预付/结算影响 |

### 4. 团期/项目/渠道/门店结算类推送

团期、项目、订单、服务单、门店、渠道结算是旅行社财务最核心的损益确认动作。结算确认后，系统把收入、成本、退款、佣金、预收预存、预付冲抵、发票、回单和毛利汇总成可入账口径。

| 结算类型 | NC 推送重点 | 财务核对重点 |
| --- | --- | --- |
| 团期/项目结算 | 收入结转、成本结转、毛利确认 | 应收、已收、退款、应付、已付、发票、回单、毛利 |
| 自由行/服务单结算 | 订单或服务单维度损益 | 采购批次成本、服务费收入、代垫款、退款扣损 |
| 门店对账 | 门店内部结算、预存扣款、差异调整 | 门店订单、POS 水单、预存充值/扣款、退款、扣项 |
| 渠道结算 | 应回款、佣金扣点、平台差异 | 渠道账单、系统订单、退款折减、已到账、佣金应付 |
| 结算调整 | 补账单、退款追溯、汇兑差异、发票红冲调整 | 原结算单、调整依据、金额影响、审批 NC |

### 5. 发票类推送

| 发票事件 | ERP 对象 | NC/税务承接 |
| --- | --- | --- |
| 销项开票 | 开票任务、销项发票 | 更新税务台账，按规则生成开票凭证或税务同步记录 |
| 进项收票 | 收票任务、进项发票 | 登记收票后待核验，核验/认证后进入税务台账和 NC |
| 红冲 | 红冲任务、红字发票 | 冲减原发票和相关收入/应收或应付口径 |
| 票据异常 | 异常任务 | 退回补票、确认差异入账或转红冲，不能强行通过 |

### 6. NC 失败处理原则

- NC 页面不能直接修改业务源单。NC 失败只影响凭证推送状态，不代表订单、收款、付款或结算失败。
- 如果失败原因是科目、辅助核算、主体、币种、客商映射或凭证字段缺失，修复配置或档案后重推。
- 如果失败原因是源单金额、发票号、回单号、汇率等业务事实不完整，要回到对应源单处理。
- 已成功推送的凭证不能覆盖修改，后续差异走红字、冲销、结算调整或补充凭证。
- 财务培训要反复强调：ERP 不是把报表推给 NC，而是把已确认的业务财务事件推成凭证。
