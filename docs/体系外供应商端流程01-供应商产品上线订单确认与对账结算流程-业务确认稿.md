# 体系外供应商端流程01：供应商产品上线、订单确认与对账结算流程

业务确认稿 v1.0  
编写日期：2026年8月2日  
面向角色：体系外供应商运营、供应商端操作人、外采产品部、外采计调、财务应付/付款/发票/NC、法务/合规负责人

## 本文件怎么读

- 体系外供应商运营和供应商端操作人重点看第五至第十三部分，确认准入、产品上传、供给维护、订单确认、名单同步、售后差异和账单提交。
- 外采产品部重点看第八至第十二部分，确认供应商产品如何被凯撒采用、代理入库、销售承接和账单审核。
- 财务应付、付款、发票和 NC 角色重点看第十二至第十八部分，确认供应商账单进入应付、付款、发票和 NC 的边界。
- 法务重点看第五部分、第十一至第十三部分，确认供应商准入、资料授权、结算依据和付款回执口径。

## 一、文档目的

本文面向凯撒体系外第三方供应商和供应商运营，确认供应商在供应商端如何完成产品上线、供给维护、订单确认、名单资料回传、售后差异、对账结算和付款回执查看。

体系外供应商包括：

- 中国国旅等同业旅行社。
- 境内外地接社。
- 邮轮资源商。
- 专列或大交通资源商。
- 酒店、车队、签证、保险、单项服务商。
- 其他与凯撒集团没有内部主体关系的供应方。

本文不适用于凯撒集团内部 A 公司和 B 公司之间的产品共享互采。集团内部主体互采由凯撒外采产品部在《外采产品部流程01：外采产品引入、代理包装、销售承接与结算流程》中确认。

## 二、核心结论

体系外供应商端流程必须坚持以下原则：

1. 供应商端只给凯撒体系外第三方使用。
2. 供应商上传的是原始产品和供给，不是凯撒最终销售页。
3. 凯撒各主体公司可以选择采购供应商产品，并形成本主体的代理产品或可售安排。
4. 采购主体公司对客户销售、签约、收款；供应商只负责供给确认和履约资料回传。
5. 供应商确认订单前，客户侧合同和最终承诺应受系统规则控制。
6. 回团或到结算节点后，供应商提交账单或结算依据，凯撒审核后形成应付和付款。
7. 供应商发起的是结算申请或账单，不是付款单；付款由凯撒财务执行。

## 三、完整业务链路

供应商端完整链路如下：

```text
供应商准入
-> 供应商端开通账号
-> 供应商上传产品和附件
-> 供应商维护供给、余位、公开价、结算价
-> 凯撒外采产品部审核并选择代理入库
-> 凯撒包装产品、维护对客价和销售策略
-> 客户下单后提交供应商确认
-> 供应商确认有位、无位、需补差或保留时效
-> 供应商接收名单、资料和变更
-> 出行变更、客诉、扣损和差异处理
-> 到结算点后供应商提交账单/发票/结算依据
-> 凯撒外采计调审核账单和差异
-> 凯撒财务形成应付、付款、发票、回单和 NC
-> 供应商端查看付款状态或付款回执
```

这条链路中，供应商负责提供和确认供给；凯撒外采产品部负责是否采用、怎么包装、怎么销售和账单初审；财务负责最终应付、付款和账务处理。

## 四、供应商端需要分清的对象

| 对象 | 维护方 | 业务含义 | 不能混淆的点 |
| --- | --- | --- | --- |
| 供应商主体 | 凯撒发起准入，供应商/财务/法务补资料 | 第三方工商主体、资质、联系人、账户、合同 | 不是凯撒内部主体公司 |
| 供应商合作范围 | 凯撒外采负责人维护 | 供应商可合作的区域、产品线、负责人和权限 | 不等于集团内部共享范围 |
| 供应商原始产品 | 供应商端维护 | 第三方提供的线路、航次、套餐、服务和素材 | 不能直接对客销售 |
| 供应商供给安排 | 供应商端维护 | 某个团期、航次、班期或出行日期的余位、公开价、结算价 | 不等于凯撒已开售 |
| 凯撒代理产品 | 凯撒外采计调维护 | 凯撒采用后包装出的本主体可售产品 | 不改变原产品类型 |
| 采购主体 | 选择采购供应商产品的凯撒主体 | 例如 B 公司采购中国国旅产品 | 决定应付和付款主体 |
| 供应商订单确认 | 供应商回传 | 确认是否接待、有无位、是否补差 | 未确认前不应给客户最终承诺 |
| 供应商结算申请/账单 | 供应商提交，凯撒审核 | 供应商向采购主体请款或对账 | 不是财务付款单 |

## 五、供应商准入与账号开通

### 1. 什么时候开通供应商端账号

以下情况应走体系外供应商准入：

- 第三方同业旅行社提供完整线路或系列团。
- 地接社提供目的地接待或打包产品。
- 邮轮资源商提供航次、舱房或邮轮代理产品。
- 酒店、车队、签证保险等第三方服务商提供可售服务。
- 外部供应商需要自行维护产品、余位、报价和订单确认。

以下情况不走供应商端：

- 凯撒集团内部主体公司维护自己的自营产品。
- A 公司销售 B 公司自营产品。
- 内部共享产品的 A-B 对账。

### 2. 供应商准入资料

准入资料包括：

- 供应商名称、简称、注册地、证照号。
- 供应商类型，例如同业旅行社、地接社、酒店、车队、邮轮资源商等。
- 主联系人、联系电话、邮箱。
- 拟合作范围和有效期。
- 合同或合作协议。
- 供应商资质、旅行社许可证、责任险证明、产品授权。
- 结算方式、开户名称、开户银行、银行账号、币种、Swift Code 等。
- 发票信息、纳税信息或境外付款凭证规则。
- 我方负责人、风险备注和准入原因。

业务规则：

- 供应商银行账户属于财务主数据，必须经过财务审核后才能付款。
- 供应商账号应按合作范围授权，不应让一个账号看到与其无关的产品线。
- 准入通过不代表具体产品可售，产品和供给仍需单独审核。

## 六、供应商上传产品

供应商进入供应商端产品管理，可以通过以下方式新建产品：

- 手工新建产品。
- 上传 Word、PDF、图片、报价单或宣传资料。
- 粘贴官网、在线文档或 URL。
- 粘贴报价文本。
- 使用 AI 智能建品拆解行程、费用、退改和资料要求。

供应商提交前应补齐：

- 产品名称和产品类型。
- 出发地、目的地、天数和适合人群。
- 逐日行程或服务说明。
- 费用包含、不含。
- 退改规则。
- 报价币种和报价有效期。
- 地接社或实际接待方信息。
- 图片版权和资料授权承诺。
- 免责声明或供应商上线承诺。

业务规则：

- 供应商原始产品只是供给资料，不是凯撒销售页。
- 供应商不能直接决定凯撒对客销售名称、销售渠道和我方价格。
- 供应商提交的完整线路必须有实际接待方或地接社信息。
- 图片版权和资料授权必须留痕。

## 七、供应商维护供给

供应商在供给维护中维护具体团期、航次、班期或出行日期。

供给字段包括：

- 产品和供给编号。
- 出发日期、返回日期或服务日期。
- 可供数量、余位、舱房、铺位、房量或服务能力。
- 供应商公开价。
- 供应商结算价。
- 价格币种和有效期。
- 报名截止和材料截止。
- 订单确认方式：固定配额、每单确认、房态回传、舱位回传、仅询位。
- 确认后保留时效。
- 退改和扣损规则。

业务规则：

- 供应商公开价和结算价是供应商提供给凯撒的供给依据。
- 凯撒是否采用、怎么销售、卖多少钱，由采购主体和外采计调决定。
- 供应商更新价格或余位后，应进入凯撒确认，不应直接影响已确认订单。

## 八、凯撒采用和代理入库

供应商提交产品后，由凯撒外采产品部审核并决定是否采用。

供应商端应能看到：

- 已提交。
- 待凯撒确认。
- 已采用。
- 已退回修改。
- 已拒绝。
- 已停售或已终止合作。

凯撒采用后，会在凯撒内部形成代理产品或可售安排。供应商不能直接维护凯撒对客销售名称、对客行程、销售渠道和客户成交价。

不同凯撒主体可以分别采购同一个供应商产品，但各自形成自己的代理安排和结算关系。例如 B 公司采购中国国旅产品后，B 是中国国旅的结算对象；A 不能自动继承 B 的供应商结算关系。

## 九、销售下单和供应商订单确认

客户下单后，如产品需要供应商确认，供应商应在供应商端处理订单确认。

供应商确认时应看到：

- 凯撒采购主体。
- 产品名称和出发日期。
- 订单人数和结构。
- 房型、舱型、铺位或服务项目。
- 客户名单是否已完整。
- 特殊餐食、证件、签证、保险或办理材料。
- 保留到期时间。
- 需确认的问题或备注。

供应商确认时应回传：

- 确认结果：已确认、暂时保留、无位、需补差、已取消。
- 确认数量。
- 供应商确认号。
- 确认时间。
- 保留到期时间。
- 补差金额或原因。
- 替代日期或方案。
- 供应商备注。

业务规则：

- 固定配额直接售卖的产品，可在库存内直接下单，但仍应保留供应商供给依据。
- 二次确认产品必须先提交供应商确认，确认前不应放行客户最终合同。
- 供应商需补差时，应先处理价格差异和客户确认，再放开合同。
- 供应商无位时，销售应改期、换产品或取消，不应继续签约。

## 十、名单、资料和履约同步

客户资料完整后，凯撒外采计调应向供应商同步：

- 客户名单。
- 证件资料。
- 房型、舱型、铺位或同住关系。
- 特殊餐食和特殊人群说明。
- 签证、保险或办理材料。
- 订单补差、升级和附加服务。

如果名单已同步，后续客户改名、换人、退团、改期，应形成变更记录，并由供应商确认是否产生损失。

业务规则：

- 供应商确认件、名单回传和变更记录应留在系统中。
- 供应商确认不能只在微信或电话中保留。
- 涉及客户侧补差和退款时，销售发起售后；涉及供应商扣款时，进入供应商结算差异。

## 十一、售后、变更和客诉

供应商外采常见异常：

- 供应商确认后又无位。
- 供应商临时涨价或要求补差。
- 客户退团、换人、改期。
- 酒店、航班、舱型、车辆、地接服务变化。
- 客户投诉接待质量。
- 供应商责任导致补偿或扣款。

处理流程：

1. 销售或客服记录客户诉求。
2. 外采计调查看订单、供应商确认记录、名单和行程。
3. 外采计调与供应商确认事实、责任、补偿或扣款方案。
4. 涉及客户退款、补差或赔付时，进入销售售后和财务流程。
5. 涉及供应商扣款时，在供应商结算申请或差异处理中体现。

业务规则：

- 门店不直接决定扣不扣供应商款。
- 供应商责任扣款必须有依据，例如投诉记录、客户确认、供应商沟通记录或审批结果。
- 已结算后发现差异，走二次结算、补付、冲减或后续抵扣。

## 十二、供应商对账结算

供应商建议采用“到结算点后，由供应商提交账单，我方审核”的方向。

流程如下：

```text
团期回团或服务完成
-> 供应商提交账单、订单明细、发票或结算依据
-> 外采计调审核订单、人数、价格、加减项和扣款
-> 差异退回供应商或内部审批确认
-> 审核通过后交财务形成应付
-> 财务审核发票、付款资料和账户
-> 财务付款并回传回执
```

业务规则：

- 供应商发起的是结算申请或账单，不是付款单。
- 外采计调审核通过前，不应生成正式可付款应付。
- 财务不负责判断供应商是否实际接待，接待事实由外采计调确认。

供应商账单应包含：

- 供应商名称和结算账户。
- 采购主体公司。
- 结算周期或团期。
- 订单明细。
- 人数和价格结构。
- 供应商结算价。
- 加项和减项。
- 投诉扣款。
- 税费或发票信息。
- 应结金额。
- 发票或境外凭证。
- 供应商备注。

外采计调审核时，应能看到系统金额、供应商账单金额、差异金额和差异原因。

## 十三、财务应付、付款和回执

供应商结算审核通过后，财务承接：

- 供应商账单。
- 应付单。
- 付款申请。
- 付款执行。
- 付款回单。
- 发票或境外凭证。
- NC 付款凭证和结转凭证。

供应商端应能查看：

- 账单审核状态。
- 差异退回原因。
- 应付确认状态。
- 发票或凭证审核状态。
- 付款状态。
- 付款回执或付款日期。

业务规则：

- 供应商不能直接发起付款单。
- 付款账户必须使用财务审核通过的供应商账户。
- 境外付款、外币结算、税费和发票规则由财务确认。
- 付款回执是否必须回传供应商端，需要业务和财务确认。

## 十四、供应商端和凯撒后台如何承接

| 业务阶段 | 系统入口 | 当前岗位做什么/产生什么 |
| --- | --- | --- |
| 供应商产品维护 | 供应商端 > 产品管理 / 新建产品 | 供应商上传原始产品、行程素材、价格规则和资料附件 |
| 供应商供给维护 | 供应商端 > 供给维护 / 新建团期 / 批量开排 | 供应商维护余位、公开参考价、结算价、确认方式和保留时效 |
| 供应商订单确认 | 供应商端 > 订单确认 | 供应商回复已确认、无位、需补差、保留到期或确认号 |
| 供应商对账结算 | 供应商端 > 对账结算 | 供应商按接待结果提交账单、差异说明和发票资料 |
| 凯撒产品市场 | 产品中心 > 外采产品 > 产品市场 | 外采产品部审核是否采用，并确认供应商结算价和入库规则 |
| 凯撒代理包装 | 产品中心 > 外采产品 > 代理产品包装 | 外采产品部包装凯撒销售名称、行程规则、图片合规、渠道和对客价格 |
| 供应商账单 | 财务 > 供应商账单 | 外采审核通过后，财务按账单形成应付、差异处理和付款依据 |
| 应付付款 | 财务 > 应付 / 付款 / 发票 / NC | 财务处理付款、发票、回单和 NC，供应商端查看进度或回执 |

## 十五、关键状态口径

| 状态 | 含义 |
| --- | --- |
| 供应商草稿 | 供应商产品或供给尚未提交 |
| 待凯撒确认 | 供应商已提交，等待凯撒审核 |
| 已采用 | 凯撒采购主体已采用并可包装 |
| 入库审核中 | 凯撒代理入库待审核 |
| 待包装 | 代理产品尚未完成销售包装 |
| 销售中 | 已可按确认规则销售 |
| 订单待供应商确认 | 订单已提交供应商，等待回复 |
| 供应商已确认 | 供应商确认可接待 |
| 供应商无位 | 供应商无法接待 |
| 供应商需补差 | 供应商要求价格或服务调整 |
| 待供应商提交账单 | 已到结算点，等待供应商提交 |
| 待外采审核 | 供应商已提交，等待外采计调审核 |
| 待财务审核 | 外采已确认，等待财务应付和发票审核 |
| 已付款 | 财务付款完成并回传回执 |

## 十六、业务补充事项与后续细化范围

1. 供应商端与集团内部主体互采入口必须分开。
2. 供应商端产品、供给、订单确认和对账结算权限必须按合作范围控制。
3. 供应商订单确认结果必须同步到销售订单和代理安排。
4. 二次确认产品在供应商确认前应拦截合同签署。
5. 供应商提交账单后，外采计调审核通过前不生成正式应付。
6. 供应商账单差异、投诉扣款、补差、退团损失需要进入结算差异。
7. 供应商付款回执是否回传供应商端需要确认。
8. 供应商公开价、结算价和我方对客价需要按权限控制展示。

## 十七、供应商端常见端到端场景

本章只讲供应商端动作会牵动凯撒外采、销售、履约和财务继续处理的场景。准入资料填写、产品上传字段和账号操作，前文已经说明，不在这里重复。供应商阅读时重点确认：我在端口提交后，凯撒内部谁处理，我什么时候能看到确认、账单和付款结果。

### 场景一：供应商产品被凯撒采用

体系外供应商在供应商端维护产品、价格、库存、退改规则和确认方式后，凯撒外采产品部会在后台审核是否采用。审核通过后，外采产品部会把供应商原始产品包装成凯撒可售产品，设置凯撒销售名称、对客价格、销售范围和内部承接规则。

采用后，供应商继续负责供给和订单确认，但不能直接控制凯撒对客价、销售渠道和合同条款。销售按凯撒产品对客下单，客户合同和客户收款由凯撒负责；供应商只根据凯撒传来的订单、名单和规则确认接待。

供应商最终能看到的结果，是产品是否被采用、是否可接单、后续订单按什么规则确认。产品被采用不代表每个订单都自动确认，具体订单仍要按确认规则处理。

### 场景二：供应商确认订单

凯撒销售卖出供应商产品后，需要供应商确认的订单会进入“供应商端 > 订单确认”。供应商需要回传明确结果，例如已确认、无位、暂保留、保留到期、需要补差、提供替代方案等。

确认结果会回到凯撒销售和外采产品部。确认成功时，销售继续合同、收款和游客资料；需要补差时，销售向客户确认是否接受；无位或替代方案时，销售再处理改期、取消或换产品。外采产品部负责跟进供应商响应时效，避免订单长时间悬着。

供应商最终要给出的是“是否能接待、按什么条件接待”的结论。未确认前是否拦截合同，保留到期是否自动释放，需要凯撒和供应商在规则中明确。

### 场景三：名单同步后发生退改或差异

订单确认后，凯撒会把游客名单、证件、房型、舱型、铺位、特殊需求等信息同步给供应商。后续如果客户退订、改期、换人、资料不合格或服务内容变化，供应商需要在端口中确认是否能接待，以及是否产生扣损或补差。

客户侧由凯撒销售和财务处理，例如客户退款、补收、合同变更。供应商侧由外采产品部和财务处理，例如账单扣减、追加费用、责任扣款或未来账单抵扣。两个结果会互相影响毛利，但不能在同一个动作里混着处理。

供应商最终需要确认的是接待事实和差异金额。名单未确认、退改扣损没有依据、补差没有确认时，供应商账单可能会被外采或财务退回。

### 场景四：供应商提交账单

供应商完成接待或达到约定结算节点后，在“供应商端 > 账单/结算申请”提交账单、发票或境外凭证。账单需要关联订单、团期或项目，列明确认人数、价格、退改差异、扣款或补差。

账单提交后，先由外采产品部审核业务事实，重点看人数、价格、接待结果、退改扣损和差异说明是否正确。外采审核通过后，财务再审核供应商账户、付款主体、币种、发票、合同或账单依据和付款风险，符合条件后进入付款流程。

供应商最终能看到的是账单审核状态、应付确认金额、付款进度和回执。提交账单不是付款申请，也不代表马上付款；账单有差异、发票不符合要求或账户信息未通过财务审核时，会被退回补充。

## 十八、业务确认事项

1. 供应商端是否只面向凯撒体系外第三方。
2. 外部供应商是否必须先完成准入和财务账户审核后才能开通产品维护。
3. 供应商上传完整线路时，地接社、图片版权和免责声明是否必填。
4. 供应商公开价、结算价和我方对客价三层价格是否作为固定规则。
5. 供应商二次确认产品在确认前是否必须拦截合同。
6. 供应商对账是否采用“供应商提交账单，我方审核”的方向。
7. 供应商发票、境外凭证、付款前收票/付款后补票规则如何配置。
8. 供应商账单差异由谁审核，哪些差异需要审批。
9. 供应商付款回执是否必须回传供应商端。
10. B 采购供应商产品后共享给 A 时，A 是否只和 B 结算，B 再和供应商结算。
