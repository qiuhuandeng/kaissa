# 订单和团期模块对订单、回团明细字段的业务记录点核对

更新时间：2026-09-12

> 本文所称“业务记录点”，是指销售、计调或团控完成一个真实业务动作时，系统同时保存该次业务事实、操作人、发生时间及变化前后内容。它不是页面浏览或按钮点击次数统计，也不是要求业务人员重复填写报表的年、月、周字段。

## 一、本次范围和业务链路

本次只核对财务补充的订单口径、回团口径两套明细字段，判断订单模块和团期模块能否产生所需的上游业务事实。

完整链路为：

`产品和目的地资料 → 团期/航次/班期/营期 → 销售下单与订单确认 → 团期履约 → 实际回团 → 收退款、成本和业务结算 → 财务明细`

- 销售顾问在订单模块负责客户订单、销售内容、数量、成交金额、销售与渠道归属及后续售后变化。
- 计调、团控在团期模块负责出行编号、计划日期、实际出团和实际回团、履约负责人及团队状态。
- 财务人员在收款、成本、结算和收入确认模块负责正式实收、供应商结算金额、业务结算收入、财务确认收入和财务回团月份。
- 年、月、周、双周、本周、上周等期间字段由报表根据业务日期和统一财务日历计算，不在订单或团期页面手工维护。

## 二、总体判断

现有订单和团期原型能提供一部分字段雏形，但还不能直接生成可信的订单口径和回团口径明细。

| 判断类别 | 结论 |
|---|---|
| 已有业务雏形 | 凯撒订单号、订单状态、创建时间、产品名称、产品类型、团期/出行编号、计划出团和计划回团日期、销售姓名、门店、人数或数量、订单金额；团期侧还有团控/计调、销售状态、履约状态和结算状态 |
| 可由报表计算 | 订单年/月/周/双周、回团年/月/周/双周、出团年/月/月日、本年、本月、周度、上周、订单周简述、周报里单项、跨年标识 |
| 页面有选择或展示但未形成可靠记录 | 渠道、分销商、平台、客服、部门、产品归属、供应商、目的地、实收、成本和结算状态；部分内容来自固定样例、名称推断或浏览器本地记录 |
| 必须新增业务记录点 | 订单确认生效、订单销售内容、发生时经营归属、订单状态变化、售后调整生效、订单与团期关联、实际出团、实际回团、回团更正 |
| 必须由其他模块产生 | 正式实收、供应商结算金额、业务结算收入、财务确认收入、实际成本、财务回团月份；毛利、毛利率和差异由报表基于这些正式金额计算 |

当前代码证据：

1. `merchant/sales/booking.html`可以选择来源渠道、分销商、分销员和平台，但保存订单时只保存门店和销售姓名，没有保存这些渠道结果。
2. 新订单写入浏览器本地记录`caesarOrderFinanceEvents`，包含订单号、产品、团期显示值、客户、门店、销售、金额、数量结构、状态和浏览器创建时间；订单号日期部分仍固定为`20260704`，不能作为正式编号或订单日期依据。
3. `merchant/sales/orders.html`和`merchant/tour/schedule-orders.html`是两套高度近似页面，虽然读取同一浏览器记录，但仍可能继续产生字段和逻辑分叉。
4. `shared/schedule-builder-page.js`可以形成团号、产品、线路、团期类型、计划日期、库存、价格、计调和三个阶段状态，但计划回团日期按线路天数重新计算，未完整保存页面确认的全部产品归属、供应商和目的地结果。
5. `merchant/tour/schedules.html`的“标记已回团”只把内存中的履约状态改为“已回团”，没有记录实际回团日期、确认人、确认时间和更正依据，刷新后也不能作为稳定履约事实。

## 三、两套明细字段的来源和缺口

### 3.1 时间和期间字段

| 财务明细字段 | 正确来源 | 当前能力 | 业务记录或计算要求 |
|---|---|---|---|
| 订单日期 | 订单首次创建时间或确认生效时间，最终口径待财务确认 | 下单时有浏览器创建时间，订单详情仍固定显示同一时间 | 分开保存创建时间和确认生效时间；迁移订单保留原系统日期 |
| 订单年、订单月、订单周、订单周简述 | 订单口径日期 | 可计算，但基础日期不可靠 | 由统一财务日历计算，不手填 |
| 年度、本月、周度、上周、周报里单项 | 报表日期与数据截止时间 | 当前没有统一规则 | 作为报表筛选或标识计算；名称和判断规则待财务确认 |
| 订单双周-时间段、订单双周 | 订单口径日期与双周日历 | 当前没有统一规则 | 报表计算并保留日历版本 |
| 出团日期 | 团期计划出团或实际出团 | 有计划日期，没有稳定实际出团记录 | 明细必须明确使用计划还是实际；建议分别保留 |
| 回团日期 | 实际回团或服务完成日期 | 只有计划日期和“已回团”状态 | 新增实际回团确认记录，不能以计划日期代替 |
| 财务回团月 | 财务确认该笔履约进入回团业绩的月份 | 订单、团期均无 | 由财务回团确认产生，不由团控填写 |
| 回团周、回团日期年/月/月日、回团双周 | 实际回团日期或财务回团月份 | 基础日期缺失，当前不可可靠计算 | 先确认日期口径，再由报表计算 |
| 出团日期年/月/月日 | 明细采用的出团日期 | 有计划日期即可计算 | 报表计算，不重复保存拆分字段 |

### 3.2 订单、团期和状态字段

| 财务明细字段 | 正确来源 | 当前能力 | 业务记录要求 |
|---|---|---|---|
| 凯撒订单号 | 新系统订单创建 | 有编号雏形 | 使用正式唯一编号；生成后不修改，作废仍保留 |
| 通通游订单号 | 历史迁移或通通游接入 | 无 | 保存来源系统、原订单号、导入批次和防重复标识 |
| 凯撒团号 | 团期/航次/班期/营期创建 | 有团号及不同出行对象 | 使用同一出行记录，订单销售内容保存明确关联 |
| 订单状态 | 订单主流程状态 | 有状态展示和部分动作，但缺变化记录 | 每次确认、取消、作废、完成保存前后状态、时间、操作人和依据 |
| 数据来源 | 新系统创建或历史数据接入 | 无正式字段 | 新订单自动记“新系统”；迁移数据保留原系统，不由业务手选 |

### 3.3 产品、目的地和供应字段

| 财务明细字段 | 正确来源 | 当前能力 | 业务记录要求 |
|---|---|---|---|
| 出入境类型 | 产品的旅游范围 | 产品侧有字段雏形，订单未保存 | 订单确认时保存发生时旅游范围 |
| 产品类别、产品类型细分 | 产品类型与批准的细分类型 | 订单保存产品类型，但细分和版本不完整 | 保存产品类型、细分类型、产品/报价版本，不能靠名称加工 |
| 产品分公司、产品归属 | 产品经营公司和产品归属部门 | 团期页按产品名称固定推断组织 | 从产品发布结果带入，订单确认时保存发生时归属 |
| 产品代理、产品代理人 | 可能分别指代理关系和产品负责人 | 当前没有稳定字段 | 建议拆为供应方式/经营分类、产品负责人；原词含义待财务确认 |
| 供应商 | 产品或销售内容的主要供应商，成本侧还需成本项目供应商 | 手工单项可保存，标准订单和团期不完整 | 订单销售内容保存主要供应方；实际供应商结算从成本明细取得 |
| 目的地分区 | 标准目的地映射 | 产品与团期使用固定资料或名称推断 | 保存主要目的地及当时分区版本 |
| 目的地分区（管理口径） | 财务批准的管理分类 | 无 | 通过带生效时间的管理映射产生，不能在报表按文字猜测 |
| 目的地国家/省份、目的地城市 | 产品线路或单项服务 | 标准产品订单未稳定保存；单项服务有手工目的地 | 订单确认时保存主要目的地和全部目的地；多目的地汇总规则待确认 |
| 自营/外采 | 供应方式或财务经营分类 | 无统一判断 | 分开保存供应方式与经营分类；凯撒甄选归类待确认 |
| 产品名称 | 订单采用的产品名称 | 已有 | 与产品编号、报价版本一起保存，产品改名不覆盖历史 |
| 出发城市 | 产品线路或团期 | 详情页多为固定展示 | 团期确认时保存主要出发城市，订单引用发生时结果 |
| 业务线汇总、业务线 | 产品经营分类资料 | 无正式贯通字段 | 由产品分类配置带入，订单确认时保存版本 |

### 3.4 销售、客服和渠道字段

| 财务明细字段 | 正确来源 | 当前能力 | 业务记录要求 |
|---|---|---|---|
| 销售ID、销售名字 | 下单销售及人员任职 | 只稳定展示销售姓名，没有人员身份 | 保存员工身份、姓名及订单发生时任职版本 |
| 销售分公司 | 销售发生时组织归属 | 无，部分详情按固定规则展示部门 | 订单确认时保存销售公司、分公司、部门和销售组 |
| 客服 | 订单客服分配 | 详情页固定展示 | 客服分配、改派形成记录；是否进入财务业绩归属待确认 |
| 渠道 | 渠道大类和具体来源 | 下单可选择但保存遗漏；固定样例行有渠道 | 订单确认时保存渠道大类、具体来源和规则版本 |
| 分销商 | 分销商或平台店铺 | 下单可选择但保存遗漏 | 分销订单保存分销商身份；非分销订单明确“不适用” |
| 亿步渠道分类、25年渠道 | 某一版本的渠道管理映射 | 无 | 不做订单手工字段；保存原渠道和规则版本，由报表按有效映射生成 |
| 单团客户名称 | 单团/项目订单委托客户 | 项目团页面有客户字段雏形 | 保存合同客户身份与名称；非单团明确“不适用” |

### 3.5 数量和金额字段

| 财务明细字段 | 正确来源 | 当前能力 | 业务记录要求 |
|---|---|---|---|
| 订单人数或商品数 | 订单销售内容数量 | 已能保存人数和部分舱房、铺位、服务结构 | 必须同时保存数量单位；售后变化追加增减记录，不只留最终合计 |
| 订单流水（万元） | 订单确认时有效成交金额及后续业绩调整 | 有订单合计、优惠和客户应付雏形 | 先按元和币种保存销售内容金额；报表展示时换算万元 |
| 实收（万元） | 财务确认且分配到订单的正式收款 | 新订单固定为0，认款后未稳定写回 | 从认款/收款确认记录汇总，订单模块只展示结果 |
| 趣享供应商结算价 | 若指供应商应结金额，应来自供应商账单或成本确认 | 订单、团期存在固定或推断金额 | 不从售价、订单金额或比例推算；正式名称和范围待财务确认 |
| 收入 | 业务结算收入或财务确认收入 | 订单、团期不能正式产生 | 拆成业务结算收入、财务确认收入，不用一个“收入”字段混用 |
| 毛利额、毛利率 | 收入与匹配成本的报表计算结果 | 页面有固定或推断毛利 | 使用选定收入减实际成本；汇总毛利率按合计金额相除 |
| 差异 | 两个明确金额或来源的比较结果 | 含义不明确 | 必须先定义比较对象，如订单流水与业务收入差异、系统与来源差异 |

## 四、订单模块最小业务记录点

| 记录点 | 触发动作 | 必须保存的业务事实 | 主要支持字段 |
|---|---|---|---|
| 订单创建 | 销售首次保存订单 | 凯撒订单号、创建时间、创建入口、来源系统、原订单号（迁移数据）、客户 | 订单号、订单日期、数据来源、通通游订单号 |
| 订单销售内容确认 | 选择产品/团期并确认数量和价格 | 销售内容编号、产品和版本、团号、数量、单位、单价、金额、币种、优惠构成 | 产品名称、团号、人数/商品数、订单流水 |
| 经营归属确认 | 订单提交或确认前核对“本单经营归属” | 产品经营公司/部门/负责人、旅游范围、经营分类、目的地、销售组织/人员、客服、渠道、门店、分销商及各自规则版本 | 产品归属、出入境、目的地、销售、渠道、分销商 |
| 订单确认生效 | 订单满足规则正式生效 | 确认时间、前后状态、确认人、是否计入业绩所需业务状态 | 订单口径日期、订单状态 |
| 订单状态变化 | 预留、占位、取消、作废、执行、完成 | 前后状态、发生时间、操作人、原因、关联单据 | 有效订单、状态追溯、数据截止复算 |
| 售后调整生效 | 取消、退订、改期、转团或改价审批生效 | 原订单和销售内容、数量及金额增减、原团号和新团号、生效日期、调整原因 | 退订人数、净订单业绩、调整期间、订单与回团差异 |

## 五、团期模块最小业务记录点

| 记录点 | 触发动作 | 必须保存的业务事实 | 主要支持字段 |
|---|---|---|---|
| 团期创建/确认 | 计调创建并确认团期 | 团号、产品和线路、团期类型、计划出回团日期、出发城市、团控/计调、履约公司、主要供应方 | 凯撒团号、产品、计划出回团、负责人、供应商 |
| 订单关联团期 | 订单确认、改期或转团 | 订单销售内容、团号、占用数量和单位、生效时间、原关联和新关联 | 订单与团期核对、人数和跨团调整 |
| 实际出团确认 | 团控确认出团 | 实际出团日期时间、确认人、确认时间、异常说明 | 实际出团及日期拆分字段 |
| 实际回团/完成确认 | 团控确认回团、离船、结营、服务完成或项目验收 | 实际完成日期、完成类型、确认人、确认时间、异常和依据 | 回团口径基础日期、团队状态、跨年标识 |
| 回团更正 | 经批准更正实际完成日期 | 原日期、新日期、原因、申请人、审批人、更正时间 | 历史报表复算和跨期差异 |
| 履约状态变化 | 未开始、执行中、已完成、取消 | 前后状态、发生时间、操作人和依据 | 团队状态和异常筛选 |

财务回团月份和回团业绩确认状态不放在团期模块维护。团控先确认实际完成，财务再决定该笔履约进入哪个财务月份，并保留确认、退回和调整记录。

## 六、当前可以直接推进的结论

1. 订单、团期模块可以承担两套明细中的业务基础字段，但不能单独承担正式实收、成本、收入和毛利。
2. 第一优先级不是继续往报表加列，而是补齐订单确认生效、发生时归属和实际回团三个核心记录；缺少它们，订单周报和回团周报都不可复算。
3. 年、月、周、双周及“本年/本月/周度/上周”等字段全部由报表计算，不在业务页面新增输入框。
4. 销售订单与团期订单必须引用同一客户订单；团期订单只作为按团查看订单的履约视角。
5. `产品代理/产品归属/产品分公司`、`收入`、`趣享供应商结算价`和`差异`仍需财务确认正式含义，当前只能按建议字段拆分，不能作为既定口径实施。

## 七、唯一下一步

按本核对结果确定第一批页面原型范围：先改订单确认前的“本单经营归属”和订单保存内容，再改团期“标记已回团”为可填写实际回团日期、确认依据并保留更正入口的“确认回团”动作；不在本批建设真实收款、成本、收入和毛利联动。
