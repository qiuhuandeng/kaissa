# 审批模板字段与条件交互调整

本次依据用户“执行改动”及随后提供的企微流程截图，调整模板编辑页的审批内容和审批流程。使用者是配置管理员，上游是各业务申请表及公司组织资料，下游是发布后的模板；审批人日常逐级办理仍属于原方案第二批。本次只改编辑原型及直接共用脚本，不扩展来源业务或财务执行。

## 审批内容

- 从当前事项的业务字段中选择展示项，支持添加和改名分组、组内排序、跨组移动以及移除普通展示项；不在审批模板另造一套业务录入表。
- “业务必填”由来源表单决定；“审批必显”指审批详情必须保留的核对项，两者独立。普通展示项可选择，必显项锁定，仍可调整分组和顺序。当前必显集合是原型默认方案，正式集合须由对应业务负责人确认。
- 门店档案准入按现有 `merchant/sales/store/index.html` 新增表单核对了 27 个目录项，包括申请信息、管理归属、联系人、自营资质、加盟资质、合作协议及启用安排。可映射字段逐一检查表单实际控件；自动带入的申请人和申请类型不伪称源表控件。未加入源表没有的营业时间。
- 门店档案、销售授权和财务配置分别使用自己的核对内容；档案准入不混入保证金等财务审核字段。其他事项沿用原核心核对项并提供统一展示配置，尚未逐一扩成来源业务全部字段目录。
- 可隐藏空的普通展示项；必显缺值显示“未填写”。本次变更字段单列前后值，不受展示选择及空值隐藏影响；即使门店类型变化后原字段不再适用，也保留变更核对。“全部申请资料”保留当前类型适用资料。
- 提供审批详情预览，可切换加盟、自营、独立资质，新增或变更，以及选填资料是否填写。补充说明及附件可分别设必填，不改变来源业务的必填要求。
- 保存草稿及发布版本包含展示分组和顺序。旧已发布版本没有新配置时继续按旧固定内容查看，编辑其修订草稿时才初始化新展示配置。

## 按用户企微截图调整流程交互

| 位置 | 交互与结果 |
| --- | --- |
| 蓝色申请人卡片 | 点击进入已有适用范围步骤，维护公司和部门 |
| 分叉横线中央“添加条件” | 新增同级条件，保存后插在默认条件之前；不再放一张能点击的大“条件分支”卡片 |
| 条件卡片名称 | 单独改名，不进入条件规则抽屉 |
| 条件卡片正文及右箭头 | 仅设置当前条件的判断字段、比较方式及数值 |
| 条件卡片复制 | 复制此条件和内部审批节点，先确认或修改规则，取消不插入；复制的节点独立可改 |
| 条件卡片删除 | 确认后删除所选条件及其内部节点；至少保留一条普通条件和默认条件 |
| 默认条件 | 静态兜底说明，固定最后，不提供条件设置、复制、改名及删除 |
| 橙色审批人卡片 | 打开该节点的审批人配置，支持组织负责人、公司审批职责、业务负责人及指定人员 |
| 路径上的“＋” | 在当前位置插入审批人、抄送或条件分支；默认路径同样可维护审批人 |
| 分叉旁“更多 → 条件顺序” | 集中调整普通条件匹配优先级，默认条件固定最后 |
| 节点“更多 → 移动” | 明确选择同一路径中的位置；移动整个条件组时保留所有内部节点 |

所有散落的上下移动箭头已移除。颜色、卡片标题、正文箭头及分叉布局按用户截图区分作用；本轮根据截图实现交互，不宣称已在线核实企微后台全部规则。当前原型仍保留发布时的条件重叠校验，并未因出现优先级就放宽原有校验。

## 验收及边界

本轮修改 `shared/approval-config-model.js`、`shared/approval-config.js`、`shared/approval-config.css`，扩展配置规则与 DOM 检查，并新增字段与分支交互 DOM 检查。页面入口仍为审批配置 → 编辑模板，无新菜单。

已执行：37 组配置规则、26 组原配置 DOM 回归、25 组字段和企微式流程交互 DOM 检查。覆盖字段选择和保存复开、必显保护、空值、类型差异、变更前后、历史版本、条件独立编辑、改名、复制和取消、嵌套副本独立、删除确认、默认条件、条件顺序、整组移动、试跑及只读。

上述 DOM 检查在本地 Node/jsdom 中加载页面源码，不是浏览器截图或实际导航验收。此前浏览器本地文件预览被工具安全策略拒绝；本轮未绕过，桌面和窄屏排版、实际列表往返及文件协议会话保存仍待工具政策允许的浏览器入口验收。原财务清单、语法和差异检查随本轮收尾执行。

本次保存仍为独立会话原型，新展示配置尚未接入日常待审批详情，不表示来源资料自动同步或业务审批已经采用新流程。正式必显集合、真实人员及阈值待确认；供应商致远分工保持。

唯一下一步：先补配置端浏览器视觉及实际往返验收；通过后按已授权方案第二批完善代表事项的逐级办理和来源提交预览，不重新规划第一批。

## 追加：异常、重复审批、意见与签名的页面归属建议

**执行更新：** 用户已确认执行，审批规则配置、发布校验、版本及模拟办理已完成，见[实施记录](审批规则配置与模拟办理实施-20260924.md)。下方为执行前建议；日常待办接入及浏览器待验仍按最新实施记录与进度执行。

用户随后提供两张设置截图，要求考虑放在哪个 Tab。以下为本次配置归属建议，尚未改页面或规则；不把截图中的勾选状态当作本系统已确认政策。

保留四个编辑步骤，将第四步“其他规则”改名“审批规则”，分为人员异常、重复审批、意见与签名、办理控制四个区域。第三步“审批流程”负责节点人员、多人方式和路径，不重复配置模板通用规则；配置首页“审批人员”仍负责公司职责及临时代办。

| 截图内容 | 设置位置 | 建议配置及边界 |
| --- | --- | --- |
| 审批人成员为空 | 审批规则／人员异常 | 暂停并交审批管理员处理，或转本公司指定人员；建议默认暂停，不沿用截图自动同意 |
| 审批人成员离职 | 审批规则／人员异常 | 管理员手动交接，或自动转本公司指定人员；已有有效代办优先使用，仍失效则转异常处理 |
| 同人重复审批 | 审批规则／重复审批 | 每个节点都审批、仅连续重复免重复审批、同单首次同意后免重复审批；建议默认每个节点都审批。只复用同一版本已明确同意的个人结果，不能跳过其他会签人；退回改动后重提重新判断 |
| 审批意见 | 审批规则／意见与签名 | 同意时意见必填可选；退回与拒绝必须填写原因，保留现有要求 |
| 审批人签名 | 审批规则／意见与签名 | 同意时要求签名可选；在办理抽屉采集并随审批记录查看，与旅游合同签署分开 |
| 办理人异常、办理意见 | 将来新增办理节点后，在审批规则显示独立设置 | 当前仅审批、条件与抄送节点，不提前摆无对应动作的设置；办理节点应有办理完成或无法办理结果，不能等同同意审批 |

选择自动转指定人员时才展开接替人；多公司模板逐公司维护，不使用一个跨公司接替人。人员仍须通过在职、所属公司及审批授权核对。提交前能发现的配置缺口先阻止提交，在途失效则暂停当前节点并由审批总览的异常处理入口承接，避免让申请人反复处理人员配置。

上述新增规则落地时须同步保存、版本、发布校验、试跑及办理端对应行为，不能只增加表单开关。既有浏览器待验及原方案第二批断点保持。
