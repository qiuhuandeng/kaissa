## 一、本次结论

说明已跟随页面统一使用“项目团”“报价与合同”“报价单”“登记客户确认”“客户委托编号”“收款阶段”。两个建团入口均保留，分别服务负责人统筹和计调日常建团；不因名称统一而将上层项目、具体项目团和订单合并。

本次补充或纠正了复制项目团、关联已有订单、收款阶段安排、共同采购交付、项目承担费用单独结算、外部审批结果、集中变更记录、工作台完成提醒及报表实际可查范围。付款退回、最终订单定价、结项后款票及财务日常入口仍按现状标明待检查，不能得出“所有分支已完整跑通”的结论。

## 二、名称与操作路径核对

| 原说明中的问题 | 当前页面及本次写法 | 业务意义 |
|---|---|---|
| “活动”“项目团”交替指同一个执行对象 | 统一称“项目团”；项目详情和项目团控均为“新增项目团” | 两个入口创建同一类记录，人员在原团上交接 |
| “客户约定”混指报价、成交、合同 | 页签“报价与合同”；记录“报价单”；按钮“登记客户确认” | 报价提出、客户确认、内部批准、合同签署分别说明 |
| “登记框架”“新增报价／新增报价”等不准确或重复名称 | “登记框架合同”“新增报价” | 读说明能找到实际按钮 |
| 收款“节点”、客户“参考号”未跟随改名 | “收款阶段”“客户委托编号” | 分订金、进度款、尾款；按客户原委托核对项目团 |
| 客户对账仍写旧选项“价款及服务确认” | 页面选项“结算金额与服务确认” | 区分金额和服务最终确认、整包部分交付进度确认 |
| 订单详情误写“申请订单改价” | “售后变更 → 订单改价 → 申请改价”；本团客户款项仍为“订单改价” | 同一改价流程按实际入口名称说明 |
| 替换后出现“收付与发票有出处的成本”等病句 | 恢复为“财务应付有真实采购和确认依据”等职责表述 | “收付与发票”仅用作实际页签名称，不替换所有财务交接文字 |

会议名称、会场、按场计价及合同条款中的“约定”保留实际业务含义，不机械替换。

## 四、流程分支与产品检查项

| 财务／业务要求 | 当前功能与缺口 | 本次说明处理 | 后续应如何验收 |
|---|---|---|---|
| 相似项目团快速建立，历史结果不误用 | 有复制项目团，清空新团日期、委托编号、名单、资源等；可复用安排和分工 | 补“复制”入口，并要求重核所复制日程日期、重办报价和确认 | 复制一团后核新日期、日程、名单、资源、完成资料及报价引用；本轮未执行此操作验收 |
| 已有成交不能重复新增订单 | 报价可关联同客户、公司、币种、金额及覆盖范围的已有订单 | 补关联已有订单条件和下一步 | 同范围沿用；金额或覆盖不符能定位原单，不增加第二份成交 |
| 按实际数量结算应形成最终客户金额 | 客户对账保存认可数量、单价和认可金额，仍保留原订单总额；结项检查指向通用订单改价 | 明确不是对账确认即最终定价；登记专项待检查 | 从金额未定订单走到最终金额、收款计划、税费依据及可认领／开票，全部与客户确认一致 |
| 付款被退回后能修正原申请 | 财务可重开已退回记录；业务侧无统一原申请金额／依据修订入口 | 保留现状及限制，未写为已补齐 | 改金额／依据后重提，审批版本、可申请余额与原记录一致 |
| 允许带未清款票结项时，还能继续办 | 结项保存遗留责任，但项目结束会阻止新认领和开票申请 | 明确已有申请与新发起不同 | 批准例外结项后，责任人能办新认领／开票并核原订单，不重复成交 |
| 财务从日常页面接手业务 | 会奖财务视图依赖项目来源进入；会奖演示流水单独维护，普通到账流水不是同一来源 | 增加来源核对和菜单承接检查，不以菜单同名证明联通 | 业务提交后，财务按日常入口找到原申请、核同一来源；查清流水和付款承接路径 |
| 客户争议能按真实处理结果结束 | 整笔争议等额减价获批有处理；部分让价、补服务后重新认可未据此验证 | 分别说明已有分支和待检查分支 | 原争议历史保留，认可、原单变化和退款各自有依据 |
| 管理结果完整、责任清楚 | 参与记录、结果导出已有；正式任职、汇率规则和完整输出仍属原第4步 | 保持原实施断点，不以说明补全代替功能完成 | 按原第4步的五团／百场故事核完整结果及未结事项 |

前两行属于说明漏写而已有相应入口；后续行包含流程承接或验收边界。真实银行、电子签约、开票平台及财务核算接口未连接，不据此要求本轮建设后台或生产集成。
