## 一 整体产品判断

航服是集团内部经营客票业务的公司，既向航司和票代采购，也向内部产品公司、同行、企业和散客供票。原型要围绕三个连续工作场景组织：**票务接单与出票、机位采购与分配、财务收付与核对**。附件 A 至 L 是能力清单，不直接做成十二个平级菜单。

采购机位可以先于旅游团期存在；客票订单可以没有旅游团号；同一个旅游团可以有多条航段、多批出票和多次变更。内部团期只约束确实给这个团供票的订单，不强制所有业务先建旅游团。

航服日常业务集中在独立一级菜单“航服”（2026-10-18用户明确，位于销售上方），财务日常集中在财务下的“航服财务”。销售、计调从原业务页面提交需求或核对本单结果；基础档案、审批和只读报表继续使用现有所属模块。沿用共享导航外壳，航服一级菜单按本轮用户指令调整。

### 1.1 术语及边界

| 名称 | 本方案中的业务含义 |
|---|---|
| BSP 客票结算 | 航司与代理人通过国际航空运输协会的结算安排核对和清算客票款；不是一种库存 |
| IATA | 国际航空运输协会；结算组织、实际承运航司和收款账户分别登记 |
| 航司 B2B 平台 | 航空公司面向代理人的业务平台；同一航司可以有不同账户和结算约定 |
| PNR | 订座记录编号，用于定位订座；不能代替电子客票票号，也不能单独证明已出票 |
| ADM | 航司或相关结算方发出的代理人补收通知；先核对原因与责任，不能一律当作退票罚金 |
| ACM | 与补收相对应的贷项通知，在适用账单中减少待结金额；保留原通知依据 |
| OCR | 从证件、截图或账单图片中识别文字；识别结果须能人工核对与纠错 |
| 准单 | 本次拟采用页面名称“航服结算单”，用于汇总本团、本票务订单或包机项目的业务结算资料；保留“准单”搜索别名 |
| 应收与应付 | 分别是已确认客户应付给我方、我方应付给供应商的金额；不等于实际收付 |
| 预收与预付 | 分别是客户先付给我方、我方先付给供应商但尚待后续使用或冲抵的款项 |
| 核销 | 把已确认的收付款对应到具体应收或应付，说明哪笔欠款已经结清 |
| NC | 集团财务核算系统；业务确认、实际资金和凭证推送各有自己的结果 |

原型交付真实可操作的表单、列表、分配、校验、导入预览、下载和示例办理结果。白屏查询、真实出票、真实支付、短信发送、银行、税控、NC 和跨端自动同步另属正式接入。没有接口也要完成成功、失败、结果待查和人工承接页面，不能只放“待接入”。演示文件和结果明确标为样例，不能把选中文件后的固定数据冒充实际解析成功。

### 1.2 附件中必须先处理的冲突

| 附件或现有设计 | 产品判断与原型处理 | 确认状态 |
|---|---|---|
| BSP 流程先出票再收款，文字又要求出票前收款 | 现结采用报价确认、收款确认、出票顺序；已出票日报导入是事后补登核对，不能倒造出票前收款记录 | 采用附件明确的现结要求；特批先出票条件待确认 |
| 库存前置绑定团号，同时要求库存与团号解耦 | 先建机位，再可选指定负责部门／计调；实际分配到团时才要求团号。部门预分配不自动生成旅游团 | 设计处理 |
| 团号双向强绑定，团期一改就自动同步 | 绑定供票关系与具体航段，不自动为所有旅游团建票务订单。已确认票价和已出票名单变动转差异处理，不静默覆盖 | 自动建立条件、拆团并团规则待确认 |
| 包机“不出票” | 解释为采购合同不按普通散票出票结算；旅客仍需要可核对的承运凭据。支持票号、包机乘机凭据两类，不臆定所有包机无票号 | 航司实际凭据待确认 |
| BSP、单团“无风险”，系列位“中低风险” | 风险按付款、取消、出票、还位条款判断；不把业务类型直接当风险结论 | 具体协议确认 |
| IATA 固定“2—3天账期” | 登记公司适用年度账期表，分开业务期间、出账日、汇款／扣款日；不硬编码天数 | 实际日历待提供 |
| 一次提交财务直审，同时要求票务主管审核 | 一次提交启动审批；主管和财务依配置顺序办理，申请人不重复提交。是否常规单免主管审需确认 | 待确认，不默认免审 |
| 航服收入强推产品成本 | 同一内部供票结算金额作为双方核对依据；先分同法人部门协作与跨法人交易，集团对客成交不得重复统计 | 法人、内部价税与确认期间待确认 |
| 退票退款合一 | 一个发起入口，供应商退票、供应商返款、客户退款分别有金额和状态；部分成功可继续处理另一侧 | 遵循现有业财基线 |
| 按供应商类型自动决定预付或付款 | 按本次协议、平台账户、结算方式和原款余额推荐。航司也可能随结，票代也可能预付，不用供应商类型一刀切 | 具体规则待确认 |
| 银企直连即自动认款、自动审核 | 唯一匹配且符合已批准规则才可演示自动确认；同额多单、第三方付款、跨公司、短款进入待核对 | 自动确认规则待确认 |
| 预收即待开票、打包即全额计税、必须进项专票 | 预收记录开票需求；按交易、开票资格和公司财务政策确认开票时点及计税方式。机票凭证与税务发票分开 | 税务政策待财务确认 |
| 已结算后财务解锁 | 支持解锁申请、审批、授权修改范围及重新核对；原结算结果保留。已关账或已推凭证默认走补充调整，不直接覆写历史 | 解锁及跨期权限待确认 |

IATA 官方说明将报账期间、出账日和汇款日分开，并按市场发布年度日历。因此本方案保留日历配置，不把附件中的天数扩用为通用规则。[IATA 代理人手册第十三章](https://www.iata.org/en/fmc-documents/0067436c-e840-469b-b815-18153ac972d2/)

## 二 角色与工作交接

| 使用角色 | 进入页面首先处理什么 | 可以完成的动作 | 交给下一角色的结果 |
|---|---|---|---|
| 航服采购／资源人员 | 航司分位、待录入航期、即将到期机位 | 录入采购、批量导入、前置分配、退位申请、包机安排 | 可使用的机位及明确采购条件 |
| 票务经办 | 新需求、资料缺项、待出票订单、未匹配日报 | 接单报价、收款申请、接收名单、登记出票、退改申请、核单提交 | 有完整航段、乘客、票号、金额和依据的订单 |
| 票务主管 | 价格／损耗／例外申请 | 审核或退回本职责事项 | 明确批准范围，不代替财务付款 |
| 产品／计调 | 本团已分配机位、票价和名单差异 | 提交购票需求、认领确认名单、确认内部报价、申请团期变更 | 可出票名单及本团认可的供票金额 |
| 销售／门店／呼叫中心 | 客户需求、收款条件、缺少的出行人资料 | 原订单录资料、确认客户报价、发起收退款／开票申请 | 客户及乘客资料；不维护航司成本或直接出票 |
| 航服收付会计 | 待认款、待付款复核、平台余额差异 | 认款、核对原款、核验申请、冲抵核销 | 可执行款项及可解释的余额 |
| 出纳 | 已批准收退款、付款及结果待查 | 登记实际资金、回单、失败／退回 | 实际金额、日期、账户及银行凭据 |
| 结算／票据／核算财务 | 账单差异、待审准单、款票与内部双方差异 | 对账、财务结算确认、开收票、凭证校验及推送演示 | 可核对的财务确认和凭证结果 |
| 管理者 | 团组毛利、未提结算、逾期和包机余位 | 查询、筛选、导出 | 经营判断，不在报表中办理业务 |

业务数据范围按所属公司、部门、负责团期和授权岗位控制。计调只看本团供票结果；销售不能看到上游采购价；航服财务看本公司资金与结算。权限必须同时作用于页面、按钮和导出。原型采用预置授权场景验证，不在业务表格旁新增“切换身份”控件。

## 四 核心业务关系

| 业务记录 | 由谁建立 | 与其他记录的关系 | 不能混淆的内容 |
|---|---|---|---|
| 采购协议和航期机位 | 航服采购 | 一份协议含多个日期／航段／舱位；可分给多个部门和旅游团 | 航期机位不是旅游团；往返可组合展示但分别核对各航段数量 |
| 机位分配 | 航服资源人员 | 总部可分部门，部门再分计调／团期；子级分配消耗父级额度 | 部门分配和团期分配不能重复扣同一批总机位 |
| 机票订单 | 票务经办接单 | 一张订单对应一个结算客户、一种结算币种，包含多名乘客和多条行程 | 客户是购买或付款方，乘客是出行人；多个付款方要逐笔说明 |
| 行程与出票记录 | 票务经办 | 乘客可参加部分航段；同张票可覆盖多个航段；退改保留原票与新票 | 一个人不等于一张票；一个订座编号不等于一个订单 |
| 旅游团期供票关系 | 计调与票务 | 一个团期可有多笔供票订单；一笔供票金额明确分到相应团期／航段 | 批量按多个团生成订单，不把无关系的客户合成一单 |
| 退改申请 | 销售／计调／票务 | 关联原订单、乘客、航段和票号；可有多个已生效版本 | 同一票的在途重复退票须拦截；允许次数多不等于可重复执行 |
| 航服结算单 | 票务提交、财务确认 | 按团期、本票务订单或包机项目形成业务结算资料 | 与 IATA 期间账单、客户月结账单分别存在，不强行一团对应一张供应商账单 |
| 收付款及平台账户 | 财务 | 一笔款可按明确金额分到多单；平台扣款对应订单或费用 | 充值不等于成本；退款获准不等于到账；分配不额外增加现金 |

### 4.1 数量与金额的设计约束

1. 按日期、航段、舱位分别核对机位，不以往返航段行数代替人数。往返可售套数受两段各自余量限制。
2. 当前有效采购量等于已确认采购及生效调整减已确认退回供应商数量。未确认退位仍占用原机位。
3. 当前有效量分为公共可用、分配后尚未订购、有效订单占用等互不重叠部分。已出票是订单占用的其中一部分，不能再加一次。多级分配只在最终使用处计一次。
4. 释放回本公司可用池与退回供应商是两种动作；已出票机位必须先按退改结果判断能否释放。
5. 原订单销售金额、客户退款、采购成本、供应商退回、补收费用和服务费分别保存；只汇总已生效调整。预估成本不冒称最终结算成本。
6. 同币种销售净额减同范围采购净成本形成业务毛利；缺成本显示“待核”，不按零成本出高毛利。不含税毛利和财务确认收入须有已批准价税规则。
7. 票面价、税费、上游政策扣点、采购应付、服务费、对客售价、内部供票价分开。每张加50元只是附件示例，不作为统一政策；扣点基数和是否含税待确认。
8. 内部供票双方核对同一结算金额，但分别承担航服经营和产品成本责任。已包含这笔机票的产品成本不再重复录入；不禁止其他来源的大交通费用。

主入口从原订单发起；集中列表供票务和财务继续办理已经建立的申请。类型包含退票、改签、升舱、联运补差、减员／加员和补收调整。主状态为草稿、审批中、处理中、已完成、已驳回、已取消；供应商与客户两侧的处理进度在详情分开显示。

加员的原票仅作为采购依据。申请、审批与办理结果分别展示原采购依据及新增乘客、证件、航段和新增票号，客票处理使用“新增出票”；新增乘客结果独立记录，原名单与原票保留。原订单详情的名单出票页签提供加员出票记录及退改单查看入口；结果待查仍须先核对原请求，成功结果不可重复办理。

申请抽屉先选乘客、航段和原票，再写变更原因、变更后行程、上游退改规则、预计采购增减、客户应退／补收、费用承担和附件。办理范围使用固定高度的客票表，按乘客／证件、当前航班航段、票号／舱位和可办理状态核对；支持中文或英文姓名、证件及当前票号即时搜索、当前航段筛选和仅看已选。表头全选只选择当前筛选内可办理客票，筛选外已选记录保留并提示数量；重置筛选不清空选择。加员单选一项原票采购依据；资料更正按一位乘客联选全部有效航段，切换乘客同步更正前资料。未出票、已退票、结果待查与已有在途申请的客票显示原因并禁选，整单费用不展开客票表。用户主动清空范围后，保存和重开草稿保留空选择，不自动补选。补收通知回原订单，不另建一张与旅客无关的“费用订单”。同一票存在在途退票时不能重复发起同范围申请。

审批通过只进入办理；实际退票、供应商退款、客户退款各自记录结果。部分退票或某一侧失败保留已成功记录，允许补处理剩余部分。已结算订单先按授权走调整或解锁申请；解锁批准只允许修改批准范围，重新核对后再锁定。财务退款结果未知时必须核对原付款结果，不能点重试就产生第二笔退款。

### 航页08 航服资金

这是航服收付的统一工作区，现有收款申请、到账认款、客户预收、客户退款、付款办理、平台预付六个页签；各页签保留有效筛选，不混加不同公司和币种。原型统一超级管理员连续操作，岗位只说明责任，动作仍按单据状态及前置条件展示。

| 页签 | 列表首先看什么 | 同页办理和结果 |
|---|---|---|
| 收款申请 | 申请单、客户、关联订单、申请金额、已认款／待收、方式和状态 | 统一申请／详情，链接、二维码及公账资料；“待收订单”抽屉按节点、到期日及月结账期找未申请订单，再合并同公司客户币种订单 |
| 到账认款 | 原流水、付款方／结算客户、我方账户、到账金额、可处理余额和状态 | 未确认客户也能先登记；核对客户后分配订单、保留预收或退回原付款方；申请与实际到账分别记录 |
| 客户预收 | 客户／收款公司、币种、可用预收、认领中与退款处理中 | 详情核对逐笔到账、订单核销及退款；多原款可用于多个订单，预收核销不重复增加到账 |
| 客户退款 | 退款申请、原订单／原款、客户、申请金额和状态 | 查看原款与办理记录，撤回、重提、执行或查结果按单据状态；未知结果先查原请求 |
| 付款办理 | 申请单、供应商、协议节点、申请金额、日期和状态 | 现有通用来源申请及结果保留；BSP、机位、票代、包机、平台五类办理范围继续按最新资金缺口清单补齐 |
| 平台预付 | 平台账户、航司、账面／可用余额、核对差额和状态 | 账户内查看充值、订单扣款、原扣款退回余额及退回银行；持续充值等遗漏按资金清单接续 |

客户分次收款与供应商一押二押分别办理。待收订单按节点显示应收、已收、认领中、未收和申请中；申请保留本次节点、到期日及客户账期，重复申请只处理剩余，公账到账认款及演示支付结果均沿用原节点。节点收齐后保留查看，不再重复申请；已有有效收款申请先查看原申请，关闭只释放未收部分，已有收款保留。

月结清单使用已明确的客户账期和到期日，同客户多单可合并申请，再按各单实际金额分配回款。缺少账期／日期时显示待确认，不根据出发日或出票日自行推算。未留节点的历史收款／退款显示待核归属，计划合计与当前订单不符时显示计划待核；本页不自行确认旧款的先后抵扣或正式月结制度。

收款链接／二维码为演示入口，不向客户自动发送或发生真实扣款。申请不计实际收款，待复核认款占用余额但不当作已收；实际到账及分配分别留记录。预收余额反查原款，后续余款用于其他订单不增加旧申请的已认款额。

信用客户仍引用现结／预付／月结条款、有效期、额度、占用、逾期和例外记录，正式政策待确认。上游平台预付与下游客户预收分别核对。当前代码与DOM交互结果见2026-10-18资金实施记录，实际浏览器视觉仍待补验，不将原历史验收扩大为本轮已验。

### 航页09 航服对账

四个单层页签分别处理 BSP账单、平台订单、银行流水、内部供票。前三者按公司、账户／供应商、币种及期间核对，内部按双方公司、团期和供票订单核对。文件导入先预览再确认，解析失败可保留文件并手工补录核对。

| 场景 | 对照依据 | 差异与处理 |
|---|---|---|
| BSP | 日报出票退改记录与IATA账单 | 已匹配、单边缺失、金额差、重复、退款未回、补收／贷项、原单未知；差异转原单调整并回看处理结果 |
| 航司平台 | 航司、平台账户、币种、航司订单号及交易明细 | 平台已出而ERP未登记、已出未提结算、金额不符、退款未回、重复导入；充值只对余额，不作为订单成本 |
| 银行 | 银行流水与系统收款、退款、付款 | 同额多候选、手续费、部分到账、退款退回、未达；匹配建议与确认结果分开 |
| 内部供票 | 航服确认供票金额与接收团期对应费用 | 缺一方、金额／币种／期间差、重复成本；不允许以强制改对方金额掩盖争议 |

航司订单号只在对应航司及平台账户内定位，不作为跨航司全局唯一依据。差额方向统一为“对方账单减系统金额”，同时保留双方原数。未解决差异不能靠“确认差异”直接归零；原因、调整单或允许保留的差异批准必须明确。

IATA付款清单按适用日历预填；经办核对本期应缴与已付后一次提交审批。是否按计划自动提交留配置及政策待确认，不默认开启无人审批。争议账单的应缴义务须按正式规则判断，不能从付款总额随意删掉争议行。

### 航页10 包机项目

2026-10-17航实06已实施，规则、页面及正常异常证据见[包机实施验收](航服包机项目完整流程实施验收-20261017.md)。列表与详情已新增，原采购、订单按依据显式引用，未自动回写；票据核算及最终岗位联验仍在航实07。

列表一行一个包机项目，展示项目／航线、执行日期范围、航次数、已确认意向／有效座位、已售／余位、主状态和负责人。项目状态为筹备中、执行中、待收尾、已结束、已取消。

详情页签为项目资料、意向与分销、航期机位、项目结算。筹备登记内部部门和外部合作方的意向数量、确认数量、价格与有效期；达到某个数字只提示，不自动签约或付款。筹备时关联直签协议及分航次确认资料，作为启动审批依据；批准后航次可分销，安全线不写死130人或140人。

项目结算归集航司固定包机款、已确认其他成本、分销销售及生效退改；无成交的座位展示空置数量，预计损失与已确认损失分开。整机成本已计入项目时，不再加一次“空位数×座位成本”。项目已结束仍可查未收、未付、待票及后续调整，不以全款收齐作为唯一业务结束条件。

### 航页11 发票与凭证

沿用发票管理的独立申请／开票和收票工作区。订单可发起单笔或合并开票申请；核对购买方、销售公司、币种、开票项目、已开与在途申请、可申请金额。退票引起的红冲与纯抬头更正分开，重复票号或超开不能直接保存。

采购侧关联航司、票代或包机协议的成本凭证，分别登记电子客票凭证及税务发票类别；进项专票是否为付款前提不得写成全部航服业务通用规则。预收提示按开票约定核对，不直接等于已发生开票义务。

NC沿用原推送页：待校验、待推送、推送中、结果待查、已成功、失败；展示公司、会计期间（财务记账所属月份）、业务来源、借贷金额和返回凭证号。借贷不平、期间不开放、内部对应不明等有明确阻断；重复点击不生成第二个演示凭证。凭证科目及收入净额／总额不在本轮替财务决定。

### 航页12 航服设置及经营查询

设置只承载低频规则：航司名单模板及版本、账期日历、出票来源连接、导入字段对应与自动确认规则。客户和供应商的准入、账户审核、合作政策在原档案维护，设置只引用。账号及证书只做脱敏演示，不要求填真实密钥。

数据中心承接七类结果：BSP日报与对账、团组毛利、客户／供应商／团号往来、未提结算、逾期、开收票、机位使用／包机空置。每张表明确日期依据、公司、币种、统计范围；订单、出票、飞行完成、结算和财务确认日期分开。报表不增加认款／付款／出票动作，不设置金额或单据点击下钻；保留直接筛选、完整明细和全查询导出。

机位使用区分订单占用率、出票率、实际使用率；分母分别说明有效采购量或实际承运座位。尚未飞行不能把未出票叫最终空置；缺完成依据只展示待核。

## 七 分步实施

每步同时做必要来源核对、页面、计算和浏览器验收，再回填清单。步骤不等于必须一次对话做完，也不把真实接口当原型完成门槛。

| 航待05 | BSP年度日历、日报与账单脱敏样本、补收及退款表示法 | 导入、对账 | 标准演示模板及可纠错预览，不宣称真实格式兼容 |
| 航待06 | 八家航司名单模板、版本、联运拆分规则与必填字段 | 名单出票 | 配置与示例导出流程完成，生产兼容验收另列 |
| 航待07 | 主管是否必审、额度／损耗例外、财务直审范围 | 审批、结算 | 一次提交的多节点样例；不默认取消主管 |
| 航待08 | 提前结算条件、暂估、锁定／解锁、关账后调整 | 结算、退改 | 可核对未齐事项及独立调整，不直接改已结历史 |
| 航待09 | 收入总额／净额、含税／不含税、包价开票、预收开票时点、进项要求 | 发票、毛利、NC | 业务金额与财务确认分开，不固化税率及分录 |
| 航待10 | 包机承运凭据、意向安全线、固定及变动成本、风险批准 | 包机 | 凭据类型可选，意向提示与批准动作分离 |
| 航待11 | 白屏与平台能力、真实出票授权、接口费用及责任人 | 设置、导入、出票 | 演示连接与失败恢复；日报和手工可继续操作 |
| 航待12 | 银行自动确认规则、支付合并限制、实际账户及NC科目对应 | 资金、核算 | 建议匹配与财务确认分开，原型不产生真实交易 |

这些事项登记为待确认，不需要在绘制第一步原型之前一次性全部答完；应在对应步骤用样例核对，涉及政策的最终结论由相应负责人确认。

### 2026-10-18 包机供票与机票详情最终边界

此前包机建议已按用户执行指令实施：内部团队用团期与来源销售名单，外部分销可导入客户名单／手录／引用客户已有团队，余位散卖只引用公共余位。订购席位与已交名单分开；项目分配份额不重复扣位，主航段只读，额外航段和乘客对应沿已有边界。订单报价按席或整单，客户收款计划属于订单；航司协议采购款在包机项目，成本分摊待财务确认。演示协议允许部分名单确认并显示截止日，不代表所有项目默认政策。XLSX／CSV导入只追加新乘客，重复跳过、身份冲突不覆盖；实际本地选择文件待人工验收。

机票订单详情最终按订单资料、名单出票、收付款、退改记录、结算日志、操作日志六Tab组织。订单资料根据三类建单展示，名单出票使用只读身份表和逐人逐段出票结果，收付款分别查看申请、到账认款、退款和采购款；订单不出现票据办理卡。变更后的当前人员和票号沿用原退改单，原记录保留。

列表是办理主入口：草稿编辑、待确认确认、待出票及出票中出票、已出票退改、已取消仅查看。名单处理、补充包机名单、查询结果、航司名单和申请收款放更多；当前待办不改变主动作名称。申请收款按当前订单带入，支持同客户同公司同币种合并、按次金额、公司收款账户、支付链接／二维码／公账转账。申请不增加实收，实际认款仍在财务；详情只查看相关单据。原型超级管理员不绕过单据状态及已出票保护。
