## 二、关键业务结果

1. 预订页按登录归属锁定渠道、门店和销售顾问，未授权用户不能通过切换控件绕过渠道配额。普通团期按人、邮轮按间、专列按铺、自由行房型按间形成占用数量；草稿和待确认订单保存为“未占位、数量0”。
2. 渠道配额调整集中在一个独立抽屉。每个渠道同时展示调整前、已占用、调整后、调整后可用和原因；调整后不得低于已占用，配额合计不得超过团期可分配总量。停售状态和历史订单原渠道保持不变。
3. P04-A逐笔释放逻辑保持：只按原订单和实际占用单位归还原渠道，不减少采购量和已付款，不重复增加名额。
4. 售后资源结果与客户款项结果分开。退款状态不再代替资源释放状态；不占舱儿童、同舱第三／第四人取消均显示释放0间。到期规则没有配置时显示“待配置”，不自行生成默认时长。
5. 团期订单列表和详情可反查销售归属及原占用依据；团期详情进入独立订单页时自动带入当前团期编号。

## 三、浏览器验收

使用本地HTTP服务和无头Chrome实际点击，未保存图片。5个页面运行时错误和控制台错误均为0。

| 场景 | 结果 |
|---|---|
| 代理配额10、占用6、可用4，释放2 | 代理变为占用4、可用6；直营保持占用5、可用0；代理仍为停售 |
| 配额正常调整 | 代理配额10调整为8，已占6、调整后可用2，保存后表格显示8和6/2 |
| 配额取消 | 抽屉内改为9后取消，主表仍为8 |
| 配额低于已占用 | 代理配额填5时就地提示“不能低于已占用6人”，未保存 |
| 配额突破总量 | 调整后合计31、团期总量30时提示超额，未保存 |
| 旧同步操作 | 页面不存在`data-sync-schedule-channel`按钮，旧提示事件已删除 |
| 待确认订单 | 渠道、门店、顾问保持登录归属；订单生成成功，原占用为0人、状态未占位 |
| 售后取消 | 详情同时存在资源处理结果、款项处理结果，并显示代理原占用编号和预计归还余额 |
| 邮轮儿童不占位 | 实际释放0间，原渠道余额不变 |
| 团期订单入口 | 链接带入`EU20240715001`，订单页只显示命中该团期的记录 |
| 团期订单归属 | 列表各行显示顾问、占用记录及数量单位；订单详情显示12项归属／占用字段 |
