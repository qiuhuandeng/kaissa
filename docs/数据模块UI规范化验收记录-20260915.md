# 数据模块 UI 规范化验收记录

日期：2026-09-15。状态：已完成。

## 一、页面在业务链路中的位置

数据模块位于订单、团期履约、收付款、结算和核算之后，供集团财务及经营分析人员查看经营结果、核对明细并导出底稿。上游来自订单确认、实际完成、收付分配、收入成本确认和预算等既有原型资料；下游是财务复核、经营分析和报表输出，不在本模块办理认款、付款、开票、结算或 NC 推送。

本次最高频任务是：选择当前报表内容，设置查询条件，查看结果，调整显示字段或排序并导出。页面操作不改变订单、团期、资金单据和会计确认记录。

## 二、本次范围

统一数据中心 16 个日常入口和 1 个六场景验收页的 UI 与布局。四个已归档历史方案仍保留归档提示，不作为日常报表界面恢复。

本次调整界面组织、默认数据呈现和非必要文案。保留原页面的筛选字段、表格字段、字段顺序、显示字段、排序、分页、查询计算、Tab 状态和导出逻辑；为原本无记录的“完成后调整、确认明细、订阅设置”补充对应模块模拟记录。

| 不强调模拟性质 | 页面、筛选项、状态和表格反复出现“演示、算例、非正式”等字样 | 仅保留业务对象、筛选条件、结果和可操作状态；模拟数据属性不在界面重复说明 | 77个视图可见文字逐页扫描，无上述文案 |
| 空辅助区不占页面 | 无缺口或无依据时仍显示空表和“当前条件无记录” | 默认无记录的辅助核对区不显示；有记录后自动恢复 | 77个视图默认状态无可见空表提示 |

### 用户复查后的纠正

用户以月度损益和收付明细实际页面复查时发现：浏览器会恢复旧版保存的“待补资料”条件，结果说明条仍显示，业务毛利的结算调整还会出现空表。纠正后不再在数据报表页面提供“资料范围”测试筛选；旧版页签状态统一失效，页面固定从本模块默认数据开始。结果说明条和“已查询／条件已修改”提示不再显示；结算调整默认加载对应记录，无数据的辅助依据区不显示。

## 四、实现位置

- `shared/data-report-ui.css`：数据报表统一页签、筛选卡片、无标题条件、结果卡片和响应式布局。
- `shared/data-report-ui.js`：给既有表单增加统一 UI 类、移动操作按钮、保持动态表单重绘后的导出入口，并隐藏页面口径说明。
- 财务查询模型：页面默认加载各主题已有模拟数据；“待补资料”只保留在模型测试中验证缺资料不当作零，不再作为页面筛选项。
- `shared/report-pages.js`、`shared/finance-accounting-view.js`、`shared/report-governance-model.js`：分别补充完成后调整、确认明细和订阅设置的页面数据。
- `shared/report-section-tabs.js`：取消内容区页面标题，页签切换后同步装配当前报表 UI。
- `shared/channel-reports.js`：渠道毛利视图中的导出按钮移动到筛选区后，继续交给原毛利导出逻辑处理。
- 16 个日常数据页及 `merchant/data/report-scenarios.html`：接入共享 UI 样式和脚本。
- `tests/report-tab-architecture-browser.cjs`：增加标题、筛选标签、更多筛选、导出顺序、口径说明和结果卡片检查。

## 六、边界与下一步

本次没有改变金额、日期、收入、成本、预算和集团抵销规则，没有改表格字段及字段顺序，也没有接入正式来源、权限、审批或财务办理流程。页面默认显示对应模块数据，不在界面强调数据性质；缺资料不当作零的规则仍由模型测试保留。导出文件仍保留原查询条件及核对依据。

下一步由用户按实际财务使用路径检查筛选密度、按钮位置和报表内容阅读顺序；后续如需调整具体字段或计算规则，另按业务和财务口径单独处理。
