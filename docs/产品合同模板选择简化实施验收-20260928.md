# 产品合同模板选择简化实施验收

日期：2026-09-28。

## 一、用户确认的边界

用户明确：产品只需“沿用系统设置”或“指定合同模板”，后者用一个下拉框选一份适用模板。合同需要的产品资料优先复用现有字段；缺失时在相应产品业务区域补充，不能在模板选择区重复制作合同长表单。

本次是C01—C04产品部分的反馈修订，优先于其历史实施报告中“每个方案维护允许范围、默认推荐及约定版本”等旧描述。产品负责人维护可复用服务资料，计调提供本团实际安排，销售在合同准备完成客户和签署确认，财务仍承接原收退款流程。

## 二、页面变化

| 页面 | 模板选择位置 | 产品资料处理 |
|---|---|---|
| 参团／自由行编辑 product-self-edit.html | 基础信息；整产品一处，不在经典／品质等方案重复设置 | 原行程、费用、退改、预订须知及购物自费保留；费用区增加可选保险服务说明。经典／品质方案原费用分别维护 |
| 邮轮编辑 product-cruise-edit.html | 基础信息 | 航程与登离船补岸上服务标准；费用区分别保留普通意外险与邮轮专项保险服务说明。具体航次、舱房及客户投保不放此处 |
| 专列编辑 product-train-edit.html | 基础信息 | 原车厢铺位、交通、行程和退改保留；保险服务说明放费用区 |
| 研学编辑 product-study-edit.html | 基础信息；详情模式只读 | 课程行程设计补总课时／每课时分钟数；费用规则补研学费用项目／旅行服务费用项目及可选保险说明。原师资、安全、餐住、课程行程复用 |
| 外采包装 product-outsource-package.html | 基础包装；不随包装方案切换重复指定 | 原供应商来源、费用及退改仍在行程与规则；可选保险说明放费用区域；不重复维护组织接待和成团客户意见 |
| 产品管理 products.html → 单项服务抽屉 | 服务表单末尾 | 规格、条件、费用包含／不含及签证材料时限放独立服务资料区；旅游范围放服务基础资料。复用原服务类型，不重复一套代办服务选择 |

共享脚本 product-contract-settings.js 统一实现以上模板选用。原“允许选用的合同、多份推荐关系、本方案约定版本、组织方式、实际接待方、成团说明、专项约定、核对合同所需资料”长表单移除。未新增HTML或菜单。

保险说明用于产品确实含保险或提供代购时记录保险公司、产品／保障计划及费用包含情况，可留空；不预填游客同意或投保结果。通用条款仍由模板管理，具体成团安排来自团期，保险购买及本单例外在合同准备确认。已有行程、预订须知或服务说明可表达的内容不再另建重复合同字段。

## 三、交互规则及原型范围

1. 默认沿用系统设置，产品保存的是选用方式，不复制一份模板全文，也不硬绑定当前第一份模板。
2. 指定模式只显示一个适用模板下拉。选项按业务、旅游范围、已启用文本及原型可用条件筛选；一日游仅在明确一天行程时出现。省级文本不根据目的地自动指定，正式签约还须核对实际签约公司、门店及地区条件。
3. 指定模式未选择不能提交；变更旅游范围使已选模板失配时清空并提示；回沿用时取消原指定。产品阶段不强迫补齐未来订单的游客、金额、签署人或客户意见。
4. 必要产品资料不足时，定位对应基础／课程／航程区域；有缺项仍可沿用原保存草稿动作。保险说明不是所有产品一律必填。
5. 单项服务按类型分别保留本页填写；保存后重开本服务，模板模式、选择及服务资料保留。产品页仍为当前页原型，未新增多页面数据库或自动回写。
6. 本次不建设新的规则引擎或跨页面匹配存储。系统设置的规则维护继续沿用既有页面；正式开发在订单确定签约公司后解析规则，无匹配或冲突不能任意取第一份模板；已送审及已签版本不被新规则覆盖。
