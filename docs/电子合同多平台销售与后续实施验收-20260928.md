# 电子合同多平台销售与后续实施验收

日期：2026-09-28。对应[多平台方案](电子合同多平台协同与定制模板完善方案-20260928.md)第2、3步。用户明确要求“第一步执行完直接进入下一步，直到执行完后汇总”，本轮连续完成销售准备、审批、签署及后续原型，不再停在单步确认。第1步成果见[集团配置验收](电子合同多平台集团配置第一步实施验收-20260928.md)。

本次交付是可操作HTML原型。集团配置在当前页面演示保存；销售只沿用既有“当前订单合同组”的会话交接，不建立全系统跨页持久化。浏览器检查采用样例受理、签署和报送结果，不代表真实账号或接口已接通。

## 一、角色与办理链路

集团技术管理员维护12301与法大大的连接和各公司授权；集团合同管理员确定模板正文、资料、签署文件、平台和版本；公司管理员确认付款条件，审批人核对本次文书。产品人员仍只选“沿用公司规则／指定模板”。销售从订单准备合同，补必要签署人与本次约定，预览送审后按模板办理；已签文件、监管报送和合同变更继续在原合同详情处理。

本轮不新增一级菜单，不把签约配置放回团期或门店，不让销售临时选平台绕过批准内容，不生成财务退款、应收应付或NC单据。

## 三、第3步：结果、文件、监管和后续

| 页面／流程 | 完成内容 | 验收结果 |
|---|---|---|
| 合同列表／详情 | 增加平台筛选和文书中的平台说明；主状态仍决定行操作；签署、文件与监管分区 | 桌面、1024宽度可操作，表格内部横向滚动，右侧操作列保持160px |
| 签署进度 | 按原平台和原申请核对逐方结果，展示文件和签署安排；执行客户先签／我方先签顺序 | 拒签、过期、身份失败、部分签署和缺我方章不能变成全完成；重复及晚到结果不清除已有签名 |
| 结果归属 | 公司、平台、合同及本次申请共同识别；超时后凭原申请核对实际任务号 | 两平台同号不串合同；错公司、错合同、旧申请拒绝覆盖；未知结果不新建或合并合同 |
| 文件取得 | 区分已签文件待取得、文件已取得但证明待取得、全部取得；支持原版本查看与HTML样例下载 | 临时失败不回退签署，也不删除已取得文件；保留原平台、公司、任务及版本 |
| 监管处理 | 独立展示适用要求、确认依据、接收渠道、获准路径及结果；需要报送、不适用、待确认分开 | 法大大签完不自动生成12301监管号；待确认不开放上传；缺文件／证明阻断；未知只查原申请；明确失败可修正重报 |
| 变更与新版本 | 沿用原平台、签署安排、监管要求和已签约定；新版本重新审批签署，不复用签名与任务号 | 邮轮变更可建立新稿并送审，未完成不替代旧版；补充协议及新版本金额按既有确认依据，不自动改订单金额 |
| 撤销／解除 | 原审批和逐方确认流程沿用本份平台，原文件与历史记录保留 | 审批通过不等于平台撤销／解除完成；原平台结果未确认不改变原合同；不自动退款 |
| 订单合同页签 | 展示实际采用模板、平台、合同覆盖及原版本入口 | 可看到法大大邮轮已签合同及整单覆盖结果，不再只显示订单旧默认模板 |
| 售后详情 | 展示原平台、原版本、原平台任务号及已签约定 | 从同订单变更反查法大大原文件；当前产品新规则不替代旧合同，合同办理与财务退款分开 |

监管要求抽屉内保留折叠的“演示样例”，只切换当前合同场景，不赋予销售批准监管政策的权限。真实要求由集团配置及确认依据决定。

## 六、代码范围与正式接入边界

本轮五个HTML入口增加共享平台办理脚本：`merchant/sales/contract-prepare.html`、`merchant/sales/contracts.html`、`merchant/approval/approvals.html`、`merchant/sales/orders-detail.html`、`merchant/sales/orders-after-sales.html`。最后一页同时补原平台及版本展示。

新增 `shared/contract-channel.js` 集中处理本份平台、审核内容保持、原申请识别、签署顺序、监管要求和文件取得。直接修改 `contract-prepare-model.js`、`contract-prepare-ui.js`、`contract-prepare.css`、`contract-workflow-model.js`、`contract-workflow-ui.js`、`contract-approval.js`、`order-contract-coverage.js`、`contract-template-bridge.js`、`contract-settings-data.js`。新增两份多平台销售检查脚本，修订一份原配置承接浏览器脚本。其余工作线未提交改动保留。

正式接入仍需核实：各公司采购版本及授权、正式模板全文、12301实际支持的创建／查询／监管能力、法大大签章文件及位置规则、真实结果鉴权、PDF文件保管、后台权限与监管适用依据。本次不填写真实凭据，不调用签署、短信或报送接口。

原方案三步的业务原型完成后，唯一下一步是用户按[页面复核清单](电子合同多平台页面变更复核清单-20260928.md)复核。不自动扩展真实对接或其他模块。
