# 电子合同三项主流程补齐实施验收

日期：2026-09-24。依据：[开发需求说明书](电子合同模块需求说明书-流程状态与业务规则-20260924.md)、[反向核查R01—R03](电子合同原型反向核查-主流程缺口-20260924.md)及用户“执行”授权。

本次完成3项原型缺口，不新增菜单或HTML页面，不接通12301后台。主要使用者是销售经办人：从已确认订单准备合同，完成签署资料和内部送审，再处理平台返回及未完成签约。审批、签署、归档仍沿用既有职责；合同操作不自动办理收款、退款或财务确认。

## 页面增改与操作路径

| 编号 | 菜单／页面 | 已完成内容 | 流程约束 |
|---|---|---|---|
| R01 | 销售中心→合同管理→编辑合同、企业归档 | 增加“签署人设置”，个人支持本人、监护人、代理人，企业维护授权代表；维护实际签署人、证件及联系方式，正文预览和签署进度引用本合同设置 | 本人姓名与证件引用订单；监护／代理／企业代表要求相应授权。更换签署关系、姓名或证件后重新提供授权，修改内容后重新预览送审；平台受理或已有签名后不能直接编辑 |
| R01关联 | 销售中心→订单详情→合同资料 | 明确“签署人及授权在合同草稿中设置”，保留游客资料入口 | 游客基础资料归订单，合同签署安排归合同；不另建一份签署人维护页面 |
| R02 | 销售中心→合同管理→列表、详情、签署进度 | 平台退回后显示“修改重提”；返回草稿，显示退回原因，保留前次审批／平台办理记录，修改附件后重新预览、审核、发起 | 只在明确未受理且没有签名／盖章事实时开放；结果未知先核对原申请。旧批准不能用于发送已修改内容，不能直接原样重复发起 |
| R03 | 销售中心→合同管理→准备合同 | 对按人分签且已撤销留下的缺口建立关联新合同；保留已签份、签名和撤销历史，已有补签草稿则继续办理 | 仅补仍需签约游客及对应已确认金额；阻止重复生成、金额依据缺失、订单变额及并行办理冲突。游客退订、已解除和复杂部分变更不自动补签 |

示例验收：订单30,000元、3人各10,000元，前两份已签，第三份撤销。重新准备只生成第三人的10,000元补签；完成后整单覆盖3人、30,000元，前两份及其签名不变。

签署人设置也随后续变更版本保留，适用授权材料继续对应实际签署人；新版本不继承旧签名。线下企业归档补齐代表身份及联系方式，代表资料变化后重新核对授权。

## 文件范围

业务改动：

- [合同办理规则](../shared/contract-workflow-model.js)：实际签署人、授权条件、退回重提、缺口补签及后续版本承接。
- [合同办理视图](../shared/contract-workflow-ui.js)：设置表单、校验、预览、归档、重提和补签入口；上传附件继续按版本隔离。
- [合同办理样式](../shared/contract-workflow.css)：紧凑设置区和窄屏布局。
- [订单合同覆盖](../shared/order-contract-coverage.js)：签署人维护位置提示。

上述脚本由[合同管理](../merchant/sales/contracts.html)和[订单详情](../merchant/sales/orders-detail.html)既有页面加载；没有新增页面或菜单，没有改动HTML文件。

验收脚本新增[续办规则](../scripts/check-contract-continuation.cjs)、[续办浏览器](../scripts/check-contract-continuation-browser.cjs)；既有销售办理和审批变更浏览器脚本只补齐企业代表资料样例，以继续覆盖归档提交。
