# 88-17个人合同、多人签署与企业合同实施与验收

## 实施范围

- 销售中心 → 合同管理：`merchant/sales/contracts.html`
- 销售中心 → 订单管理 → 订单详情 → 合同资料：`merchant/sales/orders-detail.html`
- 履约中心 → 单团项目 → 项目详情 → 承接对象：`merchant/tour/product-custom-detail.html`
- 直接共享脚本：`shared/contract-multi-sign.js`、`shared/order-contract-coverage.js`、`shared/project-enterprise-contract.js`

## 页面改动

### 合同管理

1. 生成抽屉增加业务类型、订单确认、签约主体、有效模板、适用条款及付款条件检查。“先签后款”按配置通过，不统一要求收齐全款。
2. 增加“一单一份多人合同／一单多份个人合同”，逐人选择覆盖范围，拆分时逐份填金额，显示订单金额、已分配、本次分配和剩余。空选择、0金额、合计不平、重复覆盖和重复提交均阻止。
3. 详情增加逐人签署身份、实际签署人、授权关系、签署状态和时间，并汇总同订单合同。一份待签时整单显示“覆盖未完成”。
4. 条件附件按游客、签署人、适用条件和版本维护；必要附件缺失时定位到具体人和文件，不适用项不强制。
5. 发起签署增加12301扫码预览、平台编号、状态来源、有效期和发起记录。失效后重发保留原记录，原型演示与12301平台返回分开表达。
6. MICE“线下归档”维护文件、双方盖章、授权核对、审核、归档和替换版本。缺任一条件不能归档；已归档V1创建V2时保留V1为历史版本。

### 订单详情和单团项目详情

订单“合同资料”Tab增加订单金额、有效合同、覆盖游客、已分配／剩余和必要签署数；增加补充协议和新版本入口。单团项目“承接对象”Tab增加企业合同归档区，未配置有效企业电子模板时走线下文件、双方盖章、审核和归档。

## 验收结果

- 3个新共享脚本均通过 `vm.Script` 语法检查。
- 3人30000，已给定每人10000，生成3份，合计30000；11000+10000+10000被拦截并明确提示31000与30000不一致。普通订单切换为个人合同时金额保持待填，不按人数自动平均。
- 修改拆分金额后取消，再次打开仍为3份10000；付款条件或订单确认状态待确认时不生成合同。
- 李梅的“未成年人监护人同意书”待上传时被拦截并定位。
- 3份10000合同中2份已签、1份待签，订单显示已分配30000、剩余0、必要签署2/3及覆盖未完成。
- 二维码重发后记录由1条变2条，原失效记录仍可查。
- 企业合同缺文件、双方盖章或授权资料均阻止；V1审核归档后可带原因创建V2，V1保留为历史版本。
- Chrome实页操作控制台错误0，抽屉可滚动，底部按钮完整可见；本次不保存图片。

## 边界

当前为页面内独立样例；不接12301真实接口，不做订单、合同和单团项目的跨页自动回写，不建设生产权限或法务规则。模板、法律条款和付款条件仍以已批准配置为准。

## 2026-09-19合同操作抽屉样式修正

根据用户反馈，将合同列表操作列打开的“生成、详情、签署／扫码、合同变更、企业线下归档”五类抽屉统一为销售中心“售后处理”的抽屉规格：桌面端宽920px，正文内边距16px 20px，顶部保留当前合同摘要；下方使用带标题栏的完整业务分区，分区内部统一为“左侧字段名、右侧字段值／编辑控件”的横向明细行，不再把每个字段包成独立小卡片；底部操作区固定。删除生成和详情抽屉误用的 `drawer-preview`，避免表单控件被全局样式设为不可点击。

实际Chrome验收：三类原页抽屉与售后抽屉宽度、正文间距一致；“订单变量”“模板与签署”等分区显示为整块明细表，字段行没有嵌套小卡片；金额输入可聚焦和修改；所有内容可纵向滚动；390px下抽屉宽367px，底部四个按钮完整可见，宽表格只在表格容器横向滚动；页面控制台错误0。
