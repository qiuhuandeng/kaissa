# 邮轮售后结果承接主链路实施（2026-10-24）

## 本次步骤与业务边界

按进度文档邮轮专项唯一下一步推进第五步。销售与计调沿原售后详情核对客户决定、船方结果、原／目标舱位、名单及合同处理；退款、客户实收转款继续交原财务办理页。申请提交、审批通过、业务结果确认、财务执行和最终办结分别表达。供应商预付、退回款、船方扣损与航次成本仍在原采购／结算流程核对，不随客户退款一起转移。

本次是可操作原型的结果承接：业务经办人登记已取得的处理依据及结果，不在售后页面代替船方分房、签署合同或自动删改库存／名单；保留原记录与已提交名单。财务页面的本次办理结果回到对应售后单，尚未取得回单不记实际退款，转款冲正后重新显示未完成。没有真实银行、船公司或 NC 接口。

## 验收计划

整舱退款、同舱部分乘客退订、接受转团／待决定；审批与船方未确认时保留原占用；目标舱位未确认不能办结；名单新版本与历史版本分别表达；合同结果待办理不能办结。退款提交、待回单、银行退回、金额差异、确认回单分别验证；转款未核销、核销、冲正与差额另行处理分别验证。刷新／返回保持本次结果，重复提交不重复生成款项，原其他产品类型保持原流程。检查 1440 与 1024 窗口下的原抽屉布局。

## 实施和验收结果

本步修改以上 4 个原业务页面及原批量转团的两个共享脚本；新增共享结果规则、详情呈现、财务承接和局部样式，不新增业务页面或菜单。原合同办理入口仍保留，原申请内容在详情的“查看申请资料及当时依据”保留。

- 原售后详情支持保存客户决定、售后审批依据、船方结果、整舱／部分乘客范围、原／目标舱房数量及处理依据、名单版本、附加服务和合同办理结果。只退第三人释放 0 间；原两间与目标一间分别带入。退还船方不解释为可售库存增加。
- 客户实收的退款、转用、对客扣费、继续出行乘客留原单金额逐项核对，合计不超过且须核齐本次可用实收；船方扣损单列。交财务后金额和收款对象保持只读，不重复生成款项记录。
- 退款沿原退款执行、回单、失败处理抽屉；交财务与执行后均不计实际退款，银行退回／金额差异仍未完成，金额一致且回单已确认才计入已退。原型不冒充已生成实账凭证或 NC。
- 转款沿原转款详情及核销抽屉，原／新订单和差额可核。已转用不等于补差已收；财务冲正撤回对应转款结果，已办结售后恢复未完成。关闭或退回的款项保留原因，修改金额／重新申请另行办理，本步不新增售后重提流程。
- 原售后抽屉补正确的标题节点样式，修复关闭后再开时公共标题处理删除节点的问题；原退款页在公共界面脚本尚未就绪时也能打开传入的详情。未改全站导航实现。

## 未完边界和唯一下一步

舱位、名单、附加服务、合同及补退差是经办人登记已办理的依据与结果；本步未自动执行退舱、删除已提交名单、替船方确认或签署合同，也未改写订单实收。财务退款和转款在本次原型会话中回显对应售后结果；正式财务政策、跨公司／币种转用、船方退改及签约政策仍待确认。金额差异不会按完整退款计入，但部分退款分批、冲正后重新申请等细分场景不在本步扩展。

**唯一下一步：主流程串联复验与收尾报告。** 按包船／切舱和散位代理两种起点，复核现有五步的主对象、下一步入口与办理结果；沿统一产品、订单、履约和财务流程给出已通过／待核的收尾结论，不展开新的细分功能清单，不要求真实银行、船方或 NC 接口。
