# 外采供应商对账独立页面与盖章确认第一步实施验收

> 日期：2026-09-29  
> 状态：重构方案第1步已完成并通过页面验收  
> 范围：商户端独立供应商对账、供应商端确认／异议、当前版本盖章件；不含独立付款申请和预付款逐明细退回

## 一、本步结论

供应商对账已从团期结算中拆出。商户端履约中心新增独立“供应商对账”菜单和页面，我方计调是双方对账单的唯一发起方；供应商端“对账结算”改名为“供应商对账”，不再提供主动新建或提交双方对账单的入口，只办理我方提交的待确认单。

供应商逐项核对后：

- 全部一致时，必须上传PDF或图片格式的当前版本盖章对账单，并勾选“已核对当前版本和金额”，才能确认；确认记录保存附件名称、对应版本、上传人和上传时间。
- 任一明细有异议时，只提交异议金额和依据，不使用盖章件；我方处理后形成新版本并重新提交。
- 新版本生成时清除上一版本可用盖章件，旧版本及其处理记录留在历史中，但不能代替当前版本确认。

团期结算页已经移除供应商对账页签和脚本依赖。本步暂保留其原付款申请工作区，待第2步把 `fulfillment-payment-apply.html` 改造成真正的独立页面后再一并移出，避免把未完成的付款重构误记为完成。

## 二、角色和业务承接

| 环节 | 主要角色 | 上游依据 | 当前页动作 | 下游结果 |
|---|---|---|---|---|
| 发起对账 | 我方计调 | 已保存的外采成本项、采购确认和实际服务依据 | 选择采购公司、供应商、协议、期间和费用明细，保存草稿或提交 | 形成待供应商确认的对账单 |
| 供应商核对 | 供应商管理员 | 我方提交的当前版本明细 | 逐项一致／异议；全部一致时上传当前版本盖章件 | 已确认，或差异返回我方 |
| 差异处理 | 我方计调 | 供应商异议金额和依据 | 逐项填写认可金额和处理依据，保存或重新提交 | 新版本待供应商重新核对 |
| 财务承接 | 财务应付、付款复核等岗位 | 已确认金额和盖章确认记录 | 从详情查看关联单据或进入付款申请 | 本步只保留入口方向，不模拟跨页自动回写 |

## 五、正常与异常场景结果

| 场景 | 结果 |
|---|---|
| 我方选择有效成本明细并提交 | 形成待供应商确认单 |
| 供应商逐项一致但未上传盖章件 | 拦截，不能确认 |
| 供应商上传PDF／图片且确认当前版本 | 对账完成，记录当前版本盖章件 |
| 供应商任一明细有异议 | 进入差异处理中，不保存本次盖章件 |
| 我方处理差异并重新提交 | 版本号增加，旧盖章件不能用于新版本 |
| 供应商尝试从对账页主动建单 | 页面无入口，模型也禁止供应商使用我方发起方法 |

## 六、本步边界与遗留

- 当前仍是页面会话原型，不接真实文件上传、电子印章验真、跨端消息和服务端持久化。
- 供应商账单、实际服务材料可作为采购与对账依据，但不等于供应商创建双方对账单。
- 本步没有改变付款资格、应付核算、发票、退款到账或NC处理。
- 已开票退款、外币退款和正式入账时点仍为待财务确认事项。
