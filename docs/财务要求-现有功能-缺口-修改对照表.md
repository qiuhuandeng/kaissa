# 财务要求—现有功能—缺口—修改对照表

> 本表是后续文档梳理、代码梳理、页面改造和最终验收的主清单。F-001至F-020已经完成七轮代码—文档核对并填写当前能力和缺口；后续每批实施后继续更新状态和验收记录。整体依赖、模块边界和首批范围见《业财报表整体改造蓝图》。

> **原型范围说明（2026-09-06）：** 本表中的“数据未贯通、无法复算”用于说明未来正式系统需要什么数据关系，不要求当前静态原型实现真实跨页面汇总。原型改造只检查功能、角色流程、字段埋点、业务规则、报表结构和下钻方向是否完整；模拟数据可以独立，只要不表达错误业务含义。

> **财务数据看板专项覆盖（2026-09-07）：** 用户最新要求为“无下钻、四个顶层Tab”。因此F-019在该看板中的验收方式改为顶层Tab之间按同一筛选条件核对汇总和完整明细；指标卡、图表、金额、编号和表格行不得点击，不使用抽屉、弹窗或业务页面跳转。底层订单、团期、收付、成本和结算关系仍需建立，以保证数据可复算。

> **方案三原型实施记录（2026-09-07）：** 已新建`merchant/data/finance-dashboard-v3.html`并加入数据中心导航。页面固定为四个顶层Tab，共用14项全局筛选；Tab 2至Tab 4直接铺开团期、订单、供应商应付、预付、渠道应收和账龄明细。浏览器验收确认页面内业务链接、业务编号点击目标、下钻属性和弹层均为0；四个Tab切换、筛选、重置和当前Tab导出可用。当前仍是静态业务原型，不代表共同明细关系和正式导出／定时发送服务已经实现。

> **财务补充明细字段整理（2026-09-12）：** 用户补充三组订单口径和回团口径明细表头。本轮已将`本年/年度`、`本周/周度`等同义字段按业务含义整理，将空白列和重复`产品分公司`去除，将`差异<br>`规范为`差异`。`产品代理`、`产品归属`、`产品分公司`以及`收入`、`趣享供应商结算价`、`毛利额`、`毛利率`、`差异`的最终口径仍需财务确认后再进入页面列配置或正式字段字典。

> **订单与团期字段埋点复核（2026-09-12）：** 已结合上述两套明细字段重新核对订单下单、订单列表/详情、团期创建、团期管控和回团动作。当前可以取得凯撒订单号、产品名称/类型、团号、计划出回团日期、销售姓名、门店、数量和订单金额等字段雏形，但多数仅为固定页面或浏览器本地记录；渠道选择未随订单保存，“标记已回团”也未记录实际回团日期、确认人和确认时间。订单年/月/周/双周及回团期间字段应由报表计算；正式实收、供应商结算金额、收入、成本和毛利必须由财务相关模块产生。逐字段证据和最小业务记录点见《订单和团期模块对订单回团明细字段的埋点核对》；F-001、F-003、F-004、F-009、F-010和F-018的缺口结论保持不变。

> **订单与实际回团首批实施记录（2026-09-12）：** 产品报价、销售下单、销售订单列表／详情、团期创建、团期管控和团期详情已经完成首批原型改造。订单可保存发生时产品、销售、渠道、预算归属和确认生效时间；团期可保存计划出回团、实际出团、实际回团、完成依据、确认人与时间、差异原因和更正历史。订单详情已停止在无正式财务记录时按比例推算业务结算收入和渠道佣金。当前记录仍保存于浏览器本地，只证明页面职责、字段和操作流程成立，因此F-003、F-004、F-009、F-010和F-018更新为“首批原型已完成、正式数据仍缺”，不视为整项财务能力已经完成。

> **团期订单页面边界确认（2026-09-12）：** 用户确认履约中心的团期订单列表和详情是有意独立设置的入口，本阶段保留且不修改。此前关于页面收敛的建议不再作为当前实施任务；后续只有在用户明确要求时，才继续核对销售订单与团期订单的数据关系和职责边界。

## 一、状态说明

- `待查文档`：财务要求已识别，尚未核对项目文档。
- `待查页面`：项目文档已核对，尚未核对实际页面和代码。
- `待确认口径`：需要用户或财务明确规则。
- `已确认缺口`：已有足够文档和代码证据证明系统不能承接。
- `待修改`：方案已确认，尚未实施。
- `已修改待验收`：页面或流程已修改，尚未按场景验收。
- `已完成`：需求、功能、数据和场景验收均有记录。
- 优先级中，`P0`表示不补齐就无法形成可信报表的最高优先级，`P1`表示影响重要分析或异常处理，`P2`表示可在口径稳定后建设。
