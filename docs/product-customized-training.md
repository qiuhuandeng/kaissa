# 单团项目系统培训稿

更新时间：2026-08-01

本文用于培训单团、MICE、企业团建、研学定制等项目型业务在新系统中的操作口径。最新业务口径如下：

- 单团项目不会在系统中走完整询价和对客沟通流程。
- 销售、客户和业务负责人在线上或线下确认好方案、金额、服务标准和付款节点后，再录入系统。
- 系统承接最终确认结果，重点处理项目录入、审核、项目团、订单合同、阶段收款、团期团控和团结算。
- 审核通过后进入项目团和团期管控；回团后按团结算流程处理成本、应付、付款、结算和 NC。

## 一、完整链路

```text
客户方案已确认
-> 录入单团项目
-> 补充客户确认材料
-> 提交项目审核
-> 审核通过
-> 生成项目订单、项目合同草稿、项目团、阶段应收计划
-> 项目团进入团期团控
-> 名单、资源、执行、成本按团期逻辑处理
-> 回团/项目完成
-> 团期结算/团结算
-> 财务承接应收、认款、应付、付款、结算、NC
```

一句话边界：

```text
单团项目页管录入和审核；项目团管执行；项目订单管合同和收款；财务管认款、付款、结算和 NC。
```

## 二、角色分工

| 角色 | 主要工作 | 不做什么 |
|---|---|---|
| 项目销售 | 录入客户、确认方案、确认金额、付款节点、客户附件 | 不在系统里发起完整询价流程 |
| 单团经办/项目负责人 | 补服务范围、名单要求、资源要求、履约负责人 | 不替代财务确认收款 |
| 审核人 | 审核客户、金额、服务标准、收款节点、合同主体和履约责任 | 不重新制作对客方案 |
| 团控/计调 | 项目团名单、资源确认、执行、回团和成本 | 不回头改项目确认金额 |
| 财务 | 应收、认款、退款、应付、付款、结算、NC | 不维护项目执行细节 |

## 三、状态口径

| 状态 | 含义 | 主要动作 |
|---|---|---|
| 待提交审核 | 项目已录入，仍需补确认材料或业务字段 | 补确认材料、提交审核、作废 |
| 审核中 | 项目已提交，等待审核 | 审核通过、退回补充 |
| 审核退回 | 信息不完整或金额、合同主体、服务范围不清楚 | 修改后重新提交 |
| 已成团 | 审核通过，下游对象已生成或已关联 | 查看项目团、项目订单、项目合同、阶段应收 |
| 执行中 | 项目团已进入团期管控 | 名单、资源、出团、执行、成本 |
| 已回团 | 项目执行完成，等待结算 | 补验收材料、确认成本、提交结算 |
| 已结算 | 团期结算完成 | 查看结算和 NC 承接 |
| 已取消 | 项目取消 | 处理退款、扣损和归档 |

## 四、场景一：录入单团项目

客户已经确认出行或活动方案后，销售或项目经办进入“产品中心 > 自营产品 > 单团项目”，点击“录入单团项目”。

需要录入：

- 客户单位、联系人、联系方式。
- 出行或活动日期、人数、人员结构。
- 目的地、活动类型、服务范围。
- 客户确认金额、付款节点、币种。
- 合同主体、销售归属、项目负责人。
- 客户确认材料，例如客户确认方案、报价单、邮件、合同附件、内部审批附件。

保存后，项目进入“待提交审核”。如果客户确认材料缺失，系统应提示缺口，但不应要求用户在系统里重新制作完整对客方案。

## 五、场景二：提交和审核

提交审核前，经办需要确认：

- 金额和付款节点是否与客户确认材料一致。
- 服务范围是否能支撑后续团控执行。
- 合同主体、客户主体、收款主体是否清楚。
- 是否需要线下盖章、补充协议或特殊审批。

审核人重点看业务事实是否完整。审核通过后，系统生成或关联：

- 项目订单。
- 项目合同草稿。
- 项目团。
- 阶段应收计划。

审核退回时，必须写明退回原因，例如确认金额不清、付款节点缺失、合同主体不一致、客户附件缺失、服务范围无法执行等。

## 六、场景三：项目团执行

审核通过后，项目团进入“履约中心 > 团期管控”。团控/计调在项目团中处理：

- 名单导入和资料完整度。
- 房型、分房、分车、分组。
- 交通、酒店、用车、地接、活动、会务资源确认。
- 出团通知、执行记录、异常处理。
- 预估成本、实际成本、供应商确认材料。

项目团不是公开售卖团期，不突出渠道余位、OTA 上架和公开库存。它的重点是围绕这个客户项目完成执行、成本和回团结算。

## 七、场景四：项目订单、合同和收款

项目订单承接客户、确认金额、阶段收款、合同和售后。销售或合同经办在项目订单中处理：

- 项目合同生成、发送、盖章或附件回传。
- 阶段收款登记和销售认款。
- 项目名单与订单资料反查。
- 项目变更、取消、退款申请。

收款确认仍由财务完成。销售可以提交认款和凭证，但不能在订单详情里直接完成财务认款、入账或 NC 推送。

## 八、场景五：项目变更

审核确认后，如果人数、日期、金额、服务范围或付款节点变化，不能直接覆盖原记录。必须新增项目变更。

项目变更需要记录：

- 变更类型。
- 变更前后内容。
- 金额影响。
- 影响的阶段收款、合同、名单、资源和成本。
- 客户确认依据。
- 审批结果。

变更审批通过后，销售订单、项目团、阶段应收和团结算按变更结果承接。

## 九、场景六：回团和结算

项目完成后，团控补齐回团材料、客户验收材料和实际成本。结算按团期结算/团结算流程处理：

- 核对应收、实收、退款和欠款。
- 核对实际成本、应付、已付和待付。
- 核对项目变更和客户验收材料。
- 计算毛利。
- 生成结算结果并承接 NC。

## 十、常见错误

| 错误做法 | 后果 | 正确做法 |
|---|---|---|
| 把企业团直接录成普通散客订单 | 项目名单、阶段款、合同和结算承接不清 | 录入单团项目并审核 |
| 客户确认材料缺失仍提交审核 | 审核无法判断金额和服务范围 | 补齐确认方案、金额和附件 |
| 审核后直接改确认金额 | 应收、合同和结算依据不一致 | 走项目变更 |
| 在单团项目页处理财务认款 | 财务口径失控 | 销售提交认款，财务复核确认 |
| 项目完成后只写备注不做回团结算 | 成本、应付和毛利无法确认 | 进入团期结算/团结算流程 |

## 十一、演示顺序

1. 从单团项目列表录入项目。
2. 上传客户确认材料。
3. 提交审核。
4. 审核通过并查看项目订单、项目合同、项目团、阶段应收。
5. 进入项目团维护名单和资源。
6. 在项目订单登记阶段收款。
7. 项目变更。
8. 回团后进入团期结算/团结算。
