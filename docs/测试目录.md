## 二、先按交易责任区分主场景

法人公司是独立承担法律责任的公司；核算单位是独立形成会计账务结果的单位，二者的实际对应须取得正式资料。应收表示对方已经欠本公司的款，应付表示本公司已经欠对方的款。门店名称或部门名称不能单独决定这些责任。

| 主场景                       | 业务关系                                             | 必须分别核对                                                              |
| ---------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------- |
| 同公司自营组团               | 公司向游客销售，并向酒店、地接、交通等供应商采购资源 | 客户交易、各项资源成本及供应商欠款；购买资源不自动变成整包外采产品        |
| 直接整包外采                 | 公司向外部同行采购完整参团产品，再向游客销售         | 对客成交、供应商确认及采购结算；财务收入按实际合同责任另核规则            |
| 集团内采购转售（已确认纳入） | A与游客签约并收款，向B采购产品；B提供产品并组织履约  | A对客交易、A应付B与B应收A、B对外采购和履约；集团对客成交不重复累计        |
| 集团内代销（已确认纳入）     | B与游客签约并收款；A取得销售佣金                     | B对客交易及履约、A与B的佣金结算；若A代收客户款，另核代收资金及交付B的余额 |
| 内部供货后再外采             | 上述采购转售或代销关系中，B的产品又来自外部供应商    | 游客交易、A/B之间适用的产品结算或佣金、B与外部供应商的采购各自对应        |
| 同法人部门协作               | 同一家公司下的产品部门、销售部门或直营门店协作       | 公司账务和部门贡献分开；不因两个部门参与而生成虚假的法人间采购            |

用户确认两种集团模式都存在，尚未指定各公司、产品、渠道和订单的适用范围，也未确认佣金比例、内部结算价格或会计收入方法。代销是业务关系名称，正式会计处理仍需财务按交易事实明确。

直营、加盟、呼叫中心、分销及平台等是销售组织或渠道维度；自营、外采及内部供货是产品供给维度。测试按适用组合展开，不把两组维度混成一个分类。

## 四、规则依据如何分级

1. **本轮用户明确的范围**：采用本稿第一节和集团采购转售／代销范围确认，不反复询问。
2. **项目已有明确反馈记录**：注明原记录日期、适用范围和对应源码。可作为目标规则依据，实际系统执行情况仍须验证。
3. **流程工作稿的建议**：保留为待确认选项；“建议口径”“确认稿”文件名、示例数字、原型测试通过均不能代替批准。
4. **正式制度未集中或证据不足**：标为待补依据；先核已有合同、制度和实际做法，再决定是否需要重新拍板。
5. **代码与文档、不同版本不一致**：记录冲突及后续明确反馈，不直接把代码计算值当标准答案。

最终采用一项金额规则时，至少记录适用公司和业务、来源、确认人／日期、生效日期、计算基础、舍入方式、异常及历史订单处理。单纯“同意按现有系统”不足以形成独立验收预期。
