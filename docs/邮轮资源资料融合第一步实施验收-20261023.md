# 邮轮资源资料融合第一步实施验收

> 后续完整资源核查：用户重新提供六类资源功能树后，已形成[33项对照](邮轮资源模块逐项核查-20261023.md)。本文件只记录当时局部实施验收，不代表船公司、完整船只媒体／舱型模板、港口介绍、线路PDF模板或签证资料维护已全部完成。当前范围及下一步以最新核查和进度第三、四节为准。

日期：2026年10月23日。依据：[融合补充优化方案](邮轮业务融合补充优化方案-20261023.md)第1步及用户“执行”指令。本步完成资源缺口与产品资料引用，不代表邮轮整体五步已完成。

## 一、业务位置与保留项

资源人员维护低频、可复用的船只、舱型、港口和线路模板；产品人员在原通用产品编辑中选择资料、编排逐日航程，再由原航次入口安排具体日期、库存和价格。本步不办理采购分配、订单占用或财务确认。

原资源列表与右侧编辑抽屉保持；船只仍按“船只信息—基础舱型”维护，资料补在船只信息之后。模板仍按“模板信息—港口与航程—可采购舱型”维护。产品仍用“基础信息—线路配置—图片海报”三个步骤，线路内部保留“航线与船舶—航程与登离船—舱房售卖—费用与证件”四区、左侧线路切换及原保存／审核入口。

## 二、新增与修改清单

| 性质 | 模块／菜单／页面 | 本步内容 |
|---|---|---|
| 新增页面与菜单 | 资源→邮轮资源→港口 | 中文名、英文名、别名、国家城市、当地时区、税费参考及币种；关键词／国家筛选；新增、编辑、保存后复查及取消均在右侧抽屉。默认10条资料，税费不虚填，也不自动形成当期售价 |
| 原页补充 | 资源→邮轮资源→船只档案 | 原抽屉补船舶介绍、总舱房数、政策、资料版本、图片及甲板图／手册附件；原舱型表区分名称、船方代码与分类，补面积、景观、床型、设施；保留标准／最大入住和第三四人／儿童规则，增加舱型增删及当前页保存回显 |
| 原页补充 | 资源→邮轮资源→邮轮模板 | 原航程区域改为引用港口，按天维护海上日、到离港当地时间和过夜停靠，可新增、删除、上移；首末停靠表达登离港，航程天数随卡片数量更新；保留所选船只、季节和适用舱型。船只列表“模板”入口带入该船筛选 |
| 原页补充 | 产品→产品管理→自营产品编辑（邮轮） | 在原选船位置带入对应资料、图片、版本及舱型代码；在原航程区选模板、编辑逐港安排及上传行程PDF。换船或换模板先确认替换范围，取消保留已有内容；线路切换分别保留新增引用、舱型、航程和附件编辑 |
| 共用入口最小接入 | 共享导航及通用编辑脚本 | 导航仅增加“港口”；通用编辑仅在既有邮轮配置位置挂接上述资料补充，其他类型不生成邮轮区 |

没有新增一级模块；没有另建邮轮产品编辑器、开排页、销售预订或财务流程。船公司、包舱采购、建团抽屉、价格名额、订单、名单、预付及结算本步未修改。

## 三、需求—缺口—验收对照

| 对应需求 | 原缺口与本步处理 | 实际验收结果 |
|---|---|---|
| 邮核02／融01资料部分 | 原船只只有设施备注，补介绍、图片、政策、版本与附件维护 | 实际选择图片及PDF，核附件内容可读，保存后重开显示修改；更换船只能带入对应资料；资料是示例，未确认的船方参数不编造为实值 |
| 邮核03／融01舱型部分 | 原四类下缺不同船方代码及详细资料 | BA、BC独立显示；编辑代码、面积并保存回显；新增和删除在原表完成。采购、库存和分房对代码的承接仍待后续步骤 |
| 邮核04／融02 | 缺港口档案，模板主要为文本 | 别名搜索、编辑／取消／新增、船只筛选通过；逐港时间、海上日清空时间、过夜停靠、顺序和天数保存通过 |
| 邮核06／融03引用部分 | 原通用产品有四区，但缺选船资料及逐港引用 | 原三步骤、四区保留；换船确认／取消、模板带入8天、增删同步天数、PDF并行、线路切换保存各自引用通过 |
| 多类型共用约束 | 邮轮补充不能改变其他产品编辑 | 跟团、专列、自由行的编辑区结构及全部字段值与改动前逐项一致；原步骤与保存入口均可操作 |

融01的船公司品牌／协议／佣金、融03的岸上方案完整承接以及融04—13不在本步完成范围；不把需求条目的全部验收条件一并标为通过。
