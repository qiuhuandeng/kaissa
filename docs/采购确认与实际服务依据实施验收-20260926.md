# 采购确认与实际服务依据实施验收

日期：2026-09-26。范围：同行采购差价场景的页面原型；接续双方均可先提交账单后的上游依据，不增加财务菜单。

## 一、入口、岗位和下一步

| 谁办理 | 从哪里进入 | 本步处理什么 | 处理完交给谁 |
|---|---|---|---|
| 供应商订单人员 | supplier → 订单确认 → 本单“回复” | 按原数量及价格确认、提出补差、暂时保留、无法承接；收到采购公司的取消申请后申报取消损失 | 原条件确认交采购公司计调核实际服务；补差或取消损失交采购公司计调认可；无法承接由计调重新安排采购 |
| 采购公司计调 | 履约中心 → 团期结算 → 供应商对账 → **采购依据** → 本单“办理” | 对供应商补差／取消损失填写核对依据并认可或退回重报 | 认可后形成我方采购条件；退回仍由供应商订单人员重报 |
| 采购公司计调 | 同一采购依据抽屉 → 已确认采购单 | 确认实际人数、单价、增加、减免、实际服务日期及依据 | 本页对账工作区可选该费用；已有供应商来单则补入本单核对依据 |
| 双方对账人员 | 我方“新建对账”或 supplier“提交账单” | 原先两种发起方式保持；采购单不是由对账单生成 | 我方先发交供应商；供应商先报交采购公司计调；最后同一金额双方认可后交财务应付岗 |

“采购依据”是本次同行对账上游的直接办理入口，仍在团期结算页内。原团期成本维护和付款申请保留，不在两个入口并行编辑同一套模拟数据。采购公司、供应商、订单、团期、协议、服务项目和本次办理岗位直接展示；不展示对客售价或内部毛利。

一条采购服务使用独立采购单号；同一凯撒订单的地接费、单房差可以分别确认。列表显示一个采购主状态，实际服务、供应商申报与对账占用在详情查看。列表支持公司／状态／单号查询；固定右侧操作列92px、表格内横向滚动。

## 二、业务规则与金额证据

1. 原采购10,000，供应商报加住1,200：待采购公司确认期间，原采购金额仍10,000，申报11,200单列；计调认可后采购金额才为11,200。退回保留原价和申报记录。
2. 暂时保留须有截止日和依据；无法承接须有原因，不能标成已确认。未完成采购确认的费用不能报账；已完成采购确认但实际服务未确认的，供应商仍可先报账，计调补实际依据后才能完成核对。这与“无需我方先发起对账”不冲突。
3. 取消必须有采购公司的取消申请。供应商可以申报0或非零损失，但不能自行决定采购取消的最终费用。计调认可600损失后为已取消且可对账600，不一律剔除，也不继续计原10,000。
4. 实际20人×5,000＋加住2,000－减免1,000＝101,000。采购原条件独立保留，101,000作为本次实际服务费用进入对账；客户退款不自动视为供应商减免。
5. 已提交或已确认的对账不允许从采购依据直接覆盖原费用。后补费用另行确认；本次不新增后补费用制单页。
6. 供应商来单处于“待我方核对”时可补实际服务：原60,000、供应商62,000保留，另列实际61,500，原历史不改，对账升版，旧版本不能再提交。认可61,500交供应商再次确认；认可供应商原账单则按原流程完成双方业务确认。
7. 数量、金额小数位、负值、超额减免、日期、确认号、办理依据、角色范围、状态和旧版本均校验。日期以2026-09-26演示业务日判断，不代表已确定公司的结算截止制度。
8. 确认号、保留截止、原采购条件、费用回复、实际依据及办理记录随本单保存；退出未保存表单需确认放弃。既有已对账费用只读，不能误改已确认账。

## 四、边界及唯一下一步

各页面仍是独立会话，刷新复位；实际依据在当前团期结算页可用于对账，不承诺从supplier自动发送或跨页回写。供应商提报、计调认可由两端对应样例分别演示，不用角色切换伪造实际送达。确认依据采用业务单号和文字，不模拟后台附件上传、实际应付、付款、审批或NC推送。实际岗位授权、佣金代销及正式财务政策仍待业务／财务确认。

**唯一下一步：在既有款票页面补对账结果承接**，核对对账版本、采购公司与付款公司、预付冲抵、实际已付、申请中及未付余额，明确财务应付岗、发票岗和资金岗各自办理；不新造付款模块，不扩大到真实银行或后台联调。原8批／36项／6场景及并行工作线保持。
