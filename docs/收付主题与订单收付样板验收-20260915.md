用户在整体方案交付后要求“执行”，本轮按约定先完成收付明细与订单收付综合查询样板。依据《数据中心经营分析与页面整体方案-财务附件及旅行ERP对标-20260915》第6.9、6.10及8.1节，保留原8批、月度损益成果及此前回团按钮撤回。本次不代表整体方案全部实施。

- 收付明细：出纳、收付及往来会计核对实际资金、逐单分配、核销和原款链；上游为财务已确认资料，下游为核对与导出，不产生或修改资金单据。
- 订单收付：往来会计在同一截止日看订单服务/阶段的应收、实收、未收、应付、实付、未付；上游为确认债权债务、资金分配和核销，下游为财务复核。金额口径与会计余额分别表达。
- 改动两页和必要共享呈现/Tab注册；不改源办理、独立团期订单、门店流程、附件及其他报表计算。

## 三、金额与资料边界

1. 资金分配与核销是不同事实。原收付21类算例保持原模型；新主题为已有结果按主题整理，并显式补两条应收核销及原冲回关系，不推断“金额相同就属于某订单”。
2. 订单综合使用独立核对资料，复用既有历史应收应付计算；未对源办理页做跨页联动，不能据此宣称与全部现有订单已同源取数。每一例的债权债务、资金分配、核销均有明确关联。
3. 未收差额=已确认应收−实际收款分配净额−转入净额−其他预款/减免抵收；未付差额=已确认应付−实际付款分配净额−预付/减免抵付。转款已包含在冲抵中的部分单独列示，不重复扣。此为核对样例约定，正式业务适用仍由财务确认。
4. 资金与分配资料不足时，不推算可用余额；负差额保留为超收/超付核对，不与其他订单正差额强行抵净。汇总含缺数则不显示假完整合计。
5. 原款未退/转存余额是原款整体观察，不能当作某订单可用余额或允许退款金额；原记录金额不累计成现金流。完整订单可退款资格仍在源流程判断。
6. 当前原型覆盖固定资料期。日期超出覆盖期显示资料不足，正式任意历史、银行/平台接口、真实权限、外币折算与财务政策仍待接入/批准。未提供汇率不折算，不同币种不相加。
