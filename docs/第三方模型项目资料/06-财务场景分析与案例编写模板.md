# 凯撒旅游SaaS财务场景分析与案例编写模板

版本：v1.0  
编写日期：2026年8月24日  
参考材料：《表结构 (1).docx》  
适用范围：C01—C35全部端到端业财场景

## 一、模板定位

本模板规定每个财务场景应该怎样分析和表达。目标是让财务能够顺着一个真实案例逐笔验算，让技术能够从同一案例中识别业务记录、生成时点、金额变化和前后关系。

项目提供的《表结构》采用了直观的案例表达：先说明集团、产品和结算模式，再用场景设定表、完整价格拆解、分阶段资金流、会计处理、部门利润和合同资金发票检查呈现案例。本模板保留这一主干，并补足债权债务、余额、团期结算、多主体对账、NC及反向调整。

不得直接照抄参考文档中的会计结论和数字。参考文档是表达结构来源，其中具体收入确认、管理费、佣金、税务及会计分录仍需按凯撒制度确认。

## 二、为什么统一使用这个模板

每个案例如果只描述“生成应收、收到钱、结算后推NC”，财务无法判断金额是否正确；如果只列业务单据，技术也不知道各单据什么时候形成、怎样变化和怎样核销。

统一模板要做到四件事：

1. 一眼看懂业务是谁和谁做生意；
2. 一眼看懂客户价怎样一层层拆到各公司、门店和供应商；
3. 沿时间看到每一阶段产生的单据、余额、现金和会计结果；
4. 最后用公司结果、资金结果和对账等式证明数字没有漏记或重复。

## 三、场景分析顺序

```mermaid
flowchart LR
    A[确定产品来源和销售方式] --> B[识别参与方和法人责任]
    B --> C[画合同、业务、资金和发票方向]
    C --> D[从客户价向下拆完整价格]
    D --> E[按时间推演业务和财务变化]
    E --> F[计算每阶段余额]
    F --> G[完成各类结算]
    G --> H[分别计算公司和部门结果]
    H --> I[形成会计事项和NC]
    I --> J[正算、反算和跨主体核对]
    J --> K[列变化分支和待确认结论]
```

任何一步算不平，都必须回到前一层查找差异，不能先写会计分录，把差额硬塞进某个收入、成本或费用。

## 四、每个案例固定使用的十三部分

## 第1部分：场景在业务全景中的位置

先用一句话给场景定性：

```text
产品来源 × 销售方 × 收款方 × 履约方 × 采购方 × 结算方式
```

示例：

```text
集团内B公司包装的外采产品
× A公司对客销售
× A公司收取客户款
× B公司组织履约
× B公司向外部供应商采购
× A-B按订单内部结算、B与供应商按团期结算
```

同时列出：所属业务主轴、适用产品、适用组织关系、与相近案例的区别以及不适用情况。

## 第2部分：业务场景设定

所有案例必须有具体公司、客户、产品、日期和金额，不写抽象的甲乙双方后直接推演。

| 项目 | 内容 |
|---|---|
| 销售公司 | 具体法人公司 |
| 销售门店或渠道 | 直营、加盟、OTA、分销或无渠道 |
| 产品名称 | 具体示例产品 |
| 产品类型 | 跟团、邮轮、专列、自由行、研学、MICE、单项或机票 |
| 产品来源 | 本公司自营、体系外采购、集团内部采购 |
| 客户 | 散客、企业、学校、同业或渠道 |
| 游客及数量 | 人数、房间、舱房、铺位或票数 |
| 团期或项目 | 团期、航次、班期、出行日期或项目名称 |
| 客户合同日期 | 年月日 |
| 出发和回团日期 | 年月日 |
| 收款方式 | 定金尾款、一次性、账期、预存、平台代收等 |
| 采购和付款方式 | 先服务后付款、预付、分期或周期结算 |
| 门店或渠道结算 | 全额上缴后返佣、净额汇款、预存扣款或账期 |
| 币种 | 客户、内部结算和供应商币种 |

### 4.2 成本结构

自营产品不能只写一个成本总额，应拆出交通、酒店、地接、餐饮、门票、签证、保险、领队等实际成本；固定资源还要拆已使用、可退、未售损耗和共享分摊。

### 4.3 价格和结果公式

```text
客户合同价 - 客户直接抵扣 = 客户应付

销售公司客户收入或交易总额
- 内部采购或外部采购成本
- 销售公司承担的优惠、佣金和费用
= 销售公司经营结果

产品公司内部销售额
- 外部采购净成本
- 产品公司承担的费用和损失
= 产品公司经营结果
```

如果管理费、返佣或优惠存在两种会计处理，应分别计算方案A和方案B，不得在同一张利润表中既冲减成本又重复计入收入。

## 第12部分：最终对账和反算检查

### 12.1 客户侧

```text
有效应收
= 已核销收款
+ 已核销预收/预存
+ 已批准抵销或核销
+ 期末待收
```

### 12.2 供应商侧

```text
有效应付
= 已核销付款
+ 已冲抵预付
+ 已批准抵销
+ 期末待付
```

### 12.3 经营结果

```text
结算收入 - 结算成本 - 单列费用或损失 = 结算经营结果
```

### 12.4 多主体

```text
内部提供方应收 = 内部接收方应付

各公司经营结果合计
- 集团内部未抵销影响
= 集团对外经营结果
```

### 12.5 资金反算

```text
期初资金
+ 实际收款
+ 供应商退款/平台补贴等流入
- 客户退款
- 供应商付款
- 门店/渠道佣金付款
= 期末资金
```

现金净额不等于会计利润时，要列出未收应收、未付应付、预收、预付、税费或跨期等差异，不得强行令两者相等。

## 第13部分：变化分支、备选方案和财务确认结论

### 13.1 变化分支

至少检查：收款方改变、全额上缴后返佣与净额汇款、优惠承担方改变、产品来源改变、客户退款而供应商少退、预付应付和付款时点改变、已结算已推NC或跨期后调整。

### 13.2 备选处理

当财务政策尚未确认时，不要只写“待确认”：

| 待确认事项 | 方案A及数字结果 | 方案B及数字结果 | 对收付款和结算影响 | 对会计及NC影响 | 需要谁确认 |

| 确认事项 | 最终口径 | 生效范围 | 生效日期 | 确认人 | 对其他案例的影响 |

## 五、模板中特别加强的检查

### 1. 合同价、客户实付和收入不能混为一个金额

优惠、平台补贴、门店代收和代理模式都会造成差异，必须说明差额由谁承担。

### 2. 应付和实付的差额不能消失

供应商应付16,000元、实际支付15,520元时，480元必须有合同依据和明确去向。可以是采购折让、返佣、服务收入或另行应收，但只能采用经确认的一种处理，不能重复计算。

### 3. 部门内部贡献不能冒充法人间交易

直营门店和公司内部部门的管理贡献不产生另一家法人的应收应付。只有加盟门店、集团内独立法人或外部渠道才形成往来。

### 4. “回团后自动确认”不能替代企业制度

回团后第几天结算、收入确认依据、暂估成本条件和自动处理范围必须由财务确认。案例可以给出建议时点，但应标明是设计建议。

### 5. 会计分录不能掩盖业务数据缺失

先把订单、合同、应收、收款、成本、账单、应付、付款和结算计算清楚，再说明会计事项。业务数据算不平时，不能增加一条“其他收入”或“其他支出”强行平账。

### 6. 同一笔收益不能重复出现

供应商返还既冲减成本又作为采购部收入，或者部门贡献未经抵销又计入公司利润，都会导致重复。必须通过公司结果表和部门抵销式检查。

## 六、参考文档中发现的示例差异如何处理

参考文档第一案例对同一业务出现了520元、1,480元和1,660元三种结果。按其展示金额：

```text
合同价20,000
- 供应商结算基础16,000
- 门店佣金2,000
- 总部优惠1,000
+ 供应商扣点480（若确认为额外收入）
= 公司结果1,480
```

如果480元直接冲减采购成本，则净成本为15,520元，也得到：

```text
20,000 - 15,520 - 2,000 - 1,000 = 1,480
```

两种会计展示不能同时采用，否则480元会重复。部门结果1,660元还需要重新检查销售员佣金300元究竟包含在门店佣金2,000元内部还是公司另行承担，并抵销部门间重复的480元。

这类差异正是新模板增加“公司结果—部门结果—资金反算—备选方案”四重检查的原因。外部模型引用参考文档时应继承方法，不继承未经验算的结论。

## 七、模板使用完成标准

一个场景只有同时达到以下条件才算完成：

- 场景事实具体到公司、产品、客户、团期和日期；
- 所有参与方的合同和责任明确；
- 价格从客户合同价完整拆到外部供应商实际收款；
- 业务关系、债权债务和资金流三张图齐全；
- 每一阶段都有业务记录、余额、资金和会计事项；
- 团期结算、供应商对账、应付和付款分别说明；
- 每家公司和部门结果能够相互还原；
- 合同、业务、资金、发票和会计五条线可以逐段核对；
- NC事项可追溯到业务来源；
- 客户侧、供应商侧、多主体和资金反算全部成立；
- 未确定政策提供完整备选方案并留给财务确认。
