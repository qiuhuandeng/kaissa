# 凯撒旅游SaaS多主体复杂业务示例

版本：v1.0  
编写日期：2026年8月24日  
示例主题：A公司销售B公司向外部供应商采购并包装的旅游产品

## 一、示例用途

本例用于帮助外部阅读者理解凯撒集团业务中“客户订单、集团内部产品结算和外部供应商采购同时存在”的真实结构。

本例是项目背景说明，不代表所有业务均采用相同的收入确认、开票和付款政策。涉及具体会计及税务判断的部分，正式落地时仍需按凯撒合同和财务制度确认。

## 二、参与方

| 参与方 | 本例责任 |
|---|---|
| 客户张女士 | 购买旅游产品并支付团款 |
| A公司 | 获客、报价、与客户签约并收取客户款 |
| A公司销售门店 | 具体服务客户，属于A公司内部经营单位 |
| B公司 | 提供集团内部产品，组织外部采购并负责产品履约 |
| 外部地接供应商 | 向B公司提供目的地接待服务 |

本例不设置独立资金公司，客户款直接进入A公司，供应商款由B公司支付。

## 三、业务关系

```mermaid
flowchart LR
    C[客户张女士] -->|购买旅游产品 10,000元| A[A公司]
    A -->|采购B公司产品 8,000元| B[B公司]
    B -->|采购地接服务 结算基础8,000元| S[外部地接供应商]
```

需要分别理解三段业务：

1. 客户向A公司购买产品；
2. A公司向B公司采购集团内部产品；
3. B公司向外部供应商采购地接服务。

三个关系共同服务同一位客户和同一团期，但不能合并成一张应收或应付。

## 四、金额条件

| 金额项目 | 金额 | 付款方 | 收款方 | 计算依据 |
|---|---:|---|---|---|
| 客户合同成交价 | 10,000元 | 客户 | A公司 | A公司与客户合同 |
| 客户实际付款 | 10,000元 | 客户 | A公司 | 本例一次性全额付款 |
| A公司与B公司内部结算价 | 8,000元 | A公司 | B公司 | 集团内部产品结算规则 |
| 外部采购结算基础 | 8,000元 | B公司 | 外部供应商 | B公司采购协议 |
| 供应商返还比例 | 3% | 外部供应商承担 | B公司取得 | 采购协议后返或价格折让 |
| 供应商返还金额 | 240元 | 外部供应商承担 | B公司取得 | 8,000 × 3% |
| B公司外部采购净成本 | 7,760元 | B公司 | 外部供应商 | 8,000 - 240 |

如果采购合同规定先支付8,000元、之后供应商另行返还240元，则资金过程是“先全额支付、后返还”；如果合同允许直接扣除返还，则B公司实际支付7,760元。两种资金过程不同，但必须依据合同保存，不能只保存一个净额。

## 五、客户订单链路

### 1. 下单和应收

A公司销售门店为张女士下单，订单成交价10,000元。订单确认后：

- 客户合同主体为A公司；
- A公司形成客户应收10,000元；
- 订单关联B公司提供的产品和对应团期；
- A公司销售门店记录销售归属，但门店本身不形成法人应收。

### 2. 收款和核销

客户向A公司银行账户支付10,000元：

```text
A公司到账流水：10,000元
财务确认收款：10,000元
核销客户应收：10,000元
A公司客户应收余额：10,000 - 10,000 = 0元
```

客户付款只结清客户对A公司的债务，不代表A公司已经向B公司付款，也不代表B公司已经向供应商付款。

## 六、A公司和B公司的内部结算链路

订单确认并满足内部结算条件后，按内部结算价8,000元形成：

```text
B公司对A公司的内部应收：8,000元
A公司对B公司的内部应付：8,000元
```

双方记录应使用同一个内部交易关联号，并关联同一客户订单和团期。

如果A公司向B公司全额支付8,000元：

```text
A公司实际付款：8,000元
A公司内部应付余额：8,000 - 8,000 = 0元
B公司实际收款：8,000元
B公司内部应收余额：8,000 - 8,000 = 0元
```

如果集团采用月度净额清算，8,000元仍先作为双方应收应付存在，月底再根据双方对账结果统一划款或依法抵销，不能因为尚未划款而删除内部交易。

## 七、B公司和外部供应商的采购链路

### 1. 采购和成本

B公司根据供应商合同采购地接服务。履约完成并确认实际使用后，采购结算基础为8,000元，供应商返还240元。

若返还属于本次采购价格折让，则：

```text
B公司实际采购成本 = 8,000 - 240 = 7,760元
B公司供应商应付 = 7,760元
```

若返还是履约后独立确认的返佣，则可能先形成8,000元成本和应付，再单独确认240元应收返还或成本调整。具体采用哪种方式取决于合同、发票和财务政策。

### 2. 付款

采用净额支付时：

```text
B公司供应商应付：7,760元
B公司实际付款：7,760元
B公司供应商应付余额：0元
```

采用先全额支付、后返还时：

```text
B公司先支付供应商：8,000元
供应商后返B公司：240元
B公司最终净流出：8,000 - 240 = 7,760元
```

两种方式的银行流水数量和核销过程不同，但最终都要证明应付、付款和返还已完整结清。

## 八、三段债权债务

| 交易关系 | 应收方 | 应付方 | 金额 | 结清方式 |
|---|---|---|---:|---|
| 客户销售 | A公司 | 客户 | 10,000元 | 客户向A公司付款并核销 |
| 集团内部产品结算 | B公司 | A公司 | 8,000元 | A公司向B公司付款或内部清算 |
| 外部供应商采购 | 外部供应商 | B公司 | 7,760元或合同规定的毛额 | B公司付款并处理240元返还 |

这三段关系必须分别生成和结清。它们之间通过订单、产品、团期和内部交易关联号建立追溯，不通过合并金额替代各自债权债务。

## 九、各公司经营结果

在本例假设A公司作为客户销售的主要责任方、B公司按内部产品销售确认8,000元，并将供应商返还作为采购价格折让的情况下：

### 1. A公司

```text
对客户销售金额：10,000元
向B公司采购成本：8,000元
A公司经营结果：10,000 - 8,000 = 2,000元
```

### 2. B公司

```text
向A公司内部销售金额：8,000元
外部供应商采购净成本：7,760元
B公司经营结果：8,000 - 7,760 = 240元
```

### 3. 集团整体

集团内部8,000元销售和采购在集团合并观察时相互抵销：

```text
集团对外客户销售：10,000元
集团对外供应商净成本：7,760元
集团整体经营结果：10,000 - 7,760 = 2,240元
```

也可以通过公司结果相加验算：

```text
A公司经营结果2,000 + B公司经营结果240 = 集团整体经营结果2,240元
```

上述结果以本例的主责方和采购折让假设为前提。如果A公司只是代理销售，应重新判断A公司的收入是否仅为佣金或销售差额，但客户资金、内部结算和外部采购过程仍需完整保存。

## 十、资金流结果

采用净额支付且各方均已结清时：

```mermaid
flowchart LR
    C[客户] -->|10,000元| A[A公司]
    A -->|8,000元| B[B公司]
    B -->|7,760元| S[外部供应商]
```

各方净资金结果：

| 参与方 | 流入 | 流出 | 净额 |
|---|---:|---:|---:|
| A公司 | 10,000元 | 8,000元 | 2,000元 |
| B公司 | 8,000元 | 7,760元 | 240元 |
| 集团合计 | 10,000元 | 7,760元 | 2,240元 |

资金净额与本例经营结果相同，是因为本例所有应收应付均已结清且未设置税费、未付款、预收、预付和跨期事项。真实业务不能据此假定现金利润永远等于会计利润。

## 十一、团期结算

本订单进入B公司组织的团期。团期可能还有其他销售公司和其他订单，因此团期结算需要：

1. 汇总本团全部有效订单和游客；
2. 分别确认各销售公司的客户销售金额；
3. 按各订单保存内部结算价；
4. 汇总B公司对外采购实际成本；
5. 将供应商固定费用或共享资源按确定规则分摊；
6. 核对客户退款、供应商退费和资源损耗；
7. 生成各公司内部结算明细；
8. 完成B公司与供应商的账单核对；
9. 分别展示团期经营结果和各法人公司结果。

同一团期可以汇总多张订单，但付款时可以把多个团期的供应商应付合并成一笔银行付款。合并付款后仍要把金额分配回每张应付和每个团期。

## 十二、发票关系

在常见的三段合同关系下，发票方向可能为：

```text
A公司向客户开具销售发票
B公司向A公司开具集团内部销售发票
外部供应商向B公司开具采购发票
```

实际开票主体、内容、税率和供应商返还的票据处理必须依据正式合同和税务制度。系统应保存发票与订单、内部结算、供应商账单和调整记录的对应关系。

## 十三、会计和NC承接

本例至少会形成以下会计事项：

### A公司

- 客户应收确认；
- 客户收款及应收核销；
- 对B公司的内部应付确认；
- 向B公司付款及内部应付核销；
- 符合收入确认条件后的客户收入；
- 对应的内部采购成本；
- 客户销项发票和B公司进项发票事项。

### B公司

- 对A公司的内部应收确认；
- 收到A公司款项及内部应收核销；
- 对外供应商成本和应付；
- 向供应商付款及应付核销；
- 对A公司的内部销售收入；
- 240元采购折让或返佣事项；
- 内部销项发票和供应商进项发票事项。

每家公司分别向自己的NC账套推送，保存NC凭证号。集团层面再依据内部交易关联号核对并抵销A公司的内部成本与B公司的内部收入。

## 十四、最终核对等式

本例结束时至少应满足：

```text
A公司客户应收10,000 - 客户收款核销10,000 = 0
A公司内部应付8,000 - 向B公司付款8,000 = 0
B公司内部应收8,000 - 收到A公司款8,000 = 0
B公司供应商应付7,760 - 向供应商付款7,760 = 0
A公司经营结果 = 10,000 - 8,000 = 2,000
B公司经营结果 = 8,000 - 7,760 = 240
集团经营结果 = 2,000 + 240 = 10,000 - 7,760 = 2,240
```

还要完成：

- 客户订单、应收和收款对账；
- A、B公司内部应收应付对账；
- B公司与供应商的账单和付款对账；
- 团期订单、游客和成本对账；
- 发票与交易关系对账；
- 两家公司业务系统会计事项与NC凭证对账；
- 集团内部交易抵销对账。

## 十五、同类业务的常见变化

本例只是多主体链路的基础形态。实际业务还可能变化为：

- 客户款由B公司或集团资金账户代A公司收取；
- A公司只支付净结算价，也可能先支付全款再由B公司返还销售差额；
- 客户使用优惠券，优惠由A公司、B公司、门店或平台分别承担；
- A公司是主要责任方，也可能仅为代理销售方；
- 客户部分退款，但外部供应商只退部分或不退；
- B公司提前向供应商预付，实际成本在回团后确认；
- 同一团期包含多家销售公司的订单；
- A公司和B公司按月汇总对账及清算；
- 业务已经结算或推送NC后发生补充成本和退款。

每一种变化都应在正式场景手册中使用完整数字重新验算，而不是只写一句“处理方式类似”。
