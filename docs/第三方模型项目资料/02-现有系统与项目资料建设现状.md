# 凯撒旅游SaaS现有系统与项目资料建设现状

版本：v1.0  
编写日期：2026年8月24日

## 一、本文用途

本文用于帮助外部阅读者了解项目目前已经建设到什么阶段、现有系统如何组织、现有文档分别解决什么问题。

本文不要求外部模型继承现有文档的表达结构，也不表示现有原型已经完成正式业财规则设计。

## 二、当前建设阶段

当前项目是一套覆盖旅游全业务流程的高保真业务原型，已经形成大量HTML页面、模块入口、列表、详情、抽屉和操作流程。

原型已经能够表达：

- 不同岗位从哪个模块进入；
- 每类业务对象由谁维护；
- 产品、团期、订单、履约和财务之间的入口关系；
- 收款、认款、应收、退款、成本、应付、付款、结算、发票和NC的大体操作方向；
- 跟团、邮轮、专列、自由行、单项、定制、外采和航服等产品差异。

原型的使用边界是：它用于确认业务操作和页面流程，不等同于已经建成生产系统，也不能直接作为数据库、会计规则或NC接口设计。

## 三、现有系统模块

| 模块 | 主要服务对象 | 核心内容 | 向下游交付的结果 |
|---|---|---|---|
| 资源 | 产品、采购 | 景点、酒店、交通、船司、专列、供应商和协议资料 | 可供产品和采购引用的基础资料 |
| 产品中心 | 产品经理、外采人员 | 自营产品、外采产品、线路、单团项目、定价和退改政策 | 可建立团期或销售的产品 |
| 履约中心 | 计调、团控、采购 | 团期、航次、班期、项目团、名单、动态资源、实际成本 | 履约结果、成本依据和结算依据 |
| 销售中心 | 销售顾问、订单客服 | 报价、意向、订单、合同、收款认领和售后申请 | 客户交易、应收来源和履约需求 |
| 门店中心 | 店长、门店运营 | 门店、成员、预存、经营和门店对账 | 门店订单及门店结算依据 |
| 渠道中心 | 渠道运营 | 分销商、OTA、佣金、订单台账和渠道对账 | 渠道结算依据 |
| 营销中心 | 营销运营 | 活动、优惠券、小程序页面和营销素材 | 订单营销权益及优惠来源 |
| 客户 | 销售、客户运营 | 散客、企业客户和会员规则 | 报价、合同和订单客户资料 |
| 财务 | 财务各岗位 | 到账、认款、应收、预收、预存、退款、账单、应付、付款、结算、发票、资金、NC和关账 | 有效财务单据、会计事项和NC结果 |
| 审批 | 业务及财务审批人 | 改价、退款、付款和调整等审批 | 原业务事项生效或驳回 |
| 系统设置 | 管理员 | 组织、人员、权限、参数和通知 | 全系统基础配置 |

## 四、当前已经梳理的业务流程文档

项目已经按岗位和业务板块形成以下流程确认稿：

| 文档方向 | 覆盖范围 |
|---|---|
| 销售流程 | 报价、订单、合同、收款入口和售后发起 |
| 产品计调流程 | 产品、团期、名单、资源确认、出团、回团和成本依据 |
| 外采产品流程 | 内外部产品引入、代理包装、销售承接和采购结算 |
| 体系外供应商流程 | 供应商准入、产品供给、订单确认、账单和付款状态 |
| 加盟门市流程 | 门店销售、预存、收款、退款、对账和分润 |
| 邮轮流程 | 船司、航次、舱型、包舱、名单、履约和航次结算 |
| 航服机票流程 | 散客票、团队票、切位、包机、出票、退改、BSP和内部供票 |
| 财务收款流程 | 到账、认款、应收、预收、预存、退款和转款 |
| 财务应付流程 | 成本、供应商账单、应付、预付、付款和回单 |
| 财务结算流程 | 团期、项目、门店、渠道、发票、NC和关账 |

这些文档适合让各岗位确认自己的工作流程，但它们分别从模块或岗位出发，不能单独替代财务需要的全场景验算手册。

## 五、当前已经形成的业财设计底座

项目已经进一步形成七份业财底座材料：

| 编号 | 文档主题 | 已解决的核心内容 |
|---|---|---|
| 01 | 多主体交易关系与核算责任 | 区分法人、门店、经营单元及销售、履约、收付款等责任 |
| 02 | 全业务场景财务数据链路矩阵 | 汇总86个基础场景及其应收、应付、结算、NC和对账影响 |
| 03 | 财务业务对象与数据关系 | 区分订单、应收、收款、成本、应付、付款、结算和发票等对象 |
| 04 | 会计事项与NC凭证规则 | 说明业务事项如何进入会计处理和NC |
| 05 | 对账、关账与异常控制 | 说明日常对账、月末关账和异常处理要求 |
| 06 | 跨文档一致性复核与缺口审计 | 对已有设计进行相互校验 |
| 07 | 逐场景财务链路开发承接 | 将主体、单据、余额、结算、会计、NC和对账串联 |

这七份材料主要建立底层规则，适合作为财务和技术设计依据，但表达方式仍偏规则、对象和场景矩阵。

## 六、当前场景确认手册

项目已经形成：

- 《业财场景确认手册00-编写规范与内容标准》；
- 《业财场景确认手册01-场景目录模板与首批案例》；
- 《业财场景确认手册02-订单收款与多主体结算深化案例》。

其中首批手册以35个端到端案例承接86个基础场景，覆盖客户直接购买、门店、OTA、供应商、专项产品、外采、集团内部多主体、售后、结算、NC和关账。

深化案例使用“A公司销售B公司向外部供应商采购并包装的产品”说明三段交易关系和多层价格。

这些成果是当前设计基础，但最终面向财务确认的文档仍应进一步改造成以业务主轴和真实发生过程为线索、每个场景都能从头验算到尾的完整手册。

## 七、已有场景覆盖范围

现有场景资料已经涉及：

### 1. 客户订单和收款

- 标准订单、定金尾款、企业账期；
- 一笔款对应多订单、多笔款对应一订单；
- 未认款、错认款、重复款和现金外币；
- 优惠券、积分、补贴、改价和补差；
- 预收、预存、转款和退款。

### 2. 门店和渠道

- 直营门店、内部承包门店、集团内法人门店；
- 加盟门店预存、代收、总部直收、佣金和分润；
- OTA订单、平台佣金、活动补贴、退款和净额打款；
- 外部分销账期和渠道结算。

### 3. 成本、应付和付款

- 实际成本、供应商账单、应付和付款；
- 供应商预付、付款节点、回单和核销；
- 多团期共用成本和固定资源分摊；
- 供应商退款、追款、损耗和争议款。

### 4. 专项产品

- 邮轮包舱和航次结算；
- 专列包铺和班期结算；
- 团队机票、BSP和B2B平台充值；
- 自由行采购批次；
- 单项服务、代收代付；
- 研学、MICE及定制项目。

### 5. 多主体和会计承接

- 集团内部产品互采；
- A公司销售B公司产品；
- A公司销售B公司外采产品；
- 航服公司向内部旅游公司供票；
- 集中代收代付；
- 同一法人跨部门经营分配；
- 主责方全额确认与代理方净额确认；
- 内部应收应付、内部开票、NC和合并对账。

### 6. 结算和关账

- 团期、项目、门店、渠道和供应商结算；
- 结算后补充、冲销和跨期调整；
- 同一往来单位应收应付抵销；
- NC失败、重推、重复推送和业务账与总账对账。

## 八、现有成果的正确使用方式

外部模型应将现有成果理解为三层材料：

```text
第一层：系统原型
说明岗位怎样操作、页面怎样承接

第二层：业财底座
说明主体、单据、余额、核销、结算和会计的基础规则

第三层：场景确认手册
尝试把规则放回实际业务故事进行金额验算
```

外部模型后续要做的工作，不是重新罗列页面，也不是简单复制86个场景，而是基于上述基础重新设计一套财务可以逐案确认、技术可以据此实现的场景化表达。
