### 当前操作顺序

1. **销售立项、建立大项目并分配费用额度。** 总预算和操作人员额度都是支出管理资料，不能直接作为订单价格。框架合同按原合同区关联，不因关联合同自动生成订单。
2. **在项目详情“项目团 → 新增项目团”登记服务。** 默认“尚未谈妥，先筹备子团”，保存后只有草稿子团。客户已经线下谈妥时选择“客户已在线下确认，直接创建订单”，在同一抽屉填写成交资料，点击“保存子团并创建订单”。
3. **已有草稿子团谈妥后，从该行“创建订单”办理。** 单团会奖项目团控亦有同对象抽屉入口。确认客户、服务、币种、含税成交价格、收款阶段、客户确认人、日期和依据；这次登记承接线下事实，不发给客户线上审批。订单经办人自动记录，不另设销售确认审批。
4. **一场独立成交一般一团一单；多团整包一份订单。** 项目“订单与合同 → 创建订单”可选择多个未建单子团作为整包覆盖，总价只计一次。高频会议勾选子团后用“批量建单”，逐团填写含税总价，每团产生独立订单。批量默认一期服务款；需要分期或按实际数量计价时逐团办理。已有关联有效订单的服务继续原单，不能重复建单。
5. **创建结果直接展示订单和收款计划。** 可查看原单，也可继续“确认建团”核执行资料，使子团进入进行中。确认建团只推进执行，不再生成订单；在独立订单详情核完价款后，执行入口反查项目团详情。
6. **报价资料可选。** 项目“订单与合同”先显示订单和合同，报价资料折叠保存。保存草稿或登记已报价不产生订单。谈妥后点“按此建单”带入服务、价格和收款约定；已在审批中的旧报价继续原办理，不能另建重复订单。历史报价与审批结果保留。旧报价中的“预计数量”转单仍为待最终定价。
7. **价款明确后按原流程开票、认领到账。** 项目“开票收款”集中查看各原订单与阶段，支持单笔认领和项目范围内多单分配。订单“应收收款”也可进入原认领。示例30000元、订金30%／尾款70%分别为9000／21000元，比例可修改；提交认领不增加已收，原财务认款后才记入对应订单和阶段。
8. **按实际数量计价时，保留同一订单完成最终定价。** 建单登记客户认可的含税单价和预计数量，最终金额及阶段金额显示待确认。客户认可实际数量后，在订单“确认最终价款”中核数量、原单价、依据与阶段金额；例如64人×500元＝32000元，原订单号保持，比例阶段重算为9600／22400元。历史固定金额阶段可以逐项核对。提前到账去原“预收管理”；本轮仅提供原页面入口，不新增预收核销仿真。
9. **执行、采购及结算继续原分工。** 执行详情负责人员、资源、交付与完成；项目采购登记线下采购结果；团期结算维护本团成本并核对收入、承担、税额和结算依据。订单已创建、已开票、已收款、服务完成、结算确认分别表示不同事实，不互相代替。

## 2026-10-24 试用复核：子团、报价、订单与收款如何衔接（仅分析）

用户进一步指出创建子团后，不清楚报价从哪里来、订单如何生成、团与订单数量关系、价格来源及收款操作。以下按当前代码说明，不代表页面已经调整；供应商询价继续不进入系统，原报价流程不改。

### 当前实际顺序

1. 新增项目团只保存草稿，登记服务日期、地点、人数、负责人、费用预算和客户预计金额。费用预算属于支出计划，客户预计金额也不是成交价格；不自动生成报价或订单。
2. 销售或负责报价的操作人员从项目详情“报价与合同→客户报价→新增报价”，选择本次覆盖的子团，录入客户报价。单团入口可带入本团资料；批量报价是一团一份报价，不能与整包报价混用。
3. 原报价抽屉填写含税固定总价，或确定数量×含税单价、包含服务及收款阶段。保存报价草稿和登记已报价均不生成订单。客户线下确认后登记本版本的客户确认资料；不需要待办审批时确认生成订单，需要审批时批准后生成。重复确认同一报价不会再次创建订单；符合条件的已有订单可关联。
4. 订单继承报价的客户、公司、币种、金额、覆盖团、收款阶段及来源版本。原报价列表／详情有“查看订单”，项目“开票收款”列示该单。之后“确认建团”引用有效报价／订单，使草稿团进入执行，不再生成订单。
5. 客户到账由原收款流程登记；销售在项目“开票收款”或订单“应收收款”选择到账流水、订单和阶段提交认领，财务确认认款后才增加已认款。发票、到账和认款是不同结果，开票不是已收款的前提。

### 团与订单、价格及收款的边界

| 场景 | 应如何理解及当前承接 |
| --- | --- |
| 每场独立确认价款 | 常规采用一子团一份有效报价一笔原订单；例如60人×500元，确定价款为30000元，订金30%为9000元、尾款为21000元。比例仅为说明算例，不是统一收款政策 |
| 多团整包成交 | 一份报价选择多个团，确认后只生成一笔整包订单；各团引用同一单，不能逐团重复计入整包总价 |
| 年框上限与人员额度 | 500万元年框上限、操作50万元费用额度都不直接生成订单；具体订单仍来自客户确认的服务价款 |
| 同一团后续加减价 | 原已建团要求从原订单办理改价；不能为同一服务重复生成新订单。当前逐份报价只按报价本身防重复，草稿团不同报价间的服务覆盖防重仍需明确 |
| 按实际数量计价 | 当前可形成金额待确认订单；最终数量和价款办理尚未完整，普通订单增减价不能把未知原金额视为0代替最终定价 |
| 客户合并付款 | 既有认领支持相容订单分配；项目页行内收款认领只处理选定订单，集中分配需原收款认领页，项目页承接不够清楚 |
| 未有订单／未定价先收款 | 当前项目认领需要金额明确的订单；原财务已有预收管理，但项目页未把先收项目预付款、以后分配到订单的路径表达清楚，不能假建成交单 |

## 业务口径

- 大项目是客户、合同、销售、项目组和总预算的归集对象；项目团是具体一场会议或一条执行线路。当前订单来自线下成交登记，报价准备可选；框架上限不生成收入，原报价已生成的订单继续沿原单办理。
- “会议专票团”是业务办理模式：突出含税录入和票面税额／预计可扣税额，开票申请默认专票。具体可开项目与税率引用原财务配置；实际可扣税额仍独立核定。
- 人员的负责业务金额用于原报价范围；费用预算用于支出计划。预算不足直接提示差额，不在未确认政策下增加新的审批或硬拦截。
- 项目汇总按原订单及原采购各计一次，子团仅计已明确承担；项目共同费用和未分配费用分别列示。结算确认记录与当前测算分开。
- 页面中的OA回传、OCR与发票结果注明演示，不宣称接入真实服务或实际发送通知。

## 验收与交付

已完成本轮主线原型实施。用户随后补充的“大项目容器、操作额度、子团独立办理与双向汇总”纳入本次范围；原项目详情在有效结构上补“项目总览”和“开票收款”，当前为六页签。

### 页面操作顺序

1. **单团会奖 → 单团项目 → 新建项目。** 登记客户类型、项目分类、组织方式、默认建团模式、费用总预算和项目组。可直接用默认演示资料提交核对；保存后进入本项目，顶部“核对立项”完成启用。立项本身不生成子团或订单。
2. **项目详情 → 订单与合同 → 关联OA合同。** 选择同客户、同公司的已盖章回传版本。未盖章版本提示继续在OA办理；同一版本不重复关联。合同出现在原框架合同区域，查看回传版本及依据，不额外发起ERP审批。500万上限只约束合同范围，不算已成交收入。
3. **项目详情 → 项目总览 → 分配费用额度。** 在一个抽屉内录入总预算、各操作额度、负责事项及提醒经理；实时显示已分配和项目保留。分配合计不能超过总预算。费用额度与原“负责业务金额”分别保存，原报价限制不改。
4. **项目详情 → 项目团 → 新增项目团／批量建团。** 记录目的地、日期、人数、操作、预算及服务。继承会议或旅游模式；单团可调整。批量保留手动、日期规则和导入，导入默认有可核对资料，下载模板仅含表头。单次新增可选择先筹备，或客户已谈妥时同时创建订单；已有草稿从“创建订单”或“批量建单”登记成交，再“确认建团”进入执行。报价准备可选，执行详情仍为原八页签。
5. **单团会奖 → 项目采购 → 新增采购。** 供应商询价、议价在系统外完成。直接登记采购结果：供应商、服务内容、项目／子团归属、含税金额、税率、付款条件及确认依据，报价单或确认单作为采购附件。保存明细为待确认，点击确认费用后成为已确认费用；按单团、跨团或项目整体范围维护承担。费用分配及团期结算继续引用同一原采购。
6. **原成本抽屉 → 成本税费测算／供应商票据。** 录入含税金额、税率和预计可扣方式。可以上传票据，也可直接演练默认识别字段；没有上传时明确显示“演示、未上传”。一致、税率差异、识别失败和多税率样例沿原识别核对处理。覆盖整笔费用时采用已核对票面税率，重算预计税额；不改变含税采购总额，不自动填财务核定税额。
7. **项目详情 → 开票收款。** 按原订单查看金额、已认款、待收、已开票和可申请；直接使用原开票申请及收款认领抽屉。订单确认、申请、财务结果分开表达。已开具记录可查看PDF样例和登记客户交付记录；本地文件环境另窗预览PDF，HTTP环境保留原下载。原型不会发送真实邮件。
8. **项目团详情 → 确认完成；原客户对账 → 登记认可；团期结算 → 结算。** 完成事实、客户认可、采购确认分别保留。原十页签核收入、费用承担、预计／核定税额、依据和记录，保存草稿或提交。项目详情“费用总览”汇总各团进度，财务后续总体确认本轮不扩展。

### 父子团汇总与预算计算

- 项目总览展示总预算、已分配操作额度、项目保留、总合同及子团完成数量；逐团展示目的地、人数、操作、订单金额和承担费用，可反查执行详情与结算详情。
- 操作人员可用费用额度＝人员费用额度－各团占用之和；单团占用取本团预算与已确认承担费用的较大值，避免预算和实际采购重复扣减。
- 没有明确预算或成本分配时，可用额度保持待确认。超额显示差额；本轮不制定跨公司、跨币种、超额审批或硬拦截制度。集中分配办理CNY，已有外币分工仍从原项目分工维护，不同币种不直接相加。
- 父项目金额按原订单、原采购各计一次；子团按明确归属核对。整包订单未分团时不虚构本团收入；项目承担与未分配费用由原费用总览／结算明细核对。
- 含税、预计扣税后、核定扣税后三套金额继续区分，未核定不按零处理；开票申请不直接增加已开票金额，收款认领不直接增加财务已认款金额。

### 2026-10-24 试用问答：项目采购的询价去向（仅核对，未改页面）

**历史问答：以下描述及建议已由本文件顶部“询价过程不进入系统”纠正覆盖，询价功能现已撤除。**

用户询问新增询价后由谁接收、如何继续及有何作用。本次对照询价脚本、原费用编辑／详情、付款申请、项目额度和结算引用核对，结论如下。

| 环节 | 当前原型实际操作与结果 | 使用人和下游 |
| --- | --- | --- |
| 保存询价 | 保存需求、供应商、操作人员及归属，显示询价中；不会向供应商发送，不会派发资源岗任务 | 操作人员自己继续维护询价记录；当前人员字段是登记信息 |
| 登记供应商报价 | 原询价抽屉保存含税报价、税率、报价依据及附件，显示已报价 | 操作人员决定是否采用；未采用的报价不计确认成本 |
| 采用报价 | 在询价记录点击，打开原新增费用抽屉，带入供应商、服务、日期、金额、税率和附件；仅打开不生成采购 | 操作人员继续核对费用归属、付款条件和采购依据；未确认建团时仅保留询价 |
| 保存／确认费用 | 保存为待确认，确认费用才标记已确认；一条询价至多对应一笔采购 | 项目采购维护同一原费用；团期结算按本团直接费用或分配承担额核对，项目总览按原采购归集 |
| 后续承接 | 原费用详情办理分配、供应商对账及符合条件的付款申请；已确认承担费用参与原人员额度占用计算 | 操作继续维护支出依据，财务承接原款项流程；不自动开票、付款或核定可扣税额 |

当前入口的作用是保留采购前报价依据并减少重复录入；供应商报价属于支出端，不改变客户报价或生成销售订单。已谈妥采购可继续直接使用原“新增采购”，询价不是强制前置。

本次发现的交互缺口：入口叫新增询价但无发送／接收环节；一条记录只有一个供应商，未组织同一需求的多家报价比较；后续采用入口藏在询价记录抽屉；采购保存为待确认后询价即显示已采用，两者阶段未同时表达；采购详情未展示来源询价的反查入口，需求与经办信息也未完整带到采购详情。上述属于当前原型业务表达不足，不能用已通过的采用报价测试宣称询价协同完整。

建议先按操作自行对接供应商的现行业务收敛为“询价登记→登记供应商报价→转采购→确认费用”，在原采购页清楚区分询价与采购、展示对应采购及确认状态、补原询价反查。多人分派及供应商线上回报不在此次已完成范围，不为回答疑问直接扩大实施。本次仅核代码与文档，无新增浏览器验收；下一步结合用户试用反馈明确本页调整范围。
