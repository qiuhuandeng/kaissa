## 一、先确定销售要完成的工作

主要角色是商户内部销售顾问、直营门店店员、电销顾问，以及获得相应授权的加盟店员。普通销售处理本人客户、意向、订单、合同和售后申请；主管、店长及外部分销商是需要分别确定权限的使用身份。

上游是客户咨询、分配线索、老客复购及产品岗位发布的可售产品、日期、规格和规则。销售负责需求判断、推荐、成交资料、订单办理和客户服务；计调确认资源与安排，业务审批人审批价格等业务变更，合同岗位承接签约规则与异常，财务核实到账并执行退转款。销售需要随时看到申请到了哪个岗位、缺什么资料以及返回结果。

销售每天的手机场景可归为四类：接到咨询时迅速回答和推荐；客户决定购买时及时预订并让客户完成必要动作；离开电脑后继续处理到期事项和退回材料；出行前后解释进展并发起必要变更。

主流程：推广或接待 → 记录需求／直接选产品 → 客户确认购买内容 → 预订 → 收款、合同和资料按本单条件并行 → 出行服务 → 售后与再次出行。明确产品的客户可以直接预订；模糊需求进入意向；企业定制由销售整理需求和附件，已确认方案按单团项目流程提交，不默认在手机端建设完整供应商询报价。

## 二、从现有功能到手机能力的逐项对照

“现有”仅表示本次源码和业务文档能定位到能力，不表示正式接口已上线或本次完成浏览器验收。手机能力均为本次设计建议。

| 业务要求 | merchant现有依据 | 手机功能与入口建议 | 结果／责任边界 | 后续验收方式 |
|---|---|---|---|---|
| 在授权范围办理本人业务 | 工作台sales角色、组织与门店归属；本人客户和订单范围 | 登录后带公司、门店与身份；兼任岗位时按授权切换；账号入口放工作台 | 不因可见后台菜单而获得全部数据、内部结算价或财务权限 | 不同顾问不串客户，切换范围后重验可售和可办理对象 |
| 随时知道当前要处理什么 | 销售工作台、意向回访、订单与审批结果 | 工作台列回访到期、保留临期、尾款到期、认款退回、签约未完、资料缺口和申请退回；继续草稿 | 点入原事项；消息已读不算业务完成 | 退回项能打开原申请，完成项退出待处理，临期按本单日期判断 |
| 给客户准确推荐产品 | 产品预订、团期／日期规格与退改资料 | 产品页按出发地、目的地、日期、预算、品类及余位筛选；详情先看具体日期价格和可订条件 | 起价、参考报价与所选规格金额分别表达；资源二次确认有明确提示 | 售罄不可订，报价与日期规格对应；邮轮、专列等不套统一人数价格 |
| 将可卖产品带到客户沟通中 | 产品预订；营销素材中心有推广海报与分销素材；发券中心有活动权益 | 在产品和已授权素材中制作产品卡、行程、报价或海报并分享；显示顾问联系方式，客户可咨询或留需求 | 对客内容使用公开或授权对客价；分享记录保留销售与渠道来源，最终归属按规则确认 | 客户看不到内部价格，过期团期有提示，分享来源与最终订单来源可核对 |
| 新客、模糊需求与老客可持续跟进 | 客户档案、同行游客、历史订单、意向订单、电销意向 | 客户页快速登记查重、记录本次需求及跟进、设置回访、复用同行人；意向与客户档案分别组织 | 同一客户多次出行保留各自需求，进入预订不提前算成交 | 日期待定可记录；取消预订后意向不变成已成交；同客不同需求不覆盖 |
| 客户确定后可以现场完成预订 | booking、订单主状态、价格与付款条件 | 产品选日期规格后预订；选客户、人数、附加服务及合法优惠；核费用与付款计划；保存草稿、预留／占位／待确认／确认按条件开放 | 本人销售归属默认带入；未定时限、定金比例等保留待确认 | 无位阻断；草稿不占资源；条件未明不直接确认；多人草稿分别保留 |
| 客户付款后有明确结果 | 订单收款及payment-claim；培训包含订单付款码／链接、转账与现金登记 | 从订单生成或展示本单允许的付款入口；销售核金额和收款公司，游客付款；转账上传凭证并认领；查看待复核、已确认及退回 | 游客支付与销售登记认款分开；到账确认由支付结果或财务规则承接 | 付款中不显示成功；凭证不当实收；待确认订单真实订金按预收承接 |
| 客户可以完成签约与资料补充 | 合同管理及共享流程；游客资料、签证与行程附件 | 销售核合同、签署人和附件并发起办理；游客入口签署；资料支持销售拍照上传，建议提供本单游客资料采集入口 | 游客输入待销售核对；资料齐不等于审核通过；销售不替游客签署 | 多人未签齐不记全单完成；错误证件退回可补；合同模板符合业务 |
| 销售可以解释和申请出行安排 | 订单详情游客签证、履约承接、服务变更共享规则 | 原订单查看已确认交通酒店、签证办理结果及已发布出团资料；申请联运、升舱、增减服务 | 服务由计调确认，涉及价格经业务审批；免费服务同样保留正式申请 | 未发布文件不可冒充已发布；计调拒绝后不显示已安排；改价批准前原金额不变 |
| 客户变化时能在原单继续办理 | 订单详情及售后处理、改期／退订／退款／转款 | 原订单选择涉及游客和服务、目标日期、原款及客户依据；提交、撤回、退回补充与结果查询 | 资源扣损由计调核，退款转款由财务执行 | 部分游客不影响其他人；不超原款可处理额；业务批准不显示钱已退 |
| 本人业务和申请可查看 | 销售工作台及我发起的审批；报表日期与归属规则 | 工作台提供本人订单、收款与出行数量的轻量查看；申请集中查进度，处理回原事项 | 标明统计期间与依据，提成奖金待正式考核规则；主管数据另外授权 | 非本期数据不计本期，实收不与订单额混用，普通销售看不到全店数据 |

开票资料采集与进度查询、产品收藏、常用素材、批量名单上传等可作为后续效率增强。创建营销活动、设置券规则、维护产品价格、调拨库存、采购资源、财务付款、公司间对账等继续由对应岗位在后台处理。

## 三、独立判断后的信息架构建议

建议先采用四个主入口：**工作台、产品、客户、订单**。

- 工作台：安排当天工作、接收到期与退回事项、继续草稿、查看本人业务；消息、我的申请和账号从这里进入。
- 产品：找可卖产品、看日期价格与余位、制作对客内容、预订。推广素材可作为此处的辅助入口，销售使用已发布内容。
- 客户：客户档案、意向与跟进、同行人和历史订单。新客接待和已知客户复购从这里开始。
- 订单：查单及成交后办理。关键金额、状态和缺口先呈现，再按需要进入收款、合同、资料、出行及售后，不把后台全量表格搬上手机。

四入口是根据任务频率提出的待评审建议，不是受既有页面数量约束。支付、签约、资料等围绕当前订单组织；主管专用能力按角色出现。AI先放在客户需求整理、产品比较、报价说明和订单解释等具体任务中；依据使用频率再判断是否需要独立一级入口。AI生成定制路线不是标准成交路径的前置条件。

## 四、销售与游客需要分别有操作入口

手机端的价值包括销售和客户之间的资料交接。销售端之外，建议提供与本次产品或订单关联的游客轻页面：

1. 看产品、行程和报价，联系对应顾问或提交咨询。
2. 查看本单付款金额与收款公司，完成允许的支付。
3. 填写本人的必要出行资料，查看需要补充的材料。
4. 以正确签署人身份查看并签合同。
5. 查看已发布出团通知和必要出行资料。

游客使用自己的入口与身份，不能打开销售工作台。下单首版优先销售代客办理，游客自助下单是否开放另定；不能仅因有分享功能就默认建设完整游客商城。销售提交后应能查看上述动作的进度与结果。

这些是业务与原型设计范围，正式微信分享、登录、支付、合同平台和资料服务需后续接入；本次没有实施接口。

## 五、用户提出的B2B分销功能如何归属

授权产品、分享推广、下单、付款承接、合同和订单来源是两类销售场景可复用的能力。外部分销商登录、机构内人员权限、供货价或佣金、分销对账及结算属于分销身份的专项范围，不能直接等同merchant普通销售顾问的权限。

| 用户列出的能力 | 内部销售小程序 | 外部分销商使用时补充 |
|---|---|---|
| 登录 | 员工及公司／门店授权 | 合作机构与经办账号、负责人权限、停用／到期控制 |
| 授权在售产品 | 本人可售产品及日期价格 | 机构授权、价格和可售范围 |
| 分享与营销 | 带顾问联系与来源的对客产品／素材 | 同时保留分销机构及经办来源；来源冲突规则待确认 |
| 下单与支付 | 销售代订、游客付款或销售认款 | 区分游客团款和分销采购货款，按合作约定开放现结／预存／账期 |
| 合同 | 销售发起、正确签约公司与游客签署 | 按合作方式确定由谁与游客签约；合作协议与游客合同分开 |
| 订单与结算 | 本人订单、销售来源、收款与售后结果 | 本机构订单、货款或佣金、对账异议及结算结果；资金执行归财务 |

是否把两类身份放在同一个小程序是待确定范围。本次不直接纳入外部分销，也不否定该用途。先定服务人群，再定机构登录、价格、收款签约和结算权限；采购转售和佣金代理不能默认采用同一套金额规则。

## 六、优先级和下一步

首版应让普通销售完成四个完整场景：客户问产品时能查到并分享；客户决定后能预订并交客户付款／签署／补资料；销售能持续处理原单缺口与退回；客户变更时能发起售后并查结果。普通参团游可作为首个代表业务，产品结构为其他品类保留各自规格，不宣称首版已覆盖全部业务。

后续再补个人经营查看、开票需求及效率功能，以及企业项目、邮轮、专列、自由行和单项服务的特殊流程；主管和外部分销按确定的角色范围单独补齐。AI按具体场景逐步加入。

页面清单与流程细化见[页面设计](销售移动小程序页面与操作流程设计-20260928.md)。2026-09-28已执行首条国内成人参团游原型，独立入口为 `sales/index.html`；推荐咨询、预订及游客付款／签署／资料和销售查结果的证据见[实施验收](销售移动小程序首条业务原型实施验收-20260928.md)。唯一下一步为S15服务与金额变更，之后接S16售后；原方案其他品类、外部分销及未定政策仍保留原边界。
