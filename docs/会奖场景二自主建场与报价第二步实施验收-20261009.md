# 会奖场景二自主建场与报价：第二步实施验收

日期：2026-10-09。依据用户“执行”及[七大痛点复核](会奖七大痛点业务复核与产品判断-20261009.md)第七节第2步。本次仅补项目分工、自主建场、允许范围报价和批量日常操作；税费测算与连续款票申请留在第3步，正式员工任职衔接、汇率和完整双维输出留在第4步。原财务8批／36项／6场景保持已收尾，单次／多场建档撤回决定保持。

## 1 本次产品判断与职责

上游是销售建立的客户项目、框架合同和员工已有任职；项目负责人先登记谁负责哪些城市、服务期间及事项，操作人员即可在还没有活动时接手。下游仍是原客户约定、订单、审批、活动执行与结算，不能把“委派预算”当成交，也不能由项目分工直接授予付款或财务核定权限。

保留每场活动的日期、负责人及业务记录，减少销售逐场录入和重复填写，而不是将100场会务压成一个无法独立核对的大团。不新增会奖一级菜单，不再增加详情之后的中转页；本次都在现有项目、项目团和标准抽屉内办理。

| 金额名称 | 本次用途 | 不能代表什么 |
|---|---|---|
| 框架约定金额 | 按合同登记上限／预估／客户承诺／待确认；有明确上限时，确认与审批中金额累计核对 | 不是同额订单、应收或收入；预估不能自动当硬上限 |
| 负责业务金额 | 默认计划参考；确有已批准规则才选择超出须审批或不得超出，可加单笔上限 | 不自动定义公司的正式授权制度，不替代岗位报价权限 |
| 费用预算参考 | 项目人员及活动的费用计划，独立填写 | 不当对客报价上限、已确认成本或可付款金额 |
| 报价中金额 | 草稿／已报价记录单独展示 | 不计成交，不占框架确认金额 |
| 已确认／审批中金额 | 分开显示；框架上限和已批准的人员限制同时考虑审批中申请 | 审批中不是成交；不把跨人员包价平均分配 |

不同币种分别核对，不在本步添加虚构换算。金额尚未确定时，不按零元放行硬限制。正式业务的金额性质、授权、审批条件及例外制度仍待业务／财务确认；页面中的测试规则只是明确标注的样例。

## 2 菜单与页面怎样操作

### 单团项目 → 详情 → 活动安排

新增“项目分工”区域及“新增分工／维护／结束”操作，位于活动列表之前。即使活动数为0也能登记。

填写操作人员、负责事项、服务期间、负责城市、服务类型，以及是否可以自主建场。报价办理范围分为“不办理报价”“准备报价，交销售确认”“报价及客户确认”。系统同时检查该员工已有的计调及报价岗位权限；缺少岗位权限时，选择项目报价范围不能绕过限制。

人员金额与费用预算分开；默认“计划参考”。选择“超出须审批／不得超出”时必须填写有效金额限制和已批准的规则依据，否则不保存。维护分工不重写原活动负责人及历史金额。结束分工要填原因及未完活动安排；原活动保留，可继续按原负责人执行或另行移交，但不能继续依原分工新增或报价。

活动列表原新增、批量导入、分配和移交保留，并增加“批量维护／批量报价”。先选择活动，可跨分页选中当前筛选的全部活动，再进入相应抽屉。

### 履约中心 → 项目团 → 负责项目

增加“项目团／负责项目”两个页签。“负责项目”显示项目、客户、主状态、服务期间、本人负责事项、活动数量、业务金额使用情况及新增／批量／活动入口；即使尚无活动，只要已有分工也能进入。分工已结束但仍有本人活动的项目保留查看入口，新增不可用。

“新增”打开当前项目活动抽屉；本人自动作为主责计调且不可更换，单一服务类型和城市自动带入，服务范围带入负责事项。日期、城市、服务类型超出分工时在当前表单指出原因。草稿允许未定信息，进入执行仍遵循原活动确认条件。

“批量”直接打开原批量录入抽屉。CSV中的计调留空时带入本人；不能借表格将活动建给其他人。重复客户场次号、错误日期和超范围逐行指出；只有主动选择“仅保存N个有效草稿”才保存有效行，错误行不会静默通过。框架不限制活动数量，第101场仍可在同一项目继续建立。

“活动”查看当前项目活动。计调按本人范围查看，工具区提供新增、批量录入、批量维护和批量报价；详情仍进原项目团详情，不另建工作区。

### 项目团详情 → 客户款项

新增“本场报价与客户约定”区域，查看本场报价版本与状态，点击“新增报价／办理”在原位打开“报价与客户确认”抽屉。项目、客户和本场活动自动带入，只有一个有效框架时自动选中。

- 保存报价草稿：允许整理资料，不形成订单。
- 登记已报价：核对服务内容、活动覆盖和有效价格。表示业务已经对客报价，不自动发送文件或通知客户。
- 查看报价：可下载本版HTML报价文件。用户自行发送，原型不声称已邮件送达。
- 修改已报价的价格、服务范围等：保留旧版摘要并升版；只补客户确认事实不无故升版。
- 确认客户约定：校验客户确认人、日期、依据、收款安排、有效框架和金额范围。外部批准必须对应本版本，提交业务审批则先进入待审批；只有确认或审批通过后才承接一个原订单。

只有准备报价范围的员工不能代替销售确认。审批时再次核对分工和金额限制，授权缩小或结束后不可直接批准旧申请；可退回，重新核对后按当前版本提交。真正的收款核定、发票处理及付款仍归原财务页面，本步没有扩展为完整询报价系统。

### 批量维护与批量逐场报价

批量维护可统一补开始／结束日期、城市、费用预算，也能逐行修改服务及人数；默认仅补空字段。已进入执行的活动不被批量草稿维护覆盖。预检后改值必须重新预检，取消未保存内容有确认。

批量逐场报价适用于每场分别成交的会议：填写公共币种、框架、金额、服务内容和必要客户确认资料，再逐行补客户参考号、价格及单场依据。可保存草稿，也可登记客户已经确认的报价。确认分支才检查客户依据、款项期限和审核规则。

预检逐场核对范围、金额、已有约定及累计限制；同一批中前两笔已使用的额度会影响后续行，不能每行都拿同一余额重复通过。已有约定的活动提示继续原记录，避免重复创建；整体包价仍在原客户约定覆盖多个活动，不被批量拆成100个订单。修改／取消后页面保留原对象，保存前重新校验有效行与金额。

### 单团项目 → 客户约定；审批中心

框架列表增加已确认、审批中及上限余额／约定差额。草稿不扣确认余额；框架是预估或客户承诺时不把差额当硬限制。

原桌面和手机审批沿用同一份项目分工与金额规则。本次没有新增审批菜单，不改变结算、付款等审批来源；报价申请退回后保留依据和原版本记录。

## 5 仍未完成的后续需求

第2步只完成场景二的前段日常工作流。费用、分场结算和原订单款票继续使用前一步及既有能力，不能据此宣布七大痛点全部解决。没有真实任务通知、正式任职授权或外部开票服务；它们也不应被伪装成已经接通的功能。人员费用预算目前是参考，不在本步建立另一套付款额度系统。

唯一下一步为复核报告第3步：收入与成本税费测算、票面识别冲突的原型表达、预估与核定区分、本场连续款票申请，以及财务开票状态和PDF样例。开始时依次阅读业财六份必读入口、复核报告、本报告和更新后的P02／P03／P04、F02—F06，再围绕第3步对应页面实施及验收；不重做第1／2步，不将待确认税务政策写成既定规则。
