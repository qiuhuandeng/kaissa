# 门店分润新增与验收

2026-09-15｜用户明确指定新增经营分析下的门店分润只读报表

## 一、角色与业务边界

渠道财务、门店结算财务及授权渠道负责人查看公司与门店的分润计算、结付和调整。上游是分润规则、订单业务金额、费用承担、分润确认、实际结付和调整记录；报表供分析核对，不发起分润、审批、抵扣或付款，不改变并行门店办理线。

附件A1表2第47行要求公司/门店分润汇总与明细输出；现有渠道贡献衡量经营结果，不能替代可结算分润。源佣金规则页有10%/8%留存示例；加盟业务文档还讨论实收减结算价等方案。两者不是已批准的统一财务政策，本页不直接套用其百分比。

本次页面使用独立规则和分润算例，明确标示示例数据、正式规则及权限尚未接入。每笔示例都有适用公司、门店、期间及确认依据；该算例中的“已确认”不代表真实财务批准。

**数据中心 → 经营分析 → 门店分润**，新增第17个直接入口。现共93个日常Tab。

## 四、计算及来源边界

1. 独立算例使用业务收入减业务成本作为毛利起点，并按给定规则排除升舱净额及共同费用。它不是“所有业务都按该公式分润”的财务政策。
2. 汇总的已确认金额只统计已有确认的范围；没有已确认记录时该子集合为0，不表示待确认分润为0。送审金额缺失时待确认合计未知，不按比例猜测。
3. 原计算基础、原确认分润与调整后已确认基础/分润区分；未确认调整只展示，不能变更当前应付。结算执行原币分开，成功抵扣不等于现金支付。
4. 待结算＝应付减有效结付的正差额；负差额单列待追回。零、缺数、支付失败、到期日缺失分别呈现。
5. 同公司币种、同确认号匹配结付与调整；无法匹配保留问题。实际生产仍需完整来源范围及授权服务验证。
6. 渠道贡献继续读取原费用模型。新增分润引用用于辨认已有费用，不将本报表的预估、应付余额或付款额自动写入渠道成本。尚无费用对应的分润显示尚未承接，不能自动补成本。
7. 本次未建设真实分润计算任务、审批、NC推送或付款接口；不修改门店余额/对账、原佣金规则或并行交付计划。费用、规则、税额和实际结付资料需批准后正式联验。
8. 查看范围选择是权限算例，不能作为生产用户身份认证或授权；UI明确示例。表中不输出手机号、银行账户等敏感字段。
