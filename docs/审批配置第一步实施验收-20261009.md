# 审批配置第一步实施验收（2026-10-09）

## 1. 本次范围与结论

用户指出“安排审批人员”仍只有七项旧职责。本轮实际实施《审批配置业务扩展设计》第1步：审批人员安排、模板配置和试跑、销售签约条件。此前“仅完成设计、页面尚未实施”的记录属于本次实施前历史。

审批配置由集团／公司审批管理员使用，上游是组织任职及业务单据中的公司、部门、渠道、计调和业务事实，下游是审批办理及来源业务。配置人员安排不代表发起业务审批；内部审批不代表供应商确认、实际开票、付款或合同签署。

本次已修改三个现有页面及直接共享脚本，无新增菜单。配置和试跑已验收；日常业务单据采用新配置及外部供应商确认的实际操作仍属于第2步。未修改并行会奖页面，也未恢复已撤回的履约付款页／付款类型／批量拆单。

用户反馈后，“负责范围／按什么范围安排”已改为“审批哪些业务／审批业务范围”。选项使用“本公司全部业务、指定业务部门的业务、指定产品部门的产品、指定销售渠道的订单”，并给出欧洲部及电商例子。产品部门候选依据现有组织树中的产品中心及产品归属资料，排除门店／门市部／分公司；未维护可选产品部门的公司明确显示资料缺失，不虚构部门。此处维护业务分工，不是审批人员的任职部门。见[修改后截图](evidence/approval-config-20261009/scope-explanation.png)。

新增职责：渠道负责人、渠道总监、产品总监、供应商管理审核、核算会计、财务BP、财务经理、总经理、开票审核人员。原七项保留，合计16项；外部供应商不是内部员工职责。部门经理从申请人的本次任职部门取负责人，计调从业务单据负责人取人。

同公司同职责可以分别安排业务部门、产品部门或渠道人员。相同期间范围冲突、包含下级后的重叠、未生效、过期、停用、缺人、跨公司无授权均不静默通过。公司通用安排只有在节点明确选择或允许回退时使用。调整已有安排须填写原因。

## 5. 原型边界和遗留

1. 审批人员、模板草稿与版本使用本次浏览器会话保存；销售签约条件沿用当前页保存、刷新恢复的原型方式。代码已经写入本地项目，不是只保存在浏览器中的临时修改。
2. 试跑可选择已配置人员，或明确选择“演示人员（不保存安排）”。演示人员只用于本次试跑，不能自动成为公司正式安排。
3. 收款30%、订单10000、实收2000／3000只是检查样例，不写成默认公司制度。分签合同需明确选用订单应收金额还是合同金额；资料缺失不当成0。
4. 收款检查支持生成正式合同／发起签署两种环节，最终采用哪个环节及具体比例由业务确认。免收款例外不免合同首次签约、法务等审批。
5. 实际职责人员、自审处理、开票专员职责、混合支付、跨公司及多团责任继续待确认。当前自审暂停、混合退款不默认进入常规分支、跨公司审批授权不明时暂停。
6. “供应商确认”目前表达后续办理方向，未新增外部供应商入口或伪造供应商同意；来源业务、优惠结果复用、日常在途与重提版本接入留第2步。

## 6. 唯一下一步

第2步“代表事项日常办理”：按已确认设计，将付款、退款、订单结算价变更及合同收款例外的来源提交与审批办理接入已发布配置，核对在途版本、退回重提、外部供应商确认及原业务承接。继续保持来源操作和审批配置的职责边界，不重启并行报表或会奖工作线。
