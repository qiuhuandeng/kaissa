# P02产品市场供给确认方式实施与验收

日期：2026年9月17日。范围：逐页方案P02、核心项核06的产品市场入库环节。核01公司协议成果一并回归；核06的预订、供应商回复、订单处理及售后环节仍待实施。

## 一、业务位置和角色

产品人员从“产品中心 → 外采产品 → 产品市场”选择可代理产品，在现有代理入库抽屉完成经营公司、合作协议、代理安排及供给确认方式。提交审核后交代理产品包装和销售准备；参考余位进入销售时仍需供应商确认，不能作为保证库存。

本次只修改[产品市场](../merchant/product/product-market.html)及对应局部样式，不新增询位中心，不修改预订、供应商端、供应商列表或真实库存服务。

## 二、页面修改

| 页面位置 | 修改结果 |
|---|---|
| 代理入库抽屉“供给确认方式” | 保留沿用提供方、参考余位、置零询位和确认库存四类处理；移除容易把无依据数量直接当可售承诺的“虚拟库存可下单”表达 |
| “销售使用条件” | 根据所选日期和确认方式实时显示“确认库存可直接占用”“参考余位需确认”“先询位后开售”或“待明确” |
| 参考余位 | 选择20位的安排后显示“参考余位20位，订单需供应商确认”，说明数量不是保证库存 |
| 草稿 | 没有可用协议时仍可保存；保留经营公司、确认方式和已选日期，不显示代理已生效 |
| 正式提交 | 继续校验本公司有效协议或已批准内部合作依据；确认方式未知时不能默认已确认。提交后产品详情保留本次销售使用条件 |
| 集团内部产品 | 隐藏外部供应商协议，显示产品提供公司及内部合作单；实际外部采购供应商仍由团期成本维护承接 |

## 三、验收结果

浏览器实际操作通过以下场景，未保存截图或生成图片：

1. 欧洲黄金三角选择第三个团期20位，采用参考余位后显示“订单需供应商确认”；切到置零询位后显示余位按0承接、确认后开售。
2. 北京公司已选协议后切换上海，公司协议清空；上海仅列两份本公司可用协议，不沿用北京协议。
3. 没有协议时保存草稿成功，状态为“入库草稿”；再次打开仍保留参考余位方式、第三个团期及20位结果。
4. 草稿缺协议时提交审核被拦截，抽屉保持打开；补选北京有效协议后进入“入库审核中”，详情保留北京协议和“参考余位20位，订单需供应商确认”。
5. 西藏内部产品不显示外部协议字段，显示内部合作单`INT-BJ-FJ-2026-007`；沿用实时余位时显示确认库存可直接占用，提交后合作依据保留。
6. 页面无运行时脚本错误；内联脚本解析、协议规则检查及差异格式检查通过。

本次只使用页面内一致样例，不做跨页自动取数。P08预订页仍需后续用同类样例表达待供应确认；P13供应商订单、P09订单详情和P10售后仍按核06方案待实施。

## 四、边界

- 参考余位不是保证库存；正式销售前是否收款、签约及确认超时阈值仍待业务确认。
- 确认库存只表达本次已有确认依据的业务结果，不建立生产库存并发服务。
- 保存草稿允许协议或确认条件待补，提交审核不允许缺少适用的公司合作依据。
- 供应商列表继续保持用户要求的回撤状态，本次没有修改。
