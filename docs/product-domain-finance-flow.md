# 产品域与业财流程总模型基线

更新时间：2026-09-06

> **当前状态说明：** 本文是产品与业财链路的目标基线，不代表当前原型已经形成自动承接。产品类型、旅游范围和供应方式以《产品类型矩阵》2026年9月修订为准；订单、实际回团、收入确认、成本结转和NC必须分别形成，不得把结算完成直接等同会计入账。

本文是凯撒旅游 SaaS 产品域与业财流程改造的总基线。后续字段标准、页面改造、导航归属、财务单据和 NC 推送模板，都必须能回到本文定义的业务对象和数据链路。

## 1. 总目标

让凯撒旅游 SaaS 的产品对象、库存对象、订单对象、成本对象、收付对象、结算对象、NC 凭证对象形成一条可追溯的数据链路。

每个页面、字段、按钮和流程必须回答六个问题：

1. 当前页面维护哪个业务对象。
2. 这个对象从哪里来。
3. 这个对象流向哪里。
4. 是否影响库存、订单、成本、收款、付款、退款、结算。
5. 是否触发财务单据。
6. 是否进入 NC 推送或税务台账。

## 2. 产品域总分层

系统产品域分为五条链路：

```text
标准线路：资源 -> 线路 -> 方案 -> 团期 -> 订单 -> 收款/执行/成本 -> 业务结算 -> 收入确认/成本结转 -> 会计事项 -> NC
MICE单团：客户已确认方案 -> 单团项目录入 -> 审核确认 -> 项目团/唯一团期 -> 订单/收款/履约 -> 项目结算 -> 收入确认/成本结转 -> 会计事项 -> NC
自由行：套餐组合 -> 出行日期价格库存 -> 订单 -> 采购批次 -> 服务完成 -> 订单结算 -> 收入确认/成本结转 -> 会计事项 -> NC
单项服务：服务项目 -> 服务单 -> 执行跟进 -> 服务费/代垫拆分 -> 按单结算 -> 收入确认/成本结转 -> 会计事项 -> NC
供应方式叠加：集团内部共享或体系外采购 -> 包装/定价/配额 -> 按原产品类型销售和履约 -> 业务结算 -> 收入总额或净额判断 -> 会计事项 -> NC
```

这五条链路最终都进入统一财务中心，但进入财务前的业务归集对象不同：

| 链路 | 核心业务归集对象 | 库存归集对象 | 订单归集对象 | 结算归集对象 | 收入口径 |
|---|---|---|---|---|---|
| 参团游 | 团期 | 人数名额 | 客户订单 | 团期结算单 | 按履约事实及主要责任方/代理方判断 |
| 邮轮 | 团期 | 舱型/舱位 | 客户订单 | 团期结算单 | 按履约事实及主要责任方/代理方判断 |
| 专列 | 团期 | 车厢/铺位/座位 | 客户订单 | 团期结算单 | 按履约事实及主要责任方/代理方判断 |
| 研学 | 团期 | 学生/班级/导师配置 | 客户订单或学校订单 | 团期结算单 | 按合同和履约事实判断 |
| MICE单团 | 项目/唯一团期 | 项目资源清单 | 项目订单/合同 | 团期/项目结算单 | 按合同、项目阶段和验收事实判断 |
| 自由行 | 订单 + 采购批次 | 出行日期价格库存 | 客户订单 | 订单结算单 | 按履约事实及主要责任方/代理方判断 |
| 单项服务 | 服务单 | 服务能力/办理时效 | 服务单 | 服务单结算 | 服务费为收入，代垫为代收代付 |
| 供应方式叠加 | 原产品类型 | 跟随原产品类型 | 客户订单 | 跟随原产品类型 | 不仅凭外采判断，按主要责任方/代理方确认总额或净额 |

## 3. 标准线路模型

参团游、邮轮、专列、研学统一采用“线路 -> 方案 -> 团期”三层模型。国内、出境、港澳台、入境属于旅游范围，与产品类型分开记录；凯撒自营、集团内部共享、体系外采购属于供应方式。

### 3.1 线路层

线路层是长期稳定的售卖对象，回答“这个产品是什么”。线路层不维护具体出发日期、当期价格和当期库存。

线路层维护：

- 产品名称、产品类型、旅游范围、供应方式、产品提供方、目的地。
- 适合人群或适合年级。
- 产品亮点标签。
- 封面图、详情图、附件文档。
- 发布渠道、上架时间。
- 线路费用规则，包括费用包含、费用不含、自费推荐、儿童/老人或学生/老师费用说明、退改规则。

### 3.2 方案层

方案层是线路下的差异化售卖结构，回答“这条线路如何组织服务”。一条线路可以有多个方案。

方案层维护：

- 参团游：方案名称、行程天数、出发城市、成团规模参考、分日行程、酒店、航线/车型、POI、餐厅、交通配置。
- 邮轮：船公司、船名、船舶信息、舱房售卖、靠港行程、岸上游、登离船交通。
- 专列：承运方、列车号、经停站、车厢/铺位/座位结构、下车游览、地面接驳。
- 研学：教育目标、课程体系、合作基地、合作学校/机构、带队老师要求、导师配置、每日课程、安全预案。

方案层只维护结构，不维护当期销售库存。

### 3.3 团期层

团期层是某个方案在某个出发日期的执行实例，回答“哪一天卖、卖多少钱、还剩多少、谁来执行”。团期不重复录入完整行程，只引用方案并补充当期变化。

团期层维护：

- 关联线路、关联方案、团号。
- 出发日期、回程日期、出发城市/港口/车站。
- 当期最大容量、最小成团人数、预留名额。
- 当期价格、早鸟价、尾期特卖价、渠道差价。
- 可售渠道、开售时间、截止售卖时间。
- 领队、集合地点、集合时间、特别注意事项。

不同产品的库存矩阵不同：

- 参团游：按人数维护成人、儿童占床、儿童不占床、老人、单房差。
- 邮轮：按舱型维护库存和价格，舱型来自方案层。
- 专列：按铺位/座位维护库存和价格，铺位/座位来自方案层。
- 研学：按学生容量、班级数量、带队老师、研学导师配置维护。

## 4. 非标准线路模型

### 4.1 自由行

自由行可以在旅游线路列表中作为类型展示，但底层不进入团期模型。

自由行链路：

```text
套餐配置 -> 出行日期价格库存 -> 订单下单 -> 采购执行 -> 采购批次对账 -> 成本分摊 -> 订单结算
```

自由行核心对象：

- 套餐组合：机票 + 酒店、机票 + 酒店 + 接送机、纯酒店、当地玩乐组合。
- 出行日期价格库存：某套餐在某日期的价格、酒店房量、可售人数、截止时间。
- 采购批次：按出行日期、目的地、套餐类型、供应商归集订单，用于供应商对账。
- 订单结算单：以订单为结算单位，批次成本分摊后核算单订单盈亏。

自由行关键规则：

- 不出现在团期列表，不使用“开排团期”命名。
- 采购批次是成本对账对象，订单是利润核算对象。
- 没有采购批次时，供应商对账和单订单盈亏会断链。

### 4.2 单项服务

单项服务不是线路，不进入“新建线路”。它承接签证代办、机票代订、酒店代订、接送机、保险代购等可售服务。

单项服务链路：

```text
服务项目配置 -> 服务单创建 -> 执行跟进 -> 服务费确认 -> 代垫成本核销 -> 按单结算
```

单项服务核心对象：

- 服务项目：服务名称、材料要求、办理时效、收费方式、默认流程。
- 服务单：客户、服务内容、办理节点、执行责任人、完成时间。
- 服务费：凯撒真实收入。
- 代垫款：代收代付资金，不计入营业收入。
- 服务单结算：按服务单核算服务费收入、直接成本、代垫核销和退款扣损。

单项服务关键规则：

- 主命名使用“单项服务/服务单”，不使用“单项委托”作为主菜单或主对象名称。
- NC 推送时服务费和代垫款必须走不同会计科目。

### 4.3 MICE 单团自组

MICE 和定制团是项目型成团流程，不是标准线路库，也不在系统里走完整询价报价流程。系统承接客户和销售已确认后的项目方案、金额、服务范围和付款节点。

MICE 链路：

```text
单团项目录入 -> 审核确认 -> 生成唯一团期或项目执行单 -> 收款/执行/成本 -> 团期结算
```

MICE 核心对象：

- 单团项目：客户、人数、日期、客户已确认金额、服务范围和付款节点。
- 客户确认材料：客户确认的方案、报价单、邮件、合同附件或内部审批附件。
- 项目/唯一团期：进入执行、成本、结算。
- 团期/项目结算单：以客户确认金额和后续变更单为应收基准，核对实收和实际成本。

MICE 关键规则：

- 财务应收基准来自客户确认金额、合同和项目收款计划，不来自标准团期价格。
- 后续如需要变更金额、人数、日期或服务范围，必须通过项目变更记录或变更单，不直接覆盖原确认金额。

### 4.4 供应方式叠加

集团内部共享和体系外采购不是独立产品类型，而是供应方式。引入产品的结构跟随原产品类型。

外采链路：

```text
来源判断 -> 集团内部共享产品/体系外供应商产品 -> 产品市场引入 -> 代理产品 -> 包装方案 -> 采购价或内部结算价维护 -> 对客价/渠道价 -> 配额确认 -> 销售下单 -> 内部结算或供应商结算
```

外采核心对象：

- 外采来源：集团内部其他主体共享的自营产品，或体系外供应商提交的同行产品。
- 包装产品：采购主体侧重命名、描述、封面、亮点、渠道价，不改变原产品归属主体。
- 供给安排/配额：内部产品归属主体或体系外供应商给定团期、舱型、铺位、日期或服务能力的可售额度。
- 结算：集团内部主体互采进入内部对账和内部往来；体系外供应商外采进入供应商账单、应付和付款。

供应方式关键规则：

- 外采参团游仍按团期结算，外采邮轮仍按舱型结算，外采自由行仍按订单和采购批次结算。
- 结算链路必须按来源拆开：A 销售 B 的产品，A 与 B 做内部结算；B 采购中国国旅等体系外供应商产品，B 与体系外供应商做外部供应商结算；A 销售 B 已包装的 体系外供应商产品时，A-B 和 B-体系外供应商是两条结算链。
- 客户正式收款按实际到账和核销记录承接；收入确认不能由收款金额或“外采”标签直接决定。
- NC需要分别承接正式收款、采购或内部结算、收入确认、成本结转和批准调整；总额或净额由主要责任方/代理方判断。

## 5. 数据流主轴

标准数据流：

```text
资源主数据 -> 线路 -> 方案 -> 团期 -> 客户订单 -> 应收/收款 -> 实际履约 -> 成本确认 -> 业务结算 -> 收入确认/成本结转 -> 会计事项 -> NC推送
```

成本支线：

```text
团期/项目/订单 -> 预估成本 -> 实际成本 -> 成本确认 -> 应付草稿 -> 应付确认 -> 付款申请 -> 付款执行 -> 回单 -> NC推送
```

退款支线：

```text
订单 -> 售后申请 -> 审批 -> 退款执行 -> 应收冲减/预收冲减 -> 退款凭证 -> NC推送
```

发票支线：

```text
订单/收款/结算 -> 销项开票 -> 税务台账 -> NC或税控接口
应付/付款/供应商账单 -> 进项收票 -> 认证状态 -> 税务台账
```

发票是并行业务链路，不固定排在付款执行之后。

## 6. 业财事件基线

每一笔财务单据都必须由业务事件触发，不允许脱离业务对象事后补录。

| 业务事件 | 触发财务动作 | 财务对象 | NC 影响 |
|---|---|---|---|
| 订单确认生效 | 形成应收依据并按规则确认应收 | 应收单/预收记录 | 待收款；是否形成会计事项按财务规则 |
| 正式收款生效 | 用已确认到账核销应收或形成预收 | 收款确认记录 | 形成收款会计事项，校验后推送NC |
| 资金池扣款 | 扣减门店资金池余额 | 收款凭证/资金池流水 | 生成 NC 收款或内部结算凭证 |
| 改价/补差 | 调整应收 | 应收调整单 | 收款后推送 NC |
| 退差 | 冲减应收或生成退款 | 应收冲减/退款单 | 推送红冲或退款凭证 |
| 退款执行完成 | 实际退款 | 退款凭证 | 生成 NC 退款凭证 |
| 回团成本确认 | 确认实际成本 | 成本凭证/应付草稿 | 生成 NC 成本凭证或待结算推送 |
| 应付确认 | 确认供应商应付 | 应付单 | 进入付款申请，不一定立即推送 |
| 付款申请通过 | 准备执行付款 | 付款申请 | 暂不推送 |
| 付款执行完成 | 实际付款 | 付款单/回单 | 生成 NC 付款凭证 |
| 业务结算完成 | 确认业务结算收入、有效成本和业务毛利 | 业务结算单 | 不直接等于会计入账，进入收入成本确认 |
| 收入确认/成本结转 | 按履约、责任和会计期间分别确认 | 收入确认记录/成本结转记录 | 形成会计事项，校验后推送NC |
| 销项开票 | 开票给客户 | 发票台账 | 更新税务台账；不重复确认收入 |
| 进项收票 | 收供应商发票 | 发票台账 | 更新税务台账；不重复确认成本 |

## 7. 模块职责边界

资源模块：

- 维护 POI、酒店、餐厅、车型、航线、锁位、邮轮资源、专列资源、供应商、领队资源。
- 只维护可复用基础资源，不维护某个具体产品的销售结构。

产品中心：

- 维护线路、方案、自由行套餐、单项服务项目、外采包装、团期、定价策略、渠道授权。
- 履约中心承载团期列表、成本付款、团队执行、回团处理。

销售中心：

- 承载线路浏览与报价、报价单、意向订单、订单管理、收款认领、合同管理、售后处理。
- 转团、改签改期、退款申请属于销售中心售后。

财务：

- 承载收款、认款、应收、应付、付款、退款执行、对账结算、发票、回单、资金池、汇率币种、NC 推送、财务报表。
- 退款执行属于财务，退款申请属于订单售后。

审批：

- 承接线路发布、价格调整、渠道授权、成本、付款、退款、折扣、转团、结算等跨模块审批。

渠道中心：

- 承载 OTA、分销商、代理商、佣金规则、同步日志。
- 分销商、代理商不是供应商，不挂到资源模块。

## 8. 状态机基线

标准团期不使用一个字段承载所有状态，应拆成三类状态：

| 状态组 | 状态 | 用途 |
|---|---|---|
| 销售状态 | 筹备中/开放报名/已截止/售罄/已取消 | 决定是否可售和是否占用库存 |
| 执行状态 | 未出团/操作中/已出发/已回团待确认/已确认回团/已归档 | 决定执行资料、名单、通知和实际回团动作 |
| 结算状态 | 未维护成本/预估成本/实际成本确认/结算中/已结算 | 决定成本确认、结算单和财务报表 |

关键触发：

- 开放报名：销售侧可见并可下单。
- 截止报名：锁定名单，不再接受新订单。
- 已回团待确认：记录实际回团事实并进入待确认回团分析，开启实际成本整理。
- 已确认回团：财务或获授权岗位确认回团分析依据，不等于业务结算或会计入账。
- 实际成本确认：进入结算准备范围，不因一个状态直接生成已生效结算结果。
- 已结算：进入已确认业务毛利分析，并继续承接收入确认和成本结转；不直接代表NC已经入账。
- 已取消：触发全团或相关订单退款流程，并处理预付款冲抵或退回。

## 10. 第一阶段验收标准

本文作为第一步基线，验收标准如下：

1. 五条产品链路已经明确。
