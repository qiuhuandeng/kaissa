# 会奖项目原型页面设计讨论

日期：2026-10-08。性质：根据用户两份思考稿开展的设计讨论，包含独立可点击示意，不是现有业务页面实施或财务政策确认。

后续用户已要求结合现有单团给出完整原型方案，当前建议以[基于现有单团的整体改造方案](会奖项目基于现有单团的整体改造方案-20261008.md)为准。本稿与独立示意保留为前序讨论；其中局部下一步及示意验收不替代完整方案的实施范围和验收。

## 一、对两份思考稿的判断

两份稿件值得保留的是：项目统筹多场、批量建场与分配、登记项目组、围绕活动连续办理。第二份已经提出页面内容，但不能直接按其规则实施。“基于确认的四个关键决策”是稿内表述，本轮并没有获得这些决策全部成立的外部证据。

建议将核心定义改为：**项目承接客户委托、整体安排和共同费用；活动承接一场具体交付及其直接费用；合同、客户订单、供应商采购和结算按实际交易关系关联。**

活动不是当然独立的收入确认、开票、付款或财务结算单位。设计原型时应先问用户在办哪件事，再决定本次处理覆盖一场还是多场。

| 稿件设想 | 判断 | 建议写进原型的规则 |
|---|---|---|
| 项目—批次—活动三级 | 不作为默认层级 | 默认项目—活动两级；月份、线路系列、负责人用于分组，不要求先建批次。确有独立负责人、单独委托和结算的一组活动，再评估是否需要子项目 |
| 所有收入成本必须落活动，项目仅汇总 | 不采纳 | 单场直接费用落活动；共同费用保留项目；一份整体包价没有分场约定时，项目保留成交金额，活动不显示虚构的收入或毛利 |
| 九个页签聚合全部业务财务 | 收敛 | 项目详情四个页签，活动详情五个页签；业务提交申请和查看结果，实际财务办理复用统一财务模块 |
| 选中成员自动取得成本、付款权限 | 不采纳 | 分配工作范围与已有岗位权限共同决定可办事项；兼岗无需切换页面，但不因此获得财务执行权 |
| 审批通过金额算已付款 | 必须纠正 | 申请中、已批待付和实际已付分别显示；已付只认财务确认的实际付款结果 |
| 超预算、超申请额度都软提醒 | 分开处理 | 已发生费用如实登记；预算差额按规则审批；超出本次可申请金额不能靠点继续放行 |
| 专票团／普票团决定全部计算 | 不采纳 | 成本、税额、票据、财务确认分开；未到票不等于税率为零，票种不能代替抵扣资格判断 |
| 金额变动超过10%才审批 | 不作为既定规则 | 已确认金额变动沿用现有变更审批；公司阈值待配置，不预设10%、110%等政策 |
| 全部收齐、付完、到票才结算 | 不作为统一前置 | 服务完成、客户确认、供应商对账、资金结清分别表达；允许部分确认和未结事项，不提前宣布财务结清 |
| 结算后审批解锁并修改旧金额 | 不采纳 | 新增调整并保留原结算和对应依据，不能覆盖历史 |

以上关联原[流程稿](会奖项目业务流程与功能流程梳理-20261008.md)的会奖01—14，不新增报表批次。

## 二、先定义“什么时候建一场活动”

1. 一次三天会议，含接机、酒店、会场、宴会和送机：通常建一场活动。这些是同场服务安排，不分别建五个活动。
2. 一个奖励旅游项目同时安排日本、法国等五条独立线路，各自有日期、名单、计调和采购：建五场活动，各自执行，归同一项目。
3. 同一团队在五个城市连续旅行：通常仍是一场活动，城市是行程段，不能见一个城市就拆一场。
4. 一个年度会议项目，每月几十场：每次可独立安排、执行和完成的会议是一场活动；月份按活动日期筛选。一个月合并对客户结算，不意味着把整月会议合成一场。
5. 一场大会有多个分会场或不同航班到达：先在活动内管理日程、分组和到离批次；只有责任、采购与交付确实独立时才拆活动。

“几场以内不用批次”没有业务依据。活动数量影响批量操作能力，不直接决定业务层级。

## 三、原型先画四类页面

沿用现有菜单，不另外新建一套会奖系统。侧重不同角色的两个入口，打开的是同一批项目和活动资料。

| 页面 | 主要角色与最高频任务 | 上游与下游 | 首屏内容及主操作 |
|---|---|---|---|
| ① 单团项目列表，产品中心→自营产品→单团项目 | 销售、项目负责人识别和建立客户项目 | 来自客户已确认需求；进入项目详情安排多场 | 项目名称／编号、客户、执行期间、负责人、活动数量、一个主状态；新建、查看，草稿可编辑，低频复制或关闭进更多 |
| ② 项目详情 | 项目负责人看全项目、批量建场和分配 | 承接合同与委托；向计调交接活动、向财务提供业务依据 | 顶部客户、期间、负责人、主状态；下方四个页签，默认“活动安排”；页内批量建场、分配、查看活动 |
| ③ 项目活动列表，履约中心→团期管控中的项目活动视图 | 计调跨项目查看自己负责的活动 | 来自项目分配；进入同一个活动详情 | 活动、所属项目、日期／城市／人数、计调、一个主状态、可校验缺口；日期／负责人／状态筛选，主操作为查看或当前活动处理 |
| ④ 活动详情 | 计调完成安排、采购费用、申请和交付核对 | 承接项目约定与活动安排；供应商对账、业务结算及财务办理复用现有流程 | 顶部活动识别、所属项目链接、日期地点人数、计调和主状态；五个页签及当前事项处理抽屉 |

项目负责人从②进入④；计调从③直接进入④，不必每次先进项目再找自己的场次。主状态决定稳定的操作名称；材料缺失只用于提示和筛选，不把每一行变成不同的催办按钮。

### 项目详情：四个页签

**活动安排**：活动表格是主要内容，列活动、日期地点人数、负责人、客户约定金额或“整体包价未分场”、一个执行状态、查看。支持按月份、负责人分组或筛选，批量新建、复制活动和批量分配。相同活动可从履约入口查看。

**客户约定**：记录框架合同、具体委托、客户已确认方案与金额、覆盖哪些活动、合同准备／签署／归档结果及收款约定。框架上限、合同承诺、成交金额不能混叫“总预算”。只有框架上限而没有具体委托时，不能自动产生同额成交或应收。沿用本项目“承接已确认方案”的边界，不在这里恢复完整询价报价系统。

**项目费用**：查看各活动直接费用、项目共同费用、归属待核对费用，确保同一费用只汇总一次。整体服务费或包价未分场时留在项目客户约定，不强行摊到活动。管理分析如需分摊，单独显示分摊依据和分析结果，不能改变客户约定或实际单据。

**项目资料**：项目组、职责分工、资料、变更及记录。成员登记支持导出；人员贡献先记录事实，不自动计算奖金。人员在各场承担的金额必须注明是负责业务金额还是成本预算，不能用“个人额度”一词混用。

### 活动详情：五个页签

| 页签 | 先展示什么 | 业务能办什么 | 承接边界 |
|---|---|---|---|
| 执行安排 | 日程、名单／参加人、交通住宿会场等服务、确认结果、资料缺口 | 维护日程、分组和名单，安排资源，确认服务完成 | 纯会议不强填出团航班；旅游活动复用行程、名单和派团能力 |
| 费用采购 | 费用项目、供应商、服务数量／单位、含税金额、当前确认状态 | 登记与调整费用、查看采购与票据依据、发起符合条件的付款申请、进入原供应商对账 | 实际付款和应付确认归财务；共同采购可关联多场，不强迫重复采购 |
| 客户款项 | 本场服务对应的客户约定、变更、开票申请、财务确认的实收 | 查看成交及收款依据、按权限发起开票／金额变更申请 | 不把合同价等同收入确认；实际认款、开票办理复用财务。包价未分场时回看项目，不显示本场虚构欠款 |
| 结算核对 | 服务完成依据、客户确认金额、供应商对账、未决差异、结算及调整记录 | 确认业务完成、提交业务核对、说明争议或后补调整 | 不代替财务结清；按实际约定可一场或多场结算，不重复生成同一账款 |
| 资料记录 | 合同关联、参加人员之外的项目组、附件、审批与变更记录 | 补充资料、查看意见和历史、按权限调整分工 | 不另造独立审批或合同系统，审批通过不等于签署完成 |

收入开票、收款、付款、财务核算不各建一个主页签。高频业务申请可以原位打开已有处理区，查看结果后回到当前活动；涉及财务实际办理时，交给财务对应入口。

费用列表不直接铺14个字段。税率、票面、预计与核定税额、收款账户、付款记录放在费用详情和相应申请区；支持一张发票覆盖多项费用、一项费用对应多张票据，不能假设费用与发票一一对应。

## 四、两条建档路径与关键抽屉

### 单次项目

销售选择“单次活动”，在一个表单中填客户、项目／活动名称、日期城市、预计人数、项目负责人、计调和客户已确认方案依据。保存时形成一个项目及其默认活动，不让用户重复录两遍名称、客户、日期。资料不全允许保存草稿，提交或确认时再校验必要条件。

### 年度或多场项目

销售先建项目：客户、名称、有效期间、负责人、组织方式、已有框架合同或约定依据。进入“活动安排”，批量填活动名称、日期、城市、人数和计调；可以复制参考安排，按已有权限分配工作。具体委托、金额和资料可逐场补齐；未补齐的活动保存为草稿，不伪装成已经成交。

| 当前页处理区 | 字段与行为 | 关键结果或异常 |
|---|---|---|
| 新建项目 | 单次／多场，客户，名称，期间，负责人，合同依据；单次展开活动信息 | 单次不重复录入，多场不要求先建月份／批次；客户变动影响合同订单时走变更 |
| 批量建场 | 可逐行填名称、日期、城市、人数、计调；未来可增加表格导入及逐行校验 | 只创建新草稿；重复识别后提示，不能覆盖已确认活动；本轮示意只演示逐行录入 |
| 分配计调 | 所选活动、当前负责人、新负责人、接手范围、生效安排 | 不扩大岗位权限；已确认采购和历史记录保留，不因人员变更重置 |
| 费用登记／调整 | 服务项目、供应商、服务范围、数量单位、含税金额、币种、依据；票据另列 | 可如实登记超预算已发生费用，明确差额与后续审批；未到票显示待核对，不直接设零税率 |
| 付款申请 | 对应采购或账单、付款条件与依据、本次金额、实际已付、尚在处理的金额、可申请金额 | 申请与执行分开；本次超可申请金额不能提交；不恢复已撤回的独立付款页面及类型扩展 |
| 业务完成／结算核对 | 完成范围、验收依据、客户与供应商确认金额、争议、未结事项 | 会议称已完成；旅游完成可承接回团事实。结算后补费新增调整，不解锁覆盖旧结算 |

复制活动只带入选定的服务模板、参考成本与成员建议；日期负责人重新检查，不复制供应商确认号、实际付款、发票、名单敏感资料、验收及审批结果。

## 五、用一条真实工作路径检查设计

以年度医药会议项目为例，项目框架示例上限500万元，不表示已实现500万元成交或收入。

1. 销售创建年度项目一次，关联框架合同，登记项目负责人和参与成员。
2. 项目负责人在“活动安排”建北京会议、上海会议等活动，分配计调；每场关联客户的具体委托或确认依据。
3. 计调在履约中心直接看到自己负责的活动，进入北京会议，无需切换“销售身份”才能看到客户已确认资料。
4. 在“执行安排”维护日程、参加人及酒店会场；在“费用采购”记录供应商及费用，预算参考与确认费用分开。
5. 对酒店费用发起申请。示例假定符合付款条件的确认金额28,000元、实际已付8,000元、有效申请尚未支付4,000元，无退款、冲抵等事项，当前可申请16,000元。
6. 再申请5,000元，尚在处理的金额变9,000元，可申请变11,000元，**实际已付仍为8,000元**。此时再申请11,001元应被拦住；审批通过也不能直接把实际已付增加。
7. 活动完成后记录服务交付；客户按约定逐场或按月确认，供应商按对应采购与账单对账。未到票、未收尾款、争议分别列示，不把全部活动卡在一个含义不清的“未完成”。
8. 财务在原有入口确认实收、付款、票据与核算；项目页展示关联结果。结算后发生追加费用，通过调整记录回查原依据。

申请占用只统计当前仍有效且尚未实际支付的部分，不能把一份申请的已支付部分又减一次。上述算例只解释业务区别，不替代正式预付款节点、账单、冲抵和公司审批政策。

另一个必验反例是整体包价项目：客户为五条线路共确认100万元，未分场定价。项目展示100万元客户约定，各活动展示自己的直接费用与完成情况；整包服务费、共同费用保留项目。不能为了做“每场毛利率”而把100万元机械平均，或把没有分场收入的活动显示为零收入亏损。

## 六、金额、审批和税额必须保留的判断

- **预算、费用和付款是三件事。** 预算是计划，费用是已确认或实际发生的业务成本，付款是资金实际付出。超预算可以进入调整或例外审批，但不得抹掉已发生的费用；付款资格另行校验。
- **不同金额有不同用途。** 框架上限、具体成交、客户结算确认、财务收入确认、实收分别表达。“客户确认金额减业务预计费用”可用于经营测算，不直接命名为最终财务毛利。
- **税额先核对再确认。** 含税采购金额、票面信息和财务核定税额分开；增值税专用发票不是当然全部可抵扣，其他规定凭证也可能允许抵扣。财政部、税务总局2026年第13号公告列有国内旅客运输凭证及符合条件的通行费普通发票等情形，因此“仅专票可抵扣、普票一律不能抵扣”不能写成系统通用规则。具体公司适用资格及业务限制由财务确认。
- **汇率按用途记录。** 客户固定约定、采购预算、供应商结算和实际收付可能使用不同依据，不默认全部采用录入日汇率，不让参考更新覆盖已确认交易条件。
- **审批按事项和职责处理。** 自动找到审批人可做；同一人处理不同职责不能一概跳过，旧批准不能覆盖新金额、新版本。致远审批结果、合同签署和系统归档分别表达。
- **状态按对象区分。** 项目统筹进度、活动执行进度、合同状态及财务办理结果各自有含义；一级列表只突出当前列表对象的一个主状态，相关结果在详情里查看。

税务核对来源：[财政部 税务总局关于增值税进项税额抵扣等有关事项的公告（2026年第13号）](https://shanghai.chinatax.gov.cn/zzzb/zcwj/202602/t479292.html)。这里只据此否定过度简化的产品规则，没有代公司确定税务政策。

## 七、本轮示意与后续设计边界
