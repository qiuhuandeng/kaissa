## 三、统一交互与验收原则

1. 不同分析问题归独立Tab。费用类别与部门费用、资源风险与成本分配、统计日历与来源核对不得放进同一个“查看内容”。
2. 同一个范围、同一金额含义的汇总与组成可以切换；切换保留已查询条件、币种、截止日及范围。主表旁显示当前主题和必要口径，完整规则不堆进页面。
3. 数量必须按人、间夜、舱位、铺位等单位分开；不将不同单位相加。缺数据不当零；负数和零值不是默认剔除理由。
4. 订单净成交、完成业务金额、产品考核金额、会计确认收入、实收款分别命名。产品考核的供应商结算金额不等于会计收入。
5. 有完整批准依据才计算完成率、可比增长、费用分配、奖金或分润；原型可用明确标记的独立算例验证规则，不能冒充批准政策或实账。
6. 每个待实施项至少验正常和异常各一组，并验筛选、切换、全范围导出及窄屏短值完整。已查询条件与正在编辑的条件分开，不能导出未执行的筛选。
7. 本次对既有验收只做引用，不给新增需求提前勾选完成。下面20项均待实施或专项验收。

## 四、剩余需求与具体修改方案

编号是本方案验收项，优先级表示依赖先后，不代表新批次。各项实施时须补页面、计算、正常与异常证据，不能凭文件存在销项。

### 余01｜统计日历（用户已跳过，未完成）

- **财务要求**：周报、自然月、管理月和会计月不能互相替代；比较期须按相同统计进度确定。附件Word第6、10—12段及渠道历史表提供期间要求。
- **现有及缺口**：总览已能计算上一等长期间和上年日期，但没有独立统计日历；管理页分类、组织及版本不能承载期间主题。详见 `shared/overview-report-model.js` 与 `shared/report-management.js`。
- **改法**：数据管理新增“统计日历”Tab。主表每行一个日历版本下的统计期间：日历名称、适用报表、期间名称、起止日、截止日、比较期间、版本、生效范围、确认状态和依据。自然月、管理月、会计月用明确日历类型筛选；同期间的日期组成可切换，不能混入来源校验。
- **正常验收**：自然月、26日至次月25日的独立算例、截至某日的同期；范围、期间和导出一致。
- **异常验收**：6月30日例外须有明确期间起止和相邻期间依据，不能自行补全7月；重叠、断档、闰日、截止超过结束日、未确认版本均揭示，不能生成可比结果。
- **依赖**：附件规则是需求证据，适用公司、年度和例外衔接仍待财务确认。先做只读原型与日历校验，不把示例配置成集团正式政策。接入各业务报表留余07/08，不能本项完成就宣布比较完成。

### 余02｜新增来源核对（用户已跳过，未完成）

- **要求**：Word多系统汇总、表2第56行同期核对，需要知道漏数、重复和差异发生在哪。
- **现有及缺口**：数据核对检查组织等字段缺失及完成财务缺口；不能证明通通游、亿步、新系统、财务核算资料之间完整一致。
- **改法**：数据管理新增“来源核对”Tab，按来源、公司、期间、截止批次显示来源笔数/金额、接收、排除、重复待判、无法匹配、净纳入及差额；金额按业务含义分别比较。相同核对范围可切换问题记录；问题原因/来源号为文本，办理回源模块。
- **验收**：来源合计经有依据的排除与去重后可复算；同单跨系统重复、只有一边、不同更新时间、拆单合单、币种冲突、未完整加载不可显示“核平”。补正式来源前以成对算例验原型。

### 余03｜产品考核金额及产品层级（优先）

- **要求**：产品自营周报与渠道/外采周报的金额基础不同，且需看产品部门、系列、线路和具体业务。
- **缺口证据**：`shared/report-pages.js` 产品列已有成交额、可选数量等，缺单列产品考核金额；组织选择不能代替产品系列/线路。附件A3及Word第14、19、28段。
- **改法**：产品订单/产品回团同时明确净成交额、考核金额、考核基础和资料完整度；产品系列、线路、团期/业务明细按同一产品范围分层切换。金额、数量及对应任务分别注明基础。产品结构/渠道构成补同单位数量及数量占比。
- **验收**：自营供应商结算金额与客户成交额不同仍各自正确；外采、集团内部供给、结算价缺失/多供应商分配不全、单位混合分别处理。批准前不默认用供应商结算金额覆盖所有自营业务。

### 余04｜成本构成（本次指定只读原型已完成）

最新交付见[成本构成验收](成本构成新增与验收-20260915.md)。当前支持预计/结算/差额/单位成本和同范围明细；原清单扩大描述中的待确认金额及成本占比列未在本次用户指定范围内新增，仍保留待补，不以原型交付代表正式来源完成。

- **要求**：表2第36、40、64行，查看交通、酒店、地接、领队、签证、保险等成本及团组领队姓名。
- **现有及缺口**：业务毛利有总额及资源成本分配，未形成完整业务成本类别分析；资源批次预计采购成本不等于团组预计成本。
- **改法**：业务毛利新增“成本构成”Tab，主表公司/业务范围/成本类别，列预计成本、已确认成本、待确认成本、差异、占比和可比单位成本；切换同范围费用明细，显示团号、供应商、成本项目、数量单位、领队（适用时）、确认依据。成本类别与会计科目做对应，不合并成同一字段。
- **验收**：类别汇总与完整业务成本一致；多供应商、多人领队、未分类、缺预计数和不同单位不得错摊或计算虚假单位成本。成本分类及预计版本待批准时保留未确认状态。

### 余05｜部门费用独立主题（本次指定原型已完成）

最新交付见[部门费用验收](部门费用新增与验收-20260915.md)。直接/分配/承担及未分配、同范围明细已完成，费用构成旧部门切换已移除。预算比较留余08，本页不提前算完成。

- **要求**：集团财务既看费用花在哪里，也看哪个部门承担，两个问题分开。
- **现有及缺口**：`shared/monthly-profit-view.js` 的费用分组仍有“按费用类别/按承担部门”，`shared/monthly-profit-analysis.js` 据此切换主维度。虽然只显示一表，仍不符合不同主题独立Tab的要求。
- **改法**：费用构成保留类别主表；新增“部门费用”Tab，部门行、直接费用/分配费用/承担合计/预算差异，未分配单列保留。各自切换同范围费用组成，移除费用构成中的按承担部门选项。
- **验收**：原费用不因分配重复累计；部门承担加未分配等于公司费用；缺分配依据不能强摊。两Tab独立筛选、查询、导出均一致。

### 余06｜公司与部门损益累计比较（随后）

- **要求**：月度核算财务需本月、本年累计和同期结果，区分单体、部门和集团抵销。
- **缺口**：当前公司行主要为公司/期间收入成本费用结果；费用比较列仍返回不可比文字，没有完整历史比较来源。见 `shared/monthly-profit-analysis.js`。
- **改法**：公司损益维持公司汇总，可切换同公司范围的损益项目组成；列分本月、本年累计、同期及差额。部门损益补同范围累计、直接/分配/内部结转及未归属。集团调整、内部调整维持独立Tab，分别表达抵销前后及公司总额不变。
- **验收**：累计跨月不重复结转；同期组织按原归属或经批准重述明确区分；内部结转公司合计为零，集团调整不反改公司原数。未完整提供历史月份则不计算完整累计比较。

### 余07｜三年同期及可比进度（随后，依赖余01）

- **要求**：Word及渠道历史报表需要三年相同统计进度的比较，不能只提供上年日期选择。
- **缺口证据**：总览 `comparison(..., false)` 固定不启用比较；渠道比较及任务为占位文字。基础日期函数已有，但没有可完整验收的多年度来源消费和三年列。
- **改法**：总览订单/回团、产品订单/回团/跨年收客、渠道订单/回团/门店/呼叫中心按同主题提供比较列组；绑定日历、历史组织版本、截止日及可比覆盖范围。三年作为列组，不拆三张表。跨年收客保留订单年×完成年，不能按完成年重复累计下单额。
- **验收**：三年完整资料算例、闰年和非自然管理月、当月同进度；零/负基数只给可解释差额，缺一年或组织不可比只限制受影响范围，不伪造增长率。

### 余08｜批准预算与任务覆盖（优先于完成率）

- **要求**：公司/部门、收入/成本/费用/经营结果，月季年应使用相应批准版本。
- **缺口证据**：`shared/monthly-profit-analysis.js`、模型及视图主要覆盖两个公司某月的经营费用/经营结果；当前匹配逻辑不能仅靠新增下拉选项扩大到收入成本。
- **改法**：任务预算两Tab分别维护只读经营任务和批准预算展示；明确责任组织、指标、期间、金额基础、版本、批准时间。预算差异复用批准预算，完整匹配公司/部门/指标/币种/期间；月季年切换同一指标期间，不混订单和回团任务。
- **验收**：批准/草稿/撤销、多版本、年度与月度分解不一致、部门缺任务；成本费用超预算与收入未达预算方向正确。缺预算不按0算完成率。

### 余09｜产品及渠道经营贡献（随后）

- **要求**：判断扣除责任费用后真正贡献，保留公司费用未分配范围。
- **缺口证据**：`shared/product-contribution-analysis.js` 当前明确是确认收入减成本减已归属直接费用，尚不是分配公共费用后的完整贡献。
- **改法**：现有经营贡献Tab列毛利、直接费用、直接贡献、经批准分配费用、分配后贡献、未分配范围；同范围业务组成可以切换。产品和渠道分别分析，不把两个视角相加当公司合计。

### 余10｜门店与呼叫中心完成质量（随后）
