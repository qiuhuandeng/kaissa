# 财务部门系统使用培训稿（财务人员版）

这份材料面向财务人员使用，不按菜单逐个讲功能，而是按财务日常工作中真正会遇到的业务场景来讲：一笔业务数据从上游进入系统后，财务应该在哪里看、看什么、怎么核、怎么处理异常，最后如何形成收款、付款、发票、结算、关账、NC 和报表。

财务在系统里的核心职责不是替业务补数据，而是做四件事：

- 核对：核业务来源、金额、主体、客户/供应商、币种汇率、附件和票据。
- 确认：确认应收、认款、应付、付款、结算、发票、回单等财务对象。
- 处理异常：对无法匹配、金额不一致、票据不符、账户异常、NC 失败等问题做退回、差异处理或重推。
- 完成入账承接：让系统沉淀出的财务对象进入报表、关账和 NC。

一句话记住：

> 业务部门负责把业务事实录准，系统负责把业务事实自动沉淀成财务对象，财务负责核对、确认、处理异常，完成入账、付款、开票、结算、关账和 NC。

## 第一部分 概述

### 1. 财务是业财链路的验收者

销售、产品、计调、履约完成各自业务后，最终都会沉淀到财务对象。财务要验收的不是某个页面是否填满，而是这几类问题能不能回答清楚：

- 这笔钱该不该收，来源订单或项目是否成立。
- 钱有没有到账，到账流水是否真实、唯一、可识别。
- 到账后认到哪张订单、哪张应收，是否存在拆分、合并、超收或短收。
- 这笔成本有没有业务依据，供应商账单和系统成本是否一致。
- 这笔付款有没有超过可申请金额，是否审批通过，是否真正付款并回单核销。
- 发票、回单、汇率、结算、NC 是否和源单一致。
- 报表里的数能不能穿透到订单、流水、账单、应付、付款、发票、结算和 NC。

### 2. 财务在系统里不做什么

财务不要替业务补订单、补游客名单、补产品成本、补供应商账单、补销售合同。发现源头数据不完整时，应回到对应源单退回或卡控，让业务在源头修正。

财务也不要为了让报表好看，直接改应收、应付、结算或 NC 结果。已生效的财务数据必须通过调整、冲销、红冲、补充凭证或结算调整来处理。

### 3. 财务需要把业务动作翻译成财务对象

| 业务动作 | 系统形成的财务对象 | 财务需要处理什么 |
| --- | --- | --- |
| 销售订单确认 | 应收单、应收计划、发票前置信息 | 核来源、主体、金额、账龄、客户/渠道 |
| 客户付款或门店上传水单 | 到账流水、识别结果、后续去向 | 核流水重复、付款方、收款账户、资金用途 |
| 认款确认 | 收款凭证、应收核销、NC 收款任务 | 核一笔流水认到哪张应收，处理拆分、合并、超收、短收 |
| 售后退款或改期转团 | 退款单、转款单、应收冲减、预收余额 | 核可退/可转金额、原收款、账户、发票红冲 |
| 供应商账单进入系统 | 账单识别、成本核对、应付基础 | 核供应商、关联团期/项目/批次、账单金额和差异 |
| 应付确认和付款申请 | 应付单、付款申请单、审批任务 | 核应付依据、可申请金额、本次申请金额、预付冲抵 |
| 付款执行和回单核销 | 付款单、回单、应付已付、NC 付款任务 | 核账户、付款结果、回单金额和银行退回异常 |
| 业务结算、门店对账、渠道结算 | 结算单、差异记录、结算调整、报表口径 | 核收入、成本、收付、退款、票据、毛利和 NC |

## 第二部分 业财总链路

### 1. 业财一体化主链路

财务要先从全链路理解系统，而不是只从财务菜单理解系统。

```text
产品/线路/团期/项目/服务单
-> 销售订单/合同/售后
-> 应收/到账流水/认款/预收/预存/转款/退款
-> 履约成本/供应商账单/应付/预付
-> 付款申请/审批/付款执行/回单/付款退回
-> 业务结算/门店对账/渠道结算/结算调整
-> 发票/资金池/期间关账/NC/报表
```

这条链路里，业务部门录入的是业务事实，系统沉淀的是财务对象，财务最终验收的是资金、票据、结算、凭证和报表。

### 2. 财务核心对象速查

| 财务对象 | 是什么 | 从哪里来 | 到哪里去 |
| --- | --- | --- | --- |
| 应收 | 客户、门店、渠道或项目应该付给公司的金额 | 订单、合同、项目阶段款、补差、应收调整 | 认款复核、发票、结算、NC |
| 到账流水 | 银行、POS、支付平台、OTA 或水单形成的资金流水 | 接口、导入、登记、门店水单 | 认款复核、预存账户、转款处理、退款执行、资金池 |
| 认款 | 确认一笔或多笔流水核销哪张应收 | 到账流水、应收单、自动匹配、人工选择 | 收款凭证、应收状态、订单收款状态、NC |
| 预收 | 客户或订单层面的可用余额 | 超收、企业预付款、转款剩余、退款转预收 | 新订单抵扣、退款、冻结解冻、NC |
| 预存 | 门店、渠道或客户账户余额 | 门店充值、渠道预存、账户扣款、退款退回 | 订单扣款、门店对账、资金池、NC |
| 转款 | 原订单收款转入新订单或余额处理的核销事件 | 销售售后改期、换团、转单、取消留存 | 新订单认款、预收、补收应收、退款、NC |
| 退款 | 已审批的退款执行对象 | 售后退款、退差、预收/预存退款 | 退款执行、回单、发票红冲、NC |
| 供应商账单 | 供应商提供的成本账单 | 上传、录入、邮件、接口、履约成本承接 | 应付管理、进项发票、结算 |
| 应付 | 已确认的付款义务 | 成本确认、供应商账单、采购批次、服务单代垫 | 付款申请、付款执行、发票、结算、NC |
| 预付 | 已付给供应商，待后续冲抵实际应付的余额 | 合同节点、资源锁位、舱房/铺位/酒店定金、付款执行 | 冲抵应付、余额退回、结算、NC |
| 付款申请 | 基于应付、预付节点或合同节点发起的付款申请 | 应付单、供应商账单、合同节点、业务付款申请 | 审批中心、付款执行 |
| 付款执行 | 出纳实际付款处理 | 已审批付款申请 | 付款单、回单核销、资金池、NC |
| 回单 | 付款或退款后的银行结果证明 | 银企直联、银行回单、人工上传 | 回单核销、付款完成、退款完成、NC |
| 付款退回 | 银行退回或付款失败后的异常对象 | 付款失败、银行退汇、回单差异 | 重新付款、冲销应付、恢复预付、NC |
| 结算 | 对团期、项目、订单、门店、渠道的财务确认 | 收入、成本、收付、退款、发票、回单 | 结算调整、报表、关账、NC |
| 发票 | 销项开票、进项收票、核验、认证、红冲等税务对象 | 应收、收款、应付、付款、退款、结算 | 税务台账、结算风险、NC |
| NC | 凭证推送任务和返回结果 | 收款、退款、应付、付款、发票、结算、汇兑、调整 | NC 返回号、凭证状态、失败重推、总账 |

## 第三部分 第一条主链：收入资金链

主线：

```text
销售订单/服务单/项目阶段款
-> 应收单
-> 到账流水
-> 资金用途识别
-> 认款复核
-> 应收核销
-> 预收/预存/转款/退款分流
-> 发票
-> 收入确认
-> NC
```

### 场景一：订单确认后形成应收

#### 你什么时候进入

销售订单、服务单或项目阶段款已经确认，系统生成应收，财务需要确认这张应收是否可以进入收款和开票链路。

#### 系统入口

财务 > 应收管理

#### 进入页面先看什么

在应收管理列表中，优先看这些字段：

- 应收单/来源：确认这张应收来自哪张订单、项目或服务单。
- 客户/渠道：确认付款对象或结算对象是否正确。
- 关联业务：确认团期、项目、订单、服务内容是否匹配。
- 财务主体：确认收入归属主体是否正确。
- 应收金额：确认金额和订单财务口径一致。
- 客户已收/待收：判断当前是未收、部分收款还是已收清。
- 调整/减免：确认是否存在优惠、补差、退差、核销或减免。
- 应收状态：判断下一步是确认、等待认款、查看详情还是申请核销。

#### 你要怎么操作

1. 进入应收管理，按应收单、订单号、客户、渠道、团期或项目筛选。
2. 待确认应收打开处理抽屉，先看来源依据，再看本次处理。
3. 核对应收金额、已认金额、待收金额、财务主体、调整减免和到期状态。
4. 来源、主体、金额、客户信息都正确时，确认应收。
5. 金额、主体、客户信息异常时，退回业务源单修正。
6. 已确认或已收清的应收，进入详情查看基本信息、认款记录、调整关账、处理记录。
7. 确需核销时，走申请核销，不直接修改原应收。

#### 处理完成后会发生什么

- 应收进入待收款、部分收款、已收清或已确认状态。
- 后续到账流水识别为订单收款后，会进入认款复核。
- 认款确认后回写应收已认金额和待收金额。
- 发票管理可根据应收、收款和抬头生成开票任务。
- 收款或结算确认后进入 NC 和报表口径。

#### 你要重点核什么

- 来源订单是否真实有效。
- 财务主体是否正确。
- 应收金额是否等于订单财务口径。
- 优惠、补差、退差是否已审批。
- 客户、渠道、门店对象是否准确。
- 币种、汇率、本币金额是否完整。
- 到期日和账龄是否正确。

> 注意：应收页不是销售催收页，也不是财务补订单页。财务只确认财务对象是否成立，源头错误要退回源单。

### 场景二：客户付款、水单上传与到账流水分流

#### 你什么时候进入

客户、门店、渠道或平台已经付款，银行、POS、银联、微信、支付宝、OTA 或门店水单进入系统，财务需要确认这笔钱的真实来源和后续去向。

#### 系统入口

财务 > 到账流水  
财务 > 资金池

#### 进入页面先看什么

到账流水列表中，优先看这些字段：

- 流水号/来源：判断是否来自银行、POS、支付平台、OTA 或手工登记。
- 到账时间：判断资金入账时间和账期。
- 收款账户：确认账户属于正确财务主体。
- 付款方：判断能否匹配客户、门店、渠道或供应商退回。
- 到账金额：确认金额和应收、充值、转款、退款退回是否一致。
- 资金用途：判断这笔钱是订单收款、门市充值、转款入账、退款退回还是其他入账。
- 识别对象：看系统识别到了哪个订单、应收、预存账户、转款单或退款单。
- 未识别金额：判断是否还有剩余金额需要继续处理。
- 流水状态：待识别、已识别、部分识别、异常、已关闭。

#### 资金用途怎么分流

| 资金用途 | 后续页面 | 你要确认什么 |
| --- | --- | --- |
| 订单收款 | 认款复核 | 这笔钱认到哪张订单、哪张应收 |
| 门市充值 | 预存账户 | 充值门店、账户主体、充值金额是否一致 |
| 转款入账 | 转款处理 | 原订单、新订单、可转金额和差额去向是否一致 |
| 退款退回 | 退款执行 | 是否匹配原退款单，是否需要重退或冲销 |
| 其他入账 | 其他收入或暂挂台账 | 是否有明确依据，不能成为无来源杂项 |

#### 你要怎么操作

1. 银行、POS、银联或门店水单批量进入时，使用导入流水。
2. 导入前选择主体公司、收款账户和流水日期。
3. 在导入预览中核对流水号、到账时间、付款方、到账金额、重复校验和识别建议。
4. 特殊线下收款使用登记流水，填写主体公司、到账时间、收款账户、付款方、付款方式、回单附件。
5. 待识别或部分识别流水点击识别，异常流水点击处理。
6. 在抽屉中先看流水核对，再选择资金用途、识别依据和识别对象。
7. 识别依据可以是付款方匹配、银行附言匹配或人工核对。
8. 如存在付款方不符、金额不符、附言缺失、疑似重复，要在识别差异中保留原因。
9. 完成识别后，到详情的流水信息、识别信息、后续去向、操作记录中确认这笔钱最终流向。

#### 你要重点核什么

- 流水是否重复导入。
- 收款账户是否属于正确主体。
- 付款方能否匹配客户、门店或渠道。
- 金额是否等于应收、预存充值、转款或退款退回金额。
- 银联/POS 水单与实际到账是否有清算差异。
- 部分识别时，未识别金额是否继续保留待处理。

### 场景三：系统自动认款，财务处理未匹配异常

#### 你什么时候进入

应收已经形成，到账流水也已经识别为订单收款，系统自动匹配出认款建议后，财务需要确认这笔收款最终核销哪张应收。

#### 系统入口

财务 > 认款复核

#### 进入页面先看什么

认款复核列表中，优先看这些字段：

- 认款单/来源：确认认款单和来源流水。
- 付款方：确认付款方是否与客户、门店或渠道一致。
- 关联业务：确认订单、项目、团期或服务单是否正确。
- 应收单：确认核销对象。
- 本次认款：确认本次核销金额。
- 差额：判断是否超收、短收、付款方不符或凭证异常。
- 认款场景：单订单、多订单、项目阶段等。
- 认款状态：待复核、差异中、已确认、已退回。

#### 你要怎么操作

1. 进入认款复核，按认款单、来源流水、付款方、订单或项目筛选。
2. 待复核认款点击复核，差异中点击处理。
3. 先看来源信息：来源流水、付款方、来源金额、提交人、凭证、系统校验。
4. 再看核销明细：订单/项目、应收单、应收金额、已认金额、本次认款、认后余额、差额。
5. 无差异时选择确认认款。
6. 有差异时，根据实际情况选择转入预存账户、保留待认、生成补收应收或退回补充。
7. 已确认记录可查看收款凭证和处理记录。

#### 常见认款差异怎么处理

| 异常 | 处理方式 | 财务口径 |
| --- | --- | --- |
| 一笔流水对应多张订单 | 拆分认款 | 每张应收都要有本次认款和认后余额 |
| 多笔流水对应一张订单 | 分次核销 | 应收状态按已认金额累计变化 |
| 到账金额大于应收 | 转入预存账户或保留待认 | 超收不能随意冲其他订单 |
| 到账金额小于应收 | 部分认款，剩余待收 | 不能把短收订单直接标记已收清 |
| 付款方不符 | 退回补充 | 财务不能猜客户归属 |
| 应收单选错 | 退回或冲正 | 已形成凭证不能直接删除 |
| 需要补收 | 生成补收应收 | 差额要形成新的应收对象 |

#### 处理完成后会发生什么

- 认款确认后，生成收款凭证。
- 应收状态更新为部分收款或已收清。
- 订单收款状态同步变化。
- 差额进入预收、预存、待认或补收应收。
- 收款凭证进入 NC 待推送或已推送状态。

### 场景四：预收、预存与转款核销

#### 你什么时候进入

出现超收、企业预付款、门店预存、渠道预存、订单取消留存、改期转团、原订单款项转新订单等场景时，需要进入预收、预存或转款处理。

#### 三个对象先分清

| 对象 | 页面 | 业务含义 | 常见来源 | 常见去向 |
| --- | --- | --- | --- | --- |
| 预收 | 预收管理 | 客户或订单层面的可用余额 | 超收、企业预付款、转款剩余、退款转预收 | 新订单抵扣、退款、冻结、NC |
| 预存 | 预存账户 | 门店、渠道或客户账户余额 | 门店充值、渠道预存、账户扣款、退款退回 | 订单扣款、门店对账、资金池、NC |
| 转款 | 转款处理 | 原订单收款转入新订单的核销事件 | 改期、换团、转单、取消留存 | 新订单认款、预收、补收应收、退款、NC |

#### 预收管理怎么用

在预收管理中，重点看预收单/客户、来源业务、预收金额、已用金额、可用余额、使用去向、冻结退款、预收状态。

你需要处理：

1. 待确认预收，核来源流水、订单、退款或转款记录。
2. 可使用预收，选择订单或项目进行抵扣。
3. 冻结中预收，核冻结原因后解冻或转退款。
4. 退款中预收，查看退款执行状态和凭证。
5. 已结清或已关闭预收，只做详情反查。

#### 预存账户怎么用

预存账户不是资金池。预存账户看门店、渠道或客户的业务余额；资金池看真实银行或支付账户余额。

在预存账户中，重点看账户对象、账户类型、财务主体、可用余额、冻结金额、待处理项、最近变动、账户状态。

你需要处理：

1. 门店或渠道充值到账后，确认进入哪个预存账户。
2. 订单扣款时，确认扣款对象、扣款金额和剩余余额。
3. 发生冻结、解冻、退款时，确认冻结原因、处理金额和后续单据。
4. 月结时，预存账户流水要和门店对账、资金池、NC 对齐。

#### 转款处理怎么用

在转款处理中，重点看转款单/审批、转款对象、原订单、新订单、可转金额、本次转款、新单待收、差额去向、转款状态。

你需要处理：

1. 待核销转款，核原订单已收、已退、已转、可转金额。
2. 核新订单应收、本次转款后待收金额。
3. 核差额去向：无差额、转预收、补收应收、退回客户、退回补资料。
4. 确认核销后生成转款凭证和 NC 任务。
5. 已核销后发现错误，不删除原记录，走冲正。

> 注意：预收、预存、转款都不是备注。每一次确认、使用、冻结、退款、转款、冲正，都要有余额流水、来源单据、处理记录和凭证状态。

### 场景五：退款和售后反冲

#### 你什么时候进入

销售或客服已经发起售后退款、退差、转团、改期、改舱、改铺，并且审批通过后，财务需要执行退款、处理应收冲减、回单和发票红冲。

#### 系统入口

财务 > 退款执行  
财务 > 转款处理  
财务 > 发票管理

#### 进入页面先看什么

退款执行列表中，优先看这些字段：

- 退款单/审批：确认是否来自已审批的售后。
- 来源订单：确认原订单、产品、团期或服务单。
- 退款对象：确认客户、门店或渠道。
- 退款原因：确认退款类型。
- 可退金额：确认系统计算的可退上限。
- 本次退款：确认本次实际退款金额。
- 退款去向：确认原路退回、指定账户、预收/预存退回等。
- 退款状态：待退款、退款中、待回单、退款失败、已完成、已关闭等。

#### 你要怎么操作

1. 打开退款执行列表，按退款单、来源订单、客户、状态筛选。
2. 待退款点击退款，先看执行依据，确认审批结果、原收款、可退金额。
3. 核对退款去向：原路退回、指定账户、预收/预存余额退回等。
4. 检查执行校验：退款账户、白名单、原收方式、已退金额、发票状态。
5. 确认未收部分先冲应收，已收部分才执行退款。
6. 执行退款后进入退款中或待回单。
7. 上传或同步回单，完成后生成退款凭证和 NC 任务。
8. 原订单已开票的，进入发票管理处理红冲。
9. 退款失败或银行退回时，回到退款执行或到账流水处理，不直接改订单。

#### 你要重点核什么

- 退款是否已审批。
- 原订单是否已收款。
- 可退金额是否准确。
- 未收部分是否先冲应收，已收部分才退款。
- 退款账户是否与客户或原付款方一致。
- 已开票是否触发红冲。
- 退款完成是否回写订单、应收、发票和 NC。

## 第四部分 第二条主链：成本付款链

主线：

```text
供应商账单 / 系统成本确认
-> 账单识别与业务挂接
-> 应付确认
-> 预付分摊/冲抵
-> 付款申请
-> 审批通过
-> 付款执行
-> 回单核销
-> 付款退回/异常处理
-> 应付结清 / 凭证 NC
```

### 场景一：团期、项目、服务成本进入财务

#### 你什么时候进入

计调或履约已经在团期、项目、自由行采购批次、服务单里确认成本，或供应商账单已经上传/导入，财务需要核对成本来源是否真实、账单是否能匹配业务对象。

#### 你要先判断什么

- 成本来自哪个团期、项目、采购批次或服务单。
- 供应商是否准确。
- 费用项目是否明确。
- 金额、币种、汇率、本币金额是否完整。
- 附件、账单、合同节点是否齐全。
- 成本是预估成本还是实际发生成本。

> 注意：财务不能凭口头、微信、Excel 或供应商一句话付款。成本必须能回到业务对象和供应商账单。

### 场景二：供应商账单识别与应付确认

#### 系统入口

财务 > 供应商账单  
财务 > 应付管理

#### 供应商账单怎么处理

供应商账单列表中，重点看账单号/来源、供应商、关联团期/批次、账单类型、账单金额、系统成本、核对差异、主状态、应付结果。

你需要处理：

1. 账单通过上传、录入、接口或业务成本承接进入系统。
2. 待识别账单点击识别，看原始附件、识别明细、账单信息。
3. 待挂接账单点击关联，选择团期、项目、采购批次或服务单。
4. 待核对账单点击核对，比较对方账单和系统成本。
5. 金额不一致进入差异处理，保留差异依据和处理结论。
6. 账单确认后承接到应付管理和发票管理。

#### 应付管理怎么处理

应付管理列表中，重点看应付单/来源、付款对象、关联团期/批次、费用项目、应付金额、已付/可申请、主状态、付款进度。

你需要处理：

1. 进入应付管理，查看来源账单、供应商、费用项目、关联团组。
2. 核对原币应付、汇率、本币金额、已付、待付、预付冲抵、发票风险。
3. 待确认应付点击确认应付。
4. 差异中应付点击处理差异。
5. 确认后才允许进入付款申请。
6. 付款中应付查看付款进度。
7. 已结清应付只做详情反查。

#### 你要重点核什么

- 供应商是否准确。
- 账单是否挂接到正确团期、项目、采购批次或服务单。
- 成本是否实际发生，不是预估成本。
- 金额、币种、汇率是否准确。
- 供应商账单和业务成本是否一致。
- 发票或附件是否齐全。
- 是否存在预付需要冲抵。

> 注意：预估成本不是应付，供应商账单确认也不等于已付款。财务确认应付后，才进入付款申请和付款执行。

### 场景三：供应商预付、预付冲抵与余额管理

#### 你什么时候进入

机票锁位、邮轮舱房、专列铺位、酒店定金、地接预付等业务发生预付款后，财务需要管理预付余额，并在实际账单或应付确认后做冲抵。

#### 系统入口

财务 > 预付管理

#### 进入页面先看什么

预付管理列表中，重点看预付单/付款对象、预付类型、关联团期/项目、预付金额、已冲抵/余额、主状态、凭证 NC。

预付状态包括待分摊、待冲抵、待确认、余额待处理、差异待处理、已结清、已关闭。

#### 你要怎么操作

1. 预付款执行完成后，系统形成供应商预付余额。
2. 回团或账单确认后，进入预付管理。
3. 待分摊时，按团期、项目或供应商账单确认分摊对象。
4. 待冲抵时，选择应付单或账单，系统计算可冲抵金额。
5. 余额待处理时，判断继续留存、退回、转款或关闭。
6. 冲抵后更新应付待付金额和预付余额，形成凭证 NC。

#### 你要重点核什么

- 预付来源是否有合同或付款节点。
- 是否关联正确团期、项目、供应商。
- 已冲抵和余额是否准确。
- 长期未冲抵预付是否有风险。
- 预付冲抵是否影响结算和 NC。

> 注意：预付不能直接当成本。预付只有在实际成本或账单确认后，通过冲抵进入应付和结算。

### 场景四：付款申请、审批与付款执行

#### 你什么时候进入

业务或应付会计基于应付、供应商账单、合同节点或预付节点发起付款申请后，财务需要复核付款依据；审批通过后，出纳再执行付款。

#### 系统入口

财务 > 付款申请  
财务 > 付款执行  
财务 > 回单核销  
财务 > 付款退回

#### 五个金额口径必须分清

| 金额口径 | 含义 | 重点页面 |
| --- | --- | --- |
| 应付金额 | 成本或账单确认后的付款义务总额 | 应付管理 |
| 可申请金额 | 扣除已申请、已付、已冲抵后，当前还能申请的余额 | 付款申请列表 |
| 本次可申请 | 进入申请/复核抽屉后，受付款节点、依据和规则限制的本次上限 | 付款申请抽屉 |
| 本次申请金额 | 本次实际提交的付款金额 | 付款申请、审批记录 |
| 本次实付 | 扣除预付冲抵后真正需要付款执行的金额 | 付款申请、付款执行 |

#### 付款申请怎么处理

付款申请列表中，重点看申请单/类型、付款对象、付款依据、关联团组/项目、申请信息、可申请金额、本次申请/本币、冲抵/实付、主状态。

你需要处理：

1. 待复核付款申请，打开详情看申请总览、付款依据、金额核对、附件依据。
2. 核供应商账单、应付单、合同节点、预付冲抵和附件。
3. 核可申请金额、本次申请金额、本次实付金额是否正确。
4. 依据齐全则复核通过，进入审批。
5. 依据不足或账户信息异常，退回业务补充。
6. 审批中只查看审批记录，不在财务侧替审批人审批。
7. 已通过后进入付款执行。

#### 付款执行怎么处理

付款执行列表中，重点看付款单/申请、付款对象、付款依据、关联团组、原币付款、汇率/本币、付款账户、收款账户、主状态、回单凭证。

你需要处理：

1. 待付款任务，核申请来源、付款账户、收款账户、账户余额、币种和付款方式。
2. 校验异常时，先处理账户、余额、币种、付款方式等异常。
3. 执行付款后，付款状态进入付款中或待回单。
4. 付款失败进入异常记录或付款退回。
5. 待回单状态上传或同步回单，后续进入回单核销。
6. 已付款记录查看回单和凭证 NC。

> 注意：付款申请通过不等于已付款。只有付款执行成功并完成回单核销后，应付才真正进入已付或结清。

### 场景五：回单核销与付款退回

#### 回单核销怎么处理

系统入口：财务 > 回单核销。

回单核销列表中，重点看回单号/来源、回单类型、关联单据、付款对象、关联团组、原币回单、汇率/本币、核对结果、回单状态、凭证 NC。

你需要处理：

1. 付款执行完成后，系统等待回单。
2. 回单通过银行接口同步或人工导入。
3. 待匹配点击匹配，选择付款单、退款单或相关业务单据。
4. 待核销点击核销，核对付款对象、账户、金额、币种、付款单。
5. 核销成功后应付状态更新，生成 NC 凭证任务。
6. 金额、账户或币种不一致，进入差异处理。

#### 付款退回怎么处理

系统入口：财务 > 付款退回。

付款退回列表中，重点看退回单/来源、退回对象、原付款单、关联团期/项目、退回类型、原币退回、汇率/本币、到账流水、退回状态、凭证 NC。

你需要处理：

1. 银行退回或付款失败形成退回记录。
2. 待匹配状态下，匹配原付款单。
3. 核对退回原因：账户错误、银行拒付、币种问题、金额异常等。
4. 判断下一步：重新付款、冲销应付、恢复预付或关闭。
5. 待冲销时生成冲销处理。
6. 完成后生成处理记录和 NC 调整任务。

## 第五部分 第三条主链：结算对账链

主线：

```text
团期/项目/订单/服务单/门店/渠道/OTA
-> 发起结算或对账
-> 收入成本票据回单核对
-> 差异处理 / 结算调整
-> 财务结算确认
-> 报表 / 期间关账 / NC
```

结算的本质是财务对一个业务对象的经营结果进行确认。结算不是业务补录，也不是单纯报表，而是把收入、成本、收款、退款、应付、付款、发票、回单和毛利统一核对并锁定。

### 场景一：团期、项目、订单、服务单业务结算

#### 系统入口

财务 > 业务结算  
财务 > 业务结算详情

#### 进入页面先看什么

业务结算列表中，重点看结算单/类型、结算对象、结算周期、收入核对、成本核对、票据回单、核算结果、结算状态、凭证 NC。

结算状态包括待核对、差异待处理、退回补充、审批中、已结算、已归档。

#### 你要怎么操作

1. 进入业务结算，按团期、航次、班期、项目、订单或服务单筛选。
2. 点击核对或处理，先看结算总览：收入、成本、已收、待收、已付、待付、毛利。
3. 核对收入明细：应收、已认款、退款、优惠、待收。
4. 核对成本明细：供应商、费用项目、应付、预付冲抵、已付、待付。
5. 核对票据回单：销项开票、进项收票、红冲、核验、付款回单。
6. 核对审批 NC：结算审批状态、凭证是否生成、是否失败。
7. 处理差异后确认结算。
8. 已结算后发生后补账单、退款、汇兑或发票红冲，进入结算调整。

#### 你要重点核什么

- 结算收入是否等于订单财务口径。
- 已收是否来自确认认款。
- 退款是否执行完成。
- 成本是否来自已确认成本或应付。
- 预收、预存、预付是否正确抵扣。
- 发票、回单是否存在风险。
- 毛利是否异常。
- NC 是否可推送。

### 场景二：门店月结对账

#### 你什么时候进入

门店周期性对账时，需要核订单、收款、预存、退款、扣项和差异。门店侧可自查或发起，总部财务负责确认承接。

#### 系统入口

财务 > 门店对账  
财务 > 预存账户  
财务 > 资金池

#### 进入页面先看什么

门店对账列表中，重点看对账单/门店、对账周期、对账类型、订单/收款、预存账户、门店承担/扣项、差异金额、主状态。

主状态包括待核对、差异待处理、退回补充、待确认、已对账、已关闭。

#### 你要怎么操作

1. 进入门店对账，选择门店、周期、对账类型。
2. 系统汇总门店订单、门店收款、银联/POS 水单、预存充值、预存扣款、退款。
3. 待核对点击核对，查看对账总览、收款退款、预存流水、门店扣项。
4. 有差异时点击处理，逐项处理缺流水、预存未确认、退款未执行、订单状态不一致、门店扣项等问题。
5. 核对完成后点击确认，结果进入业务结算、预存调整、应收或 NC。

> 注意：门店月结不是总部财务和门店互相对 Excel。系统会汇总订单、流水、预存和退款，财务主要看差异。

### 场景三：渠道、OTA、代理对账

#### 你什么时候进入

渠道或 OTA 平台账单进入系统后，需要和系统订单、佣金扣点、退款折减、实际回款做匹配。

#### 系统入口

财务 > 渠道结算

#### 进入页面先看什么

渠道结算列表中，重点看对账单/渠道、账期、订单/优惠、平台扣项、应回款、已到账、差异金额、主状态。

主状态包括待核对、差异待处理、待确认、已结算、已关闭。

#### 你要怎么操作

1. 导入账单或新建对账，选择渠道、账期、对账范围。
2. 系统按渠道订单、系统订单、金额、日期自动匹配。
3. 核对订单/优惠、平台扣项、退款折减、应回款、已到账。
4. 匹配成功形成对账明细。
5. 未匹配或金额不一致进入差异清单。
6. 处理订单缺失、退款不同步、佣金规则差异、平台扣项异常。
7. 确认渠道结算，结果进入应收、认款、佣金应付、业务结算和 NC。

### 场景四：结算调整与补充结算

#### 你什么时候进入

结算完成后又发生后补供应商账单、退款追溯、汇兑差异、发票红冲、成本差异时，不能改原结算单，必须走结算调整。

#### 系统入口

财务 > 结算调整

#### 进入页面先看什么

结算调整列表中，重点看调整单/来源、原结算单、结算对象、调整类型、调整金额、调整后口径、调整依据、调整状态。

调整状态包括待核对、差异中、待提交、审批中、已生效、已驳回、已关闭。

#### 你要怎么操作

1. 选择原结算单。
2. 选择调整类型：成本差异、退款追溯、汇兑差异、发票红冲、后补账单等。
3. 填写调整金额和依据。
4. 上传附件或引用来源单据。
5. 提交审批或财务复核。
6. 生效后生成调整凭证、报表重算和 NC 任务。

> 注意：已生效财务数据不能覆盖修改，所有调整都必须追加记录，保证审计可追溯。

## 第六部分 横向能力

### 1. 发票税务与自动开票

#### 你什么时候进入

需要处理销项开票、进项收票、发票核验、认证、红冲或票据异常时，进入发票管理。

#### 系统入口

财务 > 发票管理

#### 发票链路

```text
应收/收款/结算/应付/付款/退款
-> 发票任务
-> 开票/收票/核验/认证/红冲
-> 税务台账
-> NC
```

#### 进入页面先看什么

发票管理列表中，重点看发票任务、发票类型、业务来源、发票对象、发票金额、税票信息、匹配校验、主状态、凭证/NC。

主状态包括待开票、待收票、待核验、异常中、待红冲、已完成。

#### 你要怎么操作

1. 待开票任务，核应收、客户抬头、税号、可开金额、税率和发票类型后开票。
2. 待收票任务，核供应商账单、应付、付款、票面金额后登记收票。
3. 进项收票登记后进入待核验。
4. 待核验任务，选择税务平台查验或境外票据人工核验。
5. 退款或冲减场景进入待红冲，确认红冲后回写税务台账。
6. 同步失败、票面不符、税号不一致时进入异常处理。
7. 完成后生成凭证/NC 任务。

#### 你要重点核什么

- 开票对象、收票对象是否正确。
- 金额、税率、发票类型是否匹配业务来源。
- 抬头、税号、发票号码是否完整。
- 退款后是否触发红冲。
- 进项发票是否和账单、应付、付款一致。
- 发票状态是否回写结算和 NC。

### 2. 多币种、汇率与汇兑差异

#### 你什么时候进入

出境、邮轮、专列、境外酒店、境外地接、国际机票等业务涉及外币时，需要维护币种汇率、查看订单锁汇和汇兑差异。

#### 系统入口

财务 > 财务设置

#### 进入页面先看什么

财务设置页面中，重点看支持币种列表和订单锁汇记录：

- 币种代码、币种名称。
- 对 CNY 汇率。
- 最后更新时间。
- 更新方式。
- 订单外币金额。
- 锁定汇率、锁定时间。
- 当前汇率。
- 潜在差异金额。
- 锁汇状态。

#### 你要怎么操作

1. 查看系统支持币种和汇率更新时间。
2. 第三方 API 自动更新后，检查关键币种是否正常。
3. 必要时手动录入或修正汇率，填写生效日期、来源和修正原因。
4. 查看外币订单锁汇记录。
5. 在结算或关账时，确认汇兑差异进入损益或差异处理。

> 注意：多币种不是只显示一个汇率。所有涉及钱的对象都应保留原币金额、汇率、本币金额、汇率来源和锁定时间。

### 3. 资金池与资金调拨

#### 你什么时候进入

需要查看银行账户、支付账户、门店 POS 清算户、预存账户的账面余额、可用余额、待处理资金、冻结占用和同步差异时，进入资金池；需要跨主体或账户调拨时，进入资金调拨。

#### 系统入口

财务 > 资金池  
财务 > 资金调拨

#### 资金池怎么用

资金池列表中，重点看资金对象、主体公司、账户类型、系统/来源余额、可用余额、未识别/待核对、冻结/占用、最近刷新、最近资金动作、主状态。

你需要处理：

1. 查看账户余额和同步状态。
2. 余额差异进入到账流水或资金明细核对。
3. 门店预存待处理进入预存账户确认。
4. 付款占用进入付款执行查看。
5. 异常状态要查来源流水、冻结占用或同步失败原因。

资金调拨列表中，重点看调拨单/调拨主体、调出账户、调入账户、调拨金额、调拨用途、预计/实际到账、主状态、流水/NC。

你需要处理：

1. 新增调拨申请，填写调出账户、调入账户、金额、用途和依据。
2. 待提交状态确认后提交。
3. 审批中查看审批结果。

5. 待到账状态确认实际到账。
6. 已到账后查看流水和 NC。

### 4. 报表与经营分析

#### 你什么时候进入

需要查看经营损益、收款、付款、往来、预付、资金余额等结果时，进入财务报表。

#### 系统入口

财务 > 财务报表

#### 你要怎么看

财务报表不是月底手工做出来的，而是订单、认款、应付、付款、结算、发票、NC 这些对象在系统里自动沉淀出来的结果。

当前财务报表包括：

- 经营损益：看结算单、结算方式、产品/线路、团期/订单、结算收入、确认成本、毛利、毛利率、发票/NC。
- 收款分析：看收款单、来源流水、订单/应收单、客户/渠道、产品/线路、收款金额、入账结果、NC 状态。
- 付款分析：看付款对象、付款单、应付、付款金额、回单和 NC。
- 往来分析：看客户、渠道、门店、供应商往来余额。
- 预付分析：看供应商预付余额、已冲抵、余额风险。
- 资金余额：看资金池余额和账户状态。

> 注意：报表只读，可以穿透到源单，但不能在报表里直接改业务数据。报表数不对，先穿透源单看单据状态和生效口径。

### 5. 期间关账

#### 你什么时候进入

月末、季度末或财务要求锁定某一核算期间时，需要进入期间关账，先做关账预检，再处理缺口，最后执行关账。

#### 系统入口

财务 > 期间关账

#### 进入页面先看什么

期间关账列表中，重点看关账单/期间、主体公司、收入/应收、成本/应付、结算/发票、NC 凭证、主状态。

主状态包括核算中、有缺口、待关账、已关账、已反关。

#### 你要怎么操作

1. 选择主体公司和期间。
2. 发起关账预检。
3. 查看收入/应收、成本/应付、结算调整、发票税务、NC 凭证、关账缺口。
4. 对缺口逐项点击来源入口，回到对应页面处理。
5. 缺口清理完成后执行关账。
6. 已关账期间如需反关，必须发起反关审批。
7. 审批通过后回到关账页执行反关。

> 注意：关账页只显示缺口和入口，不直接修复各模块明细。修复必须回到源单，保证单据链完整。

### 6. NC 推送与异常处理

#### 你什么时候进入

收款、退款、应付、付款、发票、结算、汇兑差异、结算调整等财务事件确认后，系统生成 NC 凭证任务。你需要推送、查看结果、处理失败或缺失项。

#### 系统入口

财务 > NC 推送

#### 进入页面先看什么

NC 推送列表中，重点看推送任务、业务类型、业务单据、业务对象、金额、科目摘要、校验结果、主状态。

主状态包括待推送、推送中、成功、失败、缺失、待同步、人工处理。

#### 你要怎么操作

1. 进入 NC 推送，查看待推送、失败、缺失、待同步任务。
2. 打开凭证任务，核来源单据、金额、科目、辅助核算、客户/供应商、币种、汇率。
3. 对待推送任务执行推送或批量推送。
4. 对失败任务查看失败原因和缺失项。
5. 根据原因修复科目、辅助核算、主体、币种、发票号、客户供应商档案、凭证字段。
6. 保存并重推。
7. 推送成功后保存 NC 返回号和日志。

#### 你要遵守的原则

- NC 页面不能直接修改业务源单。
- NC 失败只影响凭证推送状态，不代表订单、收款、付款或结算失败。
- 如果失败原因是科目、辅助核算、主体、币种、客商映射或凭证字段缺失，修复配置或档案后重推。
- 如果失败原因是源单金额、发票号、回单号、汇率等业务事实不完整，要回到对应源单处理。
- 已成功推送的凭证不能覆盖修改，后续差异走红字、冲销、结算调整或补充凭证。

## 第七部分 财务岗位日常处理顺序

### 1. 应收会计

每天优先看：

1. 到账流水：待识别、部分识别、异常。
2. 认款复核：待复核、差异中、超收待处理。
3. 应收管理：待确认、待收款、部分收款、逾期。
4. 预收管理：待确认、可使用、冻结中、退款中。
5. 预存账户：待处理项、冻结、低余额。
6. 转款处理：待核销、差异中、已核销待凭证。
7. 发票管理：因收款或退款触发的开票、红冲任务。

### 2. 出纳

每天优先看：

1. 资金池：余额差异、待处理资金、付款占用、异常账户。
2. 付款执行：待付款、校验异常、付款失败、待回单。
3. 回单核销：待匹配、待核销、差异待处理。
4. 退款执行：待退款、退款中、待回单、退款失败。
5. 付款退回：待匹配、待确认、待冲销。
6. 资金调拨：待提交、待转出、待到账、已退回。

### 3. 应付会计

每天优先看：

1. 供应商账单：待识别、待挂接、待核对、差异中。
2. 应付管理：待确认、差异中、付款中。
3. 预付管理：待分摊、待冲抵、余额待处理、差异待处理。
4. 付款申请：待复核、审批中、已通过。
5. 发票管理：进项待收票、待核验、票据异常。

### 4. 税务会计

每天优先看：

1. 发票管理：待开票、待收票、待核验、待红冲、异常中。
2. 自动开票任务：抬头、税号、金额、税率是否正确。
3. 税控或电子发票同步失败。
4. 退款触发的红冲任务。
5. 发票 NC 状态。

### 5. 结算和总账

每天优先看：

1. 业务结算：待核对、差异待处理、审批中。
2. 门店对账：待核对、差异待处理、待确认。
3. 渠道结算：平台账单待核对、差异待处理、待确认。
4. 结算调整：待核对、待提交、审批中。
5. 期间关账：核算中、有缺口、待关账。
6. NC 推送：待推送、失败、缺失、待同步。
7. 财务报表：经营损益、往来、预付、资金余额。

## 第八部分 常见异常处理口径

| 异常 | 不要怎么做 | 正确处理 |
| --- | --- | --- |
| 应收金额不一致 | 财务手工改应收 | 回到订单、合同、优惠或补差源头修正 |
| 到账流水无法识别 | 随便挂某个订单 | 查付款方、附言、水单，必要时保留待识别 |
| 认错款 | 删除认款记录 | 做认款冲正，保留原凭证 |
| 超收 | 随便冲其他订单 | 转预收、预存或保留待认 |
| 退款审批通过 | 认为已退款 | 财务执行退款并回单后才完成 |
| 退款账户异常 | 强行付款 | 退回补充账户或进入执行校验异常 |
| 成本依据缺失 | 财务补成本 | 退回履约或计调补供应商账单和附件 |
| 供应商账单差异 | 直接按供应商金额付款 | 做差异处理，必要时补审批 |
| 付款申请通过 | 认为已付款 | 出纳执行成功并回单核销后才算付款完成 |
| 付款失败或银行退回 | 改原付款金额 | 进入付款退回，匹配原付款单后处理 |
| 预付已付款 | 直接当成本 | 后续冲抵实际应付 |
| 发票金额不一致 | 强行开票或收票 | 进入发票异常或应收/应付差异处理 |
| 汇率缺失 | 随便按当前汇率 | 按财务规则选择业务日、账单日、付款日或结算日汇率 |
| 结算后补成本 | 改原结算单 | 走结算调整 |
| NC 推送失败 | 回滚业务单据 | 修复科目、辅助核算、对象、币种或凭证字段后重推 |
| 报表数不对 | 直接改报表 | 穿透源单，检查单据状态和生效口径 |

## 第九部分 学习自检

完成培训后，财务人员至少要能说清这些问题：

1. 订单确认后为什么会自动形成应收。
2. 到账流水、认款单、收款凭证有什么区别。
3. 到账流水识别为订单收款、门市充值、转款入账、退款退回时，分别进入哪个页面。
4. 一笔流水对应多张订单时，如何拆分认款。
5. 超收为什么进入预收或预存，而不是随意冲其他订单。
6. 预收、预存、转款分别是什么对象。
7. 售后退款审批通过后，财务还要做哪些动作。
8. 供应商账单和系统成本金额不一致时怎么处理。
9. 应付金额、可申请金额、本次可申请、本次申请金额、本次实付有什么区别。
10. 预付为什么不能直接当成本。
11. 付款申请、审批通过、付款执行、回单核销、付款退回有什么区别。
12. 发票管理里待收票和待核验有什么关系。
13. 门店对账和渠道结算分别核什么。
14. 已结算后发生后补账单、退款追溯或汇兑差异时为什么要走结算调整。
15. 期间关账发现缺口时为什么要回源单处理。
16. NC 推送失败时应该修什么，不应该做什么。
