日期：2026-10-24。承接进度“订单确认 → 合同签署与收款进度”。本步主要使用人为销售、计调和认款财务；上游是原邮轮预订或按单采购，下游仍为统一合同、收款认领／复核及航次名单。

本次沿用订单原型存储与原合同会话，不建设另一套资金账。历史原型实收保留来源说明；本次登记与财务复核分别留记录。保舱过期只提示回原锁位重新核对，不因客户付款直接重新扣舱。正式订单及签约付款政策仍由业务／财务确认，本单演示选择不作为全公司规则。

## 实施与验收

### 已补充的主承接

1. 销售订单详情和团期订单详情仍使用原“更多 → 转确认”抽屉。核本单舱型／间数、采购或船方确认依据、确认付款条件和签约付款条件；保存核对不确认订单。订金不足、有效占用不足或已关闭订单均保留原结果，不能重复确认或重新扣舱。
2. 原“应收收款”页签新增订金／尾款节点表，沿用预订保存的金额和日期，显示已认款、待收和逾期。未保存分期的旧单保留原总额，不由历史实收倒推订金。确认订单和已收款均不等于已签合同、已出票。
3. 原收款抽屉按订金、尾款等节点登记，提交后进入统一“财务 → 收款应收 → 认款复核”。经办人可从原订单认款记录进入原复核抽屉；复核确认才计入已收，退回保留记录、不改既有实收。结果详情可返回同一订单。没有创建真实银行流水、收款凭证或NC记录。
4. 原合同管理、合同准备和两处订单的合同资料引用本单金额、客人、日期及付款约定；带入本单舱房人数，不套原上海／福冈或三人金额示例。原四步准备、内部审批、逐方签署及历史文书保留。当前本单结果与已签原文书分别保留，不拿新资料改写已签稿。
5. 原订单合同区分别核游客覆盖、必要签署方、我方盖章及整单签约结果。只签游客未盖章仍未完成，双方完成后回显整单结果；尾款仍按财务认款结果展示。

只修改原业务页面，未新增页面或菜单。补充的共享脚本是原订单和原认款页面的处理规则，不是独立邮轮订单或资金系统。实际点击发现两个直接入口问题并定点修正：认款页等待本页资料装入后初始化；从认款和合同反查已保存的邮轮订单时完整加载原详情，避免原局部导航遗漏页头依赖。本步未改共享导航。

### 保留的边界与唯一下一步

- 新订单的具体行程、接待、费用构成和退改资料缺失仍在原合同准备中显示待补；本步不编造来源，不以已收订金代替公司正式签约政策。公司邮轮签约政策、确认付款门槛和正式汇率处理仍需业务／财务确认。本单核对选择不发布为公司规则。
- 签署结果往返验收使用“已审核、平台已受理”的原型起始文书，验证原逐方办理及订单回显；不冒充缺少行程的新订单已经走完真实生成、审核、送签全过程。
- 保留原型会话与本机订单存储的边界，不要求船方、银行、合同平台或NC真实接口；完整预订至真实签约、跨浏览器与后台持续同步未作为完成条件。
- 唯一下一步：沿原售后办理核退订／退款和转团主分支的最终结果，分别交回原库存、名单、合同及款项。儿童、促销、特殊证件等细分规则继续按原评估清单保留，不扩报已验收。
