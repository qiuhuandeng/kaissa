# 平台表格对应原型实施验收

日期：2026-09-28。用户已授权执行《电子合同数据对接与模板结构设计建议》第十一节；本次只实施平台对应，不新增产品业务明细或改写正文。使用角色为集团合同实施管理员，输入为本份合同采用的ERP资料，输出为平台对应配置草稿及本地转换样例。

## 一、页面及改动

唯一页面入口：集团 → 合同管理 → 合同模板 → 新增／编辑 → 平台对应。页面文件 `admin/contract-template-edit.html`，无新增HTML／菜单。

| 区域 | 实施内容 |
|---|---|
| 普通资料对应 | 保留单项平台参数、金额／日期格式和选项对应；与表格配置分为两个页签 |
| 表格资料对应 | 显示平台接收表格、ERP整组来源、对应结果及配置入口；购物／自费来源独立于正文填写项，不要求先插入正文 |
| 单表配置 | 在同一抽屉内进入／返回；逐列选择ERP取值、受控转换方式，显示首条样例结果；平台重复记录与子项参数归折叠的实施维护区域 |
| 转换预览 | 展示源记录及逐行结果，覆盖1条、3条、第二条缺项、无安排、未取得资料、有安排无记录；可切换本单采用的经济款／品质款样例 |
| 保存与权限 | 保存草稿重开保留对应，放弃修改不覆盖；变化使原模板预览失效；送审后只读，普通合同管理员无技术入口；保存不改变原启用版本 |

结合产品源码的来源定义严格沿用原两张表的六列：

- 购物：场所名称、所属行程、城市/国家、经营品类、停留时间、合同展示名称。
- 自费：项目名称、所属行程、城市/国家、参考价格、服务时长、合同展示名称。

当前页原样例保留“约60分钟”“EUR 85/人”“半日”等事实；用于通过转换的另一组样例明确标为转换样例，不将其回写产品。购物表按用户截图表达六列，自费目标标为结构样例；所有实际平台参数和必需条件仍待接口核实。已有游客、日程、费用、邮轮／研学／服务标准对应继续保留。

## 二、关键规则

1. 整组对应确定记录范围，逐列对应确定同一条记录的各项取值；3条记录保留3行，不串行、不因缺项静默删行。取本单采用线路及版本，不混入同产品另一线路。
2. 使用稳定的集合、列及配置标识；中文名称和页面列顺序不作为正式取值依据。旧参数／子项文字配置可迁移到列控件，资料改显示名不丢对应。
3. D2只引用本单行程对应日期，不能补造时刻；全程不默认第1天。预览明确具体时间格式待接口核实。
4. “约60分钟”不等于最长60分钟；明确“最长／不超过”的时长才允许受控转换为分钟。来源缺少含义时给出具体行列问题。
5. 自费参考价不自动当本次约定费用，不只提取数字忽略币种和计价单位；无同义来源的样例选填列省略，不伪造“无”。
6. 无安排、来源未取得、有安排却无记录分别提示。无安排不制造空白行；平台省略还是传空记录仍待核实。
7. 配置完整性与数据问题分开报告。错误表格不进入可传递参数样例；预览始终为本地结果，不表示平台接受。
8. 现有产品增删和保存代码只作为来源结构证据；本次未修改产品页面、产品存储、合同准备、正文或正式读取接口，不新增跨页面持久化。

## 三、改动文件

- `admin/contract-template-edit.html`：加载两份平台对应共享脚本。
- `shared/contract-platform-tables.js`（新增）：资料集合、按场景的目标表格、逐列转换、线路／版本筛选、异常及样例。
- `shared/contract-platform-ui.js`（新增）：平台对应抽屉、两页签、单表配置、接收参数及多行预览。
- `shared/contract-settings-ui.js`：原平台入口接新抽屉，保留模板版本、权限及保存流程。
- `shared/contract-template-fields.js`：普通资料与独立表格配置共同核对、生成本地传递结果；兼容旧配置。
- `shared/contract-settings.css`：平台抽屉、表格列宽及内部滚动、固定操作列、窄屏布局。

新增规则与浏览器脚本 `scripts/check-contract-platform-tables.cjs`、`scripts/check-contract-platform-tables-browser.cjs`；既有字段浏览器脚本调整对应入口，保留普通项／正文／审批回归。
