# 应收应付余额主表重组验收

2026-09-15｜整体页面方案6.10｜本轮仅应收余额、应付余额两个主题。

## 页面任务与业务链路

入口：数据中心 → 资金核算 → 往来账龄 → 应收余额 / 应付余额。

应收会计先判断客户、渠道截至某日还欠多少；应付会计先判断供应商还有多少待付。上游为已确认应收应付、有效调整、收付核销、预款冲抵、批准减免及到期日变更。核销是用已确认款项或批准冲抵减少相应欠款；已核销不等于现金已收已付。账簿是公司使用的具体核算记录范围，不同账簿不直接混加。

本页只读查询、按条件核对及导出。认款、付款、核销、调整的办理仍在财务业务菜单；不新增点击下钻，不改变订单、团期或门店。

## 保留主题与遗留

- 应收、应付之后仍为账龄分析、内部清算、订单收付；本轮不把它们装入“统计层级”。账龄和内部清算保留原页面及计算，下一步单独重组。
- 原确认、调整与核销属于余额的来源，不能因为有关联就在余额页拼成发生额报表。当前可选核销净额用于余额分解；逐笔核销归收付明细的核销明细，期间往来变动尚待独立补充，不宣布已完成。
- 订单、组织、确认日期、到期日期限定当前单据范围；汇总不是忽略筛选的整个往来单位全账余额。名称/余额情况筛选则保留匹配单位在上述范围内全部单据。
- 不同公司、账簿、原币和往来性质分别显示；内部资金清算另查，不净额抵销、不生成集团合并结果。
- 当前使用独立算例；正式历史、财务批准规则、权限和实账平行核对仍未交付。源办理页面不在本次修改范围。
- 16入口79Tab保留，多表Tab由20降至18；原8批完成状态保持。订单/回团字段、成本构成、供应商回收依据等原待办仍保留。
