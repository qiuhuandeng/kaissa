## 1. 角色、上下游与页面归属

销售顾问从已确认订单准备合同，从售后确认记录准备变更，日常在合同管理核对内容、发起签署及办理异常。审批管理员维护公司与事项流程，审批人在审批中心处理本次版本。合同管理员核对归档结果并保留历史文件。项目负责人提供项目和客户信息，在合同管理继续准备，不能在项目页给自己审核通过。审计人员在集团操作审计查配置、办理和文件访问记录。

合同金额变化、解除及归档均不替代售后、收款或退款确认。未完成的补充协议不计入已签约定金额，未完成的新版本不替代原版；解除内部审批通过不等于完成解除。

## 3. 关键规则与金额验算

- 补充协议：30000＋3000＝33000；30000－3000＝27000；仅变集合地点的零金额补充，仍为30000。签署完成前只计原已签金额。
- 新版本：原版30000，新版33000。草稿、审核及部分签署期间原版仍为当前版；新版必要签署方全部完成并我方盖章后才替代。当前金额为33000，不累加成63000，旧编号、旧签名、文件及记录保留。
- 新合同不复制原版签名、平台编号、备案结果或已取得文件。未确认依据、同一依据重复生成、已有未完成变更、原因缺失均拦截。
- 平台已受理且尚无签名可申请撤销；受理结果未知先核对。有游客签名时走解除，不冒充未签撤销。
- 撤销／解除申请单独审批；退回需原因，可修改重提并保留前次记录。内部批准仍保留原合同状态；协议未签、超时及办理失败均不标完成。只有对应完成结果样例才改为已撤销／已解除。
- 解除后保留原文件和办理文件入口，不改订单收款、订单金额或退款结果。
- 企业归档：文件、双方盖章和代表授权齐备才能送审；内部通过仅到待归档。归档确认后纳入合同覆盖及当前约定金额，不伪造电子签名。替换版本审核退回、待归档时旧版仍有效；新版本归档完成后旧文件仍可查。
- 已上传的归档文件在保存前只属本次未保存内容，取消离开不覆盖原先保留的文件；支持20MB以内PDF／图片。样例明确标注，下载生成实际文件。

## 4. 可复核的样例与使用顺序

1. 初次签约：合同列表查`ORD-CONTRACT-NEW-30000`；订单有3名游客，支持合签或每人10000分签。沿用第2步预览、审核、发起及各方签署流程。
2. 增补或新版本：查`ORD-REVISION-33000`，已签原合同30000；详情变更选择`SH-ORD-REVISION-33000`。另有待确认来源用于验证拦截。变更方式可选补充协议或新版本。
3. 减额补充：查`ORD-REDUCE-27000`，确认服务减3000；原版30000，完成补充后27000。
4. 零金额变更／解除：查`ORD-JOINT-30000`。详情可做集合地点变更；解除在独立申请中演示待审核、退回、协议未签、未知、失败和完成。两种未完成办理不能同时提交。
5. 企业归档：查`KSMICE20260713003`，依次选文件、勾双方盖章及授权、送审、切换审核结果、归档确认，再建替换版本。电子模板已支持的独立样例为`KSMICE-ELECTRONIC-001`，可从电子合同草稿继续办理。
6. 审批中心：首次、变更、撤销、解除、归档、模板申请编号为`APR-CONTRACT-001`至`006`。页面内审批可操作，与销售页独立样例明确区分，不要求刷新后自动同步。
7. 原型配置顺序：集团接口配置与公司签约资料 → 合同模板及启用 → 基础参数合同规则 → 门店选用 → 审批配置 → 订单准备合同。第1步资料未齐场景仍可演示阻断，不用假账号和接口成功解除阻断。
