## 一、这一步验收什么，谁接谁

产品和计调提供已授权销售的产品、团期、价格、名额及采购依据；营销运营配置券、适用人群、产品团期、销售范围及承担条件，经适用审批后发放。销售根据真实游客、有效价格和可用权益形成订单；计调继续处理资源与履约。渠道人员按合同核对佣金或分润；业务审批承接已确认订单的收费变更；财务核对实际资金、往来、渠道费用、结算和凭证。报表按同一订单及规则版本引用结果。

本组要逐笔回答：客户少付了多少；哪个部门或公司承担；旅行社实际收到多少；供应商和渠道各应结多少；取消后退钱、退券、退积分及追回佣金各是多少。不能只凭“券已使用”或“对账完成”判通过。

应收是对方已经欠本公司的款，应付是本公司已经欠对方的款；有效应收总额与尚未收回的余额分列。法人公司是独立承担交易责任的公司；同法人门店的内部经营分配不自动形成公司间欠款。佣金是按约定支付给销售合作方的报酬；分润是按约定基础分配的经营收益，二者不能仅凭页面名称互换。

## 四、逐组业务场景

### 惠01：从活动建券到回团财务的连续主样板

**办理。** 按第三节创建资料，营销审批券及活动并发给会员；销售从新建产品团期下单，选实际同行游客，预留券和积分，按已批准节点确认订单、签约、分次收款；计调执行出团回团、逐笔确认35,000成本；财务办理付款、业务结算、收入成本确认及凭证。

以下采用专用测试约定：报价仅展示；预留冻结权益；订单业务确认时将优惠计入有效应收并转正式使用；不因尾款未收提前反复扣积分。正式触发节点不同，须先替换预期。

| 节点 | 客户有效应收 | 实际累计收款 | 客户待收 | 积分余额 | 冻结积分 | 可用积分 | 券状态及财务承接 |
|---|---:|---:|---:|---:|---:|---:|---|
| 建券发券并报价 | 0 | 0 | 0 | 5,000 | 0 | 5,000 | 可使用；报价49,100，未形成实际优惠费用或渠道款 |
| 创建未确认订单并预留权益 | 0 | 0 | 0 | 5,000 | 2,000 | 3,000 | 已预留；独立核团期5席占用条件 |
| 订单业务确认 | 49,100 | 0 | 49,100 | 3,000 | 0 | 3,000 | 已使用；券1,000与积分200各生效一次 |
| 首款到账并认款15,000 | 49,100 | 15,000 | 34,100 | 3,000 | 0 | 3,000 | 收款不重复用券或扣分 |
| 尾款到账并认款34,100 | 49,100 | 49,100 | 0 | 3,000 | 0 | 3,000 | 不把券和积分当作额外现金实收 |

**逐步留证。** 发放、预留、正式用券、积分冻结／消耗、订单收费行、认款、资源费用、付款、确认和凭证必须连到同一源订单。主例暂设本单不赠消费积分，赠分另见惠12；不能用后续赠分掩盖重复扣分。国内同样优惠时48,800－1,000－200＝47,600；无签证费用也不得扩大团费优惠基数。

### 惠02：门槛、折扣、人数与不可优惠项目

**独立分支。** 每次只使用表中一种券，无积分、无其他优惠；先核费用行，再提交确认。

| 输入和规则 | 应得结果 | 必须识别的错误 |
|---|---|---|
| 可优惠45,999.99，附加4,300，满46,000减1,000 | 不满足；50,299.99保持原价 | 用订单总额跨过门槛 |
| 可优惠46,000／46,000.01，附加4,300，同券 | 分别49,300／49,300.01 | 边界四舍五入后错误放行或拒绝 |
| 团费46,000打9折，最多优惠1,500 | 实际优惠1,500，总应收48,800 | 把9折当优惠90%，或把4,300附加费一起打折 |
| 同样9折但无最高优惠限制 | 优惠4,600，总应收45,700 | 将上一张券的封顶带入另一张券 |
| 2成人＋1儿童团费26,000减至24,000；本单4成人＋1儿童 | 只命中一组，减2,000，应收48,300 | 多出来的2成人也减至组合价；忽略儿童不足而算两组 |
| 旧按人直减200，规则明确仅4名成人 | 减800，应收49,500；游客仍5人 | 因优惠4人把名单或团期占用改成4人 |
| 独立订单可优惠1,000＋不可优惠500，券面额2,000且允许封顶 | 实际优惠1,000，应收500；承担按1,000分 | 消耗面额2,000并形成负应收；若正式规则禁止截断则整次拒绝、权益不扣 |

套餐游客选择按批准的价格优先和身份规则；再测成人价格不相同、免团费儿童、换人、人数不足及多个组合。免费接送服务券没有现金折抵：在惠01基础上另赠原订单未包含的一段接送，成本300，客户仍49,100，实际成本35,300，经营差额13,800；不重复登记原接送服务，服务领取与使用次数、采购成本仍需核对。

### 惠03：叠加、会员价与办理顺序

**输入与办理。** 建两个允许合用的券：团费直减1,000与团费9折无封顶，其他4,300不参与。分别在两张新订单按相反点击顺序选券。正式规则须事先选择计算顺序，不由操作先后决定。

- 若批准“先直减再折扣”：46,000－1,000＝45,000，再减4,500，总应收44,800。
- 若批准“先折扣再直减”：先减4,600再减1,000，总应收44,700。两种政策相差100，不能择与系统一致者当正确答案。
- 若两券互斥，测试约定取最大优惠时只减4,600、应收45,700；不默认系统一定自动择优，实际选择／告知方式须有规则。
- 主例积分上限按券后45,000×2%＝900；上限测试另用经批准发放且可用积分12,000的会员，分别新建订单验证9,000积分可抵900、9,010积分不可抵901，排除余额不足的干扰。若正式规则按券前算，上限920，必须另列规则版本，不混用。
- 会员价若使可优惠团费从46,000降到45,000，总价49,300；本例门槛按会员价后，满46,000券失效，应收仍49,300。会员价已生效，不能再重复减1,000会员价差。

两种点击顺序、删除其中一券、先抵分后选互斥券、人工优惠尚待审批均检查：失败不能留下券占用或积分消耗；已确认订单改优惠继续走第三组业务变更，不直接覆盖有效应收。当前新活动没有自动优惠入口；历史自动优惠按旧记录核账，不重新套当前券规则。

### 惠04：资格、销售授权与真实时间边界

**办理。** 券限定A公司M1、指定出境产品及两个团期，持券人本人或同行可用；用M2、B公司、其他团期、未同行持券人、冻结账户和未授权销售账号分别尝试。持券人与付款人、游客联系人不是同一概念；付款人为家属不自动等于盗用券，按获准的使用人条件判断。

同一产品分别放入自营与外采订单：外采适用政策未定时标“规则待确认”；批准不适用后必须拒绝且不扣权益，批准适用后继续核券承担和外采采购款。国内专属券用于出境团也同样验证。

时间测试明确测试环境时区，分开发券时间、领券截止、用券截止、下单日期与出发日期。以测试规则用券截止某日23:59:59为例，在截止前、恰好截止及下一秒用真实服务端时间验证；切换浏览器时钟不能代替后台时间。活动停发是否使已发有效券失效、券延长一次还是不延长须按已批准条款；停止新领券不能悄悄改掉已确认订单价格。

每次拒绝同时核订单应收、款项、券、积分、团期及渠道名额。只拒绝了用券但留下完整订单，可作为另一条合法办理结果；必须清楚表明订单是否创建，不能把所有失败都假设成整单回滚。

### 惠05：领取额度、使用额度、预算与并发

**输入。** 建发放100张、每人1张、指定团期仅允许使用1张、每张1,000的活动；另建实际优惠预算1,000的版本。发放数量、团期用券数、预算金额与20席团期库存分别核对。

**办理。** 两名合资格会员用独立会话同时确认不同5人订单；另测同一会员同一券在两个订单同时使用。环境健康、规则允许其中一单且无其他请求时，只有一笔1,000优惠成功；预算正式占用／消耗不超过1,000；另一单如何保留原价或等待客户确认按产品流程记录，不擅自高价成交。不能因两张订单都能付钱就算并发通过。

预留后超时、支付回执迟到、接口超时但已成功、失败任务重试、活动剩1张时批量发2张、重复发放名单、停用后后台任务继续执行均单独跑。预算是否因取消恢复、过期券是否恢复可发张数须有规则；恢复只作用于原活动、原承担方和原数量，不能返到新活动预算。跨店转单、转团和复制订单不能复用同一权益消耗记录。记录真实服务端响应和最终只读数据；顺序运行两次不能声称并发验收。

### 惠06：同法人门店承担与独立加盟佣金

**直营分支。** 惠01的A营销800、M1的400是同一法人内责任分配；可按批准管理规则影响门店贡献，但不凭标签虚造对外应付、转账或税票。销售从M1转M2后，历史优惠承担不自动转给M2；获准重归属时保存调整记录。

**独立加盟分支。** 新建F代理销售、A签约履约的订单，不用积分。团费46,000按专用5%计算基础佣金2,300；券减1,000由A承担600、F承担400，按本例合同从F佣金扣其承担，客户应收49,300、F应结1,900。实际资源成本35,000，A经营贡献49,300－35,000－1,900＝12,400；与无券贡献13,000相比只少A承担的600。

分别跑客户直接向A付49,300、F获授权代收49,300后全额转A再收佣金1,900、F获授权抵扣佣金后净转47,400三条路径。净转路径A银行实收只有47,400，另1,900以有效抵扣结清，不把银行流水虚增到49,300。客户缴款、F欠A的代收款、A欠F的佣金分别有原始依据；没有抵扣授权时，F只转47,400仍欠A1,900且A仍欠F佣金1,900，不能自动双清。

### 惠07：外采门店按可分配差额分润

**独立输入。** 客户原价100,000、已确认外采成本80,000；合同暂定优惠前差额20,000按F80%、A20%分；客户券1,000由A600、F400分别承担，不用积分和其他费用。F为独立合作方，A负责游客合同。

**办理与核账。** 客户有效应收99,000；F原分配16,000减其承担400后应结15,600；A原留存4,000减600后留存3,400。两者合计19,000＝99,000－80,000。不得先将已优惠差额19,000按80%分出15,200，再扣F400算成14,800。

核预估、待成本确认、正式应结、审批中、实付和已结：仅预估不能付款或增加预存可用余额。F应结15,600，实付10,000且批准抵扣2,000，剩余应付3,600；另外失败的付款3,600不计已付，支付结果未知先查询。共同费用、F专属费用和已在80,000内的费用分别测；缺成本不能默认为零分出虚高收益；负分润按批准合同形成待处理或追回，不擅自归零。

### 惠08：分销商净结算价与游客优惠分开

**输入与办理。** D采购转售A的参团产品，A对D约定结算价40,000；D自用采购优惠券500，仅减少D应付A。A成本35,000。正常源头创建D采购订单、源团期和实际游客资料，再应用D专用券。

### 惠09：平台优惠、合作方补贴与供应商承担

**平台代付分支。** 原价50,300，A商家优惠800后客户有效收费49,500；P获准代客户承担其中300，客户掏现金49,200。P服务费按49,500的2%为990；P向A净转48,510。对账应列客户49,200＋P代付300＝49,500，减服务费990＝48,510；不能把300既减客户合同收费又列额外补贴收入。A业务贡献49,500－35,000－990＝13,510。平台尚未结算时保留平台待转款，不冒充A银行已到账；平台付款减预留款、退款或拒付须单列原因，不直接改收费。

**额外营销补贴分支。** 与上例互斥：客户自行付49,500，合作方另按协议欠A营销补贴300，不是代客户支付；同样服务费990。补贴尚未获确认不能算到账或已实现贡献；正式确认并按本例业务口径归集后，含该补贴的贡献13,810。税票、会计科目及确认期间另按政策，不直接记旅游收入。

**供应商承担分支。** 另建原价50,300订单，券减1,000，A承担600、S承担400；客户应收49,300，原采购35,000。S确认以采购结算减400承担时，净成本34,600，经营差额14,700；若协议是保留35,000采购并另确认补贴400，则用49,300－35,000＋400核同一业务差额。两条互斥，不能同时少付400又多确认补贴400。S未确认承担前保留争议400，不能从待确认直接变成少付或客户追加欠款。

**对账异常。** 平台少转10元、重复账单、订单跨两个结算批次、手续费基数不同、优惠来源缺失及退款后服务费不退均保留逐笔差异；不新增“其他优惠10元”强行核平。

### 惠11：部分退团跨过满减门槛，且佣金已支付

## 五、AI执行时必须保存的证据与判定

每例保留：适用规则原文及批准版本、测试输入、预期计算、实际产品/团期/订单/券/积分流水/采购/结算/凭证编号、执行岗位、服务端时间、页面与接口结果、只读查询或导出、金额差异及失败后是否仍有占用。这里的接口和编号要求是面向自动化执行的记录规范，不要求业务人员手工填技术字段。

一次完整比较至少分四层：客户费用及欠款；权益数量及承担；各公司和合作方的应结、实际收付及未结；结算贡献和财务凭证。按原币最小单位精确比较本组人民币金额；不默认允许1元误差，尾差只按已批准办法处理。对账总额相同但公司、游客、券或费用行不一致也不通过。

负例开始前保存相关业务状态，失败后查询并确认哪些业务已成立、哪些未成立。遇到未知支付或结算结果先查询原业务，不能换一个新编号盲目重付。两会话并发、后台定时、跨日和重启必须有真实执行证据，独立算术程序不验证这些行为。

规则未定先标对应例“规则待确认”，继续独立可执行的例；自动化执行失败不能自动判业务失败。正式财务预期尚未批准时，停在该政策的验收判定处，保留已完成业务证据，不伪造凭证科目或给出全链路通过结论。
