# 集团旅行社岗位业财主流程审查与优先改进方案

日期：2026-09-24。状态：审查与建议，待用户确认实施范围；本次未修改业务页面。

## 一、判断与审查边界

**现有系统已覆盖主要岗位和业务对象，可以作为整体原型基础；但还不能把“各模块原型基本做完”认定为“各岗位交接到财务报表的主流程已经完整”。** 当前最需要补的是确认责任、交接依据、金额变化和异常返回路径，而不是再铺一批菜单。

现行代码中可以直接确认的问题包括：普通审批一次通过即整单结束；结算页把实收零替换成订单金额、按固定比例拆订单；供应商账单挂接覆盖我方成本；业务结算直接产生待推凭证；借贷不平的凭证仍可显示推送成功。这些会让下一个岗位收到不可靠的结果，优先级高于界面细节。

本次按集团旅行社的岗位职责归纳为20类工作角色，并不认定贵公司必须设置20个独立岗位。实际人员可以兼岗，但“业务经办、业务确认、财务复核、资金执行、审批”应在流程中区分；具体兼岗和授权由公司确认。

审查方法：

- 按项目要求读取总纲、五类财务需求、进度、总对照表、已确认集团报表方案及执行清单；检查通过，原8批、36项、6场景维持原验收状态。
- 盘点集团端、业务端、供应商端、领队端及共享导航，按岗位路径核对业务页面、共享处理逻辑和对应流程文档。
- 对关键现行函数做8项隔离算例核验，结果见附录。检查时版本为df0de06，工作区原先无未提交修改。
- 本次是全链路设计审查和关键金额、状态逻辑核验，不是全站逐按钮浏览器验收。历史验收仅用于识别已有成果，不作为本次新验收。

**原型不接后台、各页使用独立演示数据，不单独判为缺陷。** 但当前页点击“确认”后，至少应能演示正确的结果、记录、异常和承接去向；不能仅用成功提示代替核心业务判断。以下方案均可先用各页固定但可核对的样例完成，不要求跨页自动回写、真实银行、真实NC或真实合同平台。

本文使用的财务名称：

| 名称 | 业务含义 |
|---|---|
| 法人公司、核算公司 | 前者承担合同和对外责任；后者是财务独立记账的单位，两者不能仅凭部门名称推定 |
| 应收、应付 | 已确认应向客户等收取的金额、应向供应商等支付的金额；不表示已经收付，也不直接表示会计收入成本 |
| 预收、预存、预付 | 已收但需后续处理的客户款、客户或门店留存的账户款、已先付给供应商的款；各自余额与用途须核对 |
| 核销 | 把确认的款项、冲抵或调整对应到具体应收应付，减少相应未结余额 |
| 业务结算 | 业务与财务核对一团、一项目或一项服务的有效成交、成本、收付和差异 |
| 收入确认、成本结转 | 财务依据实际履约和批准政策，决定本期应记收入及对应成本；不能以收付款替代 |
| 暂估、会计期间 | 暂估是依据已发生业务及批准方法估计尚待最终核对的金额；会计期间是财务记账所属月份或期间 |
| 内部往来 | 集团不同法人之间因采购、代收代付等形成的双方待结金额；同法人部门协作另行表达 |
| NC、OTA、MICE | 分别为公司财务核算系统、携程飞猪等在线旅游平台、会议奖励旅游及会展等项目业务 |

## 二、先把各岗位的工作串起来

### 1. 一笔业务不是一条从头走到尾的直线

### 3. 每一次交接必须交清的内容

不要求把下面内容堆进每个列表，应放在相应办理抽屉、详情和处理记录中：

1. 哪张订单、哪个团期/项目/服务、哪份采购或账单。
2. 本次由谁代表哪家公司确认，下一岗位是谁。
3. 本次确认的数量、服务范围、金额、币种和依据；与原来相比变化多少。
4. 确认后改变什么状态，以及应收、应付、资金或利润中哪项受到影响。
5. 哪些尚未确认、哪些仅是预测、哪些已经生效。
6. 退回什么内容、由原岗位在哪里修改、重提如何保留原记录。

## 三、按优先级的问题与解决方案

优先级依据是错误金额、越权确认、岗位无法承接和集团账无法对清的影响，不按页面数量排序。P0建议优先确认范围；P1补齐专项与常见异常；P2完善岗位使用和验收。不将本文编号新增为原报表执行批次。

### GW-01｜P0：审批配置与日常审批办理尚未连成同一流程

**涉及岗位：** 经办人→部门/业务审批人→财务或其他后续审批人。

**现状与问题：** 集团已有可配置节点、条件及规则的审批模板，另有逐节点模拟办理能力；但普通审批页仍把一次“通过”改成整单“已通过、已完成”。“进入下一节点”的提示与实际状态不一致。组织申请已有单节点核准，不等于全部日常审批已使用发布模板。见E01、Q04。

**方案：** 沿用已建配置，在日常待办和来源提交预览中明确本次使用的发布版本、当前节点、当前可办理人员及后续节点。每次仅完成本节点，最后一个必需节点办完才整单通过；退回重提、撤回、人员停用、兼岗、自审和转交分别表达。供应商已明确走致远的范围不改回通用审批。

**修改位置：** 集团审批配置、业务审批列表与办理抽屉；首轮选付款申请、结算调整两类代表事项，复用已有组织任职和审批规则。已有工作线的执行授权保持，本报告不重建或重复立项。

**验收：** 部门负责人→财务→最终审批人三节点，第一人通过后仍在审批中；非当前审批人不能办；退回再提交不沿用不适用的旧通过结论；审批通过仅代表获准执行，不显示已付款。

### GW-02｜P0：客户款项与资金执行的几个阶段仍被混为一个结果

**涉及岗位：** 销售/售后→收款及应收会计→退款会计/出纳→结算会计。

**现状与问题：** 已有认款、预收预存、退款、转款、付款及回单页面，并非缺这些模块。但销售认款的金额差只标红，提交仍只提示成功；财务复核可直接显示应收已核销。退款关闭可被显示为应收已冲销。转款退回把原申请金额改为零，冲正把原金额改负，失去原申请与后续调整的区分。付款登记成功后仍为待回单，上传回单才改已付款；付款/退款重试会清除当前银行执行标识。见E02—E05、Q05。

**方案：** 同一业务中分别展示“交易金额变化、已批准退款/转款、资金执行结果、应收应付调整、回单核销”。销售只认领归属，财务确认真实到账和可分配金额；同一原收款的已退、已转及处理中金额共同占用可用额度。出纳登记真实支付成功即可表达已付款，回单及核销单独跟踪；执行结果不明先核实，不直接当失败再付。原申请和每次执行保留，冲正另记关联调整。客户退款与供应商追款分别办理，不互相冒充已完成。

**修改位置：** 收款认领、认款复核、售后处理、退款执行、转款处理、付款执行及相关详情；复用已有入口，不新设一个重复资金中心。

**验收：** 到账10,000不能认领12,000；原收款10,000，已退2,000、有效转款3,000，剩余可用5,000，处理中申请不得重复占用；订单减价2,000尚未退款时交易减少与现金未退分别可见；退款申请退回不会显示已冲销；线下支付成功但未传回单仍正确显示已付款及缺回单；重试保留第一次失败依据。具体核销、非原路退款和差额政策由财务确认。

### GW-03｜P0：供应商账单核对会覆盖业务成本，差异没有真实交给责任岗位

**涉及岗位：** 供应商→采购/计调→成本会计→应付会计。

**现状与问题：** 供应商账单已有识别、挂接、核对、差异、退回及应付承接。但“确认挂接”把供应商账单金额写成我方系统成本并清差；“核对一致”等选项也可直接清差。挂到哪个团不等于认可供应商金额。供应商端确认账单主要还是关闭抽屉，未形成当前对象的处理结果。见E06、E07、Q03。

**方案：** 并列保留我方已确认成本、供应商原账单、本次认可/不认可金额、尚待处理差额及证据。计调确认人数、天数、资源、服务和损耗事实；财务确认债务及付款条件。挂接只建立对应关系；有差异按责任退业务补成本或退供应商改账单。只允许已确认范围进入后续应付；部分确认是否允许结算和付款由财务政策确定。

**修改位置：** 团期结算成本明细、供应商账单核对抽屉、供应商端账单办理、应付来源明细。

**验收：** 我方80,000、对方82,000，挂接后仍差2,000；如本次只认可补差1,000，则认可81,000、剩余争议1,000及原双方金额均保留；再次提交不能重复计入已确认部分。不能点一个“无差异”把争议消掉。

### GW-04｜P0：计调交给结算会计的订单和收入依据仍可能由总额反推

**涉及岗位：** 销售及收款会计→计调/项目经理→结算会计。

**现状与问题：** 团期结算已有成本、预付、账单、项目验收及提交操作，但订单收入按62%/38%拆分并拼接订单号；实收为零时会回退成订单收入。独立算例中应收10,000、实收0被算成已收10,000、未收0。这不是“模拟数据不同”，而是同页计算掩盖了未收款。见E08、Q01—Q02。

**方案：** 在现有结算页提供逐笔固定演示订单和有效变更，汇总真实列出的明细。区分原成交、有效增减、当前应收、实收、退款、优惠承担及未收；零保留为零，缺依据显示待确认。业务确认实际服务与成本，财务核对客户款和结算范围；未收款、未付款作为余额独立列示，不一律等同不可结算。

**修改位置：** 团期结算明细和提交核对，财务业务结算的来源依据、补充结算。保持团期订单与销售订单两个独立入口。

**验收：** 两笔明细6,000、4,000汇总为10,000；实收0仍显示未收10,000；一笔部分退款、一次跨月补差可解释原额及变化；详情、汇总和导出同口径。复用既有结算后追加调整能力，不重新做第二套。

### GW-05｜P0：业务结算直接越过财务核算到NC，期间关账也缺少正确分流

**涉及岗位：** 结算会计→收入成本核算会计→发票/总账负责人→财务分析。

**现状与问题：** 财务业务结算确认后直接生成凭证号并置待推送；现有NC样例借成本297,800、贷收入441,600，差143,800仍标校验通过，推送处理直接改成功。期间关账按展示文本判断问题：虽然对白名单“未到期”等文字放行，但非零待收、未冲抵预付等金额会直接列阻断，没有正常余额与真正异常的完整分类。报表已区分会计确认与业务结算，办理端未形成对应职责。见E09—E11、Q06—Q08。

**方案：** 在现有财务业务结算详情增设独立的核算办理区或二级处理页：核实际完成范围、已结算范围、收入方式、成本依据、价税、期间及本次调整；未定政策显示待确认。业务结算完成只进入待核算，核算确认后才准备相关凭证。NC端用可核对分录校验借贷、公司、币种、期间和来源，区分待发送、处理中、成功、明确失败及结果待核实。关账分正常余额、正常时间差、批准跨期事项、必须处理异常，分别办理。

**修改位置：** 财务业务结算详情、结算调整、发票关联信息、NC推送、期间关账；数据中心核算核对继续只读。

该办理区还应按批准政策容纳“服务已完成、最终结算未完成”的财务处理，例如有依据的暂估。不能机械要求收齐款、开齐票或全部付完款才确认收入成本；具体允许条件与金额方法由财务决定。

**验收：** 同一项目业务结算已确认但核算政策未定时不能冒充会计收入；借贷相差143,800不能通过校验；正常未到期应收在批准规则下可保留余额关账，未处理错误按规则拦截；9月确认后10月补成本，保留9月原确认及10月调整，不覆盖原期。不自行给出会计科目、总额净额或暂估政策。

### GW-06｜P0：集团跨公司业务有展示口径，缺少双方日常确认与差异处理

**涉及岗位：** 销售公司、产品/履约公司、收付款公司及各自财务→集团财务。

**现状与问题：** 订单详情已经列签约、履约、采购、收款等责任说明，核算报表已有内部对账及差异样例；但在现行财务导航和办理页中，未找到与这些报表对应的内部双方确认、退回及清算主路径。资金调拨不能替代产品互采结算，报表中的“双方确认依据”也不能替代日常办理。见E12。

**方案：** 新增“内部结算”办理能力，建议归财务结算对账组，供有权限的双方财务处理；集团看未对齐项。区分跨法人产品互采、跨法人代收代付、同法人部门协作。订单按既有公司与合作规则带出责任，冲突交业务负责人和财务处理，不让销售填写一长串核算字段。双方分别确认金额、原币、范围和期间；同法人协作不生成虚假法人往来。集团层的内部抵销须有已批准范围和依据，不由任一公司直接清掉双方金额。

**验收：** A公司卖给客户10,000，B公司内部供给8,000、对外成本6,000，在明确采用总额经营分析的样例下，双方内部8,000能够对应，集团对外收入10,000、对外成本6,000，不把内部8,000重复算收入；另测代收5,000与产品互采不同、双方8,000/7,800保留差200、期间不一致不假装对平。会计确认方式仍待财务批准。

### GW-07｜P1：外采订单“供应商回复→销售重新确认”还不能完整演示

**涉及岗位：** 供应商操作人→外采计调→销售→客户；财务接最终采购依据。

**现状与问题：** 产品市场已经区分参考名额与确认供给；供应商订单页也有已确认、暂时保留、无位、需补差等字段。但不同订单按钮打开同一个抽屉，未按所点订单绑定办理；“回传确认结果”仅关闭，未保存当前页结果、确认号或差价。见E13。

**方案：** 供应商针对本单记录接单结果、确认数量、原价/补差、保留时效和依据；外采计调处理供应方事实，销售负责客户是否接受补差或替代。未获客户同意不得把需补差当成交确认；无位、超时和取消分别表达名额及资金后续去向。原型可在三端各自演示同一业务故事，不强求自动互写。

**验收：** 已确认、限时保留、无位、加价客户接受、加价客户拒绝五条路径；本单回复不覆盖另一订单；拒绝后原订单、占位、客户退款和供应商追款分别可见。

若首轮就包括需二次确认的外采订单，本项应随P0一起完成。

### GW-08｜P1：交通采购减量未充分考虑分类型价格和已使用资源

**涉及岗位：** 交通采购/调度→团控→成本会计/付款岗。

**现状与问题：** 减量用主类型单价计算整个合同；付款节点重算为零时又取原金额；总数量变化仅在单一类型时同步，且该保存处理未核对各团已分配数量下限。影响包舱多舱型、专列多铺型及部分已使用资源。见E14。

**方案：** 在既有变更抽屉按舱型/铺型/席位类型处理数量、单价、已分配、已确认使用、可释放及损耗；分别列原合同额、变更额、已付、后续应付、供应商应退。零是有效金额，不回退为旧金额；已占用部分先明确撤销/改配或拒绝直接减量。

**验收：** 100位已分配60，减到80后余20；减到50须先解决已分配部分；全部未使用资源撤销后后续应付允许为零；两种舱型按各自价格计算，不能全用第一舱型价格；已经付款不因减量直接显示追回。

### GW-09｜P1：门店/渠道对账能显示差异，但办理仍可能清差或重复形成财务结果

**涉及岗位：** 门店财务联系人/渠道运营→结算会计→收款及应付会计。

**现状与问题：** 门店财务对账“确认无差异”直接把差额归零，“确认对账”直接产生待推凭证；OTA运营侧保存、提交主要是成功提示；渠道财务侧也可选择无差异后清零。现有页面已有订单、退款、佣金、优惠等栏目，因此重点是把核对动作做实，不另建同类报表。见E15。

**方案：** 对账保留订单有效额、退款、佣金服务费、各方优惠补贴、实际到账、预存变化及未结余额。只有有来源调整/确认记录的差异才能关闭；对账确认本身不重复制造收款或收入，只有新增认可费用等事项交相应财务处理。自营门店按内部经营核对，加盟按其合作协议及预存/分润规则办理。

**验收：** 平台成交100,000、退款10,000、服务费5,000，应结85,000，实到84,500保留差500并交责任岗位；接受短款须有批准依据。门店冻结影响可用余额，不减少账面余额；重复确认同一对账单不能再算一次收款/分润。已结分润遇跨期退款须有追回或后期抵扣记录。

### GW-10｜P1：价格、优惠和承担方在订单与结算之间仍存在口径冲突

**涉及岗位：** 产品定价/营销/渠道→销售→结算会计。

**现状与问题：** 定价策略、附加项目、佣金规则及审批近期已有完善，应保留。预订页仍按产品类型、渠道和金额套固定优惠；订单已有优惠承担比例，但财务明细又把全部优惠列为“本公司承担优惠”。这样无法正确解释公司、门店、分销商和供应商各承担多少。见E16。

**方案：** 订单保存本次采用的有效价格和优惠条件，展示客户少付金额及各方承担明细；过期、不适用或互斥的规则不能随意套用。供应商承担款须有协议/确认依据，不直接扣真实应付。已从成交额中扣除的优惠不能再从毛利重复扣；佣金何时确认、按何种基数由批准政策决定。售后按原规则处理优惠、佣金及分润变化。

**验收：** 客户原价10,000减1,000只付9,000；总部承担700、门店300分别可核对；不得再以“公司承担1,000”全部扣一次。另测供应商承担500尚未确认、退款后优惠失效、佣金已结需调整。

### GW-11｜P1：项目和组合服务已有整体完成，分次完成如何交财务还需补充

**涉及岗位：** 项目经理/自由行及单项服务经办→履约→结算与核算财务。

**现状与问题：** 单团项目已有多版报价、阶段收款、成交交接；团期详情已有项目验收/最后服务项完成等依据；团期结算已有客户验收单上传及缺失拦截。不能说“没有项目验收”。但当前完成登记主要是一条整体回团/完成记录，阶段收款计划不等于阶段完成记录；报表已有分次完成样例，上游日常办理的分次范围未完整表达。见E17、E18。

**方案：** 对确实需要分阶段验收的项目、分项履约的组合服务，在现有项目团或服务详情记录本次完成范围、客户依据、实际日期、未完成部分、变更及对应金额。最后一项完成可汇总整体完成；不强迫普通跟团拆阶段，也不把客户付款百分比当完成比例。独立服务没有团期时使用服务本身，不强造团号。

**验收：** 项目两阶段30,000和70,000，只完成第一阶段时实际完成只计30,000，收款可能10,000，三者分别列示；机票已出、酒店取消的组合订单，保留各项履约与退改责任；阶段验收更正留原记录并交财务判断调整期间。实际采用哪些阶段由业务与财务确认。

### GW-12｜P1：供应商账户“待财务审核”到“可用于付款”缺少清晰承接

**涉及岗位：** 集团供应商经办→供应商财务资料审核岗→应付会计/出纳。

**现状与问题：** 现有账户新增及编辑正确保存为待财务审核，集团资料岗权限也明确不授予付款资格；但本次所查供应商办理、财务配置与导航中未定位到对应的完整账户审核主路径。付款页又可通过账户确认改成白名单已校验，两者之间缺少可核对依据。此项判为“承接待补/待明确”，不认定生产权限已经泄漏。见E19。

**方案：** 保持集团统一维护、业务端只读和合作申请边界。财务在现有配置的供应商账户审核区或二级办理页核开户名、币种、证明、适用公司、有效期及变更；明确通过、退回、停用。付款引用已审核的账户版本；临时例外走批准路径，不能出纳点击一次就自称完成主资料审核。若公司决定通过致远审核，则原型展示其受理、结果和账户生效，不再造重复审批。

**验收：** 新账户待审不可当作已审核；变更账号不覆盖已有付款依据；旧账户、新账户及各自生效范围可查；他公司或错误币种账户不能直接用于本次付款。审核负责人及致远边界待用户确认。

### GW-13｜P2：还需要一套按岗位交接验收的标准，而不只是各页面分别通过

**涉及岗位：** 各经办岗位、各部门负责人、财务与项目验收人员。

**现状与问题：** 工作台、审批待办、业务明细和报表均已存在；现有验收记录分散在各专项。原8批报表验收证明报表范围的原型能力，不能替代销售、履约、财务轮流办理同一业务故事。见E20。

**方案：** 复用现有工作台、主列表筛选和详情关联单据，为每类岗位明确“从哪里进、接到什么、处理什么、给谁、退哪里”。不要新增按岗位命名的一套业务菜单，也不把联系、催办等人工作业塞到列表操作列。对下表八条跨岗业务故事验收正常和异常结果，再判断整体完成。

**验收：** 用角色切换演示责任和可见范围；上一岗确认后，下一岗能够说明依据与办理位置，退回能找到原经办。报表保留既定只读、无金额/编号点击下钻设计，通过筛选、完整依据表和导出核对。

## 四、综合旅行社不能漏掉的业务差异

| 业务故事 | 岗位接力与关键差异 | 验收必须核对的结果 |
|---|---|---|
| 1. 同公司自营跟团 | 产品→团控→销售→收款→名单/资源/领队→实际回团→成本→结算→核算 | 已售未回团、已回团未结算、结算后补成本均有位置；实际回团不以收齐款代替 |
| 2. 体系外采购转售/代理 | 外采→供应商回复→销售接受/拒绝→履约→供应商账单→财务 | 无位、限时保留、补差、部分退款和供应商待追回；外采标签不直接决定收入总额/净额 |
| 3. 集团跨公司供给及代收代付 | 销售公司→提供公司→双方财务→集团财务 | 客户款、内部采购、代收代付各自对清；同法人部门协作不生成虚假往来 |
| 4. 包机/切位、包舱、包铺 | 资源采购→调度→团期使用→票务/名单→业务确认损耗→成本及应付财务 | 多团共用、多类型单价、分期预付、释放减量、未使用损失和供应商应退；分配预付不重复扣余额 |
| 5. 企业会议、奖励旅游及单团项目 | 客户销售→项目经理报价→合同及阶段款→执行→客户验收→结算核算 | 锁定方案、变更、分阶段验收及不同回款时间；预算、实际成本和付款不能混为一个数 |
| 6. 自由行与单项服务 | 销售→各服务履约岗→服务完成/取消→财务 | 机票、酒店、签证等独立确认与退改；本公司服务费与确有依据的代收代付分开 |
| 7. 自营门店、加盟、分销及平台渠道 | 销售/渠道→收款→渠道解释账单→财务对账→分润佣金 | 渠道是销售和结算方式，不是另一种旅游产品；净到账不能直接当成交或收入 |
| 8. 跨期售后与结算调整 | 售后→计调核供应商责任→审批→客户退款及供应商追款→财务调整→报表 | 原订单、原结算与新调整均留存；客户已退不等于供应商已退；旧期不被当前资料覆盖 |

航服独立对外售票、航空客运结算计划及行业周期账单，在业务流程文档有专门要求；现有团期交通采购有票号与退改费用，但本次没有完成这些独立航服场景的逐页面专项核验。因此列为后续专项覆盖核验，不把“团期有票号”当作航服结算已完整，也不直接认定全部缺失。研学已有原型能力可复用营期、名单和结营概念；此前两期上线计划对研学的排除不因本次审查自动改变。

月度损益还需区分团期直接成本、部门经营费用、采购返点和预算。部门费用由费用会计从已批准的财务资料承接，采购返点由采购核协议条件、财务核确认及冲抵/收回；预计返点不能直接增加已确认利润，渠道佣金不能与供应商返点混同。现有部门费用、供应商返点及预付占用报表能力保留。本次没有完成费用来源系统和返点日常确认办理的专项验收，不能据报表有样例就宣布来源完备；也不因此新增报销、人力模块，或恢复此前跳过的正式来源核对工程。
