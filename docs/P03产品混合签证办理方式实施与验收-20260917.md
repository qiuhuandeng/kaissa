# P03 产品混合签证办理方式实施与验收

日期：2026-09-17  
菜单：产品中心 → 自营产品 → 产品管理 → 编辑  
页面：[自营产品编辑](../merchant/product/product-self-edit.html)  
范围：主方案 P03、核心项核02中的产品配置部分。

## 一、业务位置与边界

产品人员只定义产品允许的签证办理方式和随团办理资料；订单后续按游客选择实际方式，签证专员只接收选择随团办理的游客。本次没有修改订单、签证工作台、价格、应收或退款，也没有建立跨页面自动同步。产品后续修改不会批量覆盖既有游客选择。

## 二、需求、原能力、修改与结果

| 业务要求 | 原能力与缺口 | 本次修改 | 当前结果 |
|---|---|---|---|
| 同一产品允许游客自办和随团办理 | 线路层和签证方案层均为单选，并把办理责任与收费含义混在一起 | 自营产品页两层均改为“游客自办／随团办理”复选；费用仍在独立“费用口径”中维护 | 两种方式可同时保存，办理人和收费含义已分开 |
| 随团资料不能被自办选择清空 | 原控件只能二选一，无法表达两种方式并存 | 随团办理被选中时展示材料版本、办理期限、本人到场及材料要求；同时选自办不会清除这些值 | 保存并重开后代办材料保持 |
| 自办仍须核对出行证件 | 原证件要求与签证方案同区展示 | 证件要求保持在产品线路层，不随“随团办理”关闭 | 只选自办时仍可见护照有效期和空白页要求 |
| 需签证产品至少有一种允许方式 | 原单选天然有值，但没有两方式清空后的校验 | 保存草稿、顶部提交和末步提交前统一校验线路层；允许随团办理时同时校验签证方案层 | 零选择就地报错并阻止保存／提交；免签和不涉及不强制代办 |
| 取消不覆盖已保存配置 | 动态签证区未纳入原页面的未保存离开判断 | 动态区单独比较本次值与最近保存值；返回离开时可取消，取消后已保存值不变 | 取消离开后刷新仍恢复上次保存的方式和材料 |
| 共享脚本不能影响其他产品编辑页 | 同一脚本被邮轮、专列、研学页面引用，自由行是自营编辑页的产品变体 | 新复选、校验、暂存和局部样式仅在 `.product-self-edit-page` 生效；独立引用页保留原单选 | 自由行正常使用新复选；邮轮、专列、研学三页保留原单选，四个场景均通过 |

页面是静态原型，保存结果使用当前页面会话内的独立样例，供重开检查；不代表正式数据库持久化。费用口径没有新增第三种办理方式，也没有默认批准自办退费规则。

## 三、修改文件

- `shared/product-visa-config.js`：渲染两层允许办理方式、显隐随团资料、校验、保存／重开和未保存离开处理。
- `shared/style.css`：仅自营产品编辑页的复选组和错误提示样式。
- `tests/product-visa-mixed-modes-browser.cjs`：P03 实际浏览器场景与共享引用页回归。

主页面结构、菜单和原方案层级均未改动；`merchant/product/product-self-edit.html` 继续通过原共享脚本承载“签证与证件”区。

## 四、实际验收

实际使用无头 Chrome 打开页面并点击控件，结果如下：

| 场景 | 结果 |
|---|---|
| 线路与签证方案同时勾选“游客自办／随团办理”，保存后重开 | 通过 |
| 需签证线路取消到零后提交 | 通过：提交弹窗未打开，就地显示至少选择一种方式 |
| 允许随团办理但签证方案取消到零后提交 | 通过：提交被阻止，方案层就地提示 |
| 先填随团材料，再保留两种方式、保存并重开 | 通过：材料仍为“在职证明、资产证明及护照原件” |
| 修改方式和材料后点返回，在离开确认中取消，再刷新 | 通过：未保存值未覆盖最近保存结果 |
| 改为免签后保存／提交 | 通过：允许方式不再强制，沿原流程进入提交结果 |
| 自由行自营变体及邮轮、专列、研学引用页 | 通过：自由行两方式默认可并选；其余3页没有新增复选，原单选仍存在 |
| 390×844 窄屏 | 通过：方式文字完整，页面无横向溢出 |
| 页面运行时错误 | 0 |

测试输出：`mixedModes`、`emptySelectionBlocked`、`materialPreservedAfterReload`、`visaExempt`、`cancelPreserved` 均为 `passed`；`sharedPageRegressions` 为 4，`failures` 为空。本次没有金额变化，因此没有金额计算算例；没有保存验收图片。
