## 一、页面任务及交付

合同管理员在“系统设置 → 合同设置 → 合同模板 → 编辑／修订”维护一份可供后续签约使用的模板。上游是所采用的文本及公司业务适用范围；下游是模板审核、启用及销售选用。模板维护不填写某个订单的游客、成交金额或客户选择，不更改财务金额。

## 二、页面之外的业务规则

1. 正文由采用的文本确定；业务和旅游范围只允许选择该文本支持的选项。选定企业文本时使用企业代表和企业授权，不沿用个人游客结构。切换文本时各自保存当前页草稿，不把上一份正文或补充约定带到另一份文本。
2. 版本由系统生成，修订启用模板时递增版本，原版本保留。草稿保存只保留当前页面的演示数据，不表示真实后端持久化。
3. 提交前检查适用范围、公司条件、日期、必需附件、正文及企业必要填写位置，并要求预览当前内容；修改正文、范围、附件或补充约定后原预览失效。
4. 提交后正文只读；退回必须给出原因，保留原内容，修改后重新预览送审；通过后才可启用。启用动作放在顶部同一主操作位置，不另堆第二组全局按钮。审批结果演示沿用当前页，正式审批仍归审批中心。
5. 删除“已核对”下拉并非跳过审批；改由预览与审批状态表达。合同客户的保险、不成团、争议方式及机构等选择仍在合同准备时确认，不在模板中预填同意。
6. 企业模板可演示业务草稿及审核，不冒称已取得真实平台签署能力。正式接口能力检查仍会拦截未知平台模板、版本及签署支持；公司资质和其他适用条件并未取消。
7. 实际平台模板标识、字段对应、参数版本等由开发依据正式接口资料维护，进入技术设计／接入配置，不还原为本页业务表单。业务模板版本与平台版本分别保存。

## 三、正文证据边界

本轮采用明确标注的“原型示例正文”，用于展示文书阅读、固定条款、签约填写位置、正文编辑及审核流程。没有取得全部获准正文，不把示例拼接内容称为12301官方全文、正式省级文本或公司批准法律条款；正式文本及固定参数仍须按获准材料替换。页面可实际编辑、预览、送审，不以真实文本和真实接口作为原型交付的阻塞条件。

正式落地时，标准正文中的固定条款与允许填写位置须按获准版本保持一致；不可把示例中的【违约责任条款】等占位直接用于生产签署。企业正文必要填写位置缺失当前已有阻断，正式开发需按公司批准的模板结构完善。
