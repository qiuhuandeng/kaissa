文件：`merchant/tour/product-custom-list.html`。销售、项目负责人使用；上游客户／线路引用，下游项目详情。

- 页面页签名称“单团项目”，页内不重复大标题；“新建项目”位于主操作区；筛选为项目／客户、业务分类、组织方式、服务期间、销售、项目负责人、项目状态，最后“查询／重置”。不加大统计卡。

文件范围见开发方案M09。订单分配、付款对象、项目及项目团、币种、来源金额、已办理／剩余、依据和备注组成来源核对区，保留原列表和抽屉风格。点击必须到本笔业务或显示本笔无关联记录的空态。销售只能申请／认领；实际认款、实付、开票及财务确认在原财务角色办理区。

### P10 通用审批与手机呈现

后台沿用`merchant/approval/approvals.html`。手机若无已有入口则补通用`approval-mobile.html`，从同一审批事项的演示链接进入。内容顺序：事项名称和当前版本→项目／项目团／申请人→本次金额与变化→依据附件→审批记录→底部批准／退回。不是手机显示后台大表格；签名按现有事项要求条件显示，不自创所有事项必签。

### P11 工作台与只读查询

工作台待办显示来源名称、到期日、未处理金额／数量、责任人，可到来源办理。数据中心现有项目结果、订单明细、执行明细、结算分析增加项目／项目团条件与结果；保持原只读、无点击下钻边界，不把待办办理按钮塞进报表。导出只导当前已查询条件和有权限字段。

### P12 变更与结项检查区

主入口仍在P02／P04及原订单售后、结算调整页面，没有新菜单。显示本次范围、原值→新值、受影响服务／订单／费用、批准依据、后续责任和记录。结项不等于资金全清；未决事项必须可见，是否准予例外按现有政策。

## 2 所有表单共有的交互规格

- 草稿校验只保证能识别记录，提交／确认执行较严校验。字段下方显示具体错误，如“请选择该项目范围内的计调”；定位第一个错误。不能仅弹“信息不完整”。
- 下拉先限定客户、公司、项目范围；失效或无权限对象不能选。没有候选时显示原因及正确维护方向，不能自动选第一项。
- 更改上游字段时先列将清除的关联项；取消则原值原关联完整保留；确认后清除不再适用的选项，已确认记录走变更而非原地改值。
- 只读自动带入字段用正常数据文本；需要用户确认的默认值保留编辑能力，不伪装已确认。未知人数、金额、税额显示“待定／待确认”，不能默认0。
- 保存后当前清单新增或更新对应行，显示业务结果、状态和下一入口；再次打开能看到本次数据。重复点击提交不重复增行。
- 右抽屉固定标题和保存／提交操作，内部滚动；关闭、取消、切页和返回有未保存保护。提交失败保留已填内容。确认弹窗只用于放弃、取消、批量确认等打断动作。
- 真实本地选文件至少显示文件名、类型、大小、预览可行性及移除；不假报上传服务器成功。示例文件要标明示例，可预览／下载。保存后版本变更保留原附件关系，未保存移除不影响原记录。
- 金额两位小数、数量精度按服务单位，币种显式；负调整与正收费区分。日期开始不得晚于结束；在客户合同、项目期间之外，草稿提示、确认前核对或走变更。

### F02 新增／编辑／确认项目团（M03、M05；P02／P03）

最新创建规则：新建只打开一次抽屉。常用七项优先展示，参考号、名单要求、时刻、预算、客户预计金额、结算期限和服务范围收在补充资料；填写开始日期时仅在结束日期为空时补同日。顶部搜索项目名称／客户／编号，选中后在同一DOM抽屉内展示客户、公司、期间与项目团表单；更换项目且已填资料时确认清空，可取消保留。新建只保存草稿，后续在详情补报价与客户委托凭据再提交／确认，编辑及复制原项目团继续原表单。

现行入口：计调从项目团列表“新增项目团”抽屉选择所属项目，自动带入本人及负责事项；所属项目只列当前允许建团的项目，包含零项目团项目。编辑／复制原项目团保持原所属项目。主责计调不可改；仅一个城市／服务类型时自动带入。保存、批量核对同时校验有效分工、公司、城市、日期及服务范围；没有分工不能自主新建，但历史本人项目团按原流程继续办理。负责人可统筹建立，再按既有分配／移交办理。

| 字段 | 来源／填写 | 保存与确认条件 |
|---|---|---|
| 所属项目、客户、我方公司 | 只读继承 | 不给项目团单独换客户的入口 |
| 项目团名称、客户场次参考号 | 名称文本；参考号可选 | 草稿名称必填；相同有效参考号提示重复且阻止重复导入，同名同日仅提示 |
| 服务类型 | 会议、旅游、会议加旅游 | 确认必填，驱动F08—F10分区 |
| 服务日期时间、地点 | 起止；城市及场地说明 | 草稿可待定；确认要可执行的日期地点，未订具体会场可明确城市与待确认资源 |
| 计划人数、确认人数、人数待定 | 正整数或待定；确认数独立 | 不用0表示待定；需要按人数采购／发名单前补相应人数；不无依据自动生成参会人 |
| 计调、项目团负责人 | 项目组与有权员工 | 执行确认必填；缺权限不因分配成功变有权限 |
| 服务范围、关联报价单 | 描述服务；选择本项目有效委托 | 执行确认必填；覆盖必须含本团，框架本身无具体授权不能代替具体委托 |
| 方案／确认材料 | 现有资料引用或附件 | 有可核对客户依据；客户按实际结算可用有效计价规则，不能伪称最终金额已定 |

保存→草稿；提交核对→待确认；确认成功→准备中，并沿用一个项目团编号进入履约。客户依据失效、期间超出或审批缺项列在核对区。项目团进入准备中不新生成另一笔订单。

### F03 批量建团、导入与复制（M03；P02／P03）

现行入口：履约“项目团 → 项目团控 → 批量建团”，产品项目详情“批量建团”复用同一流程并固定项目。只打开一个抽屉，选择项目后原位展开。操作人员及城市、服务范围沿用既有分工，提交时重验权限。

1. 共同项目团资料：名称前缀、服务类型、城市、主责计调、人数、每团费用预算、服务范围。应用默认仅补空字段；取消勾选后才覆盖下方同类字段。不同场次可逐团调整。
2. 手动添加：默认一场，统一表格编辑名称、项目团日期、城市、人数和计调；支持添加、复制、删除，参考号、服务类型、服务范围和预算按行补充。每页10场，分页保留输入；新增定位末页，复制定位新行并清空参考号。
3. 日期规则：开始日期前的“日期方式”下拉选择周期规则／手动选日期，不设二级Tab。周期支持每天、每周、隔周和每月固定日。填写开始／结束日期及每团天数，日历实时展示数量；每屏三个月，可前后翻页。周期日期可点击排除／恢复，手动日期可点选／取消。每月缺少指定日时跳过；隔周从开始日起每14天为一轮、前7天按星期安排。点击“生成项目团”后收起批量默认资料和创建设置；日期直接显示在表格中，仅点该行“调整”时显示同一行起止日期，不重复录入。日期预览上方集中数量、翻月、按需恢复和生成按钮，不显示已排除数量／已应用说明。仍可手动追加项目团；覆盖已有项目团须确认。修改日期未重新应用时不能核对保存旧清单。天数1—366，单次1—200个项目团；项目／本人分工期间限制及草稿规则保持。正式假日日历未配置，当前手动排除，不使用原团期页的样例节假日。
4. 导入表格：下载CSV模板、上传CSV／TSV或粘贴完整表头，读取到同一可编辑清单。已有填写内容时须确认替换，切换方式保留下方项目团；未读取表格切换有清空提示。
5. 核对项目团：按名称、日期、人数、有效计调、项目及分工期间、服务范围、非负金额和重复参考号逐团校验。相同名称日期的已有场次须补独立参考号，防止重复导入，同时允许真实平行会议。
6. 保存：显示整批有效／错误项目团数，错误行着色，可跨页定位首个错误；错误全部修正后保存N团草稿，不静默丢掉错误行。核对后修改须重验；提交重验分工和重复项目团。草稿不自动报价、成交、形成应收或执行确认。

本轮替代旧“仅模板导入／仅保存有效行”的创建路径；批量维护及批量报价仍沿用各自的既有核对流程。真实Excel二进制格式未实现，不在页面宣称支持。

复制勾选服务安排／预算参考／分工，名称默认“原名称-副本”，日期重核；清除名单证件、实际完成、采购确认、款票、客户确认、合同签署和审批结果。复制项目同规则，客户等基础信息须核对。

### F04 项目组、分配与移交（M03、M11；P02）

第2步增加“项目分工”，与下述参与记录用途分开。分工可先于项目团，字段为操作人员、负责事项、覆盖日期、城市、服务类型、允许建团、报价办理范围、币种、负责业务金额、费用预算参考、单笔上限及已批准规则依据。仅选已有计调岗位员工；报价范围不提升员工岗位权限。默认计划参考，限制模式必须有依据；结束填写原因及未完安排，不覆盖历史负责人和金额。金额使用以该员工实际负责的独立报价单核对，不平均拆分跨人员包价。正式员工任职衔接仍留第4步，当前明确标注样例。

字段：员工、职责（销售／项目负责／计调／资源协作／签证协作／现场支持等实际岗位）、负责项目团范围、参与起止、分工说明；保存要求员工有效、范围属于本项目、职责在既有授权内。项目团计调只能有一位当前主责，协作可多人。

批量分配先选项目团再选人员，显示每团当前负责人→新负责人；已完成项目团不改历史负责人。移交另填接手人、生效日期、原因，列未完成采购、未完申请、待验收记录；保留原经办，不把所有历史统一改名。无可接手人显示组织权限缺口。

导出列：项目、项目团、员工、职责、参与期间、移交前后和已登记服务；无奖金自动计算，不把员工当游客。手工登记成员按所选项目团分别导出一行，去除重复项目团；无所选项目团才写项目总体，失效项目团写资料待核对，不改写成整体参与。现有项目访问权限保持；成员修订、同名员工识别及本团成员查看仍属后续补齐项。

### F05 框架合同登记（M04；P02／P06）

第2步增加已确认、审批中和可用余额／约定差额显示。仅“上限”且金额明确时限制确认与审批累计；预估或客户承诺只提示差额。报价草稿不扣确认余额，不同币种不直接相减，未定金额不得按0绕过硬上限。

字段：合同来源（已签归档／进入合同办理）、合同编号、客户签约单位、我方签约公司、有效期间、服务范围、币种、金额性质（上限／预估／客户承诺／待确认）、金额、结算约定、附件、签署状态和签署日期。

客户和我方公司默认继承，不能关联其他签约方；有效期间不足覆盖项目团时提示延展／补充合同。金额性质未确认可保存待核对记录，不计已确认成交。“已签归档”须有编号与已签依据；其他来源进原合同准备页。保存框架不要求订单编号，不产生同额订单或应收。

### F06 报价、报价单及成交确认（M04；P02／P03／P04）

第2步沿用原报价单，增加草稿／已报价／待审批／已确认状态及HTML报价下载。已报价改价格／服务范围保留旧版并升版；客户确认必须对应本版批准资料，只有确认或审批通过后承接一个订单。有效分工及已有报价岗位者可办理本人项目团；仅准备报价者须由销售／负责人确认。审批时重新核对授权和金额规则，过期授权不可直接批准。

批量逐团报价填公共服务、价格、币种、框架、必要确认资料及每团参考号／金额／依据，先逐行核对；已有约定提示继续原记录，不复制新单。确认分支按顺序累计已确认＋审批中＋本批有效行；草稿不当成交，不把包价按人数或场数平分。硬限制、超限须审批与计划参考分别表达，金额政策不明时保持待配置。

| 字段 | 内容与联动 | 提交校验 |
|---|---|---|
| 报价单名称、客户参考号、版本 | 本项目客户确认单／采购单／邮件／合同依据 | 名称、依据和确认日期必填；重复依据的相同服务范围提示已有记录 |
| 覆盖项目团／服务 | 本项目团多选，展开服务范围；年度可后续追加草稿项目团 | 已确认增加范围走新版，不静默覆盖；不能选其他客户／公司 |
| 计价方式 | 固定总价／数量单价／按实际确认 | 必选，驱动金额区；与对客展示总价／分项是两个不同选择 |
| 固定总价 | 币种、含税确认总价、包含／不含内容 | 有效确认金额必填；成本上涨不改此值 |
| 数量单价 | 服务名称、计量单位、报价数量、含税单价；数量是确定／预计 | 确定数量计算确认金额；预计数量只显示预计，不算最终确认 |
| 按实际确认 | 单价／收费规则、最终数量依据、确认时间／方式、预计值（可选） | 必须有可执行规则；最终未定标待结算确认，不拿预计值充确定成交 |
| 币种与汇率依据 | 原币；需要本位币测算时单列用途和依据 | 改币种不能只换符号，确认清除旧金额并重填；固定约定汇率不自动覆盖 |
| 收入税费测算 | 默认待财务确认；单一税率或财务提供税额与依据 | 不凭票種决定适用方式；非待确认必须有依据，随报价确认承接原订单；预计值不当核定值 |
| 收款阶段 | 节点名、金额或比例、到期日或触发条件、说明 | 固定金额方案合计与应收计划基数一致；相对节点未触发不伪造已逾期 |
| 适用合同 | 有效框架、具体合同／补充单，或待办理状态 | 显示合同条件缺口，执行时按适用条件核对，不统一强制所有场景同一模板 |
| 客户确认与内部审批 | 客户确认人／日期／材料；公司审批结果引用 | 两者分开；旧批准不能批准新版本 |

金额输入支持小数与零金额服务的明确免收依据，负数留变更处理。保存草稿不计成交；提交按既有审批分支；有效确认后关联原项目订单。原型同一委托重复确认只能“查看订单”；已有关联订单不能换成新编号制造重复成交。

### F07 项目订单和合同承接（M04；P05／P06）

订单带入：客户、我方公司、项目、报价单版本、币种、计价明细、金额性质、覆盖项目团、收款阶段、合同依据；可编辑内容按现有订单权限，已确认价款不在普通信息编辑中改。

选择已有订单时限定同客户、同我方公司、同币种且服务范围不冲突；显示已有覆盖，禁止重复关联相同有效收费明细。按实际确认且金额未定的订单沿用有效收费规则，金额栏区分预计和已确认，不伪造确定应收。

合同办理带入项目来源；框架不传虚拟订单，具体合同引用真实约定／订单。签署失败显示原因及重办；已有有效同事项同版本审批可引用，不因再查看合同重复审批；范围／金额／签约主体变更进入F19。

### F08 日程与行程（M05；P04）

会议明细：日期、开始／结束时间、议程、场地、服务负责人、所需会场／设备／餐饮引用；标题和日期时间必填，时间倒置阻止，场地同时间占用冲突提示核对而不是禁止所有并行会议。旅游明细沿用日次、城市、行程、餐住交通及领队安排。

切“会议加旅游”保留两类已填内容；改成纯会议前列出旅游段处理方式，取消保持原数据，不能隐藏后直接丢失。草稿日程可缺场地确认，进入执行检查显示具体未确认项；开始执行用实际条件核对，不新增无依据的统一付款门槛。

### F09 参会／游客名单与分组（M05；P04）

基础列：姓名、参会分组、联系资料（按需）、到离批次、服务需求。仅需要交通出票、签证或住宿实名时展开所需证件及材料，字段沿用当前名单规范。导入预览、重复人处理、错误行、补充、分房分车均复用原能力。

计划60人、已提供55人显示缺5人，不按比例制造5个名字。纯会议客户只提供确认人数且服务不需实名时，允许“按人数交付”，不强制60份身份证；下游服务新增实名要求时再产生可校验缺口。项目工作人员另在F04，不自动混入客户名单。

### F10 资源安排与交付（M05；P04）

共用字段：服务类别、日期时间、供应商／资源、数量单位、安排状态、确认号或依据、联系人（必要时）、附件。选择服务类别后显示：酒店房型／入住离店／间夜；车辆车型／车次／接送点；会议场地／布置／设备台天；餐饮餐次／桌数或人数；交通班次与到离批次。

供应商从现有档案选择，资源描述与付款主体分开。资源确认不自动产生已确认成本或实付；“转费用”带入服务、数量、供应商，F11还需核金额及依据。取消资源保留取消条件和损失待确认，不自动退款。

### F11 费用与采购（M06；P04／P07办理，P02只读）

| 字段 | 带入及填写 | 规则 |
|---|---|---|
| 所属项目、服务范围 | 本团项目团／指定多个项目团／项目整体；台账单团名称为指定单团项目团 | P04项目固定，默认本团并带入项目团日期；P07新建先选项目，带入公司和项目日期。多场至少选同项目两场，整体无需项目团；P02不得录入，不能建假项目团 |
| 服务内容、类别、日期 | 资源安排可带入，可补充 | 确认费用必填；费用不是单凭供应商名即可确认 |
| 供应商、付款主体 | 引用现有有效供应商与已审核财务资料 | 换供应商需重选协议／付款条件／账单关联；本处不改银行卡为可付款 |
| 数量、单位、含税单价／总额 | 人、场、间夜、台天、辆次、固定服务费等 | 明细方式按数量×单价；总额方式不强拆人均；负调整另办 |
| 币种、折算用途和依据 | 原币必选；需要对比时填相应依据 | 外币未有可靠折算不与人民币直接相加，不自动采用当日参考覆盖历史 |
| 金额阶段 | 预算参考／最新预计／实际确认 | 三种金额分别存展示，实际确认要采购确认或其他有效依据；不能以付款额当总成本 |
| 采购覆盖与分配 | 多场勾选覆盖项目团，可填各场金额和分配依据，也可暂不分配；后续从费用详情调用F12 | 总额及各场金额可明确区分；合计不得超额。保存多场或整体采购后P04自动切到项目采购并定位原单；未分配显示待分配，不显示为零承担 |
| 付款条件与附件 | 合同条款、节点、账单等 | 保存不等于满足全部付款条件 |
| 预计票面税率与可扣处理 | 含税金额及本公司启用税率驱动未税金额／票面税额；可扣选待确认／不可扣／预计全扣／部分 | 有结论需依据，部分金额不得超预计票面税额；实际核定仍由财务办理 |

### F12 采购分配和预算调整（M06；履约办理，P02只读）

P04与P07均从原采购详情打开分配内容，可返回费用详情，不叠加抽屉；P04查看范围为本团费用时调整本团预计，为项目采购时调整项目预计。P07不摆预算概览；P02只读。采购分配字段：采购总金额／币种只读，项目团、分配金额、项目共同金额、未分配金额、依据；总额=项目团分配+共同+未分配。给定3万元分1.2万、1万、0.8万，余额0；输入合计3.1万阻止保存。共同6万元管理分摊时注明“管理分析”，项目成本仍只计6万元。分团报表和结算采用同一明确承担额；例如分给A场1.2万元、B场1.2万元、项目承担3.6万元，A场不计整笔6万元。未分配与项目承担分别展示，不自动平均。已有结算确认的分配及项目承担金额不能覆盖，须走后补调整；未结场次的分配可继续核对。仅本笔费用已纳入确认或存在有效付款占用时限制原采购修改，不能因其他场结算锁住整个项目。

预算字段：原批准预算只读、本次调整、最新预计、变化原因、客户是否追加收费及依据、适用审批。客户不追加可登记成本上涨；提交预算调整不改客户订单。未确认成本显示待确认项及金额范围，不把未知当零计算确定利润。

### F13 付款申请（M07；原费用详情内办理）

从费用详情“申请付款”切换同一抽屉，提供“返回费用详情”；有未保存内容先确认放弃。提交后回原费用详情，显示新申请记录；查看和撤回仍在当前页面。项目团分配行上进入时也只能引用原采购编号、供应商和付款余额，不建立本团分配的另一笔付款。实际复核、付款结果由原财务页面承接。

只读核对：项目／项目团、采购费用、付款对象、币种、付款条件、本次条件允许额度、实际已付、有效未付申请及冲抵影响。填写：申请金额、期望付款日、用途、付款依据／附件、备注；账号仅选财务已审核资料。

示例条件允许费用余额：28,000−8,000实付−4,000有效未付=16,000。申请5,000后未付申请合计9,000，可再申请11,000，实付仍8,000。同一申请“审批中／已批待付”只占一次；部分实付从未付占用转出。

金额必须大于0且不超过本次可申请；最终对账未完但已达到有效付款条件可以申请。重复提交保留一条申请。退回／撤回后是否释放占用依当前有效状态，已付部分不因退回变未付；原因和处理记录可查。按钮为“提交申请／查看申请”，无“确认实付”。

### F14 供应商对账（M07；P08）

字段：供应商、我方公司、币种、项目／项目团范围、采购费用、服务期间、我方数量金额、供应商认可数量金额、差异原因、当前版本、盖章件、确认日期。前四项限制可选采购；不同付款主体或币种不能无规则混账。

我方起草→提交核对→供应商确认当前版及盖章附件→按原流程确认结果。改金额生成新版，旧盖章件保留但不满足新版本确认；无当前版依据显示缺项。差异只形成增减调整，不把采购3万元和对账3万元加成6万元。

### F15 确认项目团完成（M05、M08；P04）

字段：计划日期只读、实际开始／结束、已交付服务逐项、未交付／取消项目、实际参加人数或按约定人数交付、完成依据、后续待客户核对事项。确认实际日期与服务事实必填，不强制纯会议“回团日期”。

服务实际完成可进入已完成；客户验收另列待确认。尚有真实未交付服务不可把全场无差异完成，须补交付或关联有效范围调整。未收尾款、票据未到不阻止记录完成，但出现在结算／结项检查。未开始却直接确认完成需核对真实日期和原因，不能误用计划值。

### F16 客户对账，含月度（M08；P02）

字段：客户／我方公司／币种只读，核对期间，原委托／订单，服务明细、项目团及完成依据，原报价数量／单价／金额，实际认可数量／金额，争议金额及原因，客户确认材料、确认日期、应收期限或适用节点。

选择的是原服务明细，不是勾项目团就新开销售；已纳入有效确认的明细不可重复纳入另一份同范围确认。固定包价可记服务认可进度，但不擅自按完成场数拆成独立收入；按实际计价用明确单价和认可数量核对。

草稿→待客户确认→已确认；客户部分认可时仅明确认可部分记已确认，争议明细继续待处理并有金额，原记录保留。原订单金额变动先走F19批准变更，结算记录不能旁路改价。确认材料缺失、跨客户合并、重复服务、争议金额不守恒都阻止确认。

### F17 收款认领与分配（M09；P04原位、P05／P09）

P04客户款项先明确当前订单，只有一单时带入；在本团只填写当前订单的分配与节点，多订单合并继续原销售入口。保存回原页看记录，不外跳财务办理。选择客户款项或登记认领依据，核对付款人、收款公司、币种、到账依据、原款金额；选择同客户公司币种的订单，填写本次分配、节点及备注。分配合计≤可认领款，余款显示未分配，不强塞到任意一场。

一笔80,000分订单A50,000、订单B30,000；80,001阻止提交。销售提交后显示待财务认款，实收仅引用财务已确认记录；无流水／重复认领／币种不符各有错误恢复。改变订单清除原节点选择，不能保留别的订单的尾款节点。

### F18 开票申请与办理（M09；P04原位、P05／P09）

字段：开票客户抬头、纳税识别号等原票据所需资料，销售方公司，币种、原订单明细、申请金额及逐订单分配、服务名称、开票项目、备注、收票信息、已开／处理中／本次可申请金额。票种及税额按既有财务规则，不以项目开票选择反推所有采购可抵扣。

合并申请只选签约及开票关系相容的订单，分配守恒且不超过按现行口径可申请额；原型不把“已收款”设为所有开票的统一上限。订单增加或取消后重核可申请。备注原文带到财务办理及结果，例如“2026年10月区域会议服务，含上海、杭州两场”；退回保留原因可修正重提，失败不计已开。实际开具结果由财务页呈现。财务办理必须可见申请抬头、税号、销售方公司、票种、开票项目、币种金额、收票资料、备注原文和逐订单分配；备注全宽并保留换行。申请必需资料缺失或分配合计与申请金额不一致，不能登记开具成功，可退回补充。第3步已在财务原发票管理维护本公司常用税率启停和开票项目；申请税率可以待核对，财务审核须核对税率或选择按原服务明细处理。审核后进入开票中，查询可成功／明确失败／结果未知；未知继续占用且不可重复提交，明确失败重试先重核余额，成功仅计一次已开并可下载PDF样例。历史已开仍占余额，不因缺申请明细释放；与已开明细不重复相加。人工上传结果作为备用路径。识别、开票服务和PDF是明确标注的原型表达，不接真实后台。

### F19 变更、改期和取消（M04、M10；P12）

填写：变更类型、目标项目／项目团／订单、原值只读、新值、原因、客户依据、影响明细、适用审批；涉及金额增加与减少分别显示。改期展示受影响日程、资源、合同期间及采购，不能自动把确认号搬到新日期。

取消单团先列已订资源、取消损失、客户应退或应补、供应商应退或未付调整、其余场次；确认后只该场已取消，退款只是申请／待处理。整包取消一场时订单价是否改变必须有客户依据，不能自动减五分之一。

已结算补费按新增调整关联原费用／原结算；原记录不解锁覆盖。新版本显示审批未完成，旧版本批准继续只支持旧版。变更取消亦保留提交人、日期、原因和结果。

### F20 业务结算、收付与发票与项目结项（M08—M11；P04／P09／P12）

业务结算选择本团／多场有效范围，核对完成、客户确认、费用、对账、变更、未决事项及附件；沿用原结算状态和提交、退回、确认动作。缺项可定位来源，补齐后重新核对；不同公司不可混合提交。结果的财务应收应付、款票及核算状态为原财务来源结果，不自动模拟记账。

主办理入口为P04“结算核对”。选择本次项目团，费用按直接费用、跨团明确分配、公共费用管理分摊计算；项目原采购金额只作核对参照。可另选“同时核对项目承担费用”，或只选项目承担而不选项目团。已审批中／已确认的范围禁止重复提交；无明确金额、相关分配未完或服务依据缺失时提示具体来源。没有费用须填无费用依据。

提交后保存本次项目团、承担金额、分配依据及服务完成／认可资料；审批时如依据变化，退回重新核对后提交。批准保留本次结果，不能拿当前采购全额覆盖。已结范围受保护，其他未结项目团继续维护。旧记录未区分本次承担时明确说明，不反算伪造历史。

首页结算提醒及项目结项缺项进入对应项目团的结算核对；审批及财务反查带结算编号，直接打开原位记录抽屉。错误编号、跨项目范围明确空态，不选第一条样例顶替。项目承担费用尚未确认结算，也进入结项缺项。

结项检查列：未完成项目团数、未认可服务／争议、费用及对账缺项、未结款票、未完成调整；每条可查看来源和负责人员。申请结项填写无新增服务确认、结项说明、遗留事项安排、责任人和适用批准依据。无例外规则／批准时不能带未决事项强制结项；有明确获批后续款票安排可表达业务结项与资金未清并存。结项后只读，可走后补调整，不称所有款票已结清。

### F21 审批、手机办理与外部结果登记（M11；P10）

字段：事项名称、来源单据、当前版本、申请人公司部门、金额和变更前后、覆盖项目团、附件、审批职责／人员、历史意见；操作为批准、退回及按既有规则的签名。退回必填具体原因；无权限、事项已处理或版本已变化时不再批准，显示可回到当前记录的入口。

外部办公结果登记含外部事项编号、批准版本／范围、审批人及日期、结果、依据附件、人工核对情况；缺依据不能冒称已核验。登记不是调用外部接口，也不意味着合同已签／款项已付。手机和后台引用同一事项编号及版本，原型中通过预置状态与本页交互表达，不要求真实通知与登录。

## 4 空态、失败与恢复必须逐页实现

| 情况 | 页面必须给出的内容与操作 |
|---|---|
| 无项目团／无委托／无费用 | 说明当前尚无对应记录，提供该角色有权的新增；无权则显示负责角色，不给假按钮 |
| 来源参数失效或无权限 | “未找到该项目／无权查看”，不加载第一个样例；返回来源或列表 |
| 资料缺失 | 列字段或行号，保留输入；补后可再次提交 |
| 审批退回／签署失败／对账差异 | 原因、原记录、修正入口和重新提交路径；不得把失败记录删除 |
| 保存中重复点击 | 禁止重复请求式交互，结果仅一行；提交完成按钮转查看 |
| 切Tab／关闭／浏览器返回 | 草稿变更保护或按已说明规则保留，不静默丢失 |
| 导出、附件、导入 | 文件能打开、列含义与筛选一致、错误可定位；不能仅提示“已导出” |

页面不得使用技术建模名词解释业务；“项目”“项目团”“报价与合同”“费用”“申请中未付”等直接作为字段。编号只在业务流转需要核对时展示，技术状态和测试开关不进入普通业务表格。
