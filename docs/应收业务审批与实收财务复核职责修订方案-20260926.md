# 应收业务审批与实收财务复核职责修订方案

日期：2026-09-26。依据：用户最新业务反馈。本文保留实施前的现状核对与方案；用户随后明确“执行”，本轮职责原型已实施，当前结果以[实施验收](应收业务审批与实收财务复核实施验收-20260926.md)为准。

## 一、最新业务规则

应收是按已确认订单应向客户收取的款项，由业务确定；订单确认后系统自动生成。销售可以从订单新增或申请修改应收，但所有应收变更都须经过审核链路。财务不审核业务应收金额是否允许调整，财务复核实收，即资金是否真实到账、归属订单及认款金额是否准确。

据此应采用两条不同流程：

- 订单确认→系统生成应收；销售发起后续新增／修改→业务审批→批准后系统更新应收并保留差额记录→财务查询及后续收款、结算。
- 客户付款→到账流水→销售认款／系统匹配→财务复核到账与认款→确认实收及相应应收核销。核销在此指把已确认款项抵扣相应欠款，不是再次批准应收金额。

“全部变更进入审核”不等于“全部变更由财务审核”。具体由店长、销售主管、产品负责人或其他业务岗位审批，以及金额／渠道／产品条件和先后顺序，仍待业务明确；不得默认以财务主管补足审批人。

## 三、关键异常与金额例子

- 原应收10000，业务批准增加1200：应收11200；原实收8000仍为8000，未收变为3200。审批中仍采用原应收10000。
- 原应收10000、已认款实收8000，业务批准减至7000：应收7000，原实收保持8000；1000元成为待处理多收款，按实际认款明细及退转流程处理。不能自动改成实收7000、直接退款或阻止业务合理减价。
- 已核销、已结算、已开票的订单调整须保留原记录，说明需要的认款分配调整、退款／转款、发票调整及结算后追加调整。这些下游财务动作仍有自己的依据和审批，不是恢复财务对应收价格的审批。
- 待审批期间又发生其他应收变更时，按最新已生效金额重新核对差额及累计影响，防止旧申请覆盖新值、重复计入或累计减免超过有效应收。
- 原订单确认前的报价修改、草稿编辑与已生效应收变更应区分；本次反馈明确的是所有应收变更须审核，不自动扩张为每次草稿输入都启动审批。

## 四、具体页面与优先顺序

优先一起修正销售“订单管理／订单详情”、审批配置与审批中心、财务“应收管理”，保持业务申请、业务审批、自动生效、财务只读承接一致；同时在“新建订单”明确首次生成时点。团期详情保留计调资源确认职责，仅补清与业务审批的关系。

财务“到账流水／认款复核”沿用真实到账与正确认款的处理方向，检查入口文案和来源对应即可，不因移除应收金额审核而取消认款、退款、资金、优惠承担或坏账等既有财务控制。

本方案提出时尚未实施；后续页面、规则与浏览器验收已完成，详见实施验收。未做生产账务验收，原8批／36项／6场景和并行供应商工作保持。

唯一下一步：业务明确应收变更审批岗位、适用公司及分流条件后配置正式流程；当前原型保留待配置，不代填财务审批。
