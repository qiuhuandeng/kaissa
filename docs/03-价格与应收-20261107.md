日期：2026-11-07。状态：第三组场景与独立金额样板；正式计价细则待补依据，尚未执行真实ERP测试。

本组围绕“客户到底应该付多少钱、哪个版本生效、实际付了多少、还有多少未收或待处理”验收。只覆盖国内及出境参团游；签证、保险、联运、酒店等是参团订单的组成或附加服务，不扩展成其他产品类型的独立测试。

## 一、已有确定职责和本次待确认项

项目已明确：订单业务确认后生成应收；之后新增、减免、修改数量或单价等应收变更均走业务审批；计调确认可供不代替价格审批，财务复核到账与认款，不再次批准售价。审批岗位、金额路线及正式适用条件仍需配置。[职责实施记录](应收业务审批与实收财务复核实施验收-20260926.md)

## 二、先固定金额含义和计算边界

“有效应收总额”是客户按当前已生效交易应承担的总收费；“未收”是其中尚未用有效款项覆盖的部分；“多收待处理”是已收款超过当前收费、尚需按依据退回或转用的部分。业务减价不能反向改掉银行到账记录。

本组基础样板限定同一合同公司、人民币、没有手续费、优惠、争议款、跨订单转款和币种折算，所有计入的款均已确认属于本单。此时可以独立核算：

- 有效应收总额＝首次确认收费＋已批准并生效的增减差额；待审批差额单列，不先加进去。
- 净收＝累计真实到账并归属本单的款－累计实际已退原款；退款申请／批准不减少净收。
- 确认后未收＝有效应收总额超过净收的部分；多收＝净收超过有效应收总额的部分，分别显示，不能只把负数欠款截成0。
- 确认前有效应收为0，真实到账款保留为预款，不能称为逾期欠款或直接认定多收退款。

实际存在未分配、支付争议、转出／转入或跨币种时，须逐笔核对资金归属和核销分配，不能把账户全部净收代入上式。核销指将已确认款项抵扣相应欠款，不是再批准客户价格。

对数量或单价修改：**本次差额＝修改后该项目金额－修改前该项目有效金额**。单房差1,800改1,500应减少300，不是再扣1,500。删除已生效收费也应保留原项目和冲减依据，不能直接删行使历史消失。

## 四、十二组业务验收场景

### 价01：报价版本改变，确认价不能被悄悄覆盖

产品人员发布上述版本1；销售按4成人1儿童取得50,300报价并保存依据。随后同一团期发布版本2：成人10,500、儿童6,500，其他项目不变，新报价应为52,800。

分别运行：未确认且没有有效锁价依据的旧报价；仍在获批锁价期内的报价；已经正式确认的订单。前一种按正式规则提示重新报价并取得客户确认，不能静默多收2,500；有效锁价分支按其依据处理；已确认订单仍为50,300，除非再完成正式变更。销售打开旧页面后提交时也要核有效版本。

同时验证指定团期、出发地、销售范围和币种匹配；不能取线路参考价、另一个日期价或B的内部采购价替代客户价格。报价过期、无价及价格版本缺失应显式处理，不默认0元或取最后一条历史价。

### 价02：同样显示“单房差”，单位不同结果不同

用两条独立测试价格验证：1人全程1,800，结果1,800；2人住3晚、每人每晚300，结果1,800。两者金额虽相同，服务范围与退改计算不能混同。

第二条改为1人住3晚，项目金额900、差额－900；不能按“少1人”退整笔1,800。另测加住1间2晚×600／间夜＝1,200；改成2间2晚为2,400，不把房间数、晚数和入住人数重复相乘。人数5和团期占用5不因单房差、间夜或服务段次增加。

已经含在团费中的保险、已含签证或已含接送服务不能再作为收费增项叠加；选择升级服务时，应先确认是“追加全价”还是“补差”，按批准依据计算。无明确包含关系时留规则待确认，不能两次收费后再用总折扣掩盖重复。

### 价03：从预款到应收、改价、多收及分次退款的连续样板

本例出境订单5人50,300。按已批准测试条件先收15,000预款，再确认订单；之后单房差1,800改1,500，经业务审批减少300；另加住1间2晚，经资源确认和业务审批增加1,200；再收35,000。最后因已确认服务问题批准减价2,200，形成1,000多收，实际分600及400两次退款。

| 节点                                | 有效应收总额 | 累计到账 | 累计已退 | 净收   | 未收   | 尚未覆盖应收的净款 |
| ----------------------------------- | ------------:| --------:| --------:| ------:| ------:| ------------------:|
| 报价50,300，未确认、未收款          | 0            | 0        | 0        | 0      | 0      | 0                  |

| 订单确认，预款按依据分配            | 50,300       | 15,000   | 0        | 15,000 | 35,300 | 0                  |

表中确认前15,000是预款，减价后1,000是多收待处理；分类不能互相冒用。退款须有原款及批准依据，审批通过时银行金额不动，付款结果未知时也不能当已退再付一遍。原到账总额始终50,000，最终净收49,000；应收原值50,300及－300、＋1,200、－2,200三项生效差额均保留。

首款与尾款计划只是50,300或调整后金额的分期安排，不能在“订单总应收”之外再新增一份相同应收。后续付款计划若改变，按有效规则重新安排未履行部分，原已收15,000不能跟着改成新的首款比例。

### 价04：改原项目、增新项目、取消项目要分清

从原50,300已确认订单独立开始，均假设所需服务和业务审批已批准：

- 将原单房差1,800改1,500：差额－300，结果50,000；不是新增一笔－1,500后变48,800。
- 原签证3人×500改为2人×500，且本例批准取消未办理的1份：差额－500，结果49,800；原3份及取消依据仍可查。已办理不可退不能套用本例。
- 新增加住1间2晚×600：增加1,200，结果51,500；与价03已先减300的51,200区分，禁止分支混跑。
- 原收费联运1,000改为本次获批免费：减少1,000，结果49,300，服务仍须办理。新增一个免费服务则差额0、仍50,300，不能把两种“免费”处理成同一结果。
- 原联运减少600、增加另一服务600：总额可不变，但两个服务和收费项目都有变化，仍需适用的变更依据及审批；不能因合计差额0就跳过履约和历史记录，也不为此伪造0元银行收付。

每次明确原项目、原数量／单价／单位、拟值、差额、涉及游客、供给及客户依据。若页面只让输入一个订单总金额，AI还须检查实际明细是否同步一致，不能总价对了就结束。

### 价05：免费、已含、待报价，不能都写成0

从50,300已确认订单、已收15,000开始，分别新建三笔独立服务申请：

| 服务类型     | 操作及责任                                                                 | 预期                                                                                    |
| ------------ | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 获批免费接送 | 销售登记0元及游客、日期、地点，计调确认实际可供；本例供应商费用300独立确认 | 应收仍50,300、未收35,300；服务有记录，成本不能因对客免费变0；不创建虚假的应收增额或到账 |
| 产品已含保险 | 沿原产品已含范围办理5人保险，不另收；供应商成本150另有依据                 | 客户额外收费0，保障名单仍5人，成本不重复加入两次                                        |
| 待报价加住   | 先登记未知价格及供给需求；取得客户报价600、资源及业务审批后生效            | 未定价不是免费；审批前应收50,300，生效后50,900、未收35,900，实收仍15,000                |

可供、不可供、需补差分别跑通。计调说可供不等于客户同意收费；供应商提高成本200不自动增加客户应收200。服务被拒绝或申请撤回时不得产生新的有效收费；已产生的真实供应商损失另按事实处理。

### 价06：年龄跨界、改名和免费游客的金额及人数

设置专用测试规则“按服务开始日年龄，满12周岁使用成人价”，创建在报价与出发之间满12岁的游客；本例儿童价6,000、成人价10,000。核对生日及适用日期后，若正式条件要求采用成人价，应取得正确报价／客户确认及适用审批，增加4,000；5人订单变54,300、人数仍5。不能以录单当天年龄直接判最终价格，也不能在资料改正后悄悄追收。

该年龄界限和取日只是测试配置。交通、酒店、保险可能分别适用不同年龄或服务条件，按各自来源核对，不由一个“儿童”标签包办。缺生日、边界当天、闰日生日及跨时区日期分别记录规则与结果，不填虚假生日绕过价格。

另建获批增加一名免团费游客的分支：如本例额外服务也均已明确免费，对客额仍50,300，人数由5变6、名额占6、余14，名单和必要服务包含此人；若仍需收联运或其他费，逐项加入，不能看到团费0就全单免。改名且人数、计价类别和服务都不变时，应收不变；供应商改名费用是否转给客户另有依据。

### 价07：人数减少，不把整单所有收费平均退掉

从5人50,300、已收15,000独立开始。一名成人取消，本例逐项获批：成人团费减少10,000，未使用联运减少200；其签证已经办理，相关500费用保留；房间安排已重新核实，单房差不变，其余收费不变。

有效收费为50,300－10,000－200＝40,100，客户仍欠25,100；成行人数4。不能简单按50,300÷5减10,060，也不能把签证服务办理数量强改成现成行人数。哪些供应商可退、实际名额何时释放继续按第二组六及后续售后组核对，客户收费批准不自动消掉供应商成本。

这一分支也要保留原5人订单和差额明细。已收款不足剩余收费时本例没有客户退款，不能看到“有人退团”就先退15,000／5。

### 价08：并行审批与“总额一样、原项目变了”

独立订单应收10,000、实收8,000，两份申请都基于原10,000：甲增加1,200，乙减少500。甲先生效后应收11,200、未收3,200；乙旧申请必须核对当前版本，不得把总额覆盖成9,500。经重核确认乙仍减少500并重新批准后，应收10,700、未收2,700；实际到账始终8,000。不同申请、相同业务重试及撤回重提分别留依据。

再测相同总额下的过期项目：原项目A600、B400，总额1,000；旧申请拟把A改500，原差额－100。其他已批准变更先将A改400、B改600，总额又回到1,000。旧申请此时不能因“总额仍1,000”直接生效：先退回／阻止旧依据，重核要把A400改500时实际差额应为＋100，重新批准后总额1,100，不能错成900。

还要同时核对审批时的实收：若应收10,000的减价至9,000申请等待期间，客户实际支付10,000，则批准后形成多收1,000，不能使用申请时“实收0”的旧值抹掉到账。数量、单位、币种、项目和价格版本均属于核对依据。

### 价09：批量追加费用，部分失败与分摊尾差

独立三张同公司订单，原应收10,000／20,000／30,000，已收8,000／15,000／30,000。按本例已批准分配追加费用600，分别100／200／300。

全部生效后应收10,100／20,200／30,300，未收2,100／5,200／300，合计应收60,600、未收7,600。金额不能每单都加600，也不能为凑合计把失败单金额转给别单。

本例若按逐单独立处理，第二单审批失败，第一及第三单已生效，则合计应收60,400、未收7,400，第二单仍20,000；重试只处理尚未生效的200。若正式规则采用整批统一生效，须另按该规则验证整批回退或处理中，不强套逐单结果。

精度独立样板：3份99.99加一笔0.01，应收299.98；100.00等额分给三个合格对象，本例固定顺序分33.33／33.33／33.34，合计100.00。另有不参与分摊的第三项时，0.01只在前两项中按批准顺序归属，本例为0.01／0／0，不能因为“最后一项接尾差”就分给不合格项。

上述分配只是输入样板，正式舍入方式、先逐项后合计或先合计后分配须另确认；不能由AI选一个算法再据此判ERP对错。重排页面、导出、分批重试不应无依据改变已批准的尾差归属。

### 价10：对客改价，不自动改内部采购、佣金或外部成本

本例出境对客50,300，另行约定集团采购40,000、B对外采购35,000；代销分支另约定佣金5,000。四种关系使用独立批次，测试下列业务差额，不作税额或会计净利润判断：

| 关系及前提                                    | 对客50,300时                    | 客户改价至49,000且其他约定未变时                       |
| --------------------------------------------- | ------------------------------- | ------------------------------------------------------ |
| A自营，资源已确认35,000                       | A差额15,300                     | A差额14,000；不得擅减供应商成本                        |
| A直接整包外采40,000                           | A差额10,300                     | A差额9,000；客户减价不等于S同意退1,300                 |
| A采购B40,000，B外采35,000                     | A10,300、B5,000，集团对外15,300 | A9,000、B5,000，集团对外14,000                         |
| A代销，B签客并采购35,000，约定佣金5,000暂不变 | A佣金5,000、B差额10,300         | A仍5,000、B差额9,000；B对客49,000，A不另增一笔游客应收 |

“其他约定未变”是明确测试条件；若实际佣金随成交额重算，第四组另算，不得把此处5,000固定佣金当通用政策。A代收款时按第一组记录资金清算，不能因为钱在A而把B的应收改到A。普通销售直接改他公司金额应按正式权限拒绝，页面可见不等于拥有修改权。

### 价11：已开票、已结算或已生成凭证后调价

独立创建原50,300且已全额实收的订单，按实际流程走到已开票、已结算或ERP凭证已生成的对应阶段，再按有效依据减少1,300。当前收费49,000、实际净收在退款前仍50,300、多收1,300；实际退1,300后净收49,000。此分支与价03仅收50,000、退1,000不同，不能复用同一个退款预期。

原订单、发票、结算和凭证不删除、不直接覆盖；保留改价批准、生效差额、原款退款及各自后续处理结果。具体发票更正、收入调整、科目、期间和凭证方式按正式制度验收，不在本稿编造分录或把未知税额填0。即使NC分期，本期ERP财务确认及凭证生成、来源反查仍必做。

## 五、怎样交给AI真实执行

每个实例先保存：场景编号、适用规则及版本、实际公司／账号、产品团期和订单编号、游客与服务对应、逐项数量／单位／单价／金额、是否已含／免费／待报价、原有效值、拟变化、独立预期，以及资金和财务阶段。原始输入和预期先于实际操作结果形成，不能看见系统算了什么再修改正确答案。

逐步操作“建立有效价格→报名及报价→真实预款→订单确认→原单申请→资源确认及业务审批→应收生效→实际认款／退款→结算及财务交接”。只执行本例确有的步骤；每一步保存前后状态、金额、依据、真实编号和执行账号，换岗位及重新进入仍能查到结果。API或只读数据用于复核明细、版本和金额，不修改目标应收、实收或凭证。

关键核对同时包含：项目合计等于有效应收、每人和每服务不重不漏、所有生效差额可追溯、未批准不生效、真实款不随价格重写、退款前后各自余额正确，以及最终合同／结算／财务来源一致。待审批金额不能计入当前有效应收；已到期未收与未到期计划另核，不能只看一个欠款合计。

规则未确认、系统业务结果不符、自动化操作失败、环境受阻和未执行分别记录，不统一标成失败或通过。并行审批必须使用实际重叠请求和持久结果核对；本稿算术复算不能代替该测试。价格及应收明细已经不同而总额碰巧相同的场景必须保留。
