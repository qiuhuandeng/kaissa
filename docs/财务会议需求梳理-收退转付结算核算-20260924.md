## 一、财务希望系统解决什么

财务希望把业务订单、真实资金、供应商成本、结算及财务账对应起来：每一笔钱知道从哪里来、用在哪里、还剩多少；每一次退款、转款、付款都有依据；业务人员提供完整资料，财务按职责审核；系统减少重复查流水、重复录入和逐笔点确认；最终能解释一个团、一个渠道和一家公司的经营结果。

会议二00:52:42—00:56:43给出的关注顺序是：**先保证资金安全，再做好项目结算、成本和毛利，之后承接核算与报表。** 因此，这四次会议不能只整理成“增加几张财务报表”。

归纳为十二类、60项需求：收款认款、预收与未认领款、客户退款、订单转款、成本与付款、供应商预付及退回、发票、核算衔接、结算毛利、资金报表、门店分润、基础资料与权限。详细条目见第四节。

## 七、后续验证这些需求的代表场景

以下为根据会议需求整理的验收建议，本次未执行页面或业务验收。

| 场景 | 应能判断的结果 |
|---|---|
| 一笔到账1万元，先认6000元，再分两单 | 查得到原款及各次分配；剩余4000元；所有分配不能合计超过1万元 |
| 同一交易凭证重复提交，后来导入银行流水 | 仍然只有一笔实际到账，不重复认领或形成两份相同入账依据 |
| 银行已到账但未导入，急需签约 | 财务核实、允许的签约结果、后补匹配分别可查；未匹配不被当成已完成全部财务处理 |
| 企业预收10万元，后续用5000元和2万元 | 可追原预收、两次使用和7.5万元余额；后续使用不再增加银行收入 |
| 客户退款时供应商已收款但尚未退回 | 客户退款和供应商应追款分别有状态，均回到原业务，客户流程不被统一锁死 |
| 同公司同销售同门店同客户转3000元；再试换客户及跨公司 | 常规、审批例外、禁止范围分别处理；原新订单可核对，银行收款不增加 |
| 平台月结、自营团先付供应商，当前实收为零 | 如实显示零与风险，按批准规则审核，不能套“无收款禁止付款” |
| 出纳银行付完多笔、批量确认，其中一笔使用非默认账户 | 实际日期和账户正确，允许记录差异；审批结束不提前计已付，缺回单不等于付款失败 |
| 无团资源预付后供两个团使用，剩余部分退回 | 原预付、各团使用、冲抵、退回及余额能对应；业务分类和科目按待确认规则测试 |
| 供应商累计收款20万元，分多张票且未收齐 | 按公司、供应商看清付款、已收票和缺口，能查回每笔款及票据 |
| 自销和外部代理共同组成一个团 | 按本公司实际成交／结算金额计收入，外部代理差价不计公司；产品、渠道结果可解释 |
| 审批后报次日付款计划，实际次日未付／换日付款 | 计划与执行分别反映，资金日报取已确认实际收付；与银行差异仍可核对 |
| 同公司产品与渠道内部结算、另一案例为跨法人采购 | 内部分工不重复记公司收入，跨公司分别有双方依据；不凭管理毛利直接生成会计账 |
| 门店普通订单与特殊调整订单 | 每单按适用制度展示计算过程与调整依据，不能只输出一个门店总分润 |
