# 数据中心与财务报表菜单归集方案

日期：2026-09-15。状态：用户已确认执行，导航与页面组织调整已完成原型验收；实际结果见[菜单归集交付](数据中心菜单归集交付与验收-20260915.md)，下文保留确认时的方案表述。

## 一、结论

建议所有跨单据的经营分析、财务查询和报表管理统一进入“数据中心”；“财务”继续负责收款、应付、付款、结算、发票和核算推送等业务办理。

原方案把经营分析与财务核对的职责分开是合理的，但将查数入口也分到两个一级模块，增加了使用者判断位置的负担。应保留财务责任、金额口径和权限边界，不再用菜单分散来表达这些边界。

这是对原方案“数据中心10页、财务入口6主题”的导航安排提出修订，不是否定原8批功能验收。原有10个页面功能和6类财务查询能力均保留，拟成为同一中心下16个直接功能入口；不是新增16张报表，也不重开原8批。现行规则中“财务口径报表归财务”的文字，在本方案确认后才同步修订。

## 二、当前为什么不好找

| 当前入口 | 当前内容 | 使用问题 |
|---|---|---|
| 数据中心 > 经营报表 | 总览、产品、渠道、业务毛利、供应商、订单明细、回团明细、月度损益，共8页 | 分析结果与逐笔明细混排，任务层次不清 |
| 数据中心 > 报表管理 | 经营任务与预算、口径与数据核对，共2页 | 管理功能有必要，但不应成为普通用户日常看经营结果的必经位置 |
| 财务 > 财务报表 | 收退转付、往来账龄、预款、资金、票款、结算核算，共6主题 | 需先找通用入口，再用“报表主题”下拉切换，具体报表在菜单里不可见 |

严格说是两个一级入口、三处功能分组，不是三套数据系统。不过使用者感到需要来回找数据，确实有菜单和页面组织上的原因。

原方案为控制新增页面范围，让六主题复用财务报表入口；当前程序也把它们统一识别成同一个“财务报表”导航项。这方便了实现复用，却不利于分别定位、收藏和同时打开核对。六种查询的对象、日期依据和任务不同，应有独立菜单；复用计算逻辑不要求共用一个通用页面入口。

本次依据当前目录、共享导航、页面入口、报表主题切换及页面内分区核对，不重新评审金额算法，也未重新读取财务工作簿或开展实账审计。

## 三、建议最终菜单

一级名称保留“数据中心”，不用另外新增“财务数据中心”。下面四组只是同一中心的菜单分组，不是四套独立模块。页面名称优先沿用现有名称，避免无必要改名。

| 分组 | 直接菜单/页面 | 主任务 |
|---|---|---|
| 经营分析 | 经营总览 | 看集团经营结果与主要异常摘要 |
| 经营分析 | 产品经营分析 | 看产品结构、贡献和相关资源风险 |
| 经营分析 | 渠道经营分析 | 比较渠道、门店、呼叫中心和企业客户业绩与贡献 |
| 经营分析 | 业务毛利与结算分析 | 看团期、项目、服务的毛利、成本和资源损耗 |
| 经营分析 | 供应商采购与返点 | 看采购结构、集中度、返点及预付占用 |
| 经营分析 | 月度经营损益 | 看公司部门收入、成本、费用和预算差异 |
| 业务明细 | 订单明细 | 按订单发生及变化核对销售事实 |
| 业务明细 | 回团与履约明细 | 按实际完成核对完成业务及对应财务确认 |
| 资金与核算 | 收退转付明细 | 核对逐笔资金、原款及逐订单分配 |
| 资金与核算 | 订单收付与往来账龄 | 查截止日待收、待付、账龄、逾期及内部待清算 |
| 资金与核算 | 预款与保证金 | 分别查预收、预存、预付、保证金余额和变动 |
| 资金与核算 | 资金收支与安排 | 看实际账户收支、可用资金和有依据的未来安排 |
| 资金与核算 | 发票与收付款核对 | 查票款对应、分配、时差及红冲差异 |
| 资金与核算 | 结算与核算核对 | 核对业务结算、财务确认、内部双方及集团核算系统返回 |
| 报表管理 | 经营任务与预算 | 维护经营任务，查询已批准的损益与费用预算 |
| 报表管理 | 口径与数据核对 | 分类组织对应、数据核对、版本及查看导出范围管理 |

共6个经营分析入口、2个业务明细入口、6个资金与核算入口、2个管理入口。默认仍直接打开实际报表，不增加必须先点一次的卡片目录页。

月度经营损益放经营分析，因为它用于公司部门经营复盘；不是付款处理页，也不冒充完整法定利润表。门店、呼叫中心、事业部和公司主要是分析范围，不按组织再各复制一套报表菜单。自营与外采保留现有分类和筛选，不拆成两套报表系统。

## 四、财务模块保留什么

| 财务办理分组 | 保留内容举例 | 与数据中心的区别 |
|---|---|---|
| 收款应收 | 到账流水、认款复核、应收、预收、预存、退款、转款 | 处理具体款项和单据；不是集团期间汇总 |
| 成本应付 | 供应商账单、应付、付款申请与执行、回单核销、预付 | 确认和执行应付付款；不是往来账龄分析 |
| 结算对账 | 业务结算、渠道结算、门店对账、期间关账 | 办理结算或关账；不是跨单据核算差异报告 |
| 资金票据及核算推送 | 资金池、收付款配置、资金调拨、发票管理、核算推送 | 操作账户、票据和推送；不是只读统计 |

将“财务报表”通用菜单从财务日常菜单撤下，六类查询的主入口统一归数据中心。旧收藏链接仍应打开对应的新入口，不失效、不默认跳成收款报表。

单据列表及详情已有的合计、余额、核销和结算记录继续保留。财务人员办一张单据时需要当场看这些数字，不应为统一报表而被迫跳数据中心。需要更正事实时仍回到相应办理模块，报表不增加认款、付款、开票或推送按钮。

本轮不再在财务复制一套报表目录，也不新增办理页改造。以后确有高频需要的快捷入口只能指向同一报表，不能产生第二份报表或另一套计算。

## 五、菜单、页内标签和筛选如何区分

| 表达方式 | 使用原则 | 本次应用 |
|---|---|---|
| 独立菜单 | 不同核对对象、不同日常任务，需要分别打开 | 六类财务查询各有菜单、独立标题、地址和顶部页签 |
| 页内标签 | 同一报表的相关分类或查询视角 | 收退转付内的收款/退款/转款/付款；预款内的预收/预存/预付/保证金；损益内的公司/部门/费用/预算 |
| 筛选条件 | 同一结果的范围和观察条件 | 公司、部门、业务线、门店、渠道、供应商、币种、期间等 |

删除六类独立报表之间的“报表主题”下拉，不只是将下拉改成六个顶部按钮。后者仍没有解决报表藏在一个通用入口里的问题。

菜单名称、页面标题、浏览器标题和系统顶部页签一一对应；同时打开账龄与票款核对，不能互相顶替。进入具体报表即看到其查询条件与结果，不增加中间选择页。页内同类标签保留，避免把全部视角拆成几十个菜单。

## 六、页面内容哪些保留、哪些收敛

| 内容交叉 | 主查询位置 | 另一个位置怎么处理 |
|---|---|---|
| 完成业务财务结果与会计期间发生 | 完成范围在回团与履约；按会计期间全量发生在结算与核算 | 回团保留完成业务对应的累计确认与差异；不再并列提供另一份不受完成范围约束的全量核算主查询。旧确认发生链接承接到核算查询，原记录与导出能力保留 |
| 产品资源观察与全量资源成本风险 | 全量资源批次、分配和损耗依据在业务毛利 | 产品保留产品相关风险观察，不重复一整套全量资源台账；同一资源仍共用现有规则，不新造产品分摊比例，缺归属不能按名称猜 |
| 供应商占用与预付明细 | 余额变动、冲抵、退回依据在预款与保证金 | 供应商保留采购判断需要的占用观察，共用余额，不另建预付办理或余额算法 |
| 预算维护与实际预算差异 | 任务维护和批准预算查询在报表管理；实际差异在月度损益 | 不把完整损益分析再复制进任务页；已有预算引用保留，不新建全面预算系统 |
| 总览摘要与各类完整明细 | 完整查询在对应报表 | 经营总览保留摘要，不变成所有报表拼接的大页面 |
| 业务核对与原型验收算例 | 日常数据异常在口径与数据核对 | “业务场景核对”六组演示从日常管理标签中退出，保留验收资料及独立验收访问方式，不删除算例、证据和测试 |

以上是页面组织与主查询职责的建议，不取消已验收的分析维度，不重写公式。收敛重复视图时必须先核对条件、字段、依据和导出等价性，再迁移旧入口；无法等价承接的视图先保留，不能用隐藏页面代替功能迁移。

## 七、多主体与角色边界

上游仍来自订单、实际履约、成本与结算确认、收付、票据以及已有财务资料；下游是查询核对、经营复盘和报表输出。查询本身不改变业务单据状态。报表管理只改变管理范围内的任务、规则或报表版本，不批准收入成本或实际付款。

- 集团财务在获授权范围内看跨公司经营、资金和核算结果；选“全部公司”不等于自动完成会计抵销。
- 公司财务查看所属核算范围的资金与往来；核算主体指独立形成会计结果的单位，不因菜单统一而等同于每一个部门或门店。
- 产品、销售、事业部及门店负责人查看获授权经营范围；经营查询权不自动包含银行账户、全集团往来或敏感字段导出权。
- 报表管理员管理分类、规则及版本；不因维护报表而获得业务批准或付款权限。

组织、授权、币种和版本的表达统一，但日期不能强行统一成一个“本月”：订单发生日期、实际完成日期、财务确认期间和余额截止日继续分开。公司也必须区分销售责任、产品责任、记账责任和实际资金责任，不能把一个顶部公司选择机械套到所有含义。

当前权限是原型表达，不是已接入的生产访问隔离；正式身份、授权与导出控制仍按原交接确认，本次菜单调整不扩张为权限系统开发。

## 八、确认后的实施和验收

作为一次有边界的导航与页面组织调整完成，内部按三个连续环节推进，不新增一轮八批报表建设：

1. 统一入口：调整数据中心四组菜单；六主题独立入口、标题和页签；财务办理分组不动。
2. 整理承接：取消主题下拉，按第六节收敛重复主查询，保留同报表标签及所有已验收能力；处理旧链接、旧页签和原型验收入口；同步规则与交付目录。
3. 一次验收：核对16个入口、同时开页与返回刷新、旧链接对应、筛选及全量导出；本地HTML与随机HTTP端口、桌面与窄屏回归；计算与原有36项功能不能因入口迁移丢失。无8002依赖，不增加源业务流程联调。

验收完成应交付一份新菜单与旧页面对照清单。通过的是导航与原型可用性，不宣称正式财务数据已经接入。

以上为用户确认时的实施范围；用户已于2026-09-15授权执行，实际入口与验收记录转见[菜单归集交付](数据中心菜单归集交付与验收-20260915.md)。当前断点只以进度第三、四节为准，不再等待本方案重复确认。
